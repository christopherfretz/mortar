   crtbeginS, crtendS, crtn, the -l tails with --as-needed, --push-state/--pop-state and
   --no-as-needed, and -plugin as a no-op. 546 census lines are refused for -shared alone.
   The output must include:
   - .dynsym/.dynstr/GNU_HASH exporting every default-visibility global, including C++
     COMDAT/template instances (gtest: 3840 defined);
   - PLT/GOT and dynamic relocations for preemptible references;
   - RELATIVE relocations;
   - DT_INIT/FINI and the init/fini arrays from crtbeginS;
   - PT_GNU_EH_FRAME (W2 shows what happens without it);
   - PT_GNU_RELRO, DT_NEEDED with --as-needed;
   - STB_GNU_UNIQUE, emitted with EI_OSABI GNU as GNU ld does.
2. Undefined symbols left for load time (no -z defs): 10/19 survey lines. The lua modules
   reference lua_* from the host exe and lib11/lib21 reference other modules; mold, lld and
   GNU ld agree. "-z defs"/"--no-undefined" must turn this into an error naming the symbol
   (42 census lines). Mortar does not refuse these options today; whether it enforces them
   for -shared is untested.
3. -soname: 7/19 survey lines (gtest 4, zlib 3), 4/4 libtool lines, 2/2 CMake lines. In all,
   13/25 real lines.
4. --version-script: 3/19 survey lines (zlib) and 1/4 libtool lines spelled -version-script.
   - The zlib subset: named nodes, a parent chain, global:/local:, an implicit global section,
     the `_*` local glob, and no `local: *`.
   - Names in the script that are not defined must be ACCEPTED, as GNU ld does by default.
     Otherwise zlib's configure probe fails (2/19 lines), as it does under lld.
   - The output must match GNU ld's VERDEF: BASE = soname, plus 14 entries with parents.
     Whether to emit the version-name ABS symbols is a choice (GNU ld and the system libz do;
     lld and mold do not; all run).
5. --dependency-file: 4/19 survey lines and 2/2 CMake lines. Mortar already accepts it.
6. -rpath (+ DT_RUNPATH as the default, --disable-new-dtags -> DT_RPATH): CMake libcxl and
   libtool L4 (2/25 real lines). 63 census lines. Mortar already accepts it.
7. --whole-archive/--no-whole-archive: libtool convenience archives (L3, 1/25).
   Currently refused.
8. -nostdlib with explicit crt files (libtool C++, L2): no new option, just inputs.
9. Not seen on any real line (census only, 21 lines each): -Bsymbolic(-functions),
   --dynamic-list, --exclude-libs, -z nodelete/initfirst/interpose/now, -init/-fini, -u,
   --export-dynamic, --gc-sections. Of these, -u, --dynamic-list, --exclude-libs and
   -z nodelete/initfirst/interpose are refused by mortar today; they can stay refused in the
   first package.
10. Refuse by name, never link:
    - text relocations in -shared (i686 non-PIC objects: 14 census lines link with GNU ld;
      lld and mold refuse; W1 shows the GNU ld output crashing);
    - -shared -static (21 lines; 3 link with GNU ld; W2 and W3 crash);
    - -shared -static-pie (21 lines, 0 link anywhere).
    For the non-PIC 64-bit cases, mortar's diagnostic should name the relocation, the symbol
    and "recompile with -fPIC", as all three references do.

======================================================================
DISAGREEMENTS BETWEEN THE REFERENCES (all measured)
======================================================================
D1 Undefined names in a version script (zlib probe, realbuilds.sh "probe"):
   - GNU ld: silent, rc=0.
   - mold: 56 warnings, rc=0.
   - lld 19/22: an error per name, rc=1, unless --undefined-version.
   - GNU ld with --no-undefined-version: also rc=1.
D2 .dynsym contents for zlib.map: GNU ld adds 14 version-name ABS symbols plus the LOCAL
   SECTION .data/.init (124 vs 108 entries). The system libz agrees with GNU ld. Runtime is
   the same in all 48 cross runs.
D3 EI_OSABI with STB_GNU_UNIQUE: GNU ld sets GNU; lld 19/22 and mold leave SYSV, which readelf
   shows as "<OS specific>: 10". gtest runs identically on all four.
D4 --as-needed and libc: mold records NEEDED libc.so.6 where GNU ld and lld drop it (all 5 lua
   modules, libfoo, libwa, libdep, CMake libcl). The cause is UNVERIFIED. It may be that mold
   counts the weak __cxa_finalize/_ITM_* references from crtbeginS.
D5 eu-elflint passes GNU ld's libz and flags lld's, lld19's and mold's (.relro_padding type
   and flags; .rodata merge entsize 0; lld22 .plt flags; mold __ehdr_start out of bounds).
   All of them load and run.
D6 i686 non-PIC/-fno-pic objects into -shared:
   - GNU ld links with TEXTREL warnings (14 lines).
   - lld refuses: "relocation R_386_32 cannot be used against symbol 'lib_data'; recompile
     with -fPIC". It still refuses with -z notext ('__gxx_personality_v0').
   - mold refuses: "relocation R_386_32 in .eh_frame can not be used when making a
     position-independent output; recompile with -fPIE or -fPIC".
D7 -shared -static i686:
   - GNU ld links: TEXTREL, no PT_GNU_EH_FRAME.
   - lld refuses: "relocation R_386_32 cannot be used against symbol '__TMC_END__'; recompile
     with -fPIC".
   - mold links, with PT_GNU_EH_FRAME and PHDR.
D8 Driver differences:
   - gcc C++ and Fortran -shared tails have no -lgcc; clang's do.
   - gcc uses a global --as-needed, so clang C++ keeps NEEDED libm and gcc drops it.
   - -rdynamic gives -export-dynamic on gcc aarch64 and clang, but nothing on gcc x86-64/i386.
   - -static-pie: gcc drops -shared, clang keeps it.
   - -shared -static: gcc swaps in crtbeginT and drops --eh-frame-hdr; clang keeps crtbeginS
     and --eh-frame-hdr and adds -static.
   - gfortran -lquadmath appears on x86 only.
D9 --dependency-file contents: 85 / 52 / 35 lines (GNU ld / lld / mold) for the same gtest link.
   CMake does not pass the option to mold at all.
D10 gtest library size: mold 2581472 bytes vs GNU ld 1772376 vs lld 1736672.

======================================================================
WRONG OUTPUTS (each reproduced by a script; all on lines mortar should refuse)
======================================================================
W1 GNU ld 2.44, i686, clang++ 19 and 22 with a -fno-pic C++ object and -shared.
   - Link: rc=0 with "warning: relocation in read-only section `.eh_frame'" and
     "warning: creating DT_TEXTREL in a shared object".
   - Run: the library prints "lib C++ data=41" and then SEGFAULTS (rc=139) when its exception
     is thrown.
   - The same source built with i686 g++ -fno-pic also has TEXTREL and runs OK.
   - lld and mold refuse this link.
   - Scripts: odd.sh, section A (odd.log); census.py variation fno-pic (clang19/clang22 i686 c++).
   - Root cause UNVERIFIED. Suspected: .eh_frame in a read-only segment patched by text
     relocations, or the eh_frame_hdr table computed before relocation.
W2 GNU ld 2.44, i686-linux-gnu-g++ -shared -static (the driver's own line).
   - Link: rc=0 with the crtbeginT TEXTREL warning. The output has no PT_GNU_EH_FRAME because
     the driver omits --eh-frame-hdr.
   - Run: the C++ library aborts with "terminate called after throwing an instance of
     'std::runtime_error' what(): 41" (rc=134). The C version runs OK.
   - Adding -Wl,--eh-frame-hdr makes the C++ library run OK (odd.sh, B').
   - This is arguably the driver line plus GNU ld accepting it, not GNU ld alone.
   - Scripts: odd.sh, section B; census.py variation static (gcc i686 c++).
W3 mold 2.37.1, i686-linux-gnu-gcc -shared -static -fuse-ld=mold, on a C library.
   - Link: rc=0 with no diagnostic.
   - Run: dlopen + call SEGFAULTS before the library's first output (rc=139).
   - The same line with GNU ld runs OK. lld refuses it.
   - mold's C++ variant runs OK.
   - One difference is visible: GNU ld resolves crtbeginT's non-PIC calls to
     __(de)register_frame_info_bases as dynamic R_386_PC32 text relocations. mold routes them
     through R_386_JUMP_SLOT PLT entries, which in a shared object assume %ebx = GOT. Whether
     this causes the crash is UNVERIFIED.
   - Script: odd.sh, section B, "gcc -shared -static (C) + mold".
