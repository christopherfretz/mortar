A. Export set (exp/export/partA.py; S:A)
==================================================================================================
Input. One object set: C globals and weak definitions, protected, hidden and internal symbols, statics,
common, weak undefineds (called, through the GOT, in a data word, call-only), and an archive member
(ar_f/ar_g/ar_v) of which a second member is never pulled. C++ adds COMDAT inline functions, a vtable,
typeinfo, template statics and function-local statics.
Variants: default; -fvisibility=hidden; --exclude-libs=ALL, =libar.a, =libzz.a; version script {global:
def_f;def_v;ar_f; local:*}; an anonymous version script; --dynamic-list; --export-dynamic.

A1 Default export set: the same in every linker on all 3 arches, with two exceptions.
  - bfd on a64 also writes 2 LOCAL SECTION entries (SECTION#9 and SECTION#23).
  - __cxa_finalize is WEAK NOTYPE UND in bfd and WEAK FUNC UND in lld and mold.
  Common to all:
  - C++ COMDAT functions are WEAK FUNC; the vtable and typeinfo are WEAK OBJECT; template statics and
    function-local statics are UNIQUE (GNU_UNIQUE) OBJECT.
  - Every referenced weak undefined (wk_call, wk_got, wk_word, wk_callonly) is WEAK NOTYPE UND.
  - prot_f and prot_v are exported and keep st_other = PROTECTED.
  - Hidden, internal, static and the unpulled archive member (ar_unref) are absent.
  - No linker-defined symbol is exported.
A2 Variants (A-cmp in S:A gives the removed and added names per variant):
  - exclude-libs ALL and libar.a: remove ar_f, ar_g and ar_v in all linkers. libzz.a: no change.
  - vishidden: removes the C++ symbols, com_v and so on, but keeps prot_*, expl_def_f and ar_* (the
    archive was built without the flag).
  - vs_global: only def_f, def_v and ar_f. bfd also exports the version node's name V1 as a GLOBAL OBJECT
    (ABS) entry; lld and mold do not.
  - vs_anon: def_f and def_v only.
  - dynlist and export-dynamic: identical to default for -shared, in all linkers.
A3 .dynsym order and .gnu.hash (A-hash), with n = 32 hashed symbols:
           nbuckets       maskwords (64/i386)   shift   order of defined symbols
  bfd      17             4 / 8                 8       hash order
  lld      8              8 / 16                26      first appearance (matches D-26's formula)
  mold     5 (= n/8+1)    8 / 16                26      sorted
  - All three put the undefined entries first and sort the hashed part by bucket.
  - None of them writes .hash.
  - sh_entsize of .gnu.hash on i386: bfd 4, lld 0, mold 0. D-26 says "4 on ELF32 for all three"; that
    is wrong for -shared on lld and mold.
A4 -z defs / --no-undefined (A-zdefs; the same on all arches)
  - Plain undefined reference, function or data: all refuse.
      bfd:  "a64/z/z_nosuch.o: in function `z': | z_nosuch.c:(.text+0x8): undefined reference to `nosuch'"
      lld:  "ld.lld: error: undefined symbol: nosuch | >>> referenced by z_nosuch.c | >>> a64/z/z_nosuch.o:(z)"
      mold: "mold: error: undefined symbol: nosuch", followed by the same two >>> lines.
  - A definition in a direct shared input satisfies the check. One that is only in an indirect
    dependency does not (all refuse). A weak undefined is allowed by all.
  - Reference to vf@VB, where libver.so does not define version VB:
      without a flag: bfd refuses ("no symbol version section for versioned symbol `vf@VB' |
        final link failed"); lld refuses ("undefined symbol: vf@VB"); mold LINKS (see W13).
      with -z defs: mold refuses with "undefined symbol: vf".
  - Reference to vf@VA, where libver.so defines VA:
      bfd and lld: link with FUNC UND vf@VA and NEEDED libver.so; the dlopen host gets z()=1.
      mold without a flag: links, but drops the version AND the NEEDED entry (W13).
      mold with -z defs: refuses a valid link with "mold: error: undefined symbol: vf".

C. Preemption, proven by interposition (exp/export/partC.py; S:C)
==================================================================================================
Input. libc1.so has f, v, weak wf and wv, IFUNC ifn and protected pf, with internal call_/read_/addr_
users. A host prints the internal result and whether addr_X() equals dlsym(RTLD_DEFAULT,"X"); it runs
plain and under LD_PRELOAD of pre.so (which defines all six names returning 3).
Cell format: <internal call result><address equal>, under preload. 31 = preempted (correct for an
exported, preemptible symbol). 10 = bound locally. Without preload every case prints 11.

C1 Object level (the "relocations" block in S:C):
   - gcc emits f@PLT; with -fno-semantic-interposition it emits a call to f.localalias.
   - clang (22 and 19) emits f@PLT; with -fno-semantic-interposition it emits .Lf$local, so &f also
     differs from dlsym under preload (f=10).
   - clang's default for ifn is local (ifn=10) in every linker: a compiler effect, not a linker one.
   - pf is always a direct call.
C2 gcc objects, the same on all 3 arches unless marked:
  option           bfd                           lld22 (lld19 =)                mold
  default          all 31 except pf=10           same                           same, but ifn=10 IREL=1
  -Bsymbolic       x86: all 10, DT_SYMBOLIC +    all 10, DT_FLAGS=SYMBOLIC      all 10, no DT flag
                   DT_FLAGS=SYMBOLIC; a64: REFUSED
  -Bsymbolic-func  x86: f,wf=10, v,wv,ifn=31;    f,wf=10, v,wv,ifn=31           f,wf=10, v,wv=31, ifn=10
                   a64: REFUSED
  -Bsym-non-weak-f bfd: unknown option           f=10, rest 31                  f=10, ifn=10, rest 31
  -Bsym-non-weak   bfd: unknown option           f,v,ifn=10; wf,wv=31           same
  vs local:*       all 10, not exported          same                           same
  --dynamic-list f x86: f=31 ifn=31, rest 10;    f=31, rest 10                  f=31, rest 10
                   a64: REFUSED
  dynlist + -Bsym  x86: f=31 ifn=31, rest 10;    ALL 10, DT_FLAGS=SYMBOLIC      f=31, rest 10
                   a64: REFUSED                  (f is exported and has a record, but is not preempted)
  - gcc_noifunc (ifn an ordinary function): all linkers agree on every option. With bfd on a64
    -Bsymbolic, Bsym-func and dynlist then link fine, which isolates the refusal to the IFUNC.
  - clang22_si (-fsemantic-interposition) behaves like gcc (including the bfd a64 refusals and mold
    ifn=10). Clang default and nsi objects: the linkers agree except on dynlist+Bsymbolic (lld f=10).

D. Relocation classes in -shared (exp/export/partD.py; S:D)
==================================================================================================
Input. Hand-written assembly forms, each applied to five target kinds:
  loc  local static
  hid  hidden global
  pre  default-visibility global defined in the output (preemptible)
  imp  import from libdep.so
  wk   undefined weak
Each library is loaded by a host and the value it reads is checked against the expected one. The
interposed run uses a host that defines pre_d and pre_fn, so a correct pre must yield the host's copy.
Verdicts: OK; FAIL (wrong value, no crash); CRASH (SIGSEGV); REFUSED; TEXTREL (linked with DT_TEXTREL).

   - x64: PC32 (lea, mov, call, jmp e9), PC32 in .data.

                                "unresolvable R_AARCH64_PREL32 relocation against symbol `imp_d'"

==================================================================================================
1. Disagreements (and which linker is right)
==================================================================================================
D1 -Bsymbolic DT tag: bfd writes DT_SYMBOLIC and DF_SYMBOLIC; lld writes DF_SYMBOLIC; mold writes
   nothing (S:C).
   All three bind locally, so outputs behave the same; bfd is the most complete. The tag is not
   harmless (W2).
D2 Parents in verdef: bfd writes them (vd_cnt>1); lld and mold do not. bfd follows the documented
   GNU format. glibc ignores parents, so it is harmless at run time.
D3 Version-script syntax: twoparents is accepted only by bfd; localfirst is refused only by bfd. bfd
   defines the language, so lld and mold are wrong on twoparents, and bfd is stricter on localfirst.
D4 r5 (exact name in two nodes): bfd and lld give V1, mold gives V2. bfd is the reference; mold differs
   silently, so the ABI changes.
D5 NEEDED_INDIRECT_EXTERN_ACCESS: only bfd propagates it. bfd is right: the property is the
   library's protection against copy relocations (B4 shows glibc then refuses with rc=127 instead of
