F. p_align, congruence, loader (partF.py, [F])
---------------------------------------------------------------------------------------------
Every PT_LOAD of every output satisfies p_offset == p_vaddr mod p_align for max-page-size 4K, 16K, 64K, 2M
(congruent=True everywhere) and dlopen runs "f()=42" with the 4K host.
File layout: bfd pads the file to the page (x64 mp2m file 0x600af0, a64 64K default file 0x10ee8); lld and mold
  do not pad (file stays 0x1380 / 0x1b38 on x64 at every max-page-size; vaddr jumps instead).
Loader checks on patched copies of the default output (second PT_LOAD), all linkers, all arches:
  p_align 0x10 or 0x800 (below page size): accepted, "dlopen ok f()=42".
  p_offset + 0x10: refused "ELF load command address/offset not page-aligned".
  p_offset + 0x1000 (still page-congruent, wrong bytes): not detected; crash (a64 rc=-7/-4, x64 SIGSEGV,
  i386 SIGBUS/SIGSEGV).
So glibc 2.41 checks only (p_vaddr - p_offset) mod pagesize; it does not check p_align or the congruence
modulo p_align.

Disagreements (all measured above)
---------------------------------------------------------------------------------------------
 1. PT_PHDR in -shared: lld, mold yes; bfd no.
 2. Program header order and NOTE position differ on all three (A).
 3. RELRO end: aligned to max-page-size by bfd and mold, only to 4K by lld (a64 0x21000).
 4. .got.plt: bfd puts its 3 reserved words in RELRO; lld and mold leave all of .got.plt writable when lazy.
 5. .dynamic order: three different orders; RUNPATH before NEEDED only in lld; FLAGS near the end only in mold.
 6. DT_NULL padding: bfd 5-6, lld 1, mold 6.
 7. RELACOUNT: never from mold.
 8. -Bsymbolic tags: bfd SYMBOLIC+FLAGS, lld FLAGS only, mold none (binding is the same).
 9. TLSDESC: bfd lazy (.rela.plt + TLSDESC_PLT/GOT; i386 without the tags), lld/mold eager in .rela.dyn.
