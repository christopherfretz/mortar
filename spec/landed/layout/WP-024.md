# WP-024: `mortar_layout`, the code of `spec/layout.md` (M1)

This WP implements `spec/layout.md` for static non-PIE executables in
`crates/mortar_layout`, together with the requests of its §20 to
`spec/model.md` (`mortar_core`), `spec/diag.md` (`mortar_diag`) and
`spec/cli.md` (`mortar_cli`). `mortar_plumb`, `spec/plumb.md` and
`spec/synth.md` are not touched.

## Evidence

- **Differential, stage A** (8 programs: C hello; C++ with exceptions and
  TLS; Fortran; `-ffunction-sections -fdata-sections`; `-g`; 64 KiB and
  4 KiB alignments; `.tbss`-only TLS; `.init_array` priorities; × AArch64,
  x86-64, i386; × GNU ld 2.44, lld, mold; i386 Fortran skipped, no
  libgfortran): every input section a map places, read with `mortar_elf`
  and assigned by mortar. 110 619 placements compared, 110 527 equal, 92
  different, all explained: `.gnu.warning*` consumed (L-33; lld and mold
  copy them), `.note.gnu.property` consumed (L-34). No unexplained one.
- **Differential, stage D**: lld's output-section list fed to stage D
  (`--image-base=0x400000 -z max-page-size=0x10000 -z noseparate-code`;
  23 links, each with lld's default and with
  `-z common-page-size=0x10000`): 1 476 addresses, offsets, sizes and
  segments compared; equal except 122, all explained: RELRO padding to
  maxpage, lld to the common page (L-64); a segment whose first chunk is
  aligned to maxpage or more starts a page lower than lld's (L-70); a
  `.tbss`-only template starts the RW run (L-77). With the common page
  equal to maxpage, every link other than `align` and `tbss-only` is
  identical to lld's.
- **Loadability**: 27 synthetic links (3 machines × default,
  separate-code, norelro, execstack, max-page 4/16 KiB, `.tbss`-only,
  large alignments, `.bss`-only) and 6 links shaped like lld's outputs of
  C and C++ programs: `Layout::check`, the independent [G] checker
  (`tests/common/elf.rs`, which reads only the written skeleton) and
  `pagesim.py` (`MORTAR_PAGESIM`) at every page size up to `p_align`:
  no problem. The checker finds L-1, L-4 and L-7/L-8 mutations.
- **Determinism**: every loadability link, the fixed-point links and stage
  A on the real inputs (lld's file lists) give one result under
  `par::check_schedules` (1, 2, 7, 64 threads; seeds that permute the
  processing order).
- **Scale** (`tests/scale.rs`, release, best of 3; ms; 10^6 sections,
  10^5 names; the last column is the time at 10^5 sections):

## Ambiguities and what was done

- L-60 and L-76 order the TLS chunks differently: L-76 is followed.
- resolve §8.1 makes linker-defined symbols local/hidden; L-91 says
  `STB_GLOBAL`: layout writes only values; binding is synth's.
- `.note.gnu.property` inputs are `OutOf::Consumed` (new variant): the
  synthetic note replaces them (L-34).
- L-42: COMDAT-dropped sections keep an assignment row; `Assignment::check`
  accepts that.
- W+X output sections are refused (`feature`, `writable and executable
  output section NAME`).
- `.preinit_array.*` is an orphan (no rule names it).
- The keep-by-rule set is layout's own until `spec/live.md` exists.
- `_TLS_MODULE_BASE_` is never withdrawn; with no TLS it is refused.
- x86 has no islands (`Target.islands = None`).
- A synthetic `.eh_frame` joins the `.eh_frame` output section.
- `__tdata_start` with no `.tdata`: unconditional in resolve but without a
  value; refused (`feature`). resolve should make it conditional.
- `--defsym` expressions are refused; aliases are implemented.
- An entry symbol defined outside code is a refusal, never
  `internal-error`.
- `etext` with no exec chunk is the base; `edata`/`end` follow file order.
- `-z start-stop-visibility` stays `refused`: §20.2 makes only
  `protected` a no-op and a row's status cannot depend on its value.
- The rows §20.2 makes `supported` stay `refused` until `mortar::link`
  runs layout (WP-027), as cli.md §4.2 and WP-020d did; the five no-ops
  are flipped.
- diag.md §3.3 inserts new kinds at their area, sorted (a new "layout"
  area before refusals), so `Kind::IDS` positions after
  `relocation-out-of-range` moved; the brief said "append-only".
- Commit 94fc09e (stages C/D) does not build on its own; the next does.

## The range-extension join with WP-023

Stage E judges with `mortar_arch` only: `need::{thunk_need, erratum_need,
reaches, R_MAX, FIXED_POINT}` (`fixed::R_MAX` is a re-export),
`Arch::{thunk, errata, erratum_sites, patch_reach}` (and, through
`erratum_need`, `erratum_in_place`). `fixed_point` and `place` take
`Option<&RangeExtension { arch: &dyn Arch, sites: &dyn Sites }>`; `None`
is no range extension (x86, or no scan yet; this replaces the stand-in
`RangeArch` and `NoRangeExtension`). What layout does not own comes
through the trait `fixed::Sites`:

- `branches() -> &[BranchAt { section, offset, record, site: BranchSite }]`:
  the relocations for which `need::branch_site` is `Some` (so
  `Arch::consumed` and the veneer class are applied by the caller's scan);
- `target(i, &Round) -> Option<u64>`: the final target `T` at the round;
- `code(OutSecId, &Round) -> Option<OwnedCode { addr, bytes, proof }>`:
  the words fill writes at the round's addresses before any fix, asked
  only when `Arch::errata()` is not empty. The ADRP immediate depends on
  the addresses, so this is per round (`Round::out_extent` gives the
  range).

`Arch::unit_window` is not used: it is fill's and the scan's. Step 3 is
arch.md §6 on main: an existing in-reach thunk of the key with the lowest
address; else the island of the site's part, reusing a patch of the key
already there (one created this round, or an older one, which stays a
need that the cap bounds). Stale erratum redirects are dropped at the
fixed point (a64.md §11.2); their patches stay. `tests/fixed.rs` runs
the rounds end to end with `mortar_a64` (two rounds of thunks then a
quiet third, one thunk per key; an 843419 patch and an ADR fix; a stale
redirect; the cap; L-112, L-115, L-118) and checks the result with
`write_thunk`, `erratum_branch` and `write_patch`.

What does not fit, and was not bent:

- `Arch` has no erratum patch shape: `fixed.rs` `erratum_patch_shape`
  holds 843419's two words (a64.md §11.2). An `Arch::patch(e) ->
  ThunkShape` would remove it.
- `Unproved` maps to `refused` (`feature`, `erratum 843419 scan without
  mapping symbols`) without a64.md's place and key (`LayoutDiag` refusals
  carry a name only).
- An erratum site whose final word is in a synthetic chunk (an island,
  `.plt`) has no `SectionId` key: `internal-error`.
