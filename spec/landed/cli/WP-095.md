# WP-095: mortar does not abort when its standard error or output is a closed pipe

Status: landed record. The rule is `spec/cli.md` §3.15 (S-1..S-5);
`spec/diag.md` §7.1 says how the report is emitted.

## The defect

WP-061 stage B saw `MORTAR_STEPS=1 mortar ... 2>&1 | head` end in
`SIGABRT` with a core. Reproduced on AArch64 (release build of main
675550c): every `MORTAR_STEPS` line was printed with `eprintln!`, which
panics when the write fails; Rust ignores `SIGPIPE`, so a pipe whose
reader has gone is `EPIPE`, and the release profile has `panic =
"abort"`. Backtrace (gdb, `2>/dev/full`):

```text
#13 std::io::stdio::print_to<std::io::stdio::Stderr> () at library/std/src/io/stdio.rs:1165
#14 std::io::stdio::_eprint () at library/std/src/io/stdio.rs:1286
#15 mortar_core::par::{impl#6}::drop () at crates/mortar_core/src/par.rs:722
#17 mortar_core::par::Pool::map<...> () at crates/mortar_core/src/par.rs:422
#18 mortar_input::walk::Caches::fill () at crates/mortar_input/src/walk.rs:435
```

The abort comes from a failed write: the brief's stop condition does not
apply. Closing the reader in the image phase (a reader that stops at the
line of `par mortar_image/src/plan.rs`) left `.<out>.mortar-tmp` behind
in two runs of three (`SIGABRT`; the previous output was not replaced).
Everything else was already written with `let _ = write_all(..)` in
`main.rs` and could not abort.

## What mortar did before (main 675550c)

Inputs: `u.o` (400 calls to undefined functions), `w.o` (their 400
definitions, each with a `.gnu.warning.<name>` section: 400 warnings,
53 KB), `ok.o`. "Gone": a pipe whose read end was closed before the
linker started; "closed": `2>&-` / `>&-`; "full": `/dev/full`. `ulimit
-c 0`, so "core" is a signal that dumps one.

| stream | what | gone (`EPIPE`) | closed | full (`ENOSPC`) |
|---|---|---|---|---|
| stderr | 400 errors | exit 1, no output | exit 1 | exit 1 |
| stderr | 400 warnings, success | exit 0, output | exit 0, output | exit 0, output |
| stderr | `MORTAR_STEPS=1`, success | **SIGABRT** (core), no output; `.out.mortar-tmp` left when the abort is in the image phase | exit 0, output | **SIGABRT** |
| stderr | `MORTAR_STEPS=1`, failing link | **SIGABRT** | exit 1 | **SIGABRT** |
| stderr | `--time-phases`, `--print-gc-sections`, `--incremental-report` | exit 0, output (and state) | exit 0 | exit 0 |
| stdout | `--version`, `--help`, `-V`, `-v` | exit 0 | exit 0 | exit 0 |
| stdout | `-M` | exit 0, output, **map lost silently** | exit 0 | exit 0, **map lost silently** |
| stdout | `-Map=/dev/stdout`, `--mortar-map=/dev/stdout`, `--dependency-file=/dev/stdout` | exit 1 `cannot write output file /dev/stdout: Broken pipe`, no output | exit 0, output (`/dev/null`) | exit 1 `...: No space left on device` |
| stdout | `-o /dev/stdout` | exit 1 (refused: a FIFO) | exit 0 (`/dev/null`) | exit 1 `cannot write output file` |

`-t`, `--warn-common` and `--warn-unresolved-symbols` are refused
options; there is no `--print-*` option beyond `--print-gc-sections`,
`--print-map` (`-M`) and the refused ones.

## The references

The same cases with GNU ld 2.44 (`ld.bfd`), lld 19.1.7 and 22.1.8,
mold 2.37.1 (lld and mold print `--print-gc-sections` on standard
output, GNU ld on standard error). "Gone" under `SIGPIPE` at its default
(a shell); "gone, ign." with `SIGPIPE` ignored, which is mortar's
situation.

| case | GNU ld 2.44 | lld 19 | lld 22 | mold 2.37.1 |
|---|---|---|---|---|
| errors, stderr gone | SIGPIPE, **0-byte output left** | exit 74 | SIGPIPE | SIGPIPE |
| errors, stderr gone, ign. / closed / full | 1 / 1 / 1 | 74 / 1 / 1 | 1 / 1 / 1 | 1 / 1 / 1 |
| warnings, stderr gone | SIGPIPE, **0-byte output left** | 0, output | 0, output | 0, output |
| warnings, stderr gone, ign. / full | 0, output / 0 | 0 / 0 | 0 / 0 | 0 / 0 |
| warnings, stderr closed | 0, **the warnings written into the output file** (46257 B for 23984) | 0 | 0 | 0 |
| `--version`/`--help`, stdout gone | SIGPIPE | 74 | SIGPIPE | SIGPIPE |
| `--version`/`--help`, gone ign. / closed / full | 0 / 0 / 0 | 74 / 0 / 0 | 0 / 0 / 0 | 0 / 0 / 0 |
| `-M`, stdout gone | SIGPIPE, 255-byte output left | 74, no output | SIGPIPE, no output | SIGPIPE, output |
| `-M`, gone ign. | 0, output, map lost | 74, no output | **1, no output** | 0, output, map lost |
| `-M`, closed | 0, **the map written into the output file** | 1, no output | 1, no output | 0, output |
| `-M`, full | 0, map lost | 1, no output | **1, no output** | 0, map lost |
| `-Map=/dev/stdout`, gone ign. | 0 ("not a regular file") | 74 | 1, no output | 0, map lost |
| `-Map=/dev/stdout`, closed | 1 (cannot open) | 1 (cannot open) | 1 (cannot open) | 1, output left |
| `-Map=/dev/stdout`, full | 0, map lost | 1 | 1 | 0, map lost |
| `--print-gc-sections` (their stream) gone ign. / full | 0 / 0 | 74 / 0 | 1 / 1 | 0 / 0 |
| `-t`, stdout gone ign. | 0 | 74 | 0 | (unknown option) |

What a build system needs, from these: a pipe's reader leaving never
turns a link into a crash or a half-written file (GNU ld's 0-byte
output after `SIGPIPE` is the worst row); the status is the link's for
messages (every reference with `SIGPIPE` ignored, lld 19 aside); an
output asked for and lost is not a success (lld 22's choice for `-M`
and `-Map=/dev/stdout`; mortar already made `-Map=/dev/stdout` an error
in WP-087). That is §3.15 as written; the brief's starting point is
kept, with `-M` counted among the outputs.

## What mortar does now

| stream | what | gone | closed | full |
|---|---|---|---|---|
| stderr | errors | exit 1, no output | exit 1 | exit 1 |
| stderr | warnings, success | exit 0, the same output | exit 0 | exit 0 |
| stderr | `MORTAR_STEPS=1`, success / failing / incremental | 0, output / 1, none / 0, output and state | same | same |
| stderr | `--time-phases`, `--print-gc-sections` | exit 0, output | exit 0 | exit 0 |
| stdout | `--version`, `--help`, `-V`, `-v` | exit 0 | exit 0 | exit 0 |
| stdout | `-M` | exit 1 `cannot write output file standard output (-M): Broken pipe`, no output | exit 0 (`/dev/null`, S-4) | exit 1 `...: No space left on device`, no output |
| stdout | `-Map`/`--mortar-map`/`--dependency-file` `=/dev/stdout` | exit 1, no output (unchanged) | exit 0 | exit 1, no output |

No case raises a signal; no temporary name is left in any case (the
image-phase reader of the defect, three runs: exit 0, the output alone).

## The sites

The one writer is `crates/mortar_diag/src/stream.rs`: `to_stderr`
(drops a failure), `to_stdout` (returns it), `stderr_is_terminal`. It
is in `mortar_diag` because every crate that printed depends on it
already (`mortar_core`, `mortar_image`, `mortar`), the verifier
`mortar_plumb` may depend on it (`mortar_elf` + `mortar_diag` only), and
it depends on nothing.

| site (main 675550c) | what | now |
|---|---|---|
| `crates/mortar_core/src/par.rs:722` | `eprintln!` of a `MORTAR_STEPS` region | `to_stderr` |
| `crates/mortar_core/src/wp032b_steps.rs:59` | `eprintln!` of a step | `to_stderr` |
| `crates/mortar_image/src/fill.rs:287-292` | three `eprintln!` of fill's counters | one `to_stderr` |
| `crates/mortar/src/front.rs:1116` | `eprint!` of input's and resolve's steps | `to_stderr` |
| `crates/mortar/src/main.rs:17` | `stderr().is_terminal()` | `stderr_is_terminal` |
| `crates/mortar/src/main.rs:73,78-83,90-94` | `write_all` on `stdout()`/`stderr()`, errors ignored | `to_stdout`/`to_stderr`, one write of the whole standard-error text |
| `crates/mortar/src/lib.rs` (`-M`) | the map returned in `Outcome::Linked::stdout`, printed by `main` after the verdict | `mortar::run` (the executable's entry) prints it with `to_stdout` after the dependency file and before the state; a failure is `cannot-write-output` at key `(105, 0, 0)`. `invoke`/`invoke_in`/`replay_link` still capture it in `stdout` (`PrintMap::Capture`). |

`crates/*/examples` print with `println!` and are not shipped (benches
and tools); `xtask` and the tests are outside the rule.

Other panics reachable from a failed write: none. No `BufWriter` or
`LineWriter` over a standard stream exists in a shipped crate; std's
flush of standard output at exit ignores errors, and the writer flushes
before it returns anyway. `incremental.rs`'s report to a file
(`--incremental-report=FILE`) failing is a line on standard error, not
an error, as before (WP-061's choice; unchanged here).

## Tests

- `crates/mortar/tests/streams.rs`, on the built binary, one test per
  row of the table above, each with the stream gone, closed and full:
  `errors_to_a_broken_stderr`, `warnings_to_a_broken_stderr`,
  `steps_to_a_broken_stderr` (success, failure, incremental),
  `listings_to_a_broken_stderr`, `answers_to_a_broken_stdout`,
  `print_map_to_a_broken_stdout`, `written_files_to_a_broken_stdout`.
  Each checks the exit status, no signal and no core, and the directory:
  the output byte-equal to the same link with its streams read, or no
  output, and never a temporary name. The pipe is made with
  `std::io::pipe`, its read end dropped before mortar starts
  (deterministic); the closed descriptor by `sh -c 'exec ... 2>&-'`.
  With main's `par.rs` and `wp032b_steps.rs` put back,
  `steps_to_a_broken_stderr` fails (the process ends by a signal).
- `crates/mortar_diag/tests/streams.rs`: the source scan of S-5 (with
  main's two sites put back it names `par.rs:722` and
  `wp032b_steps.rs:59`) and a check of the scanner on planted lines.
- `mortar_testutil::run_with_streams`: `run_with` with standard output
  and standard error given rather than captured (the jobserver token as
  `run_with`).

## Not verified

- x86-64 natively is verified by the hosted lane only; the experiments
  above ran on AArch64.
- A terminal that hangs up (`EIO` on a tty) was not reproduced; it is a
  write error like the others and takes the same path.
- `/dev/full` for an output file named by `-o` on a regular file system
  (a real `ENOSPC` mid-image) is WP-026's `cannot-write-output` path and
  was not re-measured.
