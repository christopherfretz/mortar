# WP-087 — a file the link writes is not a file it reads, or another file it writes

`spec/cli.md` §2.6.4 and §3.14, `spec/diag.md` (`written-file-clash`),
`spec/image.md` I-58, I-58a, I-66, I-79a, `spec/model.md` §8 (phase
95), `spec/incr.md` IN-17. Before this package `-Map=a.o` replaced the
input `a.o` with the map and exited 0, and `-Map=/dev/stdout` run as root
renamed a temporary file over the `/dev/stdout` symbolic link.

## What landed

- **The rule** (`spec/cli.md` §3.14): no file the link writes is a file
  the link read, or a file it writes for another option. It is decided
  after the front (every file read is known, including the ones a search
  or a script found) and before the image phase creates anything; a
  clash is `written-file-clash`, one per written file, key `(95, 0, n)`:
  `-Map=a.o names the input a.o; nothing is written to it`.
- **One registry.** `mortar_cli::table::WRITES` lists the 15 rows whose
  value is a file or directory the link writes, with a role; `READS`
  lists every other path-valued row. A table test fails while a row whose
  meta says `FILE`, `PATH` or `DIR` is in neither list. The facade
  (`crates/mortar/src/written.rs`) builds a link's written files from
  `WRITES` (the output, then the last use of each honored row, then the
  incremental state and report), and a unit test fails while an honored
  row of `WRITES` is not in it.
- **What is compared.** By device and inode, following symbolic links
  (std `MetadataExt`), against the store's identities (`Store::inodes`:
  objects, archives, thin members, linker scripts, shared objects, which
  the front already has), the response files (recorded as they are read:
  `Parsed::response_files`), and the scripts the command line names; and
  against each other. Names not there yet compare by name and path, and
  by their directories' identity only when the names are equal and the
  paths are not. The temporary names of the writer (`.<base>.mortar-tmp`,
  `.<base>.mortar-old`) count as written.
- **The output** may still be a file the link read (I-62, kept: renamed
  into place after every input was read, as lld and mold accept and GNU's
  `ld -r -o a.o a.o b.o` needs); its temporary names may not.
- **Non-regular targets are outside the rule** and written in place: a
  directory (I-57), a character device, a FIFO or a socket, following
  symbolic links. New: the maps and the dependency file are written in
  order into a device or a FIFO (I-79a), and a symbolic link through a
  `/proc/<pid>/fd` directory to a regular file (`-Map=/dev/stdout >
  a.map`) is written through, truncated (I-58a). `remove_stale_output`
  (I-66) no longer removes a symbolic link to a non-regular file or a
  descriptor alias, nor a response file.
- **`incremental-file-clash` retired**: incremental mode's own check
  (`start` before the front, `Session::clear_of` after it) is replaced by
  the one rule, to which the session gives its two files
  (`Session::written`). The id stays in `IDS`, never reused.

### Why a new key and not `incremental-file-clash` generalised

`incremental-file-clash` has the fields `option`, `path`, `what` and the
text `{option}={path} names {what}`; generalising it would rename an
incremental-area key into the files area and keep a misleading name. A
new key in the files area, `written-file-clash { written, what }`,
covers every writer (and the temporary names, whose `written` is not an
option), and the old one is kept as a retired id.

GNU's message for `-o` naming an input: `input file 'a.o' is the same as
output file`; it compares names and symbolic links' targets, not inodes
(the hard link passes). It opens the map before reading the inputs, so a
map over an archive or a thin member truncates it and the link then
fails. mold writes the output in place: `-o a.o` fails with the input
destroyed (`section header is out of range`), `-Map=a.o` dies of
`SIGBUS` (the input is mapped and truncated).

The `/dev/stdout` finding: run as root in this container, mortar before
created `/dev/.stdout.mortar-tmp` and renamed it over `/dev/stdout`
(`/dev` is writable there). The measurement did this twice; the link was
restored (`ln -s /proc/self/fd/1 /dev/stdout`). As a non-root user the
same command fails with `cannot-open-output`. Both are fixed by I-58a and
I-79a.

## Cost (scope 3)

A plain link pays nothing per input: the files read are compared through
the identities the store already holds. Per written file: one `stat`, and
one per temporary name (3); a file written whole that is a regular file
costs one `stat` more when it is written (I-79a's test).

`strace -f -c` on protoc (`cxx-medium-g-static`'s command line:
`-o protoc-3.21.12.0 --dependency-file=CMakeFiles/protoc.dir/link.d`,
231 inputs; the output and depfile exist):

| syscall | before (b096d06) | after |
|---|---|---|
| `statx` | 101 (31 errors) | 107 (35 errors) |
| `openat` | 31 | 31 |
| `fstat` | 5 | 5 |
| `renameat` | 4 | 4 |
| `unlinkat` | 2 | 2 |

The differences, by name: `+` the output, its two temporary names, the
depfile, its two temporary names (the check, 6 `statx`, 4 of them
`ENOENT`); `+` one `stat` of the depfile when it is written (I-79a); `−`
one for the response file: a `stat` by path and an `fstat` replaced by
`open` + one `fstat` (§2.6.4). Net `+6`, none per input; the totals vary
by ±1 `openat` between runs of either binary.

Wall time and peak RSS on the same link (`cxx-medium-g-static`, the
bench's heaviest static workload), release builds of b096d06 and of this
package, runs interleaved (before/after, then after/before) after one
warm-up each; 1-minute load 5.3–7.1 on a shared 12-core host:

| link | runs | before: wall median (min–max) | after | before: max RSS median (min–max) | after |
|---|---|---|---|---|---|
| plain | 9 | 160 ms (154–189) | 161 ms (153–172) | 247.6 MB (245.4–249.5) | 249.0 MB (246.6–250.9) |
| plain | 15 | 162 ms (155–182) | 159 ms (157–183) | 249.8 MB (246.7–253.8) | 249.4 MB (245.1–252.0) |
| `--incremental=full` | 9 | 506 ms (358–635) | 427 ms (381–507) | 302.3 MB (300.2–308.1) | 301.8 MB (298.1–305.3) |
| `--incremental=full` | 9 | 440 ms (359–605) | 498 ms (329–571) | 302.8 MB (297.6–305.1) | 303.5 MB (298.3–306.0) |

Within noise in both modes: the check is 6 to 10 `stat` calls (the
incremental mode adds the state and the report, 3 each) against a link of
~160 ms; the incremental-mode spread comes from writing its 8 MB state.

## Follow-ups

- The state's temporary file `.tmp-<pid>` is opened with `File::create`,
  which truncates an existing file of that name (`crates/mortar/src/incremental.rs`,
  the state writer): `create_new` would make it unable to replace
  anything (WP-063/061B own the file).
- A named FIFO with no reader at a written path blocks the link until a
  reader opens it (as for every program); not guarded.
- A failed link whose output is a descriptor alias (I-58a, `-o
  /dev/stdout > f`) leaves the partial bytes written in `f` (written in
  place, nothing to rename).
- GNU's `-Map=DIR` (the map written as `DIR/<output>.map`) is not
  supported: a directory is `cannot-open-output`.
- `-T` and the other script options become checked through the store
  when they stop being refused; `Reads::new` already stats `plan.scripts`.
