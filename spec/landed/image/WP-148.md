# WP-148: a merge section's end under `-pie`; `-E` of objects alone (landed)

Two pre-existing defects found by WP-136 and WP-147. Spec edits:
`spec/synth.md` S-18, S-19; `spec/resolve.md` §9.6, §10.1;
`spec/dyn.md` D-21, §13.1.

## Part 1: a reference at or past a split merge section's end

**Shape.** GNU as writes `.dc.a .Lend` (a local label after the last
string of a `SHF_MERGE` section, addend 0) as the section symbol plus
`sh_size`. It does the same for AArch64 `adrp`/`add :lo12:` of the label.
x86-64 `lea .Lend(%rip)` keeps the label; a `.reloc` keeps a named local.
`.comment` + size is the same shape (`.comment` is `SHF_MERGE|SHF_STRINGS`).

**Before.** A static link refused it as S-18, but the refusal named no
place. A `-pie`, `-static-pie` or `-shared` link stopped with the
internal error `.rela.dyn: ... a RELATIVE record without S + A`. The
RELATIVE record's value closure returned `Option`, and S-18's refusal
became `None`, as if the key had no place (P-1).

**Measured** (GNU ld 2.44, lld 19, mold 2.37; AArch64, x86-64 and i386;
`-no-pie`, `-pie`, `-static-pie`, `-shared`, `--gc-sections`;
"zq7hel\0" is 7 bytes):

| shape | GNU ld | lld | mold | mortar |
|---|---|---|---|---|
| section + 7 (end), own string | end of string | refused: "offset is outside the section" | end of string | refused (S-18), at the referring place |
| section + 7, string deduplicated with an earlier copy | end of THIS input's bytes in the output (past the kept copy: +14) | refused | end of the kept copy | refused |
| section + 7, tail-merged string | its tail-merged layout | refused | start of the kept tail | refused |
| `.rodata.cst8` + 8 | past the constant | refused | an unrelated address (`gstr`) | refused |
| section + 8 (past), section − 1 | links, values differ | refused | +8 / segfault | refused |
| `.comment` + size | its offset | refused | assertion | refused |
| AArch64 `adrp`/`add` of the end label (code) | links | refused | links | refused, at `.text+0x0` and `+0x4` |
| `.debug_info` word naming the end | links | refused | links | refused (as before, now placed) |
| a label in the middle (section + 3, or the label) | +3 | +3 | +3 | +3 (unchanged) |
| a NAMED label at `sh_size` (`.reloc`) | end of string; dedup: past the kept copy | refused, even unreferenced | end of the kept piece | end of the kept piece (S-19/S-22, unchanged) |
| `.comment`'s section symbol / its first label, in a PIE | 0, `RELATIVE` A=0 | the same | assertion | the same as GNU ld and lld (unchanged) |

The references disagree on every end shape, so S-18's conservative
reading stands: the shapes are refused by name in every output kind,
from every referring section. `GLOB_DAT`, TPOFF and `IRELATIVE` cannot
name these targets:
- `GLOB_DAT` needs a global;
- TLS and executable merge sections are placed whole (S-6);
- a GOT reference with a non-zero addend is refused (S-21).

**Fix.**
- `crates/mortar_image/src/dynrel.rs`: `SectionCx::value` returns
  `Result<u64, Unvalued>`, with `Unvalued::Refused(Box<Diagnostic>)` (S-18)
  or `NotLive` (P-1, an internal fault).
- `push_records` and `section_records` return `RecordError::{Fault,
  Refused}`.
- `crates/mortar_image/src/link.rs`: `rela_dyn` returns
  `Result<_, Failed>`. It collects every refusal with its referring place
  (`file:(section+offset)`) and the target's section, sorted by key. The
  closure has `debug_assert!(live)` for P-1.
- `LinkTables::outside_merge` builds S-18's diagnostic. It also names the
  target as `{section}+{r:#x}` and gives the section's size.
- `reloc.rs`: the static refusal gains the same place.

**Tests.**
- `tests/link/split/merge-end.test`: every refusal, static and pie,
  `no-diag: internal error`; the linked middle and `.comment` shapes.
- `tests/link/split/merge-end-named.test`: the named end, mortar-only
  steps, run.
- `crates/mortar_image/tests/dynrel.rs`:
  `wp148_relative_without_a_value_is_refused_or_a_fault`.

**Verifier finding (on correct outputs).** `ld.bfd`/`mold -static` on
`main-end.o nend.o` (a `.reloc ., R_*_ABS64, lend` with `lend` after
`"zq7hel"`, `st_value == sh_size`) gives "R6 the reference to offset 0x7
of mergeable section '.rodata.str1.1' reaches other bytes". R6
(plumb.md §5.6) needs input byte r, and at r == sh_size there is none.
mortar's output of the same link passes: in it, the end is followed by
nothing R6 maps. The finding is why `merge-end-named.test`'s steps are
mortar's only.

## Part 2: `--export-dynamic` / `--export-dynamic-symbol` of objects alone

**Accepted and silently ignored before WP-148.** In a dynamic executable
(`-pie` or `-no-pie` with `-dynamic-linker`) with no shared object on
the line, both options did nothing: `.dynsym` held the null entry and
the weak undefined. There were two causes:
- `mortar_resolve::tables::shared_link` returned `SharedLink::default()`
  (both switches off) when no input is a shared object;
- `resolve.rs` ran the shared stage, which computes `exported`, only
  with a shared input or a shared output.

With libc on the line (gcc's own line), `-E` already worked and matched
lld and mold.

**Measured** (AArch64 and x86-64, raw `ld`, `a.o` defining a default
global function and variable, protected, hidden, internal, weak, COMDAT
(C++ inline), common, TLS, `_start`; with and without `libl.so`, which
references `cb_fn`/`cb_var` and defines `dup_fn`):

| line | GNU ld | lld | mold | mortar before | mortar after |
|---|---|---|---|---|---|
| `-pie -E`, objects | every default/protected global, COMDAT, common, TLS, weak, `_start` + `_edata`, `_end`, `__bss_start`… + 2 section symbols (AArch64) | the globals, no linker symbols | = lld | empty | = lld |
| `-no-pie -E`, objects | no `.dynamic` (static) | `.interp` only | = lld's PIE set (no `PT_DYNAMIC`) | empty | = lld's PIE set |
| `--export-dynamic-symbol=exported_fn`, `=cb_var`, `='exp*'` | the names (+ section symbols) | the names | the names | empty | the names |
| `-E --gc-sections` / `--export-dynamic-symbol=unref_gc --gc-sections` | kept, exported | kept, exported | kept, exported | collected, empty | kept, exported |
| `--dynamic-list` | the list | the list | the list | refused by name | refused by name (unchanged) |
| any line with `libl.so`, with or without `-E`/`--gc-sections` | = lld + linker symbols | `cb_fn cb_var dup_fn` (+ the `-E` set) | = lld | = lld | = lld (unchanged) |
| `-static -pie --no-dynamic-linker -E` | exports | exports | exports | null entry (D-1) | null entry (D-1, unchanged) |
| `-static -E` | no `.dynsym` | no `.dynsym` | exports | none | none |

There is no `.gnu.version` without versions in any of them. `.gnu.hash`
is mortar's and GNU ld's; lld and mold also write `.hash`. Hidden and
internal symbols are never exported.

**Rule.** `spec/resolve.md` §9.6 and `spec/dyn.md` D-21 already gave the
set. The new sentence is that the set does not depend on a shared object
being on the line. A link that loads no shared object and exports
nothing still computes no export set (no cost). The fix:
- `tables.rs`: `export_symbols()` is factored out and used by both
  returns;
- `resolve.rs`: the stage runs for `opts.output.dynamic && (export_dynamic
  || !export_symbols.is_empty())`.

**A needed library's references.** A symbol that a needed library
references and the executable defines is exported without `-E`
(`ref_dynamic`), both before and after. There is no mislink.

**Tests.**
- `tests/link/dyn/dynsym/export-dynamic-callback.test` (AArch64, x86-64):
  - (1) a `-nostdlib` executable with `-E` or `--export-dynamic-symbol`
    and an `LD_PRELOAD`ed library whose constructor calls the exported
    function and reads the exported variable. This fails on the old
    binary (empty `.dynsym`). Steps: PIE with lld, mold and mortar;
    `-no-pie` mortar only.
  - (2) a `dlopen`ed plugin that calls back and writes the variable,
    `-pie` and `-no-pie`.
  - (3) a needed library's callback without any option, `-pie` and
    `-no-pie`.
- `crates/mortar_resolve/tests/shared.rs`:
  `d21_exports_without_a_shared_input`.

**Reference findings met** (the reason for (1)'s restrictions):
- GNU ld's `-pie -E` of objects alone exports `_end`/`__end__` under a
  section index that does not hold them (verifier P-D7).
- mold's `-no-pie -E` of objects alone writes `.dynsym` and `PT_INTERP`
  with no `PT_DYNAMIC` (P-D4).

**What a verifier rule for an executable's exports must check:**
- Every `.dynsym` definition is a global, protected or default, non-local
  definition of the link, at the value `.symtab` gives it, in a section
  that holds it.
- No hidden or internal definition and no section symbol is exported.
- Every key `ref_dynamic` from a needed or used library, and every key
  also defined by one (interposition), is exported.
- Under `-E`, every visible global definition of a live object is
  exported. Under `--export-dynamic-symbol`, exactly those keys are,
  beyond the forced ones.
- Linker-defined keys are exported only when `ref_dynamic`.
- Every export is reachable through `.gnu.hash` (D-22 order, bloom).
- Under `--gc-sections`, an exported definition's section is kept.
- A static-pie has the null entry only (D-1).
- An executable with `.dynsym` has `PT_DYNAMIC` (P-D4 already).
