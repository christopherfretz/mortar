# WP-031 — `--gc-sections`

`--gc-sections` was refused by name in M1 (`spec/image.md` I-5). It is
now `supported`, along with `--print-gc-sections`,
`--no-print-gc-sections` and `--gc-keep-exported`. The collector is the
mark of I-6 to I-8 and I-109. It lives in `crates/mortar_live/src/gc.rs`,
and its relocation reader is `read.rs`. It sits beside the no-gc path,
which stays in `lib.rs` (`liveness`, `frag_live`). Edges come only from
relocation records through the tables, never from instruction bytes, so
the collector is architecture-independent. It is exercised on AArch64
natively and on x86-64 under qemu.

## The claims of E14, verified (`spec/image.md` §3.2 amended in place)

Every experiment linked hand-written objects with GNU ld 2.44, lld 19/22
and mold 2.37.1. Where the three differ, the rule mortar adopts is the one
that cannot drop something a running program or a tool needs.

## The mark (file:line in `crates/mortar_live/src/gc.rs`)

- **Facts, one parallel pass per file** (`collect` :220, `file_facts`
  :399). Each section gets bits `ALLOC=1`, `ROOT=2` and `EDGES=4` (:78-87).
  A section the mark did not examine defaults to `ROOT|EDGES` (:227, :424):
  the mark never drops what it has not read.
- **Roots, by section rule** (:441-456):
  - `Assignment.keep`;
  - by type: a note, or a non-alloc section, unless it is in a group with
    an alloc member (`section_groups` :483);
  - `.eh_frame`;
  - a section kept but without a place (`OutOf::Consumed`);
  - a startup output section name (`startup_output` :189) or input name
    (`startup_input` :173).

  A `SHF_LINK_ORDER` section is never a root (:443).
- **Roots from definitions** (:269-281, round 0 at :323-339):
  - the keys resolution roots (`LiveInputs.roots`, from
    `mortar_resolve::Outcome.roots`: the entry, `-u`,
    `--require-defined`);
  - every `EXPORTED` key;
  - with `--gc-keep-exported`, every Defined non-local key of default or
    protected visibility.

  `def_target` (:536) gives a definition's section and offset. A
  conditional `PROVIDE` of `__start_X` or `__stop_X` targets the
  C-identifier sections named `X` (`Target::Named`, :558-568). A common,
  absolute or shared definition has no section and targets nothing.
- **Edges from records** (`Walk::records` :775, `record_target` :578):
  - a local or section symbol goes to its section, at the symbol's value,
    plus the addend for a section symbol;
  - a global goes through `sym_map`, then `redirect` for an undefined
    mention, then `def`;
  - a target inside a split merge section marks the piece and its fragment
    (`Marks::at` :126).

  Records are read with the scan's reader discipline (`read.rs`). A read
  failure is a keyed diagnostic `(50, file, section)`, never "no edges";
  so is a section that has relocations but no readable object (:775ff).
  Debug-named sections and `.eh_frame` have no `EDGES` bit (:464).
- **Other edge classes** (`Walk::walk` :747):
  - `SHF_LINK_ORDER` dependents follow their target (:754-759, I-109);
  - group mates are marked whole (:761-770);
  - FDE edges (:818 `frames`): when a code section is marked, the
    relocations of its FDEs and their CIEs are walked (`eh_edges` :623),
    which reaches the LSDA and the personality routine.
- **Rounds** (:355-369):
  - `Marks` holds atomic booleans set with `swap(true)`;
  - a round's units are sections, split by `SCAN_BLOCK` records (`units`
    :715);
  - the workers' buffers become the next round;
  - errors are reported by least key (`least` :381).

  The result is a set, whatever the schedule.
- **Printing**: `mortar_live::print_gc_sections` (`lib.rs:183`) writes the
  lines in `removed()` order (`lib.rs:157`), which is SectionId order,
  i.e. (file, section index). It skips size 0 and writes `name[sig]` for
  COMDAT members.
- **Wiring**:
  - `mortar/src/lib.rs` `removed_lines` (:230): only with both gc and
    print;
  - `Invocation.removed` is written to stderr before the report, on
    success and on failure (`main.rs:36`, `:47`);
  - `Plan.shaping.{print_gc_sections, gc_keep_exported}`.

## Determinism

`i8_the_mark_is_schedule_independent` runs 24 links: both input stores ×
threads 1, 2, 4 and 8 × three `MORTAR_SCHED_SEED`s. The output, the map
and the print lines are byte-identical across all of them. On x86-64,
`x64.rs`'s determinism test is unchanged.

## The differential (`/tmp`, compact version in the tests)

The matrix has 132 configurations: 6 programs × drivers × 6 flag sets,
each linked with GNU ld, lld 22, mold, mortar, mortar without gc and GNU
ld without gc, all with `--gc-sections --print-gc-sections`.

- **Programs**: c (TLS, stdio), gcstress (`__start_`/`__stop_`,
  constructors, retain, unused functions), cxx, cxxfull (exceptions,
  RTTI, `thread_local`, iostream, locale), tmpl (templates in 5 TUs,
  static registration, TLS, exceptions) and fortran.
- **Drivers**: gcc, clang, g++, clang++ and gfortran on AArch64; the same
  five on x86-64 (`x86_64-linux-gnu-*`, `clang --target`) under
  qemu-x86_64.
- **Flag sets**: O0, O2, O2 -g, -ffunction-sections -fdata-sections at
  O2, at O0 -g and at O2 -g.

findings on all 132. Static protoc (main.cc.o, libprotoc.a and

## Without `--gc-sections`: byte-identical

Against main 1d578d4 (the merged base, built in `/tmp`), mortar without

## Debuggers

`crates/mortar/tests/debuggers.rs` gains gc variants: `gc_sessions_c_gcc`,
`gc_sessions_cxx_gxx`, `gc_sessions_cxx_clangxx`, `gc_dwarf_c_clang`,
`gc_dwarf_cxx_gxx`, `gc_dwarf_cxx_clangxx` and `gc_dwarf_fortran_gfortran`.
They compile with `-ffunction-sections -fdata-sections`, add unused
functions (one that throws), and use DWARF 4 and 5 at -O0 and -O2.

- **Sessions**: gdb and lldb transcripts are equal to GNU ld's with gc.
- **TLS**: under gc, gdb cannot read TLS with either linker ("Cannot find
  thread-local variables on this target"). Both collect glibc's
  `_thread_db_*` `.rodata` in `libc.a(pthread_create.o)`. The test
  asserts it.
- **`llvm-dwarfdump --verify`**: mortar's complaints are a subset of
  GNU's.
- **gdb**: gdb's complaints are GNU's, apart from the known I-47 ones;
  the DWARF 5 rnglists case is xfail'd, as without gc (WP-027e fixes it).
- **Addresses**: mortar's debug addresses are in-section or the
  tombstone; the unused functions' subprograms are tombstoned; no
  address 0 claims code.
- **`tests/gc.rs` `debuggers_read_a_collected_program`**: gdb breaks in
  the thrower, and no dead function is at 0.

## Spec findings

- E14 Q3 refuted the old I-7 line ("each member by its own edges"): GNU
  and lld keep groups whole.
- I-6's non-alloc root needed a group exception (Q1), and the "a section
  the mark could not describe" root needed writing down.
- I-7 now states that non-debug sections' relocations are edges. GNU
  marks through `.note.stapsdt` to `.stapsdt.base`; without this,
  libstdc++'s eh_catch.o gave `discarded-section-reference`.
- I-10 states the print format and order and the size-0 skip.
- I-9's cost estimate (0.8 ms) is replaced by the measurement.
- I-47 needed the case of a debug reference to a dead merge piece. It is
  now a tombstone, like a dead section.
- resolve.md §4.7 records `Outcome.roots`.

## Follow-ups

1. **Mark speed**: 3× lld's `markLive`. Option (a): continue in the
   worker on its newly marked sections and keep the rounds only as
   load-balancing, which leaves the set unchanged (a least fixed point);
   this needs an I-8 amendment. Option (b): cache per-file symbol
   lookups in `record_target`.
2. `-u` and `--require-defined` are refused by the command line. Their
   gc root path (`Outcome.roots`) is wired and only exercised through
   `-e`.
3. The DWARF 5 `.debug_rnglists` tombstone wrap (WP-027e) is more common
   under gc. The gc debugger tests carry the same xfail.
4. lld's default `start-stop-gc` refuses some programs that GNU links. The
   harness passes `-z nostart-stop-gc` to lld.
5. `--gc-sections` with `-r` or `-shared` stays refused (I-11; M4).
