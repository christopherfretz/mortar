# WP-026s — `mortar_live` and `mortar_scan`

`mortar_live` is liveness (`spec/image.md` §3, phase 50) in its M1 form.
`mortar_scan` is the scan driver (§4, phase 70). The driver:

- cuts the scan units;
- runs `Arch::scan` over them in parallel;
- merges the demands;
- builds the record index;
- groups the events into diagnostics.

## What is implemented

| spec | where | state |
|---|---|---|
| I-1 live = `Kept` | `mortar_live::liveness` | done |
| I-2 `frag_live` | `mortar_live` `frag_live` | done. When every merge section is live, it is all true without a walk. Otherwise idempotent `AtomicBool` stores per piece of a live merge section. |
| I-3 FDE rule, CIE | `Liveness::fde_live`, `mortar_live::eh_piece_live` | done |
| I-4 no diagnostic; key `(50, F, idx)` | `mortar_live::PHASE` | done |
| I-5 `--gc-sections` refused | `liveness` returns `(Key(50,0,0), refused Option "--gc-sections")` | done. The table's shape is the M2 mark's: a column of booleans marked by idempotent stores, nothing to change. |
| §4.1 units, `SCAN_BLOCK` cuts never inside a sequence | `driver::units`, `driver::continues` | done. A cut moves forward while `unit_window` of the record after the cut names a unit that starts before it (see R-3 below). |
| §4.1 step 2, `pool.map` over units | `mortar_scan::scan` | done: one parallel call for a link that reports nothing |
| I-13 live sections only; sites through `RelocAt::site` | `driver::run_unit` | done for the resident store. The staged store's `copy_to` blocks are not done (follow-up). |
| I-14 non-alloc fast path | `Arch::scan` with `PlaceFacts{alloc:false}` | as `Arch::scan`. a64 §13.2 already raises nothing for non-alloc places, so there is no separate path. |
| I-15 outputs | `Scanned{demands, order, diagnostics, stats}` | done. Dynamic counts are summed per section over blocks. |
| I-16 load-then-`fetch_or` | `driver::Sink` | done. Locals are or-ed in a unit-local run, then sorted and or-merged. |
| I-17 errors at scan keys, unit buffers in unit order | `driver::Sec::fault`, `run_unit` | done. A unit does not stop at an error. |
| I-17 malformed relocation sections and records | `driver::units`, `Sec::open`, `Sec::fault` | done. Each is refused by name: <ul><li>unreadable table: `(70,F,idx<<32)`</li><li>`sh_info` ≠ section</li><li>`sh_link` ≠ symtab (unless every record names symbol 0)</li><li>`r_sym` out of range (`relocation {i} of section {s} names symbol {r}, but the symbol table has {n} entries`)</li><li>offset outside its section</li><li>more than 2^32−1 records (Feature)</li></ul> |
| §4.4 events, I-18 | `events::{EventClass, RefId, Event, GroupKey}`; `driver::on_undefined` | done; the R-1 point is isolated (below) |
| I-19 surviving references only | `driver::run_unit` | done. No event for: <ul><li>consumed members (`Arch::consumed`)</li><li>sections that are not live</li><li>undefined weak</li><li>verdict `Ignored`</li></ul> |
| I-110 undefined from non-alloc only | `run_unit` | done |
| I-20 per-unit accumulators | `events::{Acc, UnitEvents}` | done: a hash map for lookup only, then a vector sorted by `GroupKey` |
| I-21 merge | `events::merge` | done: concatenate in unit order, stable `pool.sort_by_key`, reduce left to right |
| I-22 diagnostic | `report::group` | done. <ul><li>key at `first[0]`</li><li>`>>> referenced by file:(section+0xoff)`, with `r_offset` re-read from the record</li><li>`referenced N more times`</li><li>hidden note, `comdat-mismatch` copies and ODR note, discarded `DefinedIn`</li><li>`gnu-warning` text up to the first NUL</li></ul> |
| I-23 shared keys | — | by construction. `GnuWarning` and `Undefined` on one record share a key, and the collector orders them by text. |
| I-24 error limit counts groups | the collector, groups as diagnostics | done (test) |
| I-29 `RecIndex` Sorted / Permuted | `RecIndex`, `driver::permutation` | done. `Permuted` is a stable sort of the record indexes by `r_offset`. Block results compose: sorted, and last ≤ next first. |
| arch §3.5 overlaps across blocks | `lib.rs` `block_overlaps`, `driver::rewalk` | done, exact. Each block decides its own overlaps. A section whose blocks' window extents intersect is re-walked over the connected component of intersecting blocks only. |

Not done:

- `--gc-sections` (M2).
- The staged store's `copy_to` reads and `REC_SAMPLE` (I-13, I-29). Only the resident store is used in M1.
- The REL path (`Recs` reads REL addends through `classify` and `read_addend`). It is written but untested, because AArch64 has no REL inputs; it gets tested when i386 arrives.

`mortar_scan`:

pub const PHASE: u16 = 70;
pub struct ScanInputs<'a, 's> { inputs, resolution, liveness,

    gnu_warnings: &[(SymbolId, FileId, SectionIndex)] }

pub struct ScanOptions<'p> { output: OutputKind, dynamic: bool, proof: &dyn CodeProof }
pub trait CodeProof: Sync { fn mark(..) -> Option<bool>; fn runs(..); }  // NoProof

Interface points, flagged:

- **`CodeProof`.** It is injected through `ScanOptions` because `Arch` has no method that turns mapping symbols into proof runs. The AArch64 adapter is `tests/support::A64Proof`, over `mortar_a64::mapping`. Follow-up: an `Arch::proof_runs` method, or the adapter in `mortar_a64`.
- **`RecIndex`.** It lives in `mortar_scan` and is sparse: only the unsorted sections are stored, and every other section is `Sorted`. model §4.5 names it as a phase cache. Follow-up: move the type to `mortar_core` when fill (WP-027) consumes it.
- **`ScanInputs::comdat_mismatch` and `gnu_warnings`.** They are taken from `mortar_resolve::Outcome`, sorted by the scan. `assignment` is `Option`: it is used only for an `Internal` definition's section, and is `None` before layout.

## The two WP-023b points (isolated)

- **R-1 `reference(class, group)`.** `driver::on_undefined` (driver.rs:404) maps `DemandOut::undefined(key, record)` to `ComdatMismatch` when the key is a mismatch key, and to `Undefined` otherwise. `DiscardedSection` and `GnuWarning` are found by the driver from the record's target: a dead local of the same file, or a warned key. When R-1 lands, `Sink::reference` replaces both.
- **R-3 `sequence_extent`.** `driver::continues` (driver.rs:107) moves a cut while `unit_window(record i)` reports a unit `< i`. When R-3 lands, it becomes one call.

## E2E differential (`crates/mortar_scan/tests/e2e.rs`)

Each program is compiled by GCC 14 with `-O2 -g` and run through the link line of `gcc -static -###`. The phases are `mortar_cli::parse` → `load` → `resolve_inputs` → `liveness` → `scan` with `A64::M1`.

(a) No diagnostics in any phase for C (TLS, libm), C++ (iostream, exceptions, `thread_local`, libm) or Fortran (allocatable, `write`).

(b) Demands against the same objects linked by ld.bfd 2.44 and ld.lld 19.1.7 (`-static`):

| program | mortar `GOT` keys | `GOT_TPREL` | GD / DESC | IPLT | ld.bfd `.got` / `.got.plt` / IRELATIVE | ld.lld `.got` / `.got.plt` / IRELATIVE |
|---|---|---|---|---|---|---|
| C | 111 | 22 | 0 / 0 | 5 | 122 / 8 / 5 | 111 / 5 / 5 |
| C++ | 584 | 22 | 0 / 0 | 5 | 585 / 8 / 5 | 584 / 5 / 5 |
| Fortran | 121 | 24 | 0 / 0 | 5 | 132 / 8 / 5 | 121 / 5 / 5 |

Each difference is explained by a rule, and `explained()` asserts every one:

- **IPLT.** Mortar's IPLT keys equal the IRELATIVE relocations of both linkers (a64 §10.4). `.got.plt` is the IPLT slots plus ld.bfd's 3 reserved words.
- **`.got` against `GOT` keys.** It is equal for ld.lld. ld.bfd has one more word, its reserved `.got[0]`. Mortar keeps a slot per `GOT` key: R5 relaxes the code, not the slot (kind 2), which is lld's behaviour.
- **TLS.** Static IE is relaxed to LE by R3, and the slot stays (kind 2): 22–24 `GOT_TPREL` keys. lld drops all of them, which is asserted as 0 extra words. ld.bfd keeps 10 in C and Fortran and 0 in C++, which is asserted ≤ mortar's `GOT_TPREL` keys. The slots mortar keeps are allowed and harmless: a static output's TP-offset slots hold constants (synth S-72).

(c) The C++ program linked without `-lstdc++ -lm` gives 26 undefined symbols. Mortar's `undefined-symbol` set equals the set of ld.bfd's `undefined reference to` lines (`--no-demangle`) exactly. No other diagnostic is reported.

## Performance (`crates/mortar_scan/examples/scan_bench.rs`)

These are release builds, measured on a shared 24-core AArch64 host under a load average of 33–44, which is noisy. Each thread count runs in its own process. The scan is the median of `RUNS` runs, and VmHWM is the peak RSS of the process, including the loaded inputs.

- **`cxx-medium-g`.** Its `response.txt` is a dynamic PIE link and M1 is static. Mortar's CLI refuses 6 of its options or inputs (the shared libraries), so the libraries' symbols are not defined. That gives 220 `undefined-symbol` groups from 23,320 events, which makes this run exercise the event path too. The record count is the live sections' (1.73 M of 2.2 M).
- **Synthetic objects.** They are written by the example: per 5 records, `bl` to a global of another file, `adrp`/`add` to a local, and `adrp`/`ldr` through the GOT. Every record is alloc, so every one gets the instruction checks of a64 §3.
- **Par calls.** It is 1 in every run: the unit map. Sorts count only above `SORT_RUN`, and no event sort or permutation reached it here.
- **Scaling.** It is near-linear to 8 threads on both workloads: 4.3× on `cxx-medium-g`, 5.8× on 10^7 and 8.8× on 10^8. The 10^8 one-thread time suffers from memory pressure and the host's load.
- **I-16 cost model gap.** The model is 3.35–3.68 ns per record. Measured, it is 44 ns per record on `cxx-medium-g` (87% debug) and 110–177 ns per record on the alloc-only synthetic. Two candidate costs are visible:
  - Every record's `unit_window` is collected and sorted per unit for `seq::overlaps` (arch §3.5), which is O(n log n) per block.
  - The symbol is decoded per record (`View::key_of`, `local_section`).

  Not profiled: there is no profiler in the container. This is a follow-up.

## Glue for WP-027

`tests/support/mod.rs::link` is the phase glue. It contains nothing test-only except the tools, and the bench reuses it through `#[path]`:

1. `mortar_cli::parse(args)` → `plan`. The plan's diagnostics come first.
2. `mortar_input::load(&plan, &LoadEnv{cwd, pool}, &store, &collector)` → `Inputs`.
3. `mortar_resolve::resolve_inputs(&inputs, &plan, &pool)` → `Outcome` (resolution, diagnostics, `comdat_mismatch`, `gnu_warning_syms`).
4. `mortar_live::liveness(&LiveInputs{inputs, resolution, assignment, split}, LiveOptions{gc_sections: plan.shaping.gc_sections}, &pool)`. An `Err` is a diagnostic to emit.
5. `mortar_scan::scan(&arch, &ScanInputs{.., assignment: None, comdat_mismatch: &mismatches(&outcome), gnu_warnings: &outcome.gnu_warning_syms}, &ScanOptions{output: output_kind(plan.kind), dynamic: false, proof: &A64Proof}, &pool)`. Then emit `scanned.diagnostics` to the collector.

`output_kind`, `mismatches` and `A64Proof` are in the same file. The driver gives `Split` and `Assignment` from `mortar_merge` and layout. Liveness runs before layout, so `Assignment::empty` is correct for M1: no `Internal` section is needed.

## Spec ambiguities and decisions

1. **§4.4 `DiscardedSection` drop reasons.** The resolve.md §6.3 table (debug names, `.eh_frame`, `.gcc_except_table`: no error) is applied to every reason a section is not live, not only COMDAT. This is the same as I-12 for M2. Any other dropped section (`SHF_EXCLUDE`, stripped) reached from a kept alloc section is `discarded-section-reference`.
2. **Demands of dead targets.** A reference to a local of a section that is not live raises no demand: it becomes a tombstone or 0, as in §6.1. A slot for it would be dead weight.
3. **A weak reference to a mismatch key** makes no event, by I-19's weak rule. resolve.md §6.3 (b) does not say whether a weak reference counts.
4. **A withdrawn conditional (`PROVIDE`) symbol whose verdict is `Bound`** reports `undefined-symbol` as an error. The verdict's error/warning split covers only real undefined keys.
5. **`GnuWarning` from any live section**, including debug sections and the file that defines the warning. GNU ld warns per reference from code. The text of resolve.md §10 does not restrict it, so the scan reports it from any live section.
6. **I-14** needs no separate path. a64 §13.2 makes `Arch::scan` cheap on a non-alloc place, and a second code path would be a second semantics.
7. **I-22 discarded `DefinedIn`** uses `Place::symbol(file, section name)`, so the line reads `>>> defined in a.o:(.text.x)`.
8. **I-22 hidden note** is added only for `Undefined` groups, and only for global keys.

Spec fixes on this branch: none were needed in §3–§4.
