# WP-013 — the `Arch` trait

`spec/arch.md`: the contract between the architecture-independent linker
and one architecture. `mortar_arch` defines it (WP-022); `mortar_a64`,
`mortar_x64` and `mortar_x86` implement it. Design only.

## What it does

- §2 vocabulary: output and target kinds, value terms, fields, checks,
  the `Howto` of a relocation type.
- §3 the trait: `classify`, the REL addend read and write-back, `scan`
  into a union-only demand sink, sequences over neighbouring records,
  `apply` with a byte window, PLT/GOT/thunk/erratum shapes, TLS variant,
  `.eh_frame_hdr` encodings, dynamic relocation roles and RELR, tombstones,
  undefined weak, GNU property merging.
- §4 demand flags and the generic class table (class × output × target
  kind → demands or error).
- §5 what is decided when, and the proof obligation that demand is
  conservative.
- §6 range extension and erratum patches as a monotone fixed point.
- §7 one overflow rule and two siblings, with diag keys.
- §9, §10 requested changes to `spec/model.md` (M-1..M-7) and
  `spec/diag.md` (three kinds).
- Appendices A and B: x86-64 and i386 walked through the trait;
  Appendix C: what that forced.

## Decisions the spec records

- **No per-relocation state.** Everything an architecture decides is a
  pure function of the record, the section bytes and the model's tables,
  recomputed in scan and fill. The only per-site data is the patch
  redirect list the model already has.
- **Sequences without state** (§3.5): a follower finds its lead by a
  bounded look-back over the same relocation section; the pattern is
  input-only, so every member agrees in any order and a removed demand
  (the `__tls_get_addr` PLT) is sound. Needs model M-2 and M-6.
- **Rewrites own a window** (`Howto.window`): x86 opcode edits before the
  field; windows of different sequences may not overlap (refused at
  scan), so fill is order-independent.
- **Two kinds of relaxation** (§5.2): input-only rules may select the
  demand of the form they choose; rules with an address part, or that
  read `Demands`, keep the unrelaxed form's demand. A missing slot in
  fill is an internal error, tested never to occur.
- **Monotone thunks** (§6): patches and redirects are only added, so the
  fixed point terminates (bounded by islands × keys plus erratum sites)
  and is deterministic; unused patches are allowed (model M-4). A cap of
  32 rounds guards against a layout-policy bug.
- **One key per overflow** (§7): reported only by fill, phase 100; layout
  never reports it; a loaded layout that violates validity is not reused.
- **New model flags** (M-1): `IPLT`, `GOT_NORELAX` per symbol; `GOT_BASE`,
  `TLS_LD`, `STATIC_TLS` per output.
- **TLS template aligned** (M-3): `tls.start ≡ 0 mod tls.align`, so both
  variants' TP offsets are closed forms of `Placement.tls`.

## Evidence

- Written against `spec/model.md` draft 2 and `spec/diag.md`; AArch64
  facts from `spec/a64.md` and its experiments
  (`landed/a64/WP-013.md`).
- The fit check (Appendices A, B) is written from the SysV x86-64 and
  i386 psABIs' relocation tables and their TLS and GOT relaxation
  sequences. One experiment checked the parts that carry the most risk.
  It used the container's cross tools: `x86_64-linux-gnu-gcc`,
  `i686-linux-gnu-gcc` (GCC 14), their GNU ld 2.44, and `ld.lld -m
  elf_i386`.
  - **TLS and GOT.** A C file with an extern `__thread` variable and
    extern data and function references was compiled with `-O2 -fPIC`
    and linked as a static executable (`-e main`). The objects carry
    x86-64 `TLSGD` + `PLT32 __tls_get_addr` and `REX_GOTPCRELX`, and
    i386 `TLS_GD` + `PLT32 ___tls_get_addr`, `GOT32X` and `GOTPC`.
    Both linkers wrote the GD → LE words of A.3 and B.5. lld relaxed
    `REX_GOTPCRELX` to `lea` and GNU ld to `mov $imm`. On i386, GNU ld
    turned `mov ev@GOT(%ebx)` into `mov $abs` and lld left it alone.
  - **IBT PLT.** A PIE was built with `-fcf-protection` against a
    shared object, linked by GNU ld with `-z ibtplt`. It showed the
    two-chunk shape of A.8: a 32-byte `.plt` with lazy `endbr64; push
    n; jmp PLT0` entries, and a `.plt.sec` with `endbr64; jmp
    *GOT[n+3]`.
  - **i386 PLTs.** An i386 non-PIC executable and a PIC shared object,
    both against a shared object, matched B.4 exactly, including
    `push 8n`.
  - **Coverage.** The x86 corpus census was not run. x64.md (WP-029)
    and x86.md (WP-030) run it, turn each appendix item into a test,
    and may add a demand class (arch.md §11 Q1).
- Forced trait changes (Appendix C): `classify` sees bytes (i386
  `GOT32`); rewrite windows; neighbour-record sequences; multi-chunk PLT
  with call and lazy chunks, PLT variant per output kind; `Base::Size`;
  negated TP-offset value and slot; per-arch GOT base; implicit addend
  read/write; TLS variant II; `Or` property merge; per-arch weak rule.
