# WP-020a — `mortar_core` part 1: ids, columns, tables, `Layout::check`

`spec/model.md` §1–§4, §7.1 and §9 in `crates/mortar_core` (WP-020b owns
`par`, `hash` and `intern`). Tests are in `crates/mortar_core/tests/`:
`ids.rs`, `tables.rs`, `layout.rs` and `identity.rs`.

## What landed

- **`id`, `column`.** The id newtypes. `MAX_ROWS = u32::MAX` (never an
  id). `IdOverflow` gives a `Refused{Feature}` diagnostic that names what
  overflowed. Also `IdRange`, `OptId` (`u32::MAX` is none), `Span`,
  `SymEntry`/`LocalSym`, and `SymKey`, packed in a `u64` so that integer
  order is §2's order (globals, then locals by `(FileId, index)`).
  `Column<I, T>` comes with a checked `split_by`.
- **`plan`.** `mortar_cli`'s `plan.rs`, moved with `git mv` (§3.1).
- **Derived tables (§3.2–§3.7).** `inputs`, `resolution`, `assignment`,
  `split`, `liveness`, `demands`. Each has a `check(...) -> Result<(), Broken>`
  for the invariants that the table, and the tables before it, can show.
- **Decision tables (§4).** `layout`: `Folds`, `MergeMap`, `Slots`,
  `Placement` and `Layout`. The §4.5 accessors are on `Addresses`
  (`section_addr`, `frag_addr`, `addr_in`, `symbol_addr` with one redirect
  hop).
- **`check`.** `Layout::check(&CheckContext) -> Result<(), Diagnostic>`,
  together with `Layout::validate`, which returns a `Violation{rule, what,
  rows}`. The rules run in a fixed order and the first violation wins:
  Range, Width (§1), Folds (§4.1), Merge (§4.2), Slots (§4.3), then rules
  1–5 of §4.4 (Places, Chunks, Segments with TLS/RELRO/copy, Patches,
  Presence).
- **`identity` (§7.1).** File, section, local, global, comdat,
  output-section, chunk and fragment identities, with conversions both
  ways. They use sorted `Lookup`s and `Ordinals`; there are no hash maps.

## Spec gaps and choices, ranked

1. **No diagnostic kind for an invalid layout.** `Layout::check` returns
   `Malformed{what: "invalid layout: <Rule>: <what>"}` with no place and
   one note per row. `spec/diagnostics.md` should name an internal-error
   kind; it is a linker bug, not bad input.
2. **Rules 4 and 6 are partial.** Rule 4 (patches) is checked only as far
   as the tables show: every patch used, redirects inside their sections,
   and patches inside their chunks. Reach of a branch needs the relocation
   scan. Rule 6 is not checked here.
3. **There is no `spec/layout.md`.** Rule 3 checks invariants rather than
   equality with a derivation: containment, flags, `offset ≡ addr (mod
   align)`, one PT_TLS covering the TLS chunks, RELRO ending on a page,
   copies in writable memory.
4. **`check` needs inputs no table holds:** `page_size`, `needs_entry`,
   and section sizes and alignments. The last comes through the
   `SectionShapes` trait (`InputShapes` reads section headers;
   `Column<SectionId, Shape>` is used for tests). §4.4 should list them.
5. **Additions to §4.4's rows.** `SymPlace` has an `align`. `Frag` does
   not store its output section; it comes from `section` (so the row stays
   16 bytes).
6. **`Split` keeps eh pieces in their own columns** (`eh_of`, `eh_off`,
   `eh_piece`), so a merge piece stays 8 bytes.
7. **Representation choices §3.3 leaves open.** `Def::Internal` carries no
   payload. `props` is its own column. One `reloc` section per section.
   `DropReason::Comdat` carries no payload. `OutOf` is 8 bytes.
8. **`Demands` does not store errors.** They go to the collector.
9. **`Slots` leaves out version definitions and needs** (M5).
   `dyn_relocs` is an order of sections. The PLT list holds PLT and
   CANONICAL_PLT demands; `dynsym` must cover EXPORT.
10. **Chunks.** A synthetic chunk's name is `&'static [u8]`. Section
    header indices are dense and consecutive in chunk order. `.tbss` may
    overlap the memory of the chunks after it.
11. **`MergeMap`.** Dead fragments must be `NONE`.
12. **Identity.** Chunk and output-section identities add an ordinal among
    same-named rows. A `FragIdentity` without alignment can collide.
    Anchors and local names are supplied by the caller (computing them is
    M7). `ContentHash` is `u128`.
13. **`Metadata` sections are treated as placed.** Commons under `-r` are
    not handled.
14. **§10 is updated to the landed shapes.** `split_by` returns `Result`,
    `SymKey` is packed with a `SymKind` view, and `check` takes a
    `CheckContext`.

## Notes for part 2 and later

- WP-020b's `par`, `hash` and `intern` are untouched; its tests (§6) and
  the §5 fill tests are not part of this package.
- `mortar_cli` now depends on `mortar_core` and re-exports `plan`. Nothing
  else changed there.
- The layout phase should run `Layout::check` in debug builds and the
  verifier on every link. A mutation test exists for each rule label
  (`tests/layout.rs`, `s4_4_rule<N>_…`, `s4_1`, `s4_2`, `s4_3`, `s1_width`).
