# WP-020d: the requests of `spec/input.md` §17 and `spec/resolve.md` §18

This WP applies, in the target specs and in their code, the changes that
`spec/input.md` §17 (WP-021) and `spec/resolve.md` §18 (WP-022) request of
other specs. Both packages build on it. `mortar_input`, `mortar_resolve`,
`mortar_arch`, `mortar_a64` and `mortar_plumb` are not touched, and neither
are `spec/input.md`, `spec/resolve.md`, `spec/arch.md` or `spec/a64.md`.

## Changed public signatures

`mortar_core::inputs`:

- The lifetime is now named `'s` (it was `'store`) on every type.
- `File`:
  - loses `input: Option<u32>`;
  - gains `origin: Origin` and `bytes: Option<FileBytes>`;
  - new method `is_lazy()`.
- `Reader::Shared` holds a `SharedObject<'s>`, where it used to hold `&[u8]`.
  `Reader` is still `Copy`, and is `allow(large_enum_variant)`.
- `Member` gains `thin: Option<&'s [u8]>`.
- `Archive`:
  - gains `origin` and `members: IdRange<FileId>`;
  - there is one row per mention.
- `InputFlags` gains `COPY_DT_NEEDED`. `LAZY` now means a `--start-lib`
  object only.
- `Inputs`:
  - gains `link: LinkInputs<'s>` and `store: StoreRef<'s>`;
  - new methods `resident`, `copy_to`, `first_closure_file`, `group_of`
    and `soname_unit`;
  - `check()` checks more (rules 1-10), and its messages start with
    `rule N:`.
- New types:
  - the store: `Blob`, `Errno`, `CopyError`, `InputStore`, `NoStore`,
    `StoreRef`, `FileBytes`;
  - files: `Origin`;
  - the link part: `GroupOrdinal`, `SonameUnit`, `EdgeOutcome`,
    `ClosureEdge`, `OpenedKind`, `Opened`, `SearchRef`, `TargetName`;
  - searches and scripts: `ProbeOutcome`, `Probe`, `ScriptEntry`,
    `DirectiveKind`, `Directive`, `LinkInputs`.

`mortar_core::resolution`:

- `FileLive`:
  - `Needed` is replaced by `Shared { needed: bool }`;
  - new variant `Closure`;
  - `Extracted` also records a root, as `(file 0, argument index)`.
- `Def::Internal` becomes `Def::Internal(InternalDef)`. `InternalDef` is
  new: `Assign(u32)`, `Alias(SymbolId)`, `Provide { conditional }`.
- `RefFlags` gains `STRONG`, `DEFINED_SHARED`, `EXPORTED` and
  `PREEMPTIBLE`.
- `SymProps` gains `verdict: Verdict`, a new enum: `Bound` (the default),
  `Error`, `Warning`, `Ignored`. The row is still 6 bytes, because it
  uses a byte that was padding.
- `Resolution`:
  - gains `comdat_copies: Box<[(ComdatId, FileId)]>`;
  - new methods `copies_of` and `check_against(&Inputs)`;
  - `check()` adds rules 5 and 6.
- Sizes are unchanged: `FileLive` and `Def` are 12 bytes.

`mortar_core::assignment`:

- `Assignment` gains `withdrawn: Box<[SymbolId]>`.
- New methods `is_withdrawn` and `def(&Resolution, SymbolId) -> Option<Def>`.
- `check` also checks `withdrawn`.

`mortar_core::identity`:

- `FileIdentity` gains `mention: u32`.
- New `ProbeCheck` and `Inputs::probe_checks() -> Option<Vec<ProbeCheck>>`.

`mortar_core::plan` (re-exported as `mortar_cli::Plan`):

- `Dynamic` gains `allow_shlib_undefined: Option<bool>`.
- `Diagnostics` gains `warn_backrefs: bool` and `warn_common: bool`.

`mortar_cli`:

- New `pub const PHASE: u16 = 10`.
- `table::Lands` gains `AllowShlibUndefined(bool)`, `WarnBackrefs(bool)`
  and `WarnCommon(bool)`.
- Every grammar and response-file key now has phase 10, where it had 0.

`mortar_diag`:

- `Kind` gains 26 variants. They are listed above.
- `Kind::Refused` gains `not_recognized: bool`. A pattern without `..`
  breaks.
- New `Diagnostic::refused_unrecognized_format(name)` and `pub const
  NOT_RECOGNIZED`.
- `Kind::IDS` grows from 19 entries to 45. `Kind::symbol` returns the name
  for every symbols-area kind except `gnu-warning`.
- The texts of `library-not-found`, `unknown-file-type`, `duplicate-symbol`
  and `undefined-symbol` change (see diag §3.1).

`mortar_elf::archive`:

- `Archive::symbol_index()` returns `Option<Result<SymbolIndex<'a>,
  Error>>`, where it returned `Option<SymbolIndex<'a>>`.
- `Archive::parse` no longer fails for a malformed index.

`mortar` (facade): the refusal of linking has the key `(11, 0, 0)`, where it
had `(1, 0, 0)`.

## Choices where the request was open

1. **The undefined and duplicate wording conflicts with `arch.md`.** I
   followed resolve §14 and §18:
   - lld's head with GNU ld's phrase:
     ``undefined symbol: x (undefined reference to `x')``;
   - one diagnostic per key, at most three `>>> referenced by` lines,
     then a count.

   This replaces WP-020c's per-reference `undefined reference to 'X'`.
   `spec/arch.md` §3.4 still says "once per live relocation" with the old
   text, and it does not list `comdat-mismatch` or
   `discarded-section-reference`. It is not editable here: **WP-023 (or
   the supervisor) must amend it.**
2. **Where the new kinds go.**
   - Input-phase kinds are in the "files" area, including
     `incompatible-file`, `ignored-member` and `no-target`.
   - resolve's kinds are in the "symbols" area.
   - The brief's "never renumber an existing kind" is read as: string ids
     never change. `IDS` stays ordered by area (diag §3.3), so kinds are
     inserted inside their area rather than appended.
3. **`unknown-file-type`** stays a unit variant. The path comes from
   `.at(Place::file)`.
4. **The refusal suffix** is a field (`not_recognized`) with its own
   builder, not a separate kind. The id stays `refused`.
5. **The store.**
   - input §17 writes `&'s Store`. The model names no concrete store, so
     `Inputs` holds `StoreRef<'s>(&'s dyn InputStore)`. The store type
     itself is `mortar_input`'s, and it implements the trait.
   - `Inputs::resident` returns the slice directly, with the lifetime
     `'s`.
   - `Inputs::bytes(SectionId)` is not added: it needs `Resolution`'s
     section numbering, so it belongs to whichever phase holds both.
6. **`ProbeOutcome::Found(u32)`** indexes `opened`, not `FileId`: a
   script or an archive has no `FileId`.
7. **`SonameUnit.mentions`** holds `Origin`s. `ClosureEdge` has no name
   field: the name is `DT_NEEDED` entry `index` of `needing`, read from
   its reader.
8. **`InternalDef`.**
   - resolve §18 writes `Assign(expr)` and `Provide(name)`. The model
     holds no expressions or names, so these are `Assign(u32)` (an
     argument index or script position) and `Provide { conditional }`
     (the name is the key).
   - `Assignment` withdraws only `Provide { conditional: true }`.
9. **`Verdict`** is per key, in `SymProps` (resolve §5.2). The scan
   reports it per surviving reference.
10. **Rule 6 of `Resolution::check`** is one-sided. A weak undefined must
    have no strong reference. The converse is not checked, because a key
    no live file mentions has no references and may be either.
11. **The mention ordinal of a member** is the ordinal of its archive
    mention among the mentions of that path. The member's own name and
    ordinal follow it. Ordinals are computed by sorting (`Ordinals`), not
    by counting, so the cost is O(n log n).
12. **`probe_checks`** returns `None` if any probe ended in `Error`: a
    link with such a probe failed and stores no state. A `Skipped`
    candidate is re-checked as present.
13. **Option statuses.** The rows named by input §17 and resolve §18 stay
    `refused`; cli §4.2 lists which package flips each. A `supported` row
    needs a test that the pipeline honours it, and no pipeline exists yet.
    This includes `--fortran-common`, which resolve §18 marks "supported
    at M1". Its help text has changed.
14. **The facade's refusal of linking** moves from phase 1 to phase 11, so
    it still sorts after the command line's diagnostics now that they are
    at phase 10.
15. **The malformed `MORTAR_SCHED_SEED`** is not reported by the parser.
    `mortar_cli::parse` is a function of the arguments and does not read
    the environment. The seed is read where a `Pool` is made, and the
    driver reports `mortar_core::seed`'s diagnostic (cli §2.10). No driver
    makes a pool yet.
