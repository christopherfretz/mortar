# WP-020c: the model amendments of `spec/arch.md`, and the new diagnostic kinds

This WP makes the amendments M-1 to M-8 that `spec/arch.md` §9 asks of
`spec/model.md`, plus the §2.3 numbering text that WP-020b corrected and the
error for a malformed `MORTAR_SCHED_SEED`. It also adds the diagnostic kinds
that `spec/arch.md` §10 needs to `spec/diag.md` and `mortar_diag`, then
brings `mortar_core` in line with the amended text. `par.rs`, `hash.rs` and
`intern.rs` are unchanged. Nothing in `mortar_arch` or `mortar_a64` is
touched (that is WP-023).

## Changed public signatures

`mortar_diag`:

- New `IncompatibleReason` (`#[non_exhaustive]`, `ALL`, `text()`), which
  is re-exported.
- `Kind` has four new variants: `RelocationIncompatible { r_type, name,
  reason }`, `RelocationMisaligned { r_type, value, align }`,
  `RelocationOutOfRange { r_type, value, min, max, name }` and
  `InternalError { what }`. `Kind` is `#[non_exhaustive]`, so this does
  not break anyone.
- `Kind::IDS` grows from 15 to 19 entries. `Kind::symbol` also returns
  the name for the incompatible and out-of-range kinds.
- `Diagnostic::new` forces `Error` for `InternalError`, as it already did
  for `Refused`.
- The text of `undefined-symbol` changes from `undefined symbol: X` to
  `undefined reference to 'X'`.

`mortar_core`:

- `DemandFlags` widens from `u8` to `u16`, so `bits()` and `from_bits()`
  now take and return `u16`. Renames: `TLS_IE` becomes `GOT_TPREL` and
  `CANONICAL_PLT` becomes `CANON_PLT`, to use the names `spec/arch.md`
  §4.2 gives. New flags: `IPLT`, `GOT_NORELAX`, `TLSIE_NORELAX`. New
  constants: `CROSS_FILE`, `GLOBAL_ONLY`, `EXCLUSIVE`. New method:
  `conflict()`.
- New `GlobalFlags` (`GOT_BASE`, `TLS_LD`, `STATIC_TLS`) and a new field
  `Demands::output`. A struct literal of `Demands` now needs it.
  `Demands::empty` sets it to empty.
- New `Demands::cross_file()`. `Demands::check` additionally rejects a key
  that has two flags of `EXCLUSIVE`.
- `Slots` gains the fields `iplt: Box<[SymKey]>` and `tls_ld: bool`. New
  `SlotKind` (with `ALL`) and `Slots::list(kind)`.
- `PatchKind::Erratum843419` is replaced by `PatchKind::Erratum { erratum:
  Erratum, section: SectionId, offset: u64 }`. New `Erratum` enum
  (`#[non_exhaustive]`, one variant, `E843419`).
- `From<Violation> for Diagnostic` now gives `internal-error` instead of
  `malformed-input`, with the same `what` text and the same notes.
  `Layout::check` therefore reports `internal-error`, but its signature
  is unchanged.
- `identity` gains:
  - the types `KeyIdentity`, `SiteIdentity`, `PatchIdentity`,
    `AllocIdentity` and `Dependee`;
  - the functions `flag_dependees`, `patch_identity` and `patch_at`;
  - the methods `Identities::{key, key_id, site, site_id, alloc,
    alloc_key}`.
- New module `seed`, with `SEED_KEY` and `impl From<par::BadSeed> for
  Diagnostic`.

Row size: a `DemandFlags` is now 2 bytes. That makes the global demand
column 2 bytes per symbol, where WP-020a's record says 1. A
`(LocalSym, DemandFlags)` row is still 12 bytes. `tests/ids.rs` asserts
both sizes.

## Choices where the request was open

1. **`undefined-symbol`: one kind, with new wording.** I extended the
   existing kind rather than adding a second one. It is now one
   diagnostic per reference, with the place in the head line and the
   message `undefined reference to 'X'`.
   - This follows arch.md and diag.md: single quotes, where GNU ld
     uses a backtick and an apostrophe.
   - The cost: a tool that searches for lld's `undefined symbol: ` no
     longer finds it. diag §8.2 records this.
2. **`internal-error`.** The message is `internal error in mortar:
   {what}`. It is always an error (status 1, no output, diag §2.1) and
   has no place.
   - A layout loaded from a link state that fails the check is not an
     internal error. It falls back to a full link (phase 15). Making
     that call is the caller's job, so `From<Violation>` always gives
     internal-error, which is what a computed layout needs.
3. **Exclusive flags.** model §3.7 now says which flags never occur
   together, and `Demands::check` rejects them:
   - `IPLT` with `PLT`, `CANON_PLT` or `COPY`;
   - `COPY` with `CANON_PLT`.

   These follow from one target kind per key (arch §2.1). arch.md does
   not state them as table invariants, so this is the model's own
   addition. A local may have `IPLT`, since local IFUNCs exist.
4. **The module slot is a `bool`.** `Slots::tls_ld` is index 0 of its
   own kind. Where it lies in the GOT relative to the other kinds is left
   to `spec/synth.md`, like every cross-kind GOT position. The field name
   `tls_ie` is kept for the `GOT_TPREL` list. The i386 negated TP-offset
   slot is left to the x86 spec.
5. **Rule 4 as far as the tables show.** `Layout::check` verifies:
   - an erratum redirect names the erratum patch keyed by its own
     `(section, offset)`;
   - a `Plt(key)` thunk's key demands `PLT`, `CANON_PLT` or `IPLT`
     (the Slots rule has run by then, so a demand means an entry);
   - an erratum patch's section is in range.

   Two checks need the code words, the relocations and the `Arch`
   predicate, so they are left to `fill` and the verifier, as model
   §4.4 now says:
   - "a thunk redirect names a thunk of the key its site needs";
   - "an erratum redirect names a site of that erratum".

   Two erratum patches with one key are not rejected: at most one can
   be used, because redirects are unique per site.
6. **The seed error lives in `seed.rs`, not `par.rs`.** `par.rs` is out
   of scope. `BadSeed` already carries the value from
   `to_string_lossy`, which shows non-UTF-8 bytes as U+FFFD, as §6 now
   specifies. The driver (`mortar_cli`) still has to report it.
7. **`Dependee`.**
   - It names every thing §7.2 lists, in identity terms. A `Flag`
     carries a single bit of `CROSS_FILE`, so the index has one row per
     flag.
   - The on-disk form, and the map from a dependee to its units, are
     `spec/incr.md`'s (M7).
   - Fragments and sections reuse the existing `FragIdentity` and
     `SectionIdentity`.

## Not done

- `mortar_cli` does not yet turn a `BadSeed` into a reported diagnostic
  (`Pool::try_new` gives the error). That is a driver follow-up.
- Rule 4's code-word part (see choice 5) and M-2/M-6 belong to scan and
  fill: WP-023 and the image WP.
- The `mortar_cli` command-line diagnostics use phase 0, where model §8
  says 10. I noticed this but did not change it; it is out of scope
  (`crates/mortar_cli/src/grammar.rs:88`).
