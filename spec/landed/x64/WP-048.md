# WP-048: M2-X64, x86-64 in dynamic executables

Branch `wp/048-m2-x64`, cut from main e910975. main was not merged:
WP-051 had not landed when the package finished, and main's only change
since the cut was `docs/BACKLOG.md`.

The rules come from `spec/dyn.md` (D-25 for x86-64, D-43 to D-49, X-57)
and from `spec/x64.md` with R-X1 to R-X3. The cut is
`spec/landed/dyn/WP-040.md` §3, row WP-M2-X64.

Only `mortar_x64` and its tests changed. The M2 rules are on only when
the value is `X64::M2`. `X64::M1`, the default and the value the linker
builds today (`crates/mortar/src/arch.rs` `LinkArch::of`), keeps every
M1 answer and byte. `cargo xtask static-identical` is green.

## The cell table (x86-64, against shared keys; `dynamic.rs`)

E/P = `Exec`/`Pie`; RO/RW = place without/with `SHF_WRITE`.

| type | data, E | data, P | function, E | function, P |
|---|---|---|---|---|
| `PC32`, `PC16`, `PC8`, `PC64` (not on a branch) | COPY | COPY (D-43) | CANON_PLT | `canonical-plt-in-pie` |
| `PC32` on `e8`/`e9`/`0f 8x` | COPY | COPY | CANON_PLT | `canonical-plt-in-pie` (finding F1) |
| `PLT32`, `PLTOFF64` | PLT | PLT | PLT | PLT |
| `GOTPCREL`, `GOTPCRELX`, `REX_GOTPCRELX`, `GOT64` | GOT, never relaxed | GOT | GOT | GOT |
| `64` RW | symbolic, place 0 | symbolic | symbolic | symbolic |
| `64` RO | COPY | `text-relocation` | CANON_PLT | `text-relocation` |
| `32`, `32S`, `16`, `8` | COPY | `relocation-incompatible` (recompile with -fPIE) | CANON_PLT | `canonical-plt-in-pie` |
| `GOTOFF64` | `relocation-incompatible` | `relocation-incompatible` | the same | the same |
| `SIZE32/64`, `GOTPC*` | none | none | none | none |

Against `weakdyn` keys, in both kinds:

- `GOTPCREL*` → GOT;
- `64` in a writable place → symbolic; in a read-only `pie` place → `text-relocation`;
- `PLT32`, `PLTOFF64` and `PC32` on a branch opcode → PLT.

`Local` and `Ifunc` keep the generic table (D-45: IPLT, GOT|IPLT,
`RELATIVE` in `pie`).

- `weak_use` for types 0 to 60 in both writabilities, under M2 and M1;
- the branch-opcode test: `e8`, `e9`, `0f 80`, `0f 85` and `0f 8f`,

- X-28: an unrecognised TLSDESC member is refused in scan and in apply;

## Stays refused by name

- the IBT PLT (`-z ibt`/`ibtplt`/all inputs IBT) in a dynamic output, at
  `write_plt` (Q4; see R-48-2);
- `canonical-plt-in-pie`;
- `text-relocation` (against shared and `weakdyn` keys);
- `relocation-incompatible` for `32`/`32S`/`16`/`8` against shared data
  in `pie`, and for `GOTOFF64` against a shared key;
- X-26: an unmatched GD against an output-defined key (`unrecognized
  general-dynamic TLS sequence`);
- an unmatched LD;
- X-28: an unrecognised TLSDESC member;
- a TLS use of a `weakdyn` key (`thread-local undefined weak symbol in a
  dynamic executable`);
- dynamic TLS models in a shared object (M4).

`weak-undefined-pc-in-pie` is raised by the generic weak pre-pass
(WP-046) from `weak_use`'s `Unfillable`.

## Spec findings

- **F1, D-44 / D-25**: GNU ld routes a `PC32` on a branch opcode
  (`is_32bit_relative_branch`) against a shared function through its PLT
  entry. The spec gives it CANON_PLT in `exec` and
  `canonical-plt-in-pie` in `pie`. For `weakdyn` keys X-57 already
  treats it as a branch. Only hand-written assembly emits it; the census
  compilers use `PLT32`. Proposed text for D-44: "`PC32` whose field
  follows `e8`, `e9` or `0f 8x` in the same input section, against a
  shared function, is a branch: PLT in both kinds (X-57's test)." Until
  then the refusal is safe.
- **F2, R-A3 not applied in code**: `crates/mortar_arch/src/class.rs`
  TABLE still has `Pc` against `Shlib` in `Pie` as `E`. x86-64
  overrides it in `dynamic_cell`. The generic fix belongs to
  `mortar_arch`.
- **F3, D-47**: the generic TX cells give
  `Incompatible(ReadOnly)`, not `text-relocation`. x86-64 maps only
  shared and `weakdyn` targets. A read-only `64` against a `Local` or
  `Ifunc` key in a dynamic `pie` keeps `relocation-incompatible`
  (`dynamic.rs` `local_and_ifunc_cells_are_the_generic_table`), because
  a static PIE's diagnostic must not change and the scan context cannot
  tell the two apart (R-48-1).

## Interface requests

- **R-48-1**: a `dynamic: bool` on `ScanCx`, or a generic class rule
  that maps TX to `DynRefusal::TextRelocation` when the output is
  dynamic. This finishes D-47 for `Local` and `Ifunc`.
- **R-48-2**: a `dynamic: bool` on `OutputCx`. With it, `plt_variant`
  refuses the IBT PLT of a dynamic output up front instead of at
  `write_plt`. A static-pie's IBT IPLT is M1 and unchanged.
- **R-48-3**: a `writable: bool` on `SectionOut`, or the record writer
  applying `DynRole::place`. Today D-46's place 0 is written only when
  the key has no COPY or CANON_PLT. A `64` in a writable place against a
  key that another use copied writes `S + A`, which is the right value
  in `exec`; `pie`'s record and place for that case are the record
  writer's.
