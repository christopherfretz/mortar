# WP-084: x86-64 large sections (`SHF_X86_64_LARGE`, the medium and large code models)

Branch `wp/084-x64-large`, cut from main 9fa03dc's mortar (6e4daa57);
main merged once (origin/main 8366315, WP-082's verifier; one conflict
in `tests/link/xfails`, where both sides deleted lines).

The staging refusals of x64.md X-52 (`section-flag` `SHF_X86_64_LARGE`,
`feature` `SHN_X86_64_LCOMMON`) are gone. Large sections are laid out by
L-36a and large commons are allocated in `.lbss` (R-15, R-16, X-54,
X-55). This works in static, PIE and `-no-pie` executables. Static-pie
is refused as a whole until WP-052.

## 1. Measurements (GCC 14.2, Clang 19.1.7/22.1.8, GNU ld 2.44, lld 22.1.8, mold 2.37.1)

Scratch harness (deleted): `lg.c` (a static 1 MiB array, a 1 MiB
initialised array, 1 MiB const, a 1 MiB common under `-fcommon`, small
data, a call into `ext.c`), `lg.cc` (a 1 MiB object with a constructor
and vtable, tables, `thread_local`, an exception), and `lg.f90` (a
module array of 200000 `real(8)`s and a COMMON block of 300000). The
programs are the ones in `crates/mortar/tests/x64.rs` (`C_LARGE`,
`CXX_LARGE`, `F_LARGE`) and in `tests/link/{layout,dyn/layout}/x64-large-*.test`.

### 1.1 What the producers emit

| producer, model | sections (flags) | `LARGE_COM` | relocation types (non-debug) |
|---|---|---|---|
| GCC C medium, any PIC | `.lbss` (NOBITS, WAl), `.ldata` (WAl), `.lrodata` (Al) | `lc` (`-fcommon`) | no-pic `32 32S 64 PC32 PLT32`; PIE `GOTOFF64 GOTPC32 PC32 PLT32`; PIC `GOTOFF64 GOTPC32 PC32 PLT32 REX_GOTPCRELX` |
| GCC C large | the same | `lc` | no-pic `64 PC32`; PIE `GOTOFF64 GOTPC64 PC32 PLTOFF64`; PIC `+GOT64` |
| Clang 19/22 C medium | `.ldata`, `.lrodata` (a large `static` zero array goes to `.lbss` only with `-fno-common`) | none: Clang's large common is a plain `COM` | as GCC medium; PIC `PC32 PLT32 REX_GOTPCRELX` |
| Clang C large | `+ .ltext` (AXl), `.lrodata.str1.1` (AMSl) | none | no-pic `64 PC64`; PIE `GOT64 GOTOFF64 GOTPC64 PC64`; PIC `GOT64 GOTOFF64 GOTPC64 PC64` |
| g++ medium/large | `.lbss` | none | medium adds `PC64`, `TPOFF32`, `TLSGD` (PIC); large PIE/PIC `GOT64 GOTOFF64 GOTPC64 PC64 PLTOFF64` |
| clang++ medium | `.ldata` | none | as g++ medium |
| clang++ large | `.ltext.*` and `.lrodata._ZT*` in COMDAT groups (AXGl, AGl); PIE/PIC `.ldata.rel.ro._ZT*` (WAGl) | none | as Clang C large, plus `TPOFF32`/`TLSGD` |
| gfortran medium/large | `.lbss` (module array) | `bigcom_` (the COMMON block) | as GCC C |

- `-mlarge-data-threshold=2000000` gives no large section. `=0` makes
  every object large, `small_b` included (a `LARGE_COM`).
- `-fdata-sections` gives `.lbss.lb`, `.ldata.ld_`, `.lrodata.lr`.
- `-g` adds `32` and `64` in `.debug_*`, and in the large PIC model
  `GOTOFF64` in `.debug_info` (X-53, already M1).
- The `x86_64-linux-gnu-gcc` driver compiles PIE code by default.
- Every type above was already M1 in x64.md's table. The relocation
  code needed no change.

### 1.3 Placement (static, GCC medium `lg.c`)

| linker | order of the alloc sections | `PT_LOAD`s |
|---|---|---|
| GNU ld | `.text` (`.ltext` after it), `.rodata`…, `.data`, `.bss`, `.lbss`, `.lrodata`, `.ldata` | R, RX, R, RW (… `.bss` `.lbss`), R (`.lrodata`), RW (`.ldata`) |
| lld 22 | `.ltext`, `.lrodata`, `.rodata`, `.text`, …, `.bss`, `.ldata`, `.lbss` | R (with `.lrodata`), RX, RW, RW (`.ldata` `.lbss`) |
| mold | `.lrodata`, `.rodata`, `.ltext`, `.text`, …, `.ldata`, `.bss`, `.lbss` | `.ldata` inside RW |
| **mortar** | every small section, then `.lrodata`, `.ltext`, `.ldata`, `.lbss` | R, RX, RELRO, RW, then R (`.lrodata`), RX (`.ltext`), RW (`.ldata` `.lbss`); a `.lbss` with no `.ldata` ends the small RW segment |

X-54's table is confirmed. Its derived 2 GiB failures were run and
hold (x64.md X-54 now says so). `_edata`/`__bss_start`/`etext` cover
the small sections. `_end` is after the last large section (GNU ld's
`_end` is after `.ldata`).

## 5. AArch64 and i386

GCC 14 `-mcmodel=large` on AArch64 has no section flag and no large
sections. It uses literal pools: `R_AARCH64_ABS64` words in
`.text.startup`, loaded through `ADR_PREL_PG_HI21` +
`LDST64_ABS_LO12_NC`; calls stay `CALL26`; one `PREL32`.

GCC refuses `-mcmodel=large` with `-fPIC`/`-fPIE` ("sorry,
unimplemented"). mortar links the static and `-no-pie` programs and
they run; `tests/link/layout/a64-large-model.test` (static) and
`dyn/layout/a64-large-model.test` (`-no-pie`) cover this, 4/4 linkers
each. Clang's `MOVW_UABS` large model is already covered by
weak-class-table's `movw` row.

i386: no change.

## 6. Spec findings

1. **X-54 / L-36a, "the small sections' addresses are exactly those of
   the same link without the large sections"**: no linker can do that.
   Each large `PT_LOAD` adds a 56-byte program header, which moves every
   small section after the header table. All three references do the
   same.
   - Experiment: `x64_small_sections_do_not_move_with_the_large`, and
     a link of `lg.c` without its large objects.
   - Proposed text (applied in L-36a; X-54's sentence is left for the
     supervisor): "No small section's address depends on the large
     sections' sizes; the large sections add up to three program
     headers, which move the small sections after the header table by
     their size, as in the three references."
   - The test asserts this form, because the literal one cannot hold.
2. **L-36a**: the spec did not say what a `.lbss` with no `.ldata`
   does. A `PT_LOAD` with no file bytes (`p_filesz` 0) is legal, but
   eu-elflint's offset heuristic flags it ("not fully contained", "no
   writable sections"), and no reference writes one. mortar now ends
   the small RW segment with it, as all three references do.
   - Rule: `Chunk::run_class`.
   - Text added to L-36a.
3. **L-36a refusals**, applied in L-36a and the §20.4 list:
   - besides TLS: non-alloc, a type other than PROGBITS/NOBITS, and a
     read-only or exec NOBITS with the flag (`section-flag`);
   - a large and a small live input in one output section
     (`section-conflict`).
4. **L-36a symbols**: `_edata`/`__bss_start`/`etext` describe the small
   sections and `_end` covers all of them. The spec was silent;
   plumb.md Y5 already expects this; GNU ld agrees on `_end` (after
   `.ldata`).
5. **L-65/L-67**: the `PT_LOAD ×1-4` row is now 1-7 on x86-64. L-36a
   says so. L-65 and L-67 were not edited (not this package's rules);
   proposal: "`PT_LOAD` ×1-7 (x86-64 large sections, L-36a)".
6. `diag.md`: no row named the staging refusal, so nothing changed.
   `docs/status`: no row changes. resolve.md §3.3 already had R-16's
   text (WP-029r) and is unchanged.
7. Q3 (b), a mortar static-pie with `.ltext`/`.ldata`, cannot be tested
   yet: mortar refuses static-pie output (WP-052). Q3 (c) is done.
