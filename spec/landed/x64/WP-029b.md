# WP-029b: `mortar_x64`, the x86-64 architecture, and x86-64 links end to end

Branch `wp/029b-x64`. Stage A, the crate and its tests, was gated at
bd8db0f. Stage B was then done after merging main twice, first
e3bb4aa (WP-027c and WP-028c) and then 33c65d7 (78dd0f9, `--sysroot`).
The crate implements `spec/x64.md` for M1. It is `forbid(unsafe_code)`
and has no third-party dependencies. Every byte that `apply` writes
comes from an x64.md rule.

## Stage B code outside the crate (local and additive)

- **`mortar_arch`:** `SymValue.tls`, `SectionOut.exec` and `with_exec`
  (arch.md §3.6).
- **`mortar_image`:** `InputUnit.exec` and `Clip.exec`, taken from the
  input section's `SHF_EXECINSTR`. X-46 is keyed on the section that
  holds the field, which is what GNU ld's `SEC_CODE` test does.
  `.eh_frame` clips are never exec. `crates/mortar/src/sites.rs` (the
  AArch64 erratum's code sections) passes `with_exec(true)`.
- **`mortar`:** `LinkArch` (A64 or X64; I386 is still refused by
  `front.rs`), its `proof()` (`NoProof` on x86-64) and its
  `feature_1()` (the BTI or IBT bit).
- **`mortar_resolve`:** `linker.rs` adds
  `When::X86_64Conditional` for `_TLS_MODULE_BASE_`. Before this, the
  name was M2 and a reference failed as "undefined symbol".
- **`crates/mortar/src/syms.rs`:** `_TLS_MODULE_BASE_` is written
  `STT_TLS`, at template value 0.
- **Test support:** `support::build_by` (cross drivers) and two
  eu-elflint known lines on `.tbss`. GNU ld's outputs produce the same
  lines: elflint places TLS symbols by `sh_offset`.

## Findings (proposed text where a spec is silent)

- **`_TLS_MODULE_BASE_` (X-47 vs resolve.md):** applied here. The
  resolve.md §8.1 row is M1 for x86-64.
- **X-47 correction:** mortar's bytes are unaffected, because T = 0 is
  decided by name (X-28). Only `.symtab` differs: mortar writes 0, lld
  writes 0, GNU writes align_up(p_memsz, p_align).
  `mortar_layout` `symbols.rs:203` places it at `tls.start`, consistent
  with plumb's mortar expectation.
- **X-26/X-28:** mortar refuses as `Refused{Feature, …}`. The spec
  says "Incompatible with feature name". Proposed: "refused by name
  (`feature`)".
- **arch.md A.6:** `TpRel(S + A)` should read `TpRel(S)` for the
  relaxed IE `mov $imm`, because A is the field's −4.
- **"Refused with bytes shown":** this cannot go through `ScanError`.
  `mortar_x64::shown_bytes` formats the reach into the feature text.
  Proposed for arch.md §3.7: "the refusal's feature names the bytes in
  the window, hex".
- **§6.3 vs diag.md:** §6.3 prints decimal values; diag.md prints hex.
- **GNU ld 2.44** asserts on `DTPOFF64` in code. Add to §14.
- **GNU as** emits REX_GOTPCRELX for the `rex64 call *@GOTPCREL` GD
  follower. GNU ld refuses it, lld accepts it, and mortar refuses it
  by name (X-30).
- **elflint** places TLS symbols by `sh_offset`. GNU ld's outputs show
  the same `.tbss` lines.
