# WP-009 — `mortar_script` stage 1: the lexer, implicit-script commands, recognition

`spec/script.md` §1-§7 and `crates/mortar_script` (depends on `mortar_diag`
only, `forbid(unsafe_code)`).

## What landed

- A modal lexer (`lex::Lexer::next(Mode)`; modes `Script`, `InputList`,
  `Expression`) with byte spans, per-mode name sets, keyword sets and
  operators, checked integers (`lex::parse_integer`: every GNU form, errors
  where GNU ld silently stops or wraps), strings without escapes, `/* */`
  and `#` comments.
- `parse(&[u8], path) -> Result<Script, Box<Diagnostic>>`: INPUT, GROUP,
  AS_NEEDED (nesting bounded at 16), STARTUP, OUTPUT_FORMAT (1 and 3
  names), OUTPUT_ARCH, TARGET, SEARCH_DIR, OUTPUT, ENTRY, EXTERN, INCLUDE,
  `;`. File forms `Path`, `Sysroot` (`=x`, `$SYSROOT/x`), `Library`
  (`-lx`), `LibraryVerbatim` (`-l:x`).
- Every other statement GNU ld 2.44 accepts at the top level, plus
  symbol assignments and the newer `LIB`, is refused by name
  (`RefusalClass::ScriptCommand`); anything else is `malformed-input` at
  line and column.
- `looks_like_script(&[u8]) -> bool` (§3.4) and `position(&[u8], offset)`.
- The resolution rules `mortar_input` applies (§2.4), the consumer rules of
  §2.5-§2.8, measured on GNU ld, lld and mold.

## Decisions taken here

- Syntax errors are `Kind::Malformed` (§2.9), no new kind.
- A comma glued to an unquoted name is an error everywhere (§2.1): GNU ld
  keeps it in the name, lld and mold split.
- Bytes GNU ld silently skips in input lists (a leading digit, `#`, `;`,
  `-x`, non-ASCII) are errors (§1.9, §2.4).
- `-l=name` and a quoted `"-l..."` are errors (the linkers disagree).
- `=name` (relative) under a sysroot must be an error in `mortar_input`
  (bfd/mold concatenate, lld joins with `/`).
- Two different `ENTRY` symbols across a link's scripts must be an error
  (GNU ld: last wins, lld: first).
- A foreign `OUTPUT_FORMAT` must be an error (GNU ld accepts any name in an
  implicit script).
- SEARCH_DIR applies to a whole script, as GNU ld (§2.6).
- Refusal is decided by the head of a statement (§2.10).
- Recognition (§3.4): not text (NUL, control bytes but tab/LF/CR, 0x7f) is
  not a script; the empty file is.
- `CommandKind` is exhaustive on purpose.

## Open questions

1. `ENTRY("")` and `INPUT("")` are errors; GNU ld accepts them as no-ops.
2. Form feed and vertical tab are not script text (GNU ld rejects, lld
   accepts).
3. Sysroot containment through symbolic links is unmeasured (§8).
4. The wildcard and version lexer modes are unmeasured (§1.10).
