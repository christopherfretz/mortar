## 1. `.deplibs` (`SHT_LLVM_DEPENDENT_LIBRARIES`)

What the references do (measured with the section in a command-line
object and in an archive member, `$R/deplib`):

| linker | specifiers | the section |
|---|---|---|
| GNU ld 2.44 | ignored; a symbol only the named library defines stays undefined | copied to the output, non-alloc (also under `-r`) |
| mold 2.37 | ignored, as GNU ld | copied, as GNU ld |
| lld 19.1.7, 22 | each loaded as `-l<name>` from the `-L` directories (objects and members alike); a missing one is `unable to find library from dependent library specifier: X` | dropped |
| lld `--no-dependent-libraries` | ignored | dropped |

GNU ld and mold reject both `--[no-]dependent-libraries`.

The rule: `spec/resolve.md` §10, the table row and the paragraph
"Dependent libraries" (consumed, not honoured; why that can only ever
surface as a named `undefined-symbol`, with the weak-undefined caveat GNU
ld shares; honouring as lld does is a later row, with what it takes in
round-based extraction). `mortar_resolve` classifies the section
`Excluded`/`Dropped(Consumed)` (`crates/mortar_resolve/src/sections.rs`);
a refused section type is named when the machine's table knows it
(`unsupported section type: SHT_LLVM_ODRTAB`, not `0x6fff4c00`;
`tables.rs`). `--no-dependent-libraries` is `noop`,
`--dependent-libraries` stays `refused` (`spec/cli.md` §4.2,
`docs/status/options.md`).

Tests: `crates/mortar_resolve/tests/rules.rs` (the row),
`crates/mortar_resolve/tests/llvm_sections.rs` (no error on `.deplibs`;
the named refusal), `tests/link/resolve/deplibs.test` (links and runs,
section absent from mortar's output), `deplibs-undefined.test` (a symbol
only a deplib defines: `undefined-symbol` naming it, from an object and
from an archive member), `aarch64-attributes.test` (the WP-033
reproducer, AArch64); the options audit row; the two reproducers in
`tests/mason/repro/` are marked fixed. On the shipped archives
`SHT_AARCH64_ATTRIBUTES` no longer refuses (WP-027d) and `.deplibs` is
consumed: the full suite in `mortar` mode needs no stripped archives.
`mortar-noattrs`/`mortar-stripped` stay as modes (cheap) but are not in
the default set (`bfd`, `mortar`). The optional `note:` listing discarded
specifiers on an undefined-symbol failure was not done (follow-up).

## 4. Repeatable

Commands (from the mortar checkout, after `source scripts/env.sh`):

```
cargo xtask mason setup                                     # once
cargo xtask mason libcxx --full --mode bfd --mode mortar --plumb -j 4 \
    --out <dir> --results <dir>/results.tsv --baseline tests/mason/baseline-mortar.tsv
cargo xtask mason libcxx --collect <dir> --results <file>   # from a kept --out
cargo xtask mason libcxx --compare <a.tsv>[:bfd] <b.tsv>[:mortar]
cargo xtask mason libcxx --full --shard 1/6 --mode lld --mode mold -j 4 --out <dir> --results <file>
cargo xtask mason programs -j 2
```

The result file (`xtask/src/mason/outcomes.rs`, `tests/mason/README.md`
"Result file"): tab-separated, `#` header, one line per test and mode:
test, mode, outcome, detail, link-ms (summed over the test's links),
links, link-rss-kib (largest), plumb (verdict, mortar modes), first-key.
The command prints the link-time table of every mode and each mode's
comparison with `bfd`. `--baseline` prints `regressed:` for a test that
does not pass and is not in the baseline (and fails the command) and
`fixed:` for a listed one that passes; `--write-baseline` writes one,
whose reasons are filled in by hand. The baseline: 8 lines (the 5
root-only failures, the timeout, the 2 XPASS).

Provisioning a fresh container (workspace root): `scripts/provision.sh`
(apt: GNU binutils, lld, lld-22, clang-22, mold, gfortran, the x86-64
cross compilers, qemu-user; Rust in `.toolchain/`); kiln and hod release
builds in `.build/target-kiln`, `.build/target-hod` (each `cargo build
--release` in its submodule with that target directory; their time was
not measured here, the builds existed); then `cargo xtask mason setup` (Debian mirror and
GitHub: about 230 MB under `.build/mason-lane`, a few minutes, then
kiln's runner build). A full mode is 20–45 minutes at `-j 4`–`6`.

## Lane defects found and fixed in this package

- `xtask mason` aborted with a core file when its standard output was a
  closed pipe (`xtask mason libcxx --compare a b | head -3`: `println!`
  panics on `EPIPE`, and the workspace's `panic = "abort"` turns the
  panic into SIGABRT; 8 MB core in the working directory). Reproducer:
  `xtask mason libcxx --compare <a> <b> | (exec 0<&-; true)` gave status
  134 and a core; now 141 and no core (`say!`/`say_raw!`/`emit` in
  `xtask/src/mason.rs`, used for every line the lane prints). The rest of
  `xtask` (not this package's) prints with `println!` and has the same
  behaviour.
- kiln's libc++ runner now runs under `ulimit -c 0`: libc++'s death
  tests and the root-only filesystem tests abort by design and wrote
  core files into the runner's scratch.
- An in-place `sed -i` on the workspace mount dropped the exec bit of
  `tests/mason/lane/ld/mortar/ld` (committed in 691fb85). clang's driver
  then skips that `-B` directory and links with the system's GNU ld, so
  a `mortar` mode silently reported GNU ld's results: the first `-O2`
  shard-1 mortar run (0 mortar links logged), re-run after the fix. The
  full mortar run had finished before the edit (7219 links logged by
  mortar's shim, each verified). Now `kiln++` refuses a lane `ld` that is
  not executable (status 125) and `xtask mason libcxx` fails a mortar
  mode none of whose links reached mortar (68ad07d).
