# WP-006: the shared-object reader

`spec/elf.md` §6: `mortar_elf`'s reader for shared objects (`ET_DYN`) of the
three targets. It reads the program headers, the dynamic table, the dynamic
symbols, their versions, and the program properties. It finds them through
the section headers, or through the dynamic table alone when the file has no
sections.

## What it does

- **Allocation-free.** It is zero-copy and allocation-free, like the object
  reader. `SharedObject::parse` checks identification, the section header
  table and the program header table, and locates the parts. Each part's
  contents are checked by the accessor that reads it. The §3.11 source scan
  covers the five new modules.
- **Class-generic.** It reads seven new widened records (`Phdr`, `Dyn`,
  `Versym`, `Verdef`, `Verdaux`, `Verneed`, `Vernaux`) through `Record` and
  `Table`.
- **Two entry paths, one view.** `Entry::Sections` and `Entry::Dynamic` give
  identical views of every shared object on the host that has sections. They
  also give identical views of a stripped sample of them (§6.13).
- **Versions.** It reads the version table with its index and hidden bit,
  and walks the definition and need chains, bounded by their bytes. It
  answers "which version does symbol i carry, and is it the default".
- **Copy-relocation facts.** It gives segment alignment, writability and the
  `PT_LOAD` that holds a symbol. It makes no decision with them.

## Decisions the spec records

- **Sections decide when present (§6.3).** GNU ld 2.44, lld 22 and mold read
  a shared object through its section headers only. On an
  `llvm-objcopy --strip-sections` file, GNU ld refuses it ("file in wrong
  format"), and lld and mold find no symbols in it. So `parse` takes the
  dynamic path only when there are no sections. `parse_by` forces either
  path, and the reader does not cross-check them.
- **No symbol count from an empty GNU hash (§6.6).** A GNU hash table whose
  buckets are all 0 states only a lower bound (`symoffset`). GNU ld writes
  `symoffset` 1 in a PIE whose 31 dynamic symbols are all unhashed. Without
  `DT_HASH`, the reader refuses with `UnhashedSymbolCount` rather than read
  one symbol. `readelf -D` cannot list these symbols either, and
  `llvm-readobj` lists none.
- **Hash counts must agree.** When both hash tables are present, their
  counts must agree, or it is `SymbolCountMismatch`.
- **Unique tags and segments.** A tag read as one value must appear once
  (`DuplicateDynamicTag`). `values` serves the tags that repeat. A segment
  type read with `unique` must appear once.
- **Dynamic-path facts.** On the dynamic path, the first global is the first
  non-`STB_LOCAL` symbol. Section indexes are not range-checked, and
  string-table errors name `DT_STRTAB`, not a section.
- **Note alignment.** A note segment's `p_align` of 0 to 4 pads to 4, 8 pads
  to 8, and any other value is an error.

## Evidence

The gate, `MORTAR_REQUIRE_TOOLS=1 cargo xtask ci --quick`, prints `[ci] ok`.
The new tests in `mortar_elf` are:

- L0, `dso.rs`: 26 tests, and `src/hash.rs`: 2 unit tests;
- §6.12, `dso_hostile.rs`: 5 tests, about 28 s in a debug build. They cover
  17 952 truncations, 582 141 edge-value inputs and 180 000 random-mutation
  inputs, over 9 subjects: 3 targets × (by sections, by the dynamic table,
  stripped). There were no panics, and every walk stayed within its step
  bound;
- L1, `dso_tools.rs`: 9 tests. The aarch64 corpus is the longest, at about
  48 s in a debug build.

Each L1 count is the number of items compared, field by field, with both
binutils 2.44 `readelf` and LLVM 22 `llvm-readobj`:

| host `ET_DYN`, x86-64 | 32 | 370 | 1000 | 22915 | 22915 | 252 | 242 | 19 |
| host `ET_DYN`, i386 | 27 | 278 | 797 | 15364 | 15364 | 267 | 195 | 0 |

The host corpus is complete, with no sampling: each target runs in under
60 s. Every file with sections was also read by its dynamic table, and the
two views were identical, except for three aarch64 PIEs. Those are
`gio-launch-desktop`, `gio-querymodules` and `glib-compile-schemas` under
`/lib/aarch64-linux-gnu/glib-2.0/`, and the dynamic table alone refuses them
by name (§6.6). The versioned library was built by GNU ld, lld and mold ×
the three hash styles.

The stripped sample takes every 16th aarch64 file (44 files) and every 2nd
x86-64 and i386 file (16 and 14). Each stripped file gives the original's
view, and its symbols agree with `readelf -D -W -s`: 7149, 17759 and 994
symbols.

L1 found one reader bug before landing: the empty GNU hash above, which first
gave a count of 1. It found six ways the tools' output differs from the bytes,
which `elf.md` §6.13 lists. It also found one way the linkers differ: GNU ld
records a version's parent, and lld and mold do not.

## Open questions

- **`input.md`:** does mortar link a shared object without section headers?
  The reader supports it, but no reference linker does. Should a PIE (an
  `ET_DYN` file with `PT_INTERP`) be accepted as a link input?
- **`resolve.md`:** the policy of copy-relocation alignment and read-only
  status (§6.9). It must also decide which `DT_SONAME` wins when it repeats
  (lld takes the last), and what a hidden-only version or an unknown version
  index means at resolution time.
