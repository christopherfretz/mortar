### 2.1 How the checks work

The input is the set of files that hold a copy of some COMDAT group
(`Resolution.comdat_copies`, keeper first). For each such file, every
defined global or weak symbol in a live copy section is collected, with
the resolved definition of the same name when that one is outside any
group. The collection is sorted by (name, group, file, index) and
checked one name at a time, in parallel over names
(`Pool::map_collect`), then put in order of the diagnostic key, so the
report does not depend on the thread count.

- **W1** (all modes but off): in one group, data symbols (`STT_OBJECT`,
  `STT_TLS`) of the same name with different `st_size`.
- **W2** (all modes but off): one name is a function (`STT_FUNC`,
  `STT_GNU_IFUNC`) in one place and data (`STT_OBJECT`, `STT_TLS`,
  common) in another, over the group copies and the resolved
  definition. `STT_NOTYPE` is neither (N23).
- **W3** (strict): the resolved definition is `STB_GLOBAL`, outside any
  group and not common, and the name also has COMDAT copies.
- **W4** (strict): data copies of a group whose section holds exactly
  the symbol: the section bytes (or the `SHT_NOBITS` size) and the
  relocations, sorted, with each target named by symbol name, `[sec]`
  for a section symbol and `[local]` for a local, differ.

A finding lists up to three files of each class, then "and N more
file(s) with the same definition", then a note naming what differs and
which copy is kept. All four are warnings in every mode (O-40/O-41);
`--fatal-warnings` makes them errors.

## 4. Cost

O-45's budget: at most 3% of the link's wall time for the default-on
checks. Release build, the bench's static workloads
(`.build/bench-work/workloads`, their `response.txt`).

**First version** (median of 15, default vs `--odr=off` alternated):
the ODR phase was 49-52 ms of a 0.27 s protoc link on one thread
(about 18%) and 18.8 ms at the default thread count. Profile of that
phase (protoc, one thread, three runs): collecting the copies'
definitions 1.4-1.6 ms, sorting them 1.4-1.8 ms, the per-key checks
44-47 ms over 25679 keys, the report under 1 µs. The per-key cost was
`resolved()`: it re-read the file's symbol table for every key.

**Now** (`foreign.rs`, `Cx::key` and `agree`): the resolved definition
is looked at only when `Resolution::def` names a definition that is
not one of the copies (an id comparison); in the default mode a key
whose copies are on one W2 side and, group by group, of one data size
is not looked at further, with no allocation. Strict mode does the
full work as before. Phase time from `--odr-stats`, three runs each,
link wall from `--time-phases` (total):

| workload | threads | ODR phase | link wall | share |
|---|---|---|---|---|
| cxx-medium-static (protoc) | 1 | 3.6-3.7 ms | 266-278 ms | 1.3% |
| cxx-medium-static | default | 3.2-3.4 ms | 152-160 ms | 2.1% |
| cxx-medium-g-static | 1 | 3.5-3.9 ms | 590-641 ms | 0.6% |
| cxx-medium-g-static | default | 3.2-3.8 ms | 234-252 ms | 1.5% |
| synthetic-comdat-static | 1 | 10.9-12.1 ms | 562-600 ms | 2.0% |
| synthetic-comdat-static | default | 9.0-24.3 ms | 248-371 ms | 3.6-6.5% |

Profile now (protoc, one thread): collect 1.4-1.5 ms, sort 1.6 ms,
checks 0.35 ms. synthetic-comdat (169507 definitions in 566 groups):
collect 4.8-13.5 ms, sort 3.6-10.2 ms, checks 0.4 ms. **Over the
budget: synthetic-comdat at the default thread count.** What remains is
reading each copy's symbol table (one `Held` per definition) and the
parallel sort of 169507 entries; it scales with the number of copies,
not with the work W1/W2 need, and is left as it is (the supervisor
decides whether the budget or the design moves: a per-group comparison
of the copies' symbol counts before anything is collected would remove
most of it).

The RSS of the first version, default vs off: within 1-2 MiB on all
three workloads (the table of the first hand-back: 138056/137960 KiB,
150652/149044 KiB on protoc).

## 5. Spec findings

Applied in this branch (round 2), all but the harness, N22 and O-44 items, in `spec/odr.md`
(O-41, §8.1 and its W table, §9.1, X20, T-O-41's row) and
`spec/cli.md` §4.2 (W4's id in §8.1's table and §9.1's).


- **O-41, cli.md §4.2** (`--detect-odr-violations` "prints a note"):
  `spec/diag.md` §2.1 has no note severity, so the row is a no-op that
  prints nothing. Proposed: "`--detect-odr-violations` is accepted and
  has no effect; mortar checks by default (O-41)."
- **O-40/O-41 vs the brief**: the brief said `--odr=error` makes W1/W2
  errors; O-40/O-41 keep the W checks warnings in every mode. The spec
  was followed. Proposed for O-41: "`error` promotes the record checks
  (§8.2); the W checks stay warnings; `--fatal-warnings` promotes them."
- **§8.1 W4, diag.md §3.1**: W4 had no diagnostic id. Added
  `odr-contents-mismatch` (strict only).
- **§9.1** shows a place `defined in a.o (kept), at h.h:3`; diag places
  are `file:(symbol)` and carry no source line. Used `a.o:(sym)` with a
  note "the first is kept". Proposed: §9.1's example uses the diag.md
  place form, and the source line waits for WP-073's records.
- **§8.1 intro** ("groups with two or more copies"): W3 (K13) needs
  groups with a single copy, because the other definition is outside
  any group. All live copies are checked. Proposed: "every COMDAT copy,
  and the resolved definition of the same name".
- **§8.1 W2/W3 scope**: only the COMDAT copies and the resolved
  definition are compared. A weak definition outside any group that
  lost resolution is not compared. This is a subset of what
  `weakcheck.py` reports, and protoc shows no difference. Proposed: name
  this as the scope.
- **harness.md `#@ diag:`**: every mortar link of the test must report
  the named diagnostic, so one test cannot hold both a default-mode and
  a strict link of the same shape. Split into separate tests
  (k5-vtable-size / k5-vtable-strict, k13-default /
  k13-strong-and-comdat). Proposed: let `diag:` follow a link step and
  apply to it only (the parser already keys on the step).
- **N22** cannot be shown with g++: the member is `STB_GNU_UNIQUE` and
  every linker reports a duplicate. The test uses clang only (F3).
- **O-44**: the stats fields other than the copy counts and W findings
  are zero until WP-073 (records) and WP-071 (container).
- **Gate**: static-identical now counts 209 links of 52 tests (was 182
  of 43).

## 6. Interfaces

- `mortar_odr` depends on `mortar_diag` and `mortar_elf` as well as
  `mortar_core`/`mortar_meta` (ARCHITECTURE.md's crate table lists core and
  meta; `mortar_resolve` is the precedent).
- `xtask` depends on `mortar_diag` (to render the wording a directive
  matches).
- WP-071 and WP-073 add their kinds to `xtask/src/linktest/odr.rs`
  `kinds()`; otherwise the directive does not recognise them, and an
  unnamed finding of those kinds does not fail a test.
