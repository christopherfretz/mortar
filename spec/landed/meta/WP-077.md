## 3. The mechanism: read the binding (prototype 3)

### 3.1 What it does

The open problem of O-54 was that prototype 2 asked where a module
*would* bind now (`dlsym`), not where it *did* bind. Prototype 3 asks
the module's own relocated slots.

**The check.** When a module's runtime entry runs, the loader has
already bound every relocation of that module: data references always,
and function references when the module is linked `-z now`. A module
links the runtime as an ordinary input. For each dynamic relocation of
type `GLOB_DAT`, `JUMP_SLOT` or `ABS` (`R_*_64`/`R_386_32`) whose
symbol has a row in the module's own table, the runtime:

1. reads the slot. The slot's value, minus the addend for RELA `ABS`
   and `GLOB_DAT`, is the address the reference bound to;
2. finds the module that holds that address, through `dl_iterate_phdr`
   with a 16-entry cache of segment ranges;
3. takes that module's row for the same key whose symbol satisfies
   `base + st_value == address`;
4. compares the two rows' hashes.

The outcome of each reference is one of these:

| the reference bound to | outcome |
|---|---|
| the module's own definition | own: nothing to compare |
| a module with no table | `no-table`: counted, not checked (O-56) |
| a module with a table, but no row at that address | `no-row`: counted |
| a row with the same hash | `same` |
| a row with a different hash | a mismatch |
| a row marked `SYSTEM` | `system`: skipped unless `strict` |
| a module named in `LD_PRELOAD` | an interposition (§5.6) |
| the executable's `R_*_COPY` target | judged against the copy's source: the first module after the executable, in load order, that defines the name, as the loader chose it (CR); `unknown` if that module defines several versions of the name |

**Lazy slots.** A `JUMP_SLOT` whose value lies inside the module itself
but is not its own definition has not been bound yet. The runtime
counts these slots and names them in one warning per module:
`odr-hook-lazy: M: N reference(s) with rows are bound lazily and NOT
checked (link the module with -z now)`. It never passes over them in
silence.

**What it does not need.** No `dlsym`, no state shared between
modules, no exported symbol (`__mason_odr_state` is gone, and with it
R6's version-node trap), no registry, no hash index, and no loader
internals beyond `dl_iterate_phdr`'s public fields.

**Versions come free.** The answer is an address, the address of the
definition the loader really chose, so the version node the reference
named (`.gnu.version`) is already accounted for. `dlvsym` is not
needed.

**What it costs.** It is linear in the module's dynamic relocations:
- a reference bound to its own definition costs one comparison;
- a reference bound into another module costs a binary search in each
  of the two tables (§6.3 has the price and the remedy).

There is no conflict path, so the quadratic case is gone.

### 3.2 Entry points

- **Shared object**: `.init_array.00000`, which runs before priority
  101 and the default priority (case I under GNU ld, lld, mold and
  mortar). The entry checks the module itself.
- **Executable**: `.preinit_array`, built with `-DMASON_RT_EXE`. It
  runs before ANY shared object's constructor (glibc's `_dl_init` runs
  the main program's `.preinit_array` first). It checks:
  - in fatal mode: the executable and every module of the initial set
    that has a table, so nothing user-written runs before the stop
    (case S-fatal: libs2's constructor never runs);
  - in report mode: only the executable and the table-only modules,
    since each runtime module reports itself at its own init and two
    reports of one mismatch are noise.
- **Finding itself**: through `__ehdr_start` (hidden, defined by every
  linker used here). A walk of `dl_iterate_phdr` per entry made 300
  modules cost O(N²) (§6.3).
- **Fatal mode at a library's init**: the first mismatch starts a sweep
  of every other module that has a table. The sweep reports every
  mismatch, quiets the lazy warnings of the other modules, and then
  calls `abort()` (§5.4).

| row | prototype 2 (`dlsym` now) | 1 without `-z now` | **1 with `-z now`, by address (prototype 3)** | 2 audit (`LD_AUDIT`) | 3 initial scope only | 4 `dlvsym` |
|---|---|---|---|---|---|---|
| A1-A3, E, F, C2 | pass | pass | **pass** | pass (functions) | pass (not checked) | as its base |
| R1m (bound at `NOW` before a global module came) | **abort**: asks now | pass | **pass** | pass (AUD-1 shows `h2 -> h2`, `h1b -> h1`) | pass (not checked) | **abort**: still a lookup now |
| R2m (promotion by `NOLOAD\|GLOBAL`) | **abort** | pass | **pass** | pass | pass (not checked) | **abort** |

| B1, B2, C1, D, T1 | report | report | **report** | report for functions only (AUD-3: a `GLOB_DAT` binding is never passed to `la_symbind`) | **missed** (all `dlopen`) | as its base |
| R3m (lazy binding after init) | **silent** | named exclusion `odr-hook-lazy` | **the shape cannot occur**: the slot is bound at load (R3m-now, no report: the process really calls its own body) | report at call time (AUD-2) | missed | as its base |

| CR (copy relocation; not in O-58's list) | not tested | pass, and CR-b missed (the copy has no row) | **pass; CR-b reported** (the copy's source found as the loader found it) | data: never seen | as 1 | as its base |
| G, H, I, J, Q | G slow, quadratic | linear | **linear, no conflict path** | not measured beyond AUD-4 | linear | as its base |

**The verdict on each candidate:**

- **Candidate 1, recorded answers.** Taken, as prototype 3: the slot is
  read once at init and matched by address, not by name, and mortar
  forces `-z now` on a module that gets the runtime (§5.1). Without
  `-z now` the lazy slots are a named exclusion (`odr-hook-lazy`), never
  silent.
- **Candidate 2, glibc's audit interface.** Rejected as the mechanism,
  for five reasons:
  - it never sees data bindings (AUD-3: `dv2`'s `GLOB_DAT` to `dv1`'s
    `dvar` gives no `la_symbind` call), and inline variables, static
    data members of templates and vtables are data;
  - it must be named in the environment or in `DT_AUDIT`; it cannot be
    an ordinary input of the program;
  - it routes every PLT call through `_dl_runtime_profile`;
  - it is glibc-only;
  - its only hook that refuses a load, `la_objsearch` returning NULL
    (FL3), runs before the file is mapped, when no binding exists.

  It remains a possible diagnostic tool for lazy bindings (§9 Q-77.6).
- **Candidate 3, the initial scope only.** Rejected: it gives up B1,
  C1, D and T1, and every row it would avoid already passes under
  prototype 3. Prototype 3 still uses the initial set, but only for the
  executable's `.preinit_array` check in fatal mode, which stops before
  any constructor.
- **Candidate 4, versioned keys with `dlvsym`.** Not needed: address
  identity carries the version (VER-b reports `f@V1`'s body against
  `libp22`'s `f`). A `dlvsym` lookup is still a lookup "now" and would
  still fail R1m and R2m.

## 4. The matrix per target

Who writes the tables:

- **aarch64 and x86-64**: mortar writes every table (`--odr-table=exported`).
  The objects are GCC's, given rows by the test producer (`xtask meta
  write desc --into`), because kiln's emission (K-1) is not used here.
  Both Mason hosts and every shared object with the runtime are linked
  by mortar.
- **Exceptions**:
  - VER's `libnv`, which has two version nodes of `f`: its table comes
    from the test producer (`xtask meta table rows --into`) on GNU ld's
    output;
  - the foreign hosts and executables: GCC with GNU ld, no table;
  - I links each case with bfd, lld, mold (aarch64 and x86-64) and
    mortar.
- **i386**: mortar refuses i386 shared objects (`spec/dyn.md` D-130,
  WP-130), so EVERY table on i386 is the test producer's. GNU ld links
  with a placeholder note, and `xtask meta table rows --into` fills it.
  The runtime is the same object, built by clang++-22 IR and hod a68
  (§6.1).

Each line: case, required outcome, observed (reports, other named
warnings, exit status; 134 is SIGABRT), verdict. `hod` is the object
kiln+hod (hod a68 on i386) build; `gcc` is GCC `-O2` of the same
source.

- qemu's `-E` splits a value at commas (`MASON_ODR=fatal,strict`).

### 4.4 The named exclusions

| id | case | what the runtime says | why it is not a report |
|---|---|---|---|
| `odr-hook-lazy` | R3m-lazy, T2-initial-lazy: a module linked `-z lazy` (glibc's and mortar's default without the option) | `warning: odr-hook-lazy: M: N reference(s) with rows are bound lazily and NOT checked (link the module with -z now)` | the slot binds at first call, after the module's init ran; the option forces `-z now` (§5.1), so this arises only for a module linked without it |
| `T2-dlopen` | a table-only module (no runtime) opened by `dlopen` after start | nothing | nothing of Mason's runs at its load; a runtime module checks its OWN references only. The rule: every module mortar links with the option gets the runtime; a table-only module is one linked without it (another linker, or `--odr-table` alone) |
| O-56 | a module with neither (foreign) | counted `no-table` under `MASON_ODR_STATS` | nothing to compare |

## 5. The modes (proposed rules)

### 5.1 The link-time option

**`--odr-runtime=off|report|fatal`** (default `off`), a new row in the
family of `--odr` and `--odr-table` (`spec/cli.md` §M6). Field:
`diagnostics.odr.runtime`. With `report` or `fatal`, mortar:

1. adds the runtime object for the output's target and kind as an
   ordinary input after the user's inputs: the shared-object flavour
   for `-shared`, the executable flavour (`.preinit_array`) for an
   executable. A static executable has no loader and no bindings, so
   there the option is refused by name (`odr-runtime-static`);
2. implies `--odr-table=exported` when the table is `off`, since a
   runtime without a table has nothing to compare;
3. links the output `-z now`. Without the runtime the option changes
   nothing, so a link without it pays nothing. An explicit `-z lazy`
   together with the option is accepted, and the lazy references are
   then named at load (`odr-hook-lazy`, §4.4). §9 Q-77.2 asks whether
   it should be refused instead;
4. writes the runtime note `NT_MASON_ODR_RT` (`0x4d4f4403`, owner
   `MasonMeta`). Its descriptor is
   `{u32 version = 1, u32 mode (1 report, 2 fatal), u32 flags = 0, u32 runtime id}`.
   The runtime id is §7's digest index. The prototype puts the note in
   its own section, `.note.mason.rt`; §9 Q-77.4 asks where it belongs.

On a target with no embedded runtime, the option is refused by name
(`odr-runtime-unsupported-target`).

### 5.2 The default mode a process runs with

Each entry takes its default from, in order:

1. the main program's runtime note, if it has one;
2. else its own module's note;
3. else `report`.

The program decides, not the plugin: a fatal library loaded into a
report executable reports, and a report library loaded into a fatal
executable stops it (case A3 and others run the fatal host
`mhostf` with report plugins).

### 5.3 The environment override

`MASON_ODR` is a comma list, read once per entry:

| value | meaning |
|---|---|
| `off` | no check |
| `report` | print every mismatch, go on |
| `fatal` | print every mismatch, then stop (§5.4) |
| `strict` | added to either mode: compare `SYSTEM` rows, and treat an `LD_PRELOAD` interposition as a mismatch (§5.6) |

An unknown word is ignored. §9 Q-77.5 asks whether it should give a
warning instead.

`MASON_ODR` wins over the notes (S-env makes a report executable stop;
S-off runs a fatal executable to `main` with no report).

Diagnostics:

- `MASON_ODR_STATS=1` prints one line per module checked:
  `mason-stats M rows= relocs= own= same= differ= interposed= no-table= no-row= lazy= unknown= copy= system=`;
- `MASON_ODR_TIME=1` prints the entry's time.

**The `.preinit_array` entry cannot use `getenv`**: in glibc 2.41,
`getenv` returns NULL there, natively and under qemu
(`exp/preinit-libc.c`: `getenv(HOME)=(null)` while `envp` has 39
entries). The executable's entry reads the `envp` argument that glibc
passes to `.preinit_array` functions.

### 5.4 What fatal does

**At program start (an executable with the runtime).** The
`.preinit_array` entry checks the executable and every module of the
initial set that has a table. It prints every mismatch as `error:`,
then
`mason: fatal: odr-violation-at-load: N mismatch(es); the process stops (MASON_ODR=report continues)`,
then calls `abort()`. No constructor of any shared object and no
constructor of the executable has run (S-fatal: `ctor s2` is never
printed). A foreign executable has no preinit entry: its libraries
check themselves at their own inits (S-foreign), in their own default
mode.

**At a `dlopen`.** The opened module's init entry checks its own
references. On the first mismatch it sweeps every other module that
has a table, prints all mismatches and the fatal line, then calls
`abort()`. dlopen never returns.

**Why `abort()` and not `_exit(status)`.** Under a debugger the stop
lands in the frame of the load that failed. A core dump, when enabled,
holds the loader's state. Harnesses see SIGABRT (status 134) and do
not confuse it with a program's own exit code. 127, the loader's
status for a failed start, was considered; §9 Q-77.1 has both.

**The plain answer on "fail the load": no.** With glibc 2.41, no code
that runs after a module is mapped and bound can make `dlopen` return
an error and leave the process running:

| try | result |
|---|---|
| FL1: the constructor calls `_dl_signal_error` (GLIBC_PRIVATE, the loader's own error path) | the process exits 127 with `fl-host: odr check: failload.so: odr-violation-at-load`; dlopen does not return. A private symbol that kills the process anyway: no gain over `abort()` |
| FL2: the constructor `dlopen(RTLD_NOLOAD)`s and `dlclose`s itself | `RTLD_NOLOAD` returns NULL while the module is being initialised; the load succeeds |
| FL3: the audit interface's `la_objsearch` returns NULL | dlopen returns NULL ("cannot open shared object file") and the process goes on; but this runs before the file is mapped, when nothing has been bound. To use it, the audit library would have to predict the bindings, which is prototype 2's error. `la_objopen`'s return value only selects audit flags (`LA_FLG_BINDTO`/`BINDFROM`), it cannot refuse |

The options left for "fail the load" without killing the process are
API-level, not loader-level, and none of them is proposed here:

- a Mason `dlopen` wrapper that calls `dlopen`, then checks and
  `dlclose`s on a mismatch. It still runs the module's constructors
  first;
- a loader change (glibc or another loader).

### 5.5 A runtime module and a table-only module

| who binds whom | what happens |
|---|---|
| runtime module X binds table-only Y's definition | checked at X's init (T1: report) |
| table-only Y binds runtime module X's definition, Y in the initial set of an executable with the runtime | checked by the executable's `.preinit_array` entry, in fatal and report modes (T2-initial-now) |
| the same, Y opened by `dlopen` | **not checked**: named exclusion `T2-dlopen` (§4.4) |
| table-only Y in the initial set, linked lazy | its function references: `odr-hook-lazy` (T2-initial-lazy); its data references are checked |

A module with neither a runtime nor a table is never checked and never
blamed (O-56). A binding INTO such a module is counted `no-table`.

### 5.6 `LD_PRELOAD` interposition

A binding into a module named in `LD_PRELOAD` (matched by full path or
by base name) is the deliberate interposition of N5. It is printed as
`warning: odr-interposed-at-load: …` and is never a mismatch, in fatal
mode too (P1: the fatal host runs on, exit 0). Under `strict` it is a
mismatch, and fatal stops (P2, exit 134). A preloaded foreign library
has no table, so it is not checked (P3). Interposing strong
definitions such as `malloc` is in no table (N5).

## 6. The runtime as kiln+hod build it

### 6.1 The routes (which front end made the IR)

| target | front end | back end | command |
|---|---|---|---|
| aarch64 | kiln (`.build/target-kiln-next/release/kiln++`) | hod-next | `KILN_BACKEND=hod KILN_HOD=<hod> KILN_HOD_STRICT=1 kiln++ -c -O0 -fPIC -fno-exceptions -fno-rtti [-DMASON_RT_EXE] mason_odr_rt.cpp` |
| x86-64 | kiln, `--target=x86_64-linux-gnu` | hod-next | the same |
| i386 | clang++-22 (`--target=i686-linux-gnu -O0 -fPIC -fno-exceptions -fno-rtti -S -emit-llvm`) | hod a68 | `hod -O0 -filetype=obj -mtriple=i686-linux-gnu -relocation-model=pic --strict rt.ll -o rt.o` |

**Determinism and pins:**

- Every route gives byte-identical objects on a repeat (2 × 2 × 3
  builds; sha256 prefixes):

  | object | `rt` (shared object) | `rtexe` (executable) |
  |---|---|---|
  | aarch64 | `e8c4652ca7549503` | `673be2a6231debbc` |
  | x86-64 | `161782f05b2bedb6` | `df63a18fdb61f3c9` |
  | i386 | `5b8e7a983e5b3f42` | `6b9364537ced2054` |

  (source at b3307bce)
- **hod a68 gives the same bytes as hod-next on aarch64 and x86-64**
  through kiln++ (`KILN_HOD=<a68>`), so one hod pin can serve all
  three targets.
- Nothing was refused and nothing was miscompiled: the runtime compiled
  the first time on every route, `--strict` included. The whole matrix
  passes with the hod objects (§4).

### 6.2 What the runtime needed

**Language and linkage:**

- C++ in the subset; no exceptions, no RTTI, no static constructors of
  its own, no libstdc++, no stdio;
- `ElfW()` throughout, with REL and RELA both walked and the target's
  relocation numbers chosen by `#if`. Nothing assumes 64 bits.
- `__ehdr_start` must be resolved by the linker (bfd, lld, mold and
  mortar all define it).

**Libc symbols** (every route's objects need the same set):

| symbol | what for | can it be avoided? |
|---|---|---|
| `dl_iterate_phdr` | modules and their segments | no (the public interface) |
| `write` | every message, to fd 2 | a raw `syscall` would need per-target inline asm: not worth it |
| `mmap`, `munmap` | the flag map for modules with more than 16,384 dynamic symbols | the map has a slow path that needs no memory (H-nommap) |
| `getenv` | the mode in a shared object's entry | the executable's entry uses `envp` (§5.3) |
| `clock_gettime` | `MASON_ODR_TIME` only | yes, if timing moves to a test build |
| `abort` | fatal | no |

Further notes on the objects:

- i386 adds `_GLOBAL_OFFSET_TABLE_` (PIC).
- GCC `-O2` adds `memset`; hod emits none.
- The runtime avoids 64-bit division (`div10`), so it needs no libgcc
  (`__udivdi3`) on i386.

**stdio.** The question was whether `fprintf`/`stderr` work before
stdio is set up or after it is torn down. `exp/preinit-libc.c` shows:

- `fprintf(stderr)` works in `.preinit_array` and in a
  `destructor(101)` after `main`, natively and under qemu-x86_64;
- `getenv` does NOT work in `.preinit_array` (§5.3).

The runtime still uses no stdio: `write(2)` with a formatter of its
own, so a program's buffered stdout is never interleaved, and nothing
depends on libc's stdio state.

**Object sections** (all three hod routes):

- `.text`, `.init_array.00000` (`.preinit_array` in the executable flavour),
  `.rodata.str1.1`, `.bss` (one pointer: `envp`), `.eh_frame`,
  `.mason.meta` (hod's own unit; i386: 88 bytes), `.note.GNU-stack`;
- `.text` size of the shared-object flavour, against GCC `-O2` of the
  same source:

  | target | hod | GCC `-O2` | allocated total, hod |
  |---|---|---|---|
  | aarch64 | 16,636 | 9,608 | 19,464 |
  | x86-64 | 17,867 | 11,843 | 20,559 |
  | i386 | 27,576 | 11,475 | 30,324 |

  All in bytes;
- hod writes `.eh_frame` although the IR has `-fno-exceptions`. It is
  harmless, and §9 Q-77.7 asks whether to keep it.

### 6.3 Cost (O-54's tables)

In-process time is the sum over every entry of `MASON_ODR_TIME`
(`clock_gettime` around the check), three runs. Wall time per start
uses `MASON_ODR=off` and `=report`, mean of five.

Head b3307bce, aarch64 natively, load 11.3 to 19.1 (the GCC half ran at the higher end):

| modules × rows | hod `-O0` (3 runs) | GCC `-O2` (3 runs) | hod / GCC | prototype 2 (O-54) |
|---|---|---|---|---|
| 4 × 1,250 clean | 0.61-0.82 ms | 0.30-0.32 ms | 2.2 | 0.08-0.09 ms |
| 4 × 12,500 clean | 8.0-8.8 ms | 4.4-7.7 ms | 1.4 | 0.81-0.94 ms |
| 4 × 125,000 clean | 98-108 ms | 61-82 ms | 1.4 | 16.5-18.3 ms |
| 300 × 1,250 clean | 68-78 ms | 25-26 ms | 2.9 | 6.4-6.9 ms |
| 300 × 1,250, one violating key | 58-59 ms | 20-22 ms | 2.8 | 43.8-47.4 ms |
| quadratic: 300 plugins, K = 10 | 1.1-1.3 ms | 0.47-0.55 ms | 2.4 | 3.2-3.4 ms at 200, quadratic |

The prototype 2 column is O-54's, measured on another day at another
load. The clean and the violating 300 × 1,250 cases do the same work
here, so their difference is noise.

Wall time per start (mean of five, `MASON_ODR=off` against `report`; noisy at this load):

| modules × rows | hod: off / report | GCC: off / report |
|---|---|---|
| 4 × 1,250 | 10.0 / 14.8 ms | 9.4 / 14.4 ms |
| 4 × 12,500 | 17.0 / 24.1 ms | 20.0 / 27.1 ms |
| 4 × 125,000 | 107 / 251 ms | 99 / 139 ms |
| 300 × 1,250 | 425 / 492 ms | 562 / 622 ms |

**What the numbers say:**

- **The price of `-O0`** is 1.4× to 2.9× GCC `-O2`. It is smallest
  where the time is memory-bound (large tables).
- **The clean path is 4-10× slower than prototype 2's.** Prototype 2
  made one linear pass over each table. Prototype 3 checks every keyed
  relocation and does a binary search in two tables for each reference
  that binds into another module:
  - at 4 × 125,000, modules 2-4 bind all 375,000 references into
    module 1, at about 260 ns each (hod) and 190 ns (GCC), cache misses
    over 3 MB tables;
  - a reference bound to its own definition costs one comparison
    (b3307bce).
- **The remedy** is a per-module map from `.dynsym` index to row,
  built in one linear pass per target module. It turns both searches
  into lookups and was not done in this prototype (Q-77.9).
- The violating key costs nothing extra: the conflict path is gone.
- **At the operator's scale** (very large, statically linked
  executables), a static executable has no load-time bindings and
  needs no runtime. The cost falls on shared-object-heavy development
  builds and plugin hosts.

Notes on the costs:

- **The quadratic path is gone.** Q, 300 `RTLD_LOCAL` plugins with
  K = 10 private versions of the same keys, opened by the fatal Mason
  host: no report, 1.1-1.3 ms summed over 301 entries (aarch64 hod).
  Prototype 2's conflict path was 3.2-3.4 ms at 200 plugins and grew
  with the square.
- **The `-z now` price.** AUD-4 measures `clang-19 --version` (libLLVM
  and libclang-cpp, a large C++ start) plainly, under `LD_BIND_NOW=1`,
  and under `LD_AUDIT`:

  | `clang-19 --version`, 15 runs each, interleaved | min | median |
  |---|---|---|
  | plain (lazy, Debian's default) | 15.05 ms | 17.13 ms |
  | `LD_BIND_NOW=1` (every module of the process bound at load) | 16.53 ms | 18.10 ms |
  | `LD_AUDIT` (`exp/audit.so`, `la_symbind` on every binding) | 15.71 ms | 18.66 ms |

  Load 10.8 to 15.5. `LD_BIND_NOW` binds every module, every PLT slot
  of libLLVM included; the option binds only the
  modules it links, so this is an upper bound: about 1 ms (6 %) on the
  median for one of the largest C++ starts on the machine. The spread
  between runs (2-4 ms) is larger than the difference.

## 7. How the bytes ship (proposal)

1. **Source**: `mason_odr_rt.cpp` in mortar's tree (proposed
   `runtime/odr/`), a test build of it under `tests/hook/`.
2. **Objects**: six objects checked in (three targets × shared-object
   and executable flavours), embedded in mortar with `include_bytes!`
   in the crate that adds inputs (mortar stays `forbid(unsafe_code)`:
   the runtime is bytes mortar links). Each object is 19-30 KB
   allocated (§6.2); about 140 KB per mortar binary.
3. **Pins**: a file next to the objects names kiln's commit (aarch64,
   x86-64), clang 22's version (i386 IR, until kiln takes
   `--target=i686-linux-gnu`) and hod's commit (a68 for all three:
   §6.1), with the exact commands of §6.1.
4. **CI**: a job that rebuilds the six objects with the pins and fails
   unless the bytes are identical. A hod or kiln bump then shows as a
   byte change, re-runs the matrix (§4) and the costs (§6.3), and
   updates the objects in one commit. Building mortar never needs kiln,
   hod or a cross compiler.
5. **A target without a runtime**: `--odr-runtime` is refused by name
   (`odr-runtime-unsupported-target`). Today mortar cannot link i386
   shared objects (D-130), so on i386 the runtime is usable only when
   another linker links it. Mortar's own i386 support would add the
   i386 objects to what it embeds.
6. **The verifier (a request to O-59 and `spec/plumb.md`)**. Mortar
   writes in the runtime note the runtime id, an index into the
   embedded table of (target, flavour, digest). The verifier would
   check:
   - the note is present exactly when the option asked for it, with the
     id of the output's target and kind;
   - the runtime's entry is the first of `.init_array` (shared object)
     or the only `.preinit_array` entry it added (executable);
   - the output's copy of the runtime's `.text` and `.rodata`, with
     mortar's relocations undone (or the embedded object relocated by
     the verifier at the output's addresses), equals the embedded
     object's bytes;
   - the output is `-z now` (`DF_BIND_NOW`/`DF_1_NOW`) unless `-z lazy`
     was given.

   P-M2 today allows only types `0x4d4f4401` and `0x4d4f4402` in
   `.note.mason`, so either P-M2 takes the third type or the note stays
   in its own section (Q-77.4).

## 8. The §10.3 proposal (rules, replacing "a design direction")

Proposed text for `spec/odr.md` §10.3 ("The load-time check"). Rule
ids are kept; each rule names the tests it needs. The tests are
`tests/hook/run.sh` case ids, to become link-and-run tests of the lane
when the runtime ships.

**O-53 (the runtime).** The runtime is one object per target and kind
(shared object, executable). Mortar adds it as an ordinary input when
`--odr-runtime=report|fatal` is given (§O-53a). It is built by hod at `-O0`
from `runtime/odr/mason_odr_rt.cpp`, through IR from kiln (aarch64,
x86-64) or clang 22 (i386, until kiln takes the target). The source is C++ with no
exceptions, no RTTI, no static constructors of its own, no libstdc++
and no stdio. It needs from libc only `dl_iterate_phdr`, `write`,
`mmap`, `munmap`, `getenv`, `clock_gettime` and `abort`, and it needs
`__ehdr_start` from the linker. Mortar stays `forbid(unsafe_code)`: the
runtime is bytes it links. Tests: I (entry order under four linkers),
the identical-bytes CI job (§O-53b).

**O-53a (the option).** `--odr-runtime=off|report|fatal`, default `off`:
- adds the runtime;
- implies `--odr-table=exported`;
- links `-z now` (an explicit `-z lazy` is kept, and its lazy
  references are named at load);
- writes `NT_MASON_ODR_RT` (`0x4d4f4403`, `MasonMeta`,
  `{1, mode, 0, runtime id}`).

It is refused by name for a static executable
(`odr-runtime-static`) and on a target without embedded runtime bytes
(`odr-runtime-unsupported-target`). Without the option nothing changes:
a link that does not ask pays nothing. Tests: the `spec/cli.md` row;
link tests for the note, the `-z now` flag, the two refusals.

**O-53b (the bytes).** The objects are checked in and embedded. A CI
job rebuilds them with the pinned kiln, clang (i386 IR) and hod, and
fails unless the bytes are identical. A pin bump updates the objects,
the matrix and the cost tables in one commit.

**O-54 (the check: read the binding).** At its entry, a module with the
runtime checks each dynamic relocation of type `GLOB_DAT`, `JUMP_SLOT`
or absolute word whose symbol has a row in its own table:

1. It reads the bound value (minus the addend for RELA absolute and
   `GLOB_DAT`).
2. It finds the module holding that address (`dl_iterate_phdr`).
3. It takes that module's row of the same key whose symbol is defined at
   that address.
4. It compares the hashes.

A value inside the module itself that is not its own definition is a
`JUMP_SLOT` still unbound: it is counted and named
(`odr-hook-lazy`), never judged. A binding into the executable's
`R_*_COPY` target is judged against the copy's source, which is the
first module after the executable, in load order, that defines the
name. When that module defines several versions of the name, the
binding is counted `unknown`. TLS relocations are not read, so
`thread_local` vague variables are a named exclusion (`odr-hook-tls`,
not yet printed: §10). The runtime never asks the loader where
a name would bind (`dlsym`, `dlvsym`), has no state shared between
modules and exports no symbol. Tests: every row of the matrix (§O-58).

**O-54a (entries).**
- **Shared object**: `.init_array.00000`. It checks itself.
- **Executable**: `.preinit_array`. In fatal mode it checks the
  executable and every module of the initial set that has a table,
  before any constructor. In report mode it checks the executable and
  the table-only modules (runtime modules report themselves). It reads
  the environment from its `envp` argument, since `getenv` fails there
  (glibc 2.41).

Tests: I, S-fatal, S-report, T2-initial-now.

**O-54b (memory and malformed input).**
- A per-symbol flag map: on the stack up to 16,384 dynamic symbols,
  `mmap` above. If `mmap` fails, a path that needs no memory.
- A malformed table is named (`odr-hook-malformed-table`) and its
  module is treated as table-less.
- Never silence.

Tests: H-map, H-nommap.

**O-55 (what only load time sees).** Unchanged: the libraries of the
running system, `dlopen`ed modules, indirect dependencies.

**O-56 (modes).**
- **Default**: the main program's `NT_MASON_ODR_RT` mode; else the
  module's own; else `report`.
- **`MASON_ODR=off|report|fatal[,strict]`** overrides it.
- **report** prints every mismatch as a warning and goes on.
- **fatal** prints every mismatch, then a sweep of every module with a
  table, then `mason: fatal: odr-violation-at-load: N mismatch(es); the
  process stops (MASON_ODR=report continues)`, then `abort()`. At
  program start this happens before any constructor; at a `dlopen`, in
  the opened module's init, and dlopen does not return. **No mode makes
  `dlopen` return an error**: no public glibc interface allows it after
  the module is bound (FL1-FL3).
- **strict** compares `SYSTEM` rows and treats an interposition as a
  mismatch.

Tests: C1-fatal, B1, B2, S-env, S-off, P2.

**O-56a (who is checked).**

| case | outcome |
|---|---|
| a module with the runtime | checks its own references |
| a table-only module in the initial set of an executable with the runtime | checked by the executable's entry |
| a table-only module opened later (exclusion `T2-dlopen`) | not checked |
| a module with neither | never checked and never blamed (`no-table`) |
| a binding into a module named in `LD_PRELOAD` | `odr-interposed-at-load`, a warning, never fatal unless `strict` (N5) |

Tests: T1, T2-dlopen, T2-initial-now, T2-initial-lazy, P1, P3,
CR-foreign.

**O-57 (the D-21 boundary).** Unchanged.

**O-58 (the matrix: the gate of every change to the runtime).** Each
row must hold on every target with embedded bytes:

- **must-not-report**: A1-A3, E, F, C2, R1m, R2m, R3m-now, R6 (both),
  R8m, VER-a, P1 (warning only), P3, CR-foreign, CR-mason, Q;
- **must-report**: B1, B2, C1 (and foreign, fatal), D, R4/R5 (three
  forms), VER-b, T1, T2-initial-now, S-*, G, H-*, CR-b, P2;
- **named exclusions**: `odr-hook-lazy` (R3m-lazy, T2-initial-lazy) and
  `T2-dlopen`;
- **runtime-first**: I under bfd, lld, mold and mortar;
- **no crash, no hang**: J.

The cost tables of §6.3 are recorded with each change. Fatal mode ships
only while every must-not-report row is green.

**O-59 (the verifier).** For an output with the runtime:
- the note matches the option;
- the runtime's entry is first;
- the runtime's bytes are the embedded object's for the runtime id;
- the output is `-z now` unless `-z lazy` was given;
- P-M2 accepts type `0x4d4f4403` (or the note's own section, Q-77.4).

## 9. Open questions, with options

- **Q-77.1, how fatal stops.**
  - (a) `abort()`, SIGABRT, status 134. Recommended: a debugger stops
    at the load, and a core dump is possible.
  - (b) `_exit(127)`, the loader's status for a failed start: quiet,
    no core.
  - (c) a configurable status (`MASON_ODR=fatal:N`).
- **Q-77.2, `-z lazy` with the option.**
  - (a) Accepted; lazy references are named at load (`odr-hook-lazy`).
    Prototyped.
  - (b) Refused by name at link time.
  - (c) Mortar binds only the keyed `JUMP_SLOT`s eagerly. ELF has no
    per-relocation flag for that, so it would mean moving those
    references to `GLOB_DAT` (a code-generation change: hod and kiln
    would emit GOT-indirect calls for rowed names).
- **Q-77.3, the default when the executable and a library disagree.**
  - (a) The executable's note wins. Prototyped: the program owner
    decides.
  - (b) The strictest wins.
  - (c) Each module keeps its own.
- **Q-77.4, where the runtime note lives.**
  - (a) A third note type in `.note.mason`; P-M2 changes.
  - (b) Its own section `.note.mason.rt` (prototyped); P-M2 unchanged,
    but a second `PT_NOTE` or a merged one.
  - (c) A field in the table header's `reserved` word; the table format
    changes, so no.
- **Q-77.5, unknown words in `MASON_ODR`.**
  - (a) Ignored (prototyped).
  - (b) One warning `odr-hook-bad-mode`, then the default.
- **Q-77.6, lazy bindings.**
  - (a) A named exclusion. Recommended: the option forces `-z now`.
  - (b) An optional audit library (`LD_AUDIT=libmason_odr_audit.so`) as
    a diagnostic tool that reports lazy function bindings at call time
    (AUD-2). It never sees data, it is glibc-only, and it costs (§6.3).
- **Q-77.7, `.eh_frame` in the runtime.**
  - (a) Keep it: unwinding through the runtime's frames (from a signal
    in fatal mode) works.
  - (b) Ask hod for a flag that leaves it out (about 1.7 KB on i386).
- **Q-77.8, the double check in a fatal executable.** The preinit
  sweep checks the initial set, then each runtime library checks itself
  again at its own init. This is correct and costs twice the clean path
  for those libraries.
  - (a) Accept it.
  - (b) The library skips its own check when the main program has the
    executable flavour in fatal mode and the library is in the initial
    set. Telling a dlopened module from an initial one needs a loader
    fact, or state shared between modules, which the design avoids.
- **Q-77.9, the cost.** The operator asked for hod's code. `-O0` costs
  1.4-2.9× GCC `-O2` (§6.3), and the larger term is the algorithm:
  prototype 3's clean path is 4-10× prototype 2's. The options:
  - (a) a `.dynsym`-index-to-row map per module (4 bytes per dynamic
    symbol, `mmap`ed, built in one linear pass, with the existing
    no-memory path when `mmap` fails). It removes both binary searches
    and is expected to bring the clean path near prototype 2's linear
    cost. Recommended before the runtime ships; not measured;
  - (b) hod optimising (not available: hod is the `-O0` back end);
  - (c) accept the cost: tens of milliseconds at 300 × 1,250, in
    development builds only.

## 10. What was not verified

- **musl** and other loaders: glibc 2.41 only. The runtime uses only
  public interfaces, plus the observed facts that glibc relocates
  `d_ptr`s in place, runs `.preinit_array` first, and returns NULL from
  `getenv` in `.preinit_array`.
- **x86-64 and i386 costs**: measured under qemu-user only (emulation);
  the aarch64 numbers are the costs.
- **kiln's own emission (K-1)**: every row came from the test producer,
  on GCC objects. That a kiln-compiled program's rows hash as the test
  producer's do is WP-075's business.
- **mortar linking i386 shared objects** (D-130): on i386 every module
  was linked by GNU ld, so mortar's `-z now`, `.preinit_array` ordering
  and table writing were not exercised on i386.
- **The verifier**: `crates/mortar_plumb` was not read. Whether it
  accepts the `.note.mason.rt` section was seen only in that every
  mortar link here succeeded.
- **Copy relocations with versioned names**: counted `unknown` by rule,
  not tested.
- **TLS references** (`R_*_TPOFF`, `DTPMOD`/`DTPOFF`): `thread_local`
  vague variables are not checked. A TLS relocation is none of the
  three types the runtime reads, so it is skipped, not misjudged.
  Named here as an exclusion for the spec to state.
- **IFUNC**: an `IRELATIVE` or a `GLOB_DAT` to an ifunc symbol binds the
  resolver's result, an address that is no symbol's `st_value`. It
  would be counted `no-row`. Not tested.
- **`dlclose` then reuse of the address range** within the 16-entry
  cache: the cache lives for one entry only (built per check), so no
  stale range is used across loads. Not tested beyond F and J.
