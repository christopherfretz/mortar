# WP-070: the design of the Mason metadata container and the one-definition-rule checks

Design record. The rules are `spec/meta.md` (MT) and `spec/odr.md` (O);
the work-package cut is `odr.md` §13, the requests to kiln and hod §11,
the amendments to other specs §14, the open questions §15. This file
records how the experiments were run and what they printed, so that a
reviewer can re-run them and compare.

`MASON_ODR=warn|off`, `MASON_ODR_TIME=1` prints its own time.

## 4. Mistakes made and corrected during the experiments

Recorded because a re-runner may meet them:

- Debian's GCC links `--as-needed`; a `-Wl,--no-as-needed` placed
  *after* `-l` options does nothing, so the first hook runs loaded no
  library and measured noise. It must precede the libraries.
- `-Wl,-t` names archives, not members; members come from `-Map`.
- GCC at `-O3` clones an inline function into a local `.constprop`
  copy, so K16d needs `__attribute__((noipa))` to keep a shared COMDAT.
- The native objdump cannot disassemble x86; use the cross one.
- The prototype note sat inside the build-id `PT_NOTE`; retyping that
  segment is what the "segment" variant measures.

## 5. Decisions of the first draft and their fate

- The container is outside COMDAT groups, one unit per TU (`meta.md` §6): kept.
- Records name symbols by anchor, not by string (`meta.md` MT-12; `odr.md` O-4): kept.
- Code bytes are never evidence (B1); W4/W5 are not default checks: kept.
- Default-on record checks and W3: withdrawn (review B1, B5; O-1, O-47).
- `abi.rtti` enforced and the RTTI slot in the layout hash: withdrawn (B3).
- The hook in `.preinit_array`, pairwise against every earlier module: replaced (B6, M2; O-54).
- `--no-odr-check` reads no container byte: kept, made a hard rule with a test (O-42, MT-42, A-8).

### 6.3 Mistakes in the revision experiments

- The note descriptor was taken at name + align(namesz): count read 0.
  glibc's rule is `desc = note + align(12 + namesz)`.
- The compiler turned `resolve()`'s `dlsym` call into a tail call, so
  glibc saw the caller's caller and resolved in the wrong scope (an A3
  false report). An empty `asm volatile` on the result keeps the frame.
- `objcopy -O binary --only-section` writes nothing for a non-allocated
  section; `--dump-section` works.
- `readelf -sW` prints a header line the index parser must skip; COMDAT
  signatures need the last `[`.
- `sed -i` dropped execute bits (exit 126); scripts are run with `bash`.
- Aborting test programs left a core file: `ulimit -c 0` in `hook2.sh`.
- N11's first attempt bound `__divti3` to `libgcc_s`; reworked with
  outline atomics and a `-static-libgcc` library.

## 7. Operator decisions

Each with options, the recommendation and what it costs.

**Default severity (Q1).**
1. *Warnings only* (`--odr=warn`) until a check has been on at zero for a
   release, then the operator moves it to error check by check.
   Recommended. Cost: a violation the checks find can still ship from a
   build whose warnings nobody reads.
2. *Errors for record-based findings from the start.* Cost: the first
   false positive breaks someone's build with nothing to do but turn the
   check off.
3. *Off by default, opt-in only.* Cost: the distinguishing feature is
   unused; violations are found by nobody.

**Q2: the table and the load-time hook.** The hook is a prototype
package (WP-077); nothing ships in M6 without a further decision. What
remains to decide is the table (data only, read by O-24) and, after
WP-077's matrix is green, whether a runtime ships.
1. *Table off by default, opt-in with `--odr-table=exported`; no runtime
   until WP-077's matrix is green and a further decision.* Recommended.
   Cost: O-24 finds violations only against libraries whose builders
   asked for a table; violations that only load time sees are not caught
   (X12).
2. *Table on in a development profile* (no runtime). Cost: 24 bytes per
   exported vague definition (96-363 KB for the system libraries
   measured), and `eu-elflint` fails on every such output.
3. *Table and a reporting runtime on in a development profile once
   WP-077 is green.* Cost: every start pays the check (6-7 ms for 300
   libraries clean on prototype 2, measured; more if the chosen mechanism
   forces `-z now`), a C object in every output, and the shipping
   question Q3. Aborting (`MASON_ODR=abort`) is a later decision still.

**Q3: how the runtime's bytes would be made, if one ships after WP-077**
(none needs a cross compiler to build mortar).
1. *C source and the generated object bytes per target, checked in,
   embedded in mortar; CI rebuilds them with the cross compilers and
   requires identical bytes.* Recommended. Cost: CI needs the cross GCCs
   (it has them); a change to the runtime is a two-step commit; the bytes
   are not Rust.
2. *Machine code synthesized by mortar in Rust per target* (as PLT stubs
   are). Cost: about 250 lines of C become three hand-written encoders;
   calls to `dlsym`, `mmap`, `write` need relocations mortar builds;
   hard to review and to change.
3. *A `no_std` Rust object compiled for each target.* Cost: needs
   `unsafe` (raw pointers into `_DYNAMIC`, the note, `mmap`ed memory), so
   the operator's approval under Mason's rule; and the Rust target
   toolchains in CI.

**Q6: mixed `-std` on USER rows** (`#if __cplusplus` bodies in user
code that really differ).
1. *A finding* (as designed, O-32). Recommended. Cost: a project that
   builds parts of itself as C++17 and parts as C++20 with
   standard-dependent inline code gets warnings it may consider noise.
2. *A stats count, like `SYSTEM` rows.* Cost: a real difference in user
   code compiled under two standards (one body for C++17 callers, another
   for C++20) is never reported.
3. *A per-project switch* (`--odr-mixed-std=report|count`). Cost: one
   more option and a test matrix; defaults still need option 1 or 2.

Also open, smaller (`odr.md` §15): Q16 (catch K16c's one-copy shape
under strict), kept as a question. Q15 was withdrawn by the ruling on
N-m2.
