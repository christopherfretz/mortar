Landed record. The rules are `spec/odr.md` O-24 and O-50 to O-52 (with
O-47's rows 14 and 15) and `spec/meta.md` MT-13. This file gives the
prototype's table (§3), what landed (§2), the tests by id (§4), the
tools' answers (§5), the cost with the table on and off and the read
counter (§6), every spec sentence changed and its evidence (§7), what M4
and WP-077/078 need (§8), the findings (§9) and what was not verified
(§10). The coordinator's ruling after the interim hand-back (marked
**ruling n**) is applied.

## 6. Cost (scope item 4) and the read counter

Release build of this branch (fat LTO). Test-producer libraries of
4,000, 13,000 and 15,000 exported functions (`libstdc++`, `libclang-cpp`,
`libLLVM` sizes of O-50), linked twice (liba, libb: same names, same
hashes, so (b) compares every name and finds nothing); and an executable
exporting that many vague definitions with rows (`-rdynamic`). Each link
is mortar alone on the argument list gcc gave it, 21 interleaved rounds
after a warm-up; wall time, CPU time (user + system of all threads) and
peak RSS, medians.

Wall times move by tens of milliseconds between rounds on this host
(13,000 above 15,000 is the host, not the link); CPU time is the
measure. Reading and comparing two tables costs about 150 ns of CPU per
library row (30,000 rows: +4.6 ms, +3.0 ms at the minimum) and about
65 bytes of peak RSS per row (+1.9 MB); writing costs about 200 ns per
row (15,000 rows: +3.1 ms) and +0.5 MB. Against O-45: these links are
20-40 ms of CPU in all, so the check is 10-18 % of them, above the 3 %
budget for links this small. O-45 is defined on the bench lane's Mason
workloads, where a link that names `libLLVM` and `libclang-cpp` is
seconds long and 30,000 rows are a few milliseconds; that lane does not
exist yet (no library has a table before M4), so the 3 % is not
measured against it. Both costs are zero unless asked for: tables are
read only under `--odr=strict`, written only with `--odr-table`, and
the default mode's row equals the strict link without tables.

The read counter with the table off (`--odr-stats`): the default mode
reads 0 container bytes and 0 tables; `--odr=strict` with libraries
without tables reads 80 container bytes (the executable's one unit) and
0 tables, the same as the same link without the libraries
(`a_library_without_a_table_reads_nothing_more`); with tables, still 80
container bytes and "shared-object tables 2 (2N rows)". A table is read
from the library's bytes resolution already holds: no file is opened and
no byte is read that the link without O-24 does not read.

## 8. What M4 and WP-077/078 need

- **M4 (shared-object output).** `mortar_odr::check(inputs, resolution,
  odr, output: Option<Output>, pool)` (`crates/mortar_odr/src/lib.rs:48`)
  with `Output { needed, executable: false }`
  (`crates/mortar_odr/src/dynamic.rs:33`): a library's rows are
  `NONPREEMPTIBLE` only when protected or bound by `-Bsymbolic` /
  `-Bsymbolic-functions`; `TableRow::row` (`dynamic.rs:62`) takes the
  flags as given, so M4 sets bit 15 per symbol from its binding
  decision (O-51; the `-Bsymbolic-functions` fact exists nowhere else in
  the output). The front's call site is `crates/mortar/src/front.rs:377`
  (today `matches!(plan.kind, Executable | PieExecutable)`), the table's
  `front.rs:607` and `fn note_mason` `front.rs:1254`; versioned outputs
  need the row's version from `.gnu.version` (identity is (name,
  version), MT-13), which the encoder does not carry (the reader takes
  it from the library's own `.gnu.version`). O-24 for a `.so` output:
  the output is not first in lookup order for its users, so (a) does
  not apply as written; M4 writes that rule.
- **WP-077 (hook).** The reader: `mortar_meta::table::{find, Table,
  Row, TableError}` (`crates/mortar_meta/src/table.rs:211`, :119, :34,
  :76), the constants of O-52 (`:14`-`:30`). The table's rows are sorted
  by key, so a runtime can binary-search them.
- **WP-078 (verifier).** The independent check of O-50 (row set equals
  the exported vague definitions with keeper hashes) can reproduce the
  rows from `.dynsym` plus the inputs' units; the encoding to check is
  `table::note` (`table.rs:49`). Executables' rows all carry `0x8000`.

## 9. Findings

1. **Executable rows are all `NONPREEMPTIBLE`.** O-50/O-51 as written
   reserved the flag for protected and `-Bsymbolic` definitions. An
   executable is first in lookup order and its own references to its
   exported definitions are bound at link time, so it always runs its
   own copy; the flag says exactly that. A spec decision, written into
   O-50; to confirm.
2. **eu-elflint** complains twice (segment and section) about the note,
   as the WP-070 experiment predicted; `dyn.md` D-71's "no allowance"
   now holds for outputs without the table only (written into `dyn.md`
   §14 and O-52).
3. **(c) needs no table.** It reads the library's `.dynsym` `st_size`,
   which resolution already read, so it works against any library,
   system ones included; it is strict-only with the rest of O-24.
4. **The harness's `diag` directive does not read `referenced by`
   places,** so `odr-size-mismatch` is matched by the library alone.
5. **`meta table` is quadratic** (it scans `.dynsym` per row): 2.6 s for
   4,000 rows, about 40 s for 15,000 in a debug xtask; test-producer only.
6. `objcopy --remove-section=.note.mason` leaves the `PT_NOTE` entries;
   readers find no note. Not mortar's to fix.

## 10. What was not verified

- musl's loader; glibc's binding of an unversioned reference against an
  earlier versioned library with no definition at index 2 (excluded).
- O-24 and the table for shared-object outputs (`[M4]`); `=full`
  (WP-076).
- Cost on real libraries with tables (none exist before M4) and on the
  bench lane's Mason workloads: only the generated tables of §6, on a
  shared, loaded host.
- gdb on x86-64 (qemu; skipped by name); patchelf; `llvm-strip` on
  mortar's output (measured on GNU ld's in WP-070).
- The i386 target: no table test (kiln and hod make no i386 objects;
  the code is target-independent and little-endian only, which every
  mortar target is).
