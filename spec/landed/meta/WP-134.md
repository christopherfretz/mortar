# WP-134: kiln as a producer of `.mason.meta`

Landed record. The rules are `spec/meta.md` MT-26 (as amended
2026-11-17), MT-31 to MT-33 and `spec/odr.md` O-11, O-17/O-18, O-19,
O-33 to O-35 (O-35 as amended 2026-11-17) and §11 (the K requests and
their rulings, K-4b included). This is the first package that reads what
kiln writes. This file gives the environment (§1), what landed (§2), the
producers table's kiln columns (§3), the read-back of kiln's units (§4),
kind 4 as kiln writes it and how mortar's notes read it (§5), the link
tests (§6), the legal corpus under `--odr=strict` (§7), the cost (§8),
the list for kiln and the spec findings (§9), what depends on the new
kiln (§10) and what was not verified (§11).

## 2. What landed

- **O-35 as amended** (`crates/mortar_odr/src/records.rs`, `kind5`,
  `kind5_one`, `c_linkage`): rows of one key whose `EXTERN_C` bits
  differ are compared by `size` only (a warning, "compared by size
  only"); a finding whose rows have `type_name` 0 names the objects and
  says `-fmason-metadata=detail records it (spec/odr.md O-35)`. Unit
  tests both directions in `crates/mortar/tests/odr_records.rs`. Cost:
  one more comparison per kind 5 group that already differs; nothing on
  a group whose rows are equal.
- **Producers `kiln` and `kiln-hod`** (`xtask/src/mason/producers.rs`,
  `xtask/src/linktest/engine.rs` `Producer`): two producers, not one
  with two routes, because the two routes are two objects (kiln's llc
  object and hod's) and a difference between them must be a row of its
  own in the baseline. Both take the container from kiln itself
  (`-fmason-metadata=<level>`: the level a test's `meta` step implies,
  `level detail` included, else the default); `kiln-hod` adds
  `-O0 -fkiln-backend=hod`.
- **`(kiln)` compile steps and `requires: kiln`** (`xtask/src/linktest/
  target.rs` `Family::Kiln`, `Feature::Kiln`; `spec/harness.md`
  "requires", "Missing tools"): a test compiles with kiln by name; such
  a step is never replaced by another producer. `requires: kiln` is met
  by a kiln that passes the probe `xtask/src/mason.rs`
  `KilnRecords::find`: it compiles a small unit at `detail` and needs an
  enumeration row (`type name=6ProbeE`), kind 4 and a kind 5 row;
  otherwise the reason is "writes no .mason.meta enumeration rows, kind
  4 or kind 5 (older than kiln d854b23bc)". A missing kiln is an error
  under `MASON_REQUIRE_TOOLS=1` only, so the lane's gate with the older
  pinned kiln SKIPs these tests by name. `cargo xtask static-identical`
  does not compare such a unit either (`engine::Results::optional_skip`,
  `report::Report::optional_skips`, `identical.rs`). The AArch64
  baseline has the kiln tests' 28 links (cut with d854b23bc; a kiln
  pin that changes kiln's bytes changes these rows and nothing else).
- **`cargo xtask meta dump`** (`xtask/src/meta.rs` `comment_items`):
  when kind 4 is printed raw because the typed text does not reproduce
  the bytes (kiln's units, whose entry order and padding the typed
  writer does not keep), each kind 3 row's entry is decoded as comment
  lines (`# details 0x.. (name): N items` and `#   <item>`), or
  `# meta-malformed: details ...`.
- **Nine link tests**, `tests/link/odr/kiln-*.test` (§6).

## 5. Kind 4 as kiln writes it, and mortar's notes

The supervisor's question: how does the first-difference note read for
each of kiln's shapes. Exact texts (from `kiln-k4-shapes.test` and
`kiln-k4-details.test`), each with a proposal; the format is unchanged.

(a) **A virtual base.** "base 3VB1 at offset 12 (virtual) in a.o; base
3VB2 at offset 16 (virtual) in b.o". Reads well. kiln hashes a virtual
direct base twice (K-4b) and writes one base item with VIRTUAL (bit 5)
per virtual base: `Mid` shows two virtual base items.

(b) **A member of unnamed class type.** "member 'f' (f) at offset 0 in
a.o; member 'l' (l) at offset 0 in b.o". kiln writes an item with an
empty name and empty type, then the nested items. The note names the
nested member as if it were the class's own and gives its offset
relative to the unnamed member. Proposal: "member 'f' (f) at offset 0
of the unnamed member at offset 0 in a.o; ...". **Spec finding (O-19):
the number of nested items is not encoded**, so where the nested items
end is ambiguous (an unnamed member followed by a named one reads the
same as an unnamed member with two members). Proposed text: "an unnamed
class-type member's item carries in `width` the number of items that
follow and describe it".

(c) **Vtable slots.** "vtable slot 2: _ZN1V1gEv in a.o only";
"vtable slot 1: __cxa_pure_virtual in a.o; vtable slot 1: _ZN1P1fEv in
b.o". The slot index is the component index without RTTI
(offset-to-top counts, K-4b), so the first virtual function is slot 1
and the second slot 2; a developer counting virtual functions from 0
reads "slot 2" as the third. Proposal: "virtual function 2 (vtable
slot 2)" or a sentence in the note's help: "slots count from the
offset-to-top entry". Pure slots name `__cxa_pure_virtual`; a deleted
one `__cxa_deleted_virtual` (as the vtable).

(d) **A negative enumerator.** "enumerator 'N0' =
0xfffffffffffffffe in a.o; 'N0' = 0xfffffffffffffffd in b.o". `meta
dump` prints the same value in unsigned decimal. Proposal: signed
decimal when the underlying type is signed ("'N0' = -2 in a.o; 'N0' =
-3 in b.o"), in the note and the dump.

Also seen:
- At the default level (no kind 4), a same-size difference of an enum
  reads "the layouts differ (members, offsets, bases or vtable) with the
  same size 4 and alignment 4", class wording for an enum. Proposal:
  "the enumerators or the underlying type differ" when the row has ENUM.
- `enum H : unsigned` against `enum H` (the layout hash differs by the
  scoped/fixed byte, K-4b): "the layout details are equal: the
  difference is in something kind 4 does not describe". Proposal: kind
  4's underlying item, or the note, says "fixed" ("underlying type j
  (fixed) in a.o; j in b.o").

## 7. The legal corpus under `--odr=strict` (scope 5)

Two corpora, both legal by construction, compiled by kiln d854b23bc
with `-fmason-metadata` and linked (`g++ -static -B <wrapper>`) by
mortar with `--odr=strict --odr-stats`, mortar at this package's head
(WP-146 in the base). Every program links and runs with its expected
output.

**A 14-unit C++ program** (`main.cc`, `tu0..tu11.cc`, `c.c`; templates,
virtual classes, `shared_ptr`, `variant`, `optional`, strings, maps,
lambdas, enums, statics in inline functions), units alternating `-O0`
and `-O2`, llc and hod, levels `detail`, `default` and `all`:

| config | rows | kind 3 | kind 5 | record findings | W1-W3 | W4 | container / objects |
|---|---|---|---|---|---|---|---|
| aarch64, libstdc++, c++20 | 18,657 | 10,153 | 8,298 | 0 | 0 | 2 | 2,281,072 / 7,523,920 B |
| x86-64, libstdc++, c++20 | 18,657 | 10,153 | 8,298 | 0 | 0 | 2 | 2,312,120 / 7,318,208 B |
| aarch64, libc++ 22, c++20 | 19,376 | 9,030 | 10,127 | 0 | 0 | 0 | 2,679,856 / 9,372,592 B |
| aarch64, libstdc++, c++17/20/23 mixed | 16,893 | 8,625 | 8,062 | 2 (O-32 warnings) | 0 | 3 | 2,029,872 / 7,139,888 B |

Each finding examined:

- **W4 `_ZTVSt18bad_variant_access` and `_ZTVSt23_Sp_counted_ptr_inplace
  <shared::Leaf,...>`** (both libstdc++ configs, the mixed one too): the
  vtables differ between `-O0` and `-O2` units in the D1 slot, which at
  `-O2` points at the D2 symbol (`_ZNSt9exceptionD2Ev`): kiln aliases
  D1 to D2 at `-O2`, as clang does (GCC does not). A true difference of
  bytes with the same behaviour: the documented strict-only N3. Not a
  false finding of mortar or of kiln's rows. Reproduction: one class
  with a virtual destructor in a header, one unit at `-O0`, one at
  `-O2`.
- **W4 `_ZZN6shared8greetingB5cxx11EvE1gB5cxx11`** (mixed -std only):
  `inline const std::string& greeting() { static const std::string g =
  "hi"; return g; }`. In the C++20 and C++23 units `g` is
  constant-initialized (`.data` with a relocation to its own SSO
  buffer); in the C++17 units it is dynamically initialized (`.bss`,
  32 bytes). A true difference, and legal (the guard variable makes the
  C++17 initializer run over the constant one with the same value). W4
  has no -std downgrade as O-32 has for rows; it is a strict-only
  warning, so the default is unaffected. A spec question for W4 (§9).
- **`odr-type-mismatch` `St12memory_order`** (mixed -std): an unscoped
  enum in C++17, `enum class memory_order : int` in C++20: a real
  difference of a system type across -std, an O-32 warning, as the rule
  says. The note uses the class wording (§5).
- **`odr-type-mismatch` `std::__detail::__variant::_Uninitialized<
  std::string, false>`** (mixed -std): libstdc++'s `<variant>:244`
  defines it with an unnamed union member from C++20 on; an O-32
  warning ("unnamed member at offset 0 in tu1.cc.o only").
- `__bool_strings` (WP-146's false W4): not seen in this corpus, before
  or after WP-146 (no unit instantiates it): nothing confirmed either
  way here.

Before the second merge (WP-146 absent) the counts were the same.

## 9. For kiln, and the spec findings

**What kiln writes that differs from the spec or the test producer:**

- K-a (MT-26): `producer` is `kiln 1.2.1` on the hod route too; MT-26's
  example writes `kiln 0.1.0 (hod 0.1.0)`. Units: every `-fkiln-backend=hod`
  unit. Harmless for the checks (the row is informative); for Tuck the
  backend is lost.
- K-b (MT-26): no `odr.layout-scheme` row. Allowed ("a unit without
  the row uses its `odr.scheme` for layouts"), and right while kiln
  writes no kind 2; once K-2 lands, the two serializations are two
  schemes and the row is needed (a note for K-2, not a defect).
- K-c (MT-26): C units write `abi.rtti=off` and `abi.exceptions=off`;
  GCC's C has neither (the test producer writes no such row for C). The
  rows are informative and do not make a mismatch with a C++ unit only
  because those keys are compared per language. A C unit with
  `-fexceptions` should write `on`.
- Fine as written: `abi.stdlib-debug` `off` with ENFORCE on every C++
  unit; `abi.stdlib-hardening` only under `_GLIBCXX_ASSERTIONS` (MT-26:
  "left out when the library has none"); `odr.scheme` only on units with
  hashed rows (C units have none).
- Nothing else: kinds 3, 4 and 5 agree with O-17/O-18, O-19 (K-4b) and
  O-33 on every unit checked (§4), and with mortar's reader on 48 units
  and format-like-g.cpp.

**Spec findings** (rule id, proposal):

- O-19: the nested-item count of an unnamed class-type member (§5 b).
- O-34 is not implemented (its register says "cannot run yet"); kiln's
  kind 5 against a foreign `st_size` gives nothing (`kiln-mixed.test`).
- The notes of §5 (slot numbering, signed enumerators, enum wording at
  the default level, relative offsets in unnamed members, fixed enums).
- K14's place lines say "defined differently in b.o" for a declaration;
  a C/C++ pair lists the summary differences (`lang`, `std`,
  `abi.rtti`...) in its note although O-32 does not judge them: noise.
- W4 under strict: vtables whose D1/D2 slots differ by destructor
  aliasing (kiln at `-O2` aliases D1 to D2 as clang does; GCC does not)
  are the documented strict-only N3 (§7).
- W4 under strict reports a constant-initialized against a dynamically
  initialized static local across -std (§7, `greeting()::g`): true and
  legal. Proposal (`odr.md` §8.1): W4 says, as O-32 does for rows, when
  the copies' units differ in `std` ("the units' -std differ: the
  initialization may differ legally").
- Not kiln's: GNU ld 2.44's x86-64 static output of an IFUNC address
  taken from data gets the verifier's F2 (GCC objects too).

- O-34 (not implemented).

- The libc++ test suite: the corpus is the Mason lane's programs and a
  14-unit program (§7), not libc++'s tests.
- The x86-64 static-identical baseline (cut on an x86-64 host only): it
  lacks the kiln tests' rows; on such a host with a kiln that passes
