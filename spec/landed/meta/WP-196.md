## 3. The runtime's changes

**Q-77.9: the maps.** Prototype 3 found each row with binary searches,
one in each of the two tables. Two maps from `.dynsym` index to row
index now replace them, 4 bytes per symbol, each built in one linear
pass.

- **The checked module's own map** covers the indexes up to the largest
  index a row names. It also carries the flags "done" and "lazy" that
  prototype 3 kept in a separate 16,384-byte flag map. It sits on the
  stack up to 4,096 entries (the same 16 KB of stack) and is `mmap`ed
  above.
- **The map of a module that references bind into** (`y`) is built at
  the first binding into a `y` of at least 64 rows. It is `mmap`ed and
  kept in the 16-entry module cache for the entry's duration. The
  candidates come from `y`'s own `DT_GNU_HASH` (else `DT_HASH`); the
  name's hashes are computed in the same pass as its FNV-1a key. A
  candidate counts when its address is the bound address and its row's
  key is the name's.

When `mmap` fails (or under `MASON_ODR_TEST_NOMMAP=1`), both lookups use
the binary searches. The statistics line then says `path=slow`.
H-nommap and RB-4097/16385-nommap pass that way.

**Bounded reads (O-54b; MT).** Every read of a module's memory now goes
through `in_mod()`, which admits a range only when it lies inside one
of the module's readable `PT_LOAD` ranges. §7 lists the reads. A
malformed table, dynamic section or symbol table is named with its
reason and never read (§7).

**Q-77.4.** The note is found by type `0x4d4f4403` and owner
`MasonMeta` in any `PT_NOTE`, and the test notes are now in
`.note.mason`. Measured: mortar keeps an input `.note.mason` holding the
type-3 note beside its own table note (`libs2.so`: one `.note.mason` of
0x68 bytes holding both), and the fatal default is read from it (S-fatal).

**Q-77.5.** An unknown word in `MASON_ODR` gets `mason: warning:
odr-hook-bad-mode: MASON_ODR: unknown word '<w>' (the words are off,
report, fatal, strict); it is ignored, the mode is <default> unless
another word sets it`. Empty words are ignored, and other words still
apply.

The ruling asks for ONE warning, but every module with the runtime
reads `MASON_ODR`. The first measurement printed it three times: the
executable's entry and two libraries' (BM-a). Now only the first module
in load order whose note says it carries the runtime prints it. When no
module has the note, each entry prints it. That costs a walk over the
modules, and only on this error path. Measured: one warning for a Mason
executable (BM-a, BM-b) and one for a foreign executable with two
runtime libraries (BM-c).

**SE.** Secure execution comes from `getauxval(AT_SECURE)`, or from the
test seam `MASON_ODR_TEST_SECURE`.

- The seam turns secure mode on only with the exact value `1`; nothing
  turns it off. An earlier draft took any value, so `=0` turned secure
  mode on (caught by SE-seam).
- In secure mode the runtime reads no environment variable, `LD_PRELOAD`
  included, and the notes decide.
- In secure mode the fatal line says `(secure execution: MASON_ODR is
  not read)` instead of pointing at `MASON_ODR=report`.

**CP, IF, TL.** These are the new outcomes `canonical-plt`, `ifunc` and
`tls` of the statistics line (O-54's table), plus `malformed`.

**libc.** The runtime now also needs `getauxval`.

## 4. Cost before and after the index

Two rounds, run back to back (`wp196/cost2.sh`, `cost.sh` unchanged):

- **before**: the starting head's runtime (b52d7a4e, `tests/hook/`
  copied to `wp196/before-hook/`), hod and GCC objects built from that
  source;
- **after**: the final checked-in hod objects, and GCC `-O2` of the
  final source.

Each cell is the range of six in-process measurements: the sum over
every entry of `MASON_ODR_TIME`, three runs per round. The script waited
45 minutes for a load of 6 or below, which never came, so it ran at 1-minute
loads of **9.7 to 15.3** (each half's load is in `cost2-*.log`). **Every
number here is provisional** (above load 6). The aarch64 numbers were
measured natively.

| modules × rows | hod `-O0` before | hod `-O0` after | GCC `-O2` before | GCC `-O2` after | prototype 2 (O-54) |
|---|---|---|---|---|---|
| 4 × 1,250 clean | 0.61-0.78 ms | 0.37-0.41 ms | 0.29-0.33 ms | 0.13-0.17 ms | 0.08-0.09 ms |
| 4 × 12,500 clean | 7.4-9.9 ms | 4.0-10.6 ms | 4.2-5.2 ms | 1.5-2.9 ms | 0.81-0.94 ms |
| 4 × 125,000 clean | 91-128 ms | 44-60 ms | 49-70 ms | 17-24 ms | 16.5-18.3 ms |
| 300 × 1,250 clean | 57-66 ms | 39-47 ms | 19-37 ms | 11-18 ms | 6.4-6.9 ms |
| 300 × 1,250, one violating key | 55-62 ms | 38-49 ms | 19-24 ms | 12-26 ms | 43.8-47.4 ms |
| quadratic: 300 plugins, K = 10 | 0.85-1.02 ms | 0.98-1.32 ms | 0.38-0.57 ms | 1.0-2.0 ms | 3.2-3.4 ms at 200 |

How the index changed the cost:

- **Large tables: 1.8× (hod) and 2.8× (GCC) faster.** At 4 × 125,000,
  modules 2-4 bind 375,000 references into module 1: hod 120-160 ns
  each (was 240-340), GCC 45-65 ns (was 130-190). The two binary
  searches per reference became two map lookups and a short walk of
  `y`'s hash chain.
- **300 × 1,250: 1.4× and 1.7× faster.**
- **The violating key costs nothing extra** (the same work as clean).
- **Against prototype 2's column** (no binding read, wrong on R1m, R2m,
  R3m and R6):
  - GCC `-O2` is now within 1.0-1.5× of it at 4 × 125,000, and 1.7-2.8×
    above it at 300 × 1,250;
  - hod `-O0` is still 2.5-6× above it.

  The remaining gap is the work prototype 2 did not do: reading every
  keyed relocation, finding the module of each address (a 16-entry
  cache, then `dl_iterate_phdr`), and the code quality of `-O0`.
- **The fixed cost per entry rose.** At 300 plugins with 10 private keys
  each (every binding `own`), it went from 0.4-0.6 ms to 1.0-2.0 ms
  summed over 301 entries (GCC), and from 0.85-1.0 ms to 1.0-1.3 ms
  (hod). That is a few microseconds per entry. The timed region is the
  same in both builds: it includes the environment parse. The new fixed
  work is:
  - the validation of the module and of the executable (O-54b);
  - `getauxval` and the secure seam;
  - clearing the module's map up to its largest row index.

  An earlier pair of runs (cost-before.log at load 12-22, cost-after.log
  at load 6-14) put GCC at 0.63 ms before and 0.61-0.91 ms after. The
  spread between rounds is as large as the change. It is not
  investigated further: it is microseconds per `dlopen`.

Wall time per start (`MASON_ODR=off` / `report`, mean of five, one
pair per round), dominated by the load: the "off" column moves as much
as the difference.

| modules × rows | hod before | hod after | GCC before | GCC after |
|---|---|---|---|---|
| 4 × 1,250 | 4 / 6, 7 / 9 ms | 6 / 5, 18 / 21 ms | 8 / 8, 7 / 6 ms | 4 / 4, 7 / 8 ms |
| 4 × 12,500 | 10 / 16, 14 / 23 ms | 15 / 16, 51 / 61 ms | 12 / 17, 18 / 20 ms | 7 / 8, 21 / 20 ms |
| 4 × 125,000 | 74 / 141, 42 / 136 ms | 32 / 85, 81 / 127 ms | 64 / 104, 52 / 85 ms | 39 / 50, 63 / 71 ms |
| 300 × 1,250 | 265 / 345, 438 / 450 ms | 504 / 544, 722 / 771 ms | 206 / 220, 325 / 344 ms | 237 / 223, 424 / 395 ms |

A 1,000,000-row table (RB-1M, §8) costs 35.4 ms of check: 1,000,000
references, each bound to the module's own definition.

rule text.

**CP (canonical PLT).** A non-PIE executable, compiled without PIC,
takes the address of `fmtlite::version()`, which `libcp2` defines
(body 2). `libcp2` takes its own function's address too, so it has a
`GLOB_DAT`.

What the executable's `.dynsym` holds, per linker (`ndx/value`):

| linker | aarch64 | x86-64 | i386 |
|---|---|---|---|
| bfd | UND/0x4005e0 | UND/0x401050 | UND/0x8049060 |
| lld | UND/0x210940 | UND/0x201810 | UND/0x4016e0 |
| mold | UND/0x210680 | UND/0x201690 | (no i386) |
| mortar | UND/0x410770 | UND/0x4016e0 | (no i386 `.so`) |

Every linker gives the executable an undefined symbol with a value: its
PLT entry. `libcp2`'s `GLOB_DAT` slot holds that address, inside the
executable, where no row is.

- **CP-\<linker\>**: the runtime finds the name undefined with that
  value in the executable's `.dynsym`. It judges the binding against
  the first module after the executable that defines the name
  (`libcp2` itself, so `own`), and counts it `canonical-plt=1`. There
  is no report, and `no-row=0`.
- **CP-b-\<linker\>**: `libcp3` defines the name with body 3. Its
  `GLOB_DAT` also binds the executable's PLT entry, which calls
  `libcp2`'s body. It is judged against `libcp2`: one report.

That holds on every target with every linker. **Never a report against
the executable.**

**IF (IFUNC with a row).** `libif` defines `fv` as an IFUNC with a row,
takes its address (`GLOB_DAT`), calls it (`JUMP_SLOT`) and calls a
hidden IFUNC (`IRELATIVE`). The relocations, per target:

- aarch64: 5 `GLOB_DAT`, 1 `IRELATIVE`, 11 `JUMP_SLOT`;
- x86-64: 5, 1 and 10;
- i386: 5, 1 and 9.

Outcomes:

- **IF-own**: the slot holds the resolver's result, inside the module,
  and the symbol is the module's own IFUNC: `ifunc=1`.
- **IF-bind**: `libifb` (a plain `fv`, same body) is opened `LOCAL`
  after `libif` `GLOBAL`. Its binding lands in `libif` at an address
  with no row, and `libif` has an IFUNC row for the key: `ifunc=2` over
  the two modules.

There is no report and no `unknown` on any target. The `IRELATIVE` has
no symbol and is never read.

**TL (`thread_local` inline variable).** `tl1` (5) is opened `GLOBAL`,
then `tl2` (6) `LOCAL` binds `tl1`'s variable. `tl2`'s TLS relocations
are:

- aarch64: one `R_AARCH64_TLSDESC`;
- x86-64: `R_X86_64_DTPMOD64` and `R_X86_64_DTPOFF64`;
- i386: `R_386_TLS_DTPMOD32` and `R_386_TLS_DTPOFF32`.

Each module counts `tls=1` (`tls=2` in all), and there is no warning.
The two bodies really differ (5 and 6). This is the named exclusion
`odr-hook-tls`, and the runtime cannot see it: the slot holds a module
id or an offset.

**HV (hidden vague definitions).** Two modules compiled with
`-fvisibility-inlines-hidden`, bodies 1 and 2. Both have `rows=0
relocs=0`, each calls its own (1 and 2), and there is no report. The
rule text says that the check judges bindings (O-55).

**SE (secure execution, through the seam).**

- **SE-off**: `MASON_ODR=off` on the fatal-default violating program. It
  still stops (exit 134), and `MASON_ODR_STATS=1` is ignored too (no
  statistics line).
- **SE-fatal**: `MASON_ODR=fatal` on the report-default program. It
  reports and runs on.
- **SE-preload**: `LD_PRELOAD` of a Mason library under the fatal Mason
  host. There is no interposition warning: the binding is judged like
  any other binding, reported, and the process stops. P1, the same run
  without secure mode, warns `odr-interposed-at-load` and runs on.
- **SE-seam**: `MASON_ODR_TEST_SECURE=0` is not secure mode, and
  `MASON_ODR=off` applies.

Unexercised: `AT_SECURE` itself. A set-user-ID test needs a binary owned
by another user with the S_ISUID bit, run as root. This workspace's
filesystem silently drops both `chown nobody` and `chmod u+s` (`ls -l`
shows root and no `s`; `getauxval(AT_SECURE)` printed 0), and scratch
outside the workspace is forbidden. qemu-user cannot test it either.
What remains unverified is therefore `getauxval(AT_SECURE)` returning 1
under a real set-user-ID or file-capability start. The line of code is
`if (getauxval(AT_SECURE)) return 1;`.

**MT (a malformed table in another module).** `mt.so` is table-only,
with rows for `version` (1) and `other` (7). It is loaded `GLOBAL`, then
`h2` (runtime, `version` 2) `LOCAL` binds it, under the fatal Mason
host. MT-good, unpatched, reports and stops. The patches
(`mt_patch.py`):

| row | patch | aarch64 / i386 | x86-64 |
|---|---|---|---|
| MT-count | count one past the descriptor | "its table note does not parse …" | same |
| MT-trunc | `descsz` 8 | the same reason | same |
| MT-seg | `PT_NOTE` (and descriptor, count) runs a few rows past its `PT_LOAD`'s end, still in the mapped page | "a PT_NOTE lies outside its loaded segments" | same |
| MT-off | `PT_NOTE`'s `p_vaddr` + 1 GiB, outside every segment | the same reason | **the loader faults** (§8), the foreign host too |
| MT-sym | row 0's `.dynsym` index 0x7ffffff0 | "a row's symbol index is 0 or past .dynsym" | same |
| MT-order | row 0's key all ones | "its rows are not in key order" | same |
| MT-own | `h2`'s own table, count past the descriptor | "...; the module is NOT checked" | same |

Each named row ends `; its definitions are NOT compared (bound from
h2.so)`, with `malformed=1`, no report, exit 0 under the fatal host.

**VC (copy relocation of a versioned name).** `libvc` defines `lvl@V1`
(5) and `lvl@@V2` (6), with a row for each. A non-PIE executable copies
`lvl@V2`:

- aarch64: `R_AARCH64_COPY … lvl@V2`;
- x86-64: `R_X86_64_COPY`;
- i386: `R_386_COPY`.

`libvc`'s `GLOB_DAT` binds the copy. The copy's source defines two
versions of the name, so the binding is `copy=1 unknown=1`, with no
report, on every target.

## 7. The audit: every read of another module

The runtime reads other modules' memory in exactly these places. "In
range" means `in_mod()` admitted the range: it lies inside one of the
module's readable `PT_LOAD` ranges, computed from the loader's program
headers. Only the first 16 such ranges are kept; a module with more is
read only within those.

| # | read | where | bound |
|---|---|---|---|
| 1 | program headers (`dlpi_phdr[0..phnum)`) | `fill_from`, `find_addr_cb` | the loader's (trusted, not module bytes) |
| 2 | every `PT_NOTE` (12-byte headers, owner name, descriptor) | `read_notes` | the whole `PT_NOTE` in range first, else `BAD_NOTE_SEGMENT`; each header needs `off + 12 <= p_memsz`, and its descriptor `doff + descsz <= p_memsz` (64-bit arithmetic) |
| 3 | the table header `{1, count, 24, 0}` | `read_notes` | `descsz >= 16` before the read; `count * 24 <= descsz - 16` (64-bit) |
| 4 | the runtime note `{1, mode, flags, id}` | `read_notes` | `descsz >= 16` before the read |
| 5 | the dynamic section, up to `DT_NULL` | `fill_from` | `PT_DYNAMIC` in range; no `DT_NULL` within `p_memsz` gives `BAD_DYNAMIC` (a module with a table) or no dynamic section |
| 6 | `DT_GNU_HASH` header, bloom, buckets | `fill_from`, `gnu_hash_count`, `each_candidate` | header (16 bytes) in range, then header + bloom + buckets in range (64-bit span) before it is used |
| 7 | `DT_GNU_HASH` chain words | `gnu_hash_count`, `each_candidate` | each word through `read_u32` (in range, else stop) |
| 8 | `DT_HASH` header, buckets, chains | `fill_from`, `each_candidate` | header (8 bytes) in range, then the whole table; chain walk bounded by `nchain` steps |
| 9 | a symbol (`ElfW(Sym)`) | `sym_at` | index < symbol count (when known), and the entry in range; for a module with a table, the whole `.dynsym` (`nsyms` entries) in range up front, else `BAD_SYMTAB` |
| 10 | a symbol's name | `name_at`, `sym_named` | `st_name < DT_STRSZ`, scan bounded by `DT_STRSZ - st_name`; the string table `[DT_STRTAB, +DT_STRSZ)` in range up front |
| 11 | relocation tables (`DT_RELA`, `DT_REL`, `DT_JMPREL`) | `walk`, `has_copy_at` | whole table in range, entry size right, size a multiple of it; `DT_PLTREL` REL or RELA; else the tables are dropped (and, with a table, `BAD_RELOC_TABLE` / `BAD_PLTREL`) |
| 12 | the rows | `build_ymap`, `first_of_key`, `row_by_sym`, `row_by_addr`, `ifunc_row`, `yfind_cb` | the rows (`count * 24`) in range; every row's `.dynsym` index in `[1, nsyms)` and keys in order checked once (`BAD_ROW_SYM`, `BAD_ORDER`), so the map's index reads are in bounds |
| 13 | a slot (the module checking itself) | `walk` | `in_mod(x, slot, word)`, else `BAD_SLOT` |
| 14 | the executable's `R_*_COPY` entries | `has_copy_at` | as 11 |
| 15 | the executable's `.dynsym` and names (canonical PLT) | `canonical_plt_at` via `each_candidate` | as 6-10 |
| 16 | a copy's or PLT entry's source module (first after the executable) | `find_src_cb` | filled by `fill_from` as any module: as 2-12 |

Nothing else of another module is dereferenced. Integer arithmetic on
addresses that a module supplies (`base + p_vaddr`, `d_ptr`, `st_value`)
is only ever compared, never dereferenced without `in_mod()`. The vDSO's
unrelocated `d_ptr`s get the base added; either way `in_mod()` bounds
the result.

The MT rows exercise reads 2, 3, 9 and 12 with bad bytes on three
targets. RB-pltrel would exercise 11, but glibc refuses that module
itself (§8).

A tool's commit is read from its source checkout. That checkout is
`MASON_KILN_SRC`, `MASON_HOD_SRC` or `MASON_HOD_I386_SRC`, else the

The objects carry no path of the build machine: the build copies the
source into a scratch directory and compiles it there by file name. The
same bytes came from another directory.

`cargo xtask odr-runtime` works as follows:

- `--check`, the default, verifies PINS's digests against the
  checked-in files. It then rebuilds the six objects in
  `$CARGO_TARGET_DIR/odr-runtime/` and compares every byte.
- `--update` rebuilds the objects and rewrites them and PINS.
- When a tool is missing, or its commit or version is not PINS's, the
  command is a named skip that prints the variable to set (exit 0). It
  fails instead under `MORTAR_REQUIRE_TOOLS=1`.
- A corrupted checked-in object fails with the object's name.
- It is not in `xtask ci` (the supervisor adds it with the pin move).
- Its unit tests: `pins_round_trip`, `pins_refuses_unknown_keys`,
  `six_objects`.

## 11. What was not verified

- **`AT_SECURE` from the kernel** (§6, SE). Only the seam was
  exercised; this filesystem keeps no owner or set-user-ID bit.
- **prelink**: not installed.
- **musl and other loaders**: glibc 2.41 only. In particular,
  `BAD_PLTREL` and an out-of-mapping `PT_NOTE` on x86-64 cannot reach
  the runtime under glibc (§8).
- **x86-64 and i386 costs**: emulation under qemu-user, not costs.
- **The objects as mortar embeds and links them** (`--odr-runtime`):
  WP-198's. Every module here got the runtime as an ordinary object on
  the command line, and the runtime note from the test's assembly.
- **mortar linking i386 shared objects** (D-130): the i386 rows used
  GNU ld and the test producer's tables. Per §9.1, the i386 rows are
  rerun with mortar's tables before the i386 objects are embedded.
- **kiln's own emission of rows (K-1)**: every row came from the test
  producer.
- **RB-1M under qemu**: aarch64 only.
