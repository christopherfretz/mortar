# WP-204: kiln 19428a411 (`.d5`: `unit.system`, `abi.wchar-sign`, enum bits) meets mortar

Landed record, the successor of `WP-199.md`. The rules are `spec/meta.md`
MT-25 ("Reserved flag bits"), MT-26 (the `unit.system` row; "Keys and
values outside the table") and `spec/odr.md` O-16, O-19, O-32, O-35
("The implementation's own definition"), O-44, as amended here. This
file gives the environment (§1), kiln's three fixes and the next findings
(§2), the reader (§3), the lane (§4), the corpus (§5), for kiln and hod
(§6) and what was not verified (§7).

- **attributes**: `[[noreturn]]` against `__attribute__((noreturn))`,

## 6. For kiln, for hod

For kiln:
1. No defect found in `.d5`.
2. `-fsigned-wchar`/`-funsigned-wchar` are refused as unknown arguments,
   as GCC 14 and clang 22 here refuse them too (measured): no option
   moves `wchar_t`'s sign on these targets, so `abi.wchar-sign` can
   differ only between targets today. If kiln ever accepts such an
   option, the row must follow it.

For hod: nothing found.

For mortar (a follow-up, not done here): beside the O-35 note, §9.1's
fact line `the translation units also differ in unit.system (...: yes;
t.o: (none))` repeats it; harmless, could be left out when the note is
there.

  odr-runtime lane tests run on the checked-in objects and pass.
