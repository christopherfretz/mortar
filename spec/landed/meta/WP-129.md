# WP-129: metadata in `-shared`: hod's `reloc-model` row, the table of a shared object, `--keep-mason-meta` in `Shared`

Landed record. The rules are `spec/meta.md` MT-10, MT-20, MT-26 (the
row `reloc-model` and its paragraph), MT-32 and MT-42 (the row's
exception); `spec/dyn.md` D-117 ("The residual hole") and D-126;
`spec/odr.md` O-24 (the version sentence, R-O10) and O-60; the second
form of `non-pic-in-shared-object` in `spec/diag.md`; the `(hod)`
compile family and `requires: hod` in `spec/harness.md`. This file gives
the environment (§1), the read-back of hod's unit (§2), the rule and its
measurements (§3), the table of a shared object (§4), MT-32 in `Shared`
(§5), the harness (§6), the producers baseline (§7), the list for hod
and the spec findings (§8), the verifier (§9), what depends on the new
hod and kiln (§10) and what was not verified (§11).

## 1. Environment

The host of `WP-070.md` §1 (aarch64, shared with other agents; GCC
14.2, binutils 2.44, LLVM 19/22). hod is NOT the workspace's pin:
`.build/target-hod-next/release/hod`, hod main **b701c7be** (H-3);
kiln `.build/target-kiln-next/release/kiln++`, kiln main **d854b23bc**.
mortar's base: `int/batch-8` (0067720), rebased on `int/batch-9`
(596a946, WP-134 merged) so that the hod probe is WP-134's mechanism.
x86-64 programs run under qemu-user. i386: hod's unit read back; no
`-shared` link (mortar refuses i386 shared objects until WP-130).

## 2. hod's unit, read back (Part 1.1)

36 objects: AArch64, x86-64, i686 x `static`/`pie`/`pic` x `-O0`/`-O2`
x alone or after a test-producer unit written into the IR (`meta write
--into-ll`, a kiln-like container). C by clang to IR, hod `--strict
-relocation-model=static|pic` (`pie` is pic with the IR's PIE level).
Checked by `cargo xtask meta dump` and byte for byte by a script of the
package (`wp129/tools/h3check.py`, not committed):

- every field as hod's H-3 says: `MASN`, major 1, minor 0, producer 2,
  flags 0, `unit_size` 88, `header_size` 32, `block_count` 1,
  `strtab_offset` 64; one kind 1 block, version 1, `block_size` 32,
  `row_size` 16, `row_count` 1; the row `reloc-model` = `static`,
  `pie` or `pic` as the model, flags 0; the string table
  `"\0reloc-model\0<value>\0"`, `strtab_size` 20 (`static`) or 17,
  zero padding to 88; the same bytes in ELF32 and ELF64. No
  `meta-malformed`.
- the section: `SHT_PROGBITS`, flags exactly `SHF_EXCLUDE`, alignment
  8, no group, no relocation section. With the kiln-like container,
  one section: its unit first and unchanged, hod's unit appended.
- `-relocation-model=dynamic-no-pic` writes `static`.
- the two-section form: a container that has a relocation (a pointer
  global in `.mason.meta`, so `.rela.mason.meta`) or that is in a comdat
  group: hod writes its unit in a second `.mason.meta` section; the
  reader reads two containers of one object (the relocated or grouped
  one is not a container, MT-2a/MT-2, and is skipped as such).
- MT-26 as amended holds: the row's three values, enforce no.

## 3. The rule (Part 1.2 to 1.4)

**The rule's sentences** (`spec/meta.md` MT-26, `crates/mortar_odr/src/
reloc_model.rs`, called from `crates/mortar/src/front.rs` for a
`Shared` output):

> In a `Shared` link, a live object one of whose units records
> `reloc-model` = `static` or `pie` and that defines an exported
> preemptible datum is refused, `non-pic-in-shared-object`, naming the
> object, its first such datum in symbol order and the row's value; a
> note counts its other such data. A datum: a non-local symbol defined
> in a section without `SHF_EXECINSTR` (`STT_TLS` included) or common,
> held by `Resolution.preemptible`. `pic` never exempts (D-117's rules
> and analysis run on every object as before); no row, or a value other
> than the three, changes nothing. The row is read in every `--odr`
> mode, `--odr=off` included (a refusal, not an ODR check), from any
> producer's unit; a link with no container pays nothing, and an
> object's containers are read only when it defines such a datum.

The message (`spec/diag.md`, the second form, no relocation):

```
ld: error: noref.o:(g): code not compiled as position-independent defines symbol `g' which may bind externally: it can not be used when making a shared object; recompile with -fPIC
>>> the Mason metadata of noref.o records reloc-model=pie (spec/meta.md MT-26): its code reaches its own definitions without the GOT, so the library would bind `g' inside itself while exporting it preemptible (spec/dyn.md D-117)
```

**Measurements.** hod objects defining and using a global datum `g`
(and the other cases), linked `-shared` by mortar and by GNU ld, loaded
under an executable (`-no-pie`, GNU ld) that defines `g = 100` itself;
AArch64 and x86-64 alike unless said. "before" is mortar before this
package (same tree without the rule); GNU ld's library is the oracle.

| case (source) | model | GNU ld | mortar before | mortar now |
|---|---|---|---|---|
| uses: `g` read by name and its address taken | static, pie | refused | refused (D-117 table: `ADR_PREL_PG_HI21`/`PC32` against `g`) | refused (the row) |
| uses | pic | links, runs `100 100 1` | same | same |
| noref: `g` defined, no code names it | static, pie | links, `3 100` | links, `3 100` | refused (the row; WP-110 Q23) |
| noref | pic | links, `3 100` | same | same |
| hole: `static int before[2]` beside `g`; `at(-1)` reaches `g` by a computed index (no relocation or instruction names `g`) | static, pie | links, `7 100`: the library reads its own `g` while `.dynsym` says preemptible | links, `7 100` (D-117's residual hole: a MISLINK by D-117's own account) | **refused** (the row) |
| hole | pic | links, `7 100` | same | same (C undefined behaviour: `before[-1]`; see §8) |
| func: exported `f` called and its address taken | static, pie | refused | refused (D-117 table, `f`) | same (the row judges data only) |
| func | pic | links, `2 1` | same | same |
| funcall: `f` only called | all three | links, `2` (PLT) | same | same |
| tls: exported `__thread t` | static, pie | AArch64 links (`5`), x86-64 refused | refused (local-exec TLS in a shared object) | refused (the row first) |
| tls | pic | links, `5` | same | same |
| ifunc: exported IFUNC, address compared | static, pie | AArch64 refused; x86-64 links, `4 0` (a wrong address: GNU ld's) | refused (D-117 table) | same |
| ifunc | pic | links, `4 1` | same | same |

The hole closed: `hole.c` (in `tests/link/shared/mt26-reloc-model-hod.
test`): GNU ld and mortar before this package link the `static` and
`pie` objects and the program prints `7 100` (the library reads 7, its
own `g`, the program 100: two instances of one exported datum);
mortar now refuses both. Before the address-level rule ever sees it.

**Functions, TLS, IFUNC** (Part 1.3): calls through the PLT are right
for every model (funcall), and an address taken is refused by D-117's
table, as before; the row adds nothing for functions, and the spec
says nothing more: nothing changed. TLS data is data (`STT_TLS` in a
non-executable section): the row refuses `static`/`pie` objects that
export TLS, which were refused already by D-119 (local-exec in a shared
object) on both targets.

**`Pie` and `Exec`** (the brief's question; a proposal, no rule):
hod's `static` code is PC-relative on both 64-bit targets; the `uses`
library linked `-pie` and `-no-pie` from `static`, `pie` and `pic`
objects, by mortar and GNU ld, links and runs `7 7 1` on both targets.
The premise "a `static` object in a `-pie` link is already refused by
its relocations" does not hold for hod. The row says nothing a `Pie`
or `Exec` link needs (an executable binds its own definitions;
preemption does not arise). Recommendation: no rule (H-3's "no effect"
stands); at most, later, a note naming the row on an existing refusal
of a `-pie` link for its relocations, if a case is ever found.

**Several units in one object** (GNU ld `-r` of two hod objects keeps
both units, measured; mortar has no `-r`): one unit saying `static` or
`pie` refuses the object (the row cannot say which definition came from
which unit). Test: `two.o` in `tests/link/shared/mt26-reloc-model.test`.

**Tests.** `tests/link/shared/mt26-reloc-model.test` (the test
producer writes the row on GCC `-fPIC` objects: refused for `pie` and
`static` (under `--odr=off` and `--odr=strict` too), the note counting
two other data (`k`, the common `c`), two units; `pic`, an unknown
value and no row link and run the interposed `100`; protected and
hidden data and functions only: links). `tests/link/shared/
mt26-reloc-model-hod.test` (hod's own objects: the measurement's cases
above, with `requires: hod`). Unit tests: `reloc_model::tests` (the
values both ways, the key), `linktest::format::tests::steps` (the
`(hod)` family).

## 4. The table of a shared object (Part 2, O-60)

`odr_output` is now `Some` for `Shared` (`executable: false`), so
`--odr-table=exported|full` writes the table of a shared object and
O-24 runs against its `DT_NEEDED` libraries. `NONPREEMPTIBLE`
(`crates/mortar_odr/src/dynamic.rs` `table_rows`): `executable ||
protected || !preemptible`, i.e. for a library exactly the exported
keys outside `Resolution.preemptible` (protected; `-Bsymbolic-functions`
for a function; `-Bsymbolic` and `--dynamic-list` follow without a
change once WP-128 accepts them). The rows' versions are `.gnu.version`
(O-51's rows carry none).

Measured (fixture `shared-o60`): `d` (default data), `f`, `v` (default
functions), `p` (protected): with a version script (node `V1`) the
rows are `d 0x0001`, `f 0x0001`, `v 0x0001`, `p 0x8001` and `.dynsym`
says `@@V1`; with `-Bsymbolic-functions` `f`, `v` and `p` carry
`0x8000`, `d` not. An executable defining `d`, `p`, `f` itself and
linked against each under `--odr=strict` is refused three times; the
notes read the bit (`... runs the output's copy` where clear, `... runs
its own copy (its row is NONPREEMPTIBLE ...)` where set), and the
programs linked without `--odr=strict` print exactly that binding:
`v()` = 42 (10 + 2 + 30) against the versioned library, 15 (10 + 2 +
3) against the `-Bsymbolic-functions` one. O-24 for a `Shared` output:
a library defining `f` differently from its needed `libl.so` is
refused under `--odr=strict` (`o24-shared-output.test`).

Tests: `tests/link/fixtures/shared-o60.fixture`, `tests/link/shared/
o60-table.test`, `o60-reader.test`, `o60-reader-symbolic.test`,
`o24-shared-output.test` (all `xfail(mortar)` for the verifier, §9;
each passes with `--no-plumb`), `o60-table-wp128.test` (`skip(mortar)`:
WP-128; its reference runs show the bindings: 6 under `-Bsymbolic`,
15 under `--dynamic-list={d;}`).

## 5. MT-32 in `Shared` (Part 3)

`--keep-mason-meta` with `-shared` worked without a change (the kept
plan is the front's, before the output kind): the non-allocated
`.mason.meta` holds MT-30's concatenation, hod's units included (two
hod objects: 0xb0 bytes; a.o's unit then b.o's two: 0x178), in no
segment, with `--gc-sections` and with `-s`.

**Loaded bytes** (AArch64 and x86-64; plain, `--gc-sections`, `-s`;
the library linked twice to one name, with and without the option):
program headers equal; every `PT_LOAD` byte equal **but** the ELF
header's `e_shoff`, `e_shnum`, `e_shstrndx` (bytes 40, 41, 60, 62:
one more section) and, with GNU's default `--build-id`, the 20 bytes of
the build ID (it hashes the whole file). With `--build-id=none` only
the four header bytes differ. The same holds for an executable
(WP-076's outputs; measured here on a PIE). Spec cell, §8.

Tests: `tests/link/dyn/odr/mt32-keep-meta-shared.test`,
`mt32-keep-meta-shared-strip.test` (`xfail(mortar)`, §9), and the
`libk.so` link of `mt26-reloc-model-hod.test` (hod's units).

## 8. The list for hod, and spec findings

For hod (relay): the second `.mason.meta` section is placed after the
content sections but **before** `.note.GNU-stack`, the `.rela`
sections and `.symtab` (hod's text says "after every other section";
MT-1 does not care where). Otherwise: checked, fine (every field, both
classes, the three models, `dynamic-no-pic`, appending, the
two-section form).

Spec findings:

1. MT-32 / D-126 item 3, "changes no loaded byte": false as written for
   executables (WP-076) and shared objects alike: the ELF header's
   three section-header fields always change, and the build ID when
   there is one. Recommendation: amend to "no loaded byte but the ELF
   header's `e_shoff`, `e_shnum`, `e_shstrndx` and the build ID" (as
   GNU ld's build ID covers debug sections); the alternative, a build
   ID that leaves out the kept section, is a synth rule nobody asked
   for. Written as [open] in MT-32.
2. MT-42 needed a sentence for the row (a correctness refusal read in
   every mode): written.
3. O-60 statement 2 and D-126 item 1 say a clear bit with a `pic` row
   "is proof" of interposability: true for code with defined behaviour;
   the `hole.c` shape compiled `pic` still reads its own `g` through
   `before[-1]` (undefined behaviour; every linker). No change made.
4. MT-20's two-producer sentence was there (checked against hod's units
   beside a kiln-like unit and in two sections); its tag moved to
   landed. mortar did NOT follow it: `records.rs` `file_value` (O-25,
   O-31) took a file's kind 1 value only when EVERY unit of the file
   stated it, so hod's unit (only `reloc-model`) beside kiln's made
   `abi.rtti` and `isa` unknown and O-25/O-31 went silent on every
   object hod makes (producers: `model-k16c-two-vtable-copies` lost its
   two `odr-vtable-rtti-mismatch` in the hod, mixed and kiln-hod columns
   with the new hod). Fixed to merge by name (units that do not state
   the row do not count; two that disagree still give none); test
   `odr_records.rs` `isa_and_vtable_rtti_beside_a_second_unit` (fails
   before the fix). A missed warning, not a mislink. Left as is: O-11's
   `--odr-stats` count of unit pairs never compared counts hod's unit
   (no `odr.scheme`) as a unit.
5. The harness's `meta` step by objcopy (`hod-objcopy` producer) failed
   on every hod object with H-3 (objcopy cannot add a second
   `.mason.meta`): `xtask/src/meta.rs` `add_with` now puts the
   description's unit before the bytes already there with
   `--update-section`, as hod appends its unit (MT-20); `hod` =
   `hod-objcopy` again on every row.

## 9. The verifier

Findings on correct outputs (tests `xfail(mortar)`):

- **P-M2** reports the `.note.mason` of a shared object: "a .note.mason
  the link does not ask for (O-50: dynamic executables with
  --odr-table, --odr not off)". Reproduction: fixture `shared-o60`
  (any `o60-*` test or `o24-shared-output`).
- **P-D22** reads `_fini` from `.symtab`: on any `-shared -s` output
  (GNU ld, lld, mold and mortar, with or without `--keep-mason-meta`)
  it reports "DT_FINI ... the output defines no '_fini'". Reproduction:
  `mt32-keep-meta-shared-strip.test`, or any `-shared -s` link of one
  C file.

What a verifier rule must check:

- `.note.mason` in a shared object (O-50 to O-52, O-60): present only
  with `--odr-table` and `--odr` not off; one `SHT_NOTE`, `SHF_ALLOC`,
  aligned 8, in a `PT_NOTE` of alignment 8; owner `MasonMeta`, type
  `0x4d4f4401` (and `0x4d4f4402` second with `=full`); rows sorted by
  key then `.dynsym` index; each row's `dynsym` index names a defined
  exported `.dynsym` entry whose name hashes (FNV-1a 64) to the key;
  `NONPREEMPTIBLE` set iff that entry is bound inside the library
  (protected, or `DT_FLAGS`/`DF_SYMBOLIC`, or `-Bsymbolic-functions`
  and `STT_FUNC`/`STT_GNU_IFUNC`, or not in `--dynamic-list`): the
  verifier's own D-112 reading; no row for a hidden or local symbol.
- the kept `.mason.meta` (MT-32): non-allocated, `SHT_PROGBITS`, flags
  0, alignment 8, in no segment; its contents a sequence of units that
  parse (MT-10), each padded to 8, each equal to a unit of a live
  input's container, in `FileId`, section, offset order, none from an
  unextracted member; present iff the option and some live unit;
  loaded bytes as in §5.

## 10. What depends on the new hod and kiln

The new hod (b701c7be): `tests/link/shared/mt26-reloc-model-hod.test`
(its `requires: hod` probe skips it, by name, with the old hod).
`cargo xtask mason producers`' hod columns (§7): with the new hod they
need §8 items 4 and 5 (in this package); with the old hod they are
unchanged. Nothing in the gate fails with the old hod. With the new hod,
`crates/mortar/tests/hod_meta.rs` `the_fixtures_are_hods` failed (hod
b701c7be appends its unit to every fixture object): the objects made
again by b701c7be are in `tests/fixtures/hod-meta-b701c7be/` (README
there), and the test accepts either directory's bytes, so that it passes
with the old and the new hod and still fails for any other; its other
tests link the a598555f objects, unchanged. The new kiln: nothing of this package.

## 11. Not verified

i386 shared objects (refused until WP-130). hod at `-O2` in links (the
read-back covers `-O2`; the link tests use `-O0`). `--odr-table=full`
in a shared object beyond its code path (no test). O-24 for a `Shared`
output beyond one shape. The kept section under `strip`/`objcopy` for a
shared object (WP-076 measured executables). `-Bsymbolic` and
`--dynamic-list` (WP-128). musl's loader.
