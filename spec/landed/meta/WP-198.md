# WP-198: `--odr-runtime=off|report|fatal`

Landed record. The rules are `spec/cli.md` §3.9 (the row) and C-ODR-RT
(what the option does to the link), `spec/odr.md` §10.2 O-52 (the third
note type) and `spec/diag.md` §4.5 (the refusals). The runtime itself is
WP-077's prototype (`spec/landed/meta/WP-077.md`); WP-196 replaces the
objects, WP-197 teaches the verifier the runtime input.

## 1. Environment

The host and tools of `WP-070.md` §1 (aarch64, shared, load average
9-13). The objects under `runtime/odr/obj/` were built from
`runtime/odr/*.cpp` at the base (b52d7a4e) with the PINS' tools
(`cargo xtask odr-runtime`); the x86-64 programs of the lane run under
qemu-user. No i386 program was run.

### 2.1 Decisions

- **`--incremental`**: refused by name (`odr-runtime-incremental`). The
  incremental state keys inputs by file identity; the runtime input is
  no file and has no row. Lifting it needs a state row for embedded
  inputs (keyed by the object's digest); not in scope.
- **explicit `--odr-table=off`**: `conflicting-options` (the runtime
  without a table checks nothing). `--odr-table=all` and `=exported`
  are kept as given.
- **`-nostdlib`**: not refused. The runtime's imports (`write`, `mmap`,
  `munmap`, `getenv`, `clock_gettime`, `dl_iterate_phdr`, `abort`,
  `__ehdr_start`) are ordinary undefined symbols: without libc the link
  fails with `undefined symbol: write` and `>>> referenced by
  <mortar:odr-runtime>:(.text+…)` (the lane's `refusals.test`). A line
  that supplies them itself links.
- **`-r`**: a no-op, class "no-op by nature" (the runtime belongs to a
  final link). There is no `at_r` column in the options table; none was
  added (`docs/status/options-at-r.md` is not this package's). Today
  `-r` is refused (`unsupported option: -r`, RL-7) and the option leaves
  that outcome and its stderr unchanged (tested).
- **`-z lazy`**: accepted; the output binds lazily and `-z now`'s
  guarantee (below) is lost. Stated in C-ODR-RT.
- **`--icf`** is a refused option in mortar today, so it cannot break
  the runtime; nothing tested.

### 2.2 The entry order (case I)

The runtime's entries are `.preinit_array` (exe flavour) and
`.init_array.00000` (both flavours); the input is the last of the line.
Measured with two stand-in objects carrying such entries
(`tests/link/odr-runtime/entry-order.test`, references `bfd`, `lld`,
`mold` and mortar, all four the same output):

- `.preinit_array` entries run in input order;
- `.init_array.NNNNN` entries of equal priority run in input order;
  priority 0 sorts before 101 and before unprioritised `.init_array`.

So a user `.preinit_array` or `.init_array.00000` entry runs before the
runtime's (the lane's `dup.o` relies on this), and the runtime's entry
runs before every constructor of priority 1 or more and every
unprioritised one. That is the order WP-077 §5.1 case I asks for.
`entry-order-runtime.test.pending` is the same with the real runtime.

### 2.3 What keeps the runtime under `--gc-sections`

The rule is E14 Q5 in `crates/mortar_live/src/gc.rs` (`startup_input`,
line 207): `.init_array*`, `.preinit_array`, `.ctors` and the rest are
roots. Everything of the runtime is reached from its entries. Tested in
`options.test.pending` (a gc link runs and reports).

### 2.4 What `-z now` changes

C-ODR-RT: the output gets `DT_FLAGS` `BIND_NOW` and `DT_FLAGS_1` `NOW`;
an undefined function that a lazily bound program never calls now fails
the load. `-z defs` with libc on a shared object still links (tested).

### 3.1 The finding classes for WP-197

All come from the verifier not knowing the runtime input or the note:
I1 (`the map names '<mortar:odr-runtime>', which is not among the
inputs`); M12; M9 (`no option mortar accepts spells it`: the verifier's
own option list); P-D3 (bind now vs the command line); P-D6 (DT_FLAGS
present iff `-z now`, its bits, DF_BIND_NOW without `-z now`, DT_NEEDED
`libc.so.6` not needed per D-11 when only the runtime needs it); P-D7
(the runtime's imports "no input references it"; `__cxa_finalize` of
type FUNC where D-23 expects 0, since libc is now needed); P-D9
(RELATIVE on a linker-made word outside `.got`); P-M2 presence and place
(the third note); P-M3 (init array bytes no input gives); E4 (the
runtime's FDEs, 46 on aarch64).

## 4. What a plain link newly does

Reads `diagnostics.odr.runtime` in `effective`, `embedded`,
`refuse_target`, the grammar's `odr_runtime_rules` and (for Status::Off
rows) `register::Status::runs`; checks one more `Option` in the walk's
`run`, `Needs::is_empty` and `fill`; the grammar records the spelling of
a given `--odr-table`. The binary carries the six objects (about 195 KB)
in read-only data. `=off` output is byte-identical to the plain line's
(tested).
