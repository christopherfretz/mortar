# WP-146: W4 compares a reference into unit-local data by what it refers to

Landed record. The rule is `spec/odr.md` §8.1 (W4's row and "W4's
comparison (normative)") and the exclusion X21 (§1's list; the brief
said "§9's list": the exclusions are in §1). Code:
`crates/mortar_odr/src/contents.rs` (new: the encoding, the comparison,
the unit tests), `crates/mortar_odr/src/foreign.rs` (`w4`, `contents`
call it; the old `reloc_name` encoding is gone). Tests:
`tests/link/odr/w4-local-refs.test`, `w4-local-refs-mutated.test`.

## 1. The finding

kiln-built libc++ under `--odr=strict`: W4 reported the COMDAT copies of
`std::__formatter::__bool_strings<char>::__true`/`__false` in three
units. Each copy has one `R_AARCH64_ABS64` against the section symbol of
the unit's `.rodata.str1.1` plus an addend (`0x4c3`/`0x4c8` in one unit,
`0x485`/`0x48a` in another) at which both units hold `true\0`/`false\0`.
W4 encoded a relocation as (offset, type, `[sec]<section name>`,
addend): the addend is a place in the unit's own pool. A false positive.

## 2. Measurement (scope 1)

Scratch: `.build/target-wp-140/wp146/m/` (`shapes.h`, `a.cc`, `b.cc`,
`run.sh`, `measure.py`, `mixed.py`, `w4count.sh`; removed with the
target directory, recreate from here). A header with eleven COMDAT data
definitions: a template static `constexpr const C*` member = `"true"`;
libc++'s shape (an explicit specialization with two `constexpr`
`{ptr, len}` members, `"true"`/`"false"`); inline variables pointing at
a string, a wide string, a `static const int[3]`, an unnamed-namespace
object and function, a `static const char* const[]` (`.data.rel.ro*`
under `-fPIC`), a `static const double` and `long long[2]` (candidates
for `.rodata.cst*`), and one table of their addresses (global targets).
`a.cc` has other strings, arrays and a function before the header,
`b.cc` one other string. Built by GCC 14.2, Clang 19 and 22, `-O0` and
`-O2`, `-fPIC` and `-fno-PIC`, AArch64, x86-64 and i386: 36
same-compiler pairs, plus 24 GCC-vs-Clang pairs and 12 `-fPIC`-vs-not
pairs of the same source (72 links of two equal units each, `mortar
--odr=strict -e 0`).

Forms per compiler (the target of the copies' relocations):

| compiler | strings | local object / function |
|---|---|---|
| Clang 19, 22 (every option) | section symbol of `.rodata.str1.1` (wide: `.rodata.str4.4`) + addend | section symbol of `.rodata`, `.data`, `.data.rel.ro`, `.text` + addend |
| GCC `-O0` | section symbol of a plain `.rodata` (no `SHF_MERGE`) + addend | section symbol of `.rodata`, `.data`, `.data.rel.ro.local`, `.text` + addend |
| GCC `-O2` | section symbol of `.rodata.str1.8` (AArch64) / `.rodata.str1.1` (x86) + addend | its own name (`_ZL3arr` in `.rodata._ZL3arr`, `_ZN12_GLOBAL__N_13objE`, `_ZL3tab` in `.data.rel.ro.local._ZL3tab`); the function: `.text` section symbol + addend |

No `.L` symbol ever reaches the symbol table (Clang's `.L.str` becomes
the section symbol); no `.rodata.cst*` target appeared (GCC and Clang
put a `static const double` in `.rodata`). i386 (`SHT_REL`): the same
forms with the addend in the section's bytes, so there the old W4 saw
the BYTES differ. The table of pointers is `.rodata` without `-fPIC`
and `.data.rel.ro(.local)` with it; GCC `-O0` strings are in a plain
`.rodata`, Clang's in `.rodata.str1.1`: so a target's kind may not
include writable or mergeable (mixed builds are legal).

W4 findings on the 72 equal pairs: **425 before** (every string member
45 of 45 pairs, `wlit` 21 where the wide pools differ, the local
object/function pointers 35-45), **0 after**. The mutation of `b`'s
`"true"` to `"True"` and `"hello"` to `"hellO"` (GCC `-O2` AArch64 and
i386 `-fPIC`, Clang 22 x86-64 `-O0`): 3 findings each after (`S::t`,
`BS::t`, `lit`, each "the data its relocation at offset 0 refers to");
GCC `-O0` gives none (strings in a plain `.rodata`: X21).

**Why the legal corpus showed none**: no COMDAT data copy in it has a
unit-local target at all. Counted with `elfmini.py` over every COMDAT
data definition that covers its section: the 12-TU mixed program's own
objects 144 copies, protoc's 84 mixed TUs plus `libprotoc.a` 943,
`libstdc++.a` 1,363: **0** with a relocation to a local or section
symbol. Their COMDAT data are vtables, `type_info` objects and names,
guard variables and integral static members, whose relocations name
globals. The shape needs a C++17 inline or template static data member
holding a pointer to a literal or a unit-local object, which libc++'s
`<format>` has and C++11-era code does not. No filter hid them.

## 3. The rule (scope 2)

As written in §8.1 ("W4's comparison"): bytes equal except, for
`SHT_REL`, the field of a relocation to a unit-local target (width per
`R_386_*` type, a table in the rule); relocations in (`r_offset`,
`r_type`) order with equal offsets and types and agreeing targets. A
target is a key (any binding but `STB_LOCAL`: name and addend, as
before) or unit-local: a **string** (absolute type, `SHF_MERGE|SHF_STRINGS`,
entsize E, p = `st_value` + addend a multiple of E in the section and a
terminator after it: the bytes from p to the terminator), an **entry**
(absolute type, `SHF_MERGE` alone: the E bytes holding p, and p mod E),
or anything else: its **kind**, code (`SHF_EXECINSTR`) or data. Strings
agree by bytes and E, entries by bytes, offset and E, keys by name and
addend; any other pair involving a kind-only target, or a string vs an
entry, by kind; a key against a unit-local target agrees (GCC
`.localalias`, Clang `$local`). Classes: each copy joins the first class
whose first copy it is the same as (the relation is not transitive
across forms; a copy that agrees with the first class is never a
finding, so a finding is always a real disagreement under the rule).
The note: "its bytes", "its relocations", "the data its relocation at
offset N refers to"; with bytes too, "its bytes and relocations"
(WP-072's wording, kept: `k5-vtable-strict`'s standard error is
unchanged) or "its bytes and the data ...".

Absolute types (only these are read by content; a PC-relative addend
carries the place's bias): `R_AARCH64_ABS64/32/16`,
`R_X86_64_64/32/32S/16/8`, `R_386_32/16/8`.

**X21** (missed): two copies pointing at different local objects or
functions or at different contents of them, at different strings in a
plain `.rodata` (GCC `-O0`), or at a key on one side and a local on the
other.

**Proposed, not implemented** (the brief's third bullet): a bounded
content comparison for a named local target (`st_size` > 0, an
`STT_OBJECT`): its bytes over `st_size` and its own relocations by the
same rule, depth at most 2, a target already on the path compared by
kind. It would catch GCC `-O2`'s named-local form of X21 (e.g.
`static const int arr[] = {1,2,3}` vs `{1,2,4}` behind an inline
pointer); it cannot help a section symbol + addend (no extent: Clang
and GCC `-O0`, the common forms). Not needed for zero false findings
(the conservative path already gives 0), so not done.

## 4. Tests (scope 4)

Unit tests (`contents.rs`, 8, constructed ELF64 AArch64/x86-64 RELA and
ELF32 i386 REL objects):

| test | pins |
|---|---|
| `same_string_at_different_places_is_the_same` | the kiln shape: `"true"`/`"false"` at different addends, AArch64 and x86-64: no finding |
| `different_string_is_a_finding` | `"true"` vs `"True"`, at different and at the SAME place (the old rule missed the latter): "the data its relocation at offset 0 refers to" |
| `the_place_inside_equal_strings_counts` | `"xtrue"+1` = `"true"`; `"true"` vs `"true"+1`: finding |
| `merged_entries_by_their_bytes_and_the_place_inside` | `.rodata.cst8`: same entry at different places: none; another entry, another offset inside the same entry: finding |
| `other_local_targets_by_kind_only` | section symbol + different addends in `.rodata`, named local vs section symbol, string pool vs plain `.rodata`, non-absolute type, unterminated string, place past the pool: none; `.text` vs `.rodata`: "its relocations" |
| `keys_by_name_and_addend` | key addends differ: finding; key vs local: none |
| `rel_implicit_addends` | i386: the kiln shape none; `"True"` finding; plain `.rodata` none; a key's implicit addend still in the bytes ("its bytes"); an unknown REL width to a local: the copy takes no part |
| `bytes_and_data_together` | the joined note |

## 6. Cost

W4 runs only under `--odr=strict`; `foreign::check` calls `w4` only
when `Checks::w4`, which only strict sets, so `--odr=off` and the
default mode run no new code and read no new byte (O-42). Release
binaries, protoc link, 11 rounds alternated, medians: ODR phase strict
3.69 ms before / 3.62 ms after (min 2.85 / 2.83), warn 2.53 / 2.69
(noise: no W4), off 0.084 / 0.079; outputs byte-identical before vs
after in all three modes. protoc has no unit-local target, so no
content lookup ran: the added cost there is the encoding only. Where
there are such targets, the cost is one read of the target section
(cached per copy) and a scan to the terminator per unit-local
relocation, under strict only.

Compare-cheaply-first (look at content only when name+addend differ)
is NOT sound and not done: equal section name and addend in two units
can hold different strings (`"true"`/`"True"` both at offset 0), which
the old rule missed and the unit test pins.
