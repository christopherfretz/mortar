# WP-076: the ODR opt-ins `--odr-check-archives`, `--odr-table=full` and `--keep-mason-meta`

Landed record. The rules are `spec/odr.md` O-23, O-41, O-42, O-50 to
O-52 and `spec/meta.md` MT-30, MT-32, MT-42. This file gives what landed
(§2), the tests (§3), the tools' answers (§4), the cost of each option
on and off and the O-1 corpus (§5), every spec sentence changed (§6),
what WP-078 and M4 need (§7), the open questions (§8) and what was not
verified (§9). `-r` (MT-30) is not built: §7 says what it needs.

## 1. Environment

The host and tools of `WP-070.md` §1: aarch64, 12 cores shared with
other agents (1-minute load 2 to 6 while these numbers were taken);
Debian's glibc 2.41, GCC 14.2, binutils 2.44, elfutils 0.192, LLVM 22
and 19 (`llvm-strip`, `llvm-objcopy`), gdb 16.3. x86-64 and i386 link
tests run their programs under qemu-user; their gdb checks are skipped
on this host.

## 4. Tools' answers

### 4.1 `.mason.meta` (MT-32's `[unverified]`, resolved)

Measured on mortar's static and PIE outputs (aarch64), each tool's
output compared with the kept bytes:

| tool | the section |
|---|---|
| `strip`, `strip --strip-debug`, `strip --strip-all` | kept, byte for byte |
| `objcopy --strip-all` | kept, byte for byte |
| `objcopy --only-keep-debug`, `llvm-objcopy --only-keep-debug` | kept, contents intact |
| `llvm-strip --strip-debug`, `llvm-strip --strip-all-gnu` | kept |
| `llvm-strip` (default; it removes `.comment` too) | removed |
| `llvm-strip --keep-section=.mason.meta` | kept |
| `eu-strip` | removed |
| `eu-strip -f k.debug` | moved into `k.debug`, intact |

The type and flags stay MT-32's proposal (`SHT_PROGBITS`, no flags,
alignment 8): GNU's tools keep it in every mode; LLVM's and elfutils'
full strips remove every non-allocated section that is not theirs, and
only an allocated section would survive them, which would load bytes
that are not for the program.

### 4.2 `=full` (only where it changes WP-075's answers)

A dynamic PIE (protoc, the corpus of §5.2) with `--odr-table=full`:
`readelf -n` prints a second `MasonMeta` note, `Unknown note type:
(0x4d4f4402)`, `eu-readelf -n` `<unknown>: 1297040386`; `file`
unchanged; `strip`, `strip --strip-all`, `eu-strip`, `llvm-strip` and
`objcopy --strip-all` keep `.note.mason` byte for byte, and each
stripped program runs; gdb runs the program; `eu-elflint --gnu-ld` makes
WP-075's complaint once more for the second note (segment and section:
4 lines against 2 with `=exported`), nothing else.

## 5. Cost (O-42) and the O-1 corpus

Release build, wall time from fork to wait (`wait4`), peak RSS from
the child's `ru_maxrss`; configurations interleaved round by round, the
first round dropped; default thread count. Load 2 to 6.

### 5.1 Plain workloads (no container anywhere)

The bench's static workloads, 21 rounds (41 for `synthetic-archives`):

| workload | default | `--odr-check-archives` | `--keep-mason-meta` |
|---|---|---|---|
| `cxx-medium-static` | 108.1 ms, 146.2 MiB | 107.3 ms, 147.0 MiB | 109.9 ms, 146.9 MiB |
| `synthetic-archives-static` | 50.5 ms, 52.3 MiB | 50.7 ms, 52.1 MiB | 50.7 ms, 52.1 MiB |
| `synthetic-library-static` | 113.8 ms, 166.7 MiB | 113.2 ms, 166.4 MiB | 113.5 ms, 166.5 MiB |
| `hello-cxx-static` | 29.0 ms, 38.5 MiB | 29.0 ms, 38.6 MiB | 29.0 ms, 38.4 MiB |

Within noise: with no container, each option costs MT-6's predicate on
the headers the link holds already. `--odr-table=full` on a static
link does nothing (no table).

### 5.2 The Mason corpus (protoc with a container in every unit)

The corpus: protoc's link (`cxx-medium-static` and `cxx-medium`, the
same objects) with a container added by the test producer to each of
its 168 objects (main and the 167 members of `libprotoc.a` and
`libprotobuf.a`): the four summaries of the link tests and one kind 2
row per defined global or weak function or object (67,826 rows; class
by symbol type, `VAGUE` for weak), hash = the first 16 bytes of
SHA-256 of the name. A model of one definition per name: a first
model hashed (name, size) and strict reported live pairs that differ,
because GCC compiles one inline function to code of different sizes in
different units; size is no proxy for a definition. 125 units are
live (2,713,240 container bytes, 56,505 rows); 43 members are not
extracted (575,960 bytes).

Static, 21 rounds:

| config | time | RSS |
|---|---|---|
| default (`warn`, reads nothing) | 94.7 ms | 146.5 MiB |
| `--odr-check-archives` | 101.5 ms (+6.8) | 147.0 MiB |
| `--odr=strict` | 101.7 ms | 148.0 MiB |
| `--odr=strict --odr-check-archives` | 103.4 ms (+1.7 over strict) | 147.1 MiB |
| `--odr=off` | 93.1 ms | 147.2 MiB |
| `--keep-mason-meta` | 96.9 ms (+2.2) | 149.7 MiB (+3.2) |
| `--odr=off --keep-mason-meta` | 93.7 ms (+0.6 over off) | 150.1 MiB (+2.9) |

O-23's cost in `warn` is mostly the read of the live units it compares
against (the default reads none): 3.3 MB of containers, 56,505 live
rows grouped and 4,447 member rows compared, +6.8 ms; on top of strict,
which reads the live units already, +1.7 ms for the members. The kept
section is 2,713,240 bytes (the live containers exactly; the units are
already multiples of 8): +2.2 ms and the section's size in RSS.

Dynamic (`cxx-medium`), 21 rounds:

| config | time | RSS |
|---|---|---|
| default | 81.4 ms | 123.2 MiB |
| `--odr-table=exported` (6 rows) | 86.5 ms | 125.7 MiB |
| `--odr-table=full` (6 rows + 21,764 hidden definitions, 0 types) | 87.2 ms (+0.7) | 127.4 MiB (+1.7) |
| `--keep-mason-meta` | 82.5 ms | 127.6 MiB |

`=full` over `=exported`: about 30 ns and 80 bytes of peak RSS a row
(696,464 bytes of note for 21,764 rows: 32 bytes a row in the output).
The corpus has no kind 3 rows, so the type rows' cost is not measured
here; they take the same path (one row per group, sorted), and the
groups exist already under any mode that reads them.

### 5.3 O-1

The corpus of §5.2 linked with `--odr-check-archives` in `warn`,
`error` and `strict`: **zero findings**, exit 0, the program runs
(`--version`); 43 members, 43 units, 4,447 rows compared. With the
(name, size) model the archive check did not run into the live
differences strict reported, but the model was dropped, not used as
evidence. The link tests' legal cases (`k17-archive-silent`, the equal
member of `k17-archive-shadow`) say nothing. Real archives on this host
carry no container, so on them the option has nothing to read (§5.1).

## 7. What WP-078 and M4 need

WP-078 (verifier, `spec/plumb.md` §13): P-M1 can tell a kept
`.mason.meta` from a stray one only by the map (the section is named in
it as a synthetic chunk); its contents are units that parse, each
padded to 8, and of live inputs only, in `FileId` order. P-M2 covers
the first note; a rule for the second would check its header, the two
arrays' order, zero layout/size/alignment in definition rows, that no
definition row's key is also an exported row's of the first note, and
that `NONPREEMPTIBLE` is clear. Nothing in this package depends on the
verifier.

M4: `-r` (MT-30) reuses `kept_units` and writes the bytes with MT-1's
attributes, without letting the inputs' containers through as ordinary
sections; a shared object's table with `=full` takes the same rows,
where "hidden" is "not in `.dynsym`" as in executables; `--keep-mason-
meta` for shared objects needs nothing new beyond the output kind.

## 8. Open questions

1. `--start-lib`/`--end-lib` objects that were not loaded behave as
   archive members (`spec/resolve.md`) but are not read by O-23 (only
   `member.is_some()` files are). Recommend: include them, with a test.
2. O-23 compares the hash only; K13's flag differences (O-15, strict)
   are not reported for members. Recommend: unchanged until a corpus
   shows a case.
3. A member unit that does not parse is silent even under strict (the
   member is not part of the program). Recommend: unchanged; `--odr-
   stats` could count them.
4. `=full`'s hidden rows are "not exported" (most definitions of an
   executable), not only `STV_HIDDEN` ones: O-50's word "hidden" read
   as "not bound by another module". The size follows (21,764 rows for
   protoc).

- A static link with `=full` has no test of its own: checked by hand on
