## 5. Cost

Input: 1000 objects, each one unit with 100 kind 2 rows (100,000 rows),
50 of them on COMDAT functions shared by all units and 50 without a
symbol, all hashes equal (no finding); generated with `cargo xtask meta
write --bin` and `gcc -c`. Two variants of the same keys: rows named
(the new path: `defined` per row, and under strict the 50,000 rows
without a symbol are compared) and rows anchored (the existing path:
those 50,000 are unanchored, counted). Release build of this branch,
`/usr/bin/time`, 6 rounds, medians:

| rows | mode | wall | peak RSS | check time (`--odr-stats`) | bytes read |
|---|---|---|---|---|---|
| named | strict | 0.16 s | 51.0 MB | 22.5 ms | 5,776,000 |
| anchored | strict | 0.145 s | 48.8 MB | 18.9 ms | 4,991,200 |
| named | warn | 0.125 s | 57.5 MB | - | 0 |
| anchored | warn | 0.14 s | 56.9 MB | - | 0 |
| named | off | 0.13 s | 56.9 MB | - | 0 |
| anchored | off | 0.125 s | 56.1 MB | - | 0 |

The named variant's strict cost over the anchored one (+3.6 ms check
time, +2.2 MB) is 16 % more container bytes (the name strings) and
50,000 more rows compared, not the anchoring lookup; `warn` and `off`
read no container byte (O-42) and their difference is noise (the
machine's load was 10-13). `off`'s output equals `warn`'s byte for
byte. (Strict's lower peak RSS than warn's is in both variants and is
not this package's; not investigated.)

## 7. Spec questions

- **Q1 (O-19, "fixed")**: kind 4 cannot say whether an enumeration's
  underlying type is fixed or whether it is scoped, though O-18 hashes
  both (K-4b). Proposed: "The `UNDERLYING` item's `value`: bit 0 set
  when the enumeration is scoped, bit 1 when its underlying type is
  fixed; 0 before kiln writes them." The note would then read
  `underlying type j (fixed) in a.o; j in b.o`.
- **Q2 (O-19, `width`)**: does the count include items of kinds the
  reader does not know? mortar counts raw items (the only reading that
  lets an older reader find the end). Proposed: "counted in raw items,
  every kind included".
- **Q3 (O-19, `wchar_t`)**: `w`'s signedness is the target's (signed on
  x86-64, unsigned on AArch64 Linux); kind 1 has no row for it, so an
  enumerator of underlying `w` prints as before. Proposed: an
  `abi.wchar` summary key, or the target from `isa`.
- **Q4 (O-23, `PARTIAL`)**: O-23 was silent on `PARTIAL`; I set those
  rows aside below strict (the option is opt-in in every mode, and O-15
  compares `PARTIAL` only under strict). Proposed text: the sentence
  added to O-23.
- **Q5 (§9.1, C/C++ pairs)**: "summary differences O-32 does not judge"
  read as "keys without `ENFORCE` in both units". Proposed: as written
  in §9.1.
