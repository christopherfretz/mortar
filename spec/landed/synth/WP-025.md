# WP-025 (code) — `mortar_synth`: what landed

Phase 80 of `spec/synth.md`, §4.2 onward: `.eh_frame`, `.eh_frame_hdr`,
the GOT, `.got.plt`, the IPLT and `.rela.plt`, `.symtab`, `.strtab`,
`.shstrtab`, `.symtab_shndx`, the build-id note, `.note.gnu.property`,
the alignment check of the other notes, and `.comment`'s string. Every
chunk has a plan (its size, before layout) and a write step (a pure
function of the plan, the inputs and the addresses), and implements
image §13 `SynthChunk` (`src/image.rs`).

Stage A built every table over a narrow input trait per table, with an
in-memory parser in the tests. Stage B (after WP-025m and WP-023b) joins
`.eh_frame` to `mortar_merge`: `EhSource` is now merge's `EhFrames`
(records, CIE classes, `keepers`, `Record::out_size`) plus each section's
bytes, file, alignment and type; `MergeEh::new(frames, link)` implements
it over any `mortar_merge::Link` (e.g. `Tables`). S-50 is
`mortar_merge::refs::eh_ref`. The tests build `EhFrames` with
`mortar_merge::eh::parse` (`tests/common/mod.rs`) and, for real objects,
run `mortar_merge::phase::run` over a test `Link` (`tests/real.rs`). The
843419 patch size is `Arch::patch(Erratum::E843419)` (`PatchFacts::of`).
`Order::frags_in` is the image's (merged chunks), not synth's.

**Not done (left to WP-027, recipes below):** the throw/catch splice
and the `.symtab` differential. Both need values only the image phase
gives: relocations applied to the copied `.eh_frame` bytes (personality,
LSDA, `pc_begin`), and real input-section and symbol addresses for
`SymAddrs`. No `SymSource`/`SymAddrs` over the real pipeline tables
exists before the driver (WP-021, WP-022 and WP-025m say the same).
x86-64 and i386 GOT tests stay deferred (no x86 arch crate).

*Splice recipe (WP-027).*
1. Compile a static C++ program that throws through two frames and
   catches in `main`, printing `caught N`. Link it with
   `g++ -static -Wl,-Map=ref.map -o ref`.
2. From `ref.map`, take the archive members and objects and each input
   section's address.
3. Run mortar's pipeline over the same inputs, through `phase::run`,
   `MergeEh` and `EhPlan` (code is live as GNU ld kept it). Write
   `.eh_frame` and `.eh_frame_hdr` at `ref`'s section addresses.
4. Apply the `.eh_frame` relocations with the image phase
   (`mortar_a64`), and the hdr's `code_addr` from the map.
5. Assert the sizes are ≤ `ref`'s sections. Overwrite them in a copy
   of `ref` (pad with a zero terminator).
6. Run the copy from the test's `/tmp` dir and expect `ref`'s output.

Once WP-027 links on its own, this test becomes the plain one: mortar's
output runs.

*`.symtab` differential recipe (WP-027).*
1. Link the C++ sets of `real.rs` plus crt files with GNU ld and lld
   (`-static`, and `--discard-none`, `-x`, `-X`), and with mortar.
2. Compare `readelf -sW` as a multiset of `(name, type, bind, vis,
   section name, size)`, and the value as an offset from its section.
3. Expected differences to whitelist: the order of locals (S-74),
   `STT_SECTION` symbols (GNU emits them, S-79 does not), linker-defined
   symbol sets (S-124), and lld's mapping symbols.

## 5. The input traits

`EhSource` (`src/eh.rs`), implemented by `MergeEh` over merge's
`EhFrames` and any `Link`:
- `frames()`: merge's records, classes and terminators, ascending by
  `SectionId` (checked by `EhPlan::new`);
- `info(s)`: the section's file, alignment and `sh_type`;
- `bytes(s)`: the section's bytes.

Merge has already refused every malformed record (S-36 to S-39).

The other inputs come from:
- `SymSource` and `Sections` (`src/symtab.rs`): resolve's symbol columns
  and the liveness of each section (`CoreSections` implements `Sections`);
- `SymAddrs`, `SlotValues` and `code_addr`: the image's address answers;
- `ObjectNotes`: per object, its `.note.gnu.property` sections.

## 6. Spec ambiguities and errors found

Ruled by the coordinator and written into `spec/synth.md`:
- **S-80.** A thunk symbol's addend goes before the suffix:
  `__foo+0x10_veneer`. The 843419 patch size is `Arch::patch`.
- **S-59.** A duplicate initial location is refused at plan time, as
  `malformed`, so the size never depends on a failure found while writing.
- **S-85.** `.symtab_shndx` exists exactly when the output has more than
  `SHN_LORESERVE` sections.
- **S-126.** A `pr_type` repeated within one note combines by its rule,
  like two notes.
- **S-75/S-76.** A global defined in a dead section has no entry. In M1
  only COMDAT and discarded sections reach this (`--gc-sections` is
  refused).

Other:
- **R-C3.** `memory_seal` is not in `Plan`. It stays a parameter until
  WP-027 moves it.
- **S-50 rule 1.** r = 0 means output offset 0, the chunk start, even
  when the first record is not that input's. The rule says this
  explicitly, and finding 18 depends on it.
- **L-91 was wrong.** It gave linker-defined symbols a binding that
  contradicts resolve §8.1, and the measured output of GNU ld and lld
  agrees with resolve. L-91 now defers to resolve §8.1 and S-77.
- **Applied in this package:** image R-12 to S-91, S-92 and S-108 (the
  build-id descriptor is sealed); Q11 and Q12 per the supervisor.
