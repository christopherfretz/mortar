# WP-025 (code, stage A) — `mortar_synth`: what landed

Phase 80 of `spec/synth.md`, §4.2 onward: `.eh_frame`, `.eh_frame_hdr`,
the GOT, `.got.plt`, the IPLT and `.rela.plt`, `.symtab`, `.strtab`,
`.shstrtab`, `.symtab_shndx`, the build-id note, `.note.gnu.property`,
the alignment check of the other notes, and `.comment`'s string. Every
chunk has a plan (its size, before layout) and a write step (a pure
function of the plan, the inputs and the addresses), and implements
image §13 `SynthChunk` (`src/image.rs`).

Stage A only: `mortar_merge` (WP-025m) is not on main yet (main has its
crate shell). The input is a narrow trait per table (§3 below); the
tests implement it in memory (`tests/common/mod.rs`) and over real
objects with a test-only parser (`tests/real.rs`). Stage B implements the
traits over `mortar_merge`'s types.

## 5. The input trait stage B needs from `mortar_merge`

`EhSource` (`src/eh.rs`) must provide:
- the live `.eh_frame` sections, ascending by `SectionId`;
- per section, its records `(offset, len, Cie | Fde{cie, code, empty_range})`,
  covering the section back to back, with each FDE's CIE in its own section;
- the section's bytes;
- the relocations at each CIE, in offset order, as
  `CieReloc{offset, r_type, target, addend}`.

Merge has already refused every malformed record (S-36, S-37, S-39).

The other inputs come from:
- `SymSource` and `Sections` (`src/symtab.rs`): resolve's symbol columns
  and the liveness of each section;
- `SymAddrs`, `SlotValues` and `code_addr`: the image's address answers;
- `ObjectNotes`: per object, its `.note.gnu.property` sections.

The input section kinds read through `Inputs::resident` are:
- the symbol tables and their string tables;
- `.eh_frame`, through merge;
- `.note.gnu.property`;
- `.comment`, through merge's piece.

## 6. Spec ambiguities and errors found

- **S-80.** The placement of a thunk symbol's addend is not said. The
  chosen form is `__foo+0x10_veneer`.
- **S-59.** The spec says a duplicate initial location is "refused when
  written". It is refused at plan time instead, as `malformed`, so the
  size never depends on a failure found during the write.
- **S-85.** Whether `.symtab_shndx` exists depends on the output section
  count (≥ `SHN_LORESERVE`). The exact test is per entry. Both agree for
  every entry that names a section.
- **S-126.** The spec does not say how a `pr_type` repeated within one
  note combines. It is combined by its rule, like two notes.
- **S-80.** The size of the Cortex-A53 843419 patch is a synth constant.
  `mortar_arch` should expose it.
- **S-76.** Whether a global defined in a dead section stays is not said.
  It is dropped, like a local.
- **R-C3.** `memory_seal` is not in `Plan`. It is taken as a parameter.
- **S-50 rule 1.** r = 0 means output offset 0, the chunk start, even
  when the first record is not that input's. The rule says this
  explicitly, and finding 18 depends on it.
- **L-91 was wrong.** It gave linker-defined symbols a binding that
  contradicts resolve §8.1, and the measured output of GNU ld and lld
  agrees with resolve. L-91 now defers to resolve §8.1 and S-77.
- **Applied in this package:** image R-12 to S-91, S-92 and S-108 (the
  build-id descriptor is sealed); Q11 and Q12 per the supervisor.
