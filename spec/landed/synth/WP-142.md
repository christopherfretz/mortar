# WP-142 — the terminator alone when no `.eh_frame` record survives: what landed

A link whose only `.eh_frame` input was a terminator carrying a symbol
(x86-64 `crtendS.o`'s `__FRAME_END__`) stopped with `internal error in
mortar: .symtab: .eh_frame has no place`. It is not a mislink. The same
gap gave `.dynsym: <name> has no value` for a global defined in such an
input of a shared object, and `fill: a reference into .eh_frame without
the chunk` for a relocation into an empty input `.eh_frame` (the shape
of x86 `crtbeginT.o`) in a link that has no record.

Branch `wp/142-eh-terminator-only`, cut from `int/batch-5` at `4de9f53`.

## 1. Measurement

GNU ld 2.44, lld 19 and mold 2.37 were measured on AArch64 and x86-64
(cross). The inputs:

- a function without `.eh_frame`;
- `term.s`, a 4-byte terminator with a local `__FRAME_END__` at offset 0;
- `end.s`, a terminator with a global at offset 4.

| case | GNU ld | lld | mold | mortar before → after |
|---|---|---|---|---|
| terminator only, `-static` | `.eh_frame` 4 B; symbol at its start | 4 B; start | 4 B; symbol dropped; hdr always | internal error → 4 B, start |
| the same, `--eh-frame-hdr` | no hdr, no `PT_GNU_EH_FRAME` | an empty table (`fde_count` 0) | hdr | → no hdr (S-57) |
| the same, `--gc-sections` | 4 B | 4 B | 4 B | → 4 B |
| two terminator inputs | 4 B; both symbols at the start | the same | 4 B | → 4 B; both at the start |
| a symbol at offset 4 (`sh_size`) | after the terminator | after the terminator | dropped (static); refused in a shared object (`symbol referring to .eh_frame is not supported`) | → the start (S-50 rule 3) |
| `-pie`, `-shared` (AArch64; x86-64 shared is refused before WP-127) | 4 B | 4 B, hdr with `--eh-frame-hdr` | 4 B, hdr | internal error (`.dynsym` too for a global) → 4 B |
| an empty input with a symbol, and a reference from code, with no terminator | a 0-byte section; the reference reads the next section's bytes | 4 B | 4 B | internal error (`fill`) → 4 B |
| an empty input and a terminator | 4 B | 4 B | 4 B | → 4 B |
| records that all die (`--gc-sections`), no terminator | 0-byte section | CIE and terminator (0x18) | the same | no `.eh_frame` (unchanged) |
| the same with a terminator input | 4 B | 0x18 | 0x18 | no `.eh_frame` → 4 B |
| control: a real record and the terminator | 0x2c | 0x2c | 0x2c | unchanged (0x2c, `__FRAME_END__` at the start, S-50 rule 1) |

In the control, mortar already places a symbol at `sh_size` of a
terminator input on the final terminator (S-50 rule 3). GNU ld places it
after the terminator. lld places it 4 bytes past the output's start.
S-48a keeps mortar's rule.

### Which crt files carry what (GCC 14, glibc)

| file | AArch64 | x86-64 | i386 |
|---|---|---|---|
| `crt1.o`, `Scrt1.o` | CIE and FDE (`_start`) | CIE and FDE | CIE and FDE |
| `crti.o` | none | none | none |
| `crtbegin.o`, `crtbeginS.o` | CIE and FDEs (0x78) | none | none |
| `crtbeginT.o` | CIE and FDEs, `__EH_FRAME_BEGIN__` | empty, with `__EH_FRAME_BEGIN__` | empty, with `__EH_FRAME_BEGIN__` |
| `crtend.o`, `crtendS.o` | terminator, `__FRAME_END__` | the same | the same |

### Real compiler-driver lines

These are `gcc` with `-fno-asynchronous-unwind-tables -fno-unwind-tables`,
linked by each linker through `-B`. Only x86-64 `gcc -shared` reaches the
case:

- GNU ld writes a 4-byte `.eh_frame`.
- lld writes 4 bytes and an empty hdr.
- mold writes 4 bytes and a hdr.
- mortar refuses x86-64 shared output before WP-127 (dyn.md D-100). S-48a
  makes that line link once WP-127 lands.

The other lines already linked and are unchanged:

- Every `-static` and `-pie` program has `crt1.o`'s or `Scrt1.o`'s FDE.
- AArch64 `-shared` has `crtbeginS.o`'s FDEs.

## 2. The rule

`spec/synth.md` **S-48a [C]** (§4.3). Its rule sentence:

> When no record is live but some input `.eh_frame` of the link holds a
> terminator or is empty (0 bytes), the output `.eh_frame` exists and is
> the terminator alone: 4 bytes, at S-47's alignment and of L-49's type,
> with no FDE, so no `.eh_frame_hdr` (S-57).

Other spec edits in `synth.md`:

- S-3's row 14 names S-48a.
- The size table names S-48a.
- §13 gains three rows: a terminator input, an empty input, and a symbol
  at `sh_size`.

S-48a is [C] rather than [G] because GNU ld writes a 0-byte section for
an empty input. That 0-byte section leaves `crtbeginT.o`'s frame list
starting on the next section's bytes.

## 3. Code

`crates/mortar_synth/src/eh.rs`:

- `EhPlan` gains a `bare` field, set in `from_records_padded`: no listed
  record, and some section row with a terminator or of size 0.
- `EhPlan::exists` is now `!records.is_empty() || bare`.

Nothing else changed:

- The size is `out_off[0] + 4 = 4`.
- The writer writes no record, and the zero word is the terminator.
- `EhPlan::value` already gives offset 0 by rules 1 and 3.
- `symtab.rs` is unchanged.

An incremental link of the case (`--incremental`, then a relink with a
record added and removed) was tried by hand. It took the full path and
ran.

## 4. Tests

- **`crates/mortar_synth/tests/eh.rs`, `s48a_wp142_a_terminator_alone_when_no_record_survives`.**
  It covers:
  - a terminator alone: 4 bytes, no FDE, symbols at 0 and 4 valued 0;
  - two terminators;
  - an empty input with a relocation at 0;
  - records that all die, with and without a terminator;
  - no input at all.

  The test needed a new `R::Term` variant in `tests/common/mod.rs`.
- **`tests/link/layout/eh-frame-terminator-only.test`** (three targets,
  static). Each link checks the 4-byte `.eh_frame`, and the symbols are
  checked on bfd, lld and mortar. The links:
  - `prog` (run);
  - `hdr` (no `PT_GNU_EH_FRAME` on bfd and mortar);
  - `gc`;
  - `two` (two `__FRAME_END__`);
  - `end` (a global at `sh_size`);
  - `crt`: the `crtbeginT.o` shape and a terminator, run. It reads the
    word at its `.eh_frame` reference and exits 42 on the terminator;
  - `empty`: an empty input alone, run on lld, mold and mortar, since GNU
    ld's output reads past its 0-byte section.

  It declares `anomaly(mold): A11`, because mold writes `__bss_start` at 0
  under `--gc-sections`.
- **`tests/link/layout/eh-frame-terminator-only-pie.test`** (AArch64,
  x86-64). It links `-pie --no-dynamic-linker --eh-frame-hdr` and runs the
  program. It has `skip(mold,aarch64)` for P-D14, as
  `dyn/dynamic/no-dynamic-linker.test` does.
- **`tests/link/layout/eh-frame-terminator-only-shared.test`** (AArch64
  only, since x86-64 shared objects are WP-127's). It links
  `ld -shared --eh-frame-hdr` of an object without unwind tables and the
  terminator, and a host program loads the library and calls it.

Every link is judged by the verifier, and no finding was reported on
mortar's outputs.

The three tests add 25 static-identical rows:

- 10 AArch64 rows, recorded here: 7, 1 and 2 for the three tests in the
  order above.
- 8 x86-64 rows (7 and 1), which come from the hosted run.
- 7 i386 rows.

No existing row changed.

## 5. Other unplaced symbols in `symtab.rs`'s placement (item 5)

These were probed on AArch64, static, with `get.o` defining `get` and no
`.eh_frame`. A reference is `.data: .quad <sym>`. The reproducers are
below.

1. **Mislink, handed to WP-136.** A referenced global in an empty
   `SHF_MERGE` section links with exit status 0, writes 0 into the
   reference and drops the symbol from `.symtab`. GNU ld and lld write an
   address.

   ```
   .section .rodata.str1.1,"aMS",@progbits,1
   .globl gms
   gms:
   ```

2. **Mislink, handed to WP-136.** A referenced global in an input
   `.note.gnu.property`, which the property merge drops, links with exit
   status 0 and writes 0. GNU ld refuses: `` `gprop' referenced in section
   `.data' ... defined in discarded section `.note.gnu.property' ``.

   ```
   .section .note.gnu.property,"a",@note
   .p2align 3
   .long 4, 16, 5
   .asciz "GNU"
   .long 0xc0000000, 4, 3, 0
   .globl gprop
   gprop:
   ```

3. **Internal error (WP-136's class).** A referenced global in
   `.note.GNU-stack` (`.section .note.GNU-stack,"",@progbits` followed by
   `.globl gstack; gstack:`) stops with `relocation R_AARCH64_ABS64: no
   live target in the tables`. GNU ld links it, at the end of the
   preceding output.
4. **Refused, not fixed: S-50 rule 5 on x86-64.** `leaq
   __EH_FRAME_BEGIN__(%rip), %rsi`, of a local label at offset 0 of an
   (empty) input `.eh_frame`, is assembled as `R_X86_64_PC32 .eh_frame-4`.
   Its `r = st_value + A = -4`, which rule 5 refuses (`offset is outside
   the section; refer to it through a named symbol`). GNU ld, lld and mold
   link it, and the program reads the terminator. The section symbol's
   addend there includes the PC bias, so rule 5 reads a PC-relative
   reference to a section's start as one outside the section.
   `crtbeginT.o` uses `R_X86_64_32 .eh_frame+0`, which is not affected.
   The link tests use a hidden global instead.

   ```
   .section .eh_frame,"a",%progbits
   __EH_FRAME_BEGIN__:
   .text
   .globl get
   get: leaq __EH_FRAME_BEGIN__(%rip), %rsi ; ...
   ld -pie --no-dynamic-linker begin.o term.o -e get
   ```

5. **Clean:**
   - a global and a local in `.comment`;
   - in `.debug_str`, with and without `-S`;
   - in an input `.note.gnu.build-id`, with and without `--build-id`;
   - a local in a losing COMDAT copy;
   - unreferenced globals in the dropped sections above, which are
     dropped from `.symtab` without an error.
