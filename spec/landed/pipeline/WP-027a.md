# WP-027a — the front of the pipeline (`mortar::link` to a validated `Layout`)

Branch `wp/027a-front`. The facade now runs phases 20 to 90 (input,
resolve, assignment, split, liveness, scan, synthetic plans, the layout
fixed point) on AArch64 Linux static links and stops at a validated
`Layout`. Writing the image and the output file is WP-027b. A link that
gets that far is refused by name:

```
mortar: error: unsupported feature: writing the output file
>>> the link was laid out; the image and the output file are WP-027b
```

The interface that WP-027b and WP-027c build on is
`spec/landed/pipeline/FRONT-INTERFACE.md`. It was first published in
d0e347e and has changed four times since; each change is listed in that
file's "Changes after first publication".

## Public surface

```rust
// crates/mortar/src/lib.rs
pub fn link(args: &[OsString]) -> Outcome;
pub fn invoke(prog: &str, args: &[OsString]) -> Invocation;
pub fn invoke_in(prog: &str, args: &[OsString], cwd: &Path) -> Invocation;
pub struct Invocation { pub outcome: Outcome, pub color: Color, pub phases: String }

// crates/mortar/src/front.rs
pub struct Env<'e> { pub cwd: &'e Path, pub pool: Pool }
pub fn front<'s>(plan: Plan, env: Env<'_>, store: &'s Store,
                 diag: &Collector, timer: &mut Timer) -> Option<Front<'s>>;
impl Front<'_> {
    pub fn sections(&self) -> Vec<OutRow>;
    pub fn with_sym_cx<T>(&self, f: impl FnOnce(&SymCtx<'_>) -> T)
        -> Result<T, mortar_synth::error::SynthError>;
}
```

- `invoke_in` runs the front when the only refused option on the command
  line is `-o`. It emits the option refusals after the front has run,
  because they are errors and the front stops at the first error.
- `--threads N` sets the pool size. `MORTAR_SCHED_SEED` sets the schedule.
  A bad seed is an error keyed (10,0,0).
- With `--time-phases`, `Invocation.phases` holds one row per phase
  (10, 20, 30, 45, 60, 50, 70, 80, 90, then the total).
- The store is `StorePolicy::from_env()`, which is Staged by default
  (WP-021b).

`mortar_layout::fixed::Sites` changed as follows:

- `targets(&self, round, pool) -> Vec<Option<u64>>` is new.
- `code(&self, out, round, pool)` now returns
  `Result<Option<OwnedCode>, LayoutDiag>`. A read failure is reported and
  never treated as "no sites".

`mortar_scan` gains `walk::Walker` (a new file), which `crates/mortar/src/sites.rs` uses.

## Validation

- **`tests/front_diff.rs`** compares the front's sections, symbol table,
  GOT, IRELATIVE count, `.eh_frame` and segments with GNU ld 2.44, lld and
  mold. The programs are built by GCC C, GCC C++, Clang C, Clang C++ and
  gfortran. The tests pass under both stores.
  - `sections_over_the_staged_limits` covers sections that are not resident.
  - `the_supported_rows_shape_the_front` covers -s, -S, -x (compared with lld -x),
    the eh-frame-hdr options, build-id, --no-gc-sections, -e,
    -z memory-seal and --discard-none.
- **`the_front_does_not_depend_on_the_schedule`**: under
  `par::check_schedules` (threads 1, 2, 7 and 64, several seeds), the
  Layout, the sections, the symbol table and the report are identical.
- **`tests/refusals.rs`** checks the exact text of each refusal:
  - `--gc-sections`;
  - an undefined entry (one warning);
  - a bad seed (`bogus`, `-1`, `2^64` and the empty string; `12345` is accepted);
  - x86-64 and i386 links, keyed (20,MAX,0), and mixed machines;
  - the `--time-phases` rows.

- **linktest**: `diag/duplicate.test`, `diag/undefined.test` and
  `resolve/comdat-mismatch.test` now pass on mortar, and their xfail markers
  are removed.

Layout was 1037/309/182 ms before b6ccaa5. Two costs were removed:

- the branch-target tables were rebuilt for every branch;
- `Object::symbols()` scanned every section header for each of 121,683
  targets in every round.

The input and layout phases stop scaling past 4 threads.

**`par` spawn share.** Measured with temporary counters, which have been
reverted. One link makes 110 parallel calls.

| threads | spawns | time in the caller's spawn loop | share of the link |
|---|---|---|---|
| 4 | 293 | 3.7 ms | 2.7% of 139 ms |
| 8 | 613 | 6.5 ms | 5.0% of 131 ms |

Spawn and join cost 13 to 35 µs per thread, which gives about 8 ms (6%)
at 8 threads. That is just over the 5% bar. It is reported only; no
`unsafe` pool was added.

## Found wrong elsewhere

- The cli stripped `0x` from `--build-id=0x…`, while synth requires it, so every hex build id failed. Fixed.
- `-S` kept the Merge-kind debug strings. Fixed in resolve.
- The entry warning came from both resolve and layout. Fixed in the front.
- `mortar_image/src/layout_plan.rs:112` calls `obj.symbols()` once per
  relocation section. That is O(sections²), the same cost layout had.
  This is for WP-027b; `mortar_image` was not edited here.
- `mortar_merge/src/cut.rs:22`: a compressed section that is placed whole
  is not decompressed by the store, but layout L-52 assumes it is.
- `PhaseTimer` (`mortar_image`) reports a lower peak on the total row than
  on the layout row.
- `--gc-sections --no-gc-sections` is refused, although the last option
  should win.
- A missing input file is also reported as `no-target` (`mortar_input`, input.md:216).
