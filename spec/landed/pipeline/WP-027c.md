# WP-027c — the whole pipeline (first executables written by `mortar`)

Branch `wp/027c-pipeline`, cut from main 063f8ac (WP-027a and WP-027b
merged). The facade now runs phases 20 to 105: the front's `Layout` is
handed to `mortar_image::link::write` (`crates/mortar/src/image.rs`), the
image is filled and the output file written (I-59/I-60/I-66). `-o`,
`-Map` and `-M` are honoured. On any error no output is left behind and
the exit status is 1; warnings leave status 0.

## What landed

- **The join.** `crates/mortar/src/image.rs` maps `Front` to `Link`;
  `lib.rs` returns `Outcome::Linked`, writes the map (`-Map`, `-M` to
  standard output), removes a stale output on a late failure (I-66) and
  keeps it on a command-line failure. `--time-phases` prints rows 100
  (image) and 105 (output file).
- **Thunks.** `link::patches` writes the Patches chunks (they were zeros:
  any far call crashed). A thunk to a BTI-marked target is refused by name
  because the target word is not proved (`PatchCx::target_word: None`).
- **Erratum 843419 (a64.md §11.2).** Layout computed the fixes but fill
  wrote the unfixed code and zero patches. `LinkSites::erratum_fixes`
  (`crates/mortar/src/sites.rs`) now computes, from the words fill writes,
  either the ADR rewrite at Q or `b patch` at F plus the patch words
  (W4', `b F+4`); they reach fill as `Link::fixups` / `Image::fixups`
  (by file offset, applied in every window before the build id).
  `--fix-cortex-a53-843419=adr|adrp` are refused by name (the value was
  read as `full`). `Front::erratum_fixes` is FRONT-INTERFACE change 5.
- **The map** lists thunk (`__<target>[+addend]_veneer`) and patch
  (`ERRATUM_843419`) chunk records.
- **Rulings implemented:** OSABI GNU when an IFUNC/unique symbol is output;
  `__rela_iplt_*` local hidden; no empty RW PT_LOAD (L-159: an output
  section with only empty inputs has no chunk); `--gc-sections` /
  `--no-gc-sections` last wins (liveness refuses when the final value is
  on); a missing input is `cannot open` alone (no follow-on no-target);
  SHF_COMPRESSED inputs refused by name; a missing entry warns
  (`cannot find entry symbol _start`) and writes `e_entry` 0; bare
  `--build-id` is 20 bytes.
- **`--time-phases` total peak** is the largest peak of any sample
  (`phases.rs`): the total read 232.5 MiB after a phase line's 233.6.

## Programs (`crates/mortar/tests/pipeline.rs`)

Each is linked by mortar and GNU ld, run natively, its output and status
compared; each output must have zero plumb findings (the narrow S-17 /
known merge-piece filter until WP-028c lands), readelf and llvm-readelf
without warnings, and only the known eu-elflint findings.

- static C, C++ (exceptions, `thread_local`, ctors/dtors, IFUNC,
  iostream, RTTI), Fortran;
- GCC and Clang, `-O0`/`-O2`, with and without `-g`,
  with `-ffunction-sections -fdata-sections --gc-sections` (refused by
  name until liveness lands; the test checks the refusal);
- a far call through a thunk; a forced erratum patch (exit 42, patch
  words checked against `.text`);
- determinism: CXX `-O2 -g` across both stores x threads 1/2/4/8 x seeds
  {none, 1, 977} plus 3 repeats: 28 runs byte-identical, output and map;
- I-110 through the driver; linking over an existing output (new inode,
  hard link keeps the old bytes, no litter); `-gz` refused by name.

protoc (static, by hand, not committed): links, `--version` works, and
`--cpp_out/--python_out/--java_out` of `descriptor.proto` and
`unittest.proto` are byte-identical to GNU ld's build. readelf clean;
plumb's only findings are R1 against `.rodata*.str1.8`/`.str4.8` (the
WP-028c merge-piece case).

Debuggers (by hand): gdb and lldb (break, bt with file:line, info line,
print local/global, next, catch throw, image lookup) match the GNU ld
build except an uninitialised local's value and lldb naming the text
segment `PT_LOAD[1]` (mortar has a separate read-only header segment).
