# WP-194: a relocation section whose target has no place (the call-graph profile)

Clang writes `.llvm.call-graph-profile` (`SHT_LLVM_CALL_GRAPH_PROFILE`,
`SHF_EXCLUDE`, `sh_link` `.symtab`, 8-byte weights) for every object
compiled with a call-graph profile (`-fprofile-use`,
`-fprofile-sample-use`, the assembler's `.cg_profile`), and names each
weight's caller and callee by an **`SHT_REL`** section
`.rel.llvm.call-graph-profile` of `R_*_NONE` records on all three
targets. Before this package mortar refused every such object on
AArch64 and x86-64 (`unsupported section type: SHT_REL`: the other-form
check of `sections::classify` ran before the target was known); i386,
where `SHT_REL` is the native form, linked. Measured against GNU ld
2.44, lld 22 and mold 2.37.1 on AArch64 (natively), x86-64 and i386
(cross, qemu).

## 1. What the references do

| | GNU ld | lld 22 | mold 2.37.1 |
|---|---|---|---|
| the two sections in a final link (static, `-pie`, `-shared`, all three targets) | dropped | dropped | dropped |
| input section order | input order | **reordered** by the weights: `--call-graph-profile-sort=cdsort` is the default (`=none`, `--no-call-graph-profile-sort` keep the input order); `_start, f, 1000` with `g` between them puts `f` first | input order |
| a member defining a symbol named only by a record | extracted | extracted | extracted |
| `--as-needed` library defining such a symbol | needed, the symbol in `.dynsym` | same | same |
| a symbol named only by a record, defined nowhere (strong) | no diagnostic | no diagnostic | no diagnostic |
| `--gc-sections`: a function named only by a record | collected | collected | collected |
| `-shared`: such an undefined symbol in `.dynsym` | kept; dropped under `--gc-sections` | kept; dropped under `--gc-sections` | kept, also under `--gc-sections` |
| a hand-made other-form section (`.rel.foo` `R_AARCH64_ABS64`/`R_X86_64_64`, `.rela.foo` `R_386_32`) of an `SHF_EXCLUDE` section, against an undefined symbol | links, no diagnostic, with and without `--gc-sections` | same | same |

mold writes Clang's `$d` mapping symbols of the dropped profile section
(AArch64) as `SHN_ABS` locals of value 0; the verifier reports them
(Y4), and no anomaly of `spec/plumb.md` §10.2 names it, so
`call-graph-profile.test` skips mold on AArch64 by name.

Using the profile (function order, as lld does) is not this package: it
is a later optimisation (an input-section order from the weights is a
layout decision, `spec/layout.md`), with lld's `cdsort` as its reference.

## 2. The rule (resolve.md §10)

The `SHT_REL`, `SHT_RELA` row now says: the other form is refused when
its target is placed, has no target, or is a consumed section whose
records a phase reads; a relocation section whose target has no place
is dropped with it, of either form, and its records are nothing (no
liveness edge, no reference beyond the object's symbol table, no
undefined-symbol diagnostic, no type check, no form check), and the
target's row records no relocation section. The new paragraph
"Relocations of a dropped section" gives the classes; the
`SHT_LLVM_CALL_GRAPH_PROFILE` row's reference column is now measured.
`spec/arch.md` §3.1, `spec/a64.md` §1, `spec/x64.md` X-2 and
`spec/x86.md` X86-2 say that the refusal is for a placed target.

## 3. The classes decided (`sections::reloc_fate`)

| target (kind, state after §10's first pass) | other form | native form | why |
|---|---|---|---|
| `Kept` | refused | applies | unchanged |
| no target (`sh_info` 0 or out of range) | refused | ignored (unchanged) | nothing shows the records unread |
| `Excluded` kind, any reason (`SHF_EXCLUDE`, consumed `SHT_LLVM_*`, `.gnu.lto_*`, input build id, `.gnu.warning*`, `.ARM.attributes`) | nothing | **nothing** (was: recorded) | no phase reads them; recording them made `mortar_scan`'s D-111 walk count their names as collected |
| `Meta` container | applies | applies | MT-2a needs to see it relocated; it then becomes `Excluded` and its `reloc` is cleared |
| `Dropped(Comdat)` | nothing | applies (unchanged) | a discarded copy; out of scope to change the native rule |
| `Dropped(Stripped)` (`-S`/`-s`) | nothing | applies (unchanged) | nothing reads them under `-S` (`--gdb-index` is off) |
| other consumed: `.debug_gnu_pub*` under `--gdb-index`, symtab, strtab, group, relocation section, `.note.GNU-stack` | refused | applies | the index reads the pub sets' records by the machine's form |
| kept at resolve, discarded later (`--gc-sections`, `/DISCARD/`) | refused | applies | decided after resolve; no producer writes one |

One behaviour change for the native form: a key named only by a
relocation of an `Excluded` section in a `-shared` link now keeps its
`.dynsym` entry (D-111: "a key named by no relocation keeps its entry"),
as all three references do without `--gc-sections`; before, mortar
dropped it (the walk read the excluded section's records as "in a
collected section"). Under `--gc-sections` mortar keeps it as mold does
(GNU ld and lld drop it), as D-111 already says for a key named by no
relocation. `s10_relocated_container_is_not_one` now expects the
converted container's `reloc` to be 0.

## 4. Cells

- (a) i386: `SHT_REL` is native there, so the profile linked before;
  it still links, and its records are no longer recorded on the target.
- (b) a record naming a local of a COMDAT group's dropped copy (`cloc`
  of `c2.o`), and one naming an undefined weak (`wk`): no diagnostic
  from any of the four, the programs run (`call-graph-profile.test`).
- (c) `--gc-sections`: `cold`, named only by `.cg_profile _start, cold,
  1000`, is collected by all four, and the archive member's `hmark` is
  gone (`call-graph-profile.test`).
- (d) `-shared` and a PIE against it: link and run on AArch64 and
  x86-64, the weak `nowhere` named only by the library's profile keeps a
  `WEAK UND` `.dynsym` entry with all four
  (`call-graph-profile-dynamic.test`). i386 dynamic output is refused
  by mortar (M4), so the test is 64-bit only.
- (e) the mirror: a hand-made `SHT_RELA` relocation section of an
  `SHF_EXCLUDE` section on i386, and `SHT_REL` ones on AArch64 and
  x86-64, with an absolute record against a symbol defined nowhere: all
  four link and run, with and without `--gc-sections`
  (`reloc-of-excluded.test`, yaml2obj).
- (f) `llvm-profdata-22` is installed but `libclang_rt.profile.a` is not,
  so the instrumented route (`-fprofile-instr-generate`) cannot link. A
  sample profile (`-fprofile-sample-use`, text format) gives a real PGO
  object with the profile and its `SHT_REL` section on all three
  targets: `call-graph-profile-pgo.test` links it statically with all
  four (by the GCC driver, glibc) and runs it; by hand also as a PIE
  with all four on AArch64.
