# WP-153: symbol rewrites and reports

`--wrap=SYM` becomes `partial` (three shapes are refused by name).
`--defsym`, `-y`/`--trace-symbol`, `--undefined-glob`,
`--export-dynamic-symbol-list` and `--retain-symbols-file`: see section 7.

What was measured: GNU ld 2.44, lld 19.1.7 and mold 2.37.1 in scratch, on
AArch64 and x86-64 in every kind (static, `-no-pie`, PIE, static-pie,
`-shared`) and on i386 static. The lane's references print as GNU ld 2.44,
`ld.lld-22` (Debian LLD 22.1.8) and mold 2.37.1. Every lane cell
gives the same answer under lld 22.

## 1. `--wrap`: why the row was refused

`mortar_resolve::options::Wrap` and `Options::redirect` existed already.
So did the consumers of `Resolution.redirect`: scan's `key_of`, image's
`LinkTables::key`, gc and merge. Three things were missing:

- the plan → options filling;
- a key row for a name that only the option gives (`__wrap_f` when no
  file mentions it), so that a redirected mention has a row to bind to
  and to be reported undefined;
- the row itself.

    (checked);
  - with the same set, an update may run: the update reruns resolution

- **Depfile**: `--wrap` reads no file.
- **Rows moved**: `--wrap`: `refused` → `partial`.

### What the verifier must read for `--wrap`

1. **The redirection**: `redirect[SYM] = __wrap_SYM` and
   `redirect[__real_SYM] = SYM`. It applies to UNDEFINED mentions only
   (raw `st_shndx == SHN_UNDEF`; versioned references `f@V` are not
   mentions of `f`). A reference inside the object that defines SYM is a
   defined mention, so it is not redirected (E13; lld differs, §16). The
   mentions of a dropped COMDAT copy are demoted, not undefined, so they
   are not redirected either. The only shape where this matters is
   refused (item 3).
2. **A chain** is one step per mention (`--wrap=f --wrap=__wrap_f`: `f`
   → `__wrap_f`, `__wrap_f` → `__wrap___wrap_f`). Wrapping twice is
   wrapping once.
3. **The three refused shapes**: `--wrap=SYM@VER`; `--wrap=__real_X`
   beside `--wrap=X`; a live file's demoted mention of SYM. A mortar
   output never has them.
4. **Roots** are not redirected: `-u SYM`, `--require-defined=SYM`,
   `-e SYM`, `--export-dynamic-symbol=SYM` name SYM itself.
   `--gc-sections` roots are likewise.
5. **Archive extraction** follows the redirected key. An undefined
   `__real_f` extracts f's member; an undefined `f` extracts
   `__wrap_f`'s member, not f's (lld differs: §16, its M12 below).
6. **`--gc-sections`**: an edge to a mention goes to its redirected
   key's definition, so SYM's section is live only through `__real_SYM`
   or a root.
7. **Names**: definitions keep their names in `.symtab` and `.dynsym`;
   nothing named `__real_SYM` is written (unless a file defines it).
   With `-shared`, the export set is the defined globals as usual
   (`f`, `__wrap_f`). The undefined ones are the redirected keys (UND
   `f` for `__real_f`, UND `__wrap_f` for `f`), and preemption is
   unchanged.
8. **Shared objects**: a redirected key that only a shared object
   defines is imported and makes the object needed. An object only
   SYM's unwrapped mentions would need is not needed under
   `--as-needed`.
9. **The text map** (I-121 item 1): an archive line's symbol is the
   redirected key.

The first measurements for the next package (AArch64; scratch

printing `&k`:

| `EXPR` | GNU ld | lld | mold |
|---|---|---|---|
| `0x1234`, `4660` | 0x1234 | 0x1234 | 0x1234 |
| `011064` | 0x1234 (octal) | 0x2b38 (decimal) | 0x2b38 (decimal) |
| `0x1234+4`, `0x1000-1`, `1<<4`, `(0x1000)` | evaluated | evaluated | refused |
| `1k`, `1M` | 0x400, 0x100000 | the same | refused ("undefined symbol: 1k") |
| `0x10K` | 0x4000 | refused (malformed number) | refused |
| `ALIGN(16)` | 0 | 0x2b9ff0 | refused |
| `b` (a symbol) | b's address | = | = |
| `b+4`, `b-4` | b ± 4 | = | refused |
| `b+b` | 0x890 | refused (one side must be absolute) | refused |

- The three agree on hexadecimal `0x...`, decimal without a leading
  `0`, and a lone symbol. A leading `0` is the one disagreement among
  numbers.
- `k=0x1234` in a PIE or a static-pie: lld and mold give the constant
  0x1234. GNU ld relocates it: `&k` = load base + 0x1234 at run time.
  `.symtab` shows `k` as `ABS` in all three. §7.2's "absolute `SYM`" is
  lld's and mold's reading.
- `a=b` with `b` a function: `a` is `FUNC` at b's value in all three
  (mold writes it LOCAL in an executable, A9).
- Code: `InternalDef::Assign(u32)` has no producer; layout refuses it
  as `feature("--defsym expression")`; scan maps `Alias`/`Assign` to
  `TargetKind::Abs`. A 64-bit value needs a wider `Assign`.
