# WP-022 — `mortar_resolve`: resolution over a view, and over `Inputs`

`spec/resolve.md` (accepted; design record `WP-022-spec.md`). Stage A
covers the algorithms over the `View` trait and their tests. Stage B
(after merging main with WP-020d) adds the view over
`mortar_core::inputs::Inputs`, the `Resolution` table with its checks,
and the `mortar_diag` diagnostics. Safe Rust (`forbid(unsafe_code)`), and the crate depends only on
`mortar_core`, `mortar_diag` and `mortar_elf`. Its only dev-dependency is
`mortar_testutil`.

The GNU simulation runs on pending sets. A lazy member becomes pending
when a key it defines changes to `Undefined`, or to `Common` for a
strong-data definer. Each pass visits only the pending members of the
archive's range, in order. The result equals the naive full visit on
every corpus (`tests/scale.rs`), and the 10^5-member descending chain
is not quadratic.

### The view trait

```rust
pub trait View: Sync {
    fn machine(&self) -> Machine;
    fn files(&self) -> u32;
    fn keys(&self) -> u32;
    fn comdats(&self) -> u32;
    fn file(&self, file: FileId) -> FileInfo;          // kind, archive, group: Option<u32>, sections, ...
    fn mentions(&self, file: FileId, out: &mut Vec<Mention>);
    fn mention(&self, file: FileId, index: SymbolIndex) -> Option<Mention>;
    fn groups(&self, file: FileId, out: &mut Groups);
    fn section(&self, file: FileId, index: SectionIndex) -> Option<SectionInfo<'_>>;
    fn key_name(&self, key: SymbolId) -> (&[u8], Option<&[u8]>);
    fn find_key(&self, name: &[u8]) -> Option<SymbolId>;
}
```

## Stage B: the view over `Inputs`

- **`InputsView::new(&Inputs, &Pool)`** reads every file in parallel. It
  decodes the symbol table and checks the globals against
  `Inputs::sym_map_of` (count, `section_of`, names). It decodes the
  groups: the signature (an `STT_SECTION` signature is its section's
  name) is looked up in `Inputs::comdats` by `identity::comdat_lookup`.
  A `foo@@V` mention also refers to the key `(foo, V)` (§9.4, the `also`
  rows). What it cannot read becomes a `Fault` (`malformed-input`)
  instead of a panic. `FileInfo.source` is the file identity without the
  mention ordinal (ruling 1).
- **`options(&Plan, &Inputs, &InputsView)`**:
  - The entry is `-e`, then the last `ENTRY` directive, then the
    default `_start`. Shared and relocatable outputs have none.
  - `-u` and `--require-defined` come from `Plan.symbols`;
    `--ignore-unresolved-symbol` gives `Options.ignore_unresolved`.
  - `--unresolved-symbols` and `--warn-unresolved-symbols` give
    `Options.unresolved`. `-S` and `-s` set strip.
  - pie is set for PIE and static-pie; dynamic for the two dynamic
    executables.
- **`resolution`** writes the columns into `mortar_core::Resolution`:
  - `FileLive::Shared{needed: false}` for a live shared file.
  - `Def::Internal(Provide{conditional})` for a linker `PROVIDE`.
  - `SymProps.refs` (FROM_OBJECT, STRONG) and `SymProps.verdict`
    (§3.7, §5.2).
  - `comdat`, `comdat_copies`, `section_base` and `sections`.
- **`resolve_inputs`** runs the whole phase. A table that fails
  `Resolution::check` or `check_against(&Inputs)` is an
  `internal-error`, never a panic.
- **`diagnostics`** maps each `What` to its `mortar_diag` kind with
  place, relations and notes. It does not emit `undefined-symbol` for a
  static reference: the scan emits one per key at phase 70 from the
  verdict.
- **Tests.** On every differential line the result over `Inputs` (built
  by `tests/support/inputs.rs`, a stand-in for `mortar_input`) equals the
  model's key by key, signature by signature and section by section. The
  table passes both checks, and no diagnostic is an error.
  `s1_1_resolve_inputs_from_a_plan` runs the phase from a `Plan`: with
  `-e main` the entry is `main`, and naming the program object twice
  gives one `duplicate-symbol` error.

## Rulings (coordinator, on the stage-A ambiguity list)

References: ld.bfd 2.44 (native, and the x86-64 and i686 cross linkers),
ld.lld 22, mold 2.37.

1. **§4.6 archive-choice, same archive twice.** Suppressed when both
   definers have the same file identity apart from the mention ordinal
   (found path, member name and ordinal). Tested by
   `s4_6_same_member_twice_is_no_choice` (model) and
   `s4_6_libgcc_twice_is_no_choice`. The second test uses the real
   `libgcc.a` named again after an archive that needs its atomics; the
   warning is gone, and a copy at another path still warns. cxx-medium
   now has no problems (it had 20 archive-choice warnings).
2. **§10 `.llvm_addrsig`.** It is `SHF_EXCLUDE`, so the first match
   gives Excluded. The table row is fixed, with a test in
   `s10_classification_table`.
3. **§10 refusals in dropped groups.** A refusal about a section's
   content or fate now applies only to sections that are kept. A
   section of a dropped COMDAT copy is `Dropped(Comdat)` and cannot
   refuse the link; `.zdebug_*` under `-S`/`-s` is `Dropped(Stripped)`.
   Structural faults of a live file (§3, §6.4, §6.5) still apply.
   Library scan: 65 system and cross `*.a` (AArch64, x86-64, i686, GCC
   14). They hold only the section types PROGBITS, NOBITS, NOTE,
   SYMTAB, STRTAB, REL, RELA, GROUP, INIT_ARRAY and FINI_ARRAY, and only
   the flags A, W, X, M, S, I, G and T. No refusal row matches any of
   their sections, kept or dropped, so the change alters nothing for
   them. Test: `s10_refusal_only_for_kept_sections`.
4. **§10 two relocation sections for one section** (yaml2obj 22):

   | input | ld.bfd | lld | mold |
   |---|---|---|---|
   | RELA + RELA | applies only the first, silently | refuses ("multiple relocation sections to one section are not supported") | assertion `target->relsec_idx == -1` |
   | REL + RELA | applies both | refuses | drops the REL silently |

   No reference applies both consistently, and `SectionRow.reloc` has
   room for one section. mortar refuses a second reloc section of a
   kept section by name: `Refused{Feature, "two relocation sections for
   one section"}` (`SectionRefusal::SecondReloc`). For a dropped target
   it is ignored, as in ruling 3. Test:
   `s10_second_reloc_section_refused`. No model request is needed.
5. **§3.3 common with alignment 0.** ld.bfd accepts it as alignment 1
   (the symbol is placed at an odd address); mold accepts it; lld
   refuses ("has invalid alignment: 0"). Two references accept it, so
   mortar treats it as alignment 1 (`align_log2` 0). Test:
   `s3_3_alignment_zero_is_one`.
6. **Accepted as done:** §2 option-only key rows; §3.7/§9 `common`
   column; §4.6 roots before the first file and the backref referrer;
   §7.1 `--wrap` and demoted mentions/roots; §9.4 `also` row; §11 shared
   sequence unit; mold's member set from `-Map`.
7. **§8.1 `__rela_iplt_*` under static-pie**, checked with
   `gcc -static-pie` and an ifunc on AArch64, x86-64 and i686
   (`__rel_iplt_*`):
   - ld.bfd leaves them out of the symbol table, lld leaves them weak
     undefined, and mold makes them absolute 0.
   - Under plain `-static`, all three define them.
   - Under static-pie, all three binaries run, with the IRELATIVE
     relocations in `.rela.dyn`, which glibc's static-pie start code
     applies.

   So mortar defines them only for a static non-PIE executable. Under
   static-pie a reference is weak undefined (zero), as in lld and in
   effect mold. Test: `s8_1_no_iplt_range_under_static_pie`.

Each ruling is a small edit of `spec/resolve.md` in §3.3, §4.6, §8.1 and
§10.

## `spec/input.md` §17: the M2 requirements for resolve.md

None applied; all left for M2. These are: the `DT_NEEDED` closure in
`Inputs`; closure files that are not `DT_NEEDED` and define nothing for
the program unless `--copy-dt-needed-entries`; exporting program symbols
referenced by a used closure file; and judging shared objects'
undefined references under `--no-allow-shlib-undefined`, with
`needed-not-found` definers judged undefined. M1 links are static, and
cli refuses shared inputs there. Stage B only maps a live shared file
to `FileLive::Shared{needed: false}`; `needed` and the closure use are
M2 work on `spec/resolve.md`'s M2 part.

### Determinism

The results are equal across `TEST_THREADS` {1, 2, 7, 64} and 10
scheduling seeds plus no seed. This holds on 8 generated corpora of 400
members (archives inside and outside groups, chains, cycles, commons,
weak definitions, COMDAT groups) and on the cxx line of each target.
Each result also equals the liveness oracle and the naive simulation.
Every rules test runs under `check_schedules`.

### Benchmark

The example lives in `crates/mortar_resolve/examples/resolve_bench.rs`,
not in `mortar_bench`, because the dependency edge points the other way.
It reports the median of 7 runs and asserts that each run equals the
sequential result.

- **cxx-medium (protoc).** 3181 files, 44768 keys and 26776 groups; 772
  files live, 10 rounds. Each `-l` is resolved to its static archive;
  the three `-l` with no static archive (`-lgcc_s` twice, and `-lm`,
  whose `libm.a` is a linker script) are skipped.
- **Synthetic.** 10^6 keys in 1000 members, all referenced from one
  object.

## Where the spec was unclear or silent, and what was chosen

| § | what was done |
|---|---|
| §2 | Names that only options mention need key rows. The view must supply them (`--wrap` already requires this). |
| §3.3 | Alignment 0 is alignment 1 (ruling 5). |
| §3.7 / §9 | The `common` column holds only the keys whose def is `Common`. |
| §4.6 | Roots, including the default `_start`, count as undefined references before the first file. The `archive-backref` referrer is the first non-weak reference in walk order. |
| §4.6 | `archive-choice` is suppressed for the same archive named twice (ruling 1). |
| §7.1 | `--wrap` does not redirect demoted mentions or roots. |
| §8 | `__rela_iplt_*` only for static non-PIE (ruling 7). |
| §9.4 | The second lookup is implemented through the `also` row. |
| §10 | `.llvm_addrsig` is Excluded (ruling 2). |
| §10 | Refusals only for kept sections (ruling 3); a second reloc section is refused (ruling 4). Faults are reported only for live files. |
| stage B | `-e` is placed at argument 0, as the `Plan` keeps no argument index for it. |
| §11 | The section and symbol sequence spaces share one unit in `DiagKey`. |
| bench | It lives in `mortar_resolve/examples` (see above). |
| differential | mold's member set comes from `-Map`, because its `--trace` lists every member it reads. |
