# WP-022 — `mortar_resolve` stage A: resolution over an abstract view

`spec/resolve.md` (accepted; design record `WP-022-spec.md`). This stage
covers the algorithms over the `View` trait and their tests. Stage B
(the view over WP-020d's model tables) waits for WP-020d to merge.
Safe Rust (`forbid(unsafe_code)`), and the crate depends only on
`mortar_core`, `mortar_diag` and `mortar_elf`. Its only dev-dependency is
`mortar_testutil`.

The GNU simulation runs on pending sets. A lazy member becomes pending
when a key it defines changes to `Undefined`, or to `Common` for a
strong-data definer. Each pass visits only the pending members of the
archive's range, in order. The result equals the naive full visit on
every corpus (`tests/scale.rs`), and the 10^5-member descending chain
is not quadratic.

### The view trait

```rust
pub trait View: Sync {
    fn machine(&self) -> Machine;
    fn files(&self) -> u32;
    fn keys(&self) -> u32;
    fn comdats(&self) -> u32;
    fn file(&self, file: FileId) -> FileInfo;          // kind, archive, group: Option<u32>, sections, ...
    fn mentions(&self, file: FileId, out: &mut Vec<Mention>);
    fn mention(&self, file: FileId, index: SymbolIndex) -> Option<Mention>;
    fn groups(&self, file: FileId, out: &mut Groups);
    fn section(&self, file: FileId, index: SectionIndex) -> Option<SectionInfo<'_>>;
    fn key_name(&self, key: SymbolId) -> (&[u8], Option<&[u8]>);
    fn find_key(&self, name: &[u8]) -> Option<SymbolId>;
}
```

### Determinism

The results are equal across `TEST_THREADS` {1, 2, 7, 64} and 10
scheduling seeds plus no seed. This holds on 8 generated corpora of 400
members (archives inside and outside groups, chains, cycles, commons,
weak definitions, COMDAT groups) and on the cxx line of each target.
Each result also equals the liveness oracle and the naive simulation.
Every rules test runs under `check_schedules`.

### Benchmark

`cargo run --release -p mortar_resolve --example resolve_bench [response.txt]`.
The example lives in `crates/mortar_resolve/examples/resolve_bench.rs`,
not in `mortar_bench`, because the dependency edge points the other way.
It reports the median of 7 runs and asserts that each run equals the
sequential result.

- **cxx-medium (protoc).** 3181 files, 44768 keys and 26776 groups; 772
  files live, 10 rounds. Each `-l` is resolved to its static archive;
  the three `-l` with no static archive (`-lgcc_s` twice, and `-lm`,
  whose `libm.a` is a linker script) are skipped.
- **Synthetic.** 10^6 keys in 1000 members, all referenced from one
  object.

| input | 1 thread | 2 threads | 4 threads | 8 threads |
|---|---|---|---|---|
| cxx-medium | 21.9 ms | 22.1 ms | 21.5 ms | 26.9 ms |
| 10^6 keys | 44.4 ms | 28.6 ms | 27.0 ms | 31.5 ms |

The load average was 28.5–29.8 on 24 cores. The timings exclude loading
the model.

## Where the spec was unclear or silent, and what was chosen

| § | what was done |
|---|---|
| §2 | Names that only options mention need key rows. The view must supply them (`--wrap` already requires this). |
| §3.3 | A common with alignment 0 is malformed. |
| §3.7 / §9 | The `common` column holds only the keys whose def is `Common`. |
| §4.6 | Roots, including the default `_start`, count as undefined references before the first file. The `archive-backref` referrer is the first non-weak reference in walk order. |
| §4.6 | `archive-choice` also fires when both definers are the same member of one archive mentioned twice (cxx-medium as converted to a static link: `-lgcc … -lc … -lgcc` gives 20 such warnings, e.g. `__aarch64_cas4_relax`). This is correct by the letter but is noise. See the follow-ups. |
| §7.1 | `--wrap` does not redirect demoted mentions or roots. |
| §8 | Static-pie `__rela_iplt_*` follows the table, but no reference link has checked it. |
| §9.4 | The second lookup is implemented through the `also` row. |
| §10 | `.llvm_addrsig` is `SHF_EXCLUDE`, so the first-match rule gives Excluded, not Consumed. The table is inconsistent. |
| §10 | Classification refusals also apply to the members of dropped groups. Faults are reported only for live files. When one section has a second reloc section, the first is kept. |
| §11 | The section and symbol sequence spaces share one unit in `DiagKey`. |
| bench | It lives in `mortar_resolve/examples` (see above). |
| differential | mold's member set comes from `-Map`, because its `--trace` lists every member it reads. |
