# WP-200: a strong reference extracts the member past a dropped COMDAT copy's definition

`gcc -static -no-pie wu.o wa.o wb.o libhx.a`: wu.o references `hx`
strongly; wb.o's copy of group `g` is dropped (wa.o keeps it) and also
defines a weak `hx`; libhx.a's member defines `hx`. Once wb.o's copy is
dropped its `hx` is no definition, so wu.o's strong reference extracts
the member and the program exits 15. mortar refused it
(`comdat-mismatch`). Measured against GNU ld 2.44, lld 22 and mold
2.37.1 on AArch64 (natively), x86-64 and i386 (cross, qemu).

The supervisor's rulings on the first hand-back (2026-11-17) are part of
this record: §4.1's iterations confirmed (Q3); a demoted mention never
pulls, whatever its binding (Q1, replacing the brief's reading of §6.2);
so the "open key" narrowing has no case left and is gone (Q2); the
verifier follows §4.1 in its own package (Q4).

## 1. The cause

The order of events in `mortar_resolve` before this package:

1. `live::targets_with` computes `first(K)` and `cfirst(K)` once, over
   every file's mentions, before anything is live. wb.o's `hx` is a
   defined weak mention in a section, so `first(hx)` = wb.o (a named
   object, lower `FileId` than the member).
2. `live::closure`: wu.o's strong undefined `hx` is an edge to
   `first(hx)` only when that is a lazy file. wb.o is not lazy, so the
   edge has no target and the member is never reached.
3. `comdat::keepers`, over the closure's live objects: wa.o keeps `g`;
   wb.o's copy is dropped.
4. D1 demotes wb.o's `hx` (`effect`: `Ref { weak: true }`): `def[hx]` is
   `Undefined`, and the scan reports `comdat-mismatch`.

The keeper was chosen after the closure, and §4.1 said so ("COMDAT does
not feed back: extraction treats a definition in a group section as a
definition whichever copy is kept"). So the strong reference was never
seen as unsatisfied: at extraction time `hx` had a definer, the one that
is dropped one step later. §6.2's text ("the binding counts for ...
archive extraction") contradicted §4.1's bullet; the brief directs §6.2.

## 2. The fix

The closure is **iterated** (`resolve.rs` `resolve_stage`, `live.rs`),
as `spec/resolve.md` §4.1 now states it step by step:

- After a closure and the keepers over its live objects, D1 (which
  already demotes per file) checks every demoted mention with
  `live::feeds_back`: its definition is `first` or `cfirst` of its key
  (`K`, or the unversioned row of a `foo@V` mention).
- If one does, the closure runs again from the previous live files
  (extracted members keep their pulling references; `live::closure`'s
  `prior`), under `live::next_targets`: the targets recomputed without
  the definitions the keepers drop (`live::Prior`: the live files and
  the keepers), never lower than before, so a `--defsym` key keeps no
  target. The edges are §4.1's: a demoted mention is a defined mention
  and adds none.
- It stops when no demoted mention feeds back, or when an iteration
  would repeat the one before (targets, live set and keepers equal). The
  live set and the dropped copies only grow, the targets only rise: it
  ends.
- `live::oracle` runs the same iterations sequentially.
  `Resolved.iterations` counts them; `Resolved.targets` stays the
  targets before the closure (what the oracle is given).
- **Neededness** (`spec/dyn.md` D-11 item 2): a demoted mention no
  longer sets `flags::OBJ_STRONG`, so it makes no `--as-needed` shared
  object needed, whatever its binding. Before this package a demoted
  `STB_GLOBAL` mention did (`effect` gave it `Ref { weak: false }`).

The same edges serve every kind of lazy file (an archive member, a
`--start-group` member, a `--start-lib` object).

**The i386 thunks.** The first hand-back's version made a demoted
non-weak mention an edge; on i386 every object's COMDAT copy of
`__x86.get_pc_thunk.*` (a global hidden symbol) then pulled 3 to 51
libgcc/libm members GNU ld does not load, and needed a narrowing. With
demoted mentions never edges, the unchanged differential tests
(`crates/mortar_resolve/tests/differential.rs`, the i386 system lines
`chello32`, `mth32`, `spie32`, `tpl32` among them) pass with no
narrowing: no new finding.

**Cost.** A link with no mismatched copy runs one iteration, as before:
`feeds_back` is two loads per demoted mention in D1 (which already
visits every demoted mention). A second iteration redoes the closure
from all live files, the keepers and D1: only for a mismatched copy.
Timing: §8.

**Bytes.** A link that ran one iteration is unchanged.

**Can a copy read first be dropped (§6.1)?** Yes, under mortar's rule:
the keeper is the lowest live `FileId`, not the first loaded; wb2.o,
named and read before libwa2.a's member is extracted, loses its copy to
the member (keeper-later). GNU ld and lld keep the copy loaded first and
bind `hx` to its definition (80); that is §6.1's recorded difference.

**`-j1` and `-j8`.** The unit tests run every case under 1, 2, 7 and 64
threads and seeds (`check_schedules`) with the oracle; the lane cell
links with `--threads=1` and `--threads=8` and compares the bytes
(identical).

## 4. The verifier

The verifier (`mortar_plumb`, L3) still models §4.1 before this package:
its M12 finds every member mortar now extracts past a dropped copy
unreachable, e.g. `ext: M12 libhx.a(hx.o) is in the link and no root or
live reference reaches it (resolve §4.1)`. mortar's outputs were shown
correct by their runs (every mortar run of the table: `--no-plumb`, all
pass) and by their bytes (AArch64 `ext`: `main` and `Y` both `bl` the
member's `hx`, `mov w0, #7`; `g` is wa.o's `mov w0, #1`; wb.o's copy is
absent; exit 15). So these tests are committed as `.test.pending` with
the finding in their first line, to be renamed when the verifier follows
§4.1's iterations:

- `comdat-mismatch-weak-archive-extract` (its `xfail(mortar)` removed),
  `comdat-mismatch-extract-orders`, `comdat-mismatch-member-copy`,
  `comdat-mismatch-keeper-later`.

Live tests, all passing L3: `comdat-mismatch-archive-first` (no
feedback; all four linkers but mold link), `comdat-mismatch-strong-needed`
(mold's `libw.so` an `xfail(mold)`, the verifier's R5; lld an
`xfail(lld)`), and the refusal tests `comdat-mismatch-strong-demoted`,
`comdat-mismatch-unique-demoted` (mold on i386 an `xfail`: it crashes)
and `comdat-mismatch-strong-demoted-needed` (its `other` line links and
runs). The existing `comdat-mismatch*` tests keep their verdicts (the
whole lane).

## 5. Spec edits

- `spec/resolve.md` §4.1: the bullet "COMDAT does not feed back" is
  replaced by "A dropped copy's definitions stop counting when it is
  dropped", with the iterations as a procedure (iteration 1; the
  trigger; what is recomputed and kept; the end), complete enough to
  implement without the code (Q3, Q4).
- §6.2: a demoted mention binds, with its binding, to whatever defines
  the key once the closure has ended; its binding counts for precedence
  and the verdict's wording, never for extraction or neededness (the
  three references extract nothing for one either); from the moment its
  copy is dropped its definition is no definition for `first`/`cfirst`
  (Q1).
- §12.1 (`first`, `cfirst` row), §12.2 (the COMDAT bullet), §13 (the
  graph depends on the keepers of the live set).
- `spec/dyn.md` D-11 item 2: a demoted mention is not a strong reference
  that makes a library needed.
