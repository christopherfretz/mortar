# WP-176: a WEAK definition only a dropped COMDAT copy has

`spec/resolve.md` §6.2 demotes a non-local mention defined in a dropped
COMDAT copy to an undefined mention of its key, with its binding. A weak
one was then an undefined weak mention: a reference through it got the
undefined-weak value, silently (a call on AArch64 branched to the next
instruction; on x86 it called 0; a GOT load read 0; `-shared` imported
it). The supervisor's ruling of 2026-11-17: **a reference through a
demoted mention whose key ends with no definition is `comdat-mismatch`,
whatever the mention's binding.** Measured against GNU ld 2.44, lld 22
and mold 2.37.1 on AArch64 (natively), x86-64 and i386 (cross, qemu).

## 1. The fix

`crates/mortar_scan/src/view.rs`: `View::is_demoted_mismatch(id,
mention)` is true when `id` is a `comdat-mismatch` key (resolution's
`ComdatMismatch` rows), its `def` in the scan's view is still
`Undefined` (a shared object's definition binds it: the rows are made
before shared objects bind), and the record's own symbol is defined in a
section that is `Dropped(Comdat)`. Then `View::facts(key, Some(mention))`
gives the kind `TargetKind::Undefined` (with `comdat_only`), so the
architecture's scan reports `ComdatMismatch` as it does for a strong
demoted mention, in every output kind. `View::is_weak0` takes the
mention for the same reason, and `weak::file_uses` skips such records
(they are neither a use that makes the key `WeakDyn` nor one that is
refused as `weak-undefined-pc-in-pie`). Resolution is unchanged: it
already made the rows for weak keys.

### Not the obvious answer: brought to the supervisor (rulings pending)

1. **A reference from a debug section** (`.debug_info` naming hx) with
   no other surviving reference: GNU ld and lld link (correct program,
   exit 1), mold refuses, mortar before linked, **mortar now refuses**
   (`comdat-mismatch ... referenced by wbg.o:(.debug_info+0x0)`). The
   brief expected the tombstone row to hold; but mortar ALREADY refuses
   the strong form there (§6.3's case (b) row says "any kept referring
   section"; mold also refuses). The fix makes weak follow strong. A
   healthy build newly refused only if its debug info names a global a
   kept copy lacks.
2. **A shared object that defines the key under `--as-needed`**
   (Debian's default): the demoted weak mention does not make the
   library needed (§9.5: a weak reference does not), so the scan sees
   `Undefined{weak}`: GNU ld, lld and mortar before wrote a weak
   undefined import with no `DT_NEEDED` and the program died (SIGSEGV);
   mold refuses; **mortar now refuses** (`comdat-mismatch`). Binding
   there instead would need the demoted mention to count as a strong
   reference for D-11's needed set.
3. **A CIE no live FDE uses** (its function collected by
   `--gc-sections`), whose personality pointer names a demoted weak
   `DW.ref.*` with no definition: GNU ld, lld, mold link a correct
   program (exit 1); **mortar now refuses** (`.eh_frame+0x13`). The
   strong form is refused by GNU ld and lld too. The scan does not know
   CIE liveness: WP-177's mechanism (below).

## 3. Spec edits (`spec/resolve.md`)

- §6.2, the demotion bullet: the binding counts for resolution
  (precedence, extraction) but not for the verdict of a reference
  through it; such a reference to a key that ends with no definition is
  `comdat-mismatch` whatever the binding; another file's undefined weak
  reference stays 0.
- §6.3, the case (b) definition: "strong, weak or `STB_GNU_UNIQUE`".
- §6.3, the table: the case (b) row split into the strong/unique row
  (unchanged) and a weak row with the references' measured behaviour.
- §6.3, the `comdat-mismatch` paragraph: which references it covers.
- §14's diagnostics row, §15's test table (four rows), §16's comparison
  table (one row).

The `.eh_frame` and `.gcc_except_table` rows are left as they are
(WP-177 amends them).

  an inline variable and an inline `thread_local` (eight compilers and

  in every copy. GCC's `C5`/`D5` groups define `C1`+`C2` / `D0`+`D1`+`D2`;
  Clang writes `C2`, `D2`, `D0` groups of their own signatures, so no
  copy of one signature differs. The only difference is the binding:
  GCC writes static locals, template statics and inline variables
  `STB_GNU_UNIQUE`, Clang `STB_WEAK`.

**Rulings (supervisor, 2026-11-17, at the merge).**
1. Debug-only reference: stays `comdat-mismatch` for now, as the strong
   form already is (mold refuses both); refused by name, never a wrong
   program. WP-179 gives the debug rows the tombstone for case (b) of
   either binding, with the verifier's side (a debug field that names an
   entity which is not in the output is not the file "needing" it).
2. A shared object under `--as-needed` that the demoted weak mention
   does not make needed: stays `comdat-mismatch`, as the archive cell
   (no extraction): the mention's binding is not rewritten for the
   needed set. `spec/resolve.md` §6.3 says so.
3. A CIE no live FDE uses: WP-177 (its rule: a field of a record that
   is not written is no error, case (a) and case (b), strong or weak).

Verifier package: WP-178 (the references' undefined-weak value through
a demoted mention as a recorded anomaly; the three `.test.pending`

## 7. For WP-177

Two shapes of case (a) (a LOCAL symbol of a dropped copy) referenced
from a record of `.eh_frame` or from `.gcc_except_table` that stays
LIVE. Sources and a script, copied: `tests/repro/wp177/` (`run.sh
WORKDIR MORTAR`; the lane does not run it). AArch64:

| shape | GNU ld | lld | mold | mortar (02adceb3 and this package) |
|---|---|---|---|---|
| `cie-lh`/`cie-kg`: `ld.bfd -r` of p1.o p2.o, `objcopy --localize-hidden` (or `--keep-global-symbol`), then `pm.o r.lh.o`: r.lh.o's CIE personality (`.eh_frame+0x13`, `R_AARCH64_PREL32` against the LOCAL `DW.ref.__gxx_personality_v0`) used by live FDEs | links; the first throw aborts (134, `terminate ... what(): neg`) | refuses `relocation refers to a symbol in a discarded section: DW.ref.__gxx_personality_v0` | links; bus error (135) | **internal error**: `r.lh.o:(.eh_frame+0x13): internal error in mortar: relocation R_AARCH64_PREL32: no live target in the tables at offset 0x13` |
| `lsda-ti`: `ld.bfd -r` of q1.o, `objcopy --localize-symbol=DW.ref._ZTISt9exception`, then `qm.o rq.ti.o`: the live LSDA's type entry (`.gcc_except_table+0x20`, `R_AARCH64_PREL32` against the LOCAL `DW.ref._ZTISt9exception`) | links, writes 0: `catch (const std::exception&)` becomes a catch-all, `api1(1) returned -1` (an `int` caught) | refuses (the same message) | links; SIGSEGV | **MISLINK**: writes 0 (the table's last word `00000000`; the direct link has `e8ee0100`), the same wrong run |
| `cie-unused` (case (b), §2 item 3): a CIE only a collected FDE uses | links, 1 | links, 1 | links, 1 | refuses `comdat-mismatch` (`.eh_frame+0x13`) |

The code map:
- `crates/mortar_arch/src/dead.rs` `dead_reference(name, alloc)`:
  `.eh_frame` is `DeadRef::DeadFde`, exactly `.gcc_except_table` is
  `DeadRef::Zero`, a non-alloc debug name `Tombstone`, anything else
  `Discarded`.
- The scan's decision: each architecture's `scan` in
  `crates/mortar_a64/src/apply.rs` (the `if sym.dead` block before
  `weak_use_kind`), and the same block in `crates/mortar_x64/src/apply.rs`
  and `crates/mortar_x86/src/apply.rs`: only `DeadRef::Discarded`
  makes an event (`EventClass::DiscardedSection`); `DeadFde` and `Zero`
  make none, whatever the record. `sym.dead` comes from
  `crates/mortar_scan/src/view.rs` `View::local_facts` (a local of a
  section with no place, `has_place`). The scan has no notion of
  `.eh_frame` records.
- Fill: the same three `apply.rs` files, the `let x = if sym.live { ...
  } else { match dead_reference(..) ... }` of the field writer:
  `Tombstone` writes the tombstone, `Zero` writes 0 (the silent LSDA
  0), `Discarded | DeadFde` returns `FieldError::MissingTerm("live
  target")` (the internal error; its comment assumes `.eh_frame` is
  never written field by field there).
- Record liveness: `crates/mortar_merge/src/eh.rs` (`parse`,
  `EhFrames`: records, each CIE or FDE with its relocations and code
  section; `EhFrames::keepers`) and `crates/mortar_synth/src/eh.rs`
  (`EhPlan::new`/`select`/`select_in` and `mark_live`: per record 0
  removed, 1 live FDE, 2 used CIE, from `code_live` =
  `Liveness::fde_live`).

Reachable without `objcopy` (judgment from the code): the internal
error needs a CIE or a live FDE whose relocation names a LOCAL or
section symbol of a dropped group member; GCC and Clang name
`DW.ref.*` and type infos by their global hidden symbols and an FDE's
own function by its section symbol (that FDE dies with it), and `ld -r`
by GNU ld keeps those symbols global, so I believe only localization
after `-r` (`objcopy --localize-hidden`, `--keep-global-symbol`,
`--localize-symbol`) or hand assembly reaches it; the same holds for
the silent 0 in a live LSDA.
