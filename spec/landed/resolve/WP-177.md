# WP-177: a live unwind record or exception table into a dropped COMDAT copy

A relocation of `.eh_frame` or exactly `.gcc_except_table` whose symbol is
§6.3's case (a) (a local or section symbol of a dropped section of the same
file) or case (b) (a demoted mention whose key nothing live defines) was
judged by its section's name: `.eh_frame` gave an internal error at fill
(`MissingTerm("live target")`) when the record was live, and
`.gcc_except_table` wrote 0 silently, a catch-all type entry in a live LSDA
(a MISLINK: `catch (const std::exception &)` caught an `int`). WP-176's
case (b) refused a CIE no live FDE uses, a correct program. The
supervisor's ruling of 2026-11-17: **a field is judged by the record that
owns it, not by its section's name.** Measured against GNU ld 2.44, lld 22
and mold 2.37.1 on AArch64 (natively), x86-64 and i386 (cross, qemu).

## 1. The mechanism

Liveness of records comes from phase 60 (merge), which already parses
`.eh_frame` into `EhFrames` with each section's relocations (`eh_relocs`),
and phase 50 (`Liveness`); the scan (phase 70) is where the references are
judged, so the scan is given a question to ask, not a table:

- `mortar_core::split::EhOwner` (`Live { code }`, `Dead`, `None`).
- `mortar_merge::eh`: `EhFrames::frame_owner(section, offset, live)` (a
  binary search for the section, then for the record; an FDE is dead at its
  initial location field or when its code section is dead; a CIE is live
  with the first live FDE that uses it) and `LsdaStarts` (per table section,
  the LSDA starts of every parsed FDE whose LSDA pointer names it, live or
  dead, whatever file the FDE is in, from the LSDA pointer's
  section-relative relocation plus addend; sorted, one row per start, live
  if any FDE of that start is; `owner(table, offset)` the greatest start
  `<= offset`).
- `mortar_scan::EhOwners` (trait), `ScanInputs::eh`, `View::eh_owner`;
  `crates/mortar/src/eh_owners.rs` implements it over `merge.eh`,
  `merge.eh_relocs` and `Liveness`; `front.rs`
  passes it to the scan, `image.rs` (the walker, which makes no events)
  `None`.
- The architectures' scans (`mortar_a64`/`x64`/`x86` `apply.rs`) now report
  a dead target in `.eh_frame` / `.gcc_except_table` as an event
  (`!= DeadRef::Tombstone`); `mortar_scan/src/driver.rs` (`walk_unit`)
  drops a `DiscardedSection` / `ComdatMismatch` event of those two exact
  names whose owner is `Dead`, keeps `Live` and `None`.
- Fill (`mortar_image/src/reloc.rs`, `judged_mismatch`): a
  `.gcc_except_table` field the scan made a `comdat-mismatch` event of (a
  `comdat_only` key with no definition whose kind at the record's mention
  is `Undefined`: a strong key, or a mention COMDAT demoted, WP-176) reaches
  fill only with a dead owner, and is 0, as a dead target's, never `S + A -
  P` of an absent `S`. Another file's honest undefined weak mention of a
  weak such key made no event and keeps the undefined weak value of every
  other section (the review's hole 2).
- The diagnostic (`mortar_scan/src/report.rs`): for case (a) the group and
  the kept copy (`>>> the section is in a discarded copy of COMDAT group
  {sig}`, `>>> kept copy: {file}`); for both cases the owner (`>>> the field
  is in the unwind information of {function}, which is written`, `>>> the
  field is in the exception table (LSDA) of {function}, which is written`;
  with no owner `>>> no FDE has an LSDA in this section at or before this
  place: the field's owner is not known` in `.gcc_except_table`, `>>> the
  field is in no record of this section: its owner is not known` in
  `.eh_frame`); the prelink note when the local name is
  the signature or a non-local name of the kept copy (case (a)), or the
  kept copy defines the name as a local (case (b)): `>>> {name} is local in
  its file: it was probably made local after a partial link (objcopy
  --localize-hidden, --keep-global-symbol); dissolve the groups first (ld
  -r --force-group-allocation), then localize`. No new kind:
  `spec/diag.md`'s table is unchanged.

**Cost.** No pass: `Owners::new` stores four references. The scan asks
only for an event of the two sections (dead targets and mismatch keys),
`frame_owner` is two binary searches, and `LsdaStarts` is built once
(`OnceLock`) on the first `.gcc_except_table` question, which no healthy
link measured here asks (§3). The events the architectures now raise in
`.eh_frame` are the dead FDEs' initial locations of dropped copies (43,400
on `cxx-large-g`), each a push and a lookup. `cxx-large-g` timed with release
binaries of the base (0fd00819) and of this branch, alternating, four
pairs, on the shared machine at a load of 11 to 12.6 (`/usr/bin/time`):
wall 12.73 / 9.04 / 7.40 / 7.71 s (base) against 8.89 / 7.32 / 4.63 /
9.30 s; user 5.00 / 6.54 / 6.29 / 7.07 s against 6.07 / 6.65 / 5.96 /
6.49 s; peak RSS 2.01 GB both. No difference above the noise; a quiet
machine's measurement is the bench's (`cargo xtask bench`), not run.
The fill's test (the review's hole 2) costs a link with no such record one
name comparison per clip (`c.name == b".gcc_except_table"`), as before;
the mention is read only for a record of that section whose key is
undefined, weak and `comdat_only`: a deferred section's `r_sym` is in hand,
another's record is read again from its table (one record, one read of at
most 24 bytes; a read that fails is the read's error, never a guess). The
LSDA starts without the same-file filter (hole 1) cost one test fewer per
FDE, and are still built only on the first `.gcc_except_table` question.

**Byte-identical.** A link without such a relocation is unchanged; with
one, the image is unchanged where mortar linked before (a dead record is
not written either way; a dead owner's `.gcc_except_table` field was and is
0): static-identical, the gate's step: 3060 links of 432 tests on aarch64
x86_64 i386, 67 differ from `tests/identical/baseline.on-aarch64.tsv`,
and all 67 are new rows (`+`), the links of this package's five runnable
tests; no row of an existing link changed. `--update` added those 67
rows and removed none. After the review: 27 rows of `comdat-eh-hand`
differ, its 12 existing links moved 6 lines down by the new header
comment with their hashes unchanged, and 3 new (`xfile`, line 55); the
baseline updated with them.

## 2. The cells, as implemented

| place | owner | case (a) | case (b) |

| `.eh_frame`, a CIE no live FDE uses | dead | no error, not written | no error, not written (was WP-176's over-refusal) |
| `.eh_frame`, a live FDE (LSDA pointer, augmentation) | live | error | error |
| `.eh_frame`, a dead FDE | dead | no error | no error |
| `.eh_frame`, an FDE's initial location | dead (always) | no error: it makes the FDE dead | no error |

| the same, owner dead (of two FDEs with one start: dead only if both are) | dead | no error, 0 | no error, 0 |

redirecting the reference to the kept copy's symbol.

## 7. The review (2026-11-17): answers

- Hole 1: the `same_file` filter is gone (no reason found to keep it: a
  global of another file's table is resolved by phase 60 to that section,
  `Target::Section`, like a local). §6.3's sentence, `EhOwners::lsda`'s
  and `EhOwner::None`'s comments and the no-owner note now say what the
  code does; the note no longer names a file.
- Hole 2: restricted as above; the honest mention reaches the block (no
  earlier rule stops it: it is live, its kind `Weak0`), so the code
  changed.
- `frame_owner` and the 64-bit extended length: never asked. Phase 60
  refuses a record whose length word is `0xffffffff` by name (`feature`,
  `64-bit DWARF .eh_frame record`, S-34; `mortar_merge/tests/eh.rs`
  checks it) and the link stops there, before the scan.
- A `.gcc_except_table` field whose FDE is in an `.eh_frame` the parse did
  not take: every kept `.eh_frame` (by name, or `SHT_X86_64_UNWIND` on
  x86-64) is parsed and any problem stops the link, so the FDEs not taken
  are those of a dropped `.eh_frame` (a member of a dropped COMDAT copy,
  `SHF_EXCLUDE`, a script's `/DISCARD/`): reachable with hand-made input.
  Such an FDE is not written, so the field's real owner is dead; the
  previous start decides: dead gives 0 (the same answer), live gives the
  error, none the error. No written record reads the field (a live FDE
  that did would be the owner by its own start), so 0 there is never a
  live record's value, and the rule was left as it is.
