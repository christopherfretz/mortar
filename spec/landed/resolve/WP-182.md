# WP-182 (RL-2): the command line and resolution at `-r`

The row RL-2 of `spec/landed/layout/WP-154.md` §F: `spec/cli.md` §3.16
(C-R1..C-R6) in `mortar_cli`, and `spec/resolve.md` §11 (RV-R1..RV-R6,
RV-R8..RV-R10, RV-R7's election and dropped copies) in
`mortar_resolve::relocatable::resolve`. Nothing calls either at `-r`
until the join (RL-7): `-r` itself stays `unsupported option: -r`.

## A. The command line

- `Parsed::refused_uses` and `Parsed::refusals` act on `Row.at_r` when
  `plan.kind == Relocatable` (C-R2b): a `Noop` row, a `Conflicting` row
  (a parse error already) and an `Acts` row whose package has landed
  are not refused whatever their final-link status; `AsFinal` and an
  `Acts` row without `until` keep their final-link status (so
  `--build-id=md5` is still refused); a `Refused` row, and an `Acts`
  row whose package has not landed, give
  `Refused{Option, "<option> with -r"}` once per row with the notes of
  `spec/diag.md` §4.4 (`-T`/`--script`: the script note,
  `--gc-sections`, `--wrap`). `--compress-debug-sections=none` and
  `-z gcs=never` are accepted; `-z gcs=implicit` keeps its final-link
  status. `rows::SHARED_ONLY`'s refusal outside a `Shared` link does not
  apply at `-r` (those keywords are C-R2a no-ops).
- The conflicts (C-R1, C-R2a, C-R4, C-R2b): `-shared`/`-pie` through the
  kind (as before; `first` is the kind's spelling on the line), every
  other `Conflicting` row as `conflicting_with_r(spelling)` at its
  argument, once per row, a use overridden by a later last-wins use
  excepted.
- `-Ur` now sets the kind (`Lands::Ur` also records `-r`): before, a
  `-Ur` line had kind `StaticExecutable`.
- **TEST-ONLY seam**: `Parsed::refusals_landed(&self, landed: &[&str])`
  (`#[doc(hidden)]`): the refusals as they will be once the packages
  named (`"RL-7"`, `"RL-8"`, `"RL-10"`, `"RL-11"`) have landed.
  `refusals()` is `refusals_landed(&[])`. RL-7 lifts `-r`'s own refusal
  by changing the `-r` rows' status (or by calling the seam with the
  landed packages), never by a test-only path in the link.
- Tests: `crates/mortar_cli/tests/relocatable.rs` (`r_kind_spellings`,
  `r_conflicting_pie_shared`, `r_conflicting_rows`, `r_refused_options`,
  `r_z_refused`, `r_noop_options`, `r_as_final_and_acting_rows`,
  `r_until_lifted_by_the_package`, `r_driver_lines`: the 399 census
  lines of `tests/relocatable-design/work/census-lines.txt`).

## C. Resolution (`relocatable::resolve`)

Stage A runs unchanged (`resolve_steps` over `options()`, whose entry is
already `Entry::None` at `-r`); then, in `relocatable.rs`:
- RV-R8: every `Def::Provide` becomes `Undefined { weak: !REF_STRONG }`;
  `linker-symbol-redefined` problems are dropped.
- RV-R3, S14: a `-u` key left undefined gets `OBJ_REF`, so its
  `refs` has `FROM_OBJECT` and it is written; `-e` and
  `--require-defined` set nothing. A `-u` name (or a script's `EXTERN`)
  that no input mentions has NO key: the input phase interns no
  option's name. The new `relocatable::undefined_without_key(plan,
  inputs) -> Vec<Box<[u8]>>` lists those names (argument order, once
  each) for RL-4 to write as `STB_GLOBAL` `SHN_UNDEF` `STT_NOTYPE`
  entries after the keys'. (Interning them in the input phase instead
  would be a change to a shared table; not made.)
- RV-R1, RV-R6: after `resolution()`, every `SymProps.verdict` is
  `Bound` and `binding` is `verdict::binding_at_r(def)` (global, weak,
  never local for hidden keys). `STB_GNU_UNIQUE` is not in the table (as
  in a final link): RL-4 reads it from the defining entry.
- S13: a live object's row of kind `Stack` or `Excluded` is
  reclassified by `kind_at_r`: `.llvm_addrsig`, the call-graph profile
  and `.gnu.lto_*` stay `Excluded`, now `Dropped(Consumed)`; the others
  (`.note.GNU-stack`, `SHF_EXCLUDE` sections, `.gnu.warning*`, an input
  build id, `.deplibs`, AArch64 attributes) take the kind §10 gives
  their type and flags without `SHF_EXCLUDE` (`SHT_NOTE` `Note`,
  `SHT_NOBITS` `Nobits`, a non-alloc `.debug*` `Debug`, `Merge` placed
  whole as `Regular`, else `Regular`), `Kept`, or `Dropped(Comdat)` in a
  copy not kept; §10's refusals (linkonce, zdebug, compressed, unknown
  type) apply to them as to any kept section. A kept `SHF_LINK_ORDER`
  section whose linked section is a dropped copy is dropped (§6.5).
- `.gnu.warning` diagnostics and `gnu_warning_syms` are cleared.
- C-R5, RV-R9: `Err` before stage A for a shared object among the files
  (`shared object input with -r`, at each) and for a line with no `-m`
  and no relocatable object (measured: the input phase refuses such a
  line first, with the final link's `target emulation unknown: -m or at
  least one .o file required`, so C-R5's name is a backstop today;
  making the load give C-R5's name at `-r` is the input phase's);
  `GCC LTO sections with -r` at a live
  object with `.gnu.lto_*` that is not slim (a slim one gets the final
  link's `GCC LTO object`).
- `check_preemptible` is not run (no export at `-r`).

Tests: `crates/mortar_resolve/tests/relocatable.rs`.

## G. Questions to the supervisor

1. `-e` at `-r`: all three references extract an archive member for
   `-e`, and GNU ld writes `UND sym` for an `-e` nothing defines. RV-R2
   says `-e` is not a root at `-r`. Kept the text (lld's and mold's
   writing; none of the three's extraction).
2. `-rpath`: all three accept it at `-r` and change no byte; mortar's
   row is `Conflicting`. Kept the row (the text's class); a
   measurement-based case for `Noop`.
3. RV-R6's `.symver` form: one key row serves `vfoo` and `vfoo@@V2`
   (`spec/model.md` §2.3), so the table's `def` of `vfoo` IS the `@@`
   definition and a plain reference binds to it: lld's form. GNU ld's
   form (the text) needs the `@@` definition on a key of its own at `-r`
   (the input phase interning `foo@@V` under its full name when
   `plan.kind == Relocatable`, or a second column), a change to shared
   tables not made. Proposal: amend RV-R6 to lld's form (the text
   already says both forms' final links run), so that RL-4 writes the
   `@@` name for the key's entry and the reference's record names it.
4. L-R1 says `.gnu.warning*` sections are copied "by all three": GNU ld
   drops the file-level `.gnu.warning` at `-r` (and warns). mortar
   copies it (lld, mold) and does not warn at `-r`.
5. S13's internal error at RL-3 ("`Excluded` with `SHF_EXCLUDE`"):
   `.llvm_addrsig` and the call-graph profile stay `Excluded` with
   `SHF_EXCLUDE` and are `Dropped(Consumed)`; RL-3's check must look at
   the state (no kept row is `Stack` or `Excluded` at `-r`).
