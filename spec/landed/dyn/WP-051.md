# WP-051: the dynamic link-test harness (WP-M2-TEST)

Record of WP-051. The harness is specified in `spec/harness.md` "Link
tests" (this package's additions: `shlib`, fixtures, `env`, `then`,
`count`, `allow`, the checks `elflint`/`ldd`/`gdb`/`lldb`, the xfails
file's per-test lines, stage 3). The cases are the rows of `spec/dyn.md`
§16 and the default lines of §2.1, under `tests/link/dyn/`.

## 1. What the harness gained

- **Fixtures** (`tests/link/fixtures/<name>.fixture`, `#@ fixture:`):
  shared libraries built by GNU ld (`shlib` step, `-shared
  -fuse-ld=bfd`) once per run and architecture, cached under the run's
  work directory, copied into each unit's inputs. Six: `greet`,
  `shlib-chain`, `shlib-prot`, `needed-libs`, `reloc-libd`,
  `dynsym-walk`.
- **Runs** get `LD_LIBRARY_PATH` = the linker's directory; `env:` lines add
  `LD_PRELOAD`, `LD_BIND_NOW`, … natively, and as `qemu -E` under qemu.
- **Checks**: `then` (order), `count: <n>` (relocations by type, `DT_NEEDED`
  entries), `elflint` with `allow` (dyn.md Q5), `ldd` (the target's loader
  `--list`, under qemu off-host), `gdb`/`lldb` in batch mode (on-host
  only; `SKIP` by name under qemu).
- **Per-test xfails**: `mortar[,<arch>...] <test>: M2: WP-0xx (NAME)` in
  `tests/link/xfails`. When a package lands, deleting its lines is the
  whole change; its rows then must PASS (an unremoved line is `XPASS`).
- **Stage 3**: `engine::stage3_present()` (`xtask/src/linktest/engine.rs`)
  probes `mortar_plumb::verify` with a bare AArch64 `ET_DYN` header; stage
  3 is absent while S1 answers "not ET_EXEC". Dynamic outputs are counted
  `not judged: stage 3 absent` until then, judged afterwards with no edit.
  The unit test `stage_3_is_absent_today` is the one line WP-050 turns
  round.

## 4. Spec findings (from the cases; proposed text)

1. **D-16 / App. B**: GNU ld does diagnose a TLS mismatch against a shared
   definition (both directions); lld and mold link and the programs crash
   or read garbage. Drop "[unverified]", cite GNU ld, add §13.2 **W14**
   "lld, mold: TLS/non-TLS mismatch against a shared definition links;
   the program crashes" (`tls-mismatch-shared`). mold also copies an
   `STT_TLS` definition (`copy-tls-refused`, reads the ELF header).
2. **D-42**: name the TLS copy refusal: "a copy of an `STT_TLS` definition
   is `tls-mismatch` (D-16)".
3. **W15 (new)**: GNU ld on AArch64 relaxes a traditional GD sequence to IE
   without a64.md R4's `nop` check; the program reads a wrong address
   (`tls-gd-unrelaxed`).
4. **a64.md §8.2 / App. B / Q10**: GNU ld relaxes the large-model TLSDESC
   (to IE against shared, LE against own); lld and mold do not know
   relocations 565-568. No reference runs mortar's eager large form.
5. **D-47 / §13.1**: GNU ld writes `DT_TEXTREL` (no refusal) for an
   address-sized word in `.rodata`, on both 64-bit targets; it refuses only
   words no record can express. mold writes `DT_TEXTREL` silently on both
   and the program runs; W6's crash is i386's.
6. **W3**: on AArch64 GNU ld also gives `a != b` in a PIE whose IFUNC unit
   is `-fno-pic`.
7. **§13.1 TLS of the executable's own symbol**: GNU ld's IE+TPOFF is
   x86-64 only, and only when the symbol is exported.
8. **D-14**: "a `Vernaux` that no judged reference requires is not
   checked" (a strong versioned reference is refused under D-13).
9. **D-18**: an x86-64 `-fPIE` PIE also needs a copy of protected data
   (all refuse); GNU ld's AArch64 canonical-PLT message is the copy one.
10. **D-13 test name** `shlib-undefined-missing-needed` vs §16
    `shlib-undefined-missing-closure` (the case uses §16's).
11. **§13.1 missing rows**: mold makes an as-needed library needed by a
    weak reference alone (D-11, 2.2a); the branch-only weak key (GNU ld,
    lld: dynamic + `JUMP_SLOT`; mold 0; mortar Weak0); `-no-pie` base
    0x200000 (lld, mold); static-pie IRELATIVE in `.rela.plt` (GNU ld) vs
    `.rela.dyn`; mold writes no `DT_RELACOUNT` in a static PIE; a copy of a
    weak definition is WEAK (bfd) or GLOBAL (lld, mold); `VARIANT_PCS`
    tag order.
12. **D-25, AArch64 `-no-pie`**: GNU ld and lld resolve `ADRP`/`ADD` to an
    undefined weak as the instruction's page, not 0; state what mortar
    writes for a `Weak0` `ADRP`.
13. **D-21**: x86-64 `-no-pie` export set is not lld's (`_ITM_*`).
14. **D-60**: no reference has D-60's order whole; say "the order is
    D-60's own". **D-61**: GNU ld on AArch64 writes two `PT_LOAD`s; lld
    omits `PT_GNU_PROPERTY` on x86-64.
15. **D-30/D-32/D-34 details**: mold drops BTI (no `DT_AARCH64_BTI_PLT`);
    mold writes `_DYNAMIC` into `.got.plt[0]` on AArch64; bfd's AArch64
    PIE `.dynsym` `sh_info` 3; mold's `.rela.plt` lacks `SHF_INFO_LINK`.
16. **X3 (D-11/D-13)**: lld and mold link, drop `libleaf.so`, load fails
    (exit 127): a W row like W8.
17. **Diagnostic names**: `diag.md` §2.2 prints no ids, so cases match the
    message text (`undefined symbol: X`, `TLS attribute mismatch: X`,
    `dynamic executable without -dynamic-linker`) and the bare refusal
    name for dyn.md refusals `diag.md` does not list
    (`copy-relocation-against-protected`, `canonical-plt-in-pie`,
    `copy-relocation-of-zero-size`, `text-relocation`,
    `weak-undefined-pc-in-pie`, `versioned-export`): `diag.md` needs a row
    fixing how each is printed (e.g. `unsupported feature: <name>`).
18. **cli.md**: `--hash-style=sysv` is a noop in mortar today;
    `hash-style-sysv-refused` needs cli.md's refusal row (R-C1).
19. lld x86-64 large-model GD (`-mcmodel=large -fPIC`) crashes in PIE and
    non-PIE (x64.md X-25 records only static); no rule covers an
    unrecognised x86-64 `TLSGD` in `Exec`/`Pie` (X-26).

## 5. Follow-ups

- gdb/lldb under qemu: `qemu -g <socket>` with `gdb-multiarch` (now
  `SKIP` by name on x86_64).
- Harness forms the authors asked for: comparing two outputs
  (`pure-function` uses its own `elfcmp` program; D-22 `--threads`
  stability), qualified `stdout`/`exit`/`env` (now one `run(<linker>)`
  step per variant), architecture-qualified build steps (now `.S` with
  `#if`), a scoped `not` ("no RELATIVE after a non-RELATIVE":
  `rela-dyn-order` reads its own file).
- `mixed-mode`'s mortar refusal expects `canonical-plt-in-pie`; if mortar
  reports `text-relocation` first for that unit, the line changes (the
  join decides).
- Not ported: `needed_order.sh`'s `bstatic_*`/`pushpop*` lines (W9's
  second form; WP-056 options), the asm-only rows of D-25's table
  (`PC32` on jcc, `CONDBR19`/`TSTBR14`).
- `no-dynamic-linker-refused` is tagged CLI; if `-pie` without
  `-dynamic-linker` does not reach input's refusal once CLI lands, it moves
  to WP-053/WP-055.
