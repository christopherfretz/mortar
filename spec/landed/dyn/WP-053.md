# WP-053: the first dynamic executables, AArch64 (WP-M2-JOIN-C)

Record of WP-053. Scope: the row WP-M2-JOIN-C of `spec/landed/dyn/WP-040.md`;
the follow-ups WP-042..WP-051 left "for the join". The dynamic-output guard
is gone: AArch64 `Exec` and `Pie` link; x86-64 dynamic output is refused by
name naming WP-055, i386 dynamic output is refused for M2, static-pie is
refused (WP-052). Static links are byte-identical (`cargo xtask
static-identical`).

## 1. What changed, by crate

- `mortar` — `dynamic.rs`: the guard (`dynamic_guard`, `DYNAMIC_OUTPUT`,
  `option_refusals`) deleted; `arch_status` looks at the architecture and
  the kind. `dynlink.rs` (new): phase 80 for an output with `.dynamic`
  (`OutWritable`, `ScanKinds`, `DynSource`, `plan`: copy, `.dynsym`,
  versions, `.dynstr`, `.rela.dyn`, `.dynamic`, `.interp` and the `Slots`
  fields they fix). `front.rs`/`image.rs`: the dynamic plans threaded to
  the image; `Front.closure_only`. `syms.rs`: `CoreSyms::default_version`
  (the `V` of a `foo@@V` definition, read from the defining entry) and
  `defined_other_flags` (`STO_AARCH64_VARIANT_PCS` of the defining entry).
- `mortar_image` — `link.rs`: the dynamic chunks (`DynPlans`, `DynView`,
  `DynChunks`), `.rela.dyn`, `sh_link`/`sh_info`, `EI_OSABI`, the map's
  dynamic records and `arg` records (P-D2); NOBITS chunks (`.dynbss`,
  `.bss.rel.ro`) get no fill row. `dynrel.rs`: the join's records.
- `mortar_synth` — `dynsym.rs`: one entry per copied shared definition
  (`copy_aliases`), `one_entry_per_definition` (refusal, §2 (a)); the
  import rows and the export row keep `STO_AARCH64_VARIANT_PCS` on
  AArch64 (§2 (b)).
- `mortar_scan` — `ScanInputs.closure_only`; `report.rs` `undefined`
  writes D-12's note (§2 (e)).
- `mortar_cli` — `AT_JOIN` folded into `ROWS` and deleted (`join_changes`,
  `status_at_join`, `refused_uses_at_join`, `join_markdown`);
  `docs/status/options.md` regenerated; `spec/cli.md` §4.2.
- `spec/dyn.md` D-23: the import row and the export row keep
  `STO_AARCH64_VARIANT_PCS` (measured: GNU ld, lld and mold).
- One table: D-43/D-44 only in `mortar_arch::class_outcome`, D-47 only in
  `mortar_scan::driver::dynamic_error`, D-46 only in
  `mortar_image::dynrel::zeroed_place`; no per-arch copy exists.

## 3. Targets

- 1a/1b (gcc default line, PIE and `-no-pie`, C hello): link, run, plumb
  findings 0; gdb breaks on `main`; lldb too (`settings set
  target.disable-aslr false`). eu-elflint: `.relro_padding` "expected
  RELR" (its `.relr` prefix match; lld's output gets the same); GNU ld's:
  no errors.
- 2: `tests/link/dyn` on AArch64: every WP-053 line removed but
  `tls-desc-large` (verifier request).
- 3: the C programs of E-corpus (`review-m2/corpus/src` `c_main.c` +
  `c_helper.c`): gcc, clang-19, clang-22 × the nine AArch64 modes of
  `corpus/run.sh` × O0/O2 × PIE/`-no-pie`, 104 combinations (4 do not
  compile: clang has no `-mtls-dialect=trad`). 50 link with GNU ld: mortar
  links all 50, output equal to GNU ld's, plumb clean. 6 (`-fno-pic`
  objects into a PIE) both refuse (mortar: `canonical-plt-in-pie`, D-44,
  for `strlen`/`memcpy` reached by `ADR_PREL_PG_HI21`). 44 (PIC/PIE objects with `-no-pie`) GNU ld refuses
  (`unresolvable R_AARCH64_ABS64 relocation against symbol
  environ@@GLIBC_2.17` in `.data.rel`); mortar links them, like lld, with
  a dynamic `R_AARCH64_ABS64` against the key in the writable word; each
  runs with the output of the same objects linked PIE by GNU ld, plumb
  clean.

## 4. Findings for the supervisor

- plumb.md P-D12 lacks D-48's kept TLSDESC record (a64 R2): a verifier
  request (reproducer `tests/link/dyn/reloc/tls-desc-large.test`).
- `.symtab` drops `STO_AARCH64_VARIANT_PCS` (`syms.rs` `other =
  visibility & 3`), static links included; GNU ld, lld and mold keep it.
  Not changed here (static-identical); a fix changes static bytes for
  inputs with variant-PCS functions.
- `.relro_padding` trips eu-elflint's `.relr` prefix match (lld too).
- `section_writable` is taken from the input flags where the brief said
  the output section's.
- `.gnu.version_r` is aligned 4; GNU ld's 8.
- static-pie is refused by the layout.
- Two unhashed imports of one shared definition (`foo` and `.symver
  foo@V` referenced by the program, no copy and no canonical PLT) give
  two `UND` entries of one name and version: kept (correct at load); mold
  writes one.
