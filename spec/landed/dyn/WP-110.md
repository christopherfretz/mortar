# WP-110: M4, shared-object output, the design

Design record of WP-110: the census of `-shared` lines (A), the
inventory of what the specs already say about a shared output (B), the
work-package cut (D), the open questions (E), and the experiments
(appendix). The rules (C) are in the owning specs: `spec/dyn.md` §17
(D-100 and later), `spec/resolve.md` §9.6-§9.7, `spec/script.md` §9;
the requests to other specs, `spec/plumb.md` and `spec/diag.md`
included, are `spec/dyn.md` §18.

Status: second pass after the adversarial review
(`briefs/reviews/review-110-shared.md`: B-1, B-2, M-1-M-8, m-1-m-9);
every changed rule is backed by a script of `exp2/` (Appendix A) whose
results are in §F.

## A. Census

Measured by `E-shared-census` (Appendix A): 21 drivers (gcc, g++,
gfortran for AArch64, x86-64 and i386; clang and clang++ 19 and 22 for
the three) × 35 variations = 723 lines, each captured by a `-B` wrapper
(`-###` agrees with it on the 7 drivers compared), linked by GNU ld (614
link), and each library `dlopen`ed (`RTLD_NOW`) by a GNU-ld-linked host
that checks it (578 pass); the real libraries of the survey (zlib 1.3.1,
the Lua 5.4.7 test modules, googletest), libtool-shaped and CMake 3.31.6
lines linked by all four references and run.

### A.1 Default lines

`$G` the GCC library directory, `$S` the system one.

| driver | line |
|---|---|
| gcc, AArch64 | `-plugin … --build-id --eh-frame-hdr --hash-style=gnu --as-needed -shared -X -EL -maarch64linux --fix-cortex-a53-843419 -o OUT $S/crti.o $G/crtbeginS.o -L… OBJ -lgcc --push-state --as-needed -lgcc_s --pop-state -lc -lgcc --push-state --as-needed -lgcc_s --pop-state $G/crtendS.o $S/crtn.o` |
| gcc, x86-64 / i386 | the same with `--sysroot=/` and `-m elf_x86_64` / `-m elf_i386`, without `-X -EL -maarch64linux --fix-cortex-a53-843419` |
| clang 19 and 22 (identical) | `[-EL] --hash-style=gnu --build-id --eh-frame-hdr -m <emul> -shared -o OUT crti crtbeginS -L… OBJ -lgcc --as-needed -lgcc_s --no-as-needed -lc -lgcc --as-needed -lgcc_s --no-as-needed crtendS crtn` (no plugin, no global `--as-needed`) |
| C++ tail | gcc `-lstdc++ -lm -lgcc_s -lc -lgcc_s` (no `-lgcc`); clang `-lstdc++ -lm -lgcc_s -lgcc -lc -lgcc_s -lgcc` |
| gfortran tail | `-lgfortran -lm -lgcc_s [--as-needed -lquadmath --no-as-needed, x86 only] -lm -lc -lgcc_s` |

Against dyn.md §2.1's executable lines: no `crt1.o`/`Scrt1.o`, no
`-dynamic-linker`, no `-pie`; `crtbeginS.o`/`crtendS.o` as for a PIE.
Every option on the 21 default lines but `-shared` is already accepted
by mortar; mortar refuses all 21 (`unsupported option: -shared`), and
546 of the 723 lines for `-shared` alone.

12 of 19 need nothing but `-shared` on the default line; among them
the 10 Lua module lines leave undefined references to load time, which
is D-118's `Shared` default (in S1a), not an option: they need nothing
beyond what the first package delivers. 4 need `-soname` (and
`--dependency-file`, accepted); 3 need `-soname` and `--version-script`.
All four references link every real library and every cross-run passes
(zlib 48/48 runs; Lua 9/9 checks and `attrib.lua`; googletest 797 tests
and a library-thrown exception caught in the executable). libtool-shaped
lines (hand-written: libtool is not installed) add `-version-script`
(one dash), `--whole-archive` of a convenience archive and `-nostdlib`
with explicit crt files; CMake's add `-soname`, `--dependency-file` and
`-rpath`, and link a library by path.

### A.4 What the first package must accept, ranked

Out of 25 real lines (19 survey, 4 libtool-shaped, 2 CMake):

1. `-shared` on the default driver line: 25/25 (21/21 default lines).
   The inputs are an executable's (crt files, `-l` tails, `--as-needed`,
   `--push-state`); the output needs D-100-D-125's core: every
   default-visibility definition exported, C++ vague linkage and
   `STB_GNU_UNIQUE` included; PLT/GOT, `RELATIVE`, symbolic records;
   init/fini; `PT_GNU_EH_FRAME`; RELRO; `DT_NEEDED` with `--as-needed`.
2. Undefined references left to load time (D-118): 10/19 (the Lua
   modules), with `-z defs`/`--no-undefined` refusing them (42 census
   lines).
3. `-soname`: 13/25.
4. `--version-script`/`-version-script`, zlib's subset, undefined names
   accepted as GNU ld does: 4/25 (D-114, script.md §9).
5. `--dependency-file`, `-rpath`: 6/25 and 2/25, already accepted.
6. `--whole-archive`: 1/25.
7. **Two generators outside the survey, measured** (`exp2/ldlines`):
   - Python 3.13's `sysconfig` `LDSHARED`, the line of every setuptools
     extension module: `aarch64-linux-gnu-gcc -shared -Wl,-O1
     -Wl,-Bsymbolic-functions -Wl,-z,relro`. So `-Bsymbolic-functions`
     is on a common default line and moves into the first package
     (S1a); `-O1` is already a no-op (`docs/status/options.md`), `-z
     relro` the default.
   - rustc 1.95's `cdylib` line: `--version-script` (a temporary
     file rustc deletes; the output has no `.gnu.version_d`, so the
     script is anonymous), `--no-undefined-version`,
     `--as-needed`, the `std` rlibs under `-Bstatic`, `-Bdynamic`,
     `--eh-frame-hdr`, `-z noexecstack`, `--gc-sections`, `-shared`,
     `-z relro,-z now`, `-O1`, `-nodefaultlibs`; the output has
     `BIND_NOW` and `DF_1_NOW`. So `-z now` in `Shared` moves into S1b
     (D-49 unchanged); the anonymous script and `--no-undefined-version`
     are S3, after which a Rust `cdylib` links. The `std`, `core`,
     `alloc` and `compiler_builtins` rlibs (405 objects; the line links
     15 more small rlibs, not scanned) pass D-117's address-level rule
     with 0 refusals (§F.1).
8. Seen on census lines only, can stay refused in the first package:
   `-Bsymbolic`, `--dynamic-list`, `--exclude-libs`, `-z nodelete`/
   `initfirst`/`interpose`, `-u`, `-init`/`-fini` with `-shared`
   (`-init`/`-fini` are already supported for executables).
9. Refused by name, never linked: text relocations (i386 non-PIC: GNU ld
   links 14 census lines, W25 crashes), non-PIC 64-bit objects (all
   three refuse when the relocation names the symbol; mortar also when
   it names an address inside an exported datum, D-117), LE TLS
   (D-119).

## D. The cut into work packages

The first joined target: **a `-shared` C library with a soname on
AArch64, from the default driver line (and Python's `LDSHARED` line),
loaded by a GNU-ld-linked host and by a mortar-linked host, verified by
stage 3.** Then versions, C++, x86-64, the option tail. Names are
provisional (the supervisor numbers them).

**Estimates** are anchored to landed packages (merge `+lines` under
`crates/` and `tests/`, wall time of the implementer), in WP-040's
classes: **S** about 1-2k lines (about 1 hour), **M** about 4-6k (1-2
hours), **L** about 8-9k (about 2 hours or more). Anchors: WP-041 step 0
+2.2k, 69 min; WP-042 cli +1.4k, 78 min; WP-043 resolve +3.6k, 111 min;
WP-044 `.dynsym` +2.8k, 48 min; WP-045 `.dynamic` +1.8k, 152 min; WP-046
relocations +3.1k, 76 min; WP-047 a64 +1.6k, 100 min; WP-048 x64 +2.0k,
125 min; WP-049 layout +1.3k, 68 min; WP-050 plumb stage 3 +6.2k, 197
min; WP-051 harness +7.8k, 89 min; WP-053 a64 join +1.8k/-0.6k, 115 min;
WP-055 x64 join +0.2k, 50 min.

## E. Open questions (each with a recommendation)

- **Q10. Closed (the review's M-6 ruling).** A `COPY` of data its
  library binds locally: refused when the datum lies in a writable
  `PT_LOAD` outside RELRO, or in none; warned otherwise (two equal
  constants). Request R-D43 against D-43, package S-R43; W30
  reclassified (dyn.md D-126 item 2, §F.5).
- **Q11. Entry of a library (D-101).** layout L-103 writes 0 for every
  `-shared` link; all three references write `&_start` when the library
  defines it. *Recommendation:* the references' (R-L11).
- **Q12. Closed (the review's M-7 ruling).** A `.symver` definition
  `foo@V1` is hidden exactly when node V1's own `local:` matches `foo`
  (GNU ld and lld; mold keeps it, §17.8), with the warning
  `versioned-definition-hidden`; a `local:` of another node leaves it
  exported (all three, `exp2/vscript2`). resolve §9.7 rule 12.
- **Q13. Undefined names in a version script.** resolve.md Q6 recommended
  accepting with a warning; GNU ld is silent. zlib's probe prints one
  warning per missing name (22) and links. *Recommendation:* the
  warning, as Q6 (applied: resolve §9.7 rule 9).
- **Q14. Narrower than every reference (D-117).** x86-64 `PC32` call or
  jump to a preemptible key (mold: a PLT entry, correct) and i386
  `R_386_PC32` in data (GNU ld, lld: a record, correct) are refused.
  *Recommendation:* refuse; no compiler emits either in `-fPIC` code, and
  each has a one-line remedy.
- **Q15. `-init`/`-fini` naming an undefined symbol (D-102).** All three
  silently drop both tags. *Recommendation:* refuse in every kind
  (`undefined-init-symbol`), the executables' D-30 rows 3-4 included
  (a request to D-30 when S6 lands).
- **Q16. Version-node name symbols (D-110 item 3).** GNU ld and the
  system's `libz.so` export them; lld and mold do not. Nothing measured
  reads them. *Recommendation:* do not export (the dynamic interface is
  then a function of the script's symbols only).
- **Q17. TLS relaxation in `Shared` (D-119).** None of the references
  relaxes GD to LD or IE in a library; mortar does not either.
  *Recommendation:* none at M4; a later speed package may add GD→LD for
  non-preemptible keys if a benchmark asks.
- **Q18. Four `PT_LOAD`s and `PT_PHDR` (D-100, D-123).** As D-61 for a
  PIE (lld's segments, GNU ld's `PT_PHDR` rule). *Recommendation:* as
  written; one layout for PIE and shared objects.
- **Q19. i386 IFUNC in a shared object (D-130).** Every reference is
  wrong or refuses a form. *Recommendation:* refused by name until a
  package designs it (likely: every address word an `IRELATIVE` to the
  resolved function, as x86.md X86-50's static-pie rule, and calls
  through the `%ebx` IPLT).
- **Q20. `DF_SYMBOLIC` written at all (D-112).** It changes nothing once
  every key is bound at link time, and is wrong with `--dynamic-list`.
  *Recommendation:* write it for plain `-Bsymbolic` (GNU ld's output,
  and D-126 item 2 reads it in other libraries); never with a list.
- **Q21. The anchor+immediate gap (D-117, W44).** GCC AArch64 `-fPIE`
  code that reaches an exported datum as `adrp`/`add` of the section
  anchor plus a load or store immediate names only the anchor: no
  relocation-level rule sees it, and every reference links it into a
  mislinked library. Measured: 19 of 84 bound definitions in the
  corpus, each in an object the rule refuses for another use; one
  constructed object (`exp2/gapdemo/gap2.c`) whose only bound uses are of
  this form links. Options: (a) decode, in the scan, the instructions
  that use the register an anchor `ADD :lo12:` defines, up to the end of
  the basic block, and apply the address rule to `anchor + immediate`
  (exact, AArch64 only, costs a walk over code that names an anchor of a
  section holding exported data); (b) a warning on any non-GOT use of
  such an anchor (no false refusal, but noise: the over-approximation
  count, 2-6 correct `-fPIC` objects per corpus group, §F.1, shows it
  fires on correct code); (c) the `DW_AT_producer` hint (`-g` objects
  record `-fPIC`/`-fPIE` in their flags) to refuse objects compiled
  without `-fPIC`: exact for GCC with `-g`, absent without it.
  *Recommendation:* (a) in a package after S1j (it is a scan-side
  addition with its own corpus measurement); until then the gap is
  stated in D-117, in P-R8's table (not caught) and by W44's test,
  which asserts today's behaviour.
- **Q22. An opt-in escape for B-1's refusal (the ruling's question).**
  The address rule refuses objects the references link: on the corpus 3
  of 54 GCC AArch64 `-fPIE` objects (`anchorgap.c`, the census
  `lib.c`, zlib's `zutil.c`) and `libgomp.a(env.o)`
  (`exp2/b1/onlyrule.py`); no census or survey `-shared` line (all
  `-fPIC`) and no rustc rlib. Candidate escape: export the bound
  definition `STV_PROTECTED` (what the code assumes) with a warning.
  Measured (`exp2/escape`): an executable that reaches a protected datum
  through a `COPY` is refused at link by all three (GNU ld ``copy reloc
  against protected `g' is dangerous`` on AArch64, ``copy relocation
  against non-copyable protected symbol`` on x86-64; lld ``cannot
  preempt symbol: g``; mold ``cannot create a copy relocation for
  protected symbol``) when it is linked against the protected build; a
  `-pie` host runs on AArch64 (GOT) and is refused on x86-64 (GCC's
  x86-64 `-fPIE` copies, D-43). An executable linked earlier against the
  default build and run against the protected one: glibc 2.41 warns
  ``copy relocation against non-copyable protected symbol`` and runs
  with two instances (`all=3 g=100`, AArch64 and x86-64); with the W41
  property (`-mno-direct-extern-access`, x86-64) the load is refused
  (``error due to GNU_PROPERTY_1_NEEDED_INDIRECT_EXTERN_ACCESS``)
  [AArch64 property unmeasured]. *Recommendation:* not in the first
  package (the ruling); if a real codebase needs it, an explicit option
  that exports such definitions protected, sets the W41 property where
  the target has one, and warns per definition, so that an old
  executable is refused by the loader instead of mislinked.

### F.9 The max page (`maxpage/`)

all load and run on this 4 KiB kernel; every `PT_LOAD` is congruent

available (qemu-user cannot change the host's page size): Appendix B.
