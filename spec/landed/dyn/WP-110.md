# WP-110: M4, shared-object output, the design

Design record of WP-110: the census of `-shared` lines (A), the
inventory of what the specs already say about a shared output (B), the
work-package cut (D), the open questions (E), and the experiments
(appendix). The rules (C) are in the owning specs: `spec/dyn.md` §17
(D-100 and later), `spec/resolve.md` §9.6-§9.7, `spec/script.md` §9;
the requests to other specs, `spec/plumb.md` included, are `spec/dyn.md`
§18.

Status: draft for review (WP-110).

## A. Census

Measured by `E-shared-census` (Appendix A): 21 drivers (gcc, g++,
gfortran for AArch64, x86-64 and i386; clang and clang++ 19 and 22 for
the three) × 35 variations = 723 lines, each captured by a `-B` wrapper
(`-###` agrees with it on the 7 drivers compared), linked by GNU ld (614
link), and each library `dlopen`ed (`RTLD_NOW`) by a GNU-ld-linked host
that checks it (578 pass); the real libraries of the survey (zlib 1.3.1,
the Lua 5.4.7 test modules, googletest), libtool-shaped and CMake 3.31.6
lines linked by all four references and run.

### A.1 Default lines

`$G` the GCC library directory, `$S` the system one.

| driver | line |
|---|---|
| gcc, AArch64 | `-plugin … --build-id --eh-frame-hdr --hash-style=gnu --as-needed -shared -X -EL -maarch64linux --fix-cortex-a53-843419 -o OUT $S/crti.o $G/crtbeginS.o -L… OBJ -lgcc --push-state --as-needed -lgcc_s --pop-state -lc -lgcc --push-state --as-needed -lgcc_s --pop-state $G/crtendS.o $S/crtn.o` |
| gcc, x86-64 / i386 | the same with `--sysroot=/` and `-m elf_x86_64` / `-m elf_i386`, without `-X -EL -maarch64linux --fix-cortex-a53-843419` |
| clang 19 and 22 (identical) | `[-EL] --hash-style=gnu --build-id --eh-frame-hdr -m <emul> -shared -o OUT crti crtbeginS -L… OBJ -lgcc --as-needed -lgcc_s --no-as-needed -lc -lgcc --as-needed -lgcc_s --no-as-needed crtendS crtn` (no plugin, no global `--as-needed`) |
| C++ tail | gcc `-lstdc++ -lm -lgcc_s -lc -lgcc_s` (no `-lgcc`); clang `-lstdc++ -lm -lgcc_s -lgcc -lc -lgcc_s -lgcc` |
| gfortran tail | `-lgfortran -lm -lgcc_s [--as-needed -lquadmath --no-as-needed, x86 only] -lm -lc -lgcc_s` |

Against dyn.md §2.1's executable lines: no `crt1.o`/`Scrt1.o`, no
`-dynamic-linker`, no `-pie`; `crtbeginS.o`/`crtendS.o` as for a PIE.
Every option on the 21 default lines but `-shared` is already accepted
by mortar; mortar refuses all 21 (`unsupported option: -shared`), and
546 of the 723 lines for `-shared` alone.

### A.3 The survey's `-shared` lines, by what they need

`.build/real-builds/results/*/lines`, kind `shared`: 15 build lines and
4 configure probes.

| project | compiler | lines | needs beyond `-shared` on the default line |
|---|---|---|---|
| Lua modules (`lib1`, `lib11`, `lib2`, `lib21`, `lib2-v2`) | gcc, clang | 10 build | nothing; undefined `lua_*` left to load time (no `-z defs`), module-to-module references |
| googletest (`libgtest_dll`, `libshared_gmock_main`) | gcc, clang | 4 build | `-soname`, `--dependency-file` (accepted); C++: 3840 exported definitions, 6 `STB_GNU_UNIQUE`, `main` exported |
| zlib `libz.so.1.3.1` | gcc | 1 build | `-soname`, `--version-script` (zlib.map: 14 nodes in a parent chain, `global:`/`local:`, the glob `_*`, no `local: *`) |
| zlib `ztest` probe | gcc, clang | 2 probe | the same; names in the script not defined in the probe must be accepted (GNU ld silent, mold warns, lld refuses: so Clang+lld builds no `libz.so`) |

12 of 19 need nothing but `-shared`; 4 need `-soname` (and
`--dependency-file`, accepted); 3 need `-soname` and `--version-script`.
All four references link every real library and every cross-run passes
(zlib 48/48 runs; Lua 9/9 checks and `attrib.lua`; googletest 797 tests
and a library-thrown exception caught in the executable). libtool-shaped
lines (hand-written: libtool is not installed) add `-version-script`
(one dash), `--whole-archive` of a convenience archive and `-nostdlib`
with explicit crt files; CMake's add `-soname`, `--dependency-file` and
`-rpath`, and link a library by path.

### A.4 What the first package must accept, ranked

Out of 25 real lines (19 survey, 4 libtool-shaped, 2 CMake):

1. `-shared` on the default driver line: 25/25 (21/21 default lines).
   The inputs are an executable's (crt files, `-l` tails, `--as-needed`,
   `--push-state`); the output needs D-100-D-125's core: every
   default-visibility definition exported, C++ vague linkage and
   `STB_GNU_UNIQUE` included; PLT/GOT, `RELATIVE`, symbolic records;
   init/fini; `PT_GNU_EH_FRAME`; RELRO; `DT_NEEDED` with `--as-needed`.
2. Undefined references left to load time (D-118): 10/19 (the Lua
   modules), with `-z defs`/`--no-undefined` refusing them (42 census
   lines).
3. `-soname`: 13/25.
4. `--version-script`/`-version-script`, zlib's subset, undefined names
   accepted as GNU ld does: 4/25 (D-114, script.md §9).
5. `--dependency-file`, `-rpath`: 6/25 and 2/25, already accepted.
6. `--whole-archive`: 1/25.
7. Seen on census lines only, can stay refused in the first package:
   `-Bsymbolic*`, `--dynamic-list`, `--exclude-libs`, `-z nodelete`/
   `initfirst`/`interpose`, `-u`, `-init`/`-fini` with `-shared`
   (`-init`/`-fini` and `-z now` are already supported for executables).
8. Refused by name, never linked: text relocations (i386 non-PIC: GNU ld
   links 14 census lines, W25 crashes), non-PIC 64-bit objects (all
   three refuse), LE TLS (D-119).

**Parallelism.** After S0: S1 and S-V and S3's parser run at once (three
worktrees). After S1: S2, S3, S6 and S7 in parallel; S5 after S2 (it
reuses its shared TLS and IFUNC rules); S4 after S3. The first target's
gate is S1 + S-V; each later package adds its tests to `tests/link/dyn`
with a `Shared` column and must keep every M1/M2 output byte-identical
(a non-shared link pays nothing for `Shared`: the only new per-key
datum is `preemptible`, false outside `Shared`).

**Where the refusal stays.** Until its package lands each item keeps a
named refusal: TLS and IFUNC in `Shared` (S2), `--version-script` and
`.symver` definitions in a shared output (S3), `extern "C++"` patterns
(the demangler), the option tail (S6), i386 `Shared` (S8), `-shared`
with `--incremental` (IN-12 stays: R-N10). Permanently refused, as
designed: text relocations (`-z notext`), LE TLS, every row D-117
refuses, `-Bsymbolic-non-weak*`, `-f`/`-F` filters, `--hash-style=sysv`
and `both`, `--spare-dynamic-tags`, RELR until its own package.

## E. Open questions (each with a recommendation)

- **Q10. A new refusal in executables (D-126 item 2, W30).** A `COPY`
  of data from a library that binds it locally (`DF_SYMBOLIC`, or a
  `NONPREEMPTIBLE` row) gives two instances; every reference links it.
  The refusal touches executables (GCC's x86-64 PIE copies by default,
  D-43). *Recommendation:* refuse (`copy-of-locally-bound-definition`),
  naming the library, the symbol and the remedy (`-fPIC` or the GOT);
  if a real codebase hits it, discuss a warning there, never silence.
- **Q11. Entry of a library (D-101).** layout L-103 writes 0 for every
  `-shared` link; all three references write `&_start` when the library
  defines it. *Recommendation:* the references' (R-L11).
- **Q12. `.symver` definition matched by `local:` (D-114).** GNU ld and
  lld drop `foo@V1` and break old executables; mold keeps it.
  *Recommendation:* keep it with a warning (resolve §9.7 already says
  versioned names are not matched); the alternative is to refuse by
  name, never to drop silently.
- **Q13. Undefined names in a version script.** resolve.md Q6 recommended
  accepting with a warning; GNU ld is silent. zlib's probe prints one
  warning per missing name (22) and links. *Recommendation:* the
  warning, as Q6 (applied: resolve §9.7 rule 9).
- **Q14. Narrower than every reference (D-117).** x86-64 `PC32` call or
  jump to a preemptible key (mold: a PLT entry, correct) and i386
  `R_386_PC32` in data (GNU ld, lld: a record, correct) are refused.
  *Recommendation:* refuse; no compiler emits either in `-fPIC` code, and
  each has a one-line remedy.
- **Q15. `-init`/`-fini` naming an undefined symbol (D-102).** All three
  silently drop both tags. *Recommendation:* refuse in every kind
  (`undefined-init-symbol`), the executables' D-30 rows 3-4 included
  (a request to D-30 when S6 lands).
- **Q16. Version-node name symbols (D-110 item 3).** GNU ld and the
  system's `libz.so` export them; lld and mold do not. Nothing measured
  reads them. *Recommendation:* do not export (the dynamic interface is
  then a function of the script's symbols only).
- **Q17. TLS relaxation in `Shared` (D-119).** None of the references
  relaxes GD to LD or IE in a library; mortar does not either.
  *Recommendation:* none at M4; a later speed package may add GD→LD for
  non-preemptible keys if a benchmark asks.
- **Q18. Four `PT_LOAD`s and `PT_PHDR` (D-100, D-123).** As D-61 for a
  PIE (lld's segments, GNU ld's `PT_PHDR` rule). *Recommendation:* as
  written; one layout for PIE and shared objects.
- **Q19. i386 IFUNC in a shared object (D-130).** Every reference is
  wrong or refuses a form. *Recommendation:* refused by name until a
  package designs it (likely: every address word an `IRELATIVE` to the
  resolved function, as x86.md X86-50's static-pie rule, and calls
  through the `%ebx` IPLT).
- **Q20. `DF_SYMBOLIC` written at all (D-112).** It changes nothing once
  every key is bound at link time, and is wrong with `--dynamic-list`.
  *Recommendation:* write it for plain `-Bsymbolic` (GNU ld's output,
  and D-126 item 2 reads it in other libraries); never with a list.
