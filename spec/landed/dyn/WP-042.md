## What changed

Dynamic output is still refused by name (`crates/mortar/src/dynamic.rs`),
and a row's status never says more than the pipeline does (cli.md §4.2).
So the rows split in two.

## Findings (rule id, proposed text)

- **D-30 row 2 (`-rpath` repeats).** Measured on AArch64 with
  `-rpath /a -rpath /b -rpath /a -rpath /a:/c`: GNU ld and mold write
  `/a:/b:/a:/c`, lld `/a:/b:/a:/a:/c`. GNU ld drops an argument equal to
  one `:`-component already in the path (`ld/lexsup.c`); mold agrees on
  this case. Proposed: "the paths joined by `:` in order, as written
  (`$ORIGIN` kept), except that an argument equal to a `:`-separated
  component already in the path is dropped (GNU ld and mold; lld keeps
  it)". The `Plan` keeps every `-rpath` as written; the composition
  (with `-R DIR`, input §4.8) is DYNAMIC's.
- **R-C1 is silent on nine rows whose status today rests on the
  refusal** (`-rpath-link`, `--no-dynamic-linker`, the five `-Bsymbolic`
  rows, `--no-undefined`, `-z defs`; and it names `-E` but not
  `--no-export-dynamic`, `-rpath` but not the two dtags rows). Proposed:
  add them to R-C1 with the statuses of `AT_JOIN`. Measured for
  `-Bsymbolic` and `-Bsymbolic-functions` in a PIE: GNU ld and mold write
  nothing, lld writes `DF_SYMBOLIC` for `-Bsymbolic`.
- **cli.md §4.2 against the brief.** The spec said WP-042 changes the
  rows "when dynamic output is lifted, WP-053; until then the statuses
  above stand", and the audit cannot evidence a `supported` row whose
  effect the guard hides. Settled by `AT_JOIN`: the true statuses now,
  R-C1's at the join. cli.md §4.2 says so.
- **`-z [no]dynamic-undefined-weak` on AArch64.** The rows belong to x86
  (`targets`), so on AArch64 the command line reports them as an unknown
  option of the target (cli.md §2.9), not as `unsupported option`. GNU
  ld accepts them there with a warning. Both refuse the line and name the
  option; R-C1 is met. If "refused by name" is to read the same on both
  targets, the rows need no targets (a question, not a change).
