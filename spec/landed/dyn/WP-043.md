## 3. Spec findings (proposed text)

- **F1, D-19a.** The roots count as position 0. Proposed: "the options'
  roots (entry, `-u`, `--require-defined`) are mentions at position 0,
  before every file".
- **F2, D-11 rule 2.** The giver of a rule-2 key, and its bind, are taken
  from data definitions only. Proposed: "a common yields only to a shared
  `STT_OBJECT`/`STT_TLS` definition. The yielding key is imported and is
  not allocated (it leaves the common list)."
- **F3, D-19a.** The fallback is computed in one pass over the mentions,
  not iterated. Proposed: "the fallback position of an unmentioned needed
  object is computed once, from the first mentions, in file order".
- **F4, D-16.** The judged mention is the symbol's type
  (`STT_TLS`/other), not the relocation class. This is now written into
  D-16.
- **F5, D-19a.** "Reproduces all 75 cases GNU ld links" is false for
  `under_asn_first_allow`. Proposed: "...all 75 except
  `under_asn_first_allow`, where GNU ld under `--allow-shlib-undefined`
  drops an as-needed object that only an under-linked library uses.
  mortar needs it, so that the image runs."
- **F6, E-usedset.** The deliberate count is 28, not 18, because of
  input §8.3's refusal of a sonameless script-named object. Record it in
  dyn.md's E-usedset paragraph.

## 4. Q1, measured

Measured with GNU ld 2.44, lld 22 and mold 2.37.1, on AArch64 and x86-64,
with `tests/oracle/q1.sh` and `q1-cyclic.sh`. The table and the rule are
in dyn.md D-12 and §15 Q1, and in resolve.md §4.4. In short:
- GNU ld and mold do not extract for an unneeded as-needed object; lld
  does.
- All three extract for a needed object when the archive follows it.
- mortar: the references of a non-as-needed member of C are edges. Those
  of an as-needed member, and of every closure file, are not.
- An as-needed member of N with a strong reference that only an
  unextracted member would define is refused as `archive member needed by
  an --as-needed shared object` (`problem.rs:83`, `tables.rs:1089`).

## 5. RefFlags decision

- `FROM_SHARED`, `DEFINED_SHARED` and `EXPORTED` are kept. They are set
  equal to the columns ref_dynamic, defined_dynamic and exported
  (`tables.rs:914-920`), so a consumer can read either the flag or the
  column.
- `PREEMPTIBLE` is set for every `Def::Shared` key (`tables.rs:924`).
- Not copied: the type and visibility of bind(k). A consumer reads them from the `Def::Shared` entry.

## 6. What DYNSYM, RELOC and DYNAMIC read

- **Resolution:** `exported`, `imported`, `ref_dynamic`,
  `defined_dynamic`; `def[k] = Def::Shared` (bind(k)); `file_live[f] =
  FileLive::Shared{needed, used}`.
- **SymProps:** `version` (bind(k)'s VerIndex, D-27); `refs`
  (`PREEMPTIBLE`, `FROM_SHARED`, `DEFINED_SHARED`, `EXPORTED`); and the
  visibility, protected, IFUNC and TLS facts of bind(k).
- **Outcome:** `needed` (`Slots.needed`, D-19a), and `closure_only` for
  the scan's note on `undefined-symbol` (`tables.rs:1317`).

## 7. Interface requests

- **mortar_core `SonameUnit`:** per-mention state, for example
  `states: Box<[SonameMention { opened: u32, as_needed: bool, group:
  Option<GroupOrdinal> }]>`. Today `shared_link` (`tables.rs:705`) infers
  each mention's `as_needed` and group from the plan. Where that is
  ambiguous it refuses by name (`NeededOrderUnknown`, `problem.rs:88`).
- **mortar_scan:** read `Outcome.closure_only` to add the D-12 note
  `defined in <file>, which is not on the command line`. It is computed,
  but no consumer reads it yet.
- **DYNSYM (WP-053):** a way to tell a versioned export (a definition
  with `@@`) from the plain one, for D-27 on exports. Resolution keeps
  only bind(k)'s index for imports.
