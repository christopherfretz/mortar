## 2. `--export-dynamic-symbol=GLOB` matched a literal name

`resolve.md` §4.2 says each key matching the glob is exported. mortar
interned the value as a key name: `--export-dynamic-symbol=exp_d*`
exported nothing and said nothing (a silent non-export: `dlsym` finds
nothing). Measured: GNU ld, lld and mold export `exp_data` for `exp_d*`
in a PIE and in `-no-pie`.

- Rule (resolve.md §4.2, rewritten): each unversioned key whose name
  matches the glob, among the keys some file mentions; `*`, `?`,
  `[set]` with ranges and `!`/`^` negation, `\` quotes; a `[` without
  `]` is literal (fnmatch(3)); a value without a wildcard names its key.
- Code: `mortar_resolve` `options.rs` `is_glob`, `glob_match` (unit
  test `globs`); `tables.rs` `shared_link` adds the keys a glob matches.
- Test: `tests/link/dyn/dynsym/export-dynamic-symbol.test` (PIE and
  `-no-pie`, by name and by glob; `dlsym(RTLD_DEFAULT)` finds exactly the
  exported ones, `.dynsym` has them and not `other_fn`). All four
  linkers pass; mortar failed it before the fix (`exp_data found 0`).
- References' differences: none measured.

## 3. The three items from other packages

### 3.1 `--export-dynamic` and `--export-dynamic-symbol` in a static-pie

Measured (glibc 2.41; AArch64 native, x86-64 under qemu; a static-pie
defining `exe_value` that `dlopen`s a library referencing it, and calls
`dlsym(RTLD_DEFAULT, "exe_value")`):

- GNU ld, lld and mold all write the exports into `.dynsym` (several
  hundred entries with `--export-dynamic`; the one name with
  `--export-dynamic-symbol`). GNU ld's x86-64 static-pie with
  `--export-dynamic` dies by SIGSEGV at start-up.
- With every reference's exporting output, the library's `dlopen` fails
  (`undefined symbol: exe_value`) and `dlsym` returns null: glibc's
  static `dlopen` does not search the static program's `.dynsym`. The
  exports are useless.

The rule this supports: accepted, no effect (`.dynsym` stays the null
entry, as P-D14 requires). For `--export-dynamic-symbol` that is
mortar's behaviour already (tested: `spie-s` in
`tests/link/dyn/spie/export-dynamic-refused.test`, by name and by glob,
one `.dynsym` entry, verifier clean). For `--export-dynamic` I made the
change and the verifier refused to judge the output: `mortar_plumb`
`line.rs:289` puts "static-pie with --export-dynamic (dyn.md D-1; M4)"
outside stage 3, and a mortar output outside stage 3 fails its test.
The verifier is not mine, so the refusal stays (the census's 14
`x-static-pie-export` lines are out of M2 by D-1), and the rule is
finding F2 (§5). The test's comment records the measurement.

### 3.2 The two x86-64 `.got` slots of a C++ static-pie nothing reads

(WP-052 §6.1.) They come from `R_X86_64_REX_GOTPCRELX` in
`libstdc++.a`: against `_ZTVSt8bad_cast` (`bad_cast.o`,
`eh_aux_runtime.o`, `functexcept.o`) and
`_ZNSt8time_put...2idE` (`locale-inst.o`, `locale_init.o`,
`localename.o`). Every use is relaxed to `lea`, so no instruction loads
the slot; the slot is allocated anyway because x64.md X-19 says the GOT
slot of a relaxed GOTPCRELX "exists in every case (kind 2)". The same
two unread slots are in the plain static output (`-static`: slots at
0x5b5620 and 0x5b6268; static-pie: 0x1d84b8 and 0x1d9100), and no
instruction of either output mentions them.

Outcome: no change. Dropping them changes static bytes (the brief
forbids it) and contradicts X-19. Finding F3 (§5) proposes the rule for a
later package.

### 3.3 D-25's writable place is the OUTPUT section's

The code judged the input section's `SHF_WRITE` (conservative: a
refusal where the spec allows a record; WP-083 finding 39). Now:

- `mortar_scan` `driver.rs` `Sec::open` (about line 355): a place is
  writable when its output section has `SHF_WRITE`, from the section
  mapping (`Opts::sections`, known before addresses); without a mapping
  (a static link) the input section's flag, as before. `weak.rs` (about
  line 264) reads the place instead of re-deriving it.
- `mortar_image` `link.rs` `LinkTables::section_writable` (about line
  729): the output section's flags (`zeroed_place`, D-46); it only acts
  for `Shlib` and `WeakDyn` kinds, so no static byte moves.
- Test: `tests/link/dyn/reloc/writable-place-output.test`. A read-only
  input `.rodata.roin` and a writable input `.rodata.rwin` in one output
  `.rodata` (L-50: the output is writable), each with an absolute word
  to the shared `shared_datum` and to the undefined weak `hook`; both
  input orders, PIE and `-no-pie`; with and without `LD_PRELOAD` of a
  library defining `hook`; the output `.rodata` is `WA`, two `ABS64` /
  `R_X86_64_64` records for each key. The read-only input alone keeps
  the PIE refused (D-47, text relocation) and links `-no-pie` (copy,
  `Weak0`). Before the fix mortar refused every link with the read-only
  input.
- References: GNU ld and mold judge the output section too. GNU ld puts
  the writable `.rodata` in an RWX segment without `PT_GNU_RELRO`
  (verifier P-D4: `xfail(bfd)`); mold writes `DT_TEXTREL` (A24). lld
  judges the input section and refuses the PIEs (`xfail(lld)`). Rows in
  `dyn.md` §13.1; the D-25 text says it.

## 5. Findings

- **F1 (verifier; for WP-091 or the verifier's owner).** P-D11 under
  `-z norelro`. `g++` x86-64, `-Wl,-z,norelro`: mortar puts the copy of
  `_ZTISt13runtime_error` in `.bss.rel.ro`, as D-42 says for a copy of a
  read-only datum (under `-z norelro` that section is an ordinary
  writable one). `crates/mortar_plumb/src/dyncheck.rs` (about lines
  1088-1104) compares the copy's read-only-ness with the PT_GNU_RELRO
  ranges and, there being none, reports "the copy ... is outside
  RELRO". P-D11's text asks for the copy to be "inside `.bss.rel.ro`",
  which it is. Suspected verifier defect (not a byte comparison: the
  output follows D-42 by its section map). Reproduce: `cargo xtask census
  --filter gcc/x86_64/c++.x-norelro --keep`; the lane lists it in
  `KNOWN_FINDINGS`. Proposed: P-D11 checks RELRO membership only when the
  output has a `PT_GNU_RELRO`.
- **F2 (dyn.md D-1; verifier line.rs:289).** Proposed text for D-1:
  "`--export-dynamic` and `--export-dynamic-symbol` are accepted in a
  `StaticPie` and have no effect: its `.dynsym` is the null entry
  (P-D14). Measured (WP-056): every reference writes the exports, and
  none of them is usable (glibc's static `dlopen` does not bind a library
  to the program's symbols; `dlsym(RTLD_DEFAULT)` does not find them)."
  With it, the verifier drops the outside-stage-3 line for a static-pie
  with `--export-dynamic`, and mortar removes its refusal (the code is
  four lines in `crates/mortar/src/dynlink.rs` `kind_and_interp`).
- **F3 (x64.md X-19).** Proposed: "a GOTPCRELX use that is relaxed needs
  no slot; the slot is allocated only when some use of the key is not
  relaxed, decided at scan". An optimisation that changes static outputs
  (two 8-byte slots in a C++ static link): a later package with a new
  static baseline.
- **F4 (reference).** GNU ld 2.44's x86-64 static-pie with
  `--export-dynamic` dies by SIGSEGV at start-up (`dyn.md` §13.1).
