## 3. `SharedFacts`

Read from the program headers and `.dynamic` only. `flags`, `flags_1`
and `DT_SYMBOLIC` are the last entry of their tag (glibc's reading);
`loads` every `PT_LOAD` in table order; `relro` the last `PT_GNU_RELRO`;
`mason_note` the descriptor of the first `MasonMeta`/`NT_MASON_ODR` note
in any `PT_NOTE`, unparsed. No new refusal: the table is located by
`SharedObject::parse`, whose out-of-bounds error is the existing
malformed-file problem (test `d43a_truncated_program_headers_are_malformed`:
`e_phoff` past the end, and a file cut inside the table); a `PT_NOTE`
whose notes do not parse is passed over, as `mortar_meta::table::find`
passes over a section.

Cost: no new bytes are read. A shared object is `Shape::Other` in the
staged store and is resident whole in both stores (`staged.rs`), so the
reader walks a table already in memory (typically 7-11 entries of 56
bytes, and the notes of one or two `PT_NOTE`s); no bench number moves
by a measurable amount.

**Reach (for WP-122).** `SharedFacts` lives in `mortar_input`; the walk
copies only `soname`, `versions` and `globals` into the core
`inputs::File` row (which is `Copy`), and `mortar_scan` does not depend
on `mortar_input`. So the new fields do not reach `scan/copies.rs` as
the tree stands. Carrying them (a side table in `mortar_core::inputs`
filled by `walk.rs`) is a change to `mortar_core/src/inputs.rs` and
`mortar_input/src/walk.rs`, files no parallel package owns; WP-122 needs
either that or a re-read from `Reader::Shared(SharedObject)` through
`mortar_elf` (scan depends on it). Left for the supervisor's brief.

## 4. `OutputKind` matches

`map::OutputKind` is the only new variant; it has one match (`token`),
given its `Shared` arm. `plan::OutputKind::Shared` and
`mortar_arch::OutputKind::Shared` existed before WP-116 (the CLI parses
`-shared` and then refuses the link), so every match on them is already
total and none was touched; among them `mortar_image/src/link.rs`'s
`e_type` maps `Shared` to `ET_DYN`, and `crates/mortar/src/dynlink.rs`
`kind_and_interp` refuses it by name (`refused("this output kind with
.dynamic")`). `mortar_plumb`'s map `OutputKind` is WP-121's.
`DynKind` (synth) is WP-118's and was not changed. The CLI refuses
`-shared`, so no `Shared` plan reaches any of them today.
