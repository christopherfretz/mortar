# WP-128: the option tail of `-shared`

The options the record `spec/landed/dyn/WP-110.md` §D gives WP-128 (cli.md
§4.2's M4 block): the D-103 `-z` flags, `-Bsymbolic`, `--dynamic-list`,
`--exclude-libs`, `-init`/`-fini` in a `Shared` link. `--whole-archive`
moved to WP-152. `SHARED_LATER` (`crates/mortar_cli/src/rows.rs`) is
empty: no option of a `Shared` line waits for a later package.

References: GNU ld 2.44, lld 19.1.7, mold 2.37.1, AArch64 natively and
x86-64 under qemu; the probes were in `.build/target-wp-141/wp128/`
(`m1` flags, `m4` exclude-libs, `m5` `-init`, `m6` dynamic list; not
committed: the results are here and in the spec sentences).

## 2. Measured, and where the spec sides

**D-103 in an executable** (`-pie`, `-no-pie`, `-static-pie`; AArch64 and
x86-64):

| keyword | GNU ld | lld | mold | mortar |
|---|---|---|---|---|
| `nodelete`, `nodlopen`, `initfirst` | dropped (`-no-pie`: an empty `DT_FLAGS_1`) | written | written | refused by name |
| `interpose`, `origin` | written | written | written | refused by name |
| any, `-static` | nothing | nothing | nothing | refused by name |

In `Shared` the three agree with D-103's table, the tags in GNU ld's
order (mortar's equal GNU ld's with `-soname` and `-Bsymbolic`).

**`-Bsymbolic`.** Under an interposer the library's own uses stay its own
and the host's calls reach the interposer (all four); a PIE host sees
the library's address for the library's function (1), a `-no-pie` host
its PLT entry (0). GNU ld still names the IFUNC (`JUMP_SLOT`) and the TLS
variable (`TLSDESC`; x86-64 `DTPMOD64`/`DTPOFF64`); lld names the TLS
variable in its x86-64 `DTPMOD64`; mortar names none (D-112 sentence
added).

**`--dynamic-list`.**

| shape | GNU ld | lld | mold | mortar |
|---|---|---|---|---|
| two `--dynamic-list` files | one list (union) | union | union | union |
| quoted entry, glob | listed | listed | listed | listed |
| `extern "C++"` block | accepted | accepted | accepted | refused by name (`script-command`) |
| `Shared`: export set | unchanged | unchanged | unchanged | unchanged |
| `Shared`: unlisted TLS, IFUNC | preemptible | bound (x86-64 TLS half, W43) | bound | bound |
| executable: listed definitions | exported | exported | exported | exported |
| executable: a listed archive member nobody needs | not extracted | not extracted | not extracted | not extracted |
| executable `--gc-sections`: a listed definition in an unreferenced section | kept | kept | kept | kept |
| executable: a listed definition `--exclude-libs` excludes | not exported | not exported | not exported | not exported |
| `-static-pie` | exports | exports | exports | no effect (D-1) |

**`--exclude-libs`.** The entry is the archive's base name, however found;
`,` and `:` separate; `ALL` exactly; a path or `all` names nothing (all
three). The exclusion wins over a version script's `global:`. In an
executable it removes `-E`, `--export-dynamic-symbol`, `--dynamic-list`
and D-21's exports; a shared input's reference to an excluded
definition: GNU ld and lld refuse, mold links a program the loader
cannot start, mortar refuses (`non-exported symbol referenced by a
shared object`). `.symtab`: GNU ld and lld `LOCAL DEFAULT`, mold `LOCAL
HIDDEN`, mortar `GLOBAL` (WP-150's question).

| entry `libfoo` for `libfoo.a` | GNU ld | lld | mold | mortar |
|---|---|---|---|---|
| | matches | nothing | nothing | refused by name (`invalid-option-value`; the row `partial`) |

**`-init`/`-fini`** (`Shared` and executables): a local symbol, a symbol
of a shared input only, an archive member nothing else extracts: all
three omit the tag (`-init` extracts nothing); mortar
`undefined-init-symbol`. A data object: all three write its address
(the loader calls it: a crash); mortar refuses by name. Under
`--gc-sections` GNU ld and lld keep the function (hidden too), mold
collects a hidden one (W22). Before WP-128 mortar collected it in an
executable under `--gc-sections` and stopped on an internal error
(".dynamic names symbol ..."): fixed by the roots.

`--export-dynamic-symbol-list` reads the dynamic-list grammar in the
three (not a list of globs): left to WP-153.

## 4. For the verifier package

The option mirror (`crates/mortar_plumb/src/opts.rs`) needs the moved
rows: `-Bsymbolic` (noop to supported), `--dynamic-list` (refused to
supported), `--exclude-libs` (refused to partial), `-z initfirst`,
`-z interpose`, `-z nodelete`, `-z nodlopen`, `-z origin` (refused to
supported, `Shared` only). Until then the new link tests are
`xfail(mortar)` on M9. What a rule must derive from the command line:

- P-D6/P-D22: `-z origin` sets `DF_ORIGIN` in `DT_FLAGS` (P-D6 reports
  "DT_FLAGS 0x1 has bits 0x1" today) and `DF_1_ORIGIN`; the other four
  their `DF_1_*` bit; only in `Shared`.
- P-D19 (exports), every kind: an archive member's definitions are not
  exported when `--exclude-libs` names the archive (its base name;
  `ALL`; `,`/`:` separators), whatever `-E`, `--export-dynamic-symbol`,
  `--dynamic-list`, a version script's `global:` or a shared input's
  definition say; in an executable `--dynamic-list`'s listed
  definitions are exported (by name without version, glob, quoted
  exact; several files one list); nothing in a static-pie.
- P-D17 view B, P-D25: with a `--dynamic-list` the list alone decides
  preemption in `Shared` (listed preemptible, every unlisted key bound,
  whatever `-Bsymbolic` form; P-D22: no `DT_SYMBOLIC`/`DF_SYMBOLIC`).
- Y3: an excluded (and a version-local) definition may be `LOCAL` in
  `.symtab` (the references); mortar keeps `GLOBAL` (WP-150).
- P-D22: `DT_INIT`/`DT_FINI` of an explicit `-init`/`-fini` point at
  code; the key is a root of `--gc-sections`.

The verifier already judges a `--dynamic-list` line's preemption (P-D17
view B reports lld's W43 library: "expected: the library's own
(bound)"); mortar's lines meet M9 only.

The byte sweep (`cargo xtask plumb <out> --map <map> --map-format mortar
--sweep`, AArch64; the lane has no `Shared` case) of a library with the
five `-z` flags, `-Bsymbolic`, `-soname`, `-init`, `-fini`, and of one
with `--dynamic-list` and `--exclude-libs ALL`: survivors the new shapes
add are `DT_SYMBOLIC`'s `d_val` (written 0, any value survives) and
`DT_FLAGS`'s `DF_ORIGIN` bit (P-D6). The other survivors are the plain
`-shared` library's too (the same library linked without an option):
`.dynsym` `st_other` bit 7 of the exports, `.gnu.version` entries of the
exports, two `.got` words of the TLS descriptor (`TlsDesc` word 6, word
7 without a record), and `.plt` padding (equivalent).
