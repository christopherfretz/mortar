# WP-117: `Shared` front, resolve and scan (AArch64)

The command line, resolution and scan of a shared object (record
`spec/landed/dyn/WP-110.md` §D row WP-117). `-shared` itself stays
refused until WP-123 joins this package with WP-118's synth and image:
`kind_and_interp` still refuses `Shared` by name, so no user line reaches
the new code yet, and every existing output is byte-identical. Tests
are crate-level, on objects compiled by the test, plus link tests of the
refusals.

Decisions (the record's reading):

- `-shared` stays `refused` (§G.4: "until then `-shared` stays
  `refused`"): `front.rs`'s `arch_status` gives M1 for `Shared` and
  would write a static-path image.
- No `noop`/`refused` to `supported` flip of `-soname`,
  `-Bsymbolic-functions`, `-Bno-symbolic`, `-z defs`, `--no-undefined`,
  `--allow-shlib-undefined`, `--no-allow-shlib-undefined`: their
  `Shared` effect is observable only when `-shared` links, `-soname` in
  an executable would drop `DT_SONAME` silently, and the audit
  (`crates/mortar/tests/options.rs`) needs evidence from outside these
  files. WP-123 flips them with their help texts.
- `Lands::last_wins` does not take the `-Bsymbolic` field: a refused
  `-Bsymbolic` stays refused under a later `-Bsymbolic-functions`
  (otherwise the refused word would reach the verifier's reader).
- `options.md` does not show the `SHARED_LATER` notes of rows that are
  `supported` elsewhere (`-init`, `-fini`): that needs `text.rs`.

The diagnostic of a bound use is GNU ld's (`relocation R against symbol
`def' which may bind externally …; recompile with -fPIC`) naming the
definition, at the relocation's place, with a note naming the address
(`.data+0x8`). A boundary use's note names `-fdata-sections`.

**The hook for WP-119** (`bound.rs:243`):

```rust
pub(crate) struct Judged { pub section: u32, pub addr: u64, pub access: bool, pub record: u32, pub note: String }
pub(crate) fn analysis(view: &View<'_, '_>, file: FileId, facts: &FileFacts, section: u32) -> Vec<Judged>
```

Called once per code section of a file with facts (on the walk of its
first block, `driver.rs:793`). It returns every address the analysis
judged (D-117 item 6: `addr` an input offset in the object's section
`section`, `access` per item 6, `record` the index in the code section's
relocation table of the relocation that formed the address, `note` naming
the function and the instruction's offset). Each is passed to
`judge(facts, section, addr, access)`: the interval and boundary rule
apply there, the same as for the rule. WP-123 replaces the body with the
call into `crate::regflow`. Today it returns nothing.

## 5. Measurements (record §D's row)

`.build/target-wp-117/measure/run.sh`: `exp3/s1d.py --hits` over 456
AArch64 objects: `exp3/hod`'s units and `sup/c.c` through kiln
(`-fkiln-backend=hod`: 36 objects at `-O0`; llc: 108 at `-O1`-`-O3`),
Clang 19, GCC 14, gfortran 14 (`m.f90`, `l.f90`); each `-O0`-`-O3` ×
`-fPIE`/`-fPIC`/`-fno-pic`. Objects refused (by the rule; by the
analysis only):

| compiler | `-fPIC` | `-fPIE` | `-fno-pic` |
|---|---|---|---|
| Clang 19 (48 each) | 0; 1 | 9; 2 | 13; 2 |
| GCC 14 (48 each) | 1; 0 | 20; 6 | 21; 6 |
| gfortran 14 (8 each) | 0; 0 | 6; 0 | 6; 0 |
| kiln + hod/llc (48 each) | 0; 1 | 14; 1 | 18; 1 |

The gfortran `-fPIE` refusals are module variables reached through the
`.data` anchor: true detections. The `-fPIC` hits are only `c.c` at
`-O0`: GCC by the rule (2 uses, `.data+8`, `gvar`), Clang 19 and
kiln+hod `-O0` by the analysis (`f+0x18`/`f+0x24`, `.data+0x10`,
`gcount`: WP-119's). Interior address-valued uses in self-GOT objects
at `-O0`: these 3 objects, no other.

D-100: `-shared -dynamic-linker`: GNU ld and lld write no `PT_INTERP`,
mold writes one; the spec's reading stands. AArch64
`NEEDED_INDIRECT_EXTERN_ACCESS`: GCC 14 and Clang 19 reject
`-mno-direct-extern-access` on AArch64 and GNU ld 2.44 ignores
`-z indirect-extern-access` there; no AArch64 producer writes the
property (keeping it is synth's, nothing to do here).

## 7. Not verified

- No `-shared` link runs end to end (WP-123): the resolution and scan
  are tested at crate level only; the verifier (WP-121) has not seen a
  `Shared` output of mortar.
- x86-64 and i386 `Shared` are refused before the scan (`front.rs`);
  the class cells are generic and give `non-pic-in-shared-object` there
  too, but D-117's x86 scope is WP-127's and WP-130's.
- An exported TLS or IFUNC definition that no relocation of a live
  object references is not refused by the scan (`shared_feature` judges
  relocations); WP-123's front or WP-124 must refuse such a definition
  if WP-124 has not landed.
- `apply.rs` (fill, not this package) writes the place of a symbolic
  `ABS64` as 0 only for `Exec`/`Pie` (`symbolic_place`): in `Shared` it
  must also cover `Preemptible`, `Shlib` and `WeakDyn` (WP-118/123).
- The `non-pic-in-shared-object` render always says "against symbol
  `x' which may bind externally"; GNU ld's `Local`-target wording
  (``relocation R_X86_64_32 against `.rodata' can not be used…``) needs a
  render variant (`mortar_diag`).
