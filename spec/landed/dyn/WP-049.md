# WP-049: the layout of dynamic executables (WP-M2-LAYOUT)

Record of WP-049. Scope: `spec/dyn.md` §9 D-60..D-62, §4 D-1/D-2, D-33,
D-42, D-49, requests R-L1..R-L3; `spec/layout.md` L-60, L-64, L-67,
L-68, L-80. The dynamic guard (`crates/mortar/src/dynamic.rs`) still
refuses every dynamic link, so nothing here is reachable from the
command line until the joins (WP-053, WP-055); it is tested alone,
against the spec's table, against lld and GNU ld, and on GNU ld images
laid out in D-60's order. Static links are byte-identical
(`cargo xtask static-identical`: 167 links, 0 differ).

## 1. The placement table as implemented

`mortar_layout::rank` (`NAMED`, `rank_in`); `(rank, within)`; `Z` is
`-z now` / `-z relro`.

| rank | class | sections, in order |
|---|---|---|
| 0 | R | file header, program headers |
| 1 | R | `.interp` (synthetic only; an input `.interp` is refused, L-39) |
| 2 | R | `.note.gnu.property`, `.note.gnu.build-id`, `.note.ABI-tag`, other notes |
| 3 | R | `.gnu.hash` (3,0), `.dynsym` (3,1), `.dynstr` (3,2), `.gnu.version` (3,3), `.gnu.version_d` (3,4), `.gnu.version_r` (3,5) |
| 4 | R | `.rela.dyn`/`.rel.dyn` (4,0), `.relr.dyn` (4,1), `.rela.plt`/`.rel.plt` (4,2) |
| 5 | R | `.rodata`, orphans, `.gcc_except_table`, `.eh_frame_hdr`, `.eh_frame` |
| 6 | RX | `.init`, `.plt`/`.iplt`, `.text`, `.fini` |
| 7 | RELRO | `.tdata`, `.tbss`, `.preinit_array`, `.init_array`, `.fini_array`, `.data.rel.ro`, `.dynamic` (7,8), `.got` (7,9), `.got.plt` under `-z now` (7,10), `.bss.rel.ro` (7,11: the copy chunk first, then input `.bss.rel.ro`), `.relro_padding` |
| 8 | RW | `.got.plt` lazy (8,0), `.data`, `.tm_clone_table`, `.bss` (8,4: the copy chunk `.dynbss` first), `.bss.rel.ro` under `-z norelro` (8,5) |

- `.dynbss` joins the output section `.bss` (`rank::home`); `.dynbss`
  and `.bss.rel.ro` lead their section (`rank::leads`: stage C key
  `(out, 0, 0)`; bodies start at sub 1). A leading copy chunk carries
  the largest alignment of its section's chunks (L-5: the section's
  `sh_addr` is its address).
- Copy allocations (D-42): `chunk::copy_rows` / `copy_extent` order
  each chunk's allocations by (least alias, index) and place them at the
  aligned prefix sum; the chunk's size must equal the extent (an
  internal error otherwise: the caller sizes the `SynthChunk`).
  `sym_place` rows `AllocKey::Copy(i)`, sorted by key.
- Program headers (`derive_segments`, D-61): `PT_PHDR` (`PF_R`, word
  alignment, the header table) and `PT_INTERP` (`PF_R`, alignment 1)
  first, exactly when a synthetic `.interp` exists; the `PT_LOAD`s;
  `PT_DYNAMIC` (`PF_R|PF_W`, word) over `.dynamic`; then `PT_NOTE`,
  `PT_TLS`, `PT_GNU_PROPERTY`, `PT_GNU_EH_FRAME`, `PT_GNU_STACK`,
  `PT_GNU_RELRO` as in M1. Four `PT_LOAD`s R, RX, RW (RELRO), RW; three
  under `-z norelro`.
- Base (D-1, L-68): `Options.pie` gives base 0; `Exec` keeps the static
  base (0x400000). `SegmentRules.pie` carries it to `Layout::check`.
- `Options::from_plan`: `Executable` → not pie, `PieExecutable` → pie;
  either on ELFCLASS32 is refused, `feature` "ELFCLASS32 dynamic
  executable"; `StaticPie` stays refused ("position-independent
  executable output") for WP-M2-SPIE.
- `_DYNAMIC` (§13.1): the start of `.dynamic`.
- `e_type` per kind was already written by `mortar_image` from
  `LinkOptions.output` (`link.rs`); nothing changed there.

## 2. New `Layout::check` rules (`mortar_core/src/check.rs`)

Rule `Segments` unless stated:

1. base 0 exactly when `segment_rules.pie` ("a position-independent
   output at base …, not 0" / "a position-dependent output at base 0");
2. `.interp` directly after the program headers;
3. `.dynamic` is `SHF_WRITE` (D-33), and inside the RELRO run when one
   exists;
4. a copy row lies in the synthetic chunk its `CopyPlace` names
   (`.dynbss` / `.bss.rel.ro`);
5. a copy row's alignment is its allocation's (power of two, row align =
   log2) and at most the chunk's (offset and extent: the existing §4.4
   `Places` rules);
6. copy rows of one chunk do not overlap and are in least-alias order;
7. a copy chunk is the first chunk of its section, and at least as
   aligned as every chunk of it (L-5).

`derive_segments` (`Layout::check` rule 3) now derives `PT_PHDR`,
`PT_INTERP`, `PT_DYNAMIC`, so a stored table without them, or with them
elsewhere, is rejected.

## 3. Oracles

- `mortar_layout/tests/dynamic.rs` `d60_d61_table`: a fixture with every
  dynamic table as a synthetic chunk and three copy allocations, {Exec,
  Pie} × lazy/now × relro/norelro + an interpreter-less PIE, AArch64 and
  x86-64: 18 cases. Section order = D-60, phdr types and order = D-61,
  PT_LOAD flags, base, `p_offset ≡ p_vaddr (mod p_align)`, `p_align` =
  maxpage, PT_PHDR/INTERP/DYNAMIC extents, RELRO end on maxpage, RELRO
  membership (`.got.plt` iff now), copy offsets, `.dynbss` first in and
  aligned as `.bss`, `_DYNAMIC`, `Layout::check` with the copy slots,
  and the file-only [G] checker on a skeleton. All pass.
- `d62_again` (placing again from the previous placement is the same
  placement), `d42_copy_chunk_size`, `l5_dynbss_aligned_as_bss`,
  `input_interp_refused`; `target.rs` `d1_kinds`; core
  `d42_copy_placement`, `d1_pie_base`.
- `d60_d61_against_references`: E-dynamic's copy program (typeinfo and
  `environ` copies) linked by lld and GNU ld, {Exec, Pie} × lazy/now ×
  relro/norelro × {AArch64, x86-64} = 32 links. Each output becomes a
  mortar layout input (linker-made sections synthetic) and every
  allocated section's class (R/RX/RELRO/RW) is compared by name. lld: 16
  of 16 equal, PT_LOAD counts equal. GNU ld: 16 of 16 have D-61's
  program header order (runs collapsed); 108 stated class differences,
  all of two kinds: (a) AArch64, GNU's R sections are in its RX PT_LOAD
  (104); (b) lazy, GNU's RELRO covers the 24-byte head of `.got.plt`
  (`DATA_SEGMENT_RELRO_END(24, .)`; 4).
- D-60 proof images (scratch, AArch64 native): GNU ld with a script in
  D-60's order and D-61's `PHDRS` (`.relro_padding` a NOLOAD section to
  maxpage; GNU ld writes `PT_GNU_RELRO` as `PT_NULL` without
  `DATA_SEGMENT_RELRO_END`, so that entry was patched to `PT_GNU_RELRO`
  over the third PT_LOAD), PIE/-no-pie × now/lazy: all four run (exit
  0), the loader maps the RELRO page `r--p`, `eu-elflint --gnu-ld`
  reports only `.relro_padding` (NOBITS/WA, D-71's allow-listed
  complaint), gdb and lldb stop at `main` and list libc.

Rows no reference backs: the whole order (no reference has it, WP-051
§4 item 14; the proof images above back it); `.bss.rel.ro` under
`-z norelro` after `.bss` is lld's place (measured), GNU ld has no
`.bss.rel.ro`; `.dynbss` first in `.bss` is GNU ld's (its default
script), lld has no `.dynbss`; the RELRO end on a 64 KiB-page kernel
(none available). The copy chunks themselves are not in the proof
images (GNU ld cannot make `.bss.rel.ro`).

## 4. Spec findings (rule id, proposed text)

1. **D-42 / L-80 (`-z norelro`)**: "placed as an ordinary writable
   section" is not a place. Proposed: "Under `-z norelro` the chunk
   `.bss.rel.ro` is ranked (8, after `.bss`) as a writable `NOBITS`
   section: L-69 forbids it among the writable `PROGBITS`; lld's place."
2. **D-61**: "GNU ld's `-z separate-code` default differs on x86" also
   needs "GNU ld writes two `PT_LOAD`s on AArch64 (RX with the read-only
   data, RW)". Measured again here (16 GNU ld links).
3. **D-60 / D-33**: GNU ld's lazy RELRO covers `.got.plt`'s three
   reserved words; mortar's (and lld's) does not. Add to §13.1: "lazy
   `.got.plt` head in RELRO: GNU ld yes, lld/mold/mortar no".
4. **L-5 / D-42**: a leading copy chunk takes its section's largest
   alignment (else `.bss`'s `sh_addr` is misaligned when an input `.bss`
   is more aligned than the copies). Proposed for L-80: "`.dynbss` is
   aligned to the alignment of the output section `.bss`".
5. **layout.md §10 rank table**: `.dynbss` with no `.bss` output section
   is an output section of its own named `.dynbss`; state it ("else an
   output section `.dynbss` at `.bss`'s rank").

## 5. Requests (interface)

1. `mortar_core::layout::CopyAlloc` has no size: layout takes
   `chunk::CopyRow { index, place, size, align (log2), first }` beside
   `Slots` (`place_with_copies(link, copies: &[CopyRow], …)`,
   `chunk::copy_rows(slots, size: impl Fn(u32, &CopyAlloc) -> u64)`).
   Request: `CopyAlloc.size: u64` (D-42 "size"), so `copy_rows` reads it.
2. JOIN (front.rs): call `place_with_copies` with `copy_rows`; give
   `SynthChunk`s `.dynbss` / `.bss.rel.ro` the size and alignment of
   `copy_extent` (`synth_chunks` front.rs:996 is `unreachable!` for the
   kinds without a header); `placed_names` (front.rs:1050) names a
   section after its lowest `ChunkId`, which is `.dynbss` for `.bss`:
   name a joined synthetic by `Staged.out_of`'s output section.
3. SPIE: lift the `StaticPie` refusal in `Options::from_plan`
   (`target.rs`, `pie: true`), and give it no `.interp` (no PT_PHDR or
   PT_INTERP follow, tested).
