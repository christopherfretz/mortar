## The pinned refusals (0e)

`crates/mortar/tests/refusals.rs`
`the_dynamic_gates_keep_their_refusals` pins the text a user saw before
0e and still sees, for the census's ranked gates (dyn.md §2.7).

- **Each gate alone**, which gives two lines:
  - `mortar: error: unsupported option: -pie` (or `-dynamic-linker`, or
    `-Bdynamic`);
  - `mortar: error: unsupported feature: linking`, with its note
    `>>> an option above is refused, so nothing is linked
    (docs/status/options.md)`.
- **Together with a refusal that is not a gate**: each gate once, at its
  first use (`--dynamic-linker` before the later `-dynamic-linker`), in
  argument order among the other refusals. Here the other refusal is
  `--build-id=md5`.

The option table still marks the gates `refused`, so `--help` and
`docs/status/options.md` do not change. `dynamic::option_refusals` takes
the gates out of the command line's refused uses, and `dynamic_guard`
reports them through the same constructor (`mortar_cli::Use::refusal`).
At the join, `DYNAMIC_OUTPUT` and the table rows change together.

## Findings (rule id, proposed text)

- **D-46 against D-49** (JUMP_SLOT place content). D-46 said a RELA
  `JUMP_SLOT` place holds 0, and D-49 said it holds the lazy target.
  WP-040r settles it as the lazy target. `DynRole::place` already
  follows that ruling.
- **S-69 / Q7 (measured).** GNU ld 2.44 writes the start of `.plt`, not
  the resolver, into an AArch64 static IPLT word, with the resolver in
  `r_addend`. Q7's ruling (`S + A`) is what the verifier accepts, and
  `IRELATIVE` overwrites the word at start-up either way.
- **layout L-101 (no change to the rule).** The baseline caught main's
  31175df, which brought mortar in line with L-101 on AArch64.
  `docs/status/m2.md` records it.
- **input §8.4 / D-31.** WP-040 §1 counts "dynamic executable without
  -dynamic-linker" among the refusals the join lifts. D-31 keeps it at
  M2, because there is no default interpreter. The record should say
  that this refusal stays.
