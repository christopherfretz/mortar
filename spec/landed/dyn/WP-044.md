## Oracles (`crates/mortar_synth/tests/dynsym.rs`)

- **Rows**: one fixture holding every D-23 row (import, weak import,
  IFUNC import, TLS import, canonical PLT, copy and two by-value aliases,
  protected export, unique export, IFUNC export at its IPLT entry, ABS
  export, WeakDyn). Each is checked field by field on AArch64 and x86-64.
  The fixture also has a local key, a Weak0 key and a non-alias shared
  datum, which are checked to be absent.
- **Refusals**: `versioned-export`, an exported IFUNC that no relocation
  names, a versioned import bound in an object that is not needed, and
  ELF32. The internal errors are a hidden export, `_DYNAMIC` exported, a
  strong undefined key, and a WeakDyn key with a shared definition.
- **Determinism**: `check_schedules` over the whole output, and sets
  built in reverse give the same tables.
- **glibc's lookup**: a port of `do_lookup_x`'s GNU path (Bloom, bucket,
  chain, `check_match`'s value-0 rule). Every hashed name is found at its
  index; imports (value 0) and 200 absent names are not found. Sizes: 0,
  1, 2, 3, 2^k − 1, 2^k and 2^k + 1 for k = 2..16, and 100 000; that is
  48 sizes.
- **Reviewer's D-22/D-26 model** (`tests/dynsym-models/gnuhash_model.py`,
  copied from `review-m2-adv/gnuhash`), run on a minimal ELF of our bytes:
  **27 of 27 tables EQUAL**, `tail=True sorted=True` (n from 0 to 5000).
- **lld** (D-26's claim of equality): 11 programs (0 to 1000 exports,
  plus a canonical PLT for `puts`), each linked `-rdynamic -no-pie` with
  lld on AArch64 and x86-64, **22 links**. Given lld's keys in lld's
  order, our plan has lld's order, our `.gnu.hash` equals lld's **byte
  for byte**, and every `.dynsym` entry equals lld's except `st_name`.
- **Reviewer's D-27 model** (`verneed_model.py`) on the imports of an lld
  C++ link of `t.cc` (libstdc++, libm, libgcc_s, libc; 12 versions):
  `verneed-in-needed-order=True vernaux-in-verdef-order=True
  vna_other=2..=True flags=none`. Each entry's `.gnu.version` names lld's
  version. The decoded `.gnu.version_r` equals lld's: the same needs and
  the same (hash, flags, name) runs in the same order. The bytes differ,
  as D-27 intends: lld writes every Verneed first and numbers
  `vna_other` by first use.
- **D-24**: two constructions of the names give the same `DynStr`. Each
  distinct string is written once, with no tail merging.
- **WP-051's cases** (`tests/link/dyn/dynsym`) were read against these
  rules. They agree on four points:
  - `dynsym-fields`: the copy of a weak definition is WEAK.
  - `environ-aliases`: the aliases are copies with versions; environ and
    _environ are WEAK, __environ is GLOBAL.
  - `versions-verneed`: a weak-only reference has `vna_flags` 0, and
    `vna_other` is numbered in output order.
  - `dynsym-order`: the unhashed block is in `SymbolId` order.

  No `tests/link/xfails` line names WP-044. Its rows wait on the join
  (WP-053, WP-055), which is when they first run mortar.

**Cost** (release, this host, 10^5 exports + 14 285 imports, best of 5):
`dynsym_plan` takes 6.4 ms at 1 thread and 6.9 ms at 8. Plan plus all
five fills (`.dynsym` written as one window, through the fixture's
BTreeMap address oracle) takes 41.6 ms at 1 thread and 33.6 ms at 8.
`tests/dynsym.rs` `cost` (ignored) measures it.

## Interface requests (beyond step 0)

1. `dynsym_plan` cannot sort by bucket without names. It becomes
   `dynsym_plan(resolution: &Resolution, demands: &Demands, slots: &Slots,
   src: &dyn DynSymSource, pool: &Pool, diag: &Collector) ->
   Result<DynsymPlan, Failed>`.
2. The join implements `DynSymSource: DynNames + Sync` (`shared(SymEntry)
   -> Option<SharedDef{info, other, value, size}>`, `program(SymbolId) ->
   Option<ProgramDef{info, other, size, version}>`, `bound_version(SymEntry)
   -> Option<VerIndex>`). It also implements `DynAddrs: Sync`
   (`defined(key) -> Option<(shndx, value)>`, `plt(key) -> Option<u64>`,
   `iplt(key) -> Option<(shndx, value)>`, `copy(alloc) -> Option<(shndx,
   value)>`).
3. The bound version comes from `bound_version`, not `SymProps.version`.
   RES sets that to 0 at `mortar_resolve/src/tables.rs:602`, so it does
   not carry the shared definition's version index. RES or the join must
   supply the `.gnu.version` index of the bound shared entry.
4. `DynNames::version_hash` is a provided method (default `None`). It
   lets the join hand over a library's `vd_hash`, so that a mismatch is
   `malformed-input`.
5. Further additions: `version::verneed_plan(plan, &DynsymInputs, needed,
   diag) -> Result<Box<Verneed>, Failed>` (it fills `Slots.verneed`);
   `dynsym::chunk_sizes(plan, verneed, dynstr, class)` (the S-108 sizes);
   and `DynsymChunk.machine` (D-23's `VARIANT_PCS`).

Fields read: from `Resolution`, `def`, `props.refs` (STRONG),
`props.visibility`, `imported`, `exported`. From `Demands`, `global`
(CANON_PLT, EXPORT, IPLT) and `weak_dyn`. From `Slots`, `needed`,
`copies`, `copy_of`. 0k is read only through `Demands.weak_dyn`.

## Spec findings (proposed text)

1. **D-27, the versioned entries**: D-27 names only imports. Proposed:
   "every `.dynsym` entry whose key has a shared definition (import,
   canonical PLT, copy and copy alias) carries the version of that
   definition". lld and the `environ-aliases` case do this.
2. **D-27, unneeded object**: proposed: "a versioned reference bound in a
   used shared object that is not needed is refused by name (no `vn_file`
   to write)". This is not reachable while D-11 makes every used library
   needed.
3. **D-23, export `st_other`**: the table says "merged visibility". We
   write the program's whole merged `st_other`, which keeps
   `STO_AARCH64_VARIANT_PCS`, as lld and GNU ld do. Proposed: "the
   merged `st_other`".
4. **D-23, IFUNC export size**: "its size" is written literally; lld
   writes 0. Proposed: keep the text and add lld's 0 to §13.1.
5. **D-23, IFUNC export without an IPLT entry**: refused by name ("an
   exported IFUNC that no relocation names"). Proposed: make D-28 demand
   IPLT for every exported IFUNC, and drop this refusal.
6. **D-23, exported `STB_GNU_UNIQUE`**: the table keeps UNIQUE, but the
   text says `.dynsym` "never holds a unique symbol". We follow the table
   (as GNU ld and lld do) and set `EI_OSABI` to GNU. Proposed: delete the
   sentence.
7. **D-21, `_DYNAMIC` / `_GLOBAL_OFFSET_TABLE_` / `__dso_handle`** in
   `exported`: these are an internal error (RES must exclude them).
   Proposed: state the exclusion in D-21's export rule.
8. **D-14 / D-27 (WP-051 finding 8: "a `Vernaux` that no judged reference
   requires is not checked")**: under these rules no such `Vernaux`
   exists. `.gnu.version_r` holds exactly the versions some `.dynsym`
   entry binds to, so every `Vernaux` is one a reference requires. The
   finding then needs no carve-out on mortar's side. It bears only on the
   references, whose extra needs WP-051 does not judge.
9. **D-27 vs lld**: lld lays out every Verneed before the Vernaux and
   numbers `vna_other` by first use. D-27's interleaved layout and
   output-order numbering are GNU ld's and mold's. Proposed for §13.1:
   "lld: Verneed headers first; `vna_other` in first-use order".
