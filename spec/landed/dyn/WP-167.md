# WP-167: a needed `--as-needed` library's references extract archive members

The M2 refusal `archive member needed by an --as-needed shared object`
(`spec/dyn.md` D-12, Q1; `spec/resolve.md` §4.4; WP-043) is withdrawn.
This distribution's `gcc`/`g++` pass `--as-needed` on every link, so it
stood on ordinary driver lines (`m1.o --as-needed libu.so libg.a`). D-12
now resolves in **stages**: a needed as-needed library's strong
references are edges from the stage after the one that finds it needed.
Measured against GNU ld 2.44, lld 22 and mold 2.37.1 on AArch64 and
x86-64 (the references give the same answer on both), `Exec` and `Pie`
run, `Shared` linked; i386 not measured (its dynamic output is M4).

## 1. The rule (approved by the supervisor, with six conditions)

`spec/dyn.md` D-12, the bullets after the table:

- stage 1 is resolution with no other shared object's reference as an
  edge, then D-11 and D-12. A **candidate** is a member of N, `as_needed`
  on, not yet a source, with a strong undefined reference whose
  `first(k)` is a lazy file that is not live. Without one the link has
  one stage. With one, the next stage resolves again with every as-needed
  member of N as an edge source; N only grows (each earlier stage's
  needed objects, item-2 givers and item-3 pairs are kept). Stages repeat
  until one has no candidate; only the final stage's diagnostics are
  reported.
- the result is the least fixed point of resolve §4.1 over the union of
  every stage's edges (N only grows, so the sources only grow: at most
  |C| + 1 stages); an implementation may continue the closure instead of
  resolving again.
- D-11 item 3 gives no reason for a key whose edge out of `x` targets a
  lazy file that is not live: the next stage extracts it (cell 7a).
- the references of an unneeded as-needed object, of a used object (U)
  and of a closure file (W) are never edges; D-13's `undefined-symbol`
  names the member a lazy archive has (`defined in`) and a note with the
  two ways out (condition 2; both U and W have it).
- a weak reference and a versioned reference `g@V` start no stage.

Old sentences (D-12): "the undefined references of a member of C whose
merged `as_needed` is on, and of every closure file (W), are never
edges" and "**`as-needed extraction`, refused by name** ... An extension
that lifts the refusal (extract in a second stage and refuse only when
that changes N) is a follow-up, not M2." New: the stage bullets above;
"The M2 refusal ... is withdrawn by WP-167: no measured cell needs it."
Q1's rule, resolve §4.4's paragraph and the unverified list follow;
resolve §13's graph bullet notes that the edges out of an as-needed
object depend on N; D-19a gains a bullet on the stages (§4);
`spec/diag.md` §4.2 lists D-12's two notes.

The proposal refused nothing new: no measured cell's answer depends on
an order mortar does not have. Nothing stays refused by this package; the
cells where mortar refuses are the references' own refusals (U, W, a
hidden or `--exclude-libs` member: D-13's `undefined-symbol` and
`non-exported-symbol`, as GNU ld). Not this package: refusing the option
`--no-allow-shlib-undefined` (WP-159's row; cell 4f).

## 3. Diagnostics, map and depfile (conditions 1, 2, 5)

- Row 1 links silently (empty stderr): the stage-1 `undefined-symbol` of
  `g` is never reported (unit test
  `d12_needed_as_needed_object_extracts_in_a_second_stage`, Error mode;
  lane `no-diag: *`).
- U (5b): `libuc.so: undefined symbol: g` / `>>> defined in
  libg.a(g.o)` / `>>> the library is not needed (--as-needed): link it
  with --no-as-needed, or name the member's definition earlier (an
  object or -u)`. W (5): `./libuc.so: undefined symbol: g` / `>>>
  defined in libg.a(g.o)` / `>>> the library is not on the command line,
  so its references extract nothing: name it on the line with
  --no-as-needed, or name the member's definition earlier (an object or
  -u)`. The note was cheap for W as well (the closure bit of the member).
- The map, as GNU ld's: row 1 `libg.a(g.o)                   libu.so (g)`;
  2d `libgv.a(gv.o)                 libu.so (g)` and
  `libw.a(w.o)                   libvw.so (w)`. Before, mortar printed
  `libu.so ()` for any member a shared object pulled (`mortar_image`
  `entry_name` now reads the shared object's `.dynsym` name).
- The depfile lists `libgv.a` and `libw.a` as every other input (2d,
  confirmed).

## 4. D-19a (condition 6)

The order is computed once from the final stage's N and reasons. A
library joining N through a later stage's member is kept at the first
mention after that member's archive, or at its first mention when none
is (`--as-needed libv.so libu.so libgv.a`: `libv.so libu.so`, lld and
mold the same, GNU ld refuses). A library kept needed (2a) keeps its
stage-1 mention: `m1y.o --as-needed libuy.so --no-as-needed libv.so
--as-needed libgy.a` gives `libuy.so libv.so` (GNU ld, mold; lld
`libv.so`). `libu.so libgv.a libv.so libu.so`: `libu.so libv.so` (all).

## 5. Cost (condition 4)

The candidate test is the loop the M2 refusal ran; a link without a
candidate runs exactly one stage. `MORTAR_STEPS=1` prints
`resolve count stages: N`; `crates/mortar/tests/as_needed_stages.rs`
asserts 1 for a default `g++` dynamic hello, a `-static` hello and the
row-1 line under `--no-as-needed`, and 2 for row 1 (AArch64, x86-64).

Resolve phase (`--time-phases` "30 resolve", minimum of 15, debug build,
AArch64, load about 13):

| line | stages | resolve | the same under `--no-as-needed` |
|---|---|---|---|
| 7b (`gcc`) | 1 | 11.5 ms | 11.6 ms |
| 1a (`gcc`) | 2 | 15.9 ms | 11.6 ms |
| 2b (`gcc`) | 2 | 15.2 ms | 11.4 ms |
| 2d (`gcc`) | 3 | 20.3 ms | 12.0 ms |
| 7b (`g++ -static-libstdc++`) | 1 | 18.7 ms | 23.7 ms |
| 1a (`g++ -static-libstdc++`) | 2 | 32.7 ms | 24.6 ms |
| 2b (`g++ -static-libstdc++`) | 2 | 32.8 ms | 24.9 ms |
| 2d (`g++ -static-libstdc++`) | 3 | 42.2 ms | 22.7 ms |

A later stage costs about 0.35-0.45 of a resolution (the kinds and
targets are computed once; the closure, `def`, columns and D-11 run
again); no section is read again. A link whose libraries are named
`--no-as-needed`, or that has no candidate, pays nothing.

## 7. The verifier package (what it has to learn)

1. An as-needed command-line shared object's strong undefined references
   are input-set edges (M11/M12) iff its soname is `DT_NEEDED` in the
   output (it is in the final N); an unneeded or used object's and a
   closure file's never are. The old rule ("edges unless `--as-needed`
   at every mention") remains for the rest.
2. Edges are taken to their least fixed point over the union (the
   output's N fixes the sources, so one closure suffices).
3. D-11 item 3 gives no reason for a key whose edge targets a lazy
   non-live member (7a2: `libg2.so` not needed).
4. A kept-needed library (2a) is justified from the inputs and the
   output: it is DT_NEEDED and, at stage 1 (the closure with no
   as-needed edges), it gives a strong reference of a live object (item
   2) or of a needed object (item 3); its key's definition in the output
   is a member extracted through an as-needed library's edge. Without
   such a stage-1 reason, DT_NEEDED naming it is still P-D6.
5. The marks that come off: the four `xfail(mortar)` above,
   `xfail(bfd,mold)` of `-kept`.
