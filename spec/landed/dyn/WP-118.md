# WP-118: `Shared` synth, layout and image (AArch64)

The output side of a shared object (record `spec/landed/dyn/WP-110.md`
§D, row WP-118), built against WP-116's types and checked by
crate-level tests with hand-made tables. `-shared` still does not link
end to end: `crates/mortar` refuses the kind (`kind_and_interp`,
`refused("this output kind with .dynamic")`) until WP-123 does the
wiring that §4 lists. Static, PIE, dynamic and static-pie outputs and
their maps stay byte-identical: the gate's `static-identical` step
shows `0 differ`.

## 4. What WP-123 passes

In `crates/mortar/src/dynlink.rs::plan`, for `plan.kind == Shared`:

1. `kind = DynKind::Shared(SharedDyn { soname: plan.soname.is_some(),
   symbolic: plan.symbolic().is_some_and(|l| l.writes_symbolic_tags()) })`,
   `interp = None`.
2. `dynsym_plan_shared(resolution, demands, slots, src, pool, diag)` in
   place of `dynsym_plan` (`Resolution.exported`, `.imported`,
   `.props[k].refs` with `FROM_OBJECT`, `Demands.weak_dyn`).
3. `verneed_plan` with `DynsymInputs { .., shared: true }`.
4. `dynstr_plan_shared(&dynsym, needed, soname_bytes, &verneed, rpath,
   names)`; keep the returned offset.
5. `GotPlan::new_shared(arch, slots, output_flags, variant, bind_now,
   kinds, &dynsym, diag)` in place of `new_dynamic` (elsewhere,
   `DynGotCx.pie` should read `kind.position_independent()`).
6. `RelaPlan::new` as for a PIE.
7. `DynamicInputs { kind, init: shared_init_key(..)?, fini:
   shared_init_key(..)?, .. }` (the named symbol's bytes and key, and
   `_init`/`_fini` when defined).
8. `DynPlans { .., interp: None, shared: Some(SharedPlans { soname:
   Some((bytes, offset)) or None, line: &SharedLine::of(plan) }) }`;
   `None` for every other kind.
9. Layout: nothing; `Options::from_plan` already reads `Shared`.

## 5. Measured first: the RELRO end at a 64 KiB max page

A small AArch64 library (`-z max-page-size=65536`; 4 KiB kernel): GNU ld
2 `PT_LOAD`s, RELRO end 0x20000; lld 4, end 0x21000 (not 64 KiB
aligned); mold 4, end 0x30000. At 4 KiB: 0x2000 (GNU ld), 0x3000 (lld,
mold). lld and mold write `PT_PHDR`, GNU ld does not. mortar's fixture
library (`d123_relro_end_at_64k`): RELRO 0x34800..0x40000, file bytes
0x14800..0x15c20, so the end is the next 64 KiB boundary and the file is
not padded. Checked: the addresses, the congruence, the `[G]` rules on
the skeleton. Not checked: a load and the RELRO `mprotect` on a 64 KiB
kernel (no such host; WP-120 records the lane gap).
