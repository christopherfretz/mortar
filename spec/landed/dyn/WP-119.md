# WP-119: the D-117 analysis, bound use through a register (AArch64)

`spec/dyn.md` D-117, "Bound use through a register", items 1-9, and the
analysis's case of "Before the start of a local object" (record
`spec/landed/dyn/WP-110.md` §D row WP-119). The analysis is
`crates/mortar_scan/src/regflow.rs`; nothing calls it yet (WP-123 joins
it to the `Shared` scan, beside WP-117's address-level rule). No
existing output changes: the module is new and is not reached by any
link.

## 1. The interface (for WP-123)

```rust
pub fn analyse<'a, E>(
    obj: &Object<'a>,
    preemptible: &[SymbolIndex],
    contents: &mut dyn FnMut(SectionIndex) -> Result<Cow<'a, [u8]>, E>,
) -> Result<Analysis, Fault<E>>;

pub struct Analysis { pub ran: bool, pub functions: u64, pub words: u64,
                      pub undecoded: u64, pub uses: Vec<BoundUse> }
impl Analysis {
    pub fn refused(&self) -> bool;                       // !uses.is_empty()
    pub fn definitions(&self) -> Vec<SymbolIndex>;       // sorted, each once
    pub fn diagnostics(&self, file: &FileRef) -> Vec<Diagnostic>;
}
pub struct BoundUse { function, function_name, section, section_name,
    offset, function_offset, reach: Reach, address: Address,
    address_section_name, definition, definition_name, boundary: bool,
    origin: Origin, origin_symbol_name, origin_section_name }
impl BoundUse { pub fn before_start(&self) -> bool;
                pub fn diagnostic(&self, file: &FileRef) -> Diagnostic; }
pub enum Reach { Computed, Access, WriteBack }
pub enum Fault<E> { Malformed(String), Contents(SectionIndex, E) }
pub fn default_line(obj: &Object<'_>) -> Result<Vec<SymbolIndex>, String>;
pub fn resident<'a>(obj: &Object<'a>)
    -> impl FnMut(SectionIndex) -> Result<Cow<'a, [u8]>, mortar_elf::Error>;
```

- `preemptible`: the symbol-table indexes of O's definitions whose key
  has `Resolution.preemptible` (D-112). The analysis keeps the
  non-local ones defined in a section without `SHF_EXECINSTR` (D-117's
  preemptible data definitions, `STT_TLS` included); the caller may
  pass every preemptible definition.
- `contents`: a section's `sh_size` bytes as in the file (the scan's
  `Walker::section_bytes`). Asked for the relocation sections of the
  executable sections first (the pre-filter), then, only when it passes,
  for the code of the functions and the relocation sections of the
  sections literal words are read from; for every relocation section
  only when a boundary address is computed and "self-GOT" must be known.
- The verdict: a non-empty `uses` refuses the link, one
  `non-pic-in-shared-object` error per use (`diagnostics`), placed at
  the instruction (code section + offset). `{name}` is the definition;
  the note names the address, how it is reached (accessed, computed,
  written back), the function and offset, and the relocation that
  formed the register (type, symbol + addend, place). At a boundary the
  note adds `-fdata-sections`; before the start of the address that
  formed it (`before_start`) it adds `-fdata-sections` and `do not form
  an address before an object` (diag.md §3.2).
- `default_line` is every `STV_DEFAULT` global, weak or unique
  definition: the oracle's assumption, for the tests and the off-gate
  check only.
- Nothing else is read; the result does not depend on the order of the
  sections, the symbols or the relocation records (the last record at
  an offset wins, as the oracle's table by offset). It never panics:
  a table that does not parse is `Fault::Malformed`; a word that does
  not decode is item 5's "unallocated" or "any other word of the
  load/store group" (kills every register); words past the end of the
  section's contents are not analysed; an `SHT_REL` section of an
  AArch64 object is not read (the scan refuses it by name).

## 3. Where the oracle and the spec differ

The off-gate comparison (§4) found no difference on any corpus. Reading
`s1d.py` against items 4-6 finds five, none of which any corpus object
reaches; the analysis follows the spec text:

1. Item 4: the 277 defining form is an `ADD`; the oracle also accepts a
   `SUB` with 277.
2. Item 4: 286 is the unsigned-offset `LDR Xt`; the oracle accepts any
   load/store form with 286.
3. Item 5: exclusive forms kill Rs+1 only when Rs is not 31; the oracle
   computes `(Rs+1) & 31` and kills x0 for Rs = 31.
4. Item 6: a `MOV` with a relocation at its word kills Rd ("an
   instruction with a relocation at its word that is not a defining form
   kills what it writes"); the oracle copies.
5. Item 6: a relocated load/store with write-back kills Rn; the oracle
   leaves it.

## 5. Cost on the largest AArch64 bench link

`cxx-large-g` of the bench (clang-19, static, `-g`; its 117 input files
under `.build/bench-work/`, 3,494 AArch64 objects counting every member
of every archive, more than the link extracts), as if `-shared`, with
the default line (every `STV_DEFAULT` global data definition
preemptible), release build, the ignored test `corpus`, three runs at a
1-minute load under 10: the pre-filter passes for **0** objects, so
**0 words** are decoded; the pass reads every executable section's
relocations. The three runs took 2.85 s, 2.26 s and 3.59 s, almost all
of it reading the 2.3 GB of inputs and parsing their headers and symbol
tables (the time includes both; the analysis proper is the pre-filter's
relocation walk). LLVM builds with `-ffunction-sections
-fdata-sections`: no code relocation names a local of a section that
holds an exported datum. The oracle agrees on a sample
(`libLLVMSupport.a`, 151 members, and `driver.cpp.o`: pre-filter 0).
In release, with reading included: kiln `-O0` (hod) `-fPIE`, 123,011
words over 4 objects, 89 ms; the 79 system archives (11,699 members,
123,763 words), 95 ms; abseil F, 171 ms (debug builds: 1.2 s, 0.19 s,
0.1 s); the release output is byte-identical to the debug one.
