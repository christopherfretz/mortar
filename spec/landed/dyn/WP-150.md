## 3a. Linker-defined exports (`_end`, `__bss_start`, ...)

Supervisor's ruling, after WP-150 reported that a mortar library never
exported a referenced `_end` (a program's `_end` then differs from the
library's view of it, which is also what lld and GNU ld do not do):
(a) `Shared`: a linker-defined `STV_DEFAULT` key is exported when an
input object references it, and is then preemptible per D-112; (b) `Exec`
and `Pie`: such a key is exported when a needed library references or
defines it. Only cells where GNU ld and lld agree against mortar change.

### Measured (`m4/run.sh`, `exe.sh`, `exe2.sh`, `rt.sh`; both machines alike)

`-shared`, the object references the key (`P` exported preemptible, `B`
exported bound, `L` local, `-` not exported, `U` undefined):

| cell | GNU ld | lld | mold | mortar before | mortar now |
|---|---|---|---|---|---|
| the seven (`_etext etext _edata edata __bss_start _end end`), plain line | P | P | - | - | P |
| the seven, `-Bsymbolic` | B | B | - | - | B |
| the seven, `-Bsymbolic-functions` | B | P | - | - | P (NOTYPE, D-112) |
| the seven, `--dynamic-list` not naming them | B | B | - | - | B |
| the seven, `local: *` | L | L | - | - | not exported |
| the seven, `global: _end` | `_end@@V1` P | same | - | - | `_end@@V1` P |
| `__etext`, AArch64 `__end__ __bss_start__ __bss_end__ _bss_end__` | P | U | - | - | - (kept) |
| `__executable_start`, `__init_array_start` | U | local hidden | - | local hidden | local hidden (kept) |

`Exec`/`Pie` (`-pie`, `-no-pie`; `main` references nothing, `mainr`
references the seven):

| cell | GNU ld | lld | mold | mortar before | mortar now |
|---|---|---|---|---|---|
| a needed library references and defines them | exported | exported | none | `mainr` only (`ref_dynamic`) | exported |
| a needed library references them (undefined there) | exported | exported | none | `mainr` only | exported |
| a needed library defines them as ordinary data (`char _end[1]`) | exported, `STT_OBJECT` | exported, `NOTYPE` | none (mainr: imports) | none | exported, `NOTYPE` (lld's) |
| objects reference them, `-E`, no library | exported | exported | none | none | exported |
| `-E`, no reference | `_edata __bss_start _end` (+ AArch64 names) | none | none | none | none (lld's) |
| no reference, no `-E`, no library | none | none | none | none | none |

Run check (`rt.sh`): `api_end() == _end`, `api_edata() == _edata`,
`api_bss() == __bss_start` in a host: a library of GNU ld, lld or
mortar under a GNU ld or a mortar host, `-pie` and `-no-pie`: `1 1 1`
on both machines. Before, a mortar library printed `0 0 0` under every
host (it bound `_end` to its own); a mortar host of a GNU ld library
already printed `1 1 1` (`ref_dynamic`). mold's library: `0 0 0`. `-Bsymbolic` and
`local: *` libraries: `0 0 0` with every linker.

### The rule as written (spec/dyn.md)

- D-110 item 2: the seven names, referenced by a live object, are
  exported `STB_GLOBAL STT_NOTYPE STV_DEFAULT` and preemptible by D-112;
  `__etext` and the AArch64-only names, `__executable_start` and
  `__init_array_start` keep mortar's form.
- D-21 item 2: the seven are exported as an ordinary definition of the
  program is (`defined_dynamic`, `-E`, `--export-dynamic-symbol`,
  `--dynamic-list` once referenced), besides `ref_dynamic`.
- §13.1: the executable row (GNU ld's `STT_OBJECT`, its `-E` exports;
  mold none). §17.6: the `-shared` row and the `-Bsymbolic-functions`
  row.
- Code: `mortar_resolve::linker::EXPORTED_AS_DEFINITIONS` and
  `Provided::exported_as_definition`; `export::exported`'s `Provide`
  arm; `shared::link` defines a key a shared object references or
  defines (`Def::Undefined`, unversioned) and exports it.
- Tests: `export.rs` `d110_export_set`; `tests/shared_output.rs`
  `d110_export_set_of_a_shared_object`, `d112_preemptible_per_form`,
  `d21_linker_defined_exports_of_an_executable`; lane
  `dyn/shared/linker-defined-export`, `dyn/dynsym/linker-defined-export-exec`.

## 1. `.symtab` binding of version-local and `--exclude-libs` keys

Measured (`m1/`, AArch64): a key a node's `local: *` or the anonymous
script makes local is `LOCAL` in `.symtab` in all three. Its visibility
stays its own in lld and mold (`HIDDEN`, `PROTECTED`); GNU ld writes
`DEFAULT`. `-x` and `-X` keep these keys (all three); `-s` drops
`.symtab`. `--exclude-libs` in `-shared`: GNU ld and lld `LOCAL DEFAULT`,
mold `LOCAL HIDDEN`. In executables (measured in `-pie`, `-no-pie`, `-static`,
`-static-pie`): lld `LOCAL DEFAULT` in every kind, mold `LOCAL HIDDEN`;
GNU ld `LOCAL DEFAULT` in a PIE and a static-pie, `GLOBAL HIDDEN` in
`-no-pie` and static without `-E`. Order: lld puts them in the defining
file's block (S-74's order). mortar before: `GLOBAL`. Now lld's form (`LOCAL DEFAULT` in all four
executable kinds)
(the visibility kept); eu-elflint finds no error on mortar's output.
Side effect: `--gc-keep-exported` now collects a version-local function,
as GNU ld does (it is not exported).

Rule: synth S-77 (the demoted set extended), S-121's sentence, D-110
item 1's `.symtab` sentence. Code: `version::apply` sets
`Dynamic::script_local`; `tables::resolution` writes `STB_LOCAL` for it
and for an `--exclude-libs` definition; `symtab::classify` demotes every
`STB_LOCAL` definition. Test: `dyn/version/symtab-local`.

## 2. `.symtab` name of a `.symver` definition

Measured (`m2/`): GNU ld writes `foo@V1` and `foo@@V2` in every kind
(a hidden `foo@V1` LOCAL too); lld and mold write `foo` twice (lld names
a hidden one LOCAL `foo@V1`). gdb 16.3 and lldb 19.1.7, a program
calling `foo` of each library, with (`g`) and without (`n`) `-g`
(`m2/gdbrun.sh`, `lldbrun.sh`; outputs `m2/gdb.*.txt`, `lldb.*.txt`):

| | GNU ld's form (`foo@V1`, `foo@@V2`) | lld's form (`foo`, `foo`) |
|---|---|---|
| gdb `bt`, no `-g` | `foo@V1 ()` | `foo ()` |
| gdb `info symbol $pc`, `info symbol foo_v1/foo_v2` (`g`, `n`) | `foo@V1`, `foo@@V2` | `foo` for both |
| gdb `break 'foo@V1'`, `break 'foo@@V2'` | one location each | "not defined" |
| gdb `break foo` | 2 locations | 2 locations |
| gdb `bt` with `-g` | `foo_v1` (DWARF) | `foo_v1` (DWARF) |
| lldb `b foo@V1`, `b foo@@V2` | one location each | pending, no location |
| lldb `image lookup -s foo@V1` | matches in `libs.so` | no match in `libs.so` |
| lldb frame / `image lookup -a $pc`, no `-g` | `foo@V1` | `foo` |

mortar's new output (`new*`) prints line for line what GNU ld's does
under gdb, and under lldb but for the `PT_LOAD[n]` index of the
addresses (mortar's text is in the second segment; layout, not names).
mold's prints what lld's does.

Decision: GNU ld's form; a debugger can tell the two definitions apart
(without `-g` it is the only name a frame has). Rule:
synth S-75's new paragraph. Code: `crates/mortar/src/syms.rs` (the
entry's own name when its string has `@` right after the key's name:
one byte read, no scan). Test: `dyn/version/symtab-symver-names` (nm,
readelf, gdb `info symbol`).

## 3. Linker-defined keys under a version script

Measured (`m3/`): under `local: *`, GNU ld makes `__start_`/`__stop_`,
`_end` and `__bss_start` `LOCAL DEFAULT`; lld keeps `__start_`/`__stop_`
exported `GLOBAL PROTECTED` and makes `_end` local; mold exports none
and writes all of them `LOCAL DEFAULT`. Under a
node's `global:`, GNU ld exports `__start_mysec@@V1`. An unreferenced
`global: _end`: GNU ld silent and absent, lld refuses, mold warns;
mortar warns, `version-script-undefined-name`. mortar now writes them
`LOCAL` with the column's visibility (`PROTECTED` for start/stop). Rule:
D-114's new bullet, S-77. Code: `version::apply`'s `Provide` branch,
`syms.rs`'s `Provide` binding. Test: `dyn/version/symtab-linker-defined-local`.

## 4. The dependency file

Measured (`m5d/`): GNU ld, lld and mold all list the `--version-script`
and `--dynamic-list` files: GNU ld before the inputs in command-line
order, lld before the inputs in its own order, mold sorted on one line, with an empty rule per file.
lld and mold also list `--retain-symbols-file` (GNU ld does not); mortar
refuses that option. No linker lists a response file. mortar listed
neither of the two. Now: both, in command-line order, before the inputs,
each once. No other file mortar reads for an accepted option is missing
(`-T` is refused; `--export-dynamic-symbol-list` is refused). Rule:
input.md §10.4. Code: `crates/mortar/src/lib.rs`
`write_dependency_file`. Test: `input/dependency-file-scripts`.
