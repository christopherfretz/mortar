# WP-137: a weak reference whose only definition is in a library `--as-needed` drops (`Shared`)

WP-123's finding F3: a `-shared` library whose only reference to the C
library is crtbeginS's weak `__cxa_finalize` (a C++ or Fortran library
calling no libc function) was refused by name (`versioned reference to
__cxa_finalize bound in a shared object that is not needed (spec/dyn.md
D-27)`). The C library is an as-needed member of C that nothing needs,
but `libstdc++.so.6` (or `libgfortran.so.5`) lists it, so D-12 made it
*used* and the D-10 setting's `bind(k)`, which ranges over N ∪ U, bound
the weak key to its versioned definition; D-27 then had no `Verneed` for
it. mortar now writes GNU ld's library: an unversioned `WEAK NOTYPE UND`
entry, no `DT_NEEDED` and no `Verneed` of the dropped library.

## 1. Measured first

Scratch script `meas.sh` (AArch64 natively, x86-64 cross objects run under
qemu; GNU ld 2.44, lld 22, mold 2.37.1). `libv.so` defines `vfn@@V1` (a
version script); `libm2.so` defines `m2fn` and lists `libv.so`
(`--no-as-needed -lv`); the program or library references `vfn` weakly
and `m2fn` strongly; `--as-needed -lv -lm2`. `libm2n.so` lists nothing
("no edge"). The type column is `.dynsym`'s entry of `vfn`
(`__cxa_finalize` for the last two rows); "ver" is `.gnu.version`'s index
(`—`: no `.gnu.version` section).

Every mortar library of the "after" column has GNU ld's `.dynsym` set
(names, types, bindings, versions; only section indices and GNU ld's
`STT_SECTION` entries differ). Run: the GOT library under a GNU ld host
prints `27` (`libv.so` loaded by `libm2.so`) and `120` with a host that
defines `vfn`.

**The executable rule.** An executable already links the "no edge" case
by D-11 ("never a reason to be needed: a weak reference alone"; the key
stays `Undefined{weak: true}`, D-25). When the dropped library is reached
by an edge (U), the D-10 setting binds the weak key there in `Exec` and
`Pie` too, and a versioned definition is refused by D-27: the refusal is
not specific to `Shared`. GNU ld and lld then write the import
unversioned (`FUNC WEAK`, 1, no `Verneed`). Left as it is here (finding
G1 below): executables stay byte-identical, and the brief's scope is
`Shared`.

## 2. The rule and the code

| rule | where | test |
|---|---|---|
| D-10 setting (`bind(k)` in `Shared` ranges over N alone) | `crates/mortar_resolve/src/shared.rs:286` `binds` (the `rank` filter of `bind(k)` gains "in N" when `opts.shared_output` is set) | `crates/mortar_resolve/tests/shared_output.rs` `d10_shared_weak_key_does_not_bind_a_used_object` (`Shared`: `Undefined{weak: true}`; `Exec`: `Shared(libv)`, unchanged); `dyn/shared/weak-dropped-need`, `cxx-weak-only-libc` |
| D-111 item 3 (such a key is `WEAK NOTYPE`, unversioned) | unchanged code: the key is weak undefined, so WP-123's D-111 path writes it | `weak-dropped-need` (`vfn`, `__cxa_finalize`), `cxx-weak-only-libc` |
| D-27 (a dropped object has no `Verneed`; the refusal stays for `Exec`/`Pie`, cannot arise in `Shared`) | `crates/mortar_synth/src/version.rs` unchanged | `weak-dropped-need` (no `.gnu.version_r`), `weak-dropped-need-no-as-needed` (`vfn@V1`, `Verneed` of `libv.so`) |

Only a weak-only key can have every definition outside N (a strong
program reference makes `giver(k)` needed, D-11 item 2, and the loader
order puts N before U), so no strong key's binding moves. Nothing names
`__cxa_finalize`.

Spec edits (`spec/dyn.md`): the D-10 setting's `bind(k)` (one sentence:
`Shared` ranges over N alone, with the three references); D-27 (a bullet:
an object that is not needed has no `Verneed`; the refusal stays in
`Exec`/`Pie`, with GNU ld's and lld's unversioned form, and cannot arise in
`Shared`); D-111 (item 3's `WEAK NOTYPE` also covers a key whose only
definitions are in objects that are not needed: crtbeginS's
`__cxa_finalize`, GNU ld's `NOTYPE`). The type follows GNU ld: D-111's
"`STT_FUNC` for an import whose definition is a function" does not apply,
the key is not an import.

## 3. Tests

- `dyn/shared/cxx-weak-only-libc`: `xfail(mortar)` lifted on AArch64;
  checks gain "no `.gnu.version_r` need of `libc.so.6`".
- `dyn/shared/weak-dropped-need` (new): the C twin (`if (vfn) vfn()`;
  run with `libv.so` present, `27`, and with `alt/libv.so` lacking `vfn`,
  `20`, for every library).
- `dyn/shared/weak-dropped-need-no-as-needed` (new): `libv.so` stays
  needed, `vfn@V1`, `Verneed`, runs `27`.
- Both tests that write the unbound key carry `xfail(mortar,aarch64)` for
  the verifier (G2); with `--no-plumb` mortar passes every step of both
  (checks and runs). All three are `xfail(mortar,x86_64)` until WP-127.
- Census: `-shared` (see §5).

## 4. Findings

- **G1** (reported, not changed): `Exec`/`Pie` refuse a weak reference
  whose only definition is a versioned one in a used, not needed object
  (the table's first two rows); GNU ld and lld link it unversioned (`FUNC
  WEAK`, 1, no `Verneed`) and it runs. Recommendation: D-27 writes 1
  for an entry bound in a used object (the loader binds an unversioned
  reference to the default version); a refused-by-name line today, so no
  existing output changes.
- **G2** (verifier, for its agent): stage 3's P-D7 on mortar's libraries
  `libwo.so` (`cxx-weak-only-libc`) and `libwv.so` (`weak-dropped-need`):
  ``P-D7 an import's type is not its definition's (D-23) against
  '__cxa_finalize'`` and ``the import '__cxa_finalize' has type 0 (D-23:
  2)`` (and the same for `vfn`). The verifier still binds the weak key to
  the used C library in `Shared`; the D-10 setting now leaves it unbound
  (`STT_NOTYPE`, P-D7's own "`STT_NOTYPE` when nothing defines it"). GNU
  ld's identical library has 0 findings. Reproduction: `xtask plumb
  libcx.so --map libcx.mmap --map-format mortar --line libcx.words` on
  `g++ -shared -Wl,--as-needed cx.o -Wl,--mortar-map=libcx.mmap` of a
  throwing function (`.build/target-wp-137/m1/out-a64-mortar/`).
- A program defining `vfn` unversioned, linked by GNU ld against a
  library whose reference is `vfn@V1`, does not export it (the verifier's
  D-12 W8 finding on the host): why the new tests have no interposing
  host.
