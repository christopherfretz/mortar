# WP-141: executables: a weak versioned reference whose only definition is in a library `--as-needed` drops (G1)

WP-137's finding G1. In `Exec` and `Pie`, a weak-only reference whose only
definition is a versioned one in a shared object that `--as-needed` drops
but a needed object's own `DT_NEEDED` reaches (a used object, U, D-12) was
refused by name: `versioned reference to <k> bound in a shared object that
is not needed (spec/dyn.md D-27)`. mortar now writes GNU ld's image: the
key stays bound in the used object, its `.dynsym` entry is unversioned
(index 1), and the object has neither `DT_NEEDED` nor a `Verneed`.
Supervisor's ruling (option A, GNU ld's image on every row, no new
refusal), taken after the measurement below.

## 1. Measured first

Scratch script `meas.sh` (`.build/target-wp-141/wp141/m/`). Tools: GNU ld
2.44, lld 19.1.7, mold 2.37.1; AArch64 natively, x86-64 cross objects
under qemu. Inputs:
- `libv.so` defines `vfn@@V1`, `vdat@@V1` and `vfn2@@V1` (a version
  script).
- `libm2.so` defines `m2fn` (20) and lists `libv.so`; `libm2n.so` lists
  nothing.
- `alt/libv.so` has `V1` with `vfn2` but no `vfn` and no `vdat`.

The programs (`--as-needed -lv -lm2`):
- `call`: `vfn()`.
- `addr`: `int (*hp)(void) = vfn;` in data, called if non-null.
- `cmp`: `if (vfn) vfn()`.
- `dat`: `&vdat ? vdat : -1`.

`-pie` uses `-fPIE` objects, `-no-pie` `-fno-pie` ones, each with and
without `-z now`. `-z now` changes nothing; only a copy's section index
differs.

**The type (D-23).** A key bound in a used object takes the definition's
type (`FUNC`/`OBJECT`), which GNU ld and lld both write. An unbound key
would be `WeakDyn`: `STB_WEAK STT_NOTYPE` (case (a), GNU ld's `NOTYPE`).
The PLT/GOT form depends on the type only when the key is bound
(`TargetKind::Shlib{func}` chooses a canonical PLT or a copy). When it is
unbound, D-25's classes decide and the type plays no part.

**The references disagree** on x86-64 non-PIC `-no-pie`. GNU ld binds
the key: a canonical PLT or a `COPY`, which runs with the library and
fails with `alt`. lld leaves it unbound: 0 even with the library loaded.
mold keeps the library needed. I reported this before choosing; the
supervisor ruled option A.

## 3. Tests

- `dyn/shlib/weak-used-versioned` (case (b)), `-pie` and `-no-pie`:
  - **Every form, every linker:** pins `call`, `addr` (`-pie`), `cmp` and
    `dat`, with `libv.so` and (except `call`) with `alt/libv.so`.
  - **GNU ld, lld and mortar:** no `DT_NEEDED` and no `Verneed` of
    `libv.so`; the unversioned `FUNC`/`OBJECT WEAK UND` entry.
  - **x86-64 `-no-pie` (GNU ld and mortar):** `cmp`'s canonical PLT and
    `dat`'s `R_X86_64_COPY`, with the hazard pinned (alt: `signal 11`,
    127).
  - **lld on x86-64** is skipped (the verifier's finding V3).
- `dyn/shlib/weak-used-versioned-addr`: `addr` in `-no-pie`. mortar's
  symbolic record gives 27, and 20 with alt. GNU ld on AArch64 (V1) and
  lld (V2) are skipped.
- `dyn/shlib/weak-used-versioned-needed` (case (c)): the same hazard with
  a NEEDED library (x86-64 `-no-pie` cmp SIGSEGV; dat 127 for GNU ld and
  mortar, 320 for lld and mold, whose copy is `WEAK`), with `vfn@V1` and
  the `Verneed`.

All three: mortar passes on both architectures and the verifier finds
nothing on mortar's outputs. With the base binary, the mortar links of
`weak-used-versioned` and `-addr` fail with the D-27 refusal.

## 5. Findings

- **F1 (for the supervisor; D-25, not changed).** Case (a)'s call-only
  cell: a weak function reached only by a branch, defined nowhere live.
  - **The sentence that gives it:** D-25's last bullet, "otherwise the
    key is **`Weak0`** … in both kinds when it has neither a GOT use nor
    an absolute word in a writable place (a branch alone: `__gmon_start__`
    style calls patched per a64 §7 / x64 X-16)".
  - **The form:** AArch64 writes a `NOP` for the `CALL26`, so the program
    goes on with `x0` unchanged and prints 21. x86-64 calls 0 and
    SIGSEGVs.
  - **What dyn.md records:** §13.1's row "undefined weak key reached by
    branches only" (GNU ld and lld: dynamic, `JUMP_SLOT`; mold 0; mortar
    `Weak0`, no entry) records the difference in form only. D-25's text
    states neither the difference from GNU ld nor its run-time effect.
  - **Measured (`vfn()`, `libv.so` dead):** GNU ld (`NOTYPE WEAK`) and
    lld (`FUNC WEAK`) write a `JUMP_SLOT`. Without a preload both crash
    (AArch64: no output; x86-64: SIGSEGV). With
    `LD_PRELOAD=./libv.so` both print 27. mortar: AArch64 prints 21 with
    and without the preload (the call silently skipped); x86-64 SIGSEGVs
    with and without it. mold makes `libv.so` needed here, so this line
    says nothing about mold; §13.1 records 0 for a key defined nowhere.
  - **Open:** a follow-up package decides.
- **F2 (wording, not changed).** D-25's opening sentence ("an undefined
  key that is weak (no definition, or one only in a shared object that is
  not needed, D-11)") and D-11's "the key's view is then
  `Undefined{weak: true}`" read as if a used object's definition left
  the key unbound. The D-10 setting binds it (unversioned definitions
  before WP-141, every one after). "In no member of N ∪ U" would say it
  exactly.
- **Follow-up to write down (not implemented): a warning** when a `COPY`
  or a canonical PLT is taken from a used, not needed object. The program
  then depends on another library's dependency list. The place:
  `crates/mortar_scan/src/copies.rs` `refusal()`. It already judges every
  key with a `COPY`/`CANON_PLT` demand there and returns D-43a's warning.
  The key's `Def::Shared(e)` gives `e.file`, whose liveness is
  `FileLive::Shared { needed: false, used: true }` in
  `Resolution.file_live`.
- **Verifier findings on reference outputs** (no recorded anomaly names
  them; nothing on mortar's outputs):
  - **V1:** GNU ld on AArch64, `-no-pie` addr. R1 "the relocated field
    holds the wrong value; `R_AARCH64_ABS64` against 'vfn' … found" the
    address of an ordinary, non-canonical PLT entry (`vfn`'s `.dynsym`
    value is 0). A37's form, without its ending.
  - **V2:** lld, `-no-pie` addr, both architectures. R1, found 0 (the key
    left unbound).
  - **V3:** lld on x86-64, `-no-pie` cmp. R2 "the value 0x7f00000010f9
    fails the check 0 <= X < 2^32" (the `R_X86_64_32` of `if (vfn)`,
    with the key bound as D-10 does).

  The reproduction: `meas.sh`'s link of `addr-nopie.o` /
  `cmp-nopie.o` with `-Wl,-Map=…` and the linker's words, then
  `xtask plumb <out> --map <map> --map-format gnu|lld --line <words>`.
