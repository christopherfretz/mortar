`DynamicPlan::new` refuses contradictory inputs as `internal-error`: a
`StaticPie` with `DT_NEEDED` or versions, more `Verneed`s than needed
objects, `RELATIVE`s in an empty `.rela.dyn`, `.rela.plt` without
`.got.plt`. An ELF32 value over 32 bits is `internal-error`, never
truncated. A value the image cannot answer (a chunk, section, symbol or
`.dynstr` string the plan names but the tables lack) is `internal-error`,
never 0.

## The oracle (numbers)

`crates/mortar_image/tests/dynamic_gnu.rs`: GNU ld 2.44 links the
dyntags program (`review-m2-adv/dyntags/t.c`, plus `myinit`/`myfini`) for
AArch64, x86-64 and i386 under 12 conditions (`pie`, `nopie`, `now`,
`rpath`, `rpath-old`, `nopie-now`, `bti` (AArch64), `relro-off`,
`static-pie`, `static-pie-now`, `init-fini`, `init-undefined`): **34
outputs**. For each, mortar's plan is built from the output's facts that
D-30's conditions read (sections present or empty, `RELATIVE` count,
`.gnu.version_r`'s `sh_info`, the command line), with a fixture `DynStr`
(GNU ld's `.dynstr` offsets; D-24's order is WP-M2-DYNSYM's), and its
values resolved against GNU ld's addresses. Results:

- **34/34** equal GNU ld's `.dynamic` entry by entry (tag, order, value)
  after D-30's stated differences;
- **34/34** spliced into GNU ld's output (mortar's table in its
  `.dynamic`): `llvm-readelf -d` gives no warning and the same listing as
  GNU ld's up to the `DT_NULL`s; `eu-elflint --gnu-ld` gives the same
  verdict as on GNU ld's output; the program runs and prints `1` (native
  AArch64, `qemu-x86_64`, `qemu-i386`);
- **D-32**: in 31 of the 34 outputs `reserved_word` gives GNU ld's
  reserved words (AArch64 `.got[0]` = `_DYNAMIC`, `.got.plt[0..2]` = 0;
  x86-64 and i386 `.got.plt[0]` = `_DYNAMIC`, `[1..2]` = 0; static-pie
  included). The three AArch64 `-z now` outputs are not compared: GNU ld
  merges `.got.plt` in front of `.got`'s header word (D-49).
- A mutation (`DT_DEBUG` = 1) fails all 34; a mutation of
  `reserved_word` fails all 31.

`review-m2-adv/dyntags/run.sh` (re-run): every GNU ld output is
`D30-ORDER`, with 5 `DT_NULL`s in PIEs and 6 in `-no-pie` outputs; lld
and mold are `NOT-D30-ORDER`.

WP-051's cases (`tests/link/dyn/dynamic/*.test`, merged at b29427f), read
as oracles against this package's plan. None runs mortar yet: every
mortar line is an xfail of WP-053, WP-055 or WP-056, and none is tagged
WP-045, so this package deletes no xfail line. What they expect agrees
with the plan:
- `dynamic-tags` and `init-fini-option`: GNU ld's order, `(DEBUG) 0x0`,
  `RUNPATH` written as given (`$ORIGIN/sub`), `FLAGS BIND_NOW` and
  `FLAGS_1 NOW PIE` under `-z now`, and `DT_NULL entries: 6`;
- `got-header`: AArch64 `got[0]` and x86-64 `got.plt[0]`, which is what
  `reserved_word` does;
- `variant-pcs-plt`: `DT_AARCH64_VARIANT_PCS` after the `RELA` group and
  before `DT_FLAGS_1`, which is `Arch::dyn_tags`'s position;
- `interp-default`: the string as given, plus one NUL (`InterpPlan`).
`dyn-shdr` (D-34, `sh_link`) and `dynamic-writable` (D-33) are about
layout and join, not about this package.

## Differences from each reference, by name

- **GNU ld**: (1) an empty `.rela.dyn` gets no `DT_RELA*` from mortar
  (D-30 rows 21-23); (2) six `DT_NULL`s, GNU ld 5 or 6 (its
  `--spare-dynamic-tags` 5; the `RELACOUNT` of a PIE takes one); (3)
  under `-z now` GNU ld merges `.got.plt` into `.got`, mortar keeps the
  chunk, so `DT_PLTGOT` is the chunk's address in both but GNU ld has no
  `.got.plt` section (D-49). No other difference on the 34 outputs.
- **lld 19/22**: its own tag order (`DT_FLAGS_1`, `DT_DEBUG` and
  `RELA*` first; arrays and `INIT`/`FINI` after `GNU_HASH`; `RUNPATH`
  before `NEEDED`); one `DT_NULL`; writes an empty `.rela.dyn`'s tags.
- **mold 2.37**: its own order (`RELA*` and `JMPREL` first, `INIT`/`FINI`
  and `GNU_HASH` late, `FLAGS*`/`DEBUG` last); six `DT_NULL`s (as
  mortar); `DF_STATIC_TLS` in every executable (D-30: never).

## Findings (rule id, proposed text)

- **D-30 rows 3-4 (measured).** GNU ld, lld and mold give **no**
  `DT_INIT` when `-init=SYM` names an undefined symbol, even with `_init`
  defined. Proposed: "`DT_INIT`: present when `-init=SYM` is given and SYM
  is defined (its address), or when no `-init` is given and `_init` is
  defined; an `-init` naming an undefined symbol gives no `DT_INIT`
  (GNU ld, lld, mold). `DT_FINI` likewise." (`init_key`.)
- **D-30's scope and D-2.** D-30 says "`.dynamic` of `Exec` and `Pie`";
  D-2 says static-pie "needs only D-30's subset (`DT_RELA*`,
  `DT_RELACOUNT`, `DT_FLAGS_1`, `DT_DEBUG`, the triplet)". GNU ld's
  static-pie (AArch64, x86-64, i386) also writes `INIT`, `FINI`, the
  three arrays, `PLTGOT`/`PLTRELSZ`/`PLTREL`/`JMPREL` and `STRSZ`/`SYMENT`,
  each under D-30's condition, and the outputs run. Implemented: D-30
  applies to `StaticPie` unchanged. Proposed D-30 first sentence:
  "`.dynamic` of `Exec`, `Pie` and `StaticPie` holds…", and D-2: "needs
  D-30's rows under their conditions; with no shared input rows 1 and
  28-30 are absent".
- **D-30 row 2 (measured).** GNU ld does not deduplicate run-path
  directories (`-rpath /x -rpath /y:/x -rpath /x` gives `/x:/y:/x`).
  Proposed: append "no directory is removed or merged" to "as written".
- **D-31 (silent).** An empty `-dynamic-linker ""` path: no reference
  measured. Refused by name here (`unsupported feature: an empty
  -dynamic-linker path`), as is a path holding a NUL (impossible from
  `argv`, possible from a response file). Proposed: "An empty path is
  refused by name."
- **D-31 / layout L-39.** The refusal of an input section named `.interp`
  already exists in `mortar_layout` (`assign.rs` `SYNTHETIC_NAMES`) for
  **every** output kind, static included, which is stricter than D-31's
  "in an executable that writes one". No change made; the rule text and
  the code should say the same thing.
- **D-32 and `-z now` on AArch64 (no change).** GNU ld's `-z now` puts
  `.got.plt`'s words in front of `.got`'s header word inside one `.got`;
  mortar's `.got[0]` stays `.got`'s own first word. glibc reads neither.

## Interface requests (beyond step 0)

- **WP-046 (`mortar_synth/src/got.rs`)**: `Region::Header`'s value and
  `.got.plt`'s reserved words in an output with `.dynamic` come from
  `mortar_synth::dynamic::reserved_word(facts, table, index, dynamic)`.
  The `.dynamic` address must reach `GotPlan`'s write: proposed
  `GotAddrs.dynamic: Option<u64>` (`None` in a static link, which keeps
  writing 0).
- **WP-M2-LAYOUT / RES (`mortar_layout/src/symbols.rs`)**: `_DYNAMIC`'s
  value is the `.dynamic` chunk's address
  (`mortar_image::dynamic::dynamic_symbol`); `symbols.rs` has no
  `_DYNAMIC` arm yet.
- **The join (WP-053)**: builds `DynamicInputs` (from the plan, `Slots`,
  WP-046's record plan, the chunk list, `OutputCx`), `InterpPlan`, wires
  `DynamicChunk` and `InterpPlan` into `link.rs`'s chunk table (the
  `SynthKind::Dynamic`/`Interp` arms), gives `.dynamic` `sh_link` =
  `.dynstr` (D-34; the header row is image's), and calls `fill_records`.
  `variant_pcs_jump_slot` needs the PLT keys' `st_other`
  (`STO_AARCH64_VARIANT_PCS`) and `bti_property` the merged
  `FEATURE_1_AND` (`OutputCx.feature_1_and`).
- **CLI (WP-042)**: `-init`/`-fini` reach the plan as names (rows 3-4).
