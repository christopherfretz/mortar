## The 0k decision (`WeakKeys`, `weak.rs`)

- `weak_dyn: IdSet<SymbolId>`: the `WeakDyn` keys. It becomes
  `Demands.weak_dyn`.
- `refused: Vec<(Key, Diagnostic)>`: one per refused key, at its first
  relocation of the refused class.
- `refused_keys: IdSet<SymbolId>`: the refused keys. The walk drops
  their records (`driver.rs:728`).

`WeakUses { got, abs_word, branch, unfillable: Option<Key> }` is
collected per key over every live allocated relocation that names it.
`verdict` then decides:

- `WeakDyn` when there is a GOT use or an absolute word in a writable
  place, and no unfillable use;
- refused when there is an unfillable use in a `Pie`:
  `weak-undefined-pc-in-pie`;
- `Weak0` otherwise.

A thread-local use is refused in both `Exec` and `Pie` (`TLS_WEAK`). A
static link, static PIE included, does no walk.

Supervisor ruling 1 (an AArch64 `-no-pie` `ADRP`/`ADD` against a Weak0
key gets no refusal and no demand) is tested in `d25_weak_classes`.

Ruling 2 (a copy of an `STT_TLS` definition): when the scan's copy path
reaches an `STT_TLS` definition, that is the named internal error
`copies.rs` `refusal`. `copy_plan` also returns an internal error if it
meets one. The TLS mismatch itself is WP-043's.

## Thread independence of the `RELATIVE` fill (D-40)

The plan fixes `counts[u]`, the `RELATIVE` count of each unit, before
addresses. It reads them from `Demands.dyn_relocs` and the GOT plan,
with the units in address order. `fill_relative` splits the output
buffer into disjoint slices at the prefix sums of `counts` before any
worker runs. Unit `u` writes only slice `u`, and only records computed
from its own section's relocations and the link-time values. No unit
reads another unit's output or any shared mutable state; errors go to a
mutex and are sorted by unit. So the bytes are a function of
`(counts, unit)` alone, whatever the number of threads or the schedule.

A unit that makes more or fewer records than its count is an internal
error that names the unit, never a short table.

Tested at 1, 2, 3 and 8 threads on 20 000 records in 257 uneven units
(`mortar_image/tests/dynrel.rs`).

Cost for 10^6 `RELATIVE` records in 4096 units: 30.9 ms at 1 thread,
8.7 ms at 8 threads (release build, best of 5). This includes the
`arch.scan` role of each record and the encoding.

## Findings (rule id, proposed text)

- **F1, D-43**: "arch.md §4.3 rows `Pc` **and `Lo`** against
  `Shlib{func: false}` in `Pie` are `C`."
  - AArch64's `-fno-pic` read is `ADR_PREL_PG_HI21` (`Pc`) paired with
    `*_ABS_LO12_NC` (`Lo`). A PIE's page-aligned load does not change
    the low 12 bits, so the pair needs nothing more.
  - With only `Pc` as `C`, every such read was refused
    `relocation-incompatible` (measured).
  - lld copies on AArch64. GNU ld refuses the AArch64 PIE copy (add to
    §13.1: "GNU ld, AArch64: no copy in a PIE").
  - `AbsNarrow` against shared data in a PIE stays `E`.
- **F2, D-42**: GNU ld writes one `COPY` per key that names an
  allocation, aliases included (all at one address). lld writes one per
  allocation, and so does mortar. Add this to §13.1. The allocation's
  size is the largest `st_size` of its keys (stated; no reference
  differs here).
- **F3, D-25 / §13.1**: lld makes an undefined weak key dynamic only
  when the link has a shared object. Without one it writes no record
  for any row. Add this to §13.1.
- **F4, D-44**: `canonical-plt-in-pie` is reported per record (the ADRP
  and its ADD), like `text-relocation`. Only
  `weak-undefined-pc-in-pie` and the copy refusals are once per key.
  diag.md's table could say so.
- **F5, S-65 / D-32**: `.got.plt`'s three reserved words are written
  only when there is a PLT or IPLT entry (or x86's `GOT_BASE`).
  Otherwise there is no `.got.plt`, which matches lld.
- **F6, D-25, ScanOptions**: a strong key under
  `--unresolved-symbols=ignore` in a dynamic link is now `Weak0`, no
  longer `WeakDyn`. D-25 classes undefined **weak** keys only; the old
  blanket rule also caught these. dyn.md should say what such a key is
  (proposed: `Undefined` stays `Undefined`, and its uses need
  `--unresolved-symbols` D-row text).
