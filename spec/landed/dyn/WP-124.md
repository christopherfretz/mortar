# WP-124: TLS and IFUNC in a shared object (AArch64)

`spec/dyn.md` D-119 and D-121 for `Shared` on AArch64. The scan's
`shared_feature` refusal is gone: every TLS model but local-exec and the
library's own IFUNCs link. Nothing is relaxed in `Shared` (the a64 scan
already chose its demands by `is_exec`, `crates/mortar_a64/src/apply.rs:184`
`tls_demand`, so neither `mortar_a64` file changed). The GOT plan of a
shared object writes D-119's records; `DF_STATIC_TLS` is set iff an IE
slot exists; a preemptible IFUNC is exported `STT_GNU_IFUNC` at its
resolver and a non-preemptible one gets D-121's IPLT entry (WP-118's
`.rela.plt` path, unchanged). Executables and static links are
byte-identical (§6).

## 1. Measurement (this host, AArch64; GNU ld 2.44, lld 22, mold 2.37)

Library: an exported, a hidden, a static and an imported TLS variable
(`e`, `h`, `s`, `o`); IFUNCs exported, static, hidden (two translation
units), protected and imported.

## 5. Spec edits

- `spec/dyn.md` D-119: GNU ld on AArch64 links local-exec TLS defined in
  the library, exported or local (W19), and refuses it against an import.
- `spec/dyn.md` D-121: the protected IFUNC is measured (no longer
  "[unmeasured]").

## 6. Census, static-identical, verifier

- Census `-shared`: before `42 lines, 9 linked, 33 refused by name`; after
  `42 lines, 15 linked, 27 refused by name`. The six Clang 22 and Clang 19
  C++ AArch64 lines link and load; GCC's three C++ AArch64 lines now meet
  F3 (`versioned reference to __cxa_finalize bound in a shared object that
  is not needed`, WP-123's finding; GNU ld drops `libc.so.6` with
  `--as-needed`), which TLS hid before.
- `static-identical` (`baseline.on-aarch64.tsv`): 36 rows changed, all
  in this package's tests: 34 added (`tls-shared-{gd,desc,ie,cxx,le-refused}`,
  `ifunc-shared-equality`: libraries and hosts) and
  `refused-shared-target`'s rows renumbered (its TLS and IFUNC lines
  removed); no existing executable, static link or map changed. The
  x86-64 host's rows come from the hosted lane.
- The verifier judged every mortar library of the new tests clean. The
  rules that judged them: P-D25 and P-D26 (the record forms), P-D9,
  P-D10 (the `IRELATIVE` order), P-D17 (view B: interposers), R4 (view A),
  F2/F4 (IFUNC), with the base rules. Mutating one record of a mortar
  library is caught each time: a local `TLSDESC` or `TPREL64` addend (R4),
  a `TLSDESC` turned `r_sym` 0 (R4, P-D17), a `TPREL64` turned `RELATIVE`
  (R4, P-D9, P-D17), a local `DTPMOD64` moved (R4), a `DTPMOD64` turned
  `DTPREL64` (R4, P-D17), an `IRELATIVE` addend (F2, F4, P-D9), a
  `GLOB_DAT` of the exported IFUNC moved (P-D17).
- On references: GNU ld's spare `R_AARCH64_NONE` record in a GD library
  is P-D25 with no anomaly id (`tls-shared-gd`'s `xfail(bfd)`); lld's
  `IRELATIVE` before `JUMP_SLOT` is A20 (declared).

## 7. For WP-127 (x86-64)

Reused as is, through the `Arch` trait's `DynRole` types:

- `GotPlan::new_shared(arch: &dyn Arch, slots: &Slots, output: GlobalFlags, variant: PltVariant, bind_now: bool, kinds: &dyn KeyKinds, dynsym: &DynsymPlan, diag: &Collector) -> Result<GotPlan, Failed>`
- `GotPlan::record_addend(&self, r: &GotRecord, values: &dyn SlotValues) -> Result<i64, SynthError>` (RELA; i386's REL form puts the offset in place: WP-130)
- `SharedDyn { soname, symbolic, static_tls }`
- `DynsymInputs::preemptible_ifunc` (private; the D-121 export form)
- the LD pair's `DTPMOD` with `r_sym` 0 (`got.rs:456`): unreachable on
  AArch64 (TLSLD types are `Later`), x86-64's `R_X86_64_TLSLD`.

Per architecture: the scan's TLS demands in `Shared` (`tls_demand` of
`mortar_x64`, no relaxation when not `is_exec`), the `DynRole` to type
map, x86-64 TLSDESC (type 36) refused until a compiler emits it.
