# WP-123: the join — mortar links a shared object (AArch64)

WP-117 (resolve and scan), WP-118 (synth, layout, image) and WP-119
(D-117's analysis) joined in `crates/mortar` (record WP-110 §D, row
WP-123). `-shared` links on AArch64, the first target of WP-110 §D:
the default line, `-soname`/`-h`, Python's LDSHARED line,
`-Bsymbolic-functions`/`-Bno-symbolic`, protected visibility, `-z now`,
`-z defs`/`--no-undefined`, libraries that depend on libraries, weak
undefined keys, `__start_`/`__stop_`, constructors and destructors,
`dlopen`/`dlsym`, `--gc-sections` (D-124), gdb, lldb, ldd and
`eu-elflint --gnu-ld` (D-125). Every library mortar writes in the tests
is judged by the verifier's stage 3 (`mortar_plumb::verify_with` with
the line's files). Everything else a `-shared` line may ask for stays
refused by name (§2). Executables, static links and their maps are
byte-identical: `static-identical` shows 0 differ.

## 4. Findings

- **F2** (fixed here): D-111 item 2 read `RefFlags::FROM_OBJECT`,
  which resolve sets before the collection. Under `--gc-sections` an
  undefined key named only from a collected section stayed a
  `GLOBAL UND` entry; a host linked by mortar (or GNU ld) then refused
  the library. Measured on `-shared --gc-sections`, no `-z defs`:
  GNU ld and lld omit the entry; mold keeps it (and omits it under
  `-z defs`). A key with no relocation: mold and mortar keep it, GNU ld
  and lld drop it; one named only from `.debug_*`: GNU ld, mold and
  mortar keep it, lld drops it.
- **F2, executable side** (reported, not changed: existing outputs stay
  byte-identical): `-pie --gc-sections` where the only call to a shared
  function is in a collected section: mortar keeps the import and its
  `DT_NEEDED` (as mold); GNU ld keeps `DT_NEEDED` and no `.dynsym`
  entry; lld drops both (the driver's `--as-needed`). Valid either way.
- **F3** (refusal stays): crtbeginS's weak `__cxa_finalize` in a C++
  library whose only definition is in the C library, which
  `--as-needed` drops. GNU ld: `NOTYPE WEAK DEFAULT UND __cxa_finalize`,
  libc not needed; lld: `FUNC WEAK DEFAULT UND __cxa_finalize`
  (unversioned), libc not needed; mold:
  `FUNC WEAK DEFAULT UND __cxa_finalize@GLIBC_2.17`, libc needed. The
  census's gfortran `-shared` lines hit it (3 lines).
- **V1** (fixed, 1e41bd2): the verifier's option mirror lacked `-shared`
  and `-h`. **V2** (fixed in batch 5): P-D6's D-30 order on `Shared`.
  **V3, V5** (fixed in cede841): P-D5 on `.symver` + version-script
  libraries, P-D8 on an unversioned weak import. **V4**: not a verifier
  defect: mold binds a preemptible IFUNC locally (W20).
- A `.symver foo_v1, foo@V1` definition is refused as
  `foo@@V1` (the message shows `@@` for a non-default version).
- `spec/harness.md` line 1254 still says "until WP-123" of the
  `-shared` census lines.
- `odr_output` is `None` for `Shared` (`crates/mortar/src/front.rs:387`):
  ODR across a shared object's needs is WP-129's.
