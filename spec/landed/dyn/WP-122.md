# WP-122: copies of data a library binds locally (D-43a, P-D24)

Record of WP-122 (record `spec/landed/dyn/WP-110.md` §D, row WP-122;
request R-D43 of `spec/dyn.md` §18.4, P-R9 of `spec/plumb.md`). Status:
D-43a and P-D24 are **landed** (the spec's "planned: WP-122" words stay
as they are, per the group's rules).

An executable (`Exec`, `Pie`) that takes a `COPY` of a datum its library
binds to itself runs with two objects where the program believes in
one: the loader binds the program's references to the copy, the
library's code keeps its own instance (W30). The rule refuses the
writable case, warns on read-only and RELRO data (two equal constants),
and refuses what it cannot place.

## 2. Diagnostics

One kind, `copy-of-locally-bound-definition` (WP-116), at the key's
first demanding record, with two notes: where the datum lies and how
the library binds it.

| place of `st_value` | severity | first note |
|---|---|---|
| `PF_W` `PT_LOAD`, outside `PT_GNU_RELRO` | error | `{name} is writable in {file}: the program would write its copy and {file} read its own` |
| read-only `PT_LOAD`, or inside `PT_GNU_RELRO` | warning | `{name} is read-only in {file}: two equal copies` (diag.md §3.2) |
| no `PT_LOAD` | error | `{name}'s value {v} lies in no PT_LOAD of {file}: mortar cannot tell whether it is writable` |
| a `PT_LOAD` of the library ends past 2^64 | error | `a PT_LOAD of {file} ends past the address space: ...` |

Second note: `{file} is linked -Bsymbolic (DT_SYMBOLIC or DF_SYMBOLIC)`,
`the .note.mason table of {file} marks {name} NONPREEMPTIBLE`, or `the
.note.mason table of {file} does not parse ({why}): every definition is
taken as bound locally`.

Readings taken (no §E question covered them; each is the conservative
one, and each is a sentence added to D-43a and P-D24):
- a table that does not parse binds every definition (it can only add
  a refusal of writable data or a warning on a constant);
- a `PT_LOAD` whose `p_vaddr + p_memsz` overflows leaves every place
  unknown (refused); a `PT_GNU_RELRO` whose end overflows covers nothing
  (it can only turn a warning into a refusal); overlapping `PT_LOAD`s
  count as writable when any is;
- RELRO is the last `PT_GNU_RELRO` (glibc's reading, as `SharedFacts`
  keeps it); the verifier takes every one (the spec's "every"). With two
  RELRO segments the linker can only refuse where the verifier accepts.

## 3. Measurements

- Before implementing (record §D: "`mason_note` from a mortar `-shared`
  output once WP-129 lands"): not measurable, mortar writes no shared
  object yet. `mortar_meta` already had O-51's reader, so the rows are
  read now, from any table (the test producer's `meta` step writes one,
  as in the O-24 tests).
- q10b again, through mortar: the link test reproduces §F.5's split
  (`ro`/`rr` warned, `rw`/`bz` refused) on AArch64 and x86-64, with GNU
  ld's library; the references' programs print `two 3` (the program
  wrote 9, the library still reads 3), against `one 9` with the plain
  library.
- The host's libraries (`/usr/lib/aarch64-linux-gnu`, 236 files): 4
  carry `DT_SYMBOLIC`/`DF_SYMBOLIC` (gdk-pixbuf, pango x3). Only
  gdk-pixbuf exports data: a `-no-pie` program reading
  `gdk_pixbuf_version` (`.data`) is refused, one reading
  `gdk_pixbuf_major_version` (`.rodata`) warned, as `classify.py` says.
- Cost: a shared object that binds nothing locally gets no row; a link
  with no shared input allocates nothing (an empty boxed slice). A
  dynamic link pays, per `-Bsymbolic` library or library with
  `NONPREEMPTIBLE` rows, one row (its `PT_LOAD` list, typically 4-5
  entries of 24 bytes, and the sorted row indices), and per copied key
  one binary search. Nothing new is read: `SharedFacts` had it all.
- Existing links (mortar's stderr of every link logged through a
  wrapper): the full census, 468 lines, 468 pass, none refused or warned
  by the rule; the whole link corpus (263 tests, 2264 results, 0 FAIL),
  no existing test refused or warned, only the two new ones.
