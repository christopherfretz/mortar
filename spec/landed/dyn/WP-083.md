# WP-083: M2 spec errata; `.relro_padding` renamed `.pad.relro`

Record of WP-083. Scope: every open spec finding of M2 in one table,
applied with its evidence; the tests' comments and xfails that named
merged packages as pending; the one code change, the RELRO padding's
section name (layout L-156); both static baselines re-cut for it. No
other linker behaviour changed.

## 1. What changed

- **The rename.** `Synth::RELRO_PADDING` (`crates/mortar_core/src/layout.rs`)
  is named `.pad.relro`; `Layout::check`'s message names it. The Rust
  identifiers (`relro_padding`, `RELRO_PADDING`) name the concept and are
  kept. Tests that compare with lld or mold keep the references' name
  (`.relro_padding`) and map it (`crates/mortar_layout/tests/differential.rs`
  `synth_name`; `dynamic.rs` `classes` skips both names). What the old
  name cost is removed: the four `allow(mortar)` lines of
  `tests/link/dyn/tools/elflint-dynamic.test` and the `.relro_padding`
  entry of `crates/mortar/tests/support/plumb.rs` `ELFLINT_KNOWN`. Specs:
  `layout.md` (L-64, L-156 rewritten with the measurement of §3, Q3, the
  reference table), `model.md`, `image.md`, `harness.md`, `dyn.md` (D-60,
  D-71, Q5), `synth.md` (a bracket in a historical quote). Records under
  `spec/landed/` keep the old name.
- **Static baselines.** `tests/identical/baseline.on-aarch64.tsv`: 211
  rows, output and map digests only (§4). `baseline.on-x86_64.tsv`: the
  hosted lane's rows (§6).
- **Spec errata**: the table of §2, files and ids in §2.1.
- **Tests.** About 75 `tests/link` files lost the "mortar: AArch64
  WP-053 (JOIN-C), x86-64 WP-055 (X64-JOIN), in tests/link/xfails" blocks
  and their WP-042/054/056 variants (those packages are merged; the
  xfail lines are gone). Five reworded by hand: `init-fini-option`,
  `hash-style-sysv-refused`, `no-dynamic-linker-refused`,
  `versioned-export-refused`, `copy-dt-needed-refused`.
  `tests/link/xfails` keeps only WP-052's static-pie line (in flight);
  the empty WP-042 and WP-056 group headings are gone. No XPASS: every
  remaining xfail still fails for its reason. Comments that said a
  finding was "reported" or "not in dyn.md" now name the row that
  records it (§2), and three xfail reasons name their new W row:
  `tls-mismatch-shared` and `copy-tls-refused` W14, `tls-gd-unrelaxed`
  W15. `crates/mortar_scan/tests/dynamic.rs`' module doc no longer calls
  the dynamic output future.

## 3. The new name, measured

On AArch64 PIE and non-PIE programs with a library, and static AArch64
and x86-64 programs, linked by mortar with `.pad.relro`:

- eu-elflint `--gnu-ld`: "No errors" (the old name drew "expected RELR"
  and "wrong flags"). Without `--gnu-ld`: the same `.debug_str`/
  `.debug_line_str` `SHF_MERGE` complaints as with the old name.
- readelf, llvm-readelf 19 and 22, `objdump -h`/`-hx`, `llvm-objdump-22
  -h`: the name shown; output otherwise equal to the old name's but for
  column padding.
- gdb: `break main`, `run`, `bt`, `info sharedlibrary`; `maint info
  sections` shows `.pad.relro`. lldb-19: `break main`, `image list`; the
  section shows as `PT_LOAD[2]..pad.relro`.
- strip, `strip --strip-debug`, llvm-strip 19 and 22, objcopy,
  llvm-objcopy-22, `objcopy --strip-all`: each program runs and elflint
  says "No errors". (`--only-keep-debug` files do not run, as for any
  name.) Static stripped AArch64 and x86-64 (qemu) run; their remaining
  elflint complaints (`IRELATIVE` in `.rela.plt`, `__ehdr_start`) are GNU
  ld's stripped output's too.
- No loader reads the name; the verifier does not know it (no verdict
  changed, §4).

## 4. The baseline change is the name alone

Two `cargo xtask linktest --keep` runs of all of `tests/link` (mortar
only, three architectures), one with the old binary and one with the new:
369 PASS, 6 XFAIL, 2 SKIP each, the same results. A comparator walked both
kept trees. For an ELF output it required: the ELF header equal but
`e_shoff`; the program headers equal; every section header equal but
`sh_name` and a non-alloc `sh_offset`; every section's bytes equal, but
`.shstrtab` (equal after replacing the name) and the build-id note (a
content hash, recomputed by plumb §6.7); every byte before `.shstrtab`
equal. For a map: equal after the name, but the `.shstrtab` chunk 4
bytes smaller. Result: 6371 files identical, 512 ELF outputs renamed
only (510 with a different build-id), 512 maps name and size only. Six
tests compiled with `-g` give inputs that differ between runs; their 36
outputs were relinked by the new binary from the old run's inputs: all
name only. Run paths, gcc's temporary names and the `bin/` wrappers were
normalised or skipped.

`static-identical` on AArch64: 274 links, 211 differ, each in output and
map only; they are exactly the 211 driver links whose output has the
padding (the direct `ld` links have no RELRO run). Re-cut with
`--update`.

## 7. Questions for the supervisor

1. **D-46, a word against a copied key** (WP-054 5.4). mortar writes the
   key's symbolic record (as lld); GNU ld writes the copy's address with
   no record. Both run (`copy-reloc`, `exceptions-rtti`, `-fno-pic
   -no-pie`). The table has no `Copy` row. Proposed: "`Copy`: symbolic
   record, as `Shlib`" (keeps `LD_PRELOAD` interposition of the copied
   object). Not written: it decides between two correct behaviours.
2. **Unique definitions in a static `.symtab`** (WP-054 5.5). D-23 says
   an executable's own unique definitions stay `STB_GNU_UNIQUE` in
   `.symtab`; static links write them `STB_GLOBAL`
   (`crates/mortar_resolve/src/tables.rs`, `symtab_entry(d, p, false)`).
   Fixing it changes static bytes (and `EI_OSABI`).
3. **`STO_AARCH64_VARIANT_PCS` in `.symtab`** (WP-053 §4). Dropped
   (`syms.rs` `other = visibility & 3`), static links included; GNU ld,
   lld and mold keep it. Fixing it changes static bytes for inputs with
   variant-PCS functions.
4. **D-25's writable place** (WP-053 §4). The spec says the output
   section's `SHF_WRITE`; `section_writable` reads the input section's.
   They differ only when an output section mixes writable and read-only
   inputs; no test has one.
5. **W14-W17 in `plumb.md` §12's W table** and WP-050 1, 3, 12: WP-089's.
