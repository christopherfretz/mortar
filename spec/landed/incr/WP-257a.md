# WP-257a: the state stores what a section IS (kind, kept, collected, output section)

Base 7f09fdfc (`int/batch-17`). Rulings "After 255c" item 1 (F-3),
"After 255d3's M1" item 2 (option A), "After 255c3" items 1 to 3.

## 1. The encoding (as built; Milestone 1's first draft corrected, see F-1)

`SECTIONS` stays 76 bytes a row. **Growth: 0 bytes a row, 0 bytes in
total on every link** (protoc `-g`, cxx-large-g included: not measured
on them, none is possible: `SectionRow`'s width is the constant 76, its
three pad bytes now hold the facts). `place_chunk`/`place_offset` are
unchanged (a place-less row's `place_offset` stays 0).

| bytes | field | values |
|---|---|---|
| 4 | `anchor_kind` | unchanged |
| 5, low 4 bits | `kind` (was pad) | resolve's `SectionKind`, its `repr(u8)` code: 0 `Regular`, 1 `Nobits`, 2 `Merge`, 3 `EhFrame`, 4 `Note`, 5 `Debug`, 6 `Null`, 7 `Symtab`, 8 `Strtab`, 9 `Reloc`, 10 `Group`, 11 `Stack`, 12 `Excluded`, 13 `Meta`; 14, 15 `state-corrupt` |
| 5, high 4 bits | `bits` (was pad) | `KEPT` = 1: resolve's `state == Kept`; `COLLECTED` = 2: kept and not live (`Liveness::is_live`); bits 4, 8, or `COLLECTED` without `KEPT`: `state-corrupt` |
| 6..7 | `out` (was pad), `u16` | `Assignment::out(id)` for EVERY section (kept or not) as its `OUTSECS` row + 1, 0 for none (`OutOf::None`, `Consumed`, `Discard`); past `OUTSECS`' count: `state-corrupt`; an `OUTSECS` row past 65534 at the capture: `state-limit` (no state written) |

The decoder (`Rec::ok`, every row read) refuses an unknown kind or bit
and `COLLECTED` without `KEPT`; the facts' reader
(`format::section_facts`, which `StoredRows` calls) also refuses an
output section past `OUTSECS`, one for a kind that carries no output,
and a placed row that is not kept, live and assigned (P-1).

**F-1 (finding, bytes seen):** Milestone 1 drafted a placed row's output
section as its chunk's `CHUNKS.out`, checked against the assignment at
the capture. The check fired on the `file_front` g++ fixture (aarch64):
`.tm_clone_table` (file 3, section 7, `Regular`, `Kept`) is assigned
`OutSecId(8)` (`.tm_clone_table`) but placed in `Body(Part { out: 4 })`
(`.data`). So a chunk's output section is NOT the assignment's for every
placed section, and the explicit 16-bit `out` above replaced it (still no
growth). Who moves `.tm_clone_table` into `.data`'s chunk, and whether
any other reader takes `CHUNKS.out` for a section's assignment, is not
followed up here (not mine).

**For your ruling**: the 16-bit `out` caps `OUTSECS` at 65535 rows for an
incremental link (refused by name as `state-limit` beyond). The
alternative is a `u32` column (+4 bytes a row).

`Assignment::out` is stored for EVERY section: a COMDAT loser keeps its
output section (layout L-42/L-43), so a keeper change flips `KEPT` and
nothing else; a liveness flip flips `COLLECTED` (and, for a placed kind,
the place, as today).

The default row (all zero) is valid: a dropped `Regular` section with
no output section. Format 4 (`MORTARST`) is untouched: the facts are
written by the format-5 capture only (they need `Liveness`, which only
`Link5` carries); format 4's check now also requires the three fields 0.

### The answers, read

- `StoredRows::section_kind(s)` = `kind` (the name/flag rule goes).
- `StoredRows::section_place(s)` (P-1, a `bool`) = `KEPT` and not
  `COLLECTED` and an output section stored. This is P-1 exactly
  (`mortar_core::place::section_place`: kept, `OutOf::Out`, live). Today's
  answer ("placed") is WRONG for a kept live `Merge`/`EhFrame` section
  (P-1 yes, no place): a disagreement with `FrontRows` the new test shows.
- The split's `phase::Link::section` triple: a new accessor
  `StoredRows::section_fact(s) -> Option<(SectionKind, bool, Option<OutSecId>)>` (`pub`, `#[must_use]`; not a `Rows` method)
  (kind, kept, output section), from which `Link::section` is
  `kept && out.is_some()`; `reloc` is not stored (the split reads it from
  the object, as resolve does: ruling "After 255d3's M1" item 2 names
  `SectionFact { kind, kept, out }` only). A kept merge section that
  `--gc-sections` collected reads kept, its output section, `COLLECTED`.

### Seam types

No change to `mortar_core/src/incr.rs` (`StoredSection` is not the
split's source; the accessor is on `StoredRows`). `capture::file_rows`
(the per-file capture, mine) gets a `liveness: &Liveness` parameter
(its callers are tests only on this base). `Rows5` gets a private
field. Nothing else.

### The schema word

`state5::VERSION` 5 -> 6: a format-5 state written before this package
is refused as `state-version` ("format version 5, this mortar reads
6"), never read with zeros for kinds. (Format 4's `FORMAT_VERSION`
stays 4: its bytes do not change.)

### Who writes a `SECTIONS` row

| writer | where | the new fields |
|---|---|---|
| full link's capture | `capture::capture_in` (format 5: the facts in `Rows5.sections`, applied by `state5_rows` through `put_section_facts`) | written from `Resolution::sections[id]`, `Liveness`, `Assignment::out` (`capture::section_facts_of`) |
| per-file capture (an update's changed files) | `capture::file_rows` | the same, from the update's front |
| U-2 patch | `state5::write::plan_patch`/`patch` (`FileRanges::sections`) | copies the rows it is given, whole: no field of its own |
| compaction | `state5::compact` (`..r.clone()`; `OUTSECS` is copied in order, never renumbered) | kept as is; the `OUTSECS` row stays right (test below) |
| canon | `state5::canon` (the row's bytes) | compared as bytes: the new fields are in IN-78's equality |
| fillers | `compact`, `read.rs` (`file: NONE, ..default`) | the default row: valid |

**Not mine, named**: which files' `SECTIONS` the join rewrites
(`FileRanges::sections: Some`) is the join's (`update/mod.rs`). With
this package an UNCHANGED file's rows change when its COMDAT keeper
changes (`KEPT`) or liveness flips one of its sections (`COLLECTED`),
also for a `Merge`/`EhFrame` section whose place does not change. The
join must list such a file (today it must already for a placed
section's place). IN-78's equality (canon) catches an omission.

### IN-18e's sentence (proposed, not written into `spec/incr.md`)

"`SECTIONS` (format 5, version 6) also holds, in format 4's three pad
bytes, resolve's `SectionKind` and two bits (kept; kept and collected by
`--gc-sections`) in byte 5, and in bytes 6 and 7 the section's output
section (`Assignment::out`, for every section, kept or not) as its
`OUTSECS` row plus one, 0 for none. An update reads these, never a rule
over names and flags, and never a chunk's output section for a
section's."
