# WP-257a: the state stores what a section IS (kind, kept, collected, output section)

Base 7f09fdfc (`int/batch-17`). Rulings "After 255c" item 1 (F-3),
"After 255d3's M1" item 2 (option A), "After 255c3" items 1 to 3.

## 1. The encoding (Milestone 1)

`SECTIONS` stays 76 bytes a row. **Growth: 0 bytes a row, 0 bytes in
total on every link** (protoc `-g`, cxx-large-g included): every new
field sits in bytes the row already has and today leaves unused.

| bytes | field | values |
|---|---|---|
| 4 | `anchor_kind` | unchanged |
| 5 | `kind` (was pad) | resolve's `SectionKind` of the section, its `repr(u8)` code: 0 `Regular`, 1 `Nobits`, 2 `Merge`, 3 `EhFrame`, 4 `Note`, 5 `Debug`, 6 `Null`, 7 `Symtab`, 8 `Strtab`, 9 `Reloc`, 10 `Group`, 11 `Stack`, 12 `Excluded`, 13 `Meta`; 14..255 `state-corrupt` |
| 6 | `bits` (was pad) | `KEPT` = 1: resolve's `state == Kept`; `COLLECTED` = 2: kept and not live (`Liveness::is_live`, `--gc-sections`); any other bit, or `COLLECTED` without `KEPT`: `state-corrupt` |
| 7 | pad | 0 |
| 64..67 | `place_chunk` | unchanged: the chunk of a placed section, else `NONE` |
| 68..75 | `place_offset` | placed: unchanged (the offset in the chunk). **Place-less** (was required 0): the assignment's output section, `Assignment::out(id)`, as `OUTSECS` row + 1, 0 for none (`OutOf::None`, `Consumed`, `Discard`); a value past `OUTSECS`' count, or a high word not 0: `state-corrupt` |

The output section of a PLACED row is its chunk's `CHUNKS.out` (a placed
row has no free bytes for it). The capture checks, for every placed
section, that this is `Assignment::out(id)` and refuses the capture by
name otherwise, so the stored answer is the assignment's own datum,
verified when written; a reader refuses a placed row whose chunk has
`out == NONE` (`state-corrupt`). **For your ruling**: the alternative is
an explicit `out` column for every row (+4 bytes a row: 76 -> 80).

Row rules a reader checks (beside today's): a placed row has `KEPT` and
not `COLLECTED`; a row with an output section has a kind that carries
output (`SectionKind::carries_output`, the assignment's own invariant).

`Assignment::out` is stored for EVERY section, kept or not: a COMDAT
loser keeps its output section (layout L-42/L-43), so a keeper change
flips `KEPT` and nothing else; a liveness flip flips `COLLECTED` (and,
for a placed kind, the place, as today).

The default row (all zero) is valid: a dropped `Regular` section with
no output section. Format 4 (`MORTARST`) is untouched: the facts are
written by the format-5 capture only (they need `Liveness`, which only
`Link5` carries); format 4's rows keep these bytes 0 and its check
(`place_offset == 0` for a place-less row) stands.

### The answers, read

- `StoredRows::section_kind(s)` = `kind` (the name/flag rule goes).
- `StoredRows::section_place(s)` (P-1, a `bool`) = placed, or `KEPT` and
  not `COLLECTED` and an output section stored. This is P-1 exactly
  (`mortar_core::place::section_place`: kept, `OutOf::Out`, live). Today's
  answer ("placed") is WRONG for a kept live `Merge`/`EhFrame` section
  (P-1 yes, no place): a disagreement with `FrontRows` the new test shows.
- The split's `phase::Link::section` triple: a new accessor
  `StoredRows::section_fact(s) -> Option<(SectionKind, bool, Option<OutSecId>)>`
  (kind, kept, output section), from which `Link::section` is
  `kept && out.is_some()`; `reloc` is not stored (the split reads it from
  the object, as resolve does: ruling "After 255d3's M1" item 2 names
  `SectionFact { kind, kept, out }` only). A kept merge section that
  `--gc-sections` collected reads kept, its output section, `COLLECTED`.

### Seam types

No change to `mortar_core/src/incr.rs` (`StoredSection` is not the
split's source; the accessor is on `StoredRows`). `capture::file_rows`
(the per-file capture, mine) gets a `liveness: &Liveness` parameter
(its callers are tests only on this base).

### The schema word

`state5::VERSION` 5 -> 6: a format-5 state written before this package
is refused as `state-version` ("format version 5, this mortar reads
6"), never read with zeros for kinds. (Format 4's `FORMAT_VERSION`
stays 4: its bytes do not change.)

### Who writes a `SECTIONS` row

| writer | where | the new fields |
|---|---|---|
| full link's capture | `capture::capture_in` (format 5: the facts in `Rows5`, applied by `state5_rows`) | written from `Resolution::sections[id]`, `Liveness`, `Assignment::out` |
| per-file capture (an update's changed files) | `capture::file_rows` | the same, from the update's front |
| U-2 patch | `state5::write::plan_patch`/`patch` (`FileRanges::sections`) | copies the rows it is given, whole: no field of its own |
| compaction | `state5::compact` (`..r.clone()`; `OUTSECS` is copied in order, never renumbered) | kept as is; the `OUTSECS` row stays right |
| canon | `state5::canon` (the row's bytes) | compared as bytes: the new fields are in IN-78's equality |
| fillers | `compact`, `read.rs` (`file: NONE, ..default`) | the default row: valid |

**Not mine, named**: which files' `SECTIONS` the join rewrites
(`FileRanges::sections: Some`) is the join's (`update/mod.rs`). With
this package an UNCHANGED file's rows change when its COMDAT keeper
changes (`KEPT`) or liveness flips one of its sections (`COLLECTED`),
also for a `Merge`/`EhFrame` section whose place does not change. The
join must list such a file (today it must already for a placed
section's place). IN-78's equality (canon) catches an omission.

### Readers of `place_chunk`/`place_offset` (brief item 5) and what each assumes

| reader | assumes | after |
|---|---|---|
| `delta.rs` `pos` (~451) | `place_offset` read only through a chunk in range (`NONE` fails the lookup) | unchanged, sound |
| `delta.rs` `placed`, `present` (~474, ~985, ~1011) | `place_chunk != NONE` | unchanged |
| `delta.rs` touched chunks (~1476, ~1483) | gated on `place_chunk` | unchanged |
| `update/file_front.rs:372` | `(place_chunk != NONE).then_some(...)` | unchanged |
| `stored_rows.rs` `place` | gated on `NONE` | unchanged |
| `stored_rows.rs` `section_kind` | name/flags, `place_chunk == NONE` for `Merge` | reads `kind` |
| `stored_rows.rs` `section_place` | placed = P-1 | reads P-1's three facts |
| `capture.rs` placement reader (~2446), `state5/read.rs` (~973) | gated on `NONE` | unchanged |

No reader depends on `place_offset == 0` for a place-less row.

### IN-18e's sentence (proposed, not written into `spec/incr.md`)

"`SECTIONS` (format 5, version 6) also holds resolve's `SectionKind`,
whether the section is kept, whether `--gc-sections` collected a kept
one, and its output section (`Assignment::out`, for every section): a
place-less row's `place_offset` is that output section's `OUTSECS` row
plus one (0 for none); a placed row's is its chunk's `out`, checked at
the capture. An update reads these, never a rule over names and flags."
