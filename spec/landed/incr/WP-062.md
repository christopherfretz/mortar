# WP-062: slack and dead ranges, the linker's side (M7 S2)

Record of WP-062. It lays out an incremental-mode link with the slack of
`spec/incr.md` §5.6 and §6 (IN-30, IN-32, IN-33, IN-34a, IN-50, IN-51b),
records it in the state (format 2) and the map (`hole`, `dead`), and
replays it. The verifier's side (IN-60's checks, reading the new map
records) is WP-091. A plain link's bytes do not change
(`static-identical: 0 differ`).

## 1. What landed

- **Amendments** A–E (`layout.md` L-141, L-142, L-144, L-147;
  `synth.md` S-110, S-111) and `plumb.md` §3.2's `hole` and `dead`
  records.
- **Policy** (`mortar_layout/src/slack.rs`): `Slack::NONE` (a plain
  link: every function returns 0) and `Slack::INCREMENTAL`; region
  slack for L-143 sections, tails, packed capacity, the PT_LOAD
  reserve, debug size classes `m·2^k` (m in 8..15, at least 32) with
  IN-51b's neutral minimums, and the 9-byte neutral abbreviation table.
- **Layout**: `Staged.holes` and `Placement.holes`, sorted by
  `(chunk, offset)`, empty without slack; `check` judges them (inside
  the chunk's size, no overlap with a placement or each other).
- **`.eh_frame`**: per-file CIEs in incremental mode (IN-34a), padding
  CIEs (length − 4, id 0, version 1, augmentation "", code alignment 1,
  data alignment −4, return register 30 on AArch64 (16 on x86-64,
  8 on i386), `DW_CFA_nop`s); a hole of 4, 8 or 12 bytes is absorbed by
  the record before it.
- **Image**: debug holes hold neutral DWARF units (`mortar_image`
  `neutral.rs`); the abbreviation table hole is zero-filled.
- **State format 2**: table `HOLES` (kind 39, 24-byte rows: chunk u32,
  kind u8, 3 pad, offset u64, size u64), written after `LEAVES`, before
  `STRINGS`. A format-1 state still reads, as no holes (its 23 tables).
- **Replay** restores the holes and capacities; a hand-made `HOLES`
  row of kind `dead-*` makes the image write the dead range and the map
  its `dead` line (the dead writer's only way in until WP-063).

## 2. Map grammar (`plumb.md` §3.2)

```
hole <output-section> <offset> <size>
dead <output-section> <offset> <size> debug|fragment|cie
```

Both follow `define`. Ordered by output section (header order) and then
offset, never overlapping. A plain link writes neither; a first link
writes no `dead`.

## 3. Findings

1. **S-50 rule 1 vs the verifier (WP-091).** With per-file CIEs,
   crtbeginT.o's `__EH_FRAME_BEGIN__` (section-relative, value 0) and
   its two `R_AARCH64_ADD_ABS_LO12_NC` against `.eh_frame` resolve, by
   S-50 rule 1 ("whatever E holds"), to the start of the output
   `.eh_frame`: byte-checked, `__EH_FRAME_BEGIN__` = the output
   section's start. The verifier applies rule 2 and reports Y4 plus two
   R1 findings. This is the only verifier difference between plain and
   incremental-mode links of the aarch64 link-test corpus. It affects 50
   tests, and they all pass with `--no-plumb`. Tests filter exactly these
   findings (`tests/support/plumb.rs` `s50_rule1_waiting_for_wp091`).
2. **IN-51b: the abbreviation table is 9 bytes, not 8.** It needs the
   terminating 0 code. readelf reports "section not zero terminated" and
   "abbreviation number 1 which does not exist" with 8. Proposed: "the
   neutral table is the 8 bytes above followed by a 0 (end of table): 9
   bytes".
3. **IN-18a: the kind order.** HOLES is kind 39 but sits before
   `STRINGS` (kind 23). "Kinds ascending, `STRINGS` last" therefore holds
   only as "file order is the writer's fixed order, `STRINGS` last".
   Proposed: state the order as a list, not by kind number, and say a
   format-1 state (23 tables, no `HOLES`) reads as having no holes.
4. **IN-33 / IN-34a: no per-range `.eh_frame` slack in a first link.**
   `.eh_frame` is packed in the policy: its growth is capacity at the
   section's tail, so a first link has no `.eh_frame` hole. Padding CIEs
   appear only through an update (WP-063) or a hand-made `HOLES` row.
5. **IN-2 item 5: per-file CIEs.** An equivalence check must pass over
   CIE pieces present in one output only, and over a record whose length
   grew by 4, 8 or 12. R13's `equiv.py` needed both, and three more
   fixes unrelated to slack: `.tbss` units (whose range overlaps the
   next section), thin archive members, and the AArch64 erratum 843419
   (which instruction moves into a veneer depends on addresses; an
   incremental link and a plain one patch different sites).
6. **Neutral units are DWARF 5.** The image writes version-5 neutral
   units, whatever the version of the units around them. readelf,
   `llvm-dwarfdump --verify`, gdb and lldb accept them.
7. **A capacity given back is invisible in the replay bytes.** Code
   slack is trap fill both ways (I-41, L-141), so a mutation that shrinks
   a capacity leaves the bytes unchanged. The replay test mutates
   capacity into the next chunk and capacity below the size instead.
8. **plumb on main rejects unknown map records**
   (`crates/mortar_plumb/src/map/mortar.rs:461`). Until WP-091 the tests'
   verifier support retries without `hole`/`dead` lines.
