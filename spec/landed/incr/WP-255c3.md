# WP-255c3: `StoredRows`, no invented datum, the evidence that a stale row is seen, and scale

Base a33d1ed4 (`int/batch-17` with WP-255c). Rulings "After 255c" items 1, 2, 4.

## A: the narrowing (ruling 1)
Readers listed first (`grep` over every crate but `mortar_plumb`): a
`Valued::NoPlace` payload was read nowhere (`fill_parts`, `global_addr`,
the map's `value`, `address`, `kept_copy_value` match the case only; the
unit test `i124_no_place_is_not_live` built each reason); `Rows::def`'s
`InternalDef` was read nowhere (`def_value` reads `DEFINED`; `def_entry`
and `address` match `Defined`/`Undefined`). So, with no reader to stop at:
- `Rows::section_place(s) -> bool` (placed or not; P-1's rule is not a row).
- `Valued::NoPlace` (no payload).
- `Rows::def(id) -> Option<RowDef>`: `RowDef` (in `rows.rs`) is `Def` with
  `Internal` payload-free; `impl From<Def> for RowDef`. `FrontRows` maps
  `Assignment::def` through it; `StoredRows` answers `RowDef::Internal`.
  `Common`/`Shared` keep their entry (`StoredRows` derives `Common`'s from
  `MENTIONS`, a stored datum; it never answers `Shared`).
`StoredRows` no longer answers `NoPlace::Collected` or
`InternalDef::Provide`. Gate: static-identical, exactly the 12 known rows.

## B: the mutation tests (`crates/mortar/tests/rows_stored.rs`)
The fixture: `_start` loads `d` and `e` through the GOT (two `SLOTS` rows
of one list), reads `_end` (a `DEFINED` row), calls `f` (another file).
On a copy of the captured state (`state5::read::decode`, one datum
changed, `state5::write::encode`, written into the test's directory and
read back; the unmutated copy compares equal first), both targets:

| test `stored_rows_sees_a_stale_<x>` | mutation | seen as |
|---|---|---|
| `resolved_value` | `RESOLVED[d].value += 8` | `d`: value differs |
| `section_place` | `SECTIONS[f's].place_offset += 0x10` | `f`: value differs |
| `chunk_addr` | `CHUNKS[d's chunk].addr += 0x10` | `d`: value differs |
| `slot_index` | `d`'s and `e`'s `SLOTS` rows swapped | `d`: `Addr` slot differs |
| `defined_value` | `DEFINED[_end].value += 8` | `_end`: value differs |
| `definer_mention` | `d`'s and `e`'s definer `MENTIONS` rows swapped | `d`: `def` entry differs |

**Finding: the value comparison of 255c alone does NOT see two of them.**
A `SLOTS` swap changes no `S` (only slot addresses). A swap of the
definer's `MENTIONS` rows is consistent inside the state (the derived
index names the swapped row, which is `d`'s, so the value is `d`'s):
run without the `def` check, the mutated state compared equal on both
targets. The three-way comparison therefore now also compares, for every
key, the slot address of each kind, the PLT entry, the TLS module slot and
`Rows::def` (the entry included). The `def` check is what sees the second.

`stored_rows_value_of_gives_the_reason` (ruling 2): `RESOLVED[d].kind =
0xee`: `value_of(d)` is `Err(state-corrupt "RESOLVED: kind")`, never a
value, `failure()` holds it, the next key's `value_of` is `Ok` and clears
it; the comparison reports `d` "has no stored value: StateCorrupt".

## C: scale (`stored_rows_scale`, `#[ignore]`)
`WP255C3_WORKLOADS=<bench workload dir>`: the workload's `response.txt`
with its relative inputs made absolute, linked `--incremental` in the
test's own directory (the bench cache only read). Release profile without
LTO (`CARGO_PROFILE_RELEASE_LTO=false`, 16 codegen units), AArch64 host,
busy machine (load ~12). Keys are matched BY NAME (below).

| workload | keys compared | equal | `.symtab` | slots | fall-backs | disagreements | `new` median | `value_of` all keys, median |
|---|---|---|---|---|---|---|---|---|
| `fortran-static` (gfortran + libgfortran, static) | 8843 | 8819 | 682 | 44215 | 24 merge globals (`image`) | 0 | 36 µs | 9.4 ms (1.06 µs a key) |
| `cxx-medium-g-static` (protoc, `-O0 -g`, static) | 46562 | 46549 | 31342 | 232810 | 13 merge globals (`image`) | 0 | 187 µs | 122.9 ms (2.64 µs a key) |

Every fall-back is the named one (`update-not-implemented (image)`, a key
defined in a `Merge` section); within the cost model's 5 µs a key.

**Finding (for a ruling): the state's `SYMBOLS` numbering is not the
link's `SymbolId` numbering at scale.** In the fixtures they agree (255c's
test asserted it); here 8819 of 8843 (fortran) and 34367 of 46562
(protoc) globals sit at another row, the state's local-key rows follow the
globals (`.LANCHOR0`, `.LANCHOR4`: `LOCAL` rows 8843..8846), and three
front keys have no `SYMBOLS` row (`_DYNAMIC`, `_end`; protoc also
`_ZN9__gnu_cxx21zoneinfo_dir_overrideEv`). Not checked: whether the
capture renumbers by design or the in-process front (parsed WITHOUT
`--incremental`, `Env { slack, state5 }`, `Pool::new(2)`) numbers
differently from the real link. `StoredRows` itself is consistent: it
reads every key by its `SYMBOLS` row; a consumer that mixes the state's
numbering with a fresh front's `SymbolId`s (255e) must map by key
identity, not by index.
