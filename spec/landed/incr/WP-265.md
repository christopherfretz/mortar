# WP-265: the `DIAGS` producer; IN-77c form (a); state version 11

The record of the package (brief `briefs/wp-265.md`), written by its
agent. It closes WP-264 F-4's gap: a full link in incremental mode now
stores every warning it printed in `DIAGS` (49), with its subjects.

## The read before `finish()`
`mortar_diag::Collector::warnings(&self) -> Vec<(Key, Diagnostic)>`: the
warnings held so far, in report order (diag.md §6.2's `order`), cloned;
collection goes on. None under `--fatal-warnings` (made errors) or `-w`
(dropped). Unit test `collect::tests::warnings_before_finish_are_the_reports`.

## The producer
`mortar_incr::capture::diag_rows(inputs, gnu_warnings, four, warnings)`,
called by `incremental.rs` `state5_bytes` with `Collector::warnings()`
(only when there is a warning), through `Rows5::capture_diags` into
`state5_rows` (before `check_capture` and `compact::normalize`, which maps
the ids). Rows are in the capture's ids: a `FILES` row is its `FileId`, a
key its `SYMBOLS` row. The rows are built with their keys by name and the
names resolved in `state5_rows` AFTER the rows it adds for the options'
names (WP-247 item b: an `entry-not-found` key has no format-4 row), one
pass over the rows for every name wanted. `diag_rows` (the tests') does
the same over a format-4 state.
- **The update's state holds the same rows**: `Session::state()` captures
  the dormant rows (no warnings) whenever the link has a `.gnu.warning`
  holder, so the update path's identity check (state vs stored, DIAGS
  compared) does not fall back `(layout)` on every glibc static link;
  `state5_bytes` recaptures with the warnings when there are some.
- **Reference-site** (`gnu-warning` or `undefined-symbol` at phase 70):
  the key subject; for `gnu-warning` the holder of the key's first
  `.gnu.warning.<key>` section (`Front::gnu_warnings`), found by the
  first reference's relocation symbol (the warning's key `(70, file,
  section × 2^32 + record)`) and checked to give the warning's text. Each
  listed `referenced by` place is mapped to the ONE relocation of that
  section (by name) at that offset whose symbol is the key; the first
  must be the key's. `ref_count` is the diagnostic's own.
- **Dormant** rows (WP-221 §2.4): every warned key no warning names
  (`diags::dormant`).
- **Any other warning**: every file its place and context lines name
  (`File`, `Section`, `Symbol`, `Record` places), its key (the kind's
  symbol) when diag.md's column has `key`, `Link` when it has `link`.
  (The test's `row_of` gave no key subject for these; the producer is
  the more conservative.)
- **The check** (write time): each row reads back (`diags::diagnostic`)
  to its warning's model and renders (plain style) to its bytes; no two
  rows share `DIAGS`' key (phase, unit, seq, code, text).
- **Refused, by name** (`incremental: no state written: DIAGS: a warning
  <code>: <why> (IN-75a)`; the next link is full, `no-state`): a code
  with no subjects in diag.md's table; an ODR record finding (phase 40,
  tagged seq: its ODR key is U-8's); a versioned warned key; a file
  display two inputs share, when named; a reference that is not one
  relocation; two warnings of one key, code and text; a row that does
  not read back.

The test logic moved: `incr_diags.rs`' `stored()` takes the capture's
rows (`Full::rows`, from `diag_rows`) and asserts they equal its own
`row_of`'s; every `link()` also runs `--incremental=full` and asserts the
state's decoded `DIAGS` (ids mapped back by path and key name) are those
rows.

## Version
`state5::VERSION` 11: a version-10 state of a link that warned holds no
`DIAGS` row, which IN-75a reads as a link without warnings; refused
`state-version` (`symtab_rows.rs` `version_10_state_is_refused`).

## IN-77c form (a) (WP-264 F-3)
`floor.rs` does not implement it: its syncs are the test-only update
path's (IN-46/47 `in_place`, `by_copy`), not the full link's. Fixed in
`incremental.rs` `boot_stamp`: with a boot id, `META.boot_id` set and
`output-synced` 0 (form (b)); without one, `P` is opened and
`fdatasync`ed before the state is written and the bit is 1 (the id
stays zero); a sync that fails writes no state. Unit test
`incremental::tests::boot_stamp_forms`.
