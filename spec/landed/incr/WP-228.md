# Step 1

## 0. What needs a ruling

1. **R-1, the entry point and the seam change it needs (§3).** U-4's
   `fate()` refuses every `.debug_*` section (`Refusal::Debug`). Proposed:
   U-4 leaves debug sections to G-1 (a new `Fate`, no placement), and the
   join calls `debug::place` after U-4 and before `refill_set`, which
   writes the debug placements, holes and dead ranges into the same
   `LayoutDelta` (its existing fields). Exact diffs in §3.3.
2. **R-2, `.debug_str` needs a stored index (§2.2).** Without one an
   update appends the changed file's whole string set (protoc: 416 KB per
   file on average, 2.19 MB max) into a tail reserve of 254 KB
   (`size/32` of 8.14 MB): compaction (`debug-compaction`) on about every
   update of an average file. Proposed: a new key-keyed table
   `DEBUG_STRS` of 13-byte rows `(out u8, hash u64, offset u32)`, no
   references, dead strings uncounted until compaction. 1.0 MB on protoc,
   at most 30 MB on cxx-large-g (upper bound: all 2,368 objects). The
   alternative of reusing `FRAGS` rows (41 bytes) costs 3.2 MB / 95 MB.
3. **R-3, dead ranges are always written in neutral form** (§1.2),
   never left as compiler bytes (IN-53 not used by updates): the update
   then never reads an old input and every dead range is one plumb
   grammar. Measured equal to the full link in every configuration (§6).
4. **R-4, the `.debug_addr` rule as IN-51 states it is needed and
   sufficient** (§6: 126 readelf "Corrupt .debug_addr" checks in the
   variants without the `DW_AT_addr_base` unit; 0 of 68 `addrbase`
   outputs, whose 7 other readelf DIFFs are the loclists-at-the-end case).
5. **R-5, type units and `.debug_macro` groups (§4):** proposed rules
   replace `debug-unit-kind` for DWARF 4/5 type units when the changed
   file keeps or gains a group, and name a fall-back
   (`debug-comdat-keeper`) when a debug group's keeper is a changed file
   whose new version drops it. Needs a new reason name (IN-70's list).
   Measured: §6's 212 type-unit and macro outputs equal the full link.
6. **R-6, what WP-238 must give G-1 (§3.4)**, stated as a rule, not
   waited for.
7. **R-7, a FULL-LINK finding outside this package (§7.1):** a GCC `-g3`
   program of two or more files linked by mortar (plain, not only
   incremental mode) makes **gdb 16 crash (SIGSEGV) on `info macro`**:
   mortar writes I-47's all-ones tombstone into every `DW_MACRO_import`
   that names a dropped COMDAT copy of a `.debug_macro` group; GNU ld
   redirects them to the kept copy and gdb answers. Bytes compared
   (readelf `DW_MACRO_import - offset : 0xffffffff`, 4 imports in the
   fixture), not diagnosed further. Needs a ruling on I-47 for
   `.debug_macro` (proposal in §7.1); not fixed here.
8. **R-9, `.debug_loc` (DWARF 4, `-O2`) has no clean neutral form**:
   zeros pass gdb, lldb and verify (108 of 108) but readelf warns for
   every dead range (108 of 108). Choose: accept readelf's warning, or a
   fall-back `debug-loc` for a changed file with `.debug_loc` (GCC and
   Clang DWARF 4 at `-O1`+; the bench's builds are DWARF 5).
9. **R-10, new neutral forms for the spec** (tested in §6, plumb does not
   accept them until IN-51b and plumb.md §6.8 say so): `.debug_macro`,
   `.debug_macinfo`, `.debug_types` with a type-unit abbreviation table
   `01 41 00 80 40 09 00 00` (where the full link writes it: proposed in
   the same `ABBREV_TABLE` hole, 17 bytes instead of 9, when any input
   has `.debug_types`), and reuse in the middle of `.debug_loclists` and
   `.debug_frame` (0 warnings in 172 and 80 outputs).
10. **R-8, spec findings (§5):** IN-50 step 1 lacks the remainder
   condition; IN-51b's `.debug_macro`, `.debug_loc` forms are missing;
   IN-27's growth-step row makes every growth step a refill of almost all
   debug bytes (31.8 MB on protoc), which should be named; U-5 must drop
   the old version's symbols defined in debug sections (Clang AArch64
   `$d`; P-I3 found them in every emulated Clang output).

**A dead range that ends its section** (the removed file last, or a
contribution moved to the tail leaving the old one last) is proposed to
be cut: the section's `sh_size` ends at the last live byte and the range
joins the tail reserve. That removes readelf's two "unused bytes at the
end" warnings (`.debug_loclists`, `.debug_loc`); not tested.

Undefined-global referrers (Clang 22's vtable location) are the only
debug words of one file that depend on another file's layout: they are
`INDEX` rows (IN-25's "non-allocated units whose target is a global",
confirmed by WP-215 R.5: `INDEX` includes debug units) and are refilled
by IN-27's "a global's definition moved" row; the referring unit has the
same size, so it is refilled in place (§2.3).

## 2. The state (item 2)

### 2.1 Per (file, debug section)

Format 5 already holds what an update needs, nothing new for placement:

- **placement**: the `SECTIONS` rows of the file's debug input sections
  (`place_chunk`, `place_offset`, `size`); the run is the file's sections
  in that chunk, contiguous.
- **allotment**: the run's end plus the `DEBUG` (kind 2) hole that
  follows it (absent when the remainder is 0). Allotment = `Σ size +
  hole.size`.
- **dead ranges**: `DEAD_DEBUG` (kind 4) holes of the chunk; the neutral
  abbreviation table is the `ABBREV_TABLE` (kind 3) hole of
  `.debug_abbrev`.

Best fit (IN-50 step 2) reads `holes_in(chunk)`: every hole of the debug
chunk. That is O(contributions of the section): 125 rows on protoc,
≤ 2,368 on cxx-large-g, × 24 bytes = 57 KB per section at most. No index
is proposed for it. The tail reserve is `CHUNKS.capacity − size`.

### 2.2 `.debug_str` (IN-56)

Measured (§5.1): protoc's 125 `-g` objects carry 51.9 MB of `.debug_str`
in 780,524 strings, 76,971 distinct (8.14 MB, the output section). A
changed file's strings are mostly already present; to reuse them an update
needs, for each of its strings, the output offset of an equal string.

| design | per update | state | risk |
|---|---|---|---|
| no index: append the file's whole string set | 416 KB mean, 2.19 MB max appended; tail 254 KB: compaction on the first update of any file over 254 KB (p50 of debug files: ~200 KB, p90 320 KB) | 0 | IN-57 fires on nearly every update |
| scan the output's `.debug_str` per update | reads 8.1 MB (protoc), 252 MB (cxx-large-g estimate) | 0 | O(debug strings), not O(change) |
| **`DEBUG_STRS` rows (proposed)** | one lookup per string of the changed file; a hit is verified by reading the bytes at the offset in the output (no false merge on a hash collision); a miss appends | 13 B × distinct strings: 1.0 MB protoc, ≤ 30 MB cxx-large-g | none |
| `FRAGS` rows for `.debug_str` | the same | 41 B × distinct: 3.2 MB / 95 MB | none |

**What an unreferenced string costs:** nothing is counted. There is no
`FRAG_USE` for debug strings (a file's references would be 15.7 M rows on
cxx-large-g); a string that no live unit names any more stays, is not a
dead range, and goes at the next compaction (IN-57). The waste grows by
the strings an edit removes: a few hundred bytes per edit. IN-57's dead
byte count therefore excludes `.debug_str`/`.debug_line_str`.

**Exact proposal** (seam, not made): `format::kind::DEBUG_STRS = 57`,
key-keyed by `(out: u8, hash: u64)`, row `{ out: u8, hash: u64, offset:
u32 }` = 13 bytes, `hash` = `rows::name_hash(bytes, b"")` of the string
without its NUL; written by the capture for every distinct string of
`.debug_str` and `.debug_line_str`; `StateRows::debug_str(out, hash) ->
Rows<Option<u32>>`, provided body `Ok(None)` (a miss: appended, never
wrong). Patched by the update with the appended strings. Compaction
rewrites it whole. A DWARF64 offset is refused (`debug-compaction`).

## 3. Relocations of debug sections in an update (item 3)

### 3.1 The changed file's own debug words

Filled as the full link fills them (`spec/image.md` I-45..I-47, I-112):
a reference to a live section or symbol gets `S + A` from the update's
placement (`LayoutDelta::place_of`); one to a section that is not live
(collected, a dropped COMDAT copy, a discarded section) gets I-47's
tombstone for the referring section and class (0 for rnglists, loclists,
addr; 1 for ranges, loc; all ones elsewhere in ELFCLASS64; the aranges
tuple length 0). A reference into `.debug_str`/`.debug_line_str` gets the
string's output offset (existing or appended, §2.2). A reference to
another debug section of the same file gets that contribution's new
offset (they move together or not at all: §3.2).

### 3.2 An unchanged file's debug word naming a key that moved

- Within one file: when any section of a file moves, IN-27 refills all of
  its non-allocated units (they are not indexed). Same size, so **in
  place, always** (step 1 of IN-50 trivially; nothing is re-placed).
- Across files: the only ones are words naming a global (IN-25). Stored
  in `INDEX` (WP-215 R.5: debug units included). Patched by U-6's refill
  from the `INDEX` rows of the moved key (IN-27 row 3).
- **Count on protoc** (`measure.py` over the incremental link's 784
  inputs): debug relocations naming an undefined global: **0**; naming
  the file's own globals: 102 (IN-25's 104); so when one protoc function
  grows and its file's sections move, **0 debug sites in other files**
  are refilled; its own file is refilled anyway. On cxx-large-g's 2,368
  objects (Clang): 8 undefined-global debug relocations (2 defining
  files, max 5 per file). Clang 22 `-O2` adds one per vtable a file uses
  but does not define (the fixture's `_ZTV5Shape`), not measured at scale
  (no Clang 22 `-g` build here).

### 3.4 What G-1 needs from WP-238 (sections of unchanged files dying or reviving under `--gc-sections`)

Rule: **a section of an unchanged file that dies or revives is listed in
`LayoutDelta::killed`/`revived`, and its file's non-allocated units are
in the refill set (IN-27's liveness row, already the spec); G-1 then
refills that file's debug contributions IN PLACE, their words naming the
dead section get I-47's tombstone and those naming a revived section its
new address, computed from the update's liveness, never the stored one.**
Plus: debug sections are never gc roots nor collected by themselves
(I-6), except debug sections in COMDAT groups, whose liveness is their
group's election (§4), not reachability. Nothing else is needed: the
debug contribution's size does not change with liveness, so no
placement.

## 4. Type units and COMDAT debug sections (item 4)

Facts (fixture links, `tu/`): with `-fdebug-types-section` GCC 4 puts
each type unit in `.debug_types` in its own group; GCC 5 and Clang 5 put
them in `.debug_info` groups; Clang 4 in `.debug_types` groups. GCC `-g3`
puts each header's macros in a `.debug_macro` group (`wm4.<file>.<n>.<md5>`)
imported by offset from each CU's macro unit. The keeper is the first
file in link order (b's and c's copies: `discard … comdat`).

- **Type units** are found by signature only (`DW_FORM_ref_sig8`), and
  no other unit names one by offset. Rule: a type-unit group of a changed
  file that still defines it is placed with the file's contributions (it
  is one of the file's debug input sections); dead copies are neutral
  units (block form, the unit's version: 4 in `.debug_types`). If the
  keeper is a changed file whose new version **drops** the group, the
  next copy (an unchanged file's discarded section) must revive:
  **fall-back `debug-comdat-keeper`** (rare: a header type no longer
  used by the first file that used it).
- **`.debug_macro` groups**: imported by offset from every file's CU
  macro unit. With mortar's current I-47 tombstone (R-7) the importers of
  dropped copies hold all ones and never change; the keeper's own import
  points into its own copy. Rule: as type units, and
  **`debug-comdat-keeper`** when the keeper drops the group. If R-7 is
  ruled as redirect-to-kept-copy, every importer names the keeper's copy
  by offset, so a moved keeper copy would refill every importing file: then
  the rule is "a keeper's macro group never moves" (it stays in place;
  a growth that does not fit falls back).
- **How often**: the keeper is the first file in link order using the
  header. An edit that removes an `#include` or the last use of a type
  from that file triggers the fall-back; any other edit does not.
  Not measured on a real edit corpus.
- Tested (§6): the old file's groups renamed (as the old version's are
  its own in an update), so its type units and macro groups die with it
  and the new version's copies are elected as in a full link: gdb, lldb,
  verify and readelf equal to the full link in all 212 type-unit and
  macro outputs (lldb: but the 28 uninitialized-local lines). The
  keeper-drops-the-group case is not emulated (its fall-back is named).
  Fixtures: `EXTRA=-fdebug-types-section` and `EXTRA=-g3` (`-g3
  -fdebug-macro` for Clang) runs of `emulate.sh`.

### 5.2 The growth step

IN-27's row "a section of an unchanged file moved (growth step)" refills
all non-allocated units of every file with a section in a moved chunk.
A growth step of `.text` moves every later allocated chunk, so nearly
every file: **31.8 MB of debug bytes refilled on protoc** (all but the
strings), ~1 GB on cxx-large-g (*estimate*) — the cost of IN-57's
compaction without its benefit. Proposed: name it (`debug-compaction`
when a growth step moves chunks holding sections of more than a quarter
of the debug bytes' files), or rule that a growth step's debug refill is
accepted as is. Needs a ruling (R-8).
