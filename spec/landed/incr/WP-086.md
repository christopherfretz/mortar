# WP-086: the image follows the layout for `.eh_frame` and `.symtab`

Record of WP-086. Every plan the image writes from is now made from the
inputs, the command line and the final `Layout`: after a replay (IN-61)
or, later, an update, no table the front computed on its way to the
layout is a second source of truth. `EH_RECORDS` is a decision with a
CIE rule and named refusals (S-49); `SYMTAB_LOCALS` is held to the
symbol table's spans (S-88); the GOT, `.shstrtab`, the merged chunks'
order, `.symtab`'s patch rows and the erratum fixes follow the final
layout too, so IN-61's refusals are gone (the WP-061 review's F8 is
closed). No output byte of any link changed; the state stays format
version 1.

## 1. Each table, before and after (scope item 1)

"Read" is the code that reads the table when bytes are written. The
outcome is that of `replay_reproduces_and_each_table_matters`
(`crates/mortar/tests/incremental.rs:658`), which replays each mutation
with `--mortar-map`, runs the verifier on changed bytes and, for a valid
mutation, runs the program. Programs: asm (AArch64), asm-x86-64,
asm-x86-64-large (WP-084's `Prog::asm_x86_64_large`, after the merge of
main), c, cxx
(AArch64, GCC), e843 (AArch64 with `--fix-cortex-a53-843419`), thunks
(AArch64: two calls across 128 MiB of code through two range-extension
thunks in one island, named in `.symtab`; `Prog::thunks`).

| table (state) | writer | read, before | read, after | kind | outcome before | outcome after |
|---|---|---|---|---|---|---|

| dynamic `Slots` | `dynlink` | `DynTables` plans from computed slots | unchanged (WP-066, §4.3) | decision | no table (v1 is static only) | unchanged |

META, STAT, FILES, PROBES, OUTSECS, SYMBOLS, the identity part of
SECTIONS, LEAVES and STRINGS describe the inputs or the output; they are
not decisions.

What each static synthetic section is made from, after:

- headers, `.shstrtab`: the final placement and the assignment's names;
- `.note.gnu.property`: the inputs' notes and `-z` options;
- build-id: the option and the final bytes;
- `.eh_frame`, `.eh_frame_hdr`: `layout.slots.eh_records` and the inputs,
  addresses from the layout;
- `.got`, `.got.plt`, IPLT `.plt`, `.rela.plt` (static): `layout.slots`;
- `.symtab`, `.strtab`, `.symtab_shndx`: the inputs, the `.eh_frame`
  plan (S-76), `layout.placement.patches`, values from the layout; spans
  held to `layout.slots.symtab_locals`;
- merged chunks: `layout.merge`;
- erratum fixes: the final placement, slots and merged map.

Nothing else the image writes was found to come from outside the
layout, the inputs and the command line for a static link. The dynamic
plans are the exception (§4.3).

### 3.1 The dropped-FDE experiment (ruling 1)

Not shipped. With both S-41 checks in `check.rs` disabled, EH_RECORDS
(drop) still fails by name before any bytes exist: on asm, c and cxx
with S-88 ("SYMTAB_LOCALS: file 1's span is entries 1+7, its block 1+6":
the dropped FDE's section-relative mapping symbol is no longer counted,
S-76), on asm-x86-64 with "a synthetic plan made from the layout's
tables is not its chunk's size". With the span and size checks also
disabled, the image writer itself refuses it (".eh_frame_hdr: a
synthetic chunk of 20 bytes written at 0..28 into 28 bytes"). A dropped
FDE changes `.eh_frame`'s and `.eh_frame_hdr`'s sizes, which the stored
placement fixes, so no output reaches the verifier: four independent
named refusals stand in front of it. Showing plumb's finding would take
a same-size substitution, which a drop is not.

## 4. Findings and follow-ups

### 4.1 Spec findings
- **S-49** had no CIE rule for a list other than the computed one (now
  stated, with the refusals).
- **L-86** said indices are in chunk order but nothing held a layout to
  it; a swapped shndx was accepted and `.shstrtab` names went wrong.
- **IN-61** described refusals that are now gone (sentence replaced).

### 4.2 The patch-overlap gap
`Layout::check` does not check that patches do not overlap, because
`CheckContext` has no patch sizes: `fn patches`
(`crates/mortar_core/src/check.rs:1583-1599`) checks only their order
and that each starts inside a patch chunk. PATCHES +4 on e843
therefore reaches the verifier, which rejects it (PATCHES +4 on the
thunk program too). Follow-up for WP-064's row (supervisor): give
`CheckContext` the patch sizes (they are a function of the patch kind
and the arch) and refuse overlap by name.

### 4.3 For WP-066: the dynamic plans
`crates/mortar/src/dynlink.rs:295-395` builds `DynsymPlan`,
`GotPlan::new_dynamic` (`dynlink.rs:342`), `RelaPlan` and `DynamicPlan`
from the computed slots (`dynlink::plan` called at
`crates/mortar/src/front.rs:589`). The static `.got` is made from the
final layout (`front.rs:960`, `final_got` is `None` when `dynamic`).
When IN-12 admits a dynamic output, those plans must be made from
`layout.slots` after the replay in the same way.

### 4.4 Not verified
- The x86-64 host is covered by the hosted run only (green).
- Thunks on x86-64: none exist (a64.md §9 is AArch64's); the thunk
  program runs on the AArch64 lane only.

## 6. The state

The format stays version 1: no table left or changed shape. A state
written before this package (fixtures `incr-state-v1-51aa582`, AArch64
and x86-64) reads and replays to the same bytes
(`a_state_written_before_wp086_replays_identically`). Such a state's
`EH_RECORDS` and `SYMTAB_LOCALS` are the computed ones, so they pass
S-49 and S-88.
