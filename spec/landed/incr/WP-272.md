# WP-272: the lane judges the state's island rows against the output's bytes

HARNESS package (WP-271 adversarial review R-2, ruled BLOCKING; the
supervisor's rulings `briefs/wp-271-rulings.md`). Base 1bfce906 (batch 26
+ WP-267 P-1c). It comes before WP-273 (the update re-plans AArch64 patch
islands), which merges only after this judge is in the lane.

## 1. What was missing

`PATCHES` (18) and `REDIRECTS` (19) are excluded by (d0) on every hop it
does not judge exactly (`tests/l10/judge.py` `D0_PLACEMENT_TABLES`), and
the verifier finds redirects from the image, not from the state. So a
stale or wrong island row passes every check of its own hop and the next
update builds on it. Today every state is a front's capture, so the rows
are right by construction; WP-273 ends that.

## 2. What landed

- **`incr_state rows <state> <TABLE>...`** (`crates/mortar_incr/examples/incr_state.rs`):
  the decoded rows of `CHUNKS`, `PATCHES`, `REDIRECTS`, `SECTIONS`,
  `FILES`, `SYMBOLS`, `HOLES`, `OUTSECS`, one per line, in the state's own
  numbering (`read::decode`), strings as map string tokens. Public reading
  API only (`read::decode`, the row structs, `FileTable`); no new public
  function was needed. `SECTIONS` carries an `index` column, the section's
  index in its file: its row's place in the file's `FILE_INDEX` range
  (`SECTIONS.ordinal` is NOT the index: it is 0 for every section of the
  scenario below). `FILES` carries `base` (to pair one archive's
  same-named members with the map's member-header offsets).
- **The `islands` check** (`tests/l10/judge.py`, `islands_check`,
  `_islands`), after `duty`, on EVERY hop with a state (an update or a
  full link, the first link included). The sources:
  - rows: the state X wrote (`S'`), through `incr_state rows`;
  - input-section addresses: the map's `place` records (the update's own
    map, whose addresses the verifier judges), paired with `SECTIONS` rows
    by (`FILES` identity -> map file id, `index`); each must also equal
    the state's own `SECTIONS` place (chunk address + place offset) and
    size, else FAIL (a stale `SECTIONS` place is what the next update
    would compute F from);
  - chunk addresses: `CHUNKS`; each non-empty island must lie inside an
    executable section's bytes (section headers) and equal the map's
    `capacity` record for (output section, `p<k>`);
  - words: the output's section headers and bytes.

  **State to bytes.** Per `PATCHES` row: its chunk is a `Patches` chunk
  (tag 5) and the patch (8 bytes kind 2, 12 bytes a thunk) lies inside
  it; no two patches overlap. Kind 2 (843419): F = the address of its
  section + its site offset; word 0 is a load/store with an unsigned
  immediate (W4', a64.md §11.2), word 1 is exactly `b F + 4`; a patch
  with no redirect is that form or eight zero bytes (a dropped patch,
  ruling R-6). Thunk (kinds 0, 1): the three words decode as a64.md §9's
  `adrp x16; add x16, x16, #lo12; br x16`, and the target is the key's
  `.symtab` address + addend (kind 0, one global/weak definition of the
  name) or the key's `slot plt`/`slot iplt` record (kind 1). A local or
  versioned key, or a key with no single definition, is a FAIL that says
  it was not decoded (no guess). Per `REDIRECTS` row: F = its section's
  map address + offset; no two rows share an F; the word at F is `b` (a
  thunk's: `b` or `bl`) to its patch's address (the chunk's address + the
  `PATCHES` offset); a kind-2 patch names the redirect's own site
  (`PATCHES.section`/site offset = the row's section/offset).

  **Bytes to state.** An island word no `PATCHES` row covers is zero (a
  hole in an island included: no `HOLES` exemption, since the image
  writes zeros there, R-6). Every word of an executable `PROGBITS`
  section whose encoding is `b`/`bl` and whose target lies inside a
  non-empty island is the F of exactly one `REDIRECTS` row.

  Verdicts: `pass (<r> redirects, <p> patches (<u> unused, <t> thunks),
  <i> islands, <b> branches into them)`; `n/a (x86-64: no patch
  islands)`, `n/a (i386: ...)`, `n/a (no island chunk)`, `n/a (no
  island: <n> Patches chunks, all empty)`, `n/a (no incr_state)`, `n/a
  the link failed`; `FAIL <row/word>`. The rows are read in two steps:
  `CHUNKS PATCHES REDIRECTS` first; the rest only when the hop has an
  island to judge.
- **The lane's summary** (`tests/incr-update/lane.py`): `incr-update:
  islands (WP-272): pass:<a> FAIL:<b> n/a:<c> (<why>:<n>, ...)`.
- **A scenario**, `tests/incr-update/scenarios/islands_843419` (gcc,
  a64, nolibc, `--fix-cortex-a53-843419`): a 4096-aligned section whose
  words at 0xff8/0xffc/0x1000 are `adrp x1, far; ldr x2, [sp]; ldr x3,
  [x1, :lo12:far]` (a64.md §11.1's 3-word form), `far` 2 MiB further in
  `.bss`, so Page(far) − Q is outside s(21) and the site gets a patch in

  of the same objects gets the same complaint, so the shape was avoided
  rather than allowed.
- **Self tests.** `lane.py` `island_units` (run by `--self-test` and by

  (`--incremental=full`), judged clean and with one thing mutated (§3).

  chunk, an empty island; `parse_rows`; a thunk's decoding.
- `spec/harness.md`: the `islands` row of the incr-update table, the

## 5. Readings taken (for the ruling)

1. **"or (a thunk) a `PATCHES` row of kind 0/1 that the branch's
   relocation target names"** (the brief's bytes-to-state alternative)
   is not taken: model.md §4.4 `patches` gives every site, thunk or
   erratum, a redirect ("the redirect list `(SectionId, offset in
   section) → patch`, at most one per site"), so a `b`/`bl` into an
   island with no `REDIRECTS` row is a FAIL whatever its relocation
   names. The stricter reading; reading the input's relocations is not
   needed for it. If a thunk use without a redirect is meant to be legal,
   the check must read the input object's relocation at that word.
2. **A kind-2 patch with no redirect** passes when its words are the full
   form (L-116, a64.md §11.2's "as if it were used") or eight zeros
   (ruling R-6). WP-273 should say which one the update writes; the check
   accepts both.
3. **Island holes are not exempt** from "an island word no row covers is
   zero": R-6 says the image writes a dropped patch as zeros.
4. **The `capacity` cross-check** compares the state's island chunk with
   the update's own map; the verifier checks only the decision records'
   syntax, so this is state against map, not against bytes. A mismatch
   is a FAIL: one of the two is stale.

## 6. Not verified

- No lane hop at the base has a thunk (L-113's fast path holds for every
  lane program), so the thunk half (decoding, the `.symtab`/`slot plt`
  target) is tested only by the decoding unit, never against a real
  thunk.
- Data words in executable sections (`$d` ranges, literal pools) are
  scanned as if they were code: a data word that encodes a `b` into an
  island would be a false FAIL. None was seen; mapping symbols are not
  read.
- The judge was not run on protoc (WP-271 §1.3's island): its output and
  state are not in this package's scratch.
- `FILES`-to-map pairing for one archive's same-named members uses
  `base` = member header offset + 60 (GNU ar); a thin archive's
  duplicates would not pair and FAIL by name (none in the lane).
