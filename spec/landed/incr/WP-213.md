## X. Signatures and placements changed (old → new, why)

1. `WriteOps`: `mortar/src/update/write.rs` → `mortar_incr/src/ops.rs`
   (`state5::patch`/`compact` in `mortar_incr` take it; `mortar` depends on
   `mortar_incr`, not the reverse). Calls take `&File`/`&Path`; `flock`
   takes a `LockMode`; `create_new`, `copy_range` added (IN-77's C1 and
   IN-18f step 5 create and copy; nothing else could).
2. `RefillSet`: `mortar_incr/src/update/refill.rs` →
   `mortar_core/src/incr.rs` (`mortar_image::update::refill` takes it;
   `mortar_image` cannot see `mortar_incr`); re-exported from `refill.rs`.
3. `patch`, `compact`, `write`: `Result<_, IncrReason>` →
   `Result<_, WriteFailure>` (IN-77e: a write's failure fails the link; it
   is not a §7 reason and a reason cannot say "fail").
4. `compact(..., dir: &Path)` → `state_path: &Path` (the temporary is
   `dir(S)/.<base(S)>.mortar-compact` and the rename target is `S`: both
   need the path, not the directory).
5. `write(out: &File, state: &File, ranges, bytes, patch, ops, path:
   WritePolicy) -> Result<Tuple, _>` → `write(pair: &Pair, view:
   &StateView, ranges, bytes, patch, ops, policy) -> Result<Written, _>`:
   W2's aside name, C3's rename and the compaction need `P`'s and `S`'s
   paths (IN-77a: descriptors for I/O, paths for directory operations
   only); `state5::patch` needs the view; IN-76 "the report says which"
   path and IN-46b's `delta state compacted` need to be returned.
6. `refill(...) -> Result<_, Failed>` → `Result<_, RefillError>`
   (`Failed` holds diagnostics only: it cannot carry `input-changed`,
   IN-75, or the "until it lands" reason).
7. `plan(stored, layout, files)` → `plan(stored, layout, files,
   globals: &[GlobalChange])` (IN-49a: an update appends, removes,
   demotes and promotes globals; WP-211's inputs named only files' locals).
   `SymtabPlan` gained `moves` and `remap` (IN-49a: the area's last entry
   and the remapped values are read from the previous output, which U-6
   holds, not U-5).
8. `clone_capable(dev, meta: &Meta)` → `meta: &MetaRow` (format 4's
   `Meta` has no probe record; IN-76a's record is format 5's `META`).
9. `layout(..., changes: &[SectionChange])` → `&[SectionChange<'_>]`
   (the section's identity borrows its anchor and name).
10. `canon`'s "until" `Err(StateError::Version)` → `StateError::Version(String)`
    (today's variant carries its detail).

## F. Spec findings

- **F-1 IN-18e has no table of regions.** IN-72 item 2 (a file's region
  per `(O, c)`, overflow regions) and WP-211 §R.12 (`region` map
  records) need them per file; `HOLES` (key-keyed by chunk) carries no
  owner file. `LayoutRows::regions_of(file)` exists; where U-2 stores the
  rows is open. **Proposed text** (IN-18e, file-keyed row): "`REGIONS`
  (51: per file its regions, `(output section, category, ordinal, chunk,
  offset, capacity)`)".
- **F-2 IN-18e has no by-name index of `SYMBOLS`.** U-3 must map a
  changed file's new global names to rows (an added reference to an
  existing key); `KEY_REFS` is keyed by key id. Without an index this is
  a scan of `SYMBOLS` and `STRINGS`, which IN-18c forbids. **Proposed**
  (IN-18e, key-keyed): "`NAMES` (52: the L64 of a global's name and
  version, its `SYMBOLS` row)". `StateRows::find_key` is the accessor;
  until the table exists U-2's reader may answer
  `update-not-implemented (state5)`.
- **F-3 `DIAGS` is read whole by IN-75a** (rows are dropped by any
  subject; no single key finds them): `StateRows::diags` is documented
  as a scan, O(warnings), under 1 MB (IN-18e).
- **F-4 the patch before W1** (Q-1).
- **F-5 ODR keys have no stated numbering.** IN-18e names `ODR_CLASSES`'
  and `ODR_REFS`' key "ODR key" without saying how it is numbered;
  `OdrClassRow::key` is a `u32` whose numbering U-8 and U-2 settle.
- **F-6 `refill` is a detail word** (`refill_set`'s "until it lands",
  WP-211 §C) missing from the brief's list; added to §7's row.
- **F-7 `EDGES`' row width is not stated** (IN-18e's estimate is 17.5 B
  a section); `EdgeRow` is `kind u8, source u32, target u32, offset u64`
  = 17 B.
