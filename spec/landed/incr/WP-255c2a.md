# WP-255c2a: the clip plan (`Plan::for_clips`) and the written-bitmap rule

Base a33d1ed4 (`int/batch-17`). Design: `spec/landed/incr/WP-255.md` §9.1;
rulings "After 255b" item 4 and "After 255c" item 5.

## What was built

- `crates/mortar_image/src/clip_plan.rs` (new, one `pub mod clip_plan;`):
  `for_clips<R: Rows>(rows, clips, sections, parts) -> Result<Plan,
  ClipError>`, a free function (not an inherent `Plan::for_clips`: `Plan`
  lives in `plan.rs` and the function reads `rows`, `layout_plan` and
  `link` types; the name is the brief's otherwise). It makes `Input` rows
  through `rows::row_for`, the pads through `layout_plan::pads` (whole),
  the debug holes' `Bytes` rows through `layout_plan::hole_bytes`, and
  the structural chunks' `Bytes` rows from `parts.structure`; the rest is
  `Builder::finish`'s gaps. A clip that meets a `Merged`, `Synthetic`,
  `Patches` or `-r` chunk, or an input section named `.eh_frame`, is
  `ClipError::NotYet(kind, chunk)`. `ClipSection` = `(SectionId, (ChunkId,
  offset), SectionFront)`, by file offset.
- `check_written(plan, chunks, piece)`: §9.1's bitmap (`Vec<u64>` per
  piece). Marked: every byte of an `Input`/`Bytes`/`Synth`/`Merged` row
  and of a gap of a non-zero pattern (only `pads` makes those; AArch64's
  trap is `Pattern::ZERO4`, not `ZERO`); of a `Gap(ZERO)` only the
  derivable zero: no in-file chunk there, a non-exec chunk's tail between
  `size` and `capacity`, and **a non-exec `Body` chunk's bytes no section
  covers** (see "Finding"). An unmarked byte is `internal-error (image:
  clip byte {offset:#x} written by no row)`.
- `layout_plan.rs`: shared helpers `is_member`, `member_front` (the body
  of `from_layout`'s member loop, moved, unchanged), `abbrev_offset` and
  `hole_bytes` (`debug_holes`' body, moved, unchanged); `pad_views` is
  `pub(crate)`.
- `link.rs`: under `debug_assertions`, `refill_ranges` runs
  `check_written` over each of its pieces (the whole plan: every lane and
  `incr-update` fixture is evidence that the derivation rule holds for a
  whole plan); `clip_plan_of` (the inputs computed from the `Link`, what
  255e takes from the state), `refill_clip_plan(link, ranges, edit)` (the
  clip filler, a test path until 255e: `fill_range` over the clip plan's
  pieces with the bitmap; `edit` is the test's hook), `ClipFill`, and
  `refill_ranges_for_test` (a `#[doc(hidden)]` wrapper so the test outside
  the crate reaches `refill_ranges`).

## The data `ClipParts` takes (for the supervisor's ruling)

| datum | why | the state's source for 255e |
|---|---|---|
| `target` | `Builder`, `pads`, the neutral unit's address size | the arch |
| `chunk_views`, `seg_views` | `pads`, whole | `CHUNKS` (+ `OUTSECS` names for `.init`/`.fini`), `SEGMENTS` |
| `separate_code` | `pads` | the option |
| `holes: &[(Hole, name)]` | the debug holes of the chunks a clip meets, with the chunk's output section name (the neutral unit's form) | `HOLES` + `OUTSECS` |
| `abbrev: u32` | the neutral abbrev table's offset in its section, a whole-placement fact (`debug_holes` found it over every hole) | `HOLES`' `AbbrevTable` row + `CHUNKS` (or stored once) |
| `structure: &BTreeMap<ChunkId, Box<[u8]>>` | the header chunks' bytes, from 255b's `write_structure` | 255b's writer on `SEGMENTS`/`CHUNKS`/`OUTSECS`/`META` |
| `proof` | `row_for` | the per-file front (255d) |

Not in the clip plan (attachments the whole plan has): `paths` (a
diagnostic names `<file N>`), `sealed` (the build id's note is a synthetic
chunk: `NotYet`), `deferred_order` (`refill_clip_plan` computes it over the
clip plan with the link's `deferred_orders`; 255e needs its own source).
`file_size` is derived from `rows.chunks()`; the window is `IMAGE_BLOCK`.

## Finding: §9.1's "only places a whole plan's Gap(ZERO) can be" is incomplete

A non-exec `Body` chunk holds several input sections, and the alignment
padding between them is a `Gap(ZERO)` of the whole plan that is neither
"no chunk" nor a tail. The bitmap derives it as zero (I-41). The cost: a
clip plan that MISSED a section of a non-exec body chunk (the caller's
`sections` list incomplete) fills it with zeros unseen by the bitmap; only
the rows-equal test (and the leaf/output hash) stands for it. Inside an exec
chunk a missed section is trap fill (the pad covers the whole chunk), also
unseen by the bitmap: the bitmap catches missing pads, structure, holes
and non-body rows, not a missing `Input` row.

## Tests (`crates/mortar/tests/clip_plan.rs`, AArch64 and x86-64)

- `clip_plan_rows_equal_the_whole_plan_clipped`: U-6's three files
  (b.o with 4 MiB of data), with c.o's function padded by 0 and by 0x3000
  (the pad fixture); cases: inside one section, a section's edge, two
  windows, the code gaps (between a.o and c.o and the `.text` tail to its
  capacity), the headers, several at once. The clip plan's pieces are
  `refill_ranges`' pieces, and over each piece the rows are the whole
  plan's, unit for unit (indices resolved).
- `clip_plan_fills_every_byte`: the same cases' bytes equal
  `refill_ranges`'; a pad row (code gap) and the ELF header row turned into
  `Gap(ZERO)` by the hook are the internal error at their first clip byte;
  a clip over `.symtab` is `NotYet(Synth, .symtab)`, over the merged
  strings `NotYet(Merged, chunk)`.

Not tested: debug holes in a clip (no `-g` incremental fixture with holes
here), a clip over an input `.eh_frame` in a body chunk, a `Patches` chunk.

## A plain link pays nothing

It never calls `for_clips`/`check_written` (both are reached only from
`refill_ranges`, the update path, and `refill_clip_plan`); `from_layout`'s
loop calls the moved helpers with the same work (the hole's chunk name
is still read for a debug unit only). `static-identical` shows no new row.
