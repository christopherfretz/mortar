# WP-255c: `Rows` from the stored state (`StoredRows`)

Base dbe047c4 (`int/batch-17`). Design: `spec/landed/incr/WP-255.md` §2.1,
§9.3, §9.5; WP-255b's `Rows` (34 methods) as ruled ("After 255b", item 2).

## M1: the source table (committed before the implementation)

The IDENTITY case: an UNCHANGED file of the state, the stored placement as
it is (no layout delta). `SV` is `StateView` (`mortar_incr::update::view`),
`SL` is `StoredLayout` (`mortar_core::incr`). "whole" / "row" / "range" /
"key" are IN-18e's cost classes as `view.rs` names them. Every read that
fails, or that finds a row out of range or a kind it does not know, makes
the method answer `None` (as `FrontRows` does) AND records the first such
reason in `StoredRows` (`state-corrupt` with the table named, or
`update-not-implemented (image)` for a fall-back); `StoredRows::value_of`
returns that reason instead of a value. Never a default value.

No row is "no source" for a global's value. The fall-backs that a GLOBAL's
`value` can reach: a key defined in a `SHF_MERGE` section without a place
(6, 10: §9.3's class (d)), a key defined in an input `.eh_frame` (18). Every
other fall-back is a local's (the file's own front, 255d).

### Signatures that force O(program) work on a state source
- `chunks() -> &Column<ChunkId, Chunk>`: O(chunks), a whole-class table
  (tens to a few thousand rows); built once. **Not narrowed.**
- `global(id) -> Valued`: computed per key on demand; `FrontRows` keeps
  its parallel cache. **Not narrowed.**
- `got() -> &GotPlan`: O(slots) once per update (`SLOTS` is whole-class).
  `value` reads it only through `plt_address` and `iplt_address`, the slot
  formula through `got_offset` and `iplt_word`. Proposed narrowing (NOT
  made here; for a ruling): replace `got()` by
  `fn plt_address(&self, key: SymKey) -> Option<u64>`,
  `fn iplt_address(&self, key: SymKey) -> Option<u64>` and
  `fn slot_offset(&self, kind: SlotKind, index: u32) -> Option<u64>`,
  each answerable from one `SLOTS` lookup plus the region counts. Until
  ruled, `StoredRows` builds the plan once.
- `name(key) -> &[u8]`: a borrow forces the state source to keep the bytes;
  `Cow<'_, [u8]>` would not. Kept (bounded by the keys read).

## M2: `StoredRows` (`crates/mortar/src/update/stored_rows.rs`)
`StoredRows::new(view, stored, arch, got_output, variant)`: the whole
tables (`CHUNKS`, `SYM_PLACE`, `DEFINED`, `PATCHES`, `REDIRECTS`,
`LAYOUT`) into a `mortar_core::layout::Placement` (its `place` column
empty), so `defined_of`, `sym_place_of` and `redirect_of` are the full
link's own lookups; the `.got` plan by `GotPlan::new` over a `Slots`
rebuilt from `SLOTS` (+ `LAYOUT.bits` `TLS_LD`). `StoredRows::value_of(key)`
is `rows::sym` over it, or the first reason a read could not answer. No
signature of `rows.rs` changed; no `dyn Rows`; no new dependency edge.

Findings (for a ruling):
- **F-1, the `.got` plan's two inputs are not rows**: the scan's output
  flags (`GOT_BASE`, with `_GLOBAL_OFFSET_TABLE_`'s rule of
  `front::got_base_defined`) and the PLT variant (the merged properties).
  The caller gives them; the plan they make is checked against the stored
  `.got`, `.got.plt` and `.plt` sizes (`state-corrupt` otherwise). Proposed:
  store both (one bit and one byte of `LAYOUT`/`META`), or the narrowing
  above.
- **F-2, an internal key's `InternalDef` payload is not stored**: `def`
  answers `Def::Internal(Provide { conditional: false })` for every
  `INTERNAL` key; no formula of `rows.rs` reads the payload (`def_value`
  and `address` read `DEFINED`). A future reader of the payload would read
  a wrong one: for a ruling (store `DEFINED.kind`'s variant, or narrow
  `def` to a payload-free kind).
- **F-3, the P-1 reason is not stored**: a section without a place answers
  `NoPlace::Collected`; `value` reads only whether there is a place
  (`fill_parts`).
- **F-4**: a dead `SHF_MERGE` section and a split one are the same row
  (place `NONE`); both are `Merge` and take §9.3's fall-back.
- An output with `.dynamic` is refused by name in `new`
  (`update-not-implemented (image)`: its plan is `dynlink`'s); so
  `copy_of` is `None` and `Shared` definitions fall back.
- `pub mod stored_rows;` (not `mod`): the test file reaches the type.

## M3: `stored_rows_value_every_global` (`crates/mortar/tests/rows_stored.rs`)
An incremental-mode full link in this process (`mortar::invoke_in` with
`--incremental`) writes the output and its format-5 state; the same link's
front is rebuilt in this process (`Env { slack, state5 }`) for
`FrontRows`. For every global `SymbolId`: the names agree (the state's
numbering is the link's), `value::<FrontRows>` = `value::<StoredRows>`
(the whole `SymValue`), and for a live non-IFUNC key in `.symtab` its
`st_value` (TLS: minus the TLS block's start). A key without a stored
value must be defined in a `Merge` or `.eh_frame` section and answer
`update-not-implemented (image)`.

| fixture | AArch64 keys / equal / `.symtab` / fall-back | x86-64 |
|---|---|---|
| U-6 (asm, + a global `gstr` in `.rodata.str1.1`) | 4 / 3 / 3 / 1 | 5 / 4 / 3 / 1 |
| C: TLS, IFUNC, merged-string global `gmsg`, global pointer to a literal | 8 / 7 / 6 / 1 | 9 / 8 / 6 / 1 |
| C++ `-O0`: inline `h`, `S<int>::v`/`get` COMDAT in two files | 5 / 5 / 4 / 0 | 5 / 5 / 4 / 0 |
| kiln/hod: inline `h` COMDAT in two files | 4 / 4 / 4 / 0 | 4 / 4 / 4 / 0 |

The fall-backs are exactly the merge globals (`gstr`, `gmsg`).
