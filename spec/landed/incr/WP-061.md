# WP-061 stage A: the link state

Record of WP-061 stage A. It covers the state's format (`spec/incr.md`
IN-18a, IN-18b), the writer in an incremental-mode full link, the
validating reader, stamps and the stat rule (IN-21, IN-22, IN-22a), the
options and modes (IN-10, IN-11, IN-12), and the replay hook (IN-61).
Amendments 6 and 8 of `incr.md` §9 are now text in `spec/model.md`
§7.3 and §7.2. There is no update path yet: `--incremental` links in
full every time, and the reason it gives is `update-not-implemented`
once a valid state exists.

## 1. What landed, by crate

- **`spec/`**
  - `incr.md` IN-18a: the bytes of format version 1. It gives the
    64-byte header, the 40-byte table records, tables 1-23 with their
    row layouts, and the order of the reader's checks.
  - `incr.md` IN-18b: the normalized plan, whose items are the `C`, `O`
    and `I` lines, and what it excludes.
  - `incr.md` IN-22: the content hash, an L128 tree over 4 MiB blocks.
  - `incr.md` IN-22a: the stamp directories, STAT trust, and the
    `st_dev` encoding.
  - `incr.md` IN-12: every output kind other than a static executable
    is WP-066's.
  - `incr.md` IN-61: the hook is a library function, `replay_link`.
  - `incr.md` §7: the row `update-not-implemented`.
  - `model.md` §7.2: IN-25's liveness graph. §7.3: dead ranges and (C).
  - `cli.md` §3.13: the incremental options.
  - `diag.md`: three kinds, a §3.2 bullet, and the area sentence.
- **`mortar_cli`**
  - `Plan::incremental` and the rows of the incremental options. The
    supported rows are `--incremental[=full|update]`,
    `--no-incremental`, `--incremental-state` and
    `--incremental-report`.
  - The refused rows are `--incremental-write`, `--incremental-sync`,
    `--incremental-verify` and `--incremental-changed`.
  - `docs/status/options.md` was regenerated.
- **`mortar_diag`**: the kinds `incremental-not-reproducible`,
  `incremental-unsupported` and `incremental-update-failed`.
- **`mortar_input`**: the store's content hash is the spec's L128 block
  tree. This adds the dependency edge `mortar_input` → `mortar_digest`.
- **`mortar_image`**: `LinkOptions::keep_leaves`, and
  `Written::{leaves, sealed, file_size}`. A plain link keeps no leaves.
- **`mortar_incr`**
  - `format`: the writer, and the validating reader with named reasons.
  - `stamp`: stamps, the probe, the stat rule, and the output binding.
  - `capture`: the state of a link in identity terms, and its replay.
- **`mortar`**

  - `front.rs`: the `Env::replay` hook, before `layout.validate`.

  - `examples/incr_roundtrip.rs`: the corpus round trip, and the

## 2. Evidence

- **Tests.** `crates/mortar/tests/incremental.rs` has 8 tests. Unit
  tests in `mortar_incr` cover the format round trip, mountinfo, the
  device numbers and the rule. Rows were added to the options audit.
- **Damage sweep.** The reader sees every byte of the state flipped 3
  ways and every truncation.
  - Of 14,526 single-byte flips, 14,525 are refused by name. The one
    accepted is the updating flag (header byte 12, bit 0), which is a
    valid state.
  - 20,000 random overwrites of 4 bytes cause no panic.
- **Replay mutations.** One mutation per non-empty decision table.
  Each mutation either changes the output or fails the link.
  - Tables mutated (C and C++ programs): CHUNKS, ORDER, SEGMENTS,
    SECTIONS, FRAGS, SLOTS, EH_RECORDS, SYMTAB_LOCALS, SIZES, DEFINED,
    SIZED and LAYOUT.
  - SYM_PLACE, PATCHES and REDIRECTS are empty in these programs (no
    copy relocations, no thunks).
- **Corpus round trip.** A wrapper as mortar under `cargo xtask
  linktest --linker bfd,mortar`, on all three targets. Each link ran
  with `--incremental=full` first and then plain.
  - Results: 156 static links gave identical bytes. Each state decodes
    and re-encodes to the same bytes, and its replay writes the same
    bytes.
    - aarch64: 53
    - x86_64: 52
    - i386: 51
  - 146 AArch64 links are PIE or dynamic and gave
    `incremental-unsupported` with no state: 105 `-pie`, 41 dynamic.
  - 0 differ, 0 replay failures. The linktest itself was 497 PASS,
    0 FAIL.
- **Stamps.** Measured on the workspace (virtiofs) and on overlay
  `/tmp` with `MORTAR_INCR_STAMP_DIR`.
  - Case A (`stamp_rule.py`): 400 rewrites right after the read, stale
    0.
    - Workspace: 0 racy, because every rewrite changed the tuple.
    - Overlay: 392 racy, all hashed.
  - Case B with `state_tick.py`: 200 updates, own output clean 200,
    unbound 0, on both file systems. The old rule's fall-backs were 0
    on both in these runs; the review had measured 39 and 60 of 200.
  - The probe passes on both file systems.
- **Gate.** `cargo xtask ci --quick` ends with `[ci] ok`, and
  static-identical reports 219 links with 0 differ.
- **A plain link does not pay.** Main 8f73db0 against this branch,
  both release builds with both binaries on overlay `/tmp`, interleaved
  runs:

  | workload | main | branch |
  |---|---|---|
  | hello-c-static, 41 runs | 13.0 ms | 13.0 ms |
  | hello-cxx-static, 21 runs | 26.3 ms | 26.7 ms |
  | synthetic-objects-static, 11 runs | 227 ms | 232 ms |
  | cxx-medium-g-static, 11 runs | 183 ms | 184 ms |

  - The spreads overlap, and RSS is equal within 0.5%.
  - The outputs are byte-identical, at default threads and at
    `--threads=1`.
  - The store's new hash alone (main plus the `mortar_input` change)
    is within noise. In a microbenchmark, `l128` runs at 25 GB/s
    against 34 GB/s for the old `hash_bytes`.
  - `cargo xtask bench --check` against the 12-core baseline exits 1.
    - The baseline is from WP-036, and the run was marked noisy.
    - It reports OUTPUT CHANGED for every static workload, which comes
      from packages merged since that baseline: this branch's outputs
      equal main's.
    - It reports `synthetic-objects-static` at `--threads=1` as
      REGRESSED (memory). The A/B gives 221.1 against 220.8 MiB.
  - Running a binary from the virtiofs workspace adds about 0.7 ms to
    `--version` alone. Compare binaries on the same file system.

Workload `cxx-medium-g-static` (protoc of protobuf 3.21.12, `-O0 -g`,
static). The output is on overlay `/tmp`. Median of 9 interleaved runs,

| `--incremental=full` | 0.528 s (0.465-0.605) | 301 MiB (298-305) |

|---|---|---|

| STRINGS | | 6,786,501 |

The extra 273 ms of an incremental-mode full link, from a temporary

| step | time |
|---|---|

| capture of the tables | ~87 ms |
| input member hashes | ~70 ms |

The hashes run on one thread, and so does the rest. No optimisation is
in this stage.

## 4. Findings and open questions

- **IN-22.** "L128 of the file" is now a block tree, so that a file can
  be hashed in parallel and by range. The text is in the spec.
- **IN-22a.** The probe needs a tick between the metadata change and
  the write, and it must take c2 before it restores the mtime. The text
  is in the spec.
- **diag.md §2.1 has no note severity.** `incr-full-link` is therefore
  a report line, not a diagnostic kind (ruled; §2.1 now says so).
- **IN-61.** The hook is a library function, not an environment
  variable.
- **IN-12.** Any `-T` is treated as unsupported, which is conservative.
  A static executable that has shared inputs warns after the link that
  incremental mode is unsupported.
- **IN-20.** The state is built in memory, not streamed (ruled for
  stage A; IN-20 amended: stage B measures the peak and decides).
- **EH_RECORDS and SYMTAB_LOCALS are not read by the image.**
  `.eh_frame` and `.symtab` are written from the front's plans, not
  from `Layout.slots`.
  - The replay therefore refuses a stored list that differs from the
    computed one.
  - A stage-B update must keep the two equal, or the image must read
    the layout's lists. This touches "the image is a pure function of
    the layout".
- **The fragment ordinal scheme** and the reserved kinds 32-40 for the
  deferred tables, as written in IN-18a.

## 5. The adversarial review (`briefs/reviews/review-061-state.md`)

Each fix has a test that fails with the fix taken out (checked by
reverting each fix alone and running its test).

- **F1, fixed.** IN-18b: rows the option table accepts and ignores
  (status `noop`) do not enter the plan hash. Every noop row's
  counterpart that would change the output is refused, so leaving one
  out can never hide a change: `strip-discarded`, `no-gdb-index`,
  `no-copy-dt-needed-entries`/`no-add-needed`,
  `no-dependent-libraries`, `Bsymbolic`, `Bsymbolic-functions`,
  `Bsymbolic-non-weak`, `Bsymbolic-non-weak-functions`, `Bno-symbolic`,
  `rosegment`, `no-undefined`, `warn-execstack`,
  `detect-odr-violations`, `plugin`, `plugin-opt`, `plugin-save-temps`,
  `flto`, `flto-partition`, `fuse-ld`, `-z defs`,
  `-z common-page-size`, `-z sectionheader`, `-z nostart-stop-gc`,
  `EL`, `g`, `O`, `Qy`, `qmagic`, `assert`, `map-whole-files`,
  `no-map-whole-files`, `no-keep-memory`, `reduce-memory-overheads`,
  `hash-size`, `max-cache-size`. Test
  `a_compiler_driver_link_twice_finds_its_state`: the second link
  through `-B<dir>` says `update-not-implemented` for gcc, g++,
  gfortran and clang. gfortran's line also exposed a writer bug: a path
  the link opens twice gave two STAT rows (now one, at the first
  opening; IN-18a says so).
- **F2, fixed.** The reader requires `META`'s output size to equal the
  STAT output row's and the build-id descriptor to be exactly the build
  id's length, at most 64 bytes; the output check reads that many bytes
  into a fixed 64-byte buffer. Test
  `the_reader_refuses_tables_that_disagree` (`meta-size`,
  `sealed-huge`).
  - **Allocation audit.** The reader's row vectors are bounded by the
    body bytes (a count is checked against the byte length before
    use). Every vector or map in `validate` (the OUTSECS map, sorted
    symbol keys, STAT paths, ORDER's placed flags, SLOTS and DEFINED
    keys) is bounded by row counts, so by the file's size;
    `leaf_count(file_size)` is compared, never allocated. The replay's
    vectors are sized by rows or by the present link. `capture`'s
    per-file buffer is the writer's, sized from the link. The one
    allocation proportional to a stored number was the build-id
    `vec!` of the output check (a 1 TiB `sealed` range allocated
    1 TiB); it is gone. `leaves_match` reads the real output after its
    length is checked against the stored size.
- **F3, fixed.** `Output::commit_identified` `fstat`s the temporary
  (or the in-place file) before the rename; `bind` refuses when the
  path's `(dev, ino)` or size differ afterwards ("is no longer the
  file this link wrote"), and any state at the state's path is
  removed. Only incremental mode takes the `fstat`. Test
  `concurrent_links_never_cross_output_and_state` (`cross_race.sh`,
  `--build-id=none`, 40 races): 0 crossed. With the bind check and
  F2's size check both taken out: 8 crossed of 40; with F2's taken out
  and the bind check in: 0.
- **F4, fixed.** `--incremental-state` and `--incremental-report=FILE`
  naming the output or an input (same path, or same `(dev, ino)`) are
  `incremental-file-clash` errors before anything is written; inputs
  found by a search are checked after the front, before the output is
  written. Test `the_state_or_report_naming_a_file_of_the_link_is_refused`.
  **`-Map`** in the same situation (unchanged here, a follow-up):
  `-Map=a.o` naming an input overwrites the input with the map and
  exits 0; `-Map=out` naming the output replaces the output with the
  map and exits 0.
- **F5, ruled (follow-up for WP-064).** The version string cannot
  separate two development builds. To be decided with WP-064 before
  any update path exists. Candidates: a stamp of the running
  executable, or a build-time identity (no build script).
- **F6, fixed (spec).** IN-18a now gives the log2 alignment of
  SEGMENTS, the `ChunkTag` values, the chunk and output-section ordinal
  schemes, the CHUNKS name/output section/part by tag, the FRAGS order
  (hash compared as 16 bytes), the STAT field widths and rows by tag,
  FILES `mention`/`base`/`len`, zero for unused fields, unknown header
  flags, the table count, and every reader check. The reader gained a
  SEGMENTS alignment check (< 64), which it lacked.
- **F7, fixed.** Duplicates in STAT, ORDER (and every chunk in ORDER),
  SLOTS and DEFINED, and FILES ranges past 2^64, are refused (test
  `the_reader_refuses_tables_that_disagree`). A state of another target
  at the same path is `options-changed` (§7), decided in `finish` once
  the target is known; test
  `a_target_change_at_the_same_path_is_options_changed`.
- **F8.1, fixed (spec).** IN-6: states compare identical apart from
  STAT's stamps and the output row's inode and times.
- **F8.7, fixed.** Why the dropped erratum redirect replayed to the
  same bytes: the redirect is neither used nor re-derived by the
  image. The erratum fixes (the branch at the site and the patch's
  words) are computed in the front from its own placement
  (`LinkSites::erratum_fixes`, `Front::erratum_fixes`) before the
  replay substitutes its tables, and the image writes those words as
  they are. The image's `Tables::redirect` serves branch relocations
  (thunks) only, and an erratum site's final word is a load. The
  replay now refuses erratum patches or redirects that differ from the
  computed ones, as for EH_RECORDS; IN-61 says so. Test
  `replay_reproduces_and_each_table_matters` with an erratum link
  (PATCHES, REDIRECTS and `REDIRECTS (drop)` mutated).
- **Follow-ups for WP-064** (ruled, not code now):
  - F5 above.
  - F8.2: the stale `<state>.tmp-<pid>` left after a kill.
  - F8.3: the sync order of output and state.
  - F8.4: the output check uses the reference stamp whatever the
    output's file system (the allow-list).
  - F8.6: the probe runs on every link rather than once per file
    system (IN-22a); cost 0.3-4 ms per device.
  - F8.5 (not ruled in the hand-back; recorded so it is not lost): a
    refused PIE or dynamic link leaves the old static state in place;
    the next link sees its output replaced (`output-changed`).
  - `-Map` naming an input or the output (above).
  - S-49 is WP-086 (the image follows the layout for `.eh_frame` and
    `.symtab`).
- **Own findings, ruled:** (a) no note severity, accepted (diag.md
  §2.1); (b) IN-12 `-T`, accepted; (c) IN-20, accepted and amended;
  (d) S-49 cut as WP-086.
- **Hosts.** The tests no longer return early off AArch64: the AArch64
  programs build with the cross tools elsewhere, and an x86-64 program
  joins the full-equals-plain and replay tests;
  `x86_64_dynamic_outputs_are_unsupported` checks dynamic and PIE
  outputs on x86-64. The stamp tests take, besides the build
  directory, `MORTAR_INCR_STAMP_DIR`, the temporary directory and
  `/dev/shm` when each is on another file system.
- **Numbers.** No row width changed. STAT loses only repeated paths
  (none on g++'s lines), so the protoc state size of §3 is unchanged by
  construction. The plain path gained nothing: the identifying `fstat`
  is taken only when `keep_leaves` is set.
