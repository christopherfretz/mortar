# WP-255d4 — the per-file scan

Record of the package (brief `briefs/wp-255d4.md`; design
`spec/landed/incr/WP-255.md` §9.4, the phase table of
`spec/landed/incr/WP-255d.md` row "scan"). Base `int/batch-17` a678029d.

## M1. What the walk of one unit reads, and where it comes from for ONE file

The walk is `mortar_scan::driver::run_unit(&View, &Unit, G: GlobalDemand)`
(`walk_unit`, `walk_types`, `Sec::open`, `RecTables`, `Recs`). Before it,
`scan_in` builds the `View`, runs `weak::classes` and `driver::units`;
after it, it merges the `UnitOut`s (per section: dynamic counts, order,
block overlaps; then locals, events, `copies::refusals`, the global column).

"Front" is `FileFront` (`crates/mortar/src/update/file_front.rs`); "state"
names a `StateView` method and its table; "delta" is what the update itself
decides for a changed file (U-3 resolve, WP-238 liveness). Sizes are per
file unless said.

### Per-file reads (no whole-program answer)

| `View` read | what, for which | source for one file |
|---|---|---|
| `prep(file)`: `inputs.files[file].reader` | the file's `Object` and `.symtab` | front: `object`, `object.symbols()` |
| `contents`, `rec_table`: `inputs.files[file].bytes` / `inputs.copy_to` | the section's and its relocation section's bytes | front: `bytes` (the whole file, hash-checked) |
| `inputs.files[file].display()` | the path in a diagnostic | state: `FILES.path`/`member` (`view.file`, `view.string`) |
| `inputs.target.machine` | `r_type` names in a diagnostic | state: `META` (the link's target) |
| `marks(file, index)` + `opts.proof` | mapping symbols of the file's code section; `CodeProof::runs` | front's symbol table; the arch's `CodeProof` (no link input) |
| `section_name(file, i)` | diagnostics | front |
| `local_facts(e)` (a local target) | its symbol (type, `st_other`, section) and `has_place(file, its section)` | front's symbol; `has_place`: below |
| `mention_facts` (a global key's undefined case) | the MENTION's type and `st_other` (`sym(m.file, m.index)`) | front's symbol table |
| `arch`, `opts.output`, `opts.dynamic` | the arch and output kind | the update's plan (= the state's link, IN-42) |

### Whole-program reads

| `View` read | what, for which keys/sections | source for one file in an update |
|---|---|---|
| `resolution.section_base`, `section_id(file, i)` (`units`, `has_place`, `is_demoted_mismatch`) | the file's `SectionId`s | front: `sections[k].id` (stored `FILE_INDEX` range; the join's `first_section` for a changed file) |
| `resolution.sections[sid].reloc` (`units`) | the relocation section of each section | front: `rela` index (`open`'s "first `SHT_RELA`/`SHT_REL` naming a target"); for UNPLACED sections `front_of` does not give it (only placed ones are needed, see liveness) |
| `resolution.sections[sid].kind` (`Defer::count`: `Regular`/`Debug`) | which non-alloc sections fill checks (I-14) | the header: `mortar_resolve::sections::classify(machine, i, &s)` (per section, pure); a dropped section is never live so never a unit |
| `liveness.is_live(sid)` (`units`) | which of the file's sections are scanned | unchanged file: state `SECTIONS.place_chunk != NONE` (= `has_place`; that live-and-unplaced never occurs with relocations is what M3's equality test checks); changed file: the delta (WP-238's liveness of the update) |
| `has_place(file, i)` (`section_place` over `resolution`, `assignment`, `liveness`) | `dead` of a LOCAL target in the file's own section | as `is_live` above (own sections only) |
| `inputs.sym_map_of(file)` (`key_of`) | the key of each non-local entry the records name | front: `keys[k].key` (`find_key`); `None` (a new key) only for a changed file: the delta (U-3 `new_keys`) |
| `resolution.redirect` (`key_of`, `Defer::mentions`) | `--wrap`: the key an UNDEFINED mention binds to | the plan's `--wrap` names + `find_key` (`update::extract`'s `redirect`); no stored row. Capture refuses a state whose demands name an unmentioned key (`capture.rs:1331`), so today every state was made without a demand through `--wrap` |
| `key_facts(id)` = `global_facts` (`def`, `props.verdict`, `props.refs PREEMPTIBLE`, `preemptible`, `assigned`, `assignment.def`, the DEFINING file's symbol and `has_place` of its section, `inputs.symbols[id].name` for `_TLS_MODULE_BASE_`), `is_mismatch`, `is_warned` | per global target key: the scan's `SymFacts` | state: `RESOLVED.facts` (`SymFacts::unpack`; WP-239 R-4a: exactly `Walker::facts(SymKey::global(id))`). For a key whose definition the update changes: the delta (U-3), the join compares before/after (`update-not-implemented (slots)`) |
| `def(id)` is `Undefined` (`at_mention`) | whether the mention's type applies | state: `RESOLVED.kind == def_kind` undefined (not derivable from `facts.kind`: an `--defsym` alias of an undefined key is `Undefined` too) |
| `is_demoted_mismatch(id, mention)` | a `comdat_only` key referenced through the file's own mention defined in its DROPPED COMDAT copy | `facts.comdat_only` (state) and whether the mention's section was dropped by COMDAT: unchanged file: its `SECTIONS` row unplaced with a COMDAT anchor whose `GROUPS` keeper (`view.group` + `rows::keeper`) is another file; changed file: the delta (U-3's keeper). A state with a `comdat-mismatch` key outside debug sections is a failed link; read only for such keys |
| `is_weak0(key, mention)` (branch candidates) | `facts.kind == Weak0` (debug-asserted equal) | as `key_facts` |
| `name(key)` / `shown_name(key)` (globals) | `inputs.symbols[id].name`, `version` | state: `SYMBOLS` (`view.symbol`, `view.string`); a new key: the front's name |
| `weak_dyn` (`undefined_kind`) | D-25's `WeakDyn` keys | in `RESOLVED.facts` (kind 6) for a stored key; empty in every static link |
| `weak_refused` (`walk_unit`: a refused key's records dropped) | D-25's refused undefined weak keys | a state exists only for a link without the refusal: empty for unchanged facts. **No source** for a CHANGED file in a DYNAMIC exec/PIE: `weak::classes` decides a key's class over EVERY live use of it (all files' relocations naming an undefined weak key); size: one walk of each file `KEY_REFS` lists for each undefined weak key the changed file names. Static links (the operator's configuration): `weak::classes` returns empty without a walk (`weak.rs:189`). Proposed: a named fall-back `update-not-implemented (weak-dynamic)` when a changed file of a dynamic output names an undefined weak key. **Needs your ruling.** |
| `eh_owner(place, sid, offset)` (`EhOwners`: `EhFrames::frame_owner`, `LsdaStarts`) | in the file's `.eh_frame` / `.gcc_except_table`, a reference to a DEAD target (common under `--gc-sections`: FDEs of collected functions) | the file's own `.eh_frame` parse (255d3's split of that file, `mortar_merge::eh`) and the liveness of the FDEs' target sections (own sections: as `is_live`). `lsda` is defined over "every parsed FDE whose LSDA pointer names `table`, whatever its file": an FDE of ANOTHER file naming this file's `.gcc_except_table` needs a global symbol there (section symbols are local); taken as own-file only, checked by M3 (a cross-file LSDA would be a named fall-back). Depends on 255d3 |
| `opts.sections` (`writable(sid)`), `bound_facts` (D-117), `closure_only` | dynamic/shared outputs only | `None`/empty in static links; a shared output is not updated here |
| `mismatches`, `gnu_warnings` (diagnostics text) | the keys' extra notes | `facts.comdat_only`/`gnu_warning` decide; the note's file: state `KEY_REFS` of the key |

### Outside `run_unit`, but in the scan of one file

| step | reads | for one file |
|---|---|---|
| `weak::classes` | every key's `def`, every use of an undefined weak key | static: nothing (returns `WeakKeys::default()`); dynamic: the "no source" above |
| `Defer::new` → `event_keys()` | EVERY key: `def`, verdict, `global_facts` | only the keys the file names matter (`Defer::mentions` asks `sym_map_of(file)` and `redirect`): `facts.kind == Undefined || comdat_only || gnu_warning` of each (state `RESOLVED.facts`); identical by `event_keys`' definition (an `Undefined` def's kind is `undefined_kind`, an internal's is `global_facts`, a defined/common/shared key is never `Undefined`) |
| the per-key demand cells (`Vec<AtomicU16>`, one per key) | the OR over all units | not needed: the per-file entry uses `Recording { cells: None }` (already exists: "an update's changed file, WP-239 §5"); its log is the file's demand per key, compared with `KEY_REFS.demand` of `(key, file)` |
| per-section merge (`counts`, `sorted`, `block_overlaps`) | the units of ONE section | per file: the same code over the file's units |
| `copies::refusals` | `COPY`/`CANON_PLT` records, per key over all files | dynamic exec only (no copy relocation in a static link) |
| `events::merge`, `report::group` | the events of all units | the file's events alone give its diagnostics; an update with an event (undefined, discarded-section reference) fails its link anyway |

### What a per-file scan gives (the brief's `FileScan`)

- per global key: the OR of `DemandFlags` over the file's live units
  (`GOT`, `PLT`, TLS kinds, `COPY`, ...) = `KEY_REFS.demand` of `(key, file)`;
  per local: the same (`FileDemands`' local rows);
- the facts it contributes: `UnitOut.output` (`GlobalFlags`), dynamic counts
  per section (`IRelative` for IFUNC in a static link), the branch
  candidates;
- proof runs per code section: `CodeProof::runs` over the section's marks
  (what `Sec::open` computes; layout's `(extras.proof)(file, index, size)`
  is the same call);
- erratum sites: NOT the scan's (the AArch64 erratum pass over the section
  bytes, `spec/a64.md` §11); the scan gives only the code sections it saw.

## M2. The seam

### Done: the pure move (commit e42f30c2)

`driver::units` is cut per file: `file_units(view, file, sections, &mut
Cut, diags)` is the old loop body for one file (the same calls in the same
order; `Cut` carries `out`, `deferred`, `bufs`, `defer`, `types` from file
to file). The full scan's units are unchanged; `static-identical` and the
plain timing in "Gate" below.

### Proposed (not built): the narrow view

Every whole-program read of the walk path (`walk_unit`, `walk_types`,
`Sec::open`, `Recs`, `RecTables`, `key_of`, `facts`, `Defer`) is one of
the rows above. The shape proposed for your ruling:

- `View<'a, 's, W = Program<'a, 's>>`: the four whole-program fields
  (`inputs`, `resolution`, `liveness`, `assignment`) move into `Program`;
  the walk path is generic over `W: Whole` (monomorphized: no `dyn` in the
  loop; every existing `&View<'_, '_>` user is `Program`'s and unchanged).
- `trait Whole` = the rows above, per file and per key: `object(file)`,
  `bytes(file)`, `display(file)`, `section_id(file, i)`, `reloc_of(sid)`,
  `kind_of(sid)`, `is_live(sid)`/`has_place(file, i)`, `global_of(file, k)`
  (`sym_map_of` + `redirect`), `key_facts(id)` (packed `SymFacts`),
  `def_undefined(id)`, `dropped_by_comdat(file, i)`, `key_name(id)`,
  `weak_refused(id)`, `eh_owner(..)`.
- `pub fn scan_file<W: Whole>(arch, &W, opts, file) -> FileOut` beside
  `run_unit`: `file_units` + `run_unit` with `Recording { cells: None }`
  + the per-section merge; the full scan keeps calling `run_unit` with
  `Shared`/`Recording { cells: Some }` over `Program`.
- `crates/mortar/src/update/file_scan.rs`: `Whole` over `FileFront` +
  `StateView` (`RESOLVED.facts`, `RESOLVED.kind`, `SECTIONS.place`,
  `SYMBOLS`, `GROUPS`).

Size: `Program` behind a trait touches `driver.rs`, `view.rs`, `bound.rs`
(its `Shared`-only rule stays on `Program`), `report.rs`, `copies.rs`;
estimated one package of its own (the reason this one stops here).
