## 1. Every state writer and what it does now

| writer | what it does with a `FILES` row's hash and position rows |
|---|---|
| the full link's capture (`capture::capture_timed`, written by `incremental.rs` `write_state`; every incremental-mode full link and every fall-back) | captures every row from the bytes it links; sets `POSITIONAL` on every row; `FRAG_AT` names the `FRAGS` row |
| the test path, step 7 (`floor.rs`) | sets the changed file's new hash and calls `capture::recapture`: when the file's `SECTIONS` rows still map to its sections in index order, rewrites their header fields, its locals' `at_index`, the `at_index` of globals whose `at_file` is the file, and its `FRAG_AT` block, from the translation of the bytes it hashed (O(the file's rows); the bit stays set); otherwise (a section permutation, the review's s1) clears the bit. The next update then translates that file by identity until a full link: its `Keys::partial` covers one more file (s1 hop 1: positional files 1 of 3 instead of 2) |
| `examples/incr_roundtrip.rs` | re-encodes a decoded state; changes nothing |
| tests that forge states (`tests/incr_review.rs`, `tests/incr-review/state_edit.rs`) | change rows on purpose, re-encode (hashes recomputed): the "forged" class |

`bind` (output binding) changes `STAT` and the output's record only.
Format 4: `FILES` byte 2 holds the flags (bit 0 `POSITIONAL`, any other bit
`state-corrupt`), byte 3 pad, the row still 60 bytes; `FRAG_AT`'s third
field is the `FRAGS` row (`u64`), checked in range at decode; a version-3
state is `state-version` and a full link.

## 2. The reader (`capture::positional_set`, `replay_by_position`)

The positional set is decided from `FILES` and the new link's files
before any identity is built: the bit, unchanged (change detection),
kind and (base, len) equal, the `SECTIONS` rows one contiguous range of
the file's section count, and each row's header (type, flags, size,
alignment, file offset) equal to section k's parsed header (this last one
catches H1; see question 1). `Keys::partial` builds identities for every
file outside the set (the old `internal-error` is gone). Locals: accepted
when `at_index < sh_info`, else `state-corrupt` (question 2). Fragments:
by position only when the `FRAGS` row has ordinal `NONE` and the
fragment's output section, and the fragment has no occurrence in a file
outside the set; a `FRAGS` row a hashed fragment also took must hold the
positional fragment's hash; any failure sends every fragment to identity.
m3: after the front, every inode the store read must equal a judged
tuple (dev, ino, size, mtime, ctime), else `input-changed`. m4: the update
writes its map (`image::map_of`) when `--mortar-map` is on its line.

## 3. The test path's guard (`mortar_incr::contribution`)

Before anything is written, the changed file's contribution is compared
with the state's rows. `layout-changed`: section count; a stored row that
is not one of its sections or names one twice; a section's type, flags,
size or alignment; the positions of its live merged fragments; the
`FRAGS` rows they are (multiset); a replay that does not translate.
`resolution-changed`: the set of global keys its symbol table names, and
each one's binding, type, visibility, definedness, section; each such
key's `RESOLVED` row (kind, definer, section, value, size, binding, type,
`st_other`); a `SLOTS`/thunk row naming an ambiguous local (§0.1).
`too-much-changed`: the changed path is more than one input.
`state-corrupt`: a local position out of range.

**Edits the test path now refuses that WP-064 must handle**:
- a weak definition made global or the reverse (W1, W1b);
- a call bound to another definition (W9; the review found it held, but a
  changed mention set is refused);
- a definition that moves inside its section (n1: the section's anchor
  changes, so the section does not translate);
- a visibility change (n2), a function made an IFUNC (n3), a common made
  a definition (n4), a local made global (W10);
- a `--gc-sections` liveness flip (W8);
- any change to the changed file's merged contents other than a
  permutation: a string changed, added or dropped (s4, W6);
- a GOT slot or thunk keyed by a section symbol of the changed file when
  that file has more than one (s3; every GCC/GAS object with two or more
  sections referenced through the GOT);
- a file named twice on the line.

## 6. The format-5 ranged state (branch `wp/105-incr-state-by-range`)

`ranged::patch` writes the blocks whose rows changed and refuses a table
whose size changed ("a journal, not a patch"); `update_reads` reads the
changed file's `FILES` row and a fixed set of tables. To keep the
writer's duty, its same-size update must, in the same patch, either
rewrite the changed file's `FILES` row with the bit cleared (one row,
always a patch) or recapture: the file's `SECTIONS` rows (header fields),
its locals' `at_index`, the `at_index` of every global whose `at_file` is
the file, and the `FRAG_AT` block of its sections. Recapture needs reads
`update_reads` does not do today: the `SYMBOLS` rows of the file's locals
(a `FILE_INDEX` range) and the globals by `at_file`, which no index finds
without a scan of `SYMBOLS` (O(all keys)); and `FRAG_AT`'s row count for
the file can change with a string permutation that changes which
occurrence is first, which is a table resize, not a patch. So: clear the
bit unless the table counts are unchanged and an `at_file` index exists.

update.

## 8. Questions on the rule's text

1. **The header check.** IN-28a's set conditions do not catch H1 (two
   `SECTIONS` rows of one file swapped, hashes recomputed): position then
   differs from identity. The code adds "each row's header equals section
   k's parsed header". It reads no file (the front parsed the headers),
   but it does look at unchanged inputs' headers; the ruling says "no
   check reads an unchanged input". Keep it (and write it into IN-28a), or
   drop it and classify H1 as the forged class?
2. **The local bound.** IN-28a: "a row that is not accepted is translated
   by identity"; but a file in the set has no identities, so a local
   position at or above `sh_info` is `state-corrupt` here. Amend the
   text, or should the set be decided again without that file?
3. **Fragments with an occurrence outside the set** (H2, §0): IN-28a
   should say a fragment is positional only when every occurrence is in a
   file of the set (the implementation's cost: O(the outside files'
   pieces)).
4. **§7.1's local identity** is a position for section symbols and for
   any name a file gives to several locals. IN-28 (by identity) gives
   s3's wrong program too; the test path refuses it, WP-064 cannot. A
   proposal: a section symbol's identity is its section's identity.
5. **The guard is stricter than the review's verdicts** for W6 and W9
   (both held as equivalent); they are refused because their outcome is
   not judged by a rule the test path implements (a dead fragment with no
   map line; a changed mention set).
