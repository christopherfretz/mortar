# WP-244: the format-5 capture from a real link

A complete format-5 state (`spec/incr.md` IN-18c..IN-18f) captured from
the link itself, behind a switch that U-10 flips; format 4 is written
exactly as before. Code: `crates/mortar_incr/src/capture.rs` (`Link5`,
`EhFile`, `Rows5`, `rows5`, `state5_rows`, `state5_encode`,
`state5_bytes`), `crates/mortar/src/incremental.rs` (`State5`,
`write_state5`), `crates/mortar/src/front.rs` (`Incr5`), the shared
producers named below. Tests: `crates/mortar/tests/state5_capture.rs`.
Experiment scripts: `tests/incr-design/wp244/`.

## 1. The switch (what U-10 flips)

- Off (every link today): no recording scan, no facts packed, no
  per-file `.eh_frame` padding, no per-object property values kept, no
  format-5 rows: a plain link and an incremental-mode (format-4) link
  are unchanged (`static-identical`, §5).
- On: `MORTAR_INCR_STATE5=<path>` in a `testhooks` build
  (`MORTAR_INCR_STATE5_COLLIDE=1` injects a fragment collision), or
  in-process `mortar::invoke_state5(.., State5 { path, collide, rows })`
  (`rows`: a sink handing the normalized rows to tests, since format 5's
  bytes do not hold seam 6's columns yet). The format-5 state is written
  BESIDE format 4, to its own path.
- U-10's flip: write `state5_bytes` as THE state at
  `--incremental-state` and drop format 4's writer.

## 3. Real links (AArch64 unless said; load beside each number)

- protoc `cxx-medium-static`: wall 1.88 / 2.30 (`--threads=1`) / 2.07 s,
  RSS 298-305 MB (load 11.8). KEY_REFS 96068 (lazy 19657 of 2485
  files, linker-defined 9), demand on 1910; MENTIONS 76402; FRAGS 1554,
  FRAG_USE 2373 (3828 with slack); SLOTS 716; 34,623,120 bytes.
- clang `cxx-large-g`: wall 59.1 / 69.8 (1 thread) / 57.5 s, RSS
  2.55-2.72 GB (load 8.9-12.1). KEY_REFS 398258 (lazy 95127 of 4372
  files), demand on 16550; FRAGS 127630, FRAG_USE 205868; 166,158,042
  bytes. Output and states deleted after measuring.
- Determinism (both): canon of 3 captures (default threads twice, one
  thread once) differ ONLY in `STAT` rows 0 and 1, the device rows'
  stamps (the link's moment); raw bytes differ there too. The in-process
  test compares 1 and 8 threads with the stamps cleared: equal.
- Series (both 64-bit targets): WP-207's M.1 (GCC `-O0 -g`, 6 hops), the
  slot series (6 hops), and M.1 with **kiln/hod objects** (`kiln++
  -fkiln-backend=hod`, no GCC `.comment`; linked through g++): every
  hop's state stored; facts equal afresh and demands OR to slots on
  every hop (20 GCC + 10 kiln/hod links); every unchanged file's stored
  rows equal hop to hop, less placement (`PLACED`: a full link places
  sections afresh) — `experiment_unchanged_files_rows_are_stable`.

## 4. canon(capture) vs canon(convert(format 4)), by name

Equal: CHUNKS, DEFINED, GROUPS, HOLES, INDEX, LAYOUT, MENTIONS, META,
ORDER, OUTSECS, PATCHES, PROBES, REDIRECTS, SECTIONS, SEGMENTS, SIZED,
SIZES, STAT. Different, each a converter stand-in:
- `COPIES`: index is the symtab index (capture) vs a row number
  (convert); size real vs 0.
- `FILES`: flags 3 (LAZY) vs 1 — format 4 has no LAZY flag; eh columns.
- `FILE_INDEX.first_global` real vs 0.
- `FRAGS`: class real vs 0; `FRAG_USE`: real class vs `u32::MAX`, one
  row per (file, fragment) vs one per fragment.
- `KEY_REFS`: real lazy rows (flags/bind/typ/demand) vs stand-ins.
- `RESOLVED.facts` filled vs 0; `SLOTS.refs` real vs 1;
  `SYMBOLS.at_file` the first LIVE mentioner vs format 4's.
- 3 keys only in the convert (`_DYNAMIC`, `_end`,
  `__gnu_cxx::zoneinfo_dir_override`): mentioned only by members the
  link did not load (`libc.a(dl-reloc-static-pie.o)`,
  `libc.a(dl-minimal-malloc.o)`, `libstdc++.a(tzdb.o)`); format 4
  cannot tell, the capture drops them (item 5).

## 6. Findings

- **F-1 (fixed here, U-2's code, pre-existing at 01f70788)**:
  `compact::normalize` renumbered SECTIONS (dropping fillers, sorting by
  file) but copied `RESOLVED.section` unchanged, while `encode` maps it.
  On a decoded state (canon, the compaction, `incr_state`'s round
  trip) every RESOLVED section past the first filler then named another
  section or none: protoc refused ("a reference to SECTIONS row 150212,
  which has none", 4512 rows); the small test links compacted
  SILENTLY with 2075 RESOLVED rows off their definitions. Fixed through
  the same map; `decoded_capture_compacts_again` fails without it.
- **F-7 (fixed here, U-2's code)**: `MemoryState::from_format4`
  (which the capture starts from, as the converter does) derived
  `FILE_INDEX` by scanning every table once per FILE: quadratic, 0.95 s
  of protoc's 1.56 s incremental-mode link (normalize and encode
  1044 ms -> 93 ms after). Now one pass per table, same rows.
- **F-2**: a capture's round trip (decode, normalize, encode) is not
  byte-equal: the 24-byte property strings are in STRINGS but no
  encoded column names them (seam 6 not encoded by U-2), so the second
  pool lacks them; every other difference is a string offset. The
  convert's round trip is byte-equal (after F-1).
- **F-3**: `OUTSECS` rows are not stable across links of DIFFERENT
  inputs: a file that brings a new output section (a GCC stub's
  `.debug_aranges` among kiln/hod objects) renumbers later rows, so
  unchanged files' `FRAG_USE.out` (and FRAGS' key) change.
- **F-4**: `STAT` device rows (0, 1) carry the link's moment: two
  captures of one link differ there (canon too).
- **F-5**: LAZY members get no MENTIONS; `META.iterations` 1 and
  `FILES.round` 0 in a capture; before seam 6's option bit a `--wrap`
  of a name no file mentions refused the state (its rows were dead),
  with the bit they are kept (`seam6_option_bit_marks_the_option_keys`);
  the `MemoryState` doc says "called by no link" (stale: the capture
  builds one).
- **F-6**: `live_keys`' `OptionKeys` entry / undefined / require-defined
  are not in `Plan::option_keys` (only `--wrap` and `--defsym`).
- **PROPOSED** `file_flags::EH_FIXED = 8` (a file whose `.eh_frame`
  range has a pointer encoding other than 0x1b/0x9b, or cannot move):
  needs a ruling. 0 such files on protoc.
