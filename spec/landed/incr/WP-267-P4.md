## (d0) as built
- **G's state**: `h<i>/prog.mortar-state`, written by the hop's own
  `--incremental=full` link (the lane's G, `lane.py` ~:285, in `h<i>`).
  S' is `<run>/ws/prog.mortar-state` right after the subject's link.
- **The tool**: `xtask incr-update` builds `mortar_incr`'s example
  `incr_state` once per lane run (`cargo build --release -p mortar_incr
  --example incr_state`: 9 s on top of mortar's release build) and passes
  `--incr-state <path>`; without it (or the file missing) `state`/`duty`
  are the stub's `n/a ... no incr_state`, never a pass; with
  `--require-tools` a missing file is an error.
- **Parsing**: `judge.parse_compare`: `<TABLE> <row>: <what>` lines, then
  `<n> differences`; the count must match and exit 0 iff no difference,
  else FAIL (unparsed output, exit 2, `timeout 120` = TIMEOUT: FAIL).
- **Never judged** (both rules, `D0_NEVER`, `d0_normalise`): `STAT` (G's
  inputs are copies: other inodes/times); in `STRINGS` the link's
  directory (G links in `h<i>`, the subject in `ws`: W renamed from `w` so
  both have the same length and no other string offset moves; checked:
  the STRINGS row must be equal once G's directory is replaced by W's).
- **Identity hop** (`judge.identity_hop`): X's map and G's map give the
  same lines outside `arg` and `symblock` (G's map has no symblocks).
- **Exact** iff identity and not base_was_update; otherwise outside
  IN-78's placement rows: whole tables CHUNKS ORDER HOLES PATCHES
  REDIRECTS REGIONS SYMTAB DEFINED SYM_PLACE SIZES SIZED SEGMENTS LAYOUT
  OUTSECS; columns SECTIONS[64:76] (place), FILES[72:80] (eh_offset,
  eh_capacity), FRAGS[24:32] (offset), META[16:24] (output size); SLOTS
  rows only as a permutation. Byte offsets checked against the lane's
  own differences (probe: 6 scenarios gcc-a64).
- **duty**: live, canon(S) against canon(S') (S copied to `h<i>/s.mortar-state`
  before X), causes None, STRINGS held out.

- **DEBUG_STRS** (supervisor's ruling on the hand-back): off an exact
  hop the row's offset (bytes 9..13) is a placement column; class and hash
  stay judged. On every update hop the rows are judged against the
  update's own output (`duty.debug_strs_check`, WP-247), excusing the
  strings inside the map's `dead <sec> <off> <len> strings` ranges (an
  update keeps a dead string as written: L-147, G-5). Bytes: in
  `g_debug_strings` gcc-a64 hop 2 the string at `.debug_str`+0x5e3 is
  `original_fill_wp230`, the renamed local's old name, and the map says
  `dead .debug_str 5e3 14 strings`.

## What (d0) does NOT judge (by name)
`STAT`; the link's directory string; `FILES.round` and `META.compactions`,
`build_id_len` (canon zeroes them); `LEAVES`; on non-exact hops the
placement tables and columns above; rows seen only as set differences
(duplicates collapse). Until the map's decision records give `P_U`, (d)
proper is not run.
