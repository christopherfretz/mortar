# B18-1 — the join-pair test's v1 front read v0's bytes (batch 18's hosted red)

The record of the fix (brief `briefs/b18-shortpath.md`).

## Symptom
`crates/mortar/tests/live_update.rs`
`live_on_the_joins_changed_files_is_the_full_marks_difference` failed on
the hosted runner (both lanes) and locally under a short
`CARGO_TARGET_TMPDIR` in `/tmp`:
`join pair aarch64: U4-U5: update-not-implemented (resolve)`, with the
finding `key k: resolve gives ResolvedRow { kind: 1, typ: 2, bind: 1,
other: 0, section: 6380, value: 0, size: 20, facts: 0 }; the front has no
such key`. Under the workspace's `.build/target-wp-157/tmp` it passed.

## Diagnosis (on the rows)
- The U4 adapter's `ChangedFile` for `a.c.o` (file 5, sections from
  6374) had four keys `g h k f` and four `SECTION` mentions; `k`'s was
  section 6380, `st_size` 20. These are v0's rows. v1's `a.c.o` defines
  `g h f` only.
- So `resolve` took `k`'s row from the `ment.new` branch of
  `defined_row`, from the changed file's own mention. `resolve`,
  `extract` and the adapter were right for the bytes they were given.
  The capture of v1's full link (the judge) had no `k`.
- The bytes were wrong. The test built v1's front (`front5`) with the
  same `Store` that had read v0. A store shares an entry between files
  with the same device and inode (`spec/input.md` §9.3, `Store::add`'s
  `by_inode`; one link's store). gcc rewrites `a.c.o` in place.
  - On overlay (`/tmp`; the hosted runner's container fs is the same
    kind) the inode is kept: `ino=2491571` before and after, size
    2168 -> 1864.
  - On the workspace's virtiofs the inode is new: 168332836 ->
    168332837.
  - So it was the filesystem, not the path length. The store handed v1's
    front v0's entry.
- No producer in `mortar_incr` or in the adapter was wrong. The
  production update makes one store per invocation, as `spec/input.md`
  §9.3 has it.

## Fix
- The test makes one store per front (`store0` for v0, `store1` for
  v1), as the linker does.
- `TARGETS` is now `targets()`, host-aware through
  `mortar_testutil::target::Arch::gnu`, as `rows_round.rs` is.

## Open points (for a ruling, not changed here)
- `Store::add` returns the existing entry on a `(dev, ino)` hit without
  checking that size and times agree (`FileMeta::same_version`). Within
  one link, a file rewritten in place between two mentions' opens would
  be read as its first version without `input-changed`. That is outside
  this fix's grants (`mortar_input`).
- `spec/input.md` §9.4 says "an inode changes on every rebuild". That is
  not true for gcc on overlay or ext4. Identity is by path and content
  hash, so the claim decides nothing, but the sentence is inaccurate.
- Other tests in `crates/*/tests` hardcode their compiler pairs (listed
  in the hand-back). Only `live_update.rs` was changed.
