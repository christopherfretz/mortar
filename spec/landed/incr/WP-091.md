# WP-091: the verifier judges holes and dead ranges (IN-3a, IN-60)

Record of WP-091. `mortar_plumb` reads mortar's `hole` and `dead` map
lines and, for a map that claims coverage, checks IN-60's coverage and
IN-3a's three checks on every range (`spec/plumb.md` §6.8, findings
`P-I1`–`P-I6`). It was written from the specs and from outputs and maps
only: no linker crate was read. No verdict on any existing output
changed (the checks run only for a map that claims coverage, and no map
today does).

## 1. Choices stated first

- **Line forms** (`plumb.md` §3.2), fields as every other mortar-map
  line writes them (offsets and sizes `0x`-hex, section by name):
  `hole <output section> <offset> <size>` and
  `dead <output section> <offset> <size> <kind>`, with `<offset>`
  relative to the output section, `<kind>` one of `neutral`,
  `contribution`, `strings`, `cie`. A `hole` holds its section's fill;
  a `dead` range holds its kind's bytes.
- **Version.** `mortar-map 1` stays. A new record `incremental` (no
  field, at most once) says "this link claims full coverage": a map
  claims coverage when it has `incremental` or any `hole`/`dead` line.
  A version-1 reader that predates these records refuses such a map
  with "unknown record" (§3.2's reader rejects every unknown keyword),
  which is the safe answer; the other linkers' maps have no such line.
- **Coverage rule**: the rule of §6.8, chosen by measurement (§3):
  0 findings on all 546 mortar outputs of a link-test run.

## 3. Coverage measured

`plumb.md` §6.8 has the table. The rule was found in five rounds over
the kept corpus; each round's misses and the fix:

1. merged pieces aligned only to their entry size: 321,063 bytes of
   `.rodata` uncovered → a piece's alignment is its input section's
   `sh_addralign`, and mortar lays a section's merged pieces out as one
   block aligned to the largest of them;
2. commons: no map line names them (1,844 bytes of `.bss`) → the output
   `.symtab` symbol of a name only common definitions give;
3. copies (6,897,168 bytes of `.bss`/`.lbss` with 2) → `copy` records;
   the gap after a copy or common may pad to the section's alignment;
4. zero-size placements at a section's tail → placements of size 0
   count for alignment;
5. `.relro_padding` (`NOBITS`, no line) → a `NOBITS` section no line
   names is accepted whole.
