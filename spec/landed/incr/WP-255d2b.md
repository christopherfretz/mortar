## Rulings needed

**R-1. A changed file's demoted globals.** S-74: a file's block is its
locals THEN its demoted globals (`Seg::Locals(f)`, `Seg::Demoted(f)`;
`plan`'s `GlobalKind::Demoted`: "the join gives it among its definer's
`FileSymbols::locals`"). The block is rewritten whole, so EVERY demoted
global the changed file defines (a hidden definition that stays hidden,
not only a `Demoted` change) belongs in `locals`. Which keys are demoted
is the resolution's (merged visibility, S-77, S-121: a default
definition here plus a hidden reference elsewhere is demoted), so
`file_symbols` cannot give them from the file. Proposal: `file_symbols`
takes the file's demoted entries from `global_changes`' producer
(below) and appends them in key order (`count`'s `demoted` order: by
`SymbolId`... of the FULL link, which is not the `SYMBOLS` row: the order
inside a file's demoted run is a second question, to be measured against
the full link's output).

**R-2. `global_changes` needs the full link's global rule, which is not
in a shared function.** `GlobalChange::kind` is not a field of
`ResolveDelta`: it is (stored entry, new entry) where the new entry is
`SymCtx::classify`'s answer over the new `RESOLVED` row (`Skip`: no
place, an unreferenced undefined; `Demoted`: hidden, internal or
`STB_LOCAL` and defined; else `Global`). `name`, `info` and `other` are
`CoreSyms::global`'s (`mortar/src/syms.rs`): the versioned name of a
`foo@@V` definition, `STB_GNU_UNIQUE` kept, `st_other`'s bits above the
visibility from the defining entry, the merged visibility. Writing these
in `file_symbols.rs` is a second copy of each. Proposal (two pure moves,
each with static-identical `0 differ` and a timing): (a) `classify`'s
binding/visibility rule as a `pub fn` in `symtab.rs` over a `GlobalIn`;
(b) the per-key part of `CoreSyms::global` (from a definition's symbol
entry and the key's props to `GlobalIn`) as a function the update calls
with the changed file's entry and `ResolvedRow`. `place`, `value` and
`size`: the new `RESOLVED` row (`section` in the update's ids, `value`,
`size`), whose producer for a changed definer is the file's symbol table
(`ChangedFile::values`); `stored` from `view.symtab_key`.

**R-3 (for step 4).** A key with no `SYMBOLS` row has no `GlobalChange`
(its `key` is a row). Its `.symtab` answer is the full link's only if the
update can name it: `_end`/`_DYNAMIC` are linker-defined
(`GlobalPlace::Linker`, the placement's `defined`), an undefined weak
with no definition is `GlobalPlace::Undefined`, a key only an unextracted
member names has no entry. Each needs a row (U-3's `new_keys`) before
`plan` can take it; not built here.

**F-1 (R-4 asked). The merged visibility and `referenced` are not in

not mine) or a pub fn; `vis_rank` collapses internal into hidden (rank 0 is

### R-4 (57ae0328): `ResolveDelta::merged`

`ResolveDelta` gains `merged: Vec<(SymbolId, u8, bool)>`, position for
position with `resolved`: the merged visibility AS `st_other`'s low bits
(`rank_vis(vis(k, new))`) and `referenced`, filled in `resolve_key` by the
existing `vis` and `referenced` (the latter split into `rooted` and
`object_ref`, one producer). `referenced` is the full link's
`RefFlags::FROM_OBJECT` (`mortar_resolve` `sym_props`, tables.rs ~1161): an
object's undefined mention or a demoted strong definition, and a root only
for a key the update does not leave undefined. `global_changes(view,
delta, fronts)` reads it (no `merged` parameter; a skewed `merged` is
`state-corrupt`).

**Internal visibility.** The full link folds `STV_INTERNAL` into
`STV_HIDDEN` itself: `SymProps::visibility` is `rank_vis` of the minimum
`vis_rank` (`mortar_resolve/src/resolve.rs` :81 "`STV_HIDDEN` for
internal", :456), and `CoreSyms::global` writes it into `GlobalIn::other`.
So `merged` writes `STV_HIDDEN` for an internal key, as the full link does;
an internal answer would differ from the full link. Bytes: in
`demoted_run_of_two_keys_in_one_file`, `wp255d2b_da` is `.internal` in
the object and its output entry has `st_other` 2 (both targets).

Test (both targets): in `global_changes_of_an_edited_file`, for every
key of `delta.merged`, `(vis, referenced)` equals the full link's
`(props.visibility, FROM_OBJECT)` by name (`wp255d_m1_data` (2, false),
`wp255d_m1` (0, true: a root), the rest (0, false)); the same check runs
in the two-key and R-3 tests (undefined weak, `_DYNAMIC`, `_end`, a key
only an unextracted member names).

### R-1 (57ae0328, test 2d588a9f): the order inside a demoted run

The full link's order: `SymtabPlan::new` (`crates/mortar_synth/src/
symtab.rs` :747-749) takes `count`'s demoted list, built per block of
global ids in `SymbolId` order (:1599-1612; the blocks concatenated in order), and sorts it by file with
`Pool::sort_by`, which is stable (`mortar_core/src/par.rs` :522): inside a
file, `SymbolId` order. A fresh link numbers `SymbolId`s by first mention
(model.md §2.3: files in `FileId` order, each file's non-local entries in
table order). The update holds that for every key: `(at_file, at_index)`
(`ResolveDelta::at` when it changed, else the `SYMBOLS` row; a new key's
`NewKey::row`), and `FileId` order is `FILES.rank` order. The state's own
`SymbolId`s keep the OLD link's first-mention order, so they are NOT the
rule. `demoted_run(view, delta, front, changes) -> Result<..>` sorts by
(`rank` of `at_file`, `at_index`); a first mention in a file new to the
state (no stored rank) falls back `(symtab)`. Sentence for IN-49a: "A
rewritten block's demoted globals follow its locals in the full link's
order, `SymbolId` order of a fresh link: by first mention (`FILES.rank`
of `at_file`, then `at_index`), not by the state's row order."

Test `demoted_run_of_two_keys_in_one_file` (both targets): old `m1.o`
defines `wp255d2b_da` then `wp255d2b_db` (default); the edit defines them
in the other order, `db` hidden, `da` internal. The state's ids: da < db;
the fresh link's: db < da. The run is `[db (size 8), da (size 4)]`, info
0x01, other 2, equal to the full link's block. Mutation (the sort
removed): the test fails.

`demoted_run`'s signature changed (it is this package's own function of
132ee164, not merged): flagged for the supervisor.

Whether the lane's judges compare `.symtab` order (spec only): plumb.md
