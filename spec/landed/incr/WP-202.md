# WP-202: the incremental update (M7 S4), designed again, and its cut

Record of WP-202, a design package: no linker code and no verifier code.
It inventories what of `spec/incr.md` §5 exists and where, writes the
update from "the link starts" to "output and state are a consistent pair
on disk" as [v1] rules in `spec/incr.md`, and cuts it into packages
modelled on WP-154's. Base: integration batch 12 + `wp/064a-position-exact`
(6b3b1f8e). Read: `docs/AGENTS.md`, `docs/ROADMAP.md` "Order of work",
`spec/incr.md` whole, the records WP-061, 061b, 062, 063, 064a, 086, 091,
092, 094, 105, 106, the review `briefs/reviews/review-in28a.md`, WP-154,
`spec/plumb.md` §6.8-§6.9, `spec/model.md` §7.1, `spec/synth.md`
S-73-S-89 and S-112, and the code of every crate except
`crates/mortar_plumb/src`.

Rules written or amended in `spec/incr.md`: **IN-18c, IN-18d, IN-18e,
IN-46b** (new: the state by range, format 5), **IN-28b** (amended: the
section-symbol identity, the slot rule), **IN-49a** (rewritten: per-file
symbol tables, the filler), **IN-70-IN-79** (new §5.10: the steps, delta

## B. The update

The rules are in `spec/incr.md` §5.10 (IN-70-IN-79), IN-18c-IN-18e,
IN-46b, IN-49a and IN-28b. This section gives what the rules rest on.

### B.1 Change detection, the positional set, the state

- U1-U3 of IN-70: the state opened by range (IN-18c), every input
  `stat`ed on the pool (WP-105 §5, landed), change detection as today
  (IN-22-IN-24), then the positional set from `FILES`/`STAT` alone.
- The state's format 5 is WP-105's prototype plus what an update writes
  (IN-18e): per-file row slack in the file-keyed tables (the prototype
  refuses a size change: "a journal, not a patch"), append areas and
  tombstones in the key-keyed tables, and the compaction. Of WP-105's
  two options for the copy path (journal or a copy of the state) the
  design takes neither: IN-77 sets the flag only after `T` is synced and
  patches the state after the rename, so the old state never has to stay
  valid past the moment the flag is set (cost: a crash in C2-C5 is a
  full link).
- **The writer's duty** (WP-064a §6) is IN-78: recapture or clear the
  bit for every file whose hash the update writes. WP-064a found that
  recapture needs (a) the file's locals by range and (b) the globals by
  `at_file`, for which no index exists. Format 5 gives (a) by
  `FILE_INDEX` and (b) through `MENTIONS`: a global whose `at_file` is
  file F is a key F mentions, so the changed file's own `MENTIONS` range
  lists every key whose `at_index` may need recapture; no scan of
  `SYMBOLS`. `FRAG_AT`'s count changing is a range in the file's slack
  (IN-18e), not a table resize.
- **Shrinking** (IN-18e): `MENTIONS` 69.0 → 51.7 MB, `RESOLVED` 66.1 →
  39.6 MB, `INDEX` 32.3 → 24.2 MB, plus `KEY_REFS` ≤ 34.5 MB, on g10x,
  all *estimates*: at most 150 MB against 167.4. `INDEX` is kept (WP-105
  proposed dropping it): IN-74 must find a referring **unit** without
  reading an unchanged input, and without `INDEX` that means reading the
  relocations of every file that mentions a moved key, which for a
  growth step is many files. Dropping it stays a measured [later] item
  for the first link's write (8.0% of g10x's bytes).
- **Hostile and stale states** (IN-28a's paragraph, extended): a patched
  state is checked block by block before use (IN-18c), so a torn patch
  is `state-corrupt` and a patch interrupted before W6 is `output-torn`;
  a stale state (a correct mortar's, for inputs since changed) is exact
  through IN-78 (a patch writes the same rows a full link would, or
  clears the bit); a forged state still chooses the output, as in IN-28a.
  The update adds one new trust: the append areas and tombstones, which
  the reader checks like any row (in range, ordered in the body).

### B.2 A changed file whose sections changed size

IN-72 (the delta layout) and IN-73 (WP-064a §3's list, one row each).
What moves: the changed file's sections inside their regions; on
overflow its region to the section's tail; on a growth step every output
section after the grown one in its segment. What is refilled: IN-27's
rows against the update's layout (IN-74). What the dependency index
must give: the referring units of a moved global or section, by `INDEX`
per referring file, the files from `KEY_REFS` (IN-18e). When it falls
back: `reserve-exhausted` (regions, tails and segment reserves, packed
sections, merged tails, slots), `tls-layout-changed`,
`island-exhausted`, `new-output-section`, `property-changed`,
`link-order-moved`, `symtab-exhausted`, `too-much-changed`.

**How common each edit is.** The census (`spec/incr.md` §1.1) has size
changes as the common case (e2, e6, e9, e10 resize). It lacks the
classes of WP-064a §3 that are about symbols and merged contents, so a
handful of real edits to one protoc source were measured
(`tests/incr-design/edits.sh` over protobuf 3.21.12's
`stubs/strutil.cc`; GCC 14 and Clang 19; `-O0 -g` as protoc's build,
and `-O2 -g -ffunction-sections -fdata-sections`; objects only, each
variant compiled from the same file and directory name;
`elfdiff.py diff` classes):

| edit | GCC -O0 -g | Clang -O0 -g | GCC -O2 -g fs | Clang -O2 -g fs |
|---|---|---|---|---|
| two statements added to an early function | `.text` +104 B; **80 globals and 11 locals moved in their section** (n1) | +76 B; 80 globals, 13 locals moved | its section +56 B; nothing moved inside a section | its section +48 B |
| a string literal changed, same length | no change (the literal is compiled out) | **merged contents** (s4/W6), `.rodata.str1.1` −1 B | merged contents, `.str1.8` −1 B | merged contents, −1 B |
| a `static` function made global (W10) | **a key appears**, a local goes | a key appears, 41 globals moved | a key appears, a section appears, locals +2 | the same |
| a `static` helper added and called | `.text` +80 B, `.eh_frame` +24, 81 globals moved, locals +1 | the same shape | inlined: debug only | debug only |
| a global function added at the end | a key appears, `.text` +24, `.eh_frame` +24 | the same | a key and a section appear | the same |
| a comment line at the top | nothing that changes a size or a symbol | nothing | nothing | nothing |

Every edit but the last two rows changes a debug size, so with `-g`
every one of them is a G-package update. Without
`-ffunction-sections`, **any size change moves dozens of definitions**
(n1): IN-27's global row is the common path, not an edge case, and the
test path's refusal of n1 refused most real edits. Symbol attributes
(W1, n2, n3, n4) did not occur in these edits, nor in the census; they
come from header refactors (an inline function moved out of line makes
a COMDAT weak copy a strong global: W1) and are covered by IN-71 except
IFUNC/TLS/absolute (`symbol-kind-changed`).

**s3 is hand-written assembly's case.** `elfdiff.py census` over 7,556
objects: protoc's (168 GCC `-O0 -g` objects, and its non-`-g` build),
`cxx-large-g`'s 2,375, AArch64 `libc.a`, `libstdc++.a`, `libgcc.a`
(2,609 members) and x86-64 `libc.a` and `libstdc++.a` (2,404): **0** GOT
relocations against a section symbol, **0** same-named locals (mapping
symbols aside: 52,669 in protoc, 272,893 in `cxx-large-g`), 0 sections
with two section symbols. IN-28b's rule is therefore for correctness,
not frequency.

### B.3 `.symtab`/`.strtab` per file (the ruling on P-E3)

IN-49a, written out: the filler's one form with `st_shndx` **1** (the
form WP-094 §4 measured with every tool; section 1 exists in every
output that has a `.symtab`, its index never changes in an update since
the header count does not, `new-output-section` otherwise); fillers in
the local area only; the global area dense, a removed global's entry
taken by the last, new ones appended; growth by `sh_size` into file
slack after each table (a map `hole` past `sh_size`); `symtab-exhausted`
when slack or the local tail reserve runs out; unnamed `.strtab` bytes
are dead ranges, and an old name stays until IN-3b. The verifier's side
is a REQUEST (below), not an edit of `spec/plumb.md`.

### B.4 Local identity

IN-28b and the REQUEST to `spec/model.md` §7.1 (below). Section symbols
take their section's identity (the ruling); a same-named local adds its
section and orders by value; mapping symbols have none. What stays
positional (two same-named locals at one value of one section) is never
translated: its slot is re-made. Measured frequency: B.2's census (0).

### B.5 Refill, writing, the crash protocol

IN-75 (dirty ranges only, the build id as a tree over stored and
recomputed leaves), IN-76 (in place the default at or above
`small-output`, copy otherwise or when an IN-45 condition fails), IN-77
(W1-W6 in place, C1-C5 by copy, the compaction, the table of kills, the
argument "the flag is clear only in the old pair or the new pair", the
lock and the leftovers, the crash hooks). The adversarial review of the
crash protocol (R-C) and of the delta layout and symbol tables (R-L) run
**before** any code of U-4, U-5 or U-7 (§C).

### B.6 `-g`

**What S4 alone gives a user whose builds always have `-g`: nothing,
and a slower link.** Every changed object of such a build has debug
sections (B.2: every size-changing edit changes a debug size), so every
update ends in `update-not-implemented (debug)` (IN-70) and the link is
an incremental-mode full link, which costs 1.6-1.8× a plain link (WP-105
§5) and writes a larger output (+9.7%, WP-062). Until G-3 merges, the
advice to the operator is: do not turn `--incremental` on in `-g`
builds. (An update could still run when only objects without debug
sections changed: generated assembly, a `-g0` file; not the operator's
case.)

The `-g` path follows as early as files allow: **G-1** (debug
contributions in place: IN-50-IN-54, IN-56, IN-57's trigger, refill of
a changed file's debug contributions in their size class, neutral forms
for dead ones, `.debug_aranges` whole) and **G-2** (split DWARF:
skeleton units handled as compile units by IN-51's neutral form, which
lifts IN-55a for `DW_UT_skeleton`; `.debug_gnu_pubnames`/`pubtypes` by
WP-065's option (A), left out of incremental-mode outputs, which lifts
IN-55 for the reference configuration; type units stay a fall-back)
start **beside U-2-U-7**, right after U-1 and R-L, because they own
their own files (§C). G-3 (the `-g` join: gdb and lldb transcripts,
IN-59) follows U-10 directly. Split DWARF with the GNU name index is
the reference configuration (`spec/incr.md` §6); G-2's option (A) is
WP-065's recommendation and needs the operator's yes (Q3 below).

### B.7 Costs

Every O(change) claim of IN-70 names its basis. The measured ones:
the ranged read and patch (WP-105 §4), the stats on the pool (WP-105
§5), the positional translation (WP-094; after WP-064a's amendment not
measured: U-2 measures it, WP-064a item 8), the per-file `.symtab`
and `.eh_frame` ranges (WP-094 §4), the syncs (R7). The *estimates*:
the front over changed files only, delta resolution (its bound: 102.7
ms of resolve on g10x, WP-105 §7), the delta layout, the refill set
against the update's own layout (bound: 46-54 ms against a full link's,
WP-063), liveness (the graph, not O(change)).

**A plain link pays nothing**: the gates are `cargo xtask
static-identical` (plain outputs byte-identical to the baseline on the
three targets), `a_plain_link_touches_nothing_of_incremental_mode`, and
`cargo xtask bench --check`'s plain rows (§8.1 amended). Every package
of §C runs them.

**The first incremental-mode link: 1.6-1.8× a plain one** (WP-105 §5,
p2 series; 1.34-2.16× across that session's loads). The design does not
depend on the operator's answer: no rule assumes a cost for the first
link, and a fall-back's full link is the same link. What would lower
it, with what each costs:

| lever | saves (basis) | costs |
|---|---|---|
| file hash composable from 64 KiB pieces, hashed as the staged store reads them | 0.54-0.96 s of file hashes (WP-105 §5, measured laps) | a format version; detection's hash changes; pieces never read are hashed at capture |
| keys numbered at first mention (parallel), no serial pass | 0.89-1.05 s on g10x, 0.13-0.19 s on `cxx-large-g` (measured laps) | `SYMBOLS` in `SymbolId` order (a format version); a name in two versions stored twice |
| the format-5 shrink (IN-18e) | part of the encode and write, 0.83-0.85 s (WP-105 §5); *estimate* ≤ 10% of the bytes | the packages' work, already in U-2 |
| no `fdatasync` of the first link's state | most of "write and sync" (543-600 ms under load, WP-105 §5) | after a power loss the state is torn: `state-corrupt`, one more full link (the output is never at risk: a full link renames a complete file) |
| fragments' capture | 243-438 ms (WP-105 §5) | unexplored |
| slack layout (phase 90) | 377 ms on g10x (708.8 against 331.6, WP-105 §5) | unexplored; it is the price of regions |

WP-105's estimate with the first two and the shrink: 1.45× (g10x) and
1.59× (`cxx-large-g`). Not cut until the operator answers (Q1).

## C. The cut

Modelled on WP-154 §F: one row per package; no file is owned by two
packages that run at the same time. Sizes in WP-110's classes (S: 1-2k
lines, M: 4-6k, L: 8-9k), *estimates*.

**Shared types first.** U-1 creates every later entry point as an empty
function in its own file, so that the later packages fill files and
never add `mod` lines:

## E. Questions

1. **(operator, through the supervisor) Is a first incremental-mode link
   at 1.6-1.8× a plain one acceptable?** The design does not depend on
   it. *Recommendation:* accept for v1 (paid once per build directory
   and after a fall-back), and cut one time-boxed prototype after U-10
   with B.7's first two levers (an estimated 1.45×/1.59×).
2. **(operator) In place by default at or above 256 MiB** (IN-76), given
   that the operator's file system clones, where the copy is O(extents)
   by argument (IN-47, not measured). *Recommendation:* in place now, as
   ruled (WP-094 §8 item 5); H-2 measures the copy on a cloning file
   system, and if it is within 10% of in place the default becomes the
   copy (it protects running processes, IN-45).
3. **(operator) Split DWARF's name index: option (A)**, leaving
   `.debug_gnu_pubnames`/`pubtypes` out of incremental-mode outputs
   (gdb then reads the skeletons without the index: slower start-up,
   same answers). *Recommendation:* (A) for G-2; (B) (neutral sets) only
   if gdb's start-up on the reference build is measured too slow.
4. **(supervisor) The filler's `st_shndx` is 1.** *Recommendation:* yes:
   the measured form, present in every output with a `.symtab`.
5. **(supervisor) `symtab-exhausted` is a full link in v1.**
   *Recommendation:* yes; the rewrite of both tables at the file's end
   (an update still) is the [later] item, cut when L10 shows the rate.
6. **(supervisor) Narrowing `symbol-kind-changed` in static executables**
   (binding, visibility, common ↔ definition become refills, IN-71).
   *Recommendation:* yes, with R-L reviewing it; dynamic outputs keep the
   wider rule.
7. **(supervisor) `INDEX` stays** (B.1), against WP-105's proposal.
   *Recommendation:* keep in v1; drop it later only with a measured
   first-link gain and a measured update cost of deriving referrers.
8. **(supervisor) A crash between C2 and C5 (or W1 and W6) costs a full
   link** rather than a journal that could resume the update.
   *Recommendation:* accept: crashes are rare, and the full link is the
   one recovery that needs no new code.
9. **(supervisor) S4 ships before `-g`?** *Recommendation:* merge U-10
   when its gate passes; the note in `--incremental`'s fall-back
   (`update-not-implemented (debug)`) tells `-g` users what happened;
   the operator is told not to enable it for `-g` builds until G-3.
