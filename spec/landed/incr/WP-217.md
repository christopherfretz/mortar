# WP-217 (U-5): the per-file symbol tables

`spec/incr.md` IN-49a, in two halves: (1) an incremental-mode full link
writes `.symtab` and `.strtab` in IN-49a's form; (2)
`mortar_synth::symtab_incr::plan` plans an update's writes of them. A
plain link is unchanged (§G). Branch `wp/217-incr-symtab`, base
a828a3de.

## Q. Findings that need a ruling

- **Q-1 (seam) Removed, demoted and changed globals.** IN-49a: "a
  removed global's entry is taken by the area's last entry"; "a demoted
  global leaves the global area as a removed one does". `plan` needs the
  removed (demoted, changed) global's **stored `.symtab` index and
  `.strtab` offset** (its `SYMTAB_KEYS` row, IN-18e). Neither
  `LayoutRows` (no accessor of `SYMTAB_KEYS`) nor `GlobalChange` (no
  index field) carries it. `plan` refuses these three kinds by name,
  `update-not-implemented (symtab)`. The removal rule itself is built and
  tested as `symtab_incr::area_after_removals(first, end, removed)`
  (descending removals, last entry moves, `(from, to)` moves in the
  previous output's indices). Two ways to close it: a `GlobalChange`
  field `stored: Option<(u32, u32)>` (index, name offset) that the join
  fills from `SYMTAB_KEYS`, or a `LayoutRows::symtab_key(SymbolId)`
  accessor. Either is a seam change (not mine to make).
- **Q-2 (seam) The moved entry's key.** When the last entry takes a
  removed one's index, its `SYMTAB_KEYS` row must be rewritten
  (review-in77 M-6). Its key is known only from the previous output's
  entry (by name, `find_key`), which U-6 reads; `plan` cannot name it.
  `SymtabPlan::moves` carries `(from, to)` only. Either U-6 (or the
  join) rewrites the row after the copy, or the seam gives `plan` the
  key at an index (`SYMTAB_KEYS` by index, which IN-18e keys by symbol).
- **Q-3 (seam) A global with no section.** `GlobalChange.section: None`
  does not tell absolute from undefined from common (`st_shndx` `ABS`,
  `UND`, `COMMON`/its `.bss` place). `plan` refuses an added or promoted
  global with no section by name. A `GlobalChange.shndx` hint (or a
  `SymDef`-like enum) would close it.
- **Q-4 (verifier) V-1 passed an output whose local names were wrong.**
  Before the fix in 998866ef, `write_strtab` in incremental mode wrote
  the first name after each region's slack at the slack's start, while
  the entry named the region's start: AArch64 static glibc, `readelf -sW`
  of the output: `32: 0 0 FILE LOCAL DEFAULT ABS ` (plain: `crtstuff.c`),
  `52: ... FILE ... ABS ` (plain: `a.c`), `60: ... ABS ` (`b.c`), `3140:
  ... ABS ` (`crtstuff.c`), `2489: 0000000000506fc8 1 OBJECT LOCAL HIDDEN
  19 readed` (plain: `__libc_single_threaded`). `cargo xtask plumb inc
  --map inc.map --map-format mortar` on that output: `linker-defined
  symbols not judged: 1 (readed)` and `findings: 0`. By `spec/plumb.md`
  §6.9 (P-E3 compares each file's locals as a multiset) I read this as a
  verifier gap (names not compared, or an unnamed `STT_FILE` not judged),
  not a spec one; I did not read `crates/mortar_plumb`. The output is
  kept at `.build/target-wp-140/wp217/t1/inc.bad` with its map. The new
  lane test `layout/symtab-incremental.test` fails on that bug (checked:
  reverted, 2 FAIL on `0 FILE LOCAL DEFAULT ABS a.c$`; restored, PASS).

## C. What was built

### Half 1: the full link (`crates/mortar_synth/src/symtab.rs`)

- `PatchFacts.room` (new field, `false` in `PatchFacts::of`): the tables
  have IN-49a's form. `crates/mortar/src/front.rs` sets it from
  `env.slack || env.replay.is_some()` (incremental mode; an IN-61 replay
  reproduces an incremental-mode output, and `mortar::replay_link` runs
  without `--incremental`, so `env.slack` is false there: without the
  second term `tests/incremental.rs`'s three replay tests failed with
  `SYMTAB_LOCALS: file 1's span is entries 1+4, its block 1+2 (S-88)`).
  One line.
- New segment `Seg::Fill`: after each block (the internal block, which
  holds the linker's symbols and the patches; each file's locals and
  demoted globals) `max(2, count/8)` fillers and the region's `.strtab`
  slack `max(16, bytes/8)`; after the last block the tail reserve
  `max(64, locals/32)` (locals: every non-filler local entry but the
  null one). `sh_info` counts them all. The filler: `st_name` 0,
  `st_info` 0x03, `st_other` 0, `st_shndx` 1, `st_value`
  `section_range(1).0`, size 0, 0 in `.symtab_shndx`.
- `with_patches` in room mode re-lays every segment (a block's
  capacity follows the patches' count) through `relaid`; the plain path
  is the old code.
- S-88 in incremental mode: `symtab_locals[f]` is `(first, capacity)`
  (fillers are the file's); the tail reserve is no file's. This keeps
  `mortar_core::check`'s contiguity rule (it failed with `(first, count)`).
- Accessors for U-2 (the `SYMTAB` rows) and U-6 (the map's `symblock`):
  `room()`, `incr_blocks()`, `incr_global_area()`, `incr_tables()`;
  `None` in a plain link. Public helpers `block_room`, `tail_room`,
  `file_slack` and the constants.
- File slack: `crates/mortar_layout/src/chunk.rs` gives `.symtab` and
  `.strtab` `slack.tail(size)` = max(4096, size/16) of chunk capacity
  (L-72's tail; the non-alloc file cursor already advances by capacity).
  One branch.

### Half 2: the update (`crates/mortar_synth/src/symtab_incr.rs`)

`plan(stored, layout, files, globals)` per its doc comment: per file of
`files` (sorted by id) its block in place when the entries fit the
capacity, else in the tail reserve with `n + max(2, n/8)` (or what is
left, when `n` fits), its old place fillers; its names in its region
when they fit, else a new region at `.strtab`'s end with `max(16,
len/8)` slack, the old region a dead range; each region's unused bytes a
dead range; `Added`/`Promoted` globals appended in key order, names at
the end, a `globals` row each; `.symtab`'s and `.strtab`'s growth
checked against their file slack. Values: the chunk's address in
`layout.placement.chunks` plus the place's offset (`place_of`, once per
section); TLS minus `placement.tls.start` (S-81). `remap` on a growth
step: every index range of `[1, end)` the plan does not write (see P-2).

Refused by name, `update-not-implemented (symtab)`: Q-1's kinds; Q-3; a
local whose section has no place (merged pieces, `.eh_frame`, a dead
section) or no address (a non-allocated chunk: v1 does not compute a
non-alloc section's value). `symtab-exhausted` (detail names the tail
reserve, `.symtab`'s or `.strtab`'s file slack); `state-corrupt` for
tables that contradict each other or a chunk the placement lacks.

## P. What other packages must know

- **U-2 (state)**: the `SYMTAB` rows are `SymtabPlan::incr_blocks()`
  (file 0 = the internal block), the global area `incr_global_area()`,
  `META.symtab` `incr_tables()`. A file with no entry has no block.
- **U-6 (map.rs)**: the holes reach it as data: `fillers` (index ranges),
  `strtab_dead` `(offset, size)` (`dead .strtab ... strings`), `tables`
  (the `hole .symtab/.strtab <sh_size> <n>` file slack is `symtab_slack`
  and `strtab_slack`), `blocks` (`symblock`). `moves` are copies from the
  previous output; `remap` (P-2).
- **P-2 remap is whole-area.** On a growth step `remap` is every index
  range the plan does not write, globals and the tail reserve included
  (fillers: their value is section 1's, which no step moves). Narrowing
  it to "blocks of files whose sections moved" needs files-by-chunk,
  which no O(change) accessor gives. U-6's remap is then O(symtab) per
  growth step. A seam question for later, not a correctness one.
- **`.symtab_shndx`** has no file slack in IN-49a; a growth past 65280
  sections in an update is not planned (no update adds sections to the
  header table in v1).
- The **file slack constants** are in two places: `mortar_layout`'s
  `Slack::tail` (what the output has) and `mortar_synth::symtab::file_slack`
  (what `incr_tables` reports); equal today; the second part's item 9 ties them by a test.

## Q2. Findings that need a ruling

- **Q2-1 (join input shape) `FileSymbols` gains two fields** for items 5
  and 7: `eh: Option<FileEh<'a>>` (`FileEh { frames: &EhFrames, kept:
  &[EhRecordIn] }`: the file's parsed `.eh_frame` and its `EhFile::records`)
  and `pieces: &[MergedPiece]` (the file's row of `LayoutInput::pieces`).
  `EhRecordIn` carries a piece index, not the record's input offset, so
  `plan` cannot place a local of an input `.eh_frame` from the seam types
  alone: S-50's function (`mortar_merge::refs::eh_ref`) takes the parsed
  `EhFrames`. Both are what the join already builds for U-4 (WP-243's
  `EhFile`, IN-72 item 6's pieces); `FileEh` is a new type in
  `symtab_incr` (not shared). `mortar_synth` already depends on
  `mortar_merge`.
- **Q2-2 `GlobalPlace::Linker`.** Ruling 3 named section, absolute,
  undefined (and common, refused). A linker-defined global (layout §13:
  `__bss_start`, `_end`, `__init_array_start`, ...) changes in an update
  whenever its value moves; it is placed by `Placement::defined`, the
  full link's `SymDef::Internal`. I added it as a fifth variant.
- **Q2-3 No shared function for the image's section values.** The full
  link's `SymAddrs` is `mortar_image::link::LinkTables` (`chunk_at`,
  `out_sections`, `frag_value`): private to `mortar_image`, which
  `mortar_synth` does not depend on. `plan` therefore MIRRORS them in
  `symtab_incr::Addrs` (`out_sections`: the same fold over the chunks;
  `chunk_at`: allocated chunk address + offset, non-allocated chunk offset
  minus its output section's offset + offset, file/program headers
  section 1; merged: the fragment's chunk offset + within). The entry is
  then computed by the full link's own `SymtabPlan::resolve` (shared as
  `symtab::resolve_at`). A test that holds the two to each other needs
  both crates (`mortar`'s tests); none is written (not asked; proposed).
- **Q2-4 (S-50 rule 4) a named local of `.eh_frame`.** The full link
  passes `droppable: !referenced` (a relocation names it); `LocalSymbol`
  has no `referenced`. `plan` computes both and refuses by name when they
  differ (a named local inside a removed record). Measured: no such local
  in any object counted below (all `.eh_frame` locals are `$d`). A
  `referenced` field would close it; not added.
- **Q2-5 what U-6 must do with the global area** (not in `SymtabPlan`):
  copy every `moves` entry (reading the previous output) BEFORE writing
  the appended entries and before the remap; when the area shrinks,
  zero `[end, old_end)` (the file slack is zeros; `SymtabPlan` has no
  field for it).

## C2. What was built (per ruling and item)

- **Ruling 1** `GlobalChange.stored: Option<(u32, u32)>` (the key's
  `SYMTAB_KEYS` row; the index `symtab_incr::NO_ENTRY` = `u32::MAX`, as
  `SymtabKeyRow::NONE`, for a key with no global entry). `None` for
  `Added`/`Promoted` (a `Some` is a join bug: `debug_assert`, refused);
  `None` for `Removed`/`Demoted`/`Changed`: `state-corrupt "SYMTAB_KEYS:
  key K has no row"`. Also `state-corrupt`: a `Changed` key with
  `NO_ENTRY`, an index outside `[sh_info, old end)`, two keys at one
  index. The three refusals are lifted: `Removed` and `Demoted` (with an
  entry) go to `area_after_removals`, their row becomes `(key, NO_ENTRY,
  0)`; `Changed` is rewritten at its stored index with its stored
  `st_name` (the name is the key's), or, when the area's last entry is
  the changed one and a removal moves it, written directly at the move's
  `to` (that move is dropped, its row `(key, to, st_name)`).
- **Ruling 2** `symtab_incr::moved_keys(moves, read, find_key,
  symtab_key) -> Vec<(SymbolId, to, st_name)>`: per move, the caller's
  read of the previous output's entry at `from` (`(from, st_name,
  name)`), `find_key(name)`, `symtab_key(key)` must equal `(from,
  st_name)`, else `update-not-implemented (symtab)`; no read for a
  `from`: `state-corrupt`. One lookup and one row a move. The caller
  splits a versioned name (`foo@V1`, `foo@@V2`, S-75) into `(name,
  version)` for `find_key` (see the experiment).
- **Ruling 3** `GlobalChange.place: GlobalPlace { Section(SectionId),
  Absolute, Undefined, Common, Linker }` replaces `section`. `Common` is
  refused by name (WP-216 R-2: the layout refuses first). `st_shndx` and
  `st_value` come from `SymtabPlan::resolve`, the full link's one function
  for every kind (S-81, S-82, S-122 to S-124, TLS), now reached through
  `symtab::resolve_at(addrs, name, info, Where)` (`Where` made
  `pub(crate)`); the `SymAddrs` it asks is the mirror of Q2-3.
- **Item 5 (`.eh_frame` locals)** `Cx::eh_where` calls
  `mortar_merge::refs::eh_ref`, the function the full link uses
  (`EhPlan::value`, through `symtab.rs`'s local walk with `EhWho::Mapping`
  for a mapping symbol, `EhWho::Symbol { droppable: !referenced }`
  otherwise), with: `kept(g)` = the record's offset in this update's
  `LayoutDelta::eh` range of the file (`EhRange::records[k]`, `k` its
  position in `FileEh::kept`); `after` = the file's next kept record
  after the section's last kept one; none: refused (the next file's
  record is not this update's to give). A local in a record that is not
  kept: S-50's mapping rule (a `$d` follows its record, S-76): DROPPED,
  no entry, as in the full link; a named one inside it: rule 4, refused
  (Q2-4); at its start: rule 3, the next kept record's place. The value
  is `.eh_frame`'s chunk address + offset (`SymAddrs::eh_frame`).
- **Item 6 (non-allocated)** On bytes (clang `-O0 -g` AArch64, two
  objects, `c2-plain` vs `c2-inc`): the full link writes a local of a
  non-allocated section as its offset in its OUTPUT section, `st_shndx`
  that section: b.o's `$d` in `.debug_abbrev` is 0xae, `.debug_info`
  0x96, `.debug_line` 0x8c (a.o's sizes before it) in the plain link,

- **Item 7 (merged)** built: `Cx::merged_where`, S-19 as
  `mortar_merge::refs::named_symbol` places a named local (the piece
  holding the value; the last piece at the section's end), the fragment
  `(out, class word, hash)` from `LayoutDelta::frags` or the stored
  `FRAGS` row (`frags_of`, once a fragment), the merged chunk's place +

  it.) Counts in §M.
- **Item 8 (the extra `$d`)** on bytes: it is crtbeginT.o's symbol 6,

## J2. What the join (U-10) and U-6 must know

- `GlobalChange` is `{key, kind, name, info, other, place: GlobalPlace,
  value, size, stored: Option<(u32, u32)>}`; `stored` from
  `view.symtab_key(key)` for `Removed`/`Demoted`/`Changed`, `None`
  otherwise. `place` from the resolution's `def_kind` (`Linker` for a
  layout §13 symbol).
- `FileSymbols` is `{file, locals, eh: Option<FileEh>, pieces}` (Q2-1).
  `locals` as the full link keeps them (S-76/S-78: no `STT_SECTION`, no
  dead or `.group` section's local, no `.L` local of a split section),
  except `.eh_frame` locals, given as read (`plan` applies S-50).
- After `plan`: the join (or U-6, which reads the previous output for
  the copy) calls `moved_keys(plan.moves, read, find_key, symtab_key)`
  with each move's `from` entry `(from, st_name, name)` and the name
  split as in §M, and appends the rows to `SymtabPlan::globals` (keep
  them sorted); a refusal there is before any write.
- U-6: copy the `moves` first (their sources are overwritten by the
  appended entries), then write `entries`, then `remap`; zero `[end,
  old_end)` when the area shrinks (Q2-5).
