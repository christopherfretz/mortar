# WP-255d3 — the per-file split (`split_of`)

Record of the package (brief `briefs/wp-255d3.md`; the phase table's
"split" row of `spec/landed/incr/WP-255d.md`; ruling "After 255d's first
half", item 2). Base `int/batch-17` a678029d.

## M1. What `phase::units` reads through `phase::Link`, and where ONE file's answer comes from in an update

`units(t, file, relocs)` (`crates/mortar_merge/src/phase.rs:319`) walks the
file's sections in index order; for each section `t.section` gives, it
emits `Unit::Merge` (a `MergeIn` and the bytes), `Unit::Whole` (S-6: a
merge section placed whole) or `Unit::Eh` (the `.eh_frame` bytes and its
classified relocations). Through `eh_relocs` and the public `target` it
also reads `section_id` and `global`. `Relocs` (the second trait object)
classifies the `.eh_frame` relocations.

Written from the reading list alone (before the first commit); the row
fields marked *(to confirm)* are confirmed or corrected in M2 below.

| `Link` method | who calls it in `units` | what it answers | ONE file in an update: source |
|---|---|---|---|
| `files()` | not `units` (only `run`'s loop) | the file count | not needed; `split_of` returns the state's `FILES` count for completeness (`view.count`) |
| `object(file)` | `units` first line | the parsed relocatable object | **`FileFront::object`** (parsed by `front_of` after the IN-24 hash check) |
| `section(file, index)` | `units`, every index | `LinkSection { id, kind, out, reloc }` for a KEPT section with an output section; `None` otherwise | `id`: **`FileFront::sections[k].id`**. Kept + `kind` + `out`: **stored rows**: the file's `SECTIONS` row *(to confirm: a kind/kept column; `out` through `place_chunk` → `CHUNKS.out`, or a column of its own; a `Merge` section's place may be NONE, its out then elsewhere)*. `reloc` (the `SectionIndex` of the relocation section applying to it): **the object**, the same first-`SHT_RELA`/`SHT_REL`-naming-it rule `front_of` uses (`FileFront` keeps only the `RelaTable` of placed sections, not the index: recomputed in `file_split.rs`, no change to `file_front.rs`) *(to confirm: resolve's `reloc` for a section whose relocation section is `Excluded`)* |
| `section_id(file, index)` | `target`, for a local / `STT_SECTION` symbol an `.eh_frame` relocation names (FDE `pc_begin`, LSDA) | the section's id, kept or not | **`FileFront::sections[index].id`** |
| `global(file, index, first_global)` | `target`, for a global an `.eh_frame` relocation names (personality, a global `pc_begin`) | `Target::{Section, Absolute, Undefined, Elsewhere}` after `redirect` | key: **`FileFront::keys[index - first_global].key`** (`find_key`); its resolution: **stored rows**: `RESOLVED` (`view.resolved(key)`) and the redirect *(to confirm: `REDIRECTS` / a `RESOLVED` column; the defining `(file, index)` → `SectionId` by the definer's `FILE_INDEX` range)* |
| `bytes(file, s)` | `units` (merge, eh), `eh_relocs` (the relocation records) | the section's bytes | **`FileFront::bytes`** through `Section::data` (the object is parsed over the whole file's bytes, all resident) |
| `class()` | not `units` (`eh_relocs` reads `object.class()`) | the ELF class | **`FileFront::object.class()`** |
| `form()` | `eh_relocs` | `Rela` or `Rel` | the target's: **stored row** `META` *(to confirm)* or the object's `e_machine` (AArch64 and x86-64: `Rela`) |
| `Relocs` (not `Link`) | `eh_relocs` | the classification | `ArchRelocs(arch)` of the state's target *(to confirm where the update gets its `Arch`)* |

**No seam beyond visibility is needed for `units` itself**: every answer is
`FileFront` or a stored row. The grant: `pub` on `units` and on `Unit`
(its return type; `MergeIn`, `Whole`, `EhReloc`, `Problem` are already
public by their use in `Phase` / `run`, *to confirm*).

What `units` does NOT do and `split_of` must still do for "the file's
pieces per merge section and its `.eh_frame` records": the cut of a
`Unit::Merge` into pieces (`merge()` does it whole-program; the per-file
cut is `mortar_merge::cut`, S-7..S-10, *to confirm public*) and the parse
of a `Unit::Eh` into records (`eh::parse`, *to confirm public*). If either
is reachable only through the whole-program `merge()` / `eh::parse` over
all files, that is a seam: named in M2, stop for the ruling.

The stored side the test compares with: `FRAG_USE` (`view.frag_uses_of(file)`,
by key) and `FRAGS` (`view.frags_of(out, class, hash)`). **`StateView` has
no reader of the `.eh_frame` rows** (`grep -i eh` in `view.rs`: none): the
comparison of eh records with stored rows needs one (a seam in
`mortar_incr`, not mine): named, the test compares eh records with the
whole front only until ruled.
