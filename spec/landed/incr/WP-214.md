# WP-214 (U-2): state format 5

The state's format version 5 (`spec/incr.md` IN-18c..IN-18f, IN-46b,
IN-78's canon) in `crates/mortar_incr/src/state5/`: the bytes, a lazy
verified reader, the writer, the in-place plan and patch, the
compaction, the canonical form; `examples/incr_state.rs`; the tests in
`tests/state5.rs`. Nothing calls it from a link yet (U-10 does): a plain
link and an incremental full link are unchanged (static-identical).

## 1. The bytes (IN-18c), as built

- Header, 80 bytes: `MORTARSR`, version 5, flags (`u32` at 12, outside
  every hash), table count, block size 4096, file length, plan hash,
  the directory's L128, the header's L128 over bytes 0..12 and 16..64.
  A format-4 magic gives `state-version`.
- Directory: one 72-byte entry per table in kind order (kind, width,
  rows, capacity, `aux`, `dead`, body offset, list offset, the list's
  L128). Then per table its block list (one L128 per 4 KiB block of the
  body) and its body (`capacity` rows, zero past `rows`). No padding.
- **38 tables**: format 4's, `FILE_INDEX`, `EDGES`, `SYMTAB`, `GROUPS`,
  `KEY_REFS`, `COMMONS`, `DIAGS`, `SYMTAB_KEYS`, `REGIONS`, `NAMES`,
  `COPIES`. `ODR_CLASSES` (47) and `ODR_REFS` (48) are **not written**
  (the supervisor's ruling on WP-220, R-1: WP-236 designs them); a patch
  or rows for them are refused. `EDGES` (42) is in the directory with
  no rows: nothing writes it (`from_format4` has none, the capture is
  format 4's; WP-215 seam 3).
- Seam commits picked (`git cherry-pick 89c735e4 85c3b28e 526d4940
  61f26084`, no conflict) and adapted (14bfc96a): `GROUPS` keyed by
  (signature bytes, file), no keeper; `COMMONS` keyed by (key, file),
  no winner (`common` is the trait's provided method over `commons`);
  `COPIES` (55) keyed by (key, file, index), **24 bytes** (key, file,
  index, size, type, tomb, 2 pad); `META.iterations` and
  `META.versioned` take the two former 4-byte pads (META stays 208);
  `FILE_INDEX.first_global` (`u32`) before `gone` (FILE_INDEX 104).
  `group`, `commons`, `copies` return the live rows sorted by key (no
  order promised). `encode`, `normalize` and `canon` keep
  `first_global` (canon: the `FILE_INDEX` rows normalized, ranges
  zeroed, so only `first_global` and `gone` are compared).
- `rows` by class: whole, append-only, key-parallel: the rows (bytes
  for `STRINGS`); file-keyed: the extent (ranges with their slack);
  key-keyed: sorted body (`aux` rows) plus the used append area, `dead`
  tombstones. `STAT`'s `aux` is the output's row (`u64::MAX`: none).
- Row widths (bytes): META 208, FILES 72, FILE_INDEX 104, MENTIONS 12,
  RESOLVED 24, INDEX 9, EDGES 17, SYMTAB 36, REGIONS 29, GROUPS 13,
  KEY_REFS 12 (tomb bit in `flags`), FRAGS 37, HOLES 24, COMMONS 25,
  DIAGS 39 (its subjects, code and text in `STRINGS`), SYMTAB_KEYS 8,
  NAMES 12, COPIES 24; the rest as format 4.
- Fresh capacity (IN-18e): whole tables rows + max(64, rows/8), every
  other class rows + max(4096, rows/64); a file's range count +
  max(4, count/8), **0 for a range of no rows** (deviation, F-6).

## 2. The calls

- `state5::open(file, plan_hash)`: header, directory and the parallel
  lengths checked; nothing else read. Every later read goes through a
  verified block (its list checked against the directory first), cached.
  `open_bytes` (tests, `incr_state`), `bytes_read` (the counting reader).
- `plan_patch(view, patch)` before W1: reads and verifies every block
  the patch writes (plus `META`'s and the `STAT` output row's), puts the
  rows in, decides in place or compaction. Compaction when: a range, an
  append area or `STRINGS` does not fit; tombstones pass 25 % of a
  key-keyed table; a `FRAGS` insert would move an area row `FRAG_AT`
  names; a new or moved rank ties a live file's; `S` is hard-linked.
  For a compaction it reads every block (IN-18f step 1), applies the
  patch in memory with the same placement (`compact::apply`) and runs
  the renumbering once to check it. Errors there are `state-corrupt`.
- `patch(view, plan, output, ops)`: writes only. The output row into
  its block, rehash the changed blocks, their list entries, the lists'
  hashes in the directory, the directory, the header but its flags
  word; `fdatasync`. A plan of another view or a compaction's plan:
  `Fallback(state-corrupt)`.
- `compact(view, plan, output, ops, S)`: binds `output` (it replaces the
  old output row), renumbers (`normalize`, CPU only), writes
  `dir(S)/.<base(S)>.mortar-compact` (`create_new`, `flock` exclusive),
  `fdatasync`, rename, `fsync` the directory; on an I/O error the
  temporary is unlinked, `Failed { step: "compact" }`.
- `normalize` (IN-18f steps 3-4) is also the full link's writer:
  `encode(normalize(capture))`. Drops gone files, their ranges and their
  `STAT` rows (unless a live file has the path), tombstones, `GONE`
  keys, unnamed strings; `FILES` by rank (`rank` := `FileId << 20`),
  `SYMBOLS` in IN-18e's order, `STRINGS` re-interned in table order (each
  distinct string once), `SECTIONS` by (file, position), `FRAGS` by
  identity (in `encode`), `NAMES` rebuilt from `SYMBOLS`. The compacted
  state therefore equals the full link's by construction.
- `canon`/`canon_of`: `normalize`, then rows per table, key-keyed
  sorted, file-keyed prefixed by their file; `LEAVES` dropped; `META`'s
  boot id, build id, `output-synced` and compaction count zeroed; the
  `STAT` output row's tuple zeroed; `FILES.round` zeroed. `compare`:
  row by row when the counts agree, else as sets.
- `size_report`, `refuse_updating`, `decode` (whole, the file's id
  space: section fillers, tombstones kept), `write::encode`,
  `write::patched_bytes`, `compact::plan_bytes`.

## 5. Findings

- **F-1 (ruling needed) StateRows has no descriptor.** `open` dups the
  descriptor and registers its reader by address in a static table;
  `plan_patch`, `patch` and `compact` find it with `core_of(view)`.
  Proposed: a `StateRows` accessor (`fn state5(&self) -> Option<&..>`)
  in the seam.
- **F-2 the SYMBOLS order is applied by `normalize`, not by
  `capture.rs`.** The format-4 bytes are unchanged; the format-5 writer
  orders. Proposed text for IN-18e: "the capture's order is the
  writer's (`normalize`)".
- **F-3 CHUNKS kept in their order**, not renumbered by (output
  section, ordinal, part) (IN-18f step 4): the capture's order already
  is the layout's; canon names a chunk by its row.
- **F-4 the output's STAT row strings** name the patched pool (old pool
  plus the patch's `strings`); U-7/U-10 build it so.
- **F-5 U-10's numbering of moved rows**: a file's new rows of a
  file-keyed table stay at the range's `first` when they fit its
  capacity, else go to the table's extent (capacity count +
  max(4, count/8)), in `ranges` order; a new `FRAGS` row's id is its
  sorted place in the append area; the patch's own `FRAG_AT` rows use
  those ids.
- **F-6 an empty range has capacity 0** (IN-18e's formula gives 4).
- **F-7 the canon does not check the support property** of
  `FILES.round` (IN-78), and `compare` does not read `P_U`: both H-1's
  today.
- **F-8 the `NAMES` delete**: `NAMES` has no tomb; a delete of a
  `NAMES` row is refused (a `GONE` key keeps its row, IN-18e).
- **F-9 "47-49 PROVISIONAL"**: kind 49 is `DIAGS`; it is written (it is
  not an ODR table). Confirm.

- **F-10 (ruling needed) `first_global` has no way into a patch.**
  IN-78's table says an update writes a changed file's
  `FILE_INDEX.first_global` from `ChangedFile::first_global`, but
  `plan_patch` gets only a `StatePatch`, and neither it nor
  `FileRanges` has the field. Today a patched file keeps its stored
  value (an appended file gets 0). Proposed: `FileRanges` gains
  `first_global: Option<u32>` (U-10 fills it from `ChangedFile`); I
  write it into the file's `FILE_INDEX` row in `plan_in_place` and
  `apply` (two lines each).
- **F-11 STRINGS growth per update (WP-215 seam 3, G2).** Measured on
  protoc's 167 archive members (section-name bytes, one per section,
  plus group signature bytes, what `ChangedFiles::strings` appends again
  for one changed file): median 46,388 B (`utility.cc.o`), p90 231,151 B,
  max 1,226,501 B (`descriptor.cc.o`, 10,030 sections, 3,681 groups),
  mean 93,580 B. `STRINGS`' fresh append area on protoc is
  9,023,282 - 8,884,463 = 138,819 B (rows/64): a median update fills
  it after **3 updates**, `descriptor.cc` compacts on the first.
  On clang the area is 1,020,005 B (about 22 updates of protoc's median size; clang's members not measured).
  So the threshold turns most protoc edit loops into a compaction
  every third update (reading and rewriting 38 MB). Proposed: the
  update reuses a changed file's stored `Str` when the bytes equal its
  old row's (section names and signatures rarely change in an edit),
  and only new names are appended; or `STRINGS`' area is
  max(4096, rows/8) (1.1 MB on protoc, +3 % size: the gate gets worse).
- **F-12 `at_file`: all inputs vs first LIVE mentioner.** The capture's
  `at_file`/`at_index` is the first mention among ALL loaded files,
  archive members not extracted and dead files included
  (`crates/mortar_incr/src/capture.rs` `first_mentions`, iterating
  `inputs.files` and `sym_map_of`). IN-18a3 and IN-71 say "first live
  object / first live mentioner". **The output does not depend on
  `at_file`**: the `.symtab` globals are in `SymbolId` order (synth.md
  S-75; `mortar_synth/src/symtab.rs` walks `SymbolId`s), and the
  `SymbolId`s are numbered by the input walk over every loaded file, so
  `.symtab` order follows first mention among ALL inputs whatever the
  state says; no diagnostic's place reads `at_file` (read from code,
  not checked against bytes). `at_file` orders `SYMBOLS` rows only
  (IN-18e, format 5's `normalize`). Consequence: a compaction after an
  update (IN-71: first LIVE) and a full link's capture (all inputs)
  order `SYMBOLS` differently when a key's first mention is in a
  non-extracted member, so "compaction equals capture" fails for such a
  key. An update cannot reproduce the all-inputs rule: `KEY_REFS` holds
  a lazy member's defined and common mentions but not its undefined
  ones. When a non-extracted member that is `at_file` is later
  extracted nothing changes under the all-inputs rule; when it goes,
  `at_file` must move to the next mentioner in load order, which the
  update cannot find for an undefined-only mention. Proposed: the
  capture follows IN-71 (first LIVE mentioner, `first_mentions` over
  live files); it changes format-4 `SYMBOLS.at_file` values (no output
  byte), which the floor's positional replay reads, so it is U-10's
  flip together with format 5. Not changed here.
- **F-13 `file_mentions`' skip.** The capture now refuses a file whose
  key map is shorter than its non-local entries before
  `file_mentions` runs (`tables.rs` `fill`: "the symbol table is not
  the one the input phase read"); the `continue` stays for
  `contribution.rs` (not mine), which calls `file_mentions` for the
  floor's comparison. It cannot fire in a link that writes a state:
  `mortar_resolve::tables` reports the same mismatch as a fault first
  (WP-213 §X2). Format 4's capture still sorts and dedups MENTIONS
  (`fill`): format 4 is still what a link writes, and the floor reads
  it so; format 5's MENTIONS by position needs the capture of format 5
  (U-10's flip).

## 6. Not done

The capture of format 5 from a link: until U-10 a link writes format 4
and no function takes a `Link` to a `MemoryState`; adding one is a new
public function (not in the seam). So these rows come only from
`from_format4` (plus `incr_state`'s `seam_rows` rebuild): REGIONS,
EDGES, lazy members, FILES rank/round from the link,
`META.iterations`/`versioned` (1 and 0), `FILE_INDEX.first_global` (0),
COPIES' `index`/`st_size`, MENTIONS by position (format 4 sorts and
dedups). U-10 flips: the capture writes `encode(normalize(m))` of a
`MemoryState` filled from the link, with those rows.

## 10. Third part: seam 5 (WP-239's format; picked as 1f2eb933)

Sections 1 to 4 describe format 5 before this part; where they differ,
this section is the format as built. `TABLES` has 37 entries.

1. **`FRAGS`** is keyed `(out, class, hash)` (class = `MergeClass::word`),
   37 bytes; no row of a `.debug_*` output section. **`FRAG_AT` (40) is
   gone; `FRAG_USE` (56)** is file-keyed, 28 bytes, names its fragment by
   key; a `FRAG_USE` key with no `FRAGS` row is `state-corrupt`.
   `FRAGS.refs` is recounted by `normalize` (writer, compaction) as the
   number of distinct live files with a `FRAG_USE` row of the key; a row
   at 0 stays (a dead range, reused by IN-72). Two live rows of one key
   with different offsets are `state-corrupt` on write. `ed.keyed`'s
   stable-rows flag is now false for `FRAGS` (nothing names a row by
   number). **What the gate's numbers are worth:** `incr_state convert`
   builds `FRAG_USE` from format 4's `FRAG_AT` (first occurrence of each
   fragment only, one file per fragment), so `FRAG_USE` is a LOWER
   bound; `FRAGS` rows and bytes are exact; `demand`, `facts`, `refs`
   and the eh columns are fixed width, so their size is exact although
   the converted values are 0.
2. **`FILES`** is 84 bytes: `eh_offset`, `eh_capacity`, `eh_records`
   (`ok`: `eh_records == 0 || eh_capacity > 0`). `EH_RECORDS` is not in
   format 5; its seam field (`ChangedFile.eh_records`,
   `FileRanges.eh_records`, `StateRows::eh_records_of`) is removed;
   `FILE_INDEX`'s `EhRecords` range must be empty. Spec IN-18e's
   file-keyed list and §IN-72's row lists say so.
3. **`KEY_REFS.demand: u16`** (14 bytes, checked by
   `DemandFlags::from_bits`), **`SLOTS.refs: u32`** (12 bytes).
   `LayoutOf` has every seam-5 accessor: `section` (`None` past the
   count, for slack rows and outside the file's live range),
   `frags_of`, `frag_uses_of`, `eh_range_of` (`None` at 0 records),
   `key_refs_of` (each mention key found by key and file; missing is
   corrupt) and `slots` with `refs`.
4. **`RESOLVED.facts: u32`** (28 bytes), stored as given (R-4a).
5. **`FileRanges.first_global`** is written by `plan_in_place` and
   `apply`, never kept from the stored row (F-10).
6. **`state-collision` / `state-limit`**: `state5::check_capture` (two
   `FRAGS` rows of one key, different offsets) and `state5::eh_columns`
   (any value, or offset + capacity, past `u32`). They sit between the
   rows and `encode`: no format-5 capture from a `Link` exists yet, so
   `incr_state convert` is the only caller; "no state written, the
   previous removed" belongs to that capture. Test
   `capture_collision_and_limit_are_refused` (injected rows).
7. **Dead keys**: `state5::live_keys(m, options)` is the one rule, used
   by `normalize` (hence the full writer and the compaction) and by the
