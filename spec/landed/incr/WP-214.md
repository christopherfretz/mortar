# WP-214 (U-2): state format 5

The state's format version 5 (`spec/incr.md` IN-18c..IN-18f, IN-46b,
IN-78's canon) in `crates/mortar_incr/src/state5/`: the bytes, a lazy
verified reader, the writer, the in-place plan and patch, the
compaction, the canonical form; `examples/incr_state.rs`; the tests in
`tests/state5.rs`. Nothing calls it from a link yet (U-10 does): a plain
link and an incremental full link are unchanged (static-identical).

## 1. The bytes (IN-18c), as built

- Header, 80 bytes: `MORTARSR`, version 5, flags (`u32` at 12, outside
  every hash), table count, block size 4096, file length, plan hash,
  the directory's L128, the header's L128 over bytes 0..12 and 16..64.
  A format-4 magic gives `state-version`.
- Directory: one 72-byte entry per table in kind order (kind, width,
  rows, capacity, `aux`, `dead`, body offset, list offset, the list's
  L128). Then per table its block list (one L128 per 4 KiB block of the
  body) and its body (`capacity` rows, zero past `rows`). No padding.
- **37 tables**: format 4's, `FILE_INDEX`, `EDGES`, `SYMTAB`, `GROUPS`,
  `KEY_REFS`, `COMMONS`, `DIAGS`, `SYMTAB_KEYS`, `REGIONS`, `NAMES`.
  `ODR_CLASSES` (47) and `ODR_REFS` (48) are **not written** (the
  supervisor's ruling on WP-220, R-1: WP-236 designs them); a patch or
  rows for them are refused. `COPIES` (55) waits for U-8's seam commit.
- `rows` by class: whole, append-only, key-parallel: the rows (bytes
  for `STRINGS`); file-keyed: the extent (ranges with their slack);
  key-keyed: sorted body (`aux` rows) plus the used append area, `dead`
  tombstones. `STAT`'s `aux` is the output's row (`u64::MAX`: none).
- Row widths (bytes): META 208, FILES 72, FILE_INDEX 100, MENTIONS 12,
  RESOLVED 24, INDEX 9, EDGES 17, SYMTAB 36, REGIONS 29, GROUPS 13,
  KEY_REFS 12 (tomb bit in `flags`), FRAGS 37, HOLES 24, COMMONS 25,
  DIAGS 39 (its subjects, code and text in `STRINGS`), SYMTAB_KEYS 8,
  NAMES 12; the rest as format 4.
- Fresh capacity (IN-18e): whole tables rows + max(64, rows/8), every
  other class rows + max(4096, rows/64); a file's range count +
  max(4, count/8), **0 for a range of no rows** (deviation, F-6).

## 2. The calls

- `state5::open(file, plan_hash)`: header, directory and the parallel
  lengths checked; nothing else read. Every later read goes through a
  verified block (its list checked against the directory first), cached.
  `open_bytes` (tests, `incr_state`), `bytes_read` (the counting reader).
- `plan_patch(view, patch)` before W1: reads and verifies every block
  the patch writes (plus `META`'s and the `STAT` output row's), puts the
  rows in, decides in place or compaction. Compaction when: a range, an
  append area or `STRINGS` does not fit; tombstones pass 25 % of a
  key-keyed table; a `FRAGS` insert would move an area row `FRAG_AT`
  names; a new or moved rank ties a live file's; `S` is hard-linked.
  For a compaction it reads every block (IN-18f step 1), applies the
  patch in memory with the same placement (`compact::apply`) and runs
  the renumbering once to check it. Errors there are `state-corrupt`.
- `patch(view, plan, output, ops)`: writes only. The output row into
  its block, rehash the changed blocks, their list entries, the lists'
  hashes in the directory, the directory, the header but its flags
  word; `fdatasync`. A plan of another view or a compaction's plan:
  `Fallback(state-corrupt)`.
- `compact(view, plan, output, ops, S)`: binds `output` (it replaces the
  old output row), renumbers (`normalize`, CPU only), writes
  `dir(S)/.<base(S)>.mortar-compact` (`create_new`, `flock` exclusive),
  `fdatasync`, rename, `fsync` the directory; on an I/O error the
  temporary is unlinked, `Failed { step: "compact" }`.
- `normalize` (IN-18f steps 3-4) is also the full link's writer:
  `encode(normalize(capture))`. Drops gone files, their ranges and their
  `STAT` rows (unless a live file has the path), tombstones, `GONE`
  keys, unnamed strings; `FILES` by rank (`rank` := `FileId << 20`),
  `SYMBOLS` in IN-18e's order, `STRINGS` re-interned in table order (each
  distinct string once), `SECTIONS` by (file, position), `FRAGS` by
  identity (in `encode`), `NAMES` rebuilt from `SYMBOLS`. The compacted
  state therefore equals the full link's by construction.
- `canon`/`canon_of`: `normalize`, then rows per table, key-keyed
  sorted, file-keyed prefixed by their file; `LEAVES` dropped; `META`'s
  boot id, build id, `output-synced` and compaction count zeroed; the
  `STAT` output row's tuple zeroed; `FILES.round` zeroed. `compare`:
  row by row when the counts agree, else as sets.
- `size_report`, `refuse_updating`, `decode` (whole, the file's id
  space: section fillers, tombstones kept), `write::encode`,
  `write::patched_bytes`, `compact::plan_bytes`.

## 5. Findings

- **F-1 (ruling needed) StateRows has no descriptor.** `open` dups the
  descriptor and registers its reader by address in a static table;
  `plan_patch`, `patch` and `compact` find it with `core_of(view)`.
  Proposed: a `StateRows` accessor (`fn state5(&self) -> Option<&..>`)
  in the seam.
- **F-2 the SYMBOLS order is applied by `normalize`, not by
  `capture.rs`.** The format-4 bytes are unchanged; the format-5 writer
  orders. Proposed text for IN-18e: "the capture's order is the
  writer's (`normalize`)".
- **F-3 CHUNKS kept in their order**, not renumbered by (output
  section, ordinal, part) (IN-18f step 4): the capture's order already
  is the layout's; canon names a chunk by its row.
- **F-4 the output's STAT row strings** name the patched pool (old pool
  plus the patch's `strings`); U-7/U-10 build it so.
- **F-5 U-10's numbering of moved rows**: a file's new rows of a
  file-keyed table stay at the range's `first` when they fit its
  capacity, else go to the table's extent (capacity count +
  max(4, count/8)), in `ranges` order; a new `FRAGS` row's id is its
  sorted place in the append area; the patch's own `FRAG_AT` rows use
  those ids.
- **F-6 an empty range has capacity 0** (IN-18e's formula gives 4).
- **F-7 the canon does not check the support property** of
  `FILES.round` (IN-78), and `compare` does not read `P_U`: both H-1's
  today.
- **F-8 the `NAMES` delete**: `NAMES` has no tomb; a delete of a
  `NAMES` row is refused (a `GONE` key keeps its row, IN-18e).
- **F-9 "47-49 PROVISIONAL"**: kind 49 is `DIAGS`; it is written (it is
  not an ODR table). Confirm.
