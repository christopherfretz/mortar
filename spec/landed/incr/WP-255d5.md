## Done in the continuation (`briefs/wp-255d5-cont.md`)

### Ruling item 2: no `unreachable!` in `Program` (commit 25b28fa0)

`Program` answers `key_facts`, `is_weak0`, `event_keys` and `is_mismatch`
itself; `View` calls `self.whole.<method>(..)` with no `program()` branch.
The four answers read state the view held, so it moved into `Program`
(a pure move, no new type):
- the per-file `Prep`s (`View::preps`) → `Program::preps`, reached through
  a new `Whole::prep(file)` (`View::prep` = `self.whole.prep(file)`);
  `Prep` is `pub` with `Prep::of(reader)` (the old `View::prep` body), so a
  narrow `Whole` builds its own;

  D-25's `weak_dyn` → `Program` (`Walker::with_weak_dyn` and `scan_in`
  write `view.whole.weak_dyn`);
- `global_facts`, `undefined_kind`, `is_warned` → `Program` methods; the
  bodies are the old ones with `p.` → `self.`.
`Whole::program()` stays for D-117 (`bound.rs`, `Shared` outputs only).

### Ruling item 3: the interim fall-back, not the move (no code yet)

`global_facts`' per-key rule is NOT a small move into a function the
update can call. For a key, it reads: `Def` (which file and entry
defines it), that entry's symbol (`STT_*`, `st_other`, `SHN_ABS`), whether
the defining section has a place (`Kept`, live, an output section),
`props.refs` `PREEMPTIBLE` and `Resolution.preemptible`, `--defsym`'s
`Resolution::assigned` (followed to depth 8), the output kind and D-25's
`weak_dyn`. For a key defined in an UNCHANGED file the update holds none
of these: only `RESOLVED.facts`, packed. A shared function needs a second
trait over those seven reads (a new shared type), and the update could
answer it only for a key the changed file itself defines, and even then
not `preemptible`. So the interim applies, as granted: a key the changed
file's relocations name whose `ResolveDelta.resolved` row is not its
stored row is `update-not-implemented (scan)`, case word `facts`.

**F-4 (the interim's reach):** every global a changed file DEFINES gets a
new `RESOLVED` row (its `section` is the changed file's new
`first_section + k`), so under the interim a changed file that refers to
any global it defines itself (a call, a GOT reference) falls back
`facts`. That is most edited C++ files. The producer (ruling item 3) is
what makes `scan_of` useful.

## Findings (second continuation)

- **F-7: a NEW key's `gnu_warning` has no source.** resolve ignores a
  `.gnu.warning.K` section of a live file when no key `K` exists
  (`mortar_resolve/src/resolve.rs` ~1023: `find_key` `None`). A key the
  old link did not have that the changed file now defines could therefore
  be warned in the new link through an UNCHANGED file, and nothing the
  state stores tells. `scan_of` falls back `facts` for a new key a record
  names (test `a_new_key_falls_back_facts`): adding a global and calling
  it in the same file falls back. Proposed: the capture records whether
  any live file holds a `.gnu.warning.<sym>` section whose `<sym>` is no
  key (one META bit or count); 0 makes the new key's bit exactly false.
  Whether the update's diagnostics (`diags.rs`) miss the same warning is
  NOT verified.
- **F-8: the record's earlier rule "stored facts when the delta row equals
  the stored one" was not exact for `dead`.** Under `--gc-sections` a key
  defined in an unchanged file keeps its row while its section's liveness
  flips (the stored `dead` is the old link's). `scan_of` recomputes it
  from `SECTIONS` and `LiveDelta`; the join's `(slots)` comparison should
  use the same recomputation (not checked).
- **F-9: undefined and linker-defined keys fall back.** The facts of an
  `UNDEFINED` row follow the merged binding of all references and the
  COMDAT copies (`comdat_only`), and an `INTERNAL` key's withdrawal
  follows the references: neither is in the row. Exact answers need the
  references' binding over all files; a weak undefined reference in an
  edited file falls back `facts`.
- **F-10 (observed, not this package's):** `changed::u5` refuses `resolve`
  when the edit changes which archive members are extracted (M2b-1); the
  test pair was chosen so v0 already makes every reference v1 makes.
