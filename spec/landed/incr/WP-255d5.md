## Findings for the supervisor

- **F-1 (blocks task 2's `key_facts`): the update's resolve gives no facts
  for a key whose definition changes.** `mortar_incr/src/update/resolve.rs`
  ~861 and ~889 build the new `ResolvedRow` with `facts: 0` ("the join
  writes the key's packed `SymFacts` into the row before the patch is
  applied (R-4a)"); only the unchanged-definer branch returns `*old` with
  its stored facts. So "the resolve delta wins over the stored row" cannot
  be read for `facts`: a 0 there is a placeholder, and unpacking it would
  answer with a default. The narrow view needs a producer of the NEW
  facts of an affected key (`View::global_facts`' rule over the new
  definition: the definer's symbol, `has_place` of its section, verdict,
  preemptible). Proposed: until one exists, a key the changed file's
  relocations name whose `ResolveDelta.resolved` row is not the stored
  row falls back `update-not-implemented (scan)` with the case word
  `facts`; needs your ruling (not one of the three granted case words).
- **F-2: events and overlaps.** An update cannot report the full link's
  scan diagnostics. `scan_file` returns the walk's diagnostics and the
  count of events and overlap records; proposed: any of them makes
  `scan_of` fall back (`(scan)`, case word `diagnostic`). Needs a ruling
  for the word.
- **F-3: new pub type `Program`.** The brief's shape names it
  (`View<'a, 's, W = Program>`); it is `pub` because `Whole::program()`
  returns it. Four `Whole` methods are `unreachable!` in `Program`'s impl
  (the view answers them from `Program` itself).
