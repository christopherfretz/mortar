### Who allocates ids today (a CHANGED file)

- **Sections**: the join (U-10) gives each `ChangedFile` its
  `first_section`, "past the state's `SECTIONS` count, in
  `ChangedFiles::files` order" (`view.rs:413-416`); `refill.rs:63`,
  `resolve.rs:310`, `odr.rs:339` read it.
- **Keys**: a changed file names keys by position in `ChangedFile::keys`
  (`KeyName`); U-3 (`mortar_incr::update::resolve`) maps each by
  `find_key` or allocates a new row `cx.symbols + i` (`resolve.rs:1106`
  `new_keys`).
- `front_of` therefore allocates nothing: for a changed file it yields
  sections relative to a `first_section` the caller passes (the join's)
  and keys as `KeyName`s with `find_key`'s answer where there is one. No
  second allocator.
