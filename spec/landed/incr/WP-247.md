## 0. Rulings asked for

1. **`FILES.flags` `DEBUG_EXPORTS` is bit value 16, not 4.** The brief's
   "bit 2" counts as format 4 did; in format 5, 2 is `LAZY`, 4 is `GONE`
   and 8 is `EH_FIXED`. `file_flags::ALL` is now 31.
2. **The schema word (item 8)**: §8 below. Proposed only; nothing written.
3. **The diet (item 9)**: §9 below. Proposed only; the format is unchanged.
4. **The compaction's `DEBUG_STRS`**: the compaction cannot read the
   output, so it keeps the stored rows plus the patch's puts, sorted, one
   row per key, the lowest offset kept. That is the capture's rule
   (`compact::debug_strs_whole`). A row whose string the update moved
   stays right only because the update puts the new row (seam 8a), and
   an update never deletes one (refused as `state-corrupt`).
5. **The references the readers take unchecked (item g's finding)**:
   §5. Proposed check; not changed.

## 1. DEBUG_STRS (kind 57, key-keyed, 13 bytes)

Row: `out` u8 (`debug_str_class`: 0 is `.debug_str`, 1 is `.debug_line_str`),
`hash` u64 (`name_hash(bytes, "")`, the bytes without their NUL), and
`offset` u32 (the string's offset in that output section). The key is
`(out, hash)` and equal keys are allowed (`Keyed::DUPLICATES`):
`Reader::debug_str` returns the lowest offset. Nothing else names one of
its rows.

- The capture is `capture::debug_str_rows`. It covers each output
  section named `.debug_str`/`.debug_line_str` whose merged chunk is
  alone on its `shndx` (otherwise that class gets no rows and a notes
  line says so). The offset is the fragment's `frag_off`; offsets at or
  past 2^32 are skipped. A testhooks switch, `MORTAR_INCR_NO_DEBUG_STRS`,
  turns the rows off for the measurement.
- Reader, canon, normalize and encode all handle the table. The patch
  puts rows (`plan_in_place`, `compact::apply`), and a delete is refused.
- duty.py: `DEBUG_STRS` is `JUDGED_BY_OUTPUT`. `debug_strs_check(state, elf)`
  reads every row against the output's bytes, using a Python port of
  wyhash v4. Selftest cases are `debug-strs-*`.
- Tests:
  - `state5.rs`: `debug_strs_round_trip_and_lookup`, `debug_strs_what_the_reader_refuses`,
    `debug_strs_canon_and_compaction_sort`, `debug_strs_patch_puts_rows`
  - `state5_capture.rs`: `debug_strs_name_the_output_strings`
- **Measured** on protoc `-g` (cxx-medium-g-static). 9 interleaved runs,
  1-minute load 7.9-8.3, medians with ranges in parentheses:

  | link | wall | peak RSS |
  |---|---|---|
  | base plain (f69596c7) | 0.260 s (0.250-0.310) | 250.7 MiB (246.0-252.4) |
  | branch plain | 0.270 s (0.250-0.310) | 249.9 MiB |
  | capture with rows | 0.650 s (0.600-0.790) | 402.2 MiB |
  | capture without rows | 0.610 s (0.540-0.770) | 396.3 MiB |

  DEBUG_STRS is 77,490 rows (76,971 `.debug_str`, 519 `.debug_line_str`):
  1,064,762 bytes, 2.95% of the 36,052,992-byte state. The duty check on
  the real output finds 0 problems.

  On clang `-g` (cxx-large-g) it is 2,082,390 rows (2,075,929 and 6,461):
  27,601,459 bytes, 14.18% of 194,585,779, again with 0 problems.

## 2. FILES.flags DEBUG_EXPORTS (16) and EH_FIXED (item d)

- `capture::object_flags(inputs, file)` computes the per-file flags from
  the file's bytes. It is called by the capture's per-file task (one
  line), and the join must call it for `files_set`/`files_append` rows.
  - `DEBUG_EXPORTS` comes from `capture::debug_exports`: a `GLOBAL`,
    `WEAK` or `GNU_UNIQUE` symbol defined in a non-alloc `.debug*` or
    `.zdebug*` section.
  - `EH_FIXED` comes from `capture::eh_fixed`. It parses every CIE in
    `.eh_frame` (version, augmentation, the z/R/L/P/S/B/G letters) and
    applies IN-34a's sentence exactly. An unreadable record counts as
    fixed. An absent `R` means `absptr`, which is fixed. This is ORed
    with the old kept-CIE `movable` test.
- The plan's check is `read::eh_fixed_check(view, moved)`. It gives
  `update-not-implemented(eh)` when a moved file has `EH_FIXED`. The join
  calls it; nothing calls it on this branch.
- Counted:

  | link | files with `DEBUG_EXPORTS` | files with `EH_FIXED` |
  |---|---|---|
  | protoc | 0 | 0 of 735 eh files |
  | protoc `-g` | 0 | 0 of 735 eh files |
  | clang `-g` | 0 | 0 of 2,783 eh files |
- Tests:
  - `capture_flags.rs`: `eh_fixed_is_ins_34a_sentence`
  - `state5.rs`: `eh_fixed_check_reads_the_bit`
  - `state5_capture.rs`: `object_flags_on_a_real_link` (no archive

## 4. The F-1 class, table-driven (item 4)

`state5::columns::COLUMNS` lists every column of every table, in row
order, with what it names (`To`). That covers `FILES`, `SYMBOLS`,
`SECTIONS`, `CHUNKS`, `OUTSECS`, `PATCHES`, `STRINGS`, the file-keyed
ranges, references that depend on the row's kind (`EDGES.target` by
`edge_kind::target`, `INDEX.target`, `PATCHES`, `DIAGS.unit` by phase),
and lists held in `STRINGS` (`DIAGS.subjects`, `DIAGS.refs`).
`DEBUG_STRS` names no row.

Tests in `crates/mortar_incr/tests/state5_columns.rs`:

- `every_table_has_its_columns`: COLUMNS is in TABLES' order and each
  table's widths sum to its row width. So a column added to a row and
  not to the list fails here.
- `every_listed_reference_has_its_reader`: there is exactly one identity
  reader per listed reference. A newly listed reference without a reader
  fails, and so does a reader of an unlisted column.
- `normalize_encode_and_compaction_keep_every_reference`: a state with a
  row in every table that holds a reference, under every renumbering:
  - files out of rank order;
  - keys out of IN-18e's order, a versioned key, an option key;
  - a filler `SECTIONS` row first;
  - strings at other offsets.

  What every reference names is the same after `normalize`, after
  `encode`+decode, after the compaction (`apply`, then `normalize`), and
  after `encode` of a state that was not normalized.
- `the_patch_and_its_compaction_keep_every_reference`: a patch with a
  new file (ranked first) and rows in every key-keyed table that holds a
  reference. The references hold through the in-place patch (asserted
  in place) and through the compaction of the patched state.

**Found and fixed (F-1).** `normalize` did not renumber `DIAGS.unit`. For
the file phases (`diags::file_unit`: 30, 40, 45, 50, 60, 70, 100) it is a
`FILES` row, and the report order reads it as a rank. After a compaction
moved files, a finding named another file's unit. The test fails without
the fix:

```
DIAGS.unit:
  before [... "finding in f0=f:f0.o", ...]
  after  [... "finding in f0=f:f1.o", ...]
```

`file_unit` is now `pub(crate)`.

## 5. Item g: a corrupt row is state-corrupt; every table mutated

- `reseal(bytes)` (in the test) seals a state again after its bodies
  were edited: block lists, list hashes, directory hash, header hash.
- `file_index_row_out_of_range_is_state_corrupt`: FILE_INDEX row 0's
  SECTIONS range is set to first 0xFFFF_FFFF, count 2. Every reader
  answers `state-corrupt`: decode, normalize, canon, the view's per-file
  and per-key reads, and `plan_patch`.
- `every_column_mutated_no_reader_panics`:
  - Every column of every table is mutated, in the first and last row
    (for a file-keyed table, the first and last row of each file's
    range). Each is filled with all-ones, then with all-ones except a
    low byte of 0xFE, and resealed.
  - No reader panics (each one runs under `catch_unwind`).
  - A reference column filled this way must be refused, except those in
    `UNCHECKED`. Any reference not in that list that a reader accepts
    fails the test.
- **The finding, for a ruling.** Format 5's readers take these references
  unchecked:
  - `SECTIONS.place_chunk`, `CHUNKS.out`, `ORDER.chunk`, `SIZES.chunk`,
    `SIZED.chunk`, `SYM_PLACE.chunk`, `DEFINED.chunk`;
  - `PATCHES.chunk`, `PATCHES.symbol`, `PATCHES.section`, `REDIRECTS.patch`;
  - `HOLES.chunk`, `REGIONS.out`, `REGIONS.chunk`, `NAMES.row`;
  - a global's `SYMBOLS.file`, which nothing reads.

  Format 4's `validate` checked the whole tables. Format 5's decode and
  the view's whole-table reads do not. The hashes stop disk corruption,
  so only a writer defect reaches these. A consumer (the image's update)
  would then index past a table.

  **Proposed:** one reference check, driven by `COLUMNS`, in
  `decode_core` and in the view's whole-table reads. Each listed column
  must be below its target table's row count, or `NONE` where the kind
  allows it. It would cost one pass over the whole tables, which are
  small. Each column it covers then comes off `UNCHECKED`.

## 8. PROPOSAL: the schema word (item 8)

- **What.** A 16-byte header field (from the reserved bytes, or by
  growing the header to 96): the L128 of this build's
  `[(kind, class, width)]` (`TABLES`) and of every table's columns
  (`COLUMNS`: name, width, `To`). `Header::parse` compares it right after
  the magic and version, before any width or count test. A mismatch is
  `state-version` (§7 already has the name: "the state's format or
  mortar version differs"), so a build whose rows differ never reads a
  state written by another, even at the same version number.
- **Cost.** One hash of a constant per open, which can be computed once.
- **Test, written with the change.** Two table variants and one state:
  - write a state with `COLUMNS` as is;
  - parse it with a variant that has one column split in two (same
    widths, so the width tests alone pass) and get `state-version`;
  - parse it with the same list and it opens.

## 9. Item e: the size, and a PROPOSED diet

**Why two ratios.** WP-244's 1.274x format 4 was protoc built without
`-g` (cxx-medium-static; format 4 is 27,178,918 bytes). U-2's 1.123x was
protoc `-g`, where format 4 is 31,016,292 bytes: `-g` grows format 4 by
3.84 MB but format 5 by only 1.14 MB. On this branch:

| link | format 4 | format 5 | ratio |
|---|---|---|---|
| protoc | 27,178,918 | 34,910,642 | 1.284 |
| protoc `-g` | 31,016,292 | 36,052,992 (35,041,686 without DEBUG_STRS rows) | 1.162 (1.130) |
| clang `-g` | 246,166,746 | 194,585,779 | 0.790 |

**Table by table**, the leaders. Full lists:
`.build/target-wp-157/wp247/real-*/size.txt`.

| table | protoc | protoc `-g` | clang `-g` |
|---|---|---|---|
| SECTIONS | 12,312,800 (35.3%) | 12,429,984 (34.5%) | 49,294,892 (25.3%) |
| STRINGS | 9,058,365 (25.9%) | 9,058,529 (25.1%) | 66,271,766 (34.1%) |
| DEBUG_STRS | 53,456 (empty) | 1,064,762 (2.95%) | 27,601,459 (14.2%) |
| SYMBOLS | 1,830,932 | 1,830,932 | 4,428,384 |
| INDEX | 1,284,808 | 1,284,808 | 11,835,110 |
| COPIES | 1,444,720 | 1,444,720 | 2,456,080 |
| RESOLVED | 1,424,060 | 1,424,060 | 3,444,304 |
| KEY_REFS | 1,407,784 | 1,407,784 | 5,684,848 |
| MENTIONS | 1,105,904 | 1,105,904 | 4,204,272 |
| FRAGS | 232,562 | — | 5,421,870 |

The capacity slack (`capacity` above `rows`, with its block lists) is
3,437,378 bytes on protoc (9.8%) and 5,333,446 on clang `-g` (2.7%). Of
that, the empty tables account for about 0.65 MB on every link: each
one's 4096-row minimum, for example DIAGS 226,160 and SYMTAB 148,032.

**Proposed diet** (bytes are protoc's unless stated; nothing changed):

1. **SECTIONS row, 76 to 52 bytes** (about 3.8 MB on protoc, 15 MB on
   clang `-g`; reads stay O(1)):
   - `align` as log2, u8: 7 bytes;
   - `sh_flags` as u32 (no flag above bit 31 is defined): 4 bytes;
   - `anchor_kind`'s padding folded into the align byte: 3 bytes;
   - `size`/`offset` as u32, with a refusal (`state-limit`) for an input
     section of 4 GiB or more: 8 bytes;
   - `place_offset` as u32: 4 bytes.

   What it costs a reader: the 4 GiB limit, and one shift for `align`.
   Dropping `SECTIONS.file` as well (the range already gives it) would
   save 4 more bytes but loses the reader's "range names another file"
   check. Not proposed.
2. **A small minimum capacity for an empty table** (for example 64 rows
   instead of 4096): about 0.6 MB on every state. Cost: a table's first
   rows outgrow it sooner, so the update may compact earlier. That is
   rare, and only on the first growth.
3. **DEBUG_STRS's hash to u32** (13 to 9 bytes): 8.3 MB on clang `-g`.
   Cost: more equal keys, so the reader compares the bytes. The row
   already allows duplicates, and the reader would need the output's
   bytes to tell them apart. Not proposed without a ruling. The cheaper
   alternative is to keep 13 bytes.
4. **STRINGS**: section names repeat their anchor symbol's name
   (`.text.` plus the name, under `-ffunction-sections`). Storing a
   section's name as a prefix code plus its anchor could save most of
   those bytes. Not measured here, so measure first.

## 12. Proposed spec text (not edited in `spec/incr.md`)

- **IN-18e**, the table list: `DEBUG_STRS` (57), key-keyed, 13-byte
  rows `out` u8, `hash` u64, `offset` u32. The key is `(out, hash)`, and
  equal keys are allowed: the reader takes the lowest offset. There is
  no tomb, and an update only puts rows.
- **IN-18e**, `FILES.flags`: bit value 16 is `DEBUG_EXPORTS`, set when
  the file defines a global, weak or unique symbol in a non-alloc
  `.debug*`/`.zdebug*` section.
- **IN-78**, the compaction's renumbering: "`DIAGS.unit` of a file phase
  is a `FILES` row, renumbered with them." DEBUG_STRS is rewritten
  whole: sorted, one row per key, the lowest offset kept.
