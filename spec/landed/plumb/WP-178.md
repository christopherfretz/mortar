# WP-178: the references' undefined-weak value through a demoted COMDAT mention (A103)

Verifier package after WP-176 (`spec/resolve.md` §6.2 the demotion
bullet, §6.3 case (b); record `spec/landed/resolve/WP-176.md`). Written
from the specs and from the outputs; no linker crate was read.

## 1. R5 is the rule's finding, not an accident of the order of checks

A relocation in a kept section against a non-local symbol DEFINED in its
file in a section of a dropped COMDAT copy: the symbol is a demoted
mention (resolve.md §6.2), an undefined mention of its key. When no
definition of the key has a place, `spec/plumb.md` §4.4 step 0 ("a name
every input definition of which is in a section without a place is that
section's") makes the target the dropped section, and §5.7 makes that
R5 "refers to section '…', which is not in the output". That is the
model of §6.3 case (b): no value exists for the reference in ANY output
kind, weak or strong. The spec did not say so for a demoted mention; the
rule's sentences are now `spec/plumb.md` §5.7a (new), with the
loader-binds clause of §4.4 step 0 extended to executables and §12.1's
model bullet.

## 2. The anomaly: A103 (ids taken: A103 only; A89 left unused)

`spec/plumb.md` §10.2 A103 (GNU ld, lld), `anomaly::classify`. One id for
every form (static call, GOT word, dynamic and `-shared` `WEAK UND`
import, archive member and `--as-needed` library left out): what is
written is in each output kind exactly the undefined-weak reading of the
reference, and one judgement decides each form.

How it matches only this defect (§5.7a): a record in an allocated
section against a **weak** symbol of its file defined in a section the
verifier's keeper drops and that has no place, which step 0 makes R5, is
judged a second time as an undefined weak reference (a trial whose
outcome is not kept: coverage and findings restored). Only when that
trial verifies or accepts the field, with no finding and nothing
uncounted, does the R5 text end "(a weak mention defined in a dropped
COMDAT copy, whose key nothing live defines, written as an undefined
weak reference: resolve.md §6.3 case (b))"; `classify` names A103 only
for GNU ld or lld, `Rule::DiscardedTarget`, and that ending. A GOT
record is decided with its group (`finish_got`): the tag only when the
group's slot verifies, before the slot's word enters view 2's list.

## 4. What the lane showed and what the verifier needed besides

- **P-D7 "'hx' is imported and no input references it"** on every
  reference's dynamic output: the model (`dynmodel::keys_of`) took the
  demoted mention as a definition. It is now an undefined mention of its
  binding (§12.1).
- **The keeper's order.** The verifier's keeper used `FileId` order,
  which is the line's for a mortar or GNU ld map but not for lld's: lld's
  map lists a file where its first section is placed, so `wb.o` (with an
  `.eh_frame`) came before `wa.o` (only `.data.g`) and the verifier kept
  wb.o's copy: lld's dynamic outputs drew untagged R5 and P-D7. The
  keeper of §5.7a and of the model now follows the line the verifier
  reads (`Engine::set_keeper_line`, `fate::comdat_dropped_ranked`; an
  object the line does not name keeps the rank of the one before it).
  The keeper of §3.3 (`collect_empty`, M10 on mortar's map) is unchanged.
- **A needed library binds the key.** Under `--no-as-needed` the key is
  live; step 0 gave R5 on mold's correct output. Step 0 now steps aside
  when the loader model binds the name to a needed library's definition
  or to a `COPY` of one (`loader::View::copied`; mold copies hx on
  x86-64).
- **x86-64 lld's A25** (WP-176 §6's note) was not A25: it was view 3
  repeating step 0's R5 ("still sees the absent definition (refers to
  section '.data.g' …)"). With the binding fixed, view 3 binds the key to
  its fresh address and the absolute uses are unfillable overflows
  (D-25): no finding, nothing to declare.

## 5. Findings on linker outputs (bytes and runs checked)

- **mortar refuses a correct program** (no output is wrong):
  `gcc -static -no-pie wu.o wa.o wb.o libhx.a` where wu.o references hx
  strongly and first: resolve.md §6.2 makes wb.o's demoted weak mention
  an undefined weak for extraction, so wu.o's strong reference extracts
  libhx.a's member and hx is defined (15). mortar answers `symbol hx is
  defined only in a discarded copy of COMDAT group g` (referenced by
  wu.o and wb.o); with hx.o on the line in place of the archive it links
  and the program exits 15. Test
  `resolve/comdat-mismatch-weak-archive-extract.test`, `xfail(mortar)`.
- On that line GNU ld and mold refuse (undefined reference to hx: both
  take the dropped copy as a definition when they scan the archive),
  and **lld writes a wrong output**: no member extracted, both calls
  (wu.o's strong one included) written as the undefined-weak value; the
  verifier's R5 at wu.o's call (`xfail(lld)`).
- **x86-64 lld, `--no-as-needed`** (`comdat-mismatch-weak-needed-live`):
  libhx.so is needed and defines hx, but lld writes hx as a `WEAK UND`
  import with 0 in the absolute fields and no record: the program exits
  1, not 8 (qemu); mold copies hx and exits 8. The verifier's R2 (the
  library's address cannot fit the 32-bit field). `xfail(lld,x86_64)`;
  AArch64 lld (GOT + `GLOB_DAT`) is right.
