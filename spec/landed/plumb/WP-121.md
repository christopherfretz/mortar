# WP-121 — stage 3 for shared objects (P-D16..P-D26)

Branch `wp/121-plumb-shared`. Written from `spec/plumb.md` §12.5,
`spec/dyn.md` §17 and `spec/resolve.md` §9.7 only; no linker crate was
read. This record covers part 1: P-D16..P-D22 with the interposer
model, P-D25 and P-D26, the line records (§3.2) (§1-§5); part 2: the
address clause of P-D17 with `sharedflow.rs` (§6), P-D23's table (§7),
the §8.1 sizing (§8), and the fixes made after part 1 landed (§9).

## 1. Subjects

There is no mortar library before WP-123. The subjects are libraries
compiled and linked at test time (`tests/shared.rs`, sources in
`tests/shared/`) by GNU ld, lld 22 and mold, on AArch64 and x86-64,
through a driver whose `ld` records the words it was given (the line is
the reference's, as `tests/dyn.rs` does for executables):

- `forms`: `lib.c` (default, protected, hidden and static data; a
  default and a hidden `__thread`; a weak, a default and a protected
  function; address words of exports and imports) against `libdep.so`,
  under six lines: plain, `-Bsymbolic`, `-Bsymbolic-functions`,
  `--dynamic-list`, a version script with `local: *`, and `-Bsymbolic`
  with `--dynamic-list` (W31);
- `more`: initial-exec TLS, a preemptible IFUNC whose address is taken,
  `__start_`/`__stop_` of a C-identifier section, `-init`/`-fini`, an
  archive member under `--exclude-libs,ALL`.

## 3. What is implemented

- `shared::SharedLine` reads D-112's facts from the words (the `-B`
  forms in order, list and script files, `--exclude-libs`, `-soname`,
  `-E`); the refused forms (`--dynamic-list-data`, `-cpp-new`,
  `-cpp-typeinfo`, `-Bsymbolic-non-weak*`, `extern "C++"`,
  `duplicate-version-pattern`, a `.symver` node the script lacks) are
  P-D1 by name.
- The version-script and dynamic-list reader and resolve §9.7's
  decision, `fnmatch` without flags; unit tests.
- `shared::compute`: the export set (merged visibility, live
  definitions only, file 0 keys when a needed object references them,
  `__start_`/`__stop_` `PROTECTED`, optional from mold), the local keys,
  the imports, each export's binding by D-112's table.
- P-D19 `.dynsym` against the set (name, version through
  `.gnu.version`/`Verdef`, binding, type, visibility; GNU's node-name
  `SHN_ABS` entries accepted).
- P-D20 (COPY, canonical PLT, `DT_TEXTREL`, a record in a read-only
  place, an input LE form, `.ctors`/`.dtors`), P-D21, P-D22 (symbolic
  tags per reference, `DT_INIT`/`DT_FINI`, `DT_SONAME`, `Verdef`,
  `GNU_PROPERTY_1_NEEDED`), P-D25 (record kinds; a record past
  `.dynsym`), P-D26 (no relaxation from the engine's coverage,
  `DF_STATIC_TLS`, mortar's TLSDESC table).
- Views: view A is P-D9's views 1 and 2 with each preemptible IFUNC key
  given a fresh "resolver's result" reachable only through a record
  naming it (P-D18); view B replaces view 3: the interposer defines
  every export and import (functions a page apart, data at fresh
  allocations of `st_size`, TLS in module 257's block); the engine
  expects the interposer's for preemptible keys and imports and the
  library's own for bound keys; `DT_SYMBOLIC`/`DF_SYMBOLIC` make the
  loader model bind the library's own (glibc), so W31 is seen.

## 6. The address clause (P-D17, D-117; `sharedflow.rs`)

Written from `spec/dyn.md` D-117 only (WP-119's `regflow.rs` was not
read). Two pieces, as P-D17 asks:

- **the relocation-level rule**: a relocation whose exact field names an
  address inside a preemptible data definition other than at its start
  (`T + A` in `[st_value, st_value + st_size)` of a definition the sets
  make preemptible); on x86 only absolute fields, `GOTOFF` and
  PC-relative fields in data places (no x86 decoder: a section-relative
  PC-relative code field is counted `not_judged`); the boundary rule
  (`m - 1` is a bound use when the object has no self-GOT or the use is
  an access); "before the start" (an address below a local object's
  start that lands in a preemptible one: the known refusal of correct
  code, reported like the linker's);
- **the AArch64 analysis**, items 1-9: the pre-filter (an object with a
  preemptible data definition and a section-relative defining form),
  functions from `STT_FUNC` and `$x`/`$d`, the defining forms (`ADRP`
  with `ADD`/`LDR`/`STR` low-12, `ADR`, `LDR` literal), register states
  propagated over the control flow (leaders, `B`/`B.cond`/`CBZ`/`TBZ`,
  `BR` ends a block, calls kill x0-x18 and x30, x19-x29 kept), a
  greatest fixed point with TOP for a predecessor not yet computed
  (`MAX_PASSES` = 64), and the verdict: an access or an address formed
  inside a preemptible definition.

Entry point `sharedflow::address_clause(&objs, &sets) -> (Vec<Finding>,
u64)`, called in `dynverify.rs`'s `Shared` branch; objects are read
through `Unit` (by position, §8.1): an object without a preemptible data
definition reads nothing but its skeleton. Messages: "the address clause
(D-117): {type} at {section}+{offset} of {object} names {T}+{a}, inside
the preemptible '{def}' ..." (the rule) and "the address clause (D-117
analysis): {function}+{offset} of {object} accesses|computes ..." (the
analysis), each ending with `non-pic-in-shared-object` and the remedy.
Tests: `sharedflow.rs` units `d117_flow_classes`, `d117_load_store_forms`;
`tests/shared.rs` rows `gap-pie` (W44: the analysis, all three
references), `before-O0` (the rule: "before the start"), `gap-pic`,
`gap-bsym`, `before-O2` clean, `hole` (the residual hole, NOT caught).

## 8. §8.1: the analysis on the largest AArch64 bench link

`cxx-large-g` (`.build/bench-work/`, 122 inputs, 2.43 GB, largest
`libclangSema.a` 284 MB, no `-l` libraries): 3,499 objects (3,489
archive members) read as if `-shared` with the default line (every
global default-visibility definition preemptible), through the ignored
test `oracle_lists` (dev profile) under `prlimit --as=8589934592` and
`nice -n 10`, load 9.8: 2.49 s wall, 0.14 s user, 1.59 s system, peak
RSS 308 MiB (315,648 KB). No object passes the pre-filter (pre 0, rule
0, analysis 0, words 0): the bench is compiled with `-fdata-sections`,
so every global datum has its own section and code names it by its
symbol, never by a local anchor; D-117 has nothing to decide. The cost
is the skeleton read (section headers, symbol tables, relocation heads),
and the time is the I/O of 2.4 GB. The peak is the driver's: it holds
one input whole (the largest archive, 284 MB); the verifier's path
reads through `Unit` by position and was not measured on this link.
Against §8.1: well under the 4 GB cap and 2x the linker's peak (1,958
MiB). The heaviest analysis measured is sys.lst's (11,699 members, 28
objects analysed, 0.09 s).

## 13. Proposed follow-up (harness; not done)

A reference's wrong output costs today a whole-test `xfail(<linker>)`
(`reloc/x64-gotpcrelx-slot.test` for lld and mold), which also hides
that test's other checks for that linker. Proposed: an expected
verifier finding per link line (the rule id and text the verifier must
report for that linker), so the test still runs every other check and
fails if the finding disappears or another appears.
