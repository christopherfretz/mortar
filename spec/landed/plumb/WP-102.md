# WP-102 — the command line is in every map, and the verifier reads its options from it

Branch `wp/102-args-in-every-map`, cut from main and merged with main
twice: 58383ca (WP-101's 85e4b59) before step 3, and after step 3 with
main 64a09af (WP-100, WP-103, WP-081). Three steps, one commit each:

1. `c617755` — the line specified (`spec/plumb.md` §3.2, the new §3.2a,
   §5.10, §6.7, §6.10, §11, §12.1, §13.1; `spec/a64.md` §11.3;
   `spec/image.md` I-78; `spec/synth.md` §17.7). The verifier accepts
   `arg` records in any map and reads its option-dependent rules from
   them, through one reader (`crates/mortar_plumb/src/opts.rs`). M9 is
   new.
2. `54c9b1a` — the linker writes the records in every map
   (`mortar_image` `map.rs`, `link.rs`; `mortar` `lib.rs`, `image.rs`).
   Before, only a dynamic link wrote them.
3. step 3 (this commit) — the verifier requires them. A mortar map with
   no `arg` record is a `MapError`. Every fallback is deleted: the
   caller's `Map.fix_843419` and `Ctx.line` for a mortar map, the
   `.gdb_index` chunk standing for `--gdb-index`, and the build-id
   chunk's style standing for the line's.

Out of scope and untouched: the erratum fix itself and the lanes'
argument passing (WP-103), output bytes, `xtask/src/realbuild*`,
`docs/BACKLOG.md`, kiln, hod.

## 1. The rules and where they read their option

`spec/plumb.md` §3.2a holds the table. Copied here as it landed:

| rule | option | mortar's map | a reference's map |
|---|---|---|---|
| C1, C5, C6 (§5.10; a64.md §11.3) | `--fix-cortex-a53-843419` given or not | the line | the caller (`Map.fix_843419`), else inferred from the fixes found |
| P-G6 (§6.10) | the last of `--gdb-index` and `--no-gdb-index`; `-s`, `--strip-all`, `-S`, `--strip-debug` | the line | not judged (mortar's rule) |
| B1 (§6.7) | the last of `--build-id[=STYLE]` and `--no-build-id`: presence, length, tree | the line; a style the chunk states must be the line's | not judged |
| P-M1's kept section, P-M2's presence, P-M3's second half (§13) | `--keep-mason-meta`; the last `--odr-table`; the last of `--odr=M` and `--no-odr-check` | the line | none |
| P-D4's `PF_X` (dynamic), S10's `PF_X` (static, new) | the last of `-z execstack` and `-z noexecstack` (L-84) | the line | P-D4: the caller's line; S10: not judged |
| stage 3 (§12, P-D1 to P-D15) | the whole line | the line | the caller's line (`Ctx.line`); without one, P-D2 |
| M9 (new) | any word: a word no accepted option spells | the line | none |

Reading the words follows `spec/cli.md` §2: the forms, the lookup order,
abbreviations, values, `-z`, and the last of an option and its negation
winning. The rule cites that section and does not restate it. The
accepted spellings are a copy of the rows of `docs/status/options.md`
that mortar does not refuse. The test
`opts::tests::s3_2a_accepted_is_the_options_table` keeps the copy equal
to the table.

Before this package, four places parsed the words, and each did it
differently:
- `gdbnames.rs`;
- `odrtable.rs` `options`;
- `dynverify.rs`;
- `xtask/src/plumb.rs`, for the erratum flag.

All four now read `Options` from `opts.rs`. `xtask plumb`'s erratum
flags and `--line` remain for reference maps only.

A link with no words cannot write a map. A link of no word is
`no-input-files`, which writes no map, and `-o` alone is not a link.
So the requirement in step 3 refuses no map that mortar can write.

## 2. The version decision: stay at `mortar-map 2`

The `arg` record has been in version 2 since the dynamic links had it.
A dynamic map is unchanged by this package: its records and their place
(the dynamic-records group, after `relro` and before `needed`) are the
same. A static map gains `arg` records in that group and nothing else.

A version-2 map from before WP-102 is either:
- dynamic: it already had its line, and is read as before; or
- static: it has no `arg` record, and step 3 refuses it by name
  (`MapError`: "no 'arg' record: a mortar map states its link's line").

Neither case judges a link by a fact its map does not state, so the
version number need not move. Contrast WP-096, where a missing record
was itself a statement and the version had to move. Here a missing
record cannot occur silently: the map is refused.

## 3a. The merge with WP-103: one truth for the erratum option

WP-103 gave every lane the linker's words and had
`xtask::plumb::line_fix_843419` tell the verifier the erratum option
from them, for mortar's outputs too. After step 3 the verifier does not
read a caller's option for mortar's map. The merge makes the lanes say
the same thing:

- `xtask/src/plumb.rs` `verify_link_line`: sets `Map.fix_843419`, from
  the caller's word or the line, for a reference's map only.
- `xtask/src/linktest/engine.rs`: a mortar output is verified with
  neither the option nor the words; a reference's with both, as WP-103
  had it.
- `xtask/src/census.rs`: the same; census judges mortar's outputs only.
- Counting: the summary note ("N with the option (S sites fixed, U not
  judged), M without (K sites)", linktest and census) counts a mortar
  output under `Coverage::erratum_option`, the option the verifier read
  from the map's line. `erratum::check` now states it for every mortar
  output, whatever the machine, so an x86 output still counts as
  "without".
- `spec/harness.md` L3 ("The erratum option", "The note") and the bench's
  verifier step now say that a mortar output's option is its map's line.

## 5. Mutants

Each rule that moved to the map has mutants of three kinds:
- the option's word removed;
- the word added;
- the word negated later in the line.

Each mutant changes the verdict as §3.2a says. The tests:

- **B1:** `crates/mortar/tests/options.rs` `build_id_styles`.
  - Mutants: `--build-id=sha1` removed; `--no-build-id`,
    `--build-id=sha256` and `--build-id=fast` added later; on a plain
    link, `--build-id` and `--build-id=sha1` added.
  - `crates/mortar_plumb/tests/mutation.rs` `s9_2l_*`:
    - the tree follows the line's word;
    - the chunk's `sha1` against the line's `fast` is B1.
- **S10 (static `PF_X`):** `options.rs` `execstack`.
  - Mutants: `-z execstack` removed; `-z noexecstack` and `-znoexecstack`
    added; on a plain link, `-z execstack` and `-zexecstack` added.
- **P-G6:** `options.rs` `the_line_decides_the_rules`.
  - Mutants: `--gdb-index` removed; `--no-gdb-index`, `-S` and
    `--strip-all` added; on a plain link, `--gdb-index` and the
    one-dash `-gdb-index` added.
  - `tests/gdb_index.rs`: on lld's indexed links, removing the word, a
    later `--no-gdb-index` and `-S` each give P-G6. With the word
    stated, removing the chunk also gives P-G6: the chunk no longer
    stands for the option.
- **C1/C6:** `crates/mortar/tests/pipeline.rs`.
  - Removing `--fix-cortex-a53-843419` from a fixed link's map gives C6.
  - Adding it to the map of a link made without it gives C1.
  - `mutation.rs` `s9_2o_erratum_rules_on_mortar_output`: the word
    taken off the line gives C6 on each fix.
- **P-M1:** `crates/mortar/tests/keep_meta.rs`
  `the_kept_section_follows_the_line`, on static links: removing or
  adding `--keep-mason-meta` gives P-M1.
- **M9:** `--no-such-option` and `-z no-such-keyword`, plus `opts::tests`
  for each kind of word M9 names.
- **The requirement:** `map::mortar::tests` checks that
  `"mortar-map 2\nend\n"` is refused.
- **P-M2:** `crates/mortar_plumb/tests/meta.rs` (dynamic PIEs, which had
  their line before this package): `--odr-table=full` removed, replaced

Not mutated separately:
- **P-M2 on static outputs, and P-M3's first half:** they read the same
  `Options` as the PIE cases above and P-M1. `opts::tests` covers the
  words (last wins, `--no-odr-check`, the abbreviations).
- **No negation mutant for `--fix-cortex-a53-843419` or
  `--keep-mason-meta`:** mortar has no negation of either. A
  `--no-fix-…` word is M9.

## 6. Still read from the caller, and why

- **Reference maps (GNU ld, lld, mold):** they have no line, so the
  caller still supplies one: `Map.fix_843419`, `Ctx.line`, and
  `xtask plumb --line` / `--fix-cortex-a53-843419`.
- **P-M3's second half on a static output** ("every relocatable file
  the map names is on the command line"): this needs the line's files
  found as the linker found them (`-l` searched in `-L`, scripts read),
  which only stage 3's `Ctx.files` has. It is not judged on static
  outputs.
- **S7's entry (`-e`):** judged in stage 3 only (P-D4). A static
  output's entry is held to "some symbol's value".
