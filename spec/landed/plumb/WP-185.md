# WP-185 (RL-5): stage R, the verifier of `-r` outputs (landed)

Branch `wp/185-plumb-relocatable`. The rules are `spec/plumb.md` §14
(RL-0's text, WP-180), implemented in `crates/mortar_plumb/src/
relocatable.rs` (the dispatch, the places, P-P2, P-P3, P-P7, P-P8,
P-P10, P-P11, the map's `-r` records), `relsym.rs` (P-P4), `releh.rs`
(P-P5) and `relgroup.rs` (P-P6). They were written from the spec and from
measurements of the references' outputs. No linker crate was read (not
`crates/mortar*` other than `mortar_plumb`, `mortar_elf` and
`mortar_testutil`). P-P1 and `compose.rs` belong to RL-6 (WP-186).

## Entry point (for RL-6)

```rust
pub fn mortar_plumb::relocatable::verify(
    output: &[u8], src: &dyn Source, map: &Map, ctx: &Ctx<'_>) -> Report
pub const mortar_plumb::STAGE_R: bool = true;
```

`verify_with`, `verify_from` and the dynamic entry point hand an output
to it when the output is `ET_REL`, when its map has `output
relocatable`, or when a foreign map's line has `-r`, `-i`,
`--relocatable` or `-Ur` (P-P9). `ctx.line` is a reference's line.
`Report::summary` adds `relocatable: pieces {n}, merged {m}, framed
{f}; groups {g}; FDEs {k} live, {r} removed; symbols {s}; sections {h}`
(§14.6). A test-only helper, `#[doc(hidden)]
relocatable::as_mortar_map`, renders the verifier's own reading of a
reference's output as a mortar map. Mutations use it where a mortar
clause needs mortar's records (see "Not verified").

## The map at `-r` (§14.2)

`map/mortar.rs` reads `rplace`, `rframe`, `rgroup`, `rcommon`,
`discard` and `output relocatable` in any order; the writer gives the
same text back. The unit test is `map::mortar::tests::s14_2_relocatable_records`:
the brief's sample in both orders, then 10 malformed maps, each
rejected at its line. One fix was found by the mutations: the `-r`
records created `map.rel`, so an `output relocatable` that came after
them was read as "a second 'output' record". The kind is now known by
`RelRecords::line != 0`. Foreign maps (GNU ld, lld, mold) are read as
§14.1 and §14.2 say: see questions 1-3.

## Questions to the supervisor

Each question gives the cell and RL-5's reading as implemented. None
changes what a rule means for mortar's output.

1. **§14.1, FileId order for a foreign map.** RL-5 numbers a foreign
   map's files in the order of the line's inputs.
2. **§14.2, mold's address-0 rows.** mold's non-alloc rows have address
   0. RL-5 lays them end to end, each aligned to its section's
   alignment.
3. **§14.2, which input section a row names**, when several sections of
   one name come from the copies. This cell was open. RL-5 takes the
   first unassigned section of the row's size; among several of that
   size, the one whose bytes outside its relocated fields equal the
   output's at the row's place. It was measured with
   `-fdebug-types-section`: GNU ld lists the CU that its script places
   first, and mold lists type units in its own order. Matching the k-th
   section of a name gave 4679 false findings.
4. **P-P7, `EI_OSABI` and `SHF_GNU_RETAIN`.** GNU ld writes
   `ELFOSABI_GNU` for a retained section (`rl0` 7 and 14). RL-5 accepts
   this from GNU ld only, as a per-linker form of the "when ... else"
   sentence.
5. **P-P11, `sh_entsize` "or 0".** RL-5 reads it as: 0 is accepted
   whatever the pieces' value. Also, the array sections
   (`INIT`/`FINI`/`PREINIT_ARRAY`): GNU ld writes the pointer size where
   clang's pieces have 0. This is accepted for references, not for
   mortar.
6. **P-P8, the container.** A reference concatenates the input
   containers, each at a multiple of 8 (`tests/meta`'s `b.o` has 8 zero
   bytes between its units). RL-5 accepts that from the references;
   mortar must write `kept_units`. Without this, every linker fails
   P-P8.
7. **§14.9, mold and IFUNC.** mold 2.37.1 crashes (`SIGSEGV`) at `-r` on
   an input that defines an IFUNC (`cifunc`). It is not run there,
   because a crash is not an output to judge.
8. **A120.** lld writes an empty `NOBITS` `COMMON` section. It is named
   as an anomaly (P-P11, "comes from no input section"), not as a
   per-linker form.
9. **A121-A124**, the new mold anomalies, as §10.2 states them.
10. **A125.** lld's `NONE` records in `.eh_frame`'s relocations are
    named as an anomaly. GNU ld's identical form is P-P3's per-linker
    list, which names GNU ld only.
11. **A126.** lld keeps a dropped copy's `wi.` signature as an
    `SHN_ABS` local.
12. **A section that §14.3 drops and the map places.** §14 does not
    say which rule names it. RL-5 makes it P-P2: "{file}:({section}) is
    in the output; §14.3 drops it: {why}". A second place is M2, as P-P2
    says.
13. **§9.2 (t) (4) says "P-P6 and P-P2".** The measured rules are P-P6
    and P-P11. The copied group's members are sections that the map
    does not place, so they "come from no input section" (P-P11). P-P2
    would fire only if the map placed the losing copy. The text should
    say P-P11, or P-P2 when the map is edited too.
14. **§9.2 (t) (15) "on a `--unique` output".** GNU ld's bare
    `--unique` affects orphan sections only, and `.text` is not one at
    `-r`, so there is one `.text`. RL-5 uses `--unique=.text` on a
    two-input case (`unique`; `rl0-1-maps`' `m1.o` has no `.text`
    records on x86-64 and i386).
15. **§14.6, `options-unknown`.** Stage R never counts it: at `-r`, an
    unknown option is not a coverage term. Should it be?
16. **Outside §14 and §10.2, still marked "planned: RL-5"**, which is not
    RL-5's to edit: §3.2's `output relocatable` row (line ~216), §7.1's
    ids (line ~3647), §9.1's relocatable corpus (line ~3897) and §9.2
    (t)'s lead sentence (line ~4150).

## Not verified

- **P-P1** (RL-6), and mortar's own `-r` output: there is none yet
  (RL-7).
- **The mortar-only clauses** (L-R8's header order, I-R4's local order,
  the `rframe` record map, tombstones, the exact L-R6 `.eh_frame`) are
  exercised only through `as_mortar_map`. That map is the verifier's own
  reading of GNU ld's output rendered as mortar's map, so a mutant tests
  the clause against a mutated output, not against an independent
  writer. The brief's sample map is read by the unit test only.
- **Not exercised by any fixture:**
  - `rcommon` (`-d`/`-dc`/`-dp`);
  - `--build-id` at `-r` (B1's whole-file descriptor);
  - `.symtab_shndx` and `SHN_XINDEX` (0xff00 sections);
  - `SHF_COMPRESSED` inputs;
  - `-b binary` inputs;
  - `-s`/`-x`;
  - `-u`;
  - `--force-group-allocation`;
  - archives with members at `-r`;
  - the x86-64 `SHT_X86_64_UNWIND` mix.
- **Mutants by target:** (10) and (12) do not run on i386, (14) runs on
  AArch64 only (gcc's `.eh_frame` `$d`), and (11)'s opcode cells differ
  by target as §9.2 (t) lists them.
- **Determinism** (I-R11) and the file mode (I-R3) belong to the lane.
