# WP-161: the `-shared` option tail and the `Shared` sweep (verifier)

Follow-up to WP-128 (mortar's option tail of `-shared`: the D-103 `-z`
flags, `-Bsymbolic`, `--dynamic-list`, `--exclude-libs`, `-init`/`-fini`;
`spec/dyn.md` D-102, D-103, D-110, D-112). Two false findings on
mortar's correct outputs are fixed and their markers removed. The rules
now take what they need from the line. The lane's byte sweep gains two
`Shared` cases. The export set keeps one derivation
(`shared::ExportRule`, WP-149). The edits to it are additive: two new
inputs, `excluded` and `only`. How a key's definition is chosen among
COMDAT copies is unchanged.

## Part 1: the two false findings

1. **P-D7 on `dyn/dynsym/exclude-libs-exe` `e-ex`** (`-pie -E
   --exclude-libs ALL`).
   - Cause: the rule did not read `--exclude-libs`, so `-E` wanted the
     excluded definitions exported.
   - Now: the line reader takes `--exclude-libs` (every kind) from the
     options table (`line::INTERPRETED`). The model marks a key
     `excluded` when every relocatable definition of it is in a member
     of an archive the option names. Such a key is exported by nothing:
     not `-E`, not a list, not a shared object's reference (D-21).
   - A true shared object reference to an excluded definition stays a
     finding. It is P-D6, "... which no export gives, D-110 item 1 (D-13:
     the link is refused)". mold's `bad-mold` (it links; the loader
     exits 127) is now FOUND by name and classified A36. GNU ld, lld and
     mortar refuse that link.
   - Markers: the `xfail(mortar)` line is gone. The test's `(mortar)`
     qualifiers on the `e-ex`, `s-ex` and `d-ex` steps are gone, so every
     linker's excluded outputs are judged. `#@ anomaly(mold): A36` and
     the `bad-mold` link and run steps are added.
2. **P-D6 on `shared/shared-dt-flags` `liborigin.so`**.
   - Cause: P-D6's mask did not let `DF_ORIGIN` through in `Shared`.
   - Now: P-D22 holds `DT_FLAGS`' `DF_ORIGIN` to the line's `-z origin`
     in every format. P-D6's mask lets it through. Marker removed.

Y3 accepts an excluded name whose `.symtab` entries are all
`STB_LOCAL` or `STV_HIDDEN` (one defined). Measured on `d-ex` (`-pie`
without `-E`): GNU ld writes `foo_fn` `LOCAL DEFAULT` and `foo_data`
`GLOBAL HIDDEN`; lld and mold write `LOCAL`; mortar keeps `GLOBAL`
(WP-150's question, not judged here). D-110 says only "local": the
GNU ld form is a spec gap, reported below.

## Part 2: what the rules derive from the line

Each item has a sentence in `spec/plumb.md`, a mutation a rule
catches, and no false finding on any reference.

`-init`/`-fini` naming a data object (measured, scratch tests
`init-data.test`, `init-data-exe.test`): GNU ld, lld and mold all write
the data object's address, in a library and in a PIE. GNU ld's PIE dies
at start-up (SIGSEGV, exit 139). The loader calls the address, so it is
a FINDING of every format, not an anomaly. No reference link test links
it, so no anomaly row is needed.

### P-D17 view B, P-D25, P-D22 with a dynamic list: the record's table

Judged before WP-161:
- `Shared`: the union of the list files; quoted names and globs.
- `Shared`: `extern "C++"` blocks are P-D1 (outside stage 3).
- `Shared`: the export set is unchanged by a list (D-112).
- `Shared`: an unlisted TLS or IFUNC key. GNU ld's preemptible
  exception; lld's x86-64 W43, found; mold and mortar bind it.
- `Shared`: P-D22, no `DF_SYMBOLIC` with a list (W31).

New in WP-161:
- An executable's listed definitions are exported (P-D7).
- An executable's `--gc-sections` roots include the listed keys (M10,
  through `ExportRule::executable`).
- A key that is listed and excluded is not exported.
- A reference's static-pie with a list is no longer reported.
- `extern "C++"` in an executable's list is P-D1.
- Mortar's `libdl` (`-Bsymbolic --dynamic-list dl.list`) without its
  list (the `arg` words and the `dynamic-list` record dropped) is
  found by all three rules: P-D22 ("the line's symbolic form is all
  without --dynamic-list"), P-D25 (a record names `opt_fn`, which the
  line then binds) and P-D17 view B (the interposer defines `opt_fn`;
  the call should be bound).

Not judged: the executable's archive extraction (WP-156's input set);
whether an executable exports MORE than W8, `-E` and its list (WP-157).

### The map's record of the list

The map's `dynamic-list <path>` and `version-script <path>` records
(`Shared` only) give the path, never the content. The verifier reads
each file from the path the line names, relative to the link's
directory (`Ctx.files`). §3.2a's table now says so. A file changed
after the link is judged as it now reads. A content digest record
would close this; it is not proposed here.

## Part 3: the `Shared` sweep

`xtask/src/sweep.rs` gains two cases, both in `--quick`:
- `shared`: a `-shared -fPIC` library of two version nodes
  (`--version-script`, `-soname`). It has an exported and a local TLS
  variable reached through TLS descriptors (AArch64
  `-mtls-dialect=desc`, x86-64 `gnu2`), and a PLT call.
- `shared.tail`: the same source unversioned (every default global
  exported), under the five D-103 `-z` words, `-Bsymbolic`,
  `-init`/`-fini` and `--exclude-libs ALL`.

`mortar_plumb::sweep` now covers `.gnu.version_d` too: the
Verdef/Verdaux fields, by name.

How each survivor is closed:

| survivor | closed by |
|---|---|
| `DT_SYMBOLIC`'s `d_val` | equivalent, new row of §12.3's table and `sweep::EQUIVALENT`. The gABI gives its `d_un` as ignored; a loader reads the tag's presence only. |
| `DF_ORIGIN` | P-D22 (part 1) |
| bit 7 of an export's `st_other` | P-D7, new: on AArch64 an export's `STO_AARCH64_VARIANT_PCS` is its input definition's (AAELF64); x86-64's was P-D7's already. Test `p_d9_tls_descriptor_words_and_variant_pcs`. |
| the exports' `.gnu.version` entries | caught in both cases by P-D8 and P-D27 (no new rule) |
| a TLS descriptor's `.got` words 6 and 7 | P-D9 (mortar), new: both words hold 0 in the file (D-119, "place 0 under RELA"). The loader writes both, so for a reference they are equivalent and not judged. Same test. |
| `.plt` padding | equivalent (the existing row) |
| `.dynsym` entry 0's `st_name` (new, found by this sweep) | P-D7 now reads the field, not the string. A flip to an offset at a `.dynstr` NUL read as "". |

Time (load about 20, 4 threads, one architecture): about 20 s per case.
The two cases add about 40 s to the quick gate on its one architecture.
Bytes: AArch64 1815 and 1696, x86-64 1712 and 1593. Every flip is caught
except the equivalent fields'.

## What the specs leave unsaid (measured)

- D-110 item 1 says an excluded definition becomes local. GNU ld leaves
  a data object `GLOBAL HIDDEN` in `.symtab` (`-pie` without `-E`).
  Y3 accepts it.
- D-102 does not state `DT_SYMBOLIC`'s value. mortar writes 0.
- D-103 does not say whether `-init`/`-fini` may name data. Every
  reference writes the address and GNU ld's PIE crashes. The verifier
  calls it a finding.
- mold writes no `DF_SYMBOLIC` under `-Bsymbolic` in `liball` (W31's
  row stands).

## Not verified

- An excluded key whose definitions are partly in an excluded member
  and partly elsewhere is taken as not excluded. No reference test
  links that shape.
- The list file's content at link time (only the path is recorded).
- `--exclude-libs` naming an archive by a path with directories: it
  matches by file name, as GNU ld documents. Not measured on lld or
  mold.
