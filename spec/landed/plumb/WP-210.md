## 0. What needs a ruling

1. **A129-A131** (reference anomalies for WP-203's Y5 findings): A129
   GNU ld's `_edata`/`__bss_start` and lld's `__bss_start` at `.bss`'s
   start when `.bss` is `PROGBITS`; A130 GNU ld's AArch64 `__bss_end__`
   before a `COMMON.x` orphan; A131 mold's split `COMMON`
   (`__start_COMMON`/`__stop_COMMON` of the last piece). The lane's
   `#@ anomaly` declarations for WP-203's steps (`tests/link`, not mine):
   bfd A129 for `prog*`/`ro*`/`nogc`, bfd,aarch64 A130 for `dotx*`, mold
   A131 for `gc`/`nogc`. With them, the lane over WP-203's steps: 114
   PASS, 0 FAIL.
2. **R5 into an input `COMMON`** was the rule's gap, not the references':
   `locate.rs` `common_sections` places an input section named `COMMON`
   by the file's `COMMON` row (§3.4-§3.6 paragraph "An input section
   named `COMMON`"). Under lld and mold a row at a `SHN_COMMON` global's
   output value is that common's (lld lists its commons first in `.bss`,
   the section in input order: two 8-byte rows of the D.3 C component's
   `-r` output, the first holding `common_x`; measured on AArch64).
3. **P-P1 item 2's order** compares the pieces both links place: the `-r`
   output's `COMMON` section (A120, it holds nothing) is a piece of `V`
   only. Before WP-210 no reader placed it, so it never entered the
   comparison; once placed it made a false order finding on
   "compc -r lld final lld".
4. **P-I8 item 3 and `.tbss`.** The final gate's `ci --quick` failed
   two `crates/mortar` `incremental` tests on P-I8 item 3: a `.tbss` input
   (`place 3 8 4ddaf8 64`) judged against `.init_array`'s chunk at the
   same address. The rule was wrong: a TLS `NOBITS` input is now judged
   against the TLS `NOBITS` sections' chunks. Item 3's corpus (1,410
   incr-update outputs, the lane) had no `.tbss` overlapping a chunked
   section; the static libc C links of `incremental.rs` do.
5. **The COMDAT keeper**: two keepers, each held to its map. GNU ld and
   lld keep the first extracted member, mold and mortar the archive's
   first (mortar's `FileId`, §6.1). The code keeps the map's order for
   ties, so it is right for all four; the text says so (§5.7a).
6. **`DeadSlot`**: a hole inside the `.got` chunk leaves the live slots
   uncovered (P-I1, coverage's container rule), so the pin puts the hole
   at the chunk's end. A real dead-slot update is not producible on this
   base (`update-not-implemented (layout)`).
7. **Y5's script clause never applied before**: it read `opts.script`,
   and mortar refuses `-T`. It now reads the line's scripts' assignments.
8. **gnuindex's `-r` case**: since item 5 a mortar map's `arg -r` sends
   the output to stage R. P-P9 names an `ET_EXEC` output ("... the map or
   the line says -r"; the word is `output relocatable` only when the map
   has the record).
