## Finding 1: P-P1 item 3 on a merged string

RL-7's 36 findings on `r-kernel-style-m` and `r-kernel-style` (static,
mortar's final) were the verifier's. Item 3 took a field's target as
`S = field - A` for every record. For `C-address.o`'s
`R_AARCH64_ABS64 .rodata.str1.8 + 0x30` (a section symbol of an
`SHF_MERGE|SHF_STRINGS` section), `S` is no place: merged pieces are
not contiguous, so `field - 0x30` landed in `dl-support.o`'s `.rodata`
in `D` and somewhere else in `V`. Measured on the bytes: the field
holds 0x4139a8 in `D` (a `""` piece of `C-address.o`, offsets
0x2c-0x30, all at 0x4139a8) and 0x413988 in `V` (the `-r` output's
padding byte, `piece 4 5 7 413988 1`; every `""` of the link is merged
into it). RL-7's reading of the cause is right; the rule's verdict came
from the bad `S`.

As ruled, a field whose symbol is defined in an `SHF_MERGE` input
section, with a full-width field, is judged by content at `S + A`: the
same input flags and entry size, the same output section name and
flags, the same bytes from the place through the terminator (strings)
or the same entry and offset in it. Fields judged so are counted
(`merged-by-content=<n>` on the `composition compared` line); one whose
`V` place is not `φ` of the place by its piece counts as (t5). Measured:
(t5) is 0 everywhere. `φ` by piece already maps libc's `""` to the
padding byte, because mortar's map places each piece. The content rule
is the ruled tolerance, and it is visible if a link ever needs it.

Item 2 had a second false finding on the fixture: "kc.o:(.rodata.str1.8)
is in output section (no section)". It named the output section of a
mergeable input by `[addr, addr + sh_size)`, which runs past the end of
the merged section. It now names it by its first byte.

Mutants (`p_p1_merged_{aarch64,x86_64,i386}`: GNU ld's `-r` of `ka.o
kb.o`, mortar's finals; `kc.o` after the component). Each must be
caught on every target:

|---|---|
| `kc_tbl[1]` (`"kernel"`) to `"other"` of the same section | "... not equal content" |
| `kc_tbl[1]` to the equal string + 1 (`"ernel"`) | "... not equal content" |
| `kc_tbl[1]` to `kc_plain` (`"kernel"` in `.rodata`, not mergeable) | "... (no mergeable piece) through -r, not equal content" |

4 of 4 are caught on each target. On AArch64 the test also asserts the

flagged that base ("kc.o+0x10 ... resolves to 0x400178 (kb.o
.rodata.str1.8+0x8)"), so the fixture reproduces the bug.

## Item 2: thin archive members

Measured (GNU ld 2.44, lld 19.1.7, mold 2.37.1), with `lib/libt2.a`
storing `../sub/m1.o`, with and without `--whole-archive`:

- GNU ld: `lib/../sub/m1.o`, bare, in the preamble and in the section
  lines.
- lld: `lib/libt2.a(../sub/m1.o)`.
- mold: `lib/libt2.a(lib/../sub/m1.o)`.

P-P1 now renames these, on both final links, to the `-r` map's
`(archive, member name)`. The rule needs no guess (§14.5, RL-6's
readings):

- The thin archives are the `-r` map's member archives whose bytes
  begin `!<thin>\n`.
- A member's own path is its stored path, taken from the archive's
  directory and normalized lexically.
- A bare path is renamed only when exactly one member has it as its
  own path and no word of that link's line is that path.

Exclusion (a) now compares those keys, not `objs`. `r-thin-whole-archive`'s
bfd unit is judged with no finding (it was "not judged (a)").
`p_p1_thin_aarch64` covers mortar's `-r` with GNU ld's and lld's
finals, whole and lazy: all 4 are judged and clean. With the renaming
switched off, the two GNU ld cells go back to "not judged (a)".

## Not verified

- mold's spelling of a thin member is implemented from the measurement
  above, but no test composes mold's finals (the test's tools have no
  mold).
- The ambiguity case (a file named both plainly and through the thin
  archive) has no test.
- Fixed-size `SHF_MERGE` entries (non-strings) and `sh_entsize` > 1
  strings: the code path exists, but no fixture has one.
- A partial field (ADRP/LO12 pairs to a string) stays judged by form,
  as before.
- Item 4 and a foreign `-r`'s `Merged` place still use RL-6's
  `VPlace::Content`, which compares bytes without checking that `V`'s
  place is mergeable.
- Before this package, every section-symbol field into a merged section
  compared two meaningless `S` values. They passed only where the
  garbage happened to map consistently. This is now judged by content.
