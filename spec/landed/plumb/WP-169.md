# WP-169: `.symtab` after WP-150, M7 on a local common, the false Y5 (verifier)

Follow-up to WP-150 (synth S-75, S-77, S-121; dyn.md D-110 item 1 and
D-114's bullet on linker-defined keys under `local:`; record
`spec/landed/dyn/WP-150.md`, "What else the verifier must read" items 4
to 6). The verifier holds mortar's `.symtab` to the forms WP-150 decided
and names each reference's form. The `xfail(mortar)` of
`dyn/version/symtab-local-common`, and the `xfail(bfd,aarch64)` and
`xfail(lld)` of `dyn/version/symtab-linker-defined-local`, are gone (the
bfd one XPASSed after WP-166's one-past-the-end rule; lld's is anomaly
A61).

## The rules as written

- **The keys the line makes local** (`Engine::made_local`, filled by
  stage 3 in `dynverify.rs`): a `Shared` output's `Sets::local` (a
  version script's `local:`, `--exclude-libs`; the derivation of
  `shared::compute`, reused as is), an executable's excluded keys
  (`Key::excluded`, D-110 item 1, `dynmodel.rs`, reused as is); none for
  a static output.
- **M7 on a local common** (`maprec.rs` `commons`). The map's `common`
  record is held to a global or weak `.symtab` symbol, or, exactly when
  the line makes the key local (the keys above, or an input's
  `HIDDEN`/`INTERNAL` global or weak entry of the name), to a defined
  `STB_LOCAL` symbol of the name (of two, the one at the record's
  address). Otherwise "... is not a global symbol of the output's
  .symtab" as before; a made-local key with no definition at all is
  "... is a key the line makes local, and no symbol of the output's
  .symtab defines it". Y3's common check (`symbols.rs`) takes the same
  local for mortar.
- **Y3, a key the line makes local** (`symbols.rs` `globals`), inputs'
  visibility below `HIDDEN`: mortar's entry is `STB_LOCAL` with its own
  visibility (S-77); a reference's is `STB_LOCAL` with its own, `DEFAULT`
  or `HIDDEN` visibility, or GNU ld's executable `GLOBAL HIDDEN`.
  Messages: "symbol 'K', which the line makes local, is not STB_LOCAL
  (synth S-77)", "... does not keep its own st_other visibility (synth
  S-77)" (mortar), "... has neither its own st_other visibility nor the
  references' DEFAULT or HIDDEN (WP-150 item 1)" (a reference).
  `shared::filter_view1` and `excluded_locals` drop the older Y3 rows for
  a reference only, never these.
- **P-D7, an exported key global in `.symtab`** (`dyncheck.rs`
  `fields`, every linker): an exported definition whose only `.symtab`
  definition at its value is `STB_LOCAL`: "'K' is exported, and .symtab
  defines it STB_LOCAL only".
- **P-D7, `.symver`** (`fields`): for mortar and GNU ld, an export whose
  versioned name (`foo@V1`/`foo@@V2` by `.gnu.version`) an input defines
  is matched to the `.symtab` global of that name at its value alone;
  none is "'foo@@V2' is exported, and .symtab has no entry of that name
  at its value (synth S-75: ...)". lld and mold are matched by either
  name; Y3's "not in .symtab" exemption for the plain base name is
  theirs alone.
- **Y5, D-114's linker-defined keys under `local:`** (`dynverify.rs`
  `script_local_linker_keys`, a `Shared` output with a script):
  `__start_SEC`/`__stop_SEC` (SEC a C identifier) and D-21 item 2's
  seven that no input defines and the script makes local are, in
  mortar's `.symtab`, `STB_LOCAL` `PROTECTED` / `DEFAULT`; GNU ld's and
  mold's `LOCAL DEFAULT` start/stop are accepted; lld's start/stop are
  not judged there (A61). That none is exported stays P-D19's.
- **Y5, `__bss_start` with no `.data`** (`symbols.rs`
  `linker_defined`): layout.md §13.1 defines it as the start of the
  first rank-8 `NOBITS` chunk, else `edata`, and L-64 makes `.pad.relro`
  rank 7, the end of the RELRO run. The window's upper bound is now the
  first writable non-TLS `NOBITS` section outside `PT_GNU_RELRO` (else
  the next allocated section). Measured before the fix on `vl-a64`
  (mortar and lld: "Y5 linker-defined symbol '__bss_start' has the
  wrong value"), clean after.
- **A61 (lld)**: P-D19 "... is in .dynsym and not in the export set (a
  version script or --exclude-libs makes it local)" on a `__start_`/
  `__stop_` name, on lld's output. Declared on
  `dyn/version/symtab-linker-defined-local` (`anomaly(lld): A61`), the
  lane's convention for a reference's real difference.

## Findings on existing outputs

- The checked-in mortar fixtures made before WP-150 (pre-S-77 mortar:
  version-local and excluded keys `GLOBAL`, `.symver` keys plain `foo`)
  now draw the new Y3/Y5/P-D7 findings, as they should:
  `tests/ldef/shloc-{a64,x64}` (WP-166, base 318dc90d),
  `tests/shared/verdef/libvd*` (WP-149) and `tests/shared/optail/libex-*`,
  `e-ex-*` (WP-161). They were regenerated by their `gen.sh` (ldef: the
  `shloc` mortar line alone) with the mortar of this base; the inputs
  came out byte-identical, the mutation tests on them pass.
- None on a current mortar output: the whole lane "398 tests, 3364
  results: 3211 PASS, 0 FAIL, 92 XFAIL, 0 XPASS, 61 SKIP"; the census
  "510 lines, 16 drivers, 510 pass, 0 fail".
- The static-identical rows of the two lane tests changed here moved by
  the removed `xfail` lines (output digests unchanged).

## What the specs leave unsaid

- Which visibility a reference's version-local key may have is
  measured, not specified (WP-150 item 1); the accepted set
  {own, DEFAULT, HIDDEN} is the union of the measured forms.
- GNU ld's `GLOBAL HIDDEN` for an excluded key: WP-150 measured it in
  `-no-pie` and static, WP-161 for a `-pie` data object without `-E`;
  it is accepted in any executable of GNU ld's.

## Not verified

- Static outputs: the line's local keys are stage 3's, and stage 3 does
  not run on a static output; a static `--exclude-libs` key's `.symtab`
  form is not judged by these rules.
- i386 (no fixture; the lane's i386 rows run).
- `.symver` with a hidden-only (`foo@V1` alone) definition is matched by
  the same rule but has no fixture.
