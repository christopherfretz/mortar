## 1. F1: P-D11 under `-z norelro`

Measured (x86-64 `g++` PIE of the census's `hello.cpp`, which copies
`_ZTISt13runtime_error` (read-only, libstdc++'s `.data.rel.ro`) and
`_ZSt4cout`; the `copy-relro` case of `tests/dyn.rs`, both machines,
`-no-pie`, a library's `int *const` (its `.data.rel.ro`, inside its
RELRO) and an `int`):

| linker | `-z relro`: read-only datum's copy | `-z norelro`: read-only datum's copy |
|---|---|---|
| GNU ld 2.44 | `.data.rel.ro`, inside RELRO | `.data.rel.ro`, writable `PT_LOAD`, no RELRO |
| lld 19/22 | `.bss.rel.ro`, inside RELRO | `.bss.rel.ro`, writable, no RELRO |
| mold 2.37.1 | `.copyrel.rel.ro`, inside RELRO | `.copyrel` (the writable one), no RELRO |
| mortar | `.bss.rel.ro`, inside RELRO | `.bss.rel.ro`, writable, no RELRO (D-42) |

Before this package all three references' `-z norelro` outputs carried
the same P-D11 finding as mortar's census line ("outside RELRO; its
definition is read-only"): a verifier defect, not a linker one. Without
a `PT_GNU_RELRO` nothing is read-only after relocation, and every
reference writes a copy the program can write through; the rule cannot
ask for more.

Rule (`plumb.md` P-D11): the allocation is in a writable `PT_LOAD` with
the definition's size and alignment, no overlap, aliases exported; RELRO
membership is judged only where the output has a `PT_GNU_RELRO` (a
missing segment the line asks for stays P-D4's); `Format::Mortar` is held
to D-42's output section (`.bss.rel.ro` for a read-only definition,
`.bss` otherwise) with or without RELRO.

Check: `crates/mortar_plumb/src/dyncheck.rs` `pd11_13` (the RELRO guard
at the `in_relro` comparison, the `Format::Mortar` section rule after the
writable-place check). `KNOWN_FINDINGS` is empty (`xtask/src/census.rs`).

Mutation rows (new classes `copy-relro`, `copy-section` in
`dynmutate.rs` `copy_place`; caught / applied, `--per-class 40`):

| class | mortar x86-64 C++ PIE (census `default`) | mortar `-no-pie` | mortar `x-norelro` | GNU ld / lld / mold `-z relro` | same, `-z norelro` |
|---|---|---|---|---|---|
| `copy-size` | 2/2 | 2/2 | 2/2 | 2/2 each | 2/2 each |
| `copy-relro` | 2/2 | 2/2 | n/a (no RELRO) | 2/2 each | n/a |
| `copy-section` | 2/2 | 2/2 | 2/2 | 0/2 each (equivalent: no reference's name is read) | 0/2 each (same) |

Dropped checks: the `Format::Mortar` section rule removed, `copy-section`
on mortar's three outputs is 0/6 (nothing else reads the name); the RELRO
membership comparison removed, `copy-relro` on the references is 4/6
(lld's and mold's "writable copy taken into RELRO" survive; GNU ld's is
also caught by P-D4) and stays 4/4 on mortar's (P-D4 and D-61 overlap).

Census: `cargo xtask census --filter x-norelro --filter c++.no-pie
--filter c++.default`: 29 lines, 29 pass, both architectures (x86-64 by
qemu); `gcc/x86_64/c++.x-norelro` passes with no finding. Test
`tests/dyn.rs s12_p_d11_copies_with_and_without_relro` (12 reference
outputs clean).

## 2. F2: a static-pie with exports

Measured (`hello.c` defining `exe_value`, `-static-pie -Wl,-E`, both
machines; global `.dynsym` entries / run):

| linker | AArch64 | x86-64 |
|---|---|---|
| GNU ld | 439, runs | 457, SIGSEGV at start-up |
| lld 22 | 432, runs | 454, runs |
| mold | 432, runs | 454, runs |

GNU ld's x86-64 fault: five `R_X86_64_TPOFF64` records against exported
TLS variables (`__libc_tsd_*`, `__libc_dlerror_result`), which glibc's
`_dl_relocate_static_pie` applies before the thread pointer exists. With
`-E` GNU ld also writes `RELATIVE` records on words holding the exported
absolute `_nl_current_*_used` (value 2): GOT slots on both machines and,
on AArch64, input words (`setlocale.o`'s `.data.rel.ro`). Recorded as
**A34** (`plumb.md` §10.2, `anomaly.rs`); P-D14's TLS-record rule and
P-D9 find them, so the verifier now explains WP-056's F4.

Rule (`plumb.md` §12.4, P-D14 `.dynsym`): a static-pie with `-E` or
`--export-dynamic-symbol` is inside stage 3. `Format::Mortar`: the null
entry only, whatever the line says (D-1 as WP-056's F2 proposes). A
reference: each defined, non-section export is the program's definition
(`.symtab`'s global value; a name `.symtab` defines; not hidden or
internal); the records stay P-D14's. W13's exported-IFUNC rule
(`dynverify.rs` `exported_ifuncs`) is not applied in a static-pie:
nothing binds an export (it fired on every reference's exported libc
IFUNC, e.g. `memcpy`, because no input reference made those resolvers
"chosen").

Checks: `crates/mortar_plumb/src/line.rs` (the outside line removed;
`Line.export_symbols`; `--export-dynamic-symbol <v>` and
`--export-dynamic-symbol-list <v>` read as options with a value: before,
the separate-word form's value was taken as an input file, a P-D2
problem), `spie.rs` `check` (the `exports` parameter and the export
block), `dyncheck.rs` `check` (passes `export_dynamic || export_symbols`),
`dynverify.rs` (W13 skipped for `StaticPie`), `anomaly.rs` (A34,
`exports`).

Mutation rows (`dynsym-value`, `dynsym-visibility`, existing classes, on
the six `-E` outputs above; caught / applied, `--per-class 40`): 40/40
each on every output (480/480). Dropped checks: the value rule removed,
`dynsym-value` is 0/40 on lld's two outputs and 2/40 on GNU ld AArch64;
the visibility rule removed, `dynsym-visibility` is 0/40 on all three.

Tests: `tests/spie.rs` cases `export` (`-Wl,--export-dynamic`) and
`export-sym` (`-Wl,--export-dynamic-symbol=main`), lazy, three
references, both machines, in `s12_4_static_pie_references_verify_clean`
(GNU ld: A34 required on `export`; its x86-64 output must fault when run
on an x86-64 host), and `s12_4_static_pie_export_mutants_are_caught`;
`line.rs` `s12_4_export_dynamic_symbol_is_an_option_with_a_value`.

The linker change (accept `--export-dynamic` in a static-pie with no
effect) is not made here; with it, mortar's output is judged by the
stricter null-entry rule. `tests/link/dyn/spie/export-dynamic-refused.test`
and the census's `OUT_OF_M2` entry for it are the linker package's.

(At the interim merge the supervisor made that change: the refusal in

## 9. Item 6: the sweep on mortar's outputs

§12.3's sections flipped by bit 0 and bit 7; surviving bytes):

| case | AArch64 bytes | survive | x86-64 bytes | survive |
|---|---|---|---|---|
| C PIE, lazy (`pie.lazy`) | 1549 | 0 | 1351 | 0 |
| C PIE, `-z now` (`pie.now`) | 1565 | 0 | 1367 | 0 |
| C `-no-pie` (`nopie`) | 1300 | 0 | 940 | 0 |
| C++ PIE (`cxx`) | 2444 | 0 | 2242 | 0 |
| C static-pie, 256-byte window (`spie`) | 2117 | 0 | 2157 | 0 |

No survivor and no panic on either target: nothing to explain or close.
The static-pie's whole sweep takes 537 s on AArch64 (9552 bytes of
`RELATIVE` addends alone); the lane sweeps its sections 256 bytes at
each end (28.6 s, 0 survivors), the rest being the same fields repeated.

The lane: `cargo xtask sweep [--quick]` (`xtask/src/sweep.rs`), a gate
step after `census` (`spec/harness.md` "ci"). It fails on a finding on
the unmutated output, a panic, or any survivor. Cost (this host, shared, 1-minute load 6-13; the sweep runs inside
`xtask`, a debug build, on 4 threads): the full lane 463.5 s for both
targets (per case: about 13-16 s each C dynamic case, 93-95 s each C++,
96-97 s each windowed static-pie); `--quick` (host, `pie.lazy` and
`nopie`) about 27 s plus the compiles. With `spie` the quick subset took
129.8 s, over the brief's minute, so `spie`, `pie.now` and `cxx` are the
full gate's only. A release `xtask plumb --sweep` on 2 threads is 2-4x
faster (7.2 s `pie.lazy`, 30.2 s `cxx`, 28.6 s windowed `spie`, all
AArch64); an `opt-level` for `mortar_plumb` in the dev profile would
bring the lane near that, but `Cargo.toml` is not this package's.
