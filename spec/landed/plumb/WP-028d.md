## Item 0 — erratum 843419 (WP-032e's mislinks)

Reproduced on main 4afb6df's linker (built separately) with eafc050's
input and three variants (window in the previous section, ADR and patch
paths, a mergeable target), and on the `synthetic-sections` workload's
objects linked static. **Main's verifier was not silent: it reports R1 on
every mislinked output** (the ADRP an ADR replaced: expected
`0xb0000080`, found `0x10ff8020`; the patch's load: expected
`0xf9401800`, found `0xf9400000`). The bench harness never runs the
verifier, which is how the mislink went unreported. Post-fix (eafc050)
outputs are clean; GNU ld's and lld's outputs of the same inputs are
clean (they choose ADR or patch differently; no difference in meaning).

Added, from `spec/a64.md` §11.3: §5.10's by-site rules C1–C6 (an unfixed
site; both fixes or an ADR outside a site; a redirect at no site; an
unproved candidate; a code chunk at page offset 0xFFC–0x008; a fix
without the option), the window `[P+0xFF8, P+0x100C)` which may start in
the previous section, S12's acceptance of an ADR over an ADRP without a
record, the option from `xtask plumb --fix-cortex-a53-843419` or the
response file (else inferred from the fixes), mutation class
`erratum-fix`, and tests `s9_2o_*`. One new anomaly: A18, GNU ld 2.44
leaves a 4-word site unfixed in `synthetic-sections` (after two of its
own stubs moved code onto the page end). A4 (mold leaves sites) is now
judged when the option is stated.

## Item 4 — cost

`xtask plumb` (release) on mortar's static AArch64 protoc (11.7 MB,
212 384 records): the verifier is single-threaded, so the link's thread
count changes nothing (the outputs at 1 and 8 threads are identical).

| | before | after |
|---|---|---|
| wall | 0.38–0.47 s | 0.27–0.33 s |
| RSS | 176 MiB | 176 MiB |

The win: `locate` scanned an archive's member list for every member it
looked up (27% of the time); it now indexes each archive once. Left:
SipHash over string keys (~11%: a crate-local FNV hasher), `symbols`
(15%), `check_eh_frame` (8%). For reference, mortar links protoc in
0.37 s (1 thread) and 0.22 s (8).

## Item 5 — i386 sizing

`spec/x86.md` (accepted on main) asks plumb for R-8 (the table), X86-42
(reference forms) and R-12 (a shared ModRM module). What exists: ELF32
images, REL records and ELF32 IRELATIVE rows are read; properties are
shared with x86-64. What is needed: `src/x86.rs` (x86.md §6.1's 22 M1
rows, A read through the field, mod 2^32), an `x86rec.rs` record path
(GOT32/GOT32X with X86-13's operand readings and the GOT base, G1–G5,
I1–I5, D1–D3, L1–L2, T1–T2 with X86-31 pairing), the IPLT forms of
X86-48/X86-49, `.got.plt`'s `_GLOBAL_OFFSET_TABLE_`, and a corpus of
GCC/Clang `-m32` links by the three references. Size: about WP-028c's
(x64.rs + x64rec.rs ~1 000 lines, tests ~700), one work package; the
ModRM split (R-12) first, as a small refactor of `x64rec.rs`.
