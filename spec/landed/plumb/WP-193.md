# WP-193: P-D6's order model for a mention again inside a script, and why two identical lists drew two verdicts

This is a verifier package that follows WP-172 (`spec/dyn.md` D-19a; record
`spec/landed/dyn/WP-172.md`). It was written from the specs and from the
outputs; no linker crate was read.

## 1. The two verdicts (found before any change)

On `g-anx-obj`, `nested-group` and `nested-group-asn`, GNU ld and mortar
write `na nb nx nc c`. The verifier passed mortar's output and reported
P-D6 on GNU ld's, "D-19a gives `na nx nb nc c`". The lane's kept runs
show why:

- **The object's spelling in the map.** The object `use_x.o` is found by
  the script `g_anx_obj.so` (or by the nested `g_sx_use.so`).
  - GNU ld's map names it `./use_x.o` (`LOAD ./use_x.o`, and
    `libnx.so ./use_x.o (f_nx)` in the archive-member table). GNU ld
    names a file a script found by the script's directory.
  - mortar's map names it `use_x.o` (`file 4 use_x.o`).
  - The verifier's line model (`line.rs`) holds the script's entry as
    `use_x.o`, the word as written, which the current directory has.
  - `Line::position_of` matched an input to a line item by exact path,
    and `dynmodel::keys_of` counted an input it could not place at
    position 0 with no group (`pos.unwrap_or(0)`). The model therefore
    put GNU ld's `./use_x.o` before every mention. Its strong reference
    to `f_nx` then qualified libnx.so's first, as-needed mention, which
    gave `na nx nb nc c`.
  - For mortar's map the match succeeded: `use_x.o` sat in the script's
    `GROUP`, the group of the mention again, and the list came out as
    D-19a's.

  The model was wrong on GNU ld's correct output and right on mortar's,
  because of a difference of spelling between the two maps. This was a
  different path through the model, not two object sets, and it hid no
  finding on mortar: mortar's list is D-19a's.
- **A record mortar writes was believed.** For a mortar map, the verifier
  took the line from the map's `arg` records (mortar's own account of its
  line) even when the caller passed the line (`dynverify::line_words`).
  The mentions' states, groups and positions on a mortar output were
  therefore mortar's word, while for a reference they came from the
  caller. In the lane those records are the caller's words verbatim
  (`diff` of `arg` records and `.linktest-ld-status-20.line`: the same),
  so no verdict depended on them, but the field was believed. A mortar
  whose `arg` records disagreed with its real line would have been
  judged by its own story.

Both are closed:

- The line is the caller's for every format. A mortar map's `arg`
  records are used only when the caller gives no line.
- An input is placed on the line by file identity up to spelling
  (`line::same_file`: `.` components and repeated `/` removed, and
  `dir/..` collapsed lexically). The `dir/..` collapse is needed for
  mold, whose maps name the driver's
  `/usr/lib/gcc/T/14/../../../T/crti.o` as `/usr/lib/T/crti.o`. Without
  it, the first dynamic-lane run drew 360 mold P-D2s.
- An input the map names that no line item is becomes P-D2 ("an input of
  the map that no line item is (D-19a needs its position)"), and stage 3
  stops. It is never again placed before every mention.

## 2. The rule

The rule is `spec/plumb.md` §12.1a (new), written before the code. It
covers:

- the line's source;
- the mentions, with scripts expanded inline: `INPUT`, `GROUP`,
  `AS_NEEDED`, nested scripts, `-l` in a script and, new, `INCLUDE`;
- a mention's state: its script entry's, `AS_NEEDED` forcing it on,
  push/pop-state;
- a mention's group, through nested scripts; an `INPUT` entry is in its
  script entry's group, so beside a `GROUP` it is in none;
- a mention again, which takes its script entry's state and group;
- each input's position and group by file identity, with an unplaced
  input being P-D2;
- the keeping mention: a reason before the mention, or in its group. The
  fallback is the first mention.

GNU ld's and mortar's outputs are held to it. lld's and mold's outputs
are held to first mention (W9).

`spec/plumb.md` §12.1's line bullet and `Ctx::line`'s doc say the same.
The line model (`line.rs`) already gave every entry its script entry's
state and group; what was wrong was where inputs were placed and whose
line it was.

## 4. The three cells GNU ld refuses (item 4)

The model gives, for mortar's output:

| cell | list | why |
|---|---|---|
| `before_asn_ref_late` | `na nx nb nc c` | the mention again in `s_anx.so` is `AS_NEEDED`, and `use_x.o` follows both mentions in no group |
| `nested_group_none` | `na nx nb nc c` | `n_sx.so`'s nested entry has the state of `--as-needed n_sx.so` and no group, and `use_x.o` is after it |
| `input_then_group` | `na nx nb nc c` | the `INPUT(libnx.so)` entry is in no group (its script was named outside every group), and `use_x.o` in the script's `GROUP` comes after it |

In each case no mention qualifies, so the fallback is the first
mention. These lists are derived by the model from the line, the
scripts and the symbol tables, and compared with the image's
`DT_NEEDED`. They are not copied from mortar. The lane's
`needed-order-script.test` runs these lines on mortar under L3 with no
finding, and the `input-then-group` fixture is clean in the unit tests.
mortar's list on each is lld's and mold's.

## 5. The test, and two new cells (item 6)

`tests/link/dyn/shlib/needed-order-script-group.test.pending` has been
renamed to `.test`. Its first line (`# PENDING …`) is replaced by one
comment line. Two cells were added at its end:

- `include-again`: a mention again reached through `INCLUDE`
  (`i_sx.so`: `INCLUDE s_x.lds`, with `INPUT(libnx.so)`), named plain
  after libnb.so. GNU ld and mortar give `na nb nx nc c`, and lld gives
  `na nx nb nc c` (measured). mold 2.37.1 refuses: `unknown linker
  script token` at `INCLUDE` in an input script. The verifier's line
  model reads `INCLUDE` now (script.md §2.8). Before, it was "script
  word not modelled", a P-D2.
- `libg-anx-obj.so`: `g_anx_obj` in a `-shared` output. GNU ld gives
  `na nb nx nc c`; lld and mold give `na nx nb nc c` (measured).

`spec/dyn.md` D-19a's Tests list and `spec/landed/dyn/WP-172.md` §4 now
name the test as written. Static-identical: 10 rows added for the
test (5 links on each of aarch64 and x86_64), recorded by the final
gate's `--update`.

## 6. Not verified

- x86-64 fixtures: the unit tests are AArch64 only, while the lane runs
  both architectures.
- An `INCLUDE` inside a `GROUP` (GNU ld rejects it) and `INCLUDE` found
  through `SEARCH_DIR`.
- The lexical `..` collapse through a symbolic link: no line or map of
  the corpus names a file that way.
- The other formats' maps for the same spelling question (lld and mold
  maps were not seen to prefix `./`).
- Whether other stages believe a mortar map's `arg` records:
  `opts::of(map)` still reads them for options (§3.2a). That was not
  changed here.
