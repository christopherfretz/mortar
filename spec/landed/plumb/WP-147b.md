# WP-147b: an export's definition is its kept COMDAT copy (verifier)

A false finding of P-D19's "placeless export" (WP-147, WP-149) on the
hosted x86-64 lane: `dyn/shared/tls-shared-cxx.test` failed for lld's and
mold's AArch64 libraries (`'_ZNSt9bad_allocC1Ev' is defined in .dynsym
(at 0x4efe4), but its definition has no place`; mold:
`_ZNKSt9type_info4nameEv`). The libraries are correct.

## Cause

Debian's cross `libstdc++.a` for AArch64 (`libstdc++-14-dev-arm64-cross`
14.2.0-19cross1) is an unoptimised build: an inline function has a weak
COMDAT copy in several members. In the lld link, `functexcept.o` and
`new_op.o` both carry the group `_ZNSt9bad_allocC5Ev`; lld keeps
`new_op.o`'s and writes no line for `functexcept.o`'s, which the map
names first (for its `.rodata`). Under GNU ld's and mortar's maps a
discarded copy is `Discarded` and never a definition; under lld's and
mold's it is `Absent`, so it stayed among the key's definitions, and
`shared::compute` took the first one in object order (first strong, else
first not common) as THE definition without asking whether it had a
place: the discarded copy, placeless, so the kept export was reported.
For mold the same with `_ZNKSt9type_info4nameEv` (`dyncast.o` first,
`class_type_info.o` kept).

## Fix

`crates/mortar_plumb/src/shared.rs` (`compute`): the key's definition is
chosen among the definitions with a place (first strong, else first not
common); only when NO definition has a place is the key placeless
(§4.4 step 0's predicate asked of every definition, as step 0 and Y3
already did in `Engine::placeless_def`). `spec/plumb.md` P-D19 and §4.4
step 0 amended.

Not weakened: a key whose every copy has no place is still a finding.

## Tests

- `tests/link/dyn/shared/comdat-copies-export.test`: three archive members
  compiled `-O0 -fPIC` with copies of an inline function and an inline
  constructor (C1/C2 in one group), extracted k3, k2, k1; GNU ld and lld
  keep k3's copy (the archive's last member), mold and mortar k1's; k2.o
  alone has `.rodata`, so every map names it first. Before the fix:
  FAIL for lld and mold on aarch64 and x86_64 (`P-D19 '_Z4pickv' is
  defined in .dynsym ..., but its definition has no place ... (and 2
  more)`); after: PASS for all four linkers on both.
- `crates/mortar_plumb/tests/pexport.rs`,
  `wp147b_comdat_export_is_judged_by_its_kept_copy`: `cka.s` (kept) and
  `ckb.s` (with `.rodata`), `-shared` with GNU ld, lld and mold, AArch64
  and x86-64: clean; with the kept copy's lines removed from lld's and
  mold's maps (every copy absent) each of the three exports is the
  finding "its definition has no place". The WP-147 tests still pass.

## What else was checked

- §4.4 step 0 and Y3 (`Engine::placeless_def`) already require EVERY
  definition to have no place before taking "the first strong one":
  not affected.
- Y4 (`symbols.rs`) counts placed locals first and reports only when no
  local of the name is placed: not affected.
- M10's line roots (`fate.rs`, `line_roots`) take "the first strong
  definition in object order, else the first" too. M10 runs under
  mortar's map only, whose files are in `FileId` order, so the first
  COMDAT copy is the keeper (§6.1) and no true finding was hidden; it
  now skips a copy of a group not kept (`comdat_dropped`) all the same,
  so the choice cannot fall on a dropped copy.
- P-1's `gone` keys (every definition `Discarded`) are skipped when any
  live definition exists: unchanged.
