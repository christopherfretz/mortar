# WP-163: a root under `--as-needed` (verifier)

Follow-up to WP-152 (resolve.md §4.2, dyn.md D-11 item 2, D-21 item 1;
resolve.md §5.5, layout.md L-103). Three findings on correct outputs
are closed. The three `dyn/shared/root-as-needed*` tests carry no
`xfail` line. Every linker with steps is judged, and the two
references' differences are named.

## The rules as written

- **Roots, one derivation.** `Line::root_names` gives the line's roots
  once each, in this order:
  - `-e` (else the script's `ENTRY`);
  - `-u`;
  - `--require-defined`;
  - the implicit scripts' `EXTERN`.

  A quoted script name (`EXTERN("k")`) is the name inside the quotes.
  `Line::entry_name` is the entry symbol's name, unquoted the same way.
  The input set's rule (§3.8, `inset.rs`, WP-156) reads the same `Line`
  fields with their positions. It is not rewritten onto
  `root_names`: WP-156 changes `inset.rs`'s script reading beside this
  package.
- **P-D6 (D-11 item 2).** The model marks a root key `root`. A root is
  no longer a strong reference from file 0 (before, `-u` and `-e` were
  one). The needed set comes from the inputs' references alone.
  - A library in `DT_NEEDED` that only a root names a definition of is
    P-D6 "... which D-11 does not make needed (only a root names a
    definition of it: D-11 item 2)".
- **P-D7 (D-21 item 1).** After the needed set's fixed point, a root
  is imported iff all of these hold:
  - the program does not define it;
  - no input references it;
  - a library of the final needed set has a visible definition of it,
    unversioned or of its default version (what a reference without a
    version binds).

  Such a root becomes a strong reference (`root_import`). Otherwise it
  is written nowhere. The findings:
  - A root a needed library defines that is missing from `.dynsym` is
    P-D7 "... is a root defined by L, a needed library, and is not in
    .dynsym (D-21 item 1: a root is imported)".
  - A root in `.dynsym` that no needed library defines is P-D7 "... is
    imported and no library of the needed set defines it (a root: D-21
    item 1, D-11 item 2)".
  - The old exemption (`line.undefined` counted as referenced) is gone.
- **P-D4 (L-103, resolve.md §5.5).** The entry symbol may be undefined
  in the output: neither a live relocatable object nor file 0 defines
  it. In that case:
  - `e_entry` 0 is accepted from every linker;
  - in mortar's output any other value is P-D4 "... is defined by no
    live object and the entry point is X: layout L-103 writes 0";
  - a reference's own fallback (GNU ld: the start of `.text`) is held
    to an executable `PT_LOAD`, as before.

  When the symbol is defined, the existing rule stands, so a 0 is P-D4.
  The static-pie call (P-D14) is unchanged.
- **Anomalies.**
  - A47 (lld, mold): no `.dynsym` entry for a root that only a needed
    library defines.
  - A48 (mold): an `--as-needed` library is needed because of a root
    alone.
  - Both are in spec/plumb.md §10.2 and `anomaly.rs`. A47 and A48 were
    the next free ids on every branch checked (`int/batch-9`, `wp/152`,
    `wp/155`, `wp/156`).

## What the specs leave unsaid

- D-21 item 1 says "a root names". It does not say whether `-e` and
  `--require-defined` import a needed library's definition the way `-u`
  and `EXTERN` do. The verifier treats every root of §4.2's table
  alike.
- §5.5 does not say whether a reference's fallback `e_entry` must be 0
  or may be the start of `.text`. Only mortar's 0 is binding (L-103).
- An `-e` given as an address (`-e 0x1000`) is no key. The verifier
  takes it as an undefined entry symbol, so mortar's non-zero `e_entry`
  would be P-D4. No test has that line.
- A root bound only by a library's non-default version (`k@V1`, no
  `k@@V`) is not imported, because an unversioned reference cannot
  bind it. Untested.
