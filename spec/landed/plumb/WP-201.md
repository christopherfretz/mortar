# WP-201: a record's field judged by its owner; A104, A105, A106; the options from the caller's line

Verifier package after WP-177 (`spec/resolve.md` §6.3, the record that
owns a field), WP-178 (§5.7a, A103), WP-193 (§12.1a) and WP-194
(`.llvm.call-graph-profile`). Written from the specs and the outputs; no
linker crate was read. Base `953f3bee` (int/batch-12).

## 1. A field of `.eh_frame` or `.gcc_except_table`: its owner (§5.7b, new)

The rule is `spec/plumb.md` §5.7b; §5.7 points at it, §6.4 states the
CIE half. The verifier names the owner itself (`src/ehowner.rs`, a child
of `reloc`):

- LSDA starts: the LSDA pointer targets of every FDE of every input
  `.eh_frame` the link reads (alloc, not `SHF_EXCLUDE`, not a member of
  a COMDAT copy the verifier's keeper drops), over every input file
  (a global LSDA label in another file's table counts there). Own parse
  (`eh::parse_as`, 32- and 64-bit lengths), own liveness (§6.4: dropped
  when the initial location resolves into a section not in the output,
  or the range is 0; unknown when it cannot be resolved), own keeper.
- A start is live if any FDE at it is live, else unknown if any is, else
  dead. The owner of offset `r` is the greatest start not above `r` in
  that table section.
- Dead owner: no finding on another linker's output (the record is
  counted with the records of sections not in the output); mortar's
  must hold 0 (verified `tombstone`), else a Field finding.
- Live owner: R5, its text naming the form (A105, A106, §2), §5.7a's
  trial first for a weak demoted mention.
- No owner named (no start at or before; an unreadable `.eh_frame` or
  relocation section; an LSDA pointer of another type or whose target
  cannot be placed, which may name any table; an FDE of unknown life):
  R5 with the reason. Never taken as dead.
- A written CIE's personality field that refers to a section not in the
  output: R5 at the CIE's field (it was `not checked: eh-frame` and
  suppressed E4 before: a hole, found while doing this item).
- An input `.eh_frame` that is a member of a dropped COMDAT copy is not
  read by the link: its records are absent, not E2 (found by the `drop`
  fixture: GNU ld's output had an E2 for an FDE the link never read).

lld's unused-CIE link (`comdat-eh-dead.test`'s `kg.o`, the weak form of
`comdat-eh-unused-cie.test`): the finding does NOT stay. lld writes 0 in
the LSDA's field, whose owner (F's FDE, F collected) is dead: no
finding; the CIE is used by no live FDE: its personality is counted
absent. Its comment now says so.

## 2. The anomalies (ids taken: A104, A105, A106; A107-A109 left unused)

- **A105 (GNU ld)**: a field of a written record that refers to a
  dropped copy holds 0 (R5 ending "… written 0: resolve.md §6.3").
- **A106 (mold)**: the field holds `A` or `A - P` (its target taken at
  address 0; R5 ending "… written as if its target were at address 0:

  owner), only that value; another value is plain R5

- **A104 (mold, AArch64)**: Y4 on a mapping symbol written `SHN_ABS`,

  mapping symbol of an input section dropped as SHF_EXCLUDE, written

  (its line 19) is removed and `#@ anomaly(mold,aarch64): A104` added;
  `call-graph-profile-pgo.test` and `-dynamic.test` had no such skip.

## 3. `comdat-mismatch-weak-prelink`: A103, by two corrections of §5.7a

The referring mentions (`x2.o`'s and the libstdc++.a members'
`DW.ref.__gxx_personality_v0`, `DW.ref._ZTISt9exception`) are WEAK
HIDDEN, non-local: demoted mentions. The LOCAL symbols are the
component's kept definitions (`objcopy --localize-hidden`), which bind no
mention. So §5.7a applies as written; no local demoted mention exists in
the test, and no question to `spec/resolve.md` was needed. What the trial
did wrong, now corrected (§5.7a):

- **The keeper's order for archive members.** A member took the rank of
  the object before it in `FileId` order; lld's map lists a file where
  its first section goes, so `eh_alloc.o` came before `comp.lh.o` and
  its copy of `DW.ref.__gxx_personality_v0` was taken as the kept one.
  A member is now ranked at the word naming its archive (its path,
  `-l<name>`, `-l:<file>`), in `reloc::set_keeper_line` and in stage
  3's model (`dynmodel.rs`, `line.position_of`).
- **§4.4 step 3 in the trial.** "The one output symbol of the name, of
  any binding" found the component's local `DW.ref._ZTISt9exception`
  in GNU ld's `.symtab` and judged the field against it. In the trial
  no definition of the key has a place: the step is not taken.
- **The personality trial.** A written CIE's personality field is judged
  by the same trial: the undefined weak form is the field holding `A`
  (the place) or `S = 0` in every output CIE that carries it.

Verdicts (`#@ anomaly(bfd,lld): A103`; `run` per target):

| target | GNU ld | lld | mold | mortar |
|---|---|---|---|---|
| AArch64 | A103 (0: place); runs, signal 6 | A103; signal 6 | refuses | refuses |
| x86-64 | A103 (`S = 0`); signal 11 | A103; signal 11 | refuses | refuses |

The test's header said "GNU ld and lld write 0 into both … signal 6":
true on AArch64 only; on x86-64 both write `-P` and the throw faults
(signal 11, measured). The header and the `run` lines say so now.

## 5. The options from the caller's line (§3.2a, §12.1)

`opts::of(map, line)` reads the caller's line when one is given, for
every format, and a mortar map's `arg` records only when the caller
gives none. Every reader takes the line it is given: B1/`buildid::Style`,
P-G6 (`gdbnames`, `gdbindex`), S10, the layout check
(`structure::check_layout`), the erratum's option
(`Engine::caller_line`), stage 3 (`dynverify`, `dyncheck::pd4`). M9
judges the map's own records with or without a caller's line
(`opts::unread_findings`). Options `opts` reads: `--fix-cortex-a53-843419`,
`--gdb-index`/`--no-gdb-index`, `-s`/`--strip-all`, `-S`/`--strip-debug`,
`--keep-mason-meta`, `--odr-table`, `--odr=`/`--no-odr-check`,
`--build-id[=]`/`--no-build-id`, `-z execstack`/`noexecstack`,
`--gc-sections`, `-T`, `-e`, `-shared`, `-E`/`--export-dynamic`, the
named roots (`-u`, `--require-defined`), `-z max-page-size`, `--wrap`,
`--defsym` (`-z now`, `-z relro`, `-pie`, `--hash-style` are `line.rs`'s,
caller-first since WP-193). No option-mirror constant was missing.

## 8. Questions

1. `spec/resolve.md` §6.3's table, the row "any other alloc section
   (`.text`, …, `.gcc_except_table.foo`, …), case (a)": GCC's
   `-ffunction-sections` writes the LSDAs as `.gcc_except_table.<fn>`
   (libstdc++.a's `vterminate.o` has
   `.gcc_except_table._ZN9__gnu_cxx27__verbose_terminate_handlerEv`),
   which every linker puts in the output `.gcc_except_table`. The owner
   rule applies to the exact name only, so a dead-owner field of such a
   section is an error for mortar and R5 for the verifier, while the
   same field in `.gcc_except_table` is accepted. Should the owner rule
   cover `.gcc_except_table.*`? The verifier follows the cell as
   written.
2. `abs` (an LSDA pointer against an absolute symbol): the verifier
   names no owner in any table, so mortar's own correct output (the dead
   word 0) gets R5 "owner not known". Conservative by §5.7b; tell me if
   an absolute LSDA pointer should instead name no table.
