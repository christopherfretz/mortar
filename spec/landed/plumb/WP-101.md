# WP-101 — the byte sweep must not be answered by the build id

Branch `wp/101-sweep-build-id`. Only `crates/mortar_plumb/`,
`xtask/src/sweep.rs` (and the `--no-reseal` flag of `xtask/src/plumb.rs`),
`spec/plumb.md` (§9.5's reseal sentence, §12.3), `spec/harness.md`
("ci", the `sweep` paragraph), dated notes at the top of `WP-082.md` and
`WP-088.md`, and this record. The verifier was written from the specs,
the psABIs and the outputs the tools produce; no linker crate was read.

## 2. What changed in the sweep

- `buildid::reseal(file, map)`: one function for the mutation tool and
  the sweep. It rewrites the id only for a map in mortar's format (a
  stated or unstated tree hash; a `Given` or unknown style is left); a
  reference's id is never rewritten. The mutation tool used to reseal
  any map's id; it now calls this function, so a reference's id is left
  as its linker wrote it (B1 does not judge it).
- `sweep::run_with(.., Options { threads, window, sections, reseal })`:
  after each flip outside the id the id is resealed; each flip records
  the rules whose findings are new.
- B1's own case: `.note.gnu.build-id`'s descriptor is swept and never
  resealed (every flip must be caught, by B1), and one flip of
  `e_ident`'s last padding byte is judged unsealed: B1 must be among its
  rules (`Sweep::unsealed`; the lane fails otherwise). `--no-reseal`
  measures B1 alone.
- The table marks a surviving range `equivalent` when its field is in
  §12.3's table (`sweep::EQUIVALENT`), then prints `flips, caught,
  survived (E of fields named equivalent)` and, per rule, the flips it
  caught and those it alone caught. A PLT byte is `code` or `code no
  path executes` (`plt::executed`: the bytes the walks of §12.2 reach).
- The lane (`xtask/src/sweep.rs`) fails on a survivor whose field is not
  in the table, on a finding unmutated, on a panic, and when the
  unsealed flip is not B1's. Each case prints `bytes, flips: caught,
  equivalent, survive` and `caught by: <rule> <flips>...`.

## 4. The closures

Each rule was written in `plumb.md` §12.3 ("The field rules of WP-101")
before its code; ids and texts there. In the order of danger:

1. **P-D9, every format: a `RELATIVE` record's word.** A RELATIVE on a
   word no input's absolute use makes an address passed if its addend
   lay in any `PT_LOAD`; now its place must be an aligned `.got` word and
   its addend a value some input's GOT-indirect reference demands
   (`got_demands`, filled by the AArch64 and x86-64 engines), or an IPLT
   entry. A mutated offset or addend could make the loader write an
   arbitrary address into an arbitrary GOT word.
2. **E5, every format: `DW_EH_PE_indirect`.** The header's encodings
   ignored 0x80; an unwinder honours it (libgcc, LLVM libunwind), so a
   header unwinding through a wrong table passed.
3. **P-D10 (mortar): `.got[0]`, `DT_PLTGOT`, the reserved `.got.plt`
   words in every kind, no `JUMP_SLOT` outside `DT_JMPREL`, the AArch64
   entry's `add x16`.** x86-64's `GLOB_DAT` → `JUMP_SLOT` in `.rela.dyn`
   is honoured by glibc as a symbolic write, but D-41 gives mortar one
   table.
4. **P-D7 (mortar): imports' D-23 fields and the copy row.** Binding,
   type, size, `STO_AARCH64_VARIANT_PCS` (the loader reads it for a lazy
   binding of a vector-PCS callee); a copy's type and size.
5. **P-D8: version index 0.** A defined entry with index 0 is a finding
   in every format (gABI `VER_NDX_LOCAL`; musl skips such a definition);
   an import's 0 is read as unversioned and is mortar's finding.
6. **P-D9 (mortar): what a dynamic record's place holds.** `S + A` for
   RELATIVE, 0 for GLOB_DAT, the symbolic word and TPOFF; the IPLT word
   (AArch64 the resolver, x86-64 0); a `.got` word with no record holds
   a demanded value.
7. **P-D5 and P-D6 (mortar): Bloom words exactly D-26's bits,
   `symoffset`, the spare DT_NULLs 0.**

**Named equivalent** (§12.3's table, `sweep::EQUIVALENT`): one field,
`.plt` "code no path executes": AArch64's three header `nop`s after
`br x17` (12 bytes, 24 flips per case) and x86-64's four bytes of header
padding after `jmp *GOTPLT+16` (8 flips per case). No other field is
named.

## 6. L3 on the four linkers after the rules

`MORTAR_REQUIRE_TOOLS=1 cargo xtask linktest -j 4` (every test, the
three architectures, GNU ld, lld, mold and mortar).

First run, with the rules as first written: 96 FAIL.

| linker | what | cause | change |
|---|---|---|---|
| GNU ld, AArch64 (86 results) | P-D8 `'' is defined with version index 0` | GNU ld's local `STT_SECTION` entries in `.dynsym` have index 0, by right | P-D8 judges global and weak entries only |
| mold, x86-64 (4: `weak-class-table`, three large-model tests) | P-D9 `a RELATIVE record on a .got slot with addend <_GLOBAL_OFFSET_TABLE_>` | mold gives a `GOTPC64` reference to `_GLOBAL_OFFSET_TABLE_` a GOT slot of the symbol, which nothing loads; harmless | the rule accepts that value for a reference (narrowed, written in §12.3; not an anomaly: no program can observe it) |
| mortar, AArch64 and x86-64 (6: `ifunc-equality-pie`, `ifunc-from-dso`, `spie/ifunc`, `gd-trad-corpus`, `mixed-mode`) | P-D9 RELATIVE or unrecorded `.got` word with a value "no reference demands" | the verifier's gap, not mortar's: an IFUNC's slot holds its IPLT entry, which mortar puts in `.plt` (a64.md §10.4; the rule looked in `.iplt` only); a relaxed TLS reference's slot holds its TPREL word, which the engines did not record | IPLT entries are every PLT-like entry whose word carries an `IRELATIVE`; every TLS slot reference demands its TPREL word and module pair, relaxed or not |

Second run: 1772 PASS, 0 FAIL, 70 XFAIL, 34 SKIP, 0 ORACLE (122.5 s).
The XFAIL and SKIP counts are those of the first run's passing lines.

## 9. Follow-ups

| row | what |
|---|---|
| i386 | i386 dynamic and static-pie outputs are outside stage 3 (one P-D1 finding), so the sweep cannot measure them. |
| static outputs | `sweep::run_with` refuses a static output (`DynOut::read`), so the static sections (`.got`, `.iplt`, `.rela.plt`, `.eh_frame_hdr` of an `-static` link) are not swept. |
