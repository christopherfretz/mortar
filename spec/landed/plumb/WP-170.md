# WP-170 part 1 — the verifier follows `--wrap` (landed)

Branch `wp/170-plumb-wrap-defsym` from f20a6d6c. The rule is
`spec/plumb.md` §4.4a, written from `spec/resolve.md` §7.1 (E13, the
three refused shapes) and from the outputs of the four linkers; no linker
crate was read. Part 2 (`--defsym`) is a separate commit range.

## The derivation

One place: `crates/mortar_plumb/src/wrap.rs`, `Wrap::key(name)`. It is
built from the line's `--wrap` words (mortar's `arg` records, a
reference's line) and maps an undefined, unversioned mention `SYM` to
`__wrap_SYM` and `__real_SYM` to `SYM`, one step per mention. An empty
set is the identity: `key` returns the name and no rule does more work.
Readers:

- `reloc.rs` `Engine::resolve_any`: every lookup by name of a global
  (R1, R2, R4, R5, the slot and PLT checks), and so stage 3's views and
  S12 at the redirected sites (`lib.rs`, `dynverify.rs`, `equiv.rs` set
  it through `Engine::set_wrap`);
- `inset.rs` `redirect`: the edges of the input set (M11, M12);
- `dynmodel.rs`, `shared.rs`: the program's keys (P-D6, P-D7) and a
  shared object's export and import sets;
- `symbols.rs` `wrap_real`: Y3 on an entry `__real_SYM` that no input
  defines.

Roots are not redirected. `-e`, `-u`, `--require-defined`,
`--export-dynamic-symbol` and the gc roots still name `SYM`. An entry
point at `__wrap_ENTRY` is P-D4.

## Per linker

- **mortar**: everything is judged and nothing is named by an anomaly.
  The five lane tests and the 14 mortar fixtures of `tests/wrap.rs`
  are clean.
- **lld**: its forms are named by the tag at the end of the finding's
  text, on lld only:
  - A80: E13, a reference inside `SYM`'s own definer is bound to
    `__wrap_SYM`, either directly or through `__wrap_SYM`'s PLT entry;
  - A81: a weak `SYM` written `GLOBAL` when a strong `__real_SYM` binds
    to it;
  - A82: the entry point at `__wrap_ENTRY`;
  - A83: the member defining `SYM` is extracted even though only wrapped
    references name it;
  - A84: an input's `__real_SYM` definition is left out of `.symtab`.
- **mold**: its `.symtab` gives `__wrap_SYM` and `SYM` as `STB_LOCAL`.
  A9 already covers this, so no new id was needed.
- **GNU ld**: no `--wrap` form. The bfd anomalies in `wrap-kinds.test`
  (A30 and A31) are the existing ones.
- **Refused shapes** (resolve.md §7.1). These are judged on a
  reference's output only, because mortar refuses the line. Each is
  named in the coverage line `--wrap, not judged: ...`:
  - a versioned word;
  - `__real_X` beside `X`;
  - a word with two or more definitions, one of them in an `SHF_GROUP`
    section the output does not place (a dropped COMDAT copy). Every
    record against that name is reported as `wrap-shape`.

## Tests

- Lane: `resolve/wrap.test`, `wrap-kinds.test`, `wrap-refused.test` and
  `wrap-cxx.test`, plus `dyn/shared/wrap-shared.test`, have moved out of
  `.pending` and carry anomaly header lines. Their 83 static-identical
  rows are recorded.
- `tests/wrap.rs` with the fixtures in `tests/wrap/` (`gen.sh`):
  - cells `st`, `mem`, `real`, `gc` and `gck` on AArch64, x86-64 and
    i386, and `dm` (`-pie --wrap=malloc --wrap=_start`) on the two
    64-bit targets;
  - each cell is linked by mortar, lld, GNU ld and mold.
- The `clean` test covers 56 fixtures. `lld_forms_are_named`,
  `gc_over_retention_is_not_judged` and `no_wrap_no_coverage` are the
  other checks.
- Mutations: the test asserts that each one is caught on every mortar
  output of its cell; the references' outputs are mutated too.

  | mutation | caught by |
  |---|---|
  | a wrapped call retargeted to `f` | R1 `sym=f` |
  | a `__real_f` call retargeted to `__wrap_f` | R1 `sym=__real_f` |
  | `f`'s own call retargeted to `__wrap_f` | R1 `sym=f`, the E13 tag (named only on lld) |
  | `.strtab` `__wrap_f` renamed `__real_f` | Y3 `'__real_f'` |
  | the `f`-defining member added to the map | M12 |
  | the `__wrap_`-defining member removed | M11 |
  | a wrapped `malloc` call to the PLT | R1 `sym=malloc` |
  | the slot `p = malloc` named `malloc` (GLOB_DAT) | R1 / P-D9 |
  | the entry point at `__wrap__start` | P-D4 `'_start'` |

- `wrap::tests` unit tests: one step per mention, the identity, the
  refused shapes named.

## Cost (`cxx-large-g`, clang `-g`, static, AArch64, no `--wrap`)

- **Setup**:
  - one link with the existing release mortar, from the bench's inputs
    and WP-156's response file: 6.03 s, 1,958 MiB peak;
  - the verifier is `xtask plumb` (dev profile) built from fb4cf72e's
    `mortar_plumb` (before) and from this branch (after);
  - each run had `prlimit --as=8 GiB` and `nice -n 10`, and started at a
    load under 8, on a shared host.
- **Results**:

  | run | wall (s) | peak (KiB) |
  |---|---|---|
  | before | 19.63, 18.58, 12.36, 23.16 (mean 18.4) | 1,749,104 / 1,748,968 / 1,749,648 / 1,749,176 |
  | after | 23.41, 17.64, 13.99, 16.55 (mean 17.9) | 1,749,288 / 1,748,992 / 1,749,484 / 1,749,168 |

- **Reading**: the spread comes from the host's load, not the change.
  The report is the same before and after (162 lines each). It has no
  `--wrap` coverage line.
- **Why it does not pay**: with an empty set, `key` returns at once,
  `set_wrap` loops over nothing, and the E13 test needs a wrapped name.

## What the specs leave unsaid

- Liveness under `--gc-sections`. A section kept only by `SYM`'s
  (wrapped-away) references is over-retention, and §3.3 has no rule for
  it. `gc_over_retention_is_not_judged` records the current state.
- The static `-e` on an ET_EXEC. It is judged only in stage 3 (P-D4), so
  a static output's entry under `--wrap=ENTRY` is not judged.
- The dropped-COMDAT shape is detected as "an `SHF_GROUP` definition not
  placed, among two or more". A shape that resolve.md would call the same
  but that is not in a group is not detected.

## Not verified

- The A82 tag matches `__wrap_ENTRY` at `e_entry` without reading the
  line's wrap set.
- lld `gc-a64` with unwind tables gives a Y4 `$d` mapping-symbol finding
  inside `.eh_frame`, from a gc'd FDE. It is not wrap-related and was
  not examined. The fixtures avoid it with `-fno-unwind-tables`.
- Versioned words and the `__real_X` pair are tested on the lane's
  `wrap-refused.test` only, not mutated.
