## WP-156b — empty sections not in the output

**Cause.** The 208 were false. The clang link has no `--gc-sections`: each
finding is an empty COMDAT copy not kept (e.g. `libLLVMCodeGen.a
(MachineScheduler.cpp.o)` [336] `.text._ZN4llvm20PostGenericScheduler12
scheduleTreeEj`, size 0, AXG, its own group), whose `.debug_addr` word
mortar writes as 0, the I-47 tombstone. I-78 writes a `discard` record
only for a section with bytes, so the map is silent on an empty section
that is not in the output (and lld and mold omit it; GNU ld lists it under
"Discarded input sections"). WP-143's `empty_unrecorded` path made every
such section a placed empty target and required its address: R5. A
section `--gc-sections` collects (the coordinator's reproducer) falls in
the same path.

**Fix.** `fate::collect_empty`, run after locate (static, dynamic,
`--equiv`): an empty section without a map record is discarded when it is
a COMDAT copy not kept, or, under `--gc-sections`, not an I-6 root,
reached by nothing live and defining no line root. A discarded section's
references are judged as any other's: the I-47 tombstone of their debug
section (§5.8), GNU ld's kept-copy address allowed as before; another
value is R1. An empty section the map does not discard and that is live
keeps its address requirement (a live empty section is always listed: I-78
`place`, lld, mold, GNU ld). spec/plumb.md §3.3: the "discarded" row of
the place table and the new bullet "An empty section not in the output
(WP-156b)"; nothing else changed.

**Tests.** `tests/gc_empty.rs` (fixtures AArch64 and x86-64 from
`tests/gc_empty/gen.sh`, mortar, GNU ld, lld): clean on all; collected
word set to an address or all ones, `.debug_ranges` word set to 0, empty
COMDAT copy's word set to kept+0x100, all ones or 1: each the tombstone
R1; the live empty section's word set to 0: R1 the wrong value. Before the
fix the three tests failed with R5 on mortar's outputs. Lane:
`resolve/gc-empty-debug.test` (static, `--gc-sections`, and a COMDAT pair,
`.debug_addr`, `.debug_rnglists`, `.debug_ranges`, `.debug_loc`,
`.debug_info` words to a collected empty, a live empty and a collected
non-empty section): before, lld and mold ORACLE on the three targets (so
mortar was not run), GNU ld passed; after, 12 of 12 PASS.

**clang re-run.** The same link with this branch's release build, merged
with batch 9 (6.90 s, 1,978 MiB peak), the verifier as above, each run
started at a load under 8: 0 findings in both (the 208 R5 gone, nothing
new); `input set: files judged 7603 of 7603 (in the link 2845, required
2845)`. Run 1: 24.53 s (load 8 rising), run 2: 15.22 s; peak 1,708 MiB
(GNU time), profile 1,799 MiB, as before.

**How it escaped.** Gates that verify mortar outputs: the lane (every
link), `cargo xtask bench` (bench/verify.rs), census and realbuild. No
lane test had debug information referring to an empty section that is
not in the output. The bench's `-g` workloads that run by default are GCC
builds (`cxx-medium-g`, `cxx-medium-g-static`, `synthetic-comdat*`);
evidently none has an empty section, not in the output, that debug
information refers to (not measured here). `cxx-medium-gc-static` has
`--gc-sections` but no `-g`. The one clang `-g` link, `cxx-large-g`, is
`class = on-request`. WP-109 verified it with 0 findings before WP-143
added the empty target. **Proposal.** The lane test above is the smallest
gate that catches it on every target and linker. As a census line: a
`-g` twin of `cxx-medium-gc-static` built by clang (empty COMDAT copies
and collected sections, with debug information, in a medium link).

## The script reader's quoted words (batch 9)

`resolve/extern-root.test`'s `EXTERN("k_fn")` gave a false M12 on the
references: neither script reader (`line.rs`, the implicit scripts;
`inset.rs`, `-T`) knew quoted strings, so the root was `"k_fn"` with its
quotes. Both now use `line::tokens`: a string (`"` to `"`, no escapes,
script.md §1.6) is one word, never a keyword, a parenthesis or a `-l`;
a comma separates words (§2.1); `INPUT("a,b")` is one file, `"a.o"b.o`
two. Unit tests `line::tests::s1_6_quoted_words_of_an_implicit_script`,
`inset::tests::a_script_s_roots_and_assignments`.
