# WP-165: D-25 as WP-155 changed it (verifier)

Follow-up to WP-155 (dyn.md D-25, the supervisor's ruling (A); record
`spec/landed/dyn/WP-155.md` §6). The verifier holds an undefined weak
key reached by branches to its import, accepts exactly the ruled form of
the split key in `Exec`, and names the references' other forms. The
three `xfail` lines of `dyn/reloc/weak-branch-split.test` are gone.

## The rules as written

- **One derivation** (`crates/mortar_plumb/src/weakclass.rs`,
  `derive`). The candidate keys: undefined, referenced only weakly, no
  definition in a member of N ∪ U (`Model::bind_in` over the loader's
  order restricted to N ∪ U, as P-D7 binds imports). Each live
  relocation naming one (a placed, allocated input section; a section
  the map does not place or discards has none, so a branch
  `--gc-sections` collects is no use) gets D-25's class (`class`): GOT,
  absolute word in a writable place (the place's OUTPUT section's
  `SHF_WRITE`; a section whose pieces the map does not place falls back
  to the output section of its name, then its own flags), branch (x86
  `PC32` with the branch-opcode test, `branch_opcode`: `E8`/`E9` at −1
  or `0F 80..8F` at −2 inside the section), unfillable (every type the
  table does not list), TLS, no use. `Uses::verdict` gives D-25's
  "Then:" items: `WeakDyn`, `Split` (`Exec`: a branch and an unfillable
  use, no GOT use, no writable absolute word), `Weak0`, `Refused`; a
  kind other than `Exec`/`Pie` is never judged (`Shared` has no `Weak0`;
  static-pie imports nothing). Computed once in `dynverify::judge`,
  read by P-D7, P-D9 and view 3.
- **P-D7 (the import).** A `WeakDyn` or `Split` key missing from
  `.dynsym`: "'K' is an undefined weak key reached by ... and is not in
  .dynsym (D-25: WeakDyn)"; for the split key "... (D-25 ruling (A):
  WeakDyn for its branches)". New rule, beside P-D7's existing import
  loop (which still accepts a weak import's presence or absence for the
  keys outside the strict set).
- **P-D9 (the `JUMP_SLOT`).** Such a key with a branch, in `.dynsym` as
  an undefined entry, with no `JUMP_SLOT` record naming that entry:
  "'K', an undefined weak key reached by ... has no JUMP_SLOT record
  (D-25: every branch through a PLT entry)".
- **Judged per linker.** mortar's output: every `WeakDyn`/`Split` key
  (GOT-used keys included: D-25 makes them `WeakDyn` and mortar writes
  them so). A reference's: the keys whose uses besides their branches
  are unfillable or none (`Uses::branch_cell`: a branch alone, the
  split key), the cells WP-155 measured. GNU ld and lld are held as
  mortar; mold's missing entry is **A55**; GNU ld x86-64's missing entry
  for the split key is **A56** (§13.1's named difference). A key with a
  GOT use or a writable absolute word is not held in a reference's
  output (D-25 records mold's 0 everywhere; measured here: mold writes
  no `__gmon_start__` entry, AArch64 crti's GOT + `JUMP26`, in any
  driver link, where GNU ld and lld write `GLOB_DAT` + `JUMP_SLOT`).
- **The split key's unfillable uses** (P-D9 view 3). A view 3 finding
  at the site of an unfillable use of a `Split` key is dropped
  (`Classes::split_site`): the use holds `Weak0`'s value whatever is
  loaded, and view 1 judges that value (§4.4). A dynamic record whose
  `r_offset` lies in the field of such a use is P-D9 "a dynamic record
  (type T) at X on an unfillable use (R) of 'K' (D-25 ruling (A): an
  unfillable use of the split key keeps Weak0's value and has no
  record)".
- **View 3 and branches (a hole closed).** View 3 exempted a use whose
  field is too narrow for a library address (`Rule::Overflow`) unless
  another use reached the definition. A branch's field is always too
  narrow for the fresh address, so a branch of an imported weak key to
  0 (or anywhere but its PLT entry) passed every view when it was the
  key's only use: mortar's `bo-exec-a64` with `ccall`'s `b` patched to 0
  had no finding. A branch site (`Classes::branch_site`) is now never
  exempted: it reaches any definition through a PLT entry.
- **W12 unchanged.** A GOT use or a writable absolute word beside an
  unfillable use in `Exec` is `Weak0`: nothing new is asked, the
  references keep A25/W12's view 3 findings (`weak-mixed-exec`,
  `weak-data-init-exec` keep their `xfail` lines: their cells are not
  the split key), and mortar's `Weak0` output stays clean (`w12-*`).

Spec edits (`spec/plumb.md`): P-D7 (the derivation, the strict set,
the messages, what is not judged), §12.1 "The views" (a branch is never
a narrow field; the split key's unfillable uses), §12's mutation
paragraph, §10.2 A55 and A56.

## What the specs leave unsaid

- D-25's table does not list x86-64 `GOTPCREL64`, `GOTPLT64`,
  `CODE_4_GOTPCRELX` (and the other `CODE_*` forms): by its letter they
  are unfillable, and the derivation takes them so. No lane input has
  one against an undefined weak key.
- Whether a key D-25 makes `Weak0` may be in mortar's `.dynsym` (D-21
  lists the `WeakDyn` keys; it does not forbid more): not judged.
- A `Pie` with an unfillable use (D-25 refuses it) that mortar links:
  not judged by these rules (a missing refusal is the harness's
  `exit: fail` step, `weak-undef-pc-pie-refused`, `weak-branch-split`).
- A mortar output of a TLS-class weak key: D-25 refuses; not judged.

## i386

Stage 3 does not model i386 dynamic outputs (§12.1: one P-D1 "outside
stage 3: i386" line, nothing else judged), and mortar refuses every
dynamic i386 output (`docs/status/i386.md`, X86-3). The derivation has
the i386 column (`class`, unit-tested) but no rule reaches it: not
verified.
