## 2. V1: the PLT header (P-D10)

P-D10 walks each `JUMP_SLOT` entry's lazy path symbolically (plumb.md
§12.2): what glibc's trampoline receives (x86-64: `[GOT[1], k]` on the
stack and the jump through `GOTPLT + 16`; AArch64: `x16 = GOTPLT + 16`
at the resolver and `GOTPLT + 24 + 8k` pushed), `GOTPLT[0..2]`, and the
BTI/IBT landing pads. The brief's reproducer (x86-64 hello PIE, PLT0's
rel32 at `.plt + 8` lowered by 0x1030) gives a P-D10 finding.

## 4. V2: R1 and TLSDESC relaxed to initial-exec

R1 now accepts, in a dynamic output, `GOTPC32_TLSDESC` on `lea
x@tlsdesc(%rip), %reg` rewritten `mov G(%rip), %reg` into any register:
REX (with W) and ModRM kept, `8d` made `8b`, G a GOT word with the
symbol's `TPOFF64` record. **Registers tested**: all sixteen (`%rax` …
`%r15`), each a `f_R` function of `tests/dyn/tlsdesc_regs.s`, linked by
GNU ld, lld and mold, PIE and `-no-pie` (case `tlsdesc-regs`). The 15
runnable ones ran under qemu-x86_64 and the program exits 0 (`%rsp` is
linked and judged, not called). Before: 14 R1 findings and one S12 per
output; after: 0.

## 5. P-D12 and the kept large-model descriptor

An AArch64 large-model TLSDESC sequence (565 `movz` + 566 `movk` at
+4, 567 and 569 against the same symbol, addend 0, no small-model
TLSDESC reference to the symbol) keeps one `TLSDESC` record, exactly at
`_GLOBAL_OFFSET_TABLE_` + the 32-bit offset the two instructions write.
Anything else stays P-D12. `tls-desc-large` passes for all four linkers;
its xfail line is removed. Negative: the `movk` moved to offset 0x40 gives
a P-D12 finding.

## 6. lld's 843419 patch symbols

`__CortexA53843419_<hex>`: the hex is the address of the site's patched
final word; the symbol must be the patch W8 accepted for that site,
size 8 (Y5). A name with no patched site labels dead bytes and is listed as not judged: the site's own verdict (C1 when the option is known, `erratum_not_judged` otherwise) reports the undone fix, as §9.2 (o)'s test expects. `tests/corpus.rs` no longer
allows them unjudged. The lld erratum link (`e843.s`) has
`__CortexA53843419_212000`, judged; `symtab-value` caught 5/6 there (the
miss is the `$x` mapping symbol, not this package's).

## 7. WP-054's requests

- **(a) `tlsgd-to-ie`.** plumb.md §5.3 has the rule (WP-054's text, plus
  "G a valid slot holding X; in a dynamic output, X as the loader writes
  it"). GNU ld writes it (`adrp; ldr` of a `TLS_TPREL64` word; `mrs x1,
  tpidr_el0; add x0, x1, x0`); mold keeps the GD sequence (`DTPMOD64` +
  `DTPREL64`, judged as before); lld refuses relocations 513/514. GNU
  ld's PIE and `-no-pie` outputs went from 3 R1 + 1 S12 to 0 and run
  (`tv 7 same 1`). Negative: the `ldr` offset moved one word gives R1
  ("…not to W12's local-exec form or the initial-exec form of
  tlsgd-to-ie").
- **(b) unique exports.** P-D7: a name every input defines
  `STB_GNU_UNIQUE` (and none `GLOBAL`/`WEAK`) is exported
  `STB_GNU_UNIQUE`. Fixture `unique` (`S<int>::c`, a template's inline
  variable, defined by the program and its library). All three
  references write the export unique in `.dynsym` and `.symtab`; GNU ld
  writes `EI_OSABI` 3, **lld and mold write 0**, so the `EI_OSABI` part
  is S1's (mortar only), not P-D7's. Mutation `dynsym-unique` (binding
  10 → 1 in `.dynsym` and `.symtab`, WP-054's wrong output) is caught 6/6.
- **(c) S1** counts `.dynsym`'s IFUNC and unique entries as well as
  `.symtab`'s.

## 8. Reference outputs whose verdict changed

None got a new finding: the 48-output corpus, the IBT/BTI shapes, the
`tlsdesc-regs`, `tlsgd-ie` and `unique` cases give no P-D finding; mold's
remaining findings are its recorded anomalies (S8, S11, Y3). Verdicts
that changed to clean: GNU ld/lld/mold x86-64 TLSDESC → IE into
non-`%rax` registers (V2); GNU ld AArch64 `tlsgd-to-ie` (6a); the four
linkers' `tls-desc-large` (P-D12). On GNU ld's C++ output with a library
(`unique` fixture) stage 2 gives Y3 on `__TMC_END__` (a label of an empty
section); that is stage 2's, unchanged by this package (follow-up 5).

## 12. Follow-ups

1. `.eh_frame`'s PLT FDE (GNU ld x86-64): 132/208 flips survive; nothing
   judges the FDE's range or CFA program against `.plt`
   (`crates/mortar_plumb/src/cfi.rs`; plumb.md §6.4).

   flips) and `st_shndx` (8) survive because P-D7 only places a section
   symbol by `st_shndx` and nothing reads them (`dyncheck.rs` `fields`).
   D-21 says mortar writes none; a reference's could be held to the
   section start of the right section.
4. The AArch64 large-model local-exec sequence against the executable's
   own TLS symbol is not judged by stage 2 (seen while building item 4's
   fixture; `reloc.rs` TLS operations).
5. Y3 on GNU ld's `__TMC_END__` in a C++ program with a library
   (`symbols.rs`), stage 2.
6. `.got` words that no record and no code reaches (lld's and mold's
   relaxed GOT references) are not judged: harmless, but a byte change
   there is invisible.
