# WP-231: the verifier's §4.1 closure iterated over dropped COMDAT copies (M11/M12, A128)

Verifier package after WP-200 (`spec/resolve.md` §4.1 "A dropped copy's
definitions stop counting when it is dropped", §6.2; record
`spec/landed/resolve/WP-200.md`). Written from the specs and from the
outputs; no linker crate was read.

## 1. What the verifier models now

`spec/plumb.md` §3.8 "§4.1's iterations": every closure the input set
computes (mortar's two bounds, D-12's stages, rule 2's comparison) is
resolve §4.1's procedure, steps 1 to 4, from the inputs alone:

- **Read** (§3.8 "The files"): each object's `GRP_COMDAT` groups in
  section-index order, signatures as §6.1 computes them, and each
  definition in a member section marked with its group.
- **Step 1**: `T₁` = `first`/`cfirst` as before; `L₁` the closure;
  `C₁` the keepers of §6.1 over the relocatable objects of `L₁` (per
  signature the least live `FileId`, its first group by section index).
- **Step 2** (trigger): a definition marked with a dropped group, of a
  live object that is the key's `first` or `cfirst` in `T_i` (for a key
  with `@`, also the unversioned key).
- **Step 3**: `T_{i+1}` without the dropped copies' definitions of live
  files, per key and column the later of that and `T_i`; `L_{i+1}` the
  closure from the roots and `L_i`; `C_{i+1}` the keepers of `L_{i+1}`.
- **Step 4**: stop when `T_{i+1} = T_i`, `L_i = L_{i−1}`, `C_i =
  C_{i−1}` (as written; §3 Q1).
- A demoted mention is a defined mention: no edge (§6.2). An M12 member
  that defines a demoted mention's key names the mention, its file and
  its group. D-12 item 3 reads the last iteration's `first(k)`.
- **Neededness** (§5.7a, `dynmodel::Key::need_ref`): a demoted
  `STB_GLOBAL`/`STB_GNU_UNIQUE` mention is a strong reference for the
  binding the output asks for, never for D-11 (dyn.md D-11 item 2): a
  library in `DT_NEEDED` only such mentions refer to is P-D6 "...
  (only a mention defined in a dropped COMDAT copy refers to a definition
  of it: resolve §6.2, D-11 item 2)". Before this package such a mention
  set the strong-reference flag D-11 counted, so a library only it named
  passed.
- **References (rule 2)**: unchanged, no keepers: a definition in any
  COMDAT copy defines its key (what GNU ld, lld and mold do when they scan
  an archive). Only the comparison closure, coverage, is iterated.

## 2. The four pending tests (renamed to `.test`)

Each passes L3 on mortar's output on AArch64, x86-64 and i386, because
the member the verifier's second iteration reaches is the one the map
names (and nothing else is extra):

- `comdat-mismatch-weak-archive-extract` (`ext`): wb.o's copy of `g`
  dropped for wa.o's (lower `FileId`); wb.o is `first(hx)` → feeds back;
  `T₂`'s `first(hx)` is libhx.a(hx.o); wu.o's strong `hx` extracts it.
- `comdat-mismatch-extract-orders` (`after`, `back`, `member`, `grp`,
  `lazy`, `t1`, `t8`): the same in every order and kind of lazy file;
  §4.1 has no order (the archive before wu.o, `back`, too).
- `comdat-mismatch-member-copy` (`later`): libhxg.a(hxg.o) extracted in
  iteration 2, its own copy of `g` dropped in `C₂`, its `hx` outside the
  group defines the key.
- `comdat-mismatch-keeper-later` (`grp`, `back`): wa2.o (extracted by
  wb2.o's `A`) has the lower `FileId` and keeps `g`; wb2.o's copy, read
  first, is dropped in `C₁`; iteration 2 extracts libhx.a(hx.o).

`comdat-mismatch-strong-demoted-needed.test` now declares
`#@ anomaly(bfd): A128` (its `asn` line).

## 5. Questions

- Q1 (§4.1 step 4): "except when the iteration would repeat the one
  before: `T_{i+1} = T_i`, `L_i = L_{i−1}` and `C_i = C_{i−1}`" mixes
  `i+1` and `i−1`. Implemented as written; the reading "(T, L, C)
  repeats" gives the same final set (§3.8 explains why), so no verdict
  depends on it.
- Q2 (§4.1 step 2): the trigger fires for a dropped copy's definition
  that is `first(K)` even when nothing refers to `K` (the `dem` cell
  runs a second iteration that extracts nothing). Implemented as
  written; only the coverage's iteration count sees it.
