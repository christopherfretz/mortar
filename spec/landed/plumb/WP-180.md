## C. Open questions (for the supervisor; each is marked open where it is used)

**RULED (supervisor, 2026-11-17), all of them; the texts are in the
linker specs and plumb.md follows them:**

- **Q-R1: (a), and input `R_*_NONE` records are CARRIED.** The question
  showed a defect of the design: `spec/image.md` I-R5 dropped the
  inputs' `NONE` records. A `NONE` record is a reference: a
  `--gc-sections` edge in GNU ld, lld and mortar (image.md I-7), carried
  by GNU ld's and lld's `-r`. Measured for the ruling (AArch64):
  `_start` with `.reloc ., R_AARCH64_NONE, keepme`; `keepme` survives a
  `--gc-sections` link directly and through both references' `-r`, and
  is collected without the record. A mortar `-r` as I-R5 was written
  would have made the final link drop code a direct link keeps,
  silently. I-R5 now carries them; a relocation section exists exactly
  when it holds an output record, `NONE` included (L-R10 defines
  "relocated piece"). P-P3 therefore requires every input `NONE` record
  of a kept place once, in every linker's output; what stays per-linker
  is GNU ld's own `NONE` for a removed FDE. §9.2 (t) gains the mutation
  "an input `NONE` record dropped" and P-P1's corpus the measured case
  with `--gc-sections` in the final link.
- **D1: `.llvm.call-graph-profile` is dropped at `-r` with its
  relocation section** (`spec/layout.md` L-R1, as `.llvm_addrsig`);
  A-R4 corrected (it judges relocation sections of placed sections).
  Carried when a line needs it.
- **Q-R2: (a).** RL-6 writes P-P1 in `crates/mortar_plumb/src/compose.rs`
  (RL-1 adds the `mod` line) and is briefed as a verifier-side agent
  (it reads no linker crate); RL-5 writes P-P9.
- **Q-O1 to Q-O7: `spec/cli.md` C-R2b.** Q-O1 (a)+(b), with
  `--orphan-handling` a no-op while `-T` is refused; Q-O2 (a); Q-O3 (a),
  RL-2 measuring GNU ld with the symbol undefined; Q-O4 (a); Q-O5 (b):
  both no-ops (a line that carries `--odr-table` for every link must
  not fail at its `-r` step); Q-O6 (a); Q-O7 (a): the class at `-r`
  wins.
- **D2**: MD-R3 corrected (the build ID is computed at `-r`). **D5**:
  the interim name is `Refused{Option, "<option> with -r"}` (C-R2b).
  **D10**: I-R12 corrected. **D7, D8**: as done here and by Q-R2.
- **`-T` at `-r`**: RL-11 keeps `-T` refused unless a verifier rule for
  placement by a script at `-r` is written first (a verifier package
  before it); the row of WP-191 says so.

- **Q-R1 (plumb §14.8): does a relocation section with no output
  record exist?** The case is a section whose input records are all NONE
  or all dropped. L-R10 does not define "relocated piece".
  - (a) A relocation section exists only when it holds at least one
    record;
  - (b) one for every section that has an input relocation section;
  - (c) as (b), and the NONE records are written.

  *Recommended:* (a). P-P3 and P-P11 are written for (a).
- **Q-R2 (plumb §14.8): who writes P-P1 and P-P9?** The cut gives
  RL-6 "V-R1's comparison" and "S1 on ET_REL", but RL-6 owns no

  - (a) RL-6 writes `crates/mortar_plumb/src/compose.rs` (RL-1 adds its
    `mod` line), and RL-5 writes P-P9;
  - (b) both go in `xtask/src/linktest`;
  - (c) RL-5 writes both.

  *Recommended:* (a).
- **Q-O1 (options-at-r.md): accepted rows with no `-r` class.**
  - (a) Add the "noop: measured, unlisted" rows to C-R2 as measured.
  - (b) Classify the unmeasured rows by hand:

- **Q-O2: `--start-lib` at `-r`.** lld makes the objects lazy and

    `noextern-protected-data`, `noindirect-extern-access`,
    `pack-relative-relocs`, `nopack-relative-relocs`,
    `report-relative-reloc`, `mark-plt`, `nomark-plt` and
    `noreloc-overflow`.
  - C-R2's `-q`/`--emit-relocs` and `--no-relax` are refused in a final

  Two readings, and the options:
  - (a) at `-r` they are no-ops (the class table wins);

## E. Defects found in the linker-side specs (reported, not edited)

- **D1 (`spec/layout.md` L-R1, `spec/arch.md` A-R4, `spec/image.md`
  I-R5): `.llvm.call-graph-profile`.**
  - Clang writes `.llvm.call-graph-profile` (`SHT_LLVM_CALL_GRAPH_PROFILE`,
    `SHF_EXCLUDE`, `sh_link` to `.symtab`) with an **`SHT_REL`** section
    of `R_AARCH64_NONE` records (`rl0` case 13). The records name the
    functions, and the section's entries refer to them by position.
  - A-R4 refuses an `SHT_REL` on AArch64 and says "no compiler on the
    matrix produces one". That is false: clang does, for every object
    built with a call-graph profile (PGO, or `.cg_profile`).
  - If the section were accepted, L-R1 would copy it by name, and
    I-R5's "no NONE records" would drop the records it needs.
  - Proposal: at `-r`, drop it with its `SHT_REL`, as `.llvm_addrsig`
    is dropped (an optimization hint), or refuse it by name. Either way,
    A-R4's sentence must be corrected.
- **D2 (`spec/model.md` MD-R3 against `spec/image.md` I-R8).** MD-R3
  says that "the build ID" is not computed at `-r`. I-R8 (and C-R3)
  write it over the `-r` output under `--build-id`.
- **D3 (`spec/resolve.md` RV-R4): `multiple-definition` is not an
  id.** Fixed to `duplicate-symbol`, the only edit to a linker spec.
- **D4 (`spec/cli.md` C-R2a's last sentence against its first row, and
  C-R2's `--emit-relocs`/`-q`/`--no-relax`).** This is Q-O7.
- **D5 (`spec/cli.md` C-R3, C-R2a): interim refusal names are not
  spelled.**
  - The options that act at `-r` "until" a package (`-d`, `-s`, `-S`,
    `-x`, `-b`, `--force-group-allocation`) have no refusal name.
  - C-R2a's `unique-symbol` row says only "refused by name".
  - diag §4.4 reads `{option} with -r` and marks the reading open.
- **D6 (`spec/cli.md` C-R2 and others): unclassified rows.** About 60
  accepted rows have no `-r` class. These are Q-O1 to Q-O6.
- **D7 (record §F): RL-0 is given a generated file.** The cut lists
  `docs/status/options.md` as RL-0's. That file is generated from
  `crates/mortar_cli/src/rows.rs` and checked by
  `crates/mortar_cli/tests/table.rs status_file_is_current`. The
  `at_r` status in `rows.rs` is RL-1's, by the same table. RL-0 wrote
  `docs/status/options-at-r.md` instead; RL-1 turns it into the column
  and deletes it.
- **D8 (record §F): ownership of V-R1 and V-R9.** The cut gives them to
  RL-6, but RL-6 owns no `mortar_plumb` file. RL-5's row lists
  "V-R2-V-R8, V-R10, V-R11, V-R12". This is Q-R2.
- **D9 (`spec/plumb.md` §3.8, which predates the design, against
  `spec/resolve.md` RV-R2).** §3.8 named `-e` as a root at `-r`. Fixed
  in plumb.md, which is this package's file.
- **D10 (`spec/image.md` I-R12): the map format.** I-R12 says that "A
  GNU-style `-Map` lists the output sections and their pieces without
  addresses". mortar's `-Map` writes its own format
  (`spec/harness.md` L3, `spec/plumb.md` §3.2). The plumb.md map at
  `-r` is §14.2's. I-R12's sentence should say that mortar's `-Map` at
  `-r` is §14.2's records.
- **D11 (`spec/layout.md` L-R10): "relocated piece" is not defined.**
  This is Q-R1.
