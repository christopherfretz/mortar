# WP-197: the verifier's rules for an output linked with `--odr-runtime` (verifier)

Follow-up to WP-198, the load-time ODR runtime (`spec/odr.md` O-52,
O-53, O-58, O-59; `spec/cli.md` C-ODR-RT). Every mortar output that
carries the runtime is now held to `spec/plumb.md` §13's rules. The
five `.test.pending` files of `tests/link/odr-runtime/` are `.test`
files.

## The rules as written (`spec/plumb.md`)

- **§13.1, the options and the input.**
  - The line's last `--odr-runtime` (`report`, `fatal`, `off`; default
    `off`) is read. Whether `--odr-table` is spelled is read too, and so
    is the last of `-z now` and `-z lazy` (§3.2a's new row).
  - The runtime implies `--odr-table=exported`, and it writes the table
    under `--odr=off` as well.
  - It implies `-z now` unless `-z lazy` is given. P-D6 (§12.3) reads
    this effective `now`, so a mortar output with the runtime and
    without `-z lazy` needs `DF_BIND_NOW` and `DF_1_NOW`.
  - The runtime input `<mortar:odr-runtime>` is the line's last input.
    Its bytes are the verifier's own copy (see below).
- **P-M2, the runtime note** (type `0x4d4f4403`).
  - At most one runtime note, and it is last.
  - It is present exactly when the line asks for the runtime and the
    output has `PT_INTERP` or is a shared object.
  - `n_descsz` is 16. The descriptor reads: version 1, mode (1 report,
    2 fatal, from the line; 1 or 2 when the options are unknown), flags
    0, and the expected id (machine and kind, from `e_machine`,
    `PT_INTERP` and `e_type`).
  - A line mortar refuses is itself a finding: static with the runtime,
    an explicit last `--odr-table=off` beside it, or a value other than
    off/report/fatal.
  - A reference's map is held to none of mortar's options, so a type-3
    note in a reference output is a presence finding.
- **P-M3, "no code, or exactly this code".** The existing first half is
  unchanged, except that the file `<mortar:odr-runtime>` is exempt from
  "on the line" exactly when the line asks for the runtime. With the
  runtime asked for, also:
  - *input*: the map names the runtime, and no non-member file follows
    it in the map's file order.
  - *kept*: every allocated runtime section that has bytes has a place.
    ICF is not judged, because mortar refuses `--icf`.
  - *entry*: the entry section (`.preinit_array` for exe,
    `.init_array.00000` for so) is placed whole and once, in an output
    section of its `sh_type`. Every other same-type input section in
    that output section is before it exactly when WP-198 §2.2's order
    says so:
    - `.preinit_array`: input order;
    - `.init_array`: priority (`.init_array.N` = N; unnumbered and
      `.ctors` after every numbered one), then input order.
  - *exports*: no `.dynsym` definition, `DT_INIT` or `DT_FINI` inside a
    runtime section.
  - *imports*: each non-weak undefined runtime symbol, except
    `__ehdr_start` and `_GLOBAL_OFFSET_TABLE_`, is imported by
    `.dynsym` or defined by the output or an input.
- **"Does not judge"** now says that the runtime's behaviour at load is
  `tests/hook/run.sh`'s matrix. The verifier judges that the bytes, the
  entry, the note and the binding mode are the ones that matrix measured.
- **§2's stage-4 row, §2.2, §7.2 and §13.2's coverage.**
  - `MetaCoverage` gains `runtime_outputs`, `runtime_entries` and
    `runtime_imports`.
  - The summary gains the line `ODR runtime: outputs N, entries N,
    imports N`.
- **Anomaly table:** no new rows (A110-A119 unused).

## How the verifier reads the runtime's bytes

`crates/mortar_plumb/src/odrrt.rs` holds `OBJECTS`, which
`include_bytes!`s the six `runtime/odr/obj/mason_odr_rt-<arch>-<kind>.o`
in id order (0 a64-so, 1 a64-exe, 2 x64-so, 3 x64-exe, 4 i386-so,
5 i386-exe). A unit test checks each object's SHA-256 and size against
`runtime/odr/PINS`.

`embedded(output, map)` picks the object by the output's expected id when
`serves(map)` holds: a mortar map that names `<mortar:odr-runtime>`
(not as a member) and whose line asks for the runtime.

The seam is `dynverify.rs` `verify_src`:
- When `embedded` gives bytes, the caller's `Source` and `Files` are
  wrapped in `Overlay` and `OverlayFiles`. These answer the path
  `<mortar:odr-runtime>` with the embedded object, as one extra last
  file. A file of that name on disk is never read.
- `line_words` appends the word `<mortar:odr-runtime>` for such maps, so
  the input set (M11, M12) sees the runtime as the line's last input.

From there, the runtime object is an input like any other, and the
existing passes cover it:
- store, locate, and the relocation engine (R1, every `.rela` record
  re-applied);
- S12 (every uncovered byte equals the input);
- `.eh_frame` (E1-E4);
- symbols (Y-rules);
- dead and placed sections (§4.4);
- the input set (M11, M12);
- the dynamic model (P-D6's `DT_NEEDED` and bind-now; P-D7's bindings;
  P-D9's RELATIVE records).

Stage 4's P-M3 additions are the only rules that know the file is the
runtime.

## Mutations (`crates/mortar_plumb/tests/odrrt.rs`)

The fixtures are in `tests/odrrt/{aarch64,x86_64}/`, built by `gen.sh`:
- `prog`: a PIE with `--odr-runtime=report --odr-table=full`, so it has
  three notes;
- `lib.so`: `--odr-runtime=fatal`;
- `plain`: no runtime;
- `ref`, `ref-note`: GNU ld's PIE, then the same with prog's runtime
  note added.

All of them are accepted as linked, except `ref-note`. Every mutant is
run on both arches, and each is asserted caught by the named rule and
message prefix.

P-M2, 17 per arch (the first six on both `prog` and `lib.so`):

| Mutant | Caught by |
|---|---|
| version 2 | P-M2 `runtime: version` |
| mode swapped | P-M2 `runtime: mode` |
| flags 1 | P-M2 `runtime: flags` |
| other kind's id | P-M2 `runtime: runtime id` |
| other target's id | P-M2 `runtime: runtime id` |
| note removed (`sh_size` − 40) | P-M2 `presence` (absent) |
| second runtime note (the =full note retyped) | P-M2 `place` |
| option removed from the map | P-M2 `presence` (present, off) |
| runtime note added to `plain` | P-M2 `presence` |
| explicit `--odr-table=off` | P-M2 `presence` (conflicting-options) |
| `--odr-runtime=loud` | P-M2 `presence` (refused value) |

P-M3 and P-D6, 14 per arch:

| Mutant | Caught by |
|---|---|
| one byte of the runtime's code | S12 `the output differs from the input` |
| a relocated field (first `.rela.text` record) | R1 `the relocated field holds the wrong value` |
| exe entry moved before the user's (map and image agree) | P-M3 `entry` |
| the words swapped in the image only | R1 |
| `user_fn` written into the exe entry | R1, and P-D9 `a RELATIVE record` |
| exe entry removed from the map | P-M3 `entry`, and P-M3 `kept` |
| so entry moved after priority 101 | P-M3 `entry` |
| so entry removed | P-M3 `entry` |
| `user_fn` in the so entry | R1 |
| `DF_BIND_NOW` cleared | P-D6 `-z now and DT_FLAGS has no DF_BIND_NOW` |
| `DF_1_NOW` cleared | P-D6 `-z now and DT_FLAGS_1 has no DF_1_NOW` |
| `-z lazy` added to the line | P-D6 `DF_BIND_NOW or DF_1_NOW without -z now` |
| the runtime's file renamed to main.o | P-M3 `input` |
| the option dropped | I1 `the map names '<mortar:odr-runtime>'` |

The renamed file is also caught by R1 and by E3/E4, because main.o's
bytes then stand in for the runtime's.

Reference, 1 per arch:

| Mutant | Caught by |
|---|---|
| GNU ld PIE plus a type-3 note | P-M2 `presence: the runtime note is present and the line's --odr-runtime is off` |

Totals: 32 per arch, 64 in all, every one caught by its named rule.

## Cells where the spec left a choice

- A static output with the runtime, an explicit `--odr-table=off`, or a
  refused value are presence findings: mortar must have refused the
  line.
- ICF is not judged (mortar refuses `--icf`).
- `equiv.rs` (M7's re-link) and `mutate.rs` `places()` are not
  overlaid, because `--incremental` with the runtime is refused.
- An unterminated `--start-lib` before the appended runtime word would
  take it into the group. mortar's line never ends that way. Not judged
  apart.
- A real file literally named `<mortar:odr-runtime>` on the line is
  shadowed by the overlay.
- `line_words` appends the runtime word even when `embedded()` is
  `None` (a static output). The presence finding names that case.
- A reference's `now` stays its own `-z` words: the runtime's implied
  `-z now` is mortar's alone.
