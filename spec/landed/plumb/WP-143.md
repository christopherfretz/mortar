# WP-143 — a relocation against a symbol whose section has no place

Branch `wp/143-plumb-placeless`, from `int/batch-5`. Only
`crates/mortar_plumb/`, `spec/plumb.md` and this record. The verifier
was written from the specs and the outputs; no linker crate was read.
`shared.rs` was not touched.

## The hole

WP-136 found two silent mislinks: a relocation against a defined global
whose section mortar gave no place holds 0, and the verifier reported
nothing.

1. `emptymerge.o` + `r-gms.o`: `gms` (global) at offset 0 of an empty
   `SHF_MERGE|SHF_STRINGS` `.rodata.str1.1`, referenced by `.quad gms`.
   mortar wrote 0 and left `gms` out of `.symtab`; GNU ld, lld and mold
   write its address (GNU ld the end of `.text`, lld and mold an empty
   output section).
2. `prop.o` + `r-gprop.o`: `gprop` (global) in an input
   `.note.gnu.property`, which the link consumes into its own note.
   mortar wrote 0; GNU ld, lld and mold refuse the reference.

**Cause.** `spec/plumb.md` §4.4 resolves a global by the output's
`.symtab` (step 1), then by its *placed* definitions (step 2), then by a
unique output symbol (step 3), and ends in `symbol-unresolved`, a
not-checked count (§7.2). R5 (§5.7) was reached only from a local
symbol's section. A global whose every definition is in a section without
a place (case 2), or in an empty merged section mortar's map has no
record of (case 1: no piece, I-78), fell through to the count. It was not
a named permission: it was the fallback for stripped outputs, applied to
every name. Around it, three more rules let the mislink through: Y3
skipped a name absent from `.symtab` (`continue`), Y3 counted a name with
no placed definition as unchecked, and nothing asked why a section had no
place (a `discard` record's reason, or no record at all, was taken as
given).

How wide: every global reference — field, GOT slot, TLS, IFUNC, FDE
target, tombstone — whose target is a global of a discarded or absent
section, and every reference to a label of an empty section without a
record, on every architecture and map format.

## The rules (`spec/plumb.md`)

- **§4.4 step 0** (new, before step 1): a name with input definitions,
  none `SHN_ABS` or common, every one in a discarded or absent section
  (not one without bytes), the loader not binding it: the first strong
  definition, else the first; S from its section as for a local — R5, or
  §5.8's tombstone from a non-alloc place, whatever `.symtab` says.
- **§4.4** last paragraph and the local row "empty without a record": a
  name defined only in sections without bytes and without a record is
  judged by the address the field names (below).
- **§3.3** place table: an empty foreign mergeable section with a row is
  whole (its row is its labels' address); an allocated section without
  bytes and without a record is not "not in the output": an
  address-naming reference (address-sized `S + A`, 4- or 8-byte
  `S + A - P`) must name an address in or at the end of an allocated
  output section, else R5; other types `section-not-locatable`.
- **M4** (amended): under mortar's map an empty allocated section placed
  whole is in or at the end of an allocated output section. Not for
  foreign maps: GNU ld places one where its dropped empty output section
  would have been (A10); the corpus' `veneer/bfd` has two.
- **M10** (new, mortar's map): every non-consumed section with bytes and
  no place has a reason the verifier derives from the inputs and the
  line. Permitted reasons, with citations:
  | reason | source |
  |---|---|
  | `SHF_EXCLUDE` | resolve.md §10 |
  | `.mason.meta` container | resolve.md §10, meta.md MT-6 |
  | `.note.GNU-stack` (consumed) | resolve.md §10 |
  | `.note.gnu.build-id` (excluded) | resolve.md §10, WP-135 |
  | `.note.gnu.property`, `SHT_NOTE` (consumed into the output's note) | resolve.md §10, synth.md |
  | `.gnu.lto_*` | resolve.md §10 |
  | `.gnu.warning`, `.gnu.warning.*` (consumed) | resolve.md §10 |
  | `SHT_LLVM_ADDRSIG`, `_CALL_GRAPH_PROFILE`, `_DEPENDENT_LIBRARIES` | resolve.md §10 |
  | `SHT_AARCH64_ATTRIBUTES` on AArch64 | resolve.md §10, layout.md L-35 |
  | non-alloc debug section under `-S`/`-s` (stripped) | resolve.md §10 (and §6.3's names) |
  | `.debug_gnu_pubnames`/`pubtypes` under `--gdb-index`, no `-S`/`-s` | resolve.md §10, synth.md S-G6 |
  | member of a COMDAT group not its signature's keeper (least `FileId`, then section index) | resolve.md §6.1, §6.2 |
  | `discard gc` with `--gc-sections` on the line and not a root the inputs show (`SHF_GNU_RETAIN`; start-up tables by type or name; a note or non-alloc section outside an allocated group; `.eh_frame`; a C-identifier section whose `__start_`/`__stop_` is referenced; `SHF_LINK_ORDER` with its link placed is a finding) | image.md I-5, I-6, I-109 |
  | `discard script` with `-T` on the line | image.md I-78 (M4) |
  A section without bytes needs no record. A `discard` whose reason does
  not match (`comdat` not in a dropped group, `unspecified` with no row,
  `gc` without `--gc-sections` or of a root, `script` without `-T`), and
  a section with bytes no record names and no row explains, are M10.
  Not re-derived: roots that need the line's symbols (entry, `-u`,
  `--require-defined`, exports), a script's `KEEP`. A live section's
  reference to a collected one is R5 (I-7's edge seen from its end).
- **§5.7 R5** (amended): also a global by step 0, and an empty section's
  label at an address outside every allocated output section.
- **§6.5 Y3** (amended): a missing global (the output has `.symtab`, no
  symbol of the name, default or protected visibility, an input defines
  it in an allocated section placed whole or as pieces or — mortar's map —
  empty without a record) is a finding; an empty section's label must be
  in or at the end of an allocated output section; under mortar's map a
  name the output defines though every input definition has no place is a
  finding. A foreign map's merged section is not known to hold anything
  (lld collects pieces under `--gc-sections`: the corpus' `gc-sections/lld`
  drops `_IO_stdin_used`), so its names are not judged missing.
- **§7.1**: `M1`–`M10`.

Sites: `reloc.rs` (`resolve_any` step 0, `placeless_def`, `empty_only`,
`empty_record`, `Target::Empty`, `in_section`), `x64rec.rs`, `x86rec.rs`,
`eh.rs` (the new target), `locate.rs` (`Sec::discard`,
`Sec::empty_unrecorded`, the foreign empty mergeable row, M4),
`fate.rs` (M10, new), `opts.rs` (`gc_sections`, `script`),
`symbols.rs` (Y3), `image.rs` (`holds_or_ends`, `has_name`), `lib.rs`.

## WP-143b: a label of an input `.eh_frame` (follow-up)

**The false positive.** Merged with WP-142 (`synth.md` S-48a), WP-143's
Y3 found on `tests/link/layout/eh-frame-terminator-only.test` line 45
(`get.o end.o`, three targets): `symbol 'frame_end_after' is defined in
the output, but every input definition is in a section not in it
('.eh_frame')`. end.o's `.eh_frame` is a terminator with the global at
offset 4 (= `sh_size`). mortar removes the terminator, so the map has no
`piece` for that input and its place is *absent*; `placeless_def`
counted an absent input `.eh_frame` as "not in the output". mortar's
bytes are right: the output `.eh_frame` is the terminator alone at
0x4000e8 and the label is S-50 rule 3's final terminator, 0x4000e8.

**Before and after.** Before WP-143, a global label of an input
`.eh_frame` was judged only at r = 0 (rule 1, the section's start) or
inside or at the end of a kept record (a piece; rule 2); otherwise it
was in `globals_unchecked`. WP-143 turned the rest, under mortar's map,
into the placeless finding. Locals are Y4's, which neither package
changed: a local of an absent or rewritten `.eh_frame` is unchecked
unless rule 1 or a piece places it. The same false positive was
reachable with records present: a global in an input whose records are
all removed (here the terminator; also a duplicate CIE, dead FDEs)
while other inputs keep the output `.eh_frame`. Not at r = 0 (rule 1
gives a place), nor at the end of an input whose last record is kept
(the piece ending there; packing is contiguous, S-47, so this equals
rule 3).

**The rule now** (`spec/plumb.md` §6.5 Y3, §4.4 step 0 and the "in
`.eh_frame`" row). While the output has an allocated `.eh_frame`, a
label of an input `.eh_frame` is never "not in the output":
- under mortar's map, its value is S-50's, re-derived from the `piece`
  records: rule 1; rule 2 (a covering piece); rule 3, and rule 4 for a
  symbol (the next kept record of the record it is in): the first piece
  of the same section at or after r, else the first piece of the later
  input `.eh_frame` sections in SectionId order (S-46), else the final
  terminator (the output's last 4 bytes). No record is parsed: a symbol
  inside a removed record and one at its start take the same next kept
  record, and one inside a kept record is in its piece. What is not
  re-derived: relocations to an offset in or at a removed record stay
  `eh-frame` (rule 4 refuses one inside a removed record, which needs
  the record boundaries; not judged, counted);
- under a reference's map: in or at the end of the output `.eh_frame`,
  else a finding (Y1 instead where GNU ld's map places the edited
  input).

With no output `.eh_frame`, mortar's map: the placeless Y3 finding, and
a reference to the section is R5; a reference's map: unchecked.

**Measured** (`get.o end.o`, `get.o getc.o end.o`, `get.o end.o
getc.o`; AArch64, x86-64, i386; same on each): GNU ld writes the label
at the edited input's place, the output's end for the first two and
offset 4 for the third (where it drops the terminator, so its output has
none: E1 fires on that output, an existing rule, not this package's);
lld writes the output's start + 4 for all three; mold drops the name.
mortar writes the start (S-48a), the final terminator, and getc.o's CIE.

**Tests.** `tests/ehsym.rs`, fixtures `tests/ehsym/<arch>/` (`gen.sh`):
mortar's three outputs are clean and at S-50's values; the label moved
past the end, to 0, or to GNU ld's place (the end, where S-50 says
otherwise) is found; the output without an `.eh_frame` (renamed) is the
placeless finding; the references are clean under their own maps, and
the label moved out is found.
