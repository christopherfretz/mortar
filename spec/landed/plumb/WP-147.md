# WP-147: definitions with no place in `.dynsym` and `.symtab` (verifier)

Follow-up to WP-136, the linker side of `spec/resolve.md` §10.1 P-1:
every defined symbol either has a place or has no place by a named
rule, and an unreferenced placeless symbol is omitted from `.symtab` and
`.dynsym`. The verifier's sets of expected symbols now follow P-1 for
mortar's output. They derive "no place" once, from §4.4 step 0's
predicate (`Obj::no_place` in `locate.rs`: discarded or absent, except
an allocated section without bytes and an input `.eh_frame` while the
output has one). §4.4 step 0, Y3, Y4 and P-D19's export set all ask
that one predicate.

## Measurements

The globals are `gprop` (`.note.gnu.property`), `gstk`
(`.note.GNU-stack`), `gex` (`SHF_EXCLUDE` `.foo`) and `gbid` (an input
`.note.gnu.build-id`), none referenced, beside the placed `gplain`. They
were linked `-shared` and `-pie --export-dynamic -dynamic-linker ...`
on AArch64 and x86-64, with the same result on both:

| linker | `-shared` `.dynsym` | `-pie -E` `.dynsym` |
|---|---|---|
| GNU ld 2.44 | `gprop`, `gbid` `SHN_ABS` at their offset (0); `gstk` at the end of `.text` (placed in its map) | the same |
| lld 22 | all four `UND` | none of them |
| mold 2.37 | `gex` (its own `.foo`, placed in its map) | `gex` |
| mortar | none of them | none (and no `gplain`: mortar's `-pie -E` exports nothing, recorded by WP-136) |

A local `lprop` in the note, unreferenced, in a static link: GNU ld,
lld and mortar omit it; mold writes it `SHN_ABS` at its offset (0xc).
Before WP-136, mortar wrote the same.

An empty `SHF_MERGE` section (`gms`, `wcs`, `lms`; `gmid` after a merged
input): mortar places it whole with a `place` record of size 0, and
`gmid` sits at the end of `gpre`'s string (L-162), on all three targets.
GNU ld and lld each write a row for it at its labels' address.

## Rules as amended (`spec/plumb.md`)

- **§4.4 step 0.** Its predicate is the one derivation that every rule
  listing expected symbols asks.
- **P-D19.** A definition with no place, or a key every definition of
  which is discarded (not a COMDAT copy another object keeps), is not in
  the export set.
  - Under mortar's map, such a key defined in `.dynsym`, in any form, is
    a finding.
  - Under a reference's map, the measured forms are accepted: GNU ld's
    `SHN_ABS` at the definition's offset (another value is a finding);
    lld's `UND` (P-D7's "imported and no input references it" is
    dropped for it); mold's absence.
  - Before WP-147, the set held these keys, so a mortar library without
    them was "in the export set and not defined in .dynsym".
  - `-s` changes nothing: P-D19 reads `.dynsym`.
- **Y4.** Under mortar's map, an output local whose every input local
  (not a mapping symbol, no global of the name) is in a section with no
  place is a finding. Under a reference's map it stays unchecked.
- **M10, the roots the line names.** A `discard gc` record, or a
  collected `NOBITS` section, is also M10 when the section holds the
  definition of a key the line roots:
  - the entry (`-e`, else `_start` outside `-shared`);
  - `-init`, `-fini`, `--export-dynamic-symbol`;
  - under `output shared`, or exec/pie with `-E`, every
    default/protected global.
  - mortar refuses `-u`, `--require-defined`, version scripts, dynamic
    lists and `--exclude-libs`, so its lines never carry them.
- **Empty merge (S-6, L-162).** No rule changed. Under mortar's map the
  section is *whole* (its size-0 `place`). Its labels and the address
  words that name them are judged by that one address (Y1/Y3, R1), so a
  move of one byte, or to 0, is a finding. A reference's map is judged
  the same way when it has a row; without one, the label must be in or
  at the end of an allocated output section (§3.3, WP-143).

## Tests

- `crates/mortar_plumb/tests/pexport.rs`, with fixtures in
  `tests/pexport/<arch>/` (`gen.sh`; mortar's `lib.so`, `libs.so` with
  `-s`, and `loc`):
  - mortar's outputs are clean.
  - `gplain` renamed `gprop` in `.dynstr` gives two findings: the
    placeless export present, and the placed export missing.
  - The same entry in GNU ld's absolute form is still a finding under
    mortar's map.
  - `lprop` written at its offset, in a section or `SHN_ABS`, is Y4.
  - The references are clean as measured. GNU ld's form at offset 4 is
    a finding in a library.
- `tests/emerge.rs`, with fixtures in `tests/emerge/<arch>/`:
  - mortar's outputs and the GNU ld and lld links are clean (recorded
    anomaly A10 aside).
  - `gms`, `wcs` and `gmid` moved by +1, -1 or to 0 are each a new
    finding, and so are the address words of `gp`, `wp`, `lp`, `sp` and
    `mp` (R1/R5). This holds on all three targets.
- `tests/placeless.rs wp147_gc_of_a_line_root_is_m10`.
- `tests/link/resolve/place-note-property.test` and
  `place-dropped-global.test`: the `-shared` links on AArch64 and
  x86-64, with all four linkers verified. `gprop`, `gex`, `gbid` and
  `gstk` are checked absent from mortar's `.dynsym` (and `gprop` from
  mold's).

## Closed from WP-143's "Not verified"

- An exported placeless definition's `.dynsym` under `-s`: P-D19 (the
  `libs.so` tests).
- Y4 for locals of placeless sections: the rule above.
- gc roots that need the line's symbols: M10's roots, as above.

## Not verified

- An executable's export set (`-pie --export-dynamic`) is not P-D19's
  (§12.5 is a `Shared` output's). mortar's `-pie -E` exports nothing,
  `gplain` included, and the verifier does not report it (pre-existing,
  WP-136's record).
- Globs of `--export-dynamic-symbol`, and a script's `KEEP`, as roots.
- Y4 under a reference's map (mold's absolute local stays unchecked).
- A placeless definition that a debug word references (the tombstone) is
  treated as omitted from `.dynsym` like any placeless export. P-1's
  "unreferenced" is read as "referenced from no section that needs an
  address".
