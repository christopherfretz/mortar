# WP-164: the metadata of a shared object, and stripped outputs (verifier)

Three parts. Part 1 fixes P-D22's false finding on every `-shared -s`
output, and the same defect in the other rules that read the OUTPUT's
`.symtab`. Part 2 is P-M2 for a `Shared` output's `.note.mason`
(O-60). Part 3 is P-M1 for MT-32's kept `.mason.meta` in every output
kind. The six `xfail(mortar)` lines are gone, and every link of those
tests is judged. No anomaly id is taken (A49 and up stay free).

## Part 1: stripped outputs

### The rules as written

- **P-D22 and P-D6, `DT_INIT`/`DT_FINI`** (plumb.md P-D22, "A stripped
  output"). Without a `.symtab`, the function is looked up in two
  places:
  1. `.dynsym`, for an exported definition: its value.
  2. The relocatable inputs' non-local definitions in sections the map
     places whole: place + `st_value`. The tag holds one of those
     addresses (P-D22). P-D6 uses the address only when the
     definitions agree on one.

  "The output defines no ..." is reported only when neither place
  defines the name. When the inputs define it in sections the map does
  not place whole, the value is judged by segment only (a `PF_X`
  `PT_LOAD`), and the coverage line names that case:
  `stripped output (no .symtab), not judged: DT_INIT: the symbol is not
  in the output, value judged by segment only`.

  Code: `dyncheck.rs` `has_symtab`, `Stripped`, `stripped_def`;
  `shared.rs` `static_checks`; `dyncheck.rs` `fields`.
- **Stage 3's "the output defines the name"** (plumb.md P-D9, stage 2
  extension). Stripped, a name is defined exactly when resolution
  chooses an input definition or a common for it. Before, an empty
  `.symtab` made every name look imported, which gave view B a false
  finding on mold's `-s -Bsymbolic` library. Code: `reloc.rs`
  `undefined_out`.
- **The GOT base** (plumb.md §4.1 "GOT"). Stripped on x86-64, the base
  is the start of `.got.plt`; otherwise it is `.got`. This fixes a
  false R1 on mold's stripped large-model `GOTOFF64`. Code: `reloc.rs`.
- **P-D9, the GOT-slot addends** (plumb.md §12.3 P-D9). In a stripped
  output, a reference to a name that only the linker defines is
  `symbol-unresolved`, so the demands are not all known. A slot whose
  addend no known demand asks for is then counted, not judged. The
  coverage line names it: `P-D9: N .got slot addends (...)`. When every
  reference resolves, the clause is judged as before. Code:
  `dynverify.rs`, with the marker `dynfields::UNDEMANDED`.
- **The coverage line** (plumb.md §7.2). `Coverage::stripped_not_judged`
  holds the clauses above that were not judged, by name.

### The `.symtab`-reading rules, run stripped

Each rule was run on stripped outputs of `-shared`, `-pie` and
`-no-pie` links by GNU ld, lld, mold and mortar, on AArch64 and x86-64.
The strip options were `-s`, `--strip-all`, `-S` and `--strip-debug`.
Tests: `shared/shared-stripped`, `dyn/dynamic/exec-stripped`,
`dyn/dynamic/exec-stripped-x64-large`.

| rule (site) | before | now |
|---|---|---|
| P-D22 `DT_INIT`/`DT_FINI` (`shared.rs`) | false finding on every `-shared -s` output: "defines no '_fini'" | `.dynsym`, then the placed inputs, then the segment (named) |
| P-D6 `-init`/`-fini` value (`dyncheck.rs` `fields`) | a stripped value was taken as "the function is not in the output" and not judged | the same lookup as P-D22, segment only otherwise (named) |

| Y1-Y5 (`symbols.rs`, `content.rs`) | vacuous: no symbols to compare | unchanged (vacuous; `-S` keeps `.symtab`, so they are judged) |
| S7's labelled check, S8 (`structure.rs`) | vacuous | unchanged |

| D3 (`dead.rs`) | vacuous | unchanged |

| `dsoword` | falls back to the chosen definition | unchanged |
| M7 (`maprec.rs`) | already "not judged" when stripped | unchanged |

It reports nothing false and judges nothing. What stays unjudged is the
named coverage lines plus the `symbol-unresolved` relocations (§4.4
item 4).

## Part 2: P-M2 for a shared object (O-60)

`odrtable.rs`: `check` with `Pending`, and `shared_rows`, which runs
after stage 3 computes `Sets`. plumb.md §13.1 covers the output kind
and the export set; §13.2 covers the row set and the flags.

- **Presence.** A table is due in a `Shared` output (by the line) under
  the executable's options: `--odr-table` not `off` and `--odr` not
  `off`. The record asked for "and there is a row to write", but the
  spec and the measurement differ. mortar writes a count-0 table when
  there are no units or only C units, as it does for an executable.
  The spec wins: present iff asked.
- **Place, header, order, key, version, hash.** These are O-51/O-52's,
  shared with executables.
- **Row set.**
  - A row naming an undefined, local, hidden or internal entry is a
    finding, in every output kind (new).
  - In `Shared`, every row's name must be in the export set (`Sets`,
    D-110).
  - Every export-set name whose keeper's row qualifies must have a row,
    even when its `.dynsym` entry is missing. A name whose entries are
    all optional is not required.
- **Flags.** The fifteen other bits must equal the keeper's row's. Bit 15
  must be `!Sets::preemptible(name)`, the derivation P-D17 view B uses
  for D-112: protected, `-Bsymbolic`, `-Bsymbolic-functions` with a
  function, and `--dynamic-list`.
- **Coverage.** A Shared row counts as not judged until `shared_rows`
  judges its bit. After that, "names not judged" is 0 on every mortar
  library of the lane (`o60-*`, `o24-shared-output`, the fixtures).

## Part 3: P-M1 for the kept `.mason.meta`, one rule for every kind

Before this package (WP-076/WP-078), `exec` already meant "not ET_REL",
so libraries were judged the same way:

- the kept section is `SHT_PROGBITS`, flags 0, alignment 8;
- its bytes equal `meta::kept` of the live units;
- it is present iff `--keep-mason-meta` and some unit parses;
- no input container is placed.

What is new is "in no segment": `sh_addr` must be 0 and no program
header's file bytes may overlap the section (D-126 item 3). The text now
reads "executable or shared object".

MT-32's loaded-bytes sentence is a property of two links. No rule of
one output can judge it, beyond the two clauses above (no address, no
segment). plumb.md §13.2 names it unjudged, and the lane tests' `cmp`
(`dyn/odr/mt32-keep-meta-*.test`) is its only check.

For a unit that parses, MT-32's padding is always empty, because MT-14
makes `unit_size` a multiple of 8. The "padding non-zero" mutation is
therefore written two ways:

- a unit's own zero bytes changed (its string table's padding up to
  `unit_size`);
- bytes appended after the last unit (zero or not).

## Mutations (`crates/mortar_plumb/tests/meta.rs`)

The fixtures are mortar's `-shared` of the stage-4 inputs:
`tests/meta/{aarch64,x86_64}/lib.so` and `lib.map` (`gen.sh`). The rows
are `_Z2prv` (protected, bit set), `_Z2viv` and `_Z2wdv` (default,
clear). Both targets are covered.

| mutation | caught by |
|---|---|
| a row removed (note, section and PT_NOTE shrunk) | P-M2 `row set: '_Z2viv' ... no row names it (O-50)` |
| a row for a hidden symbol (its `.dynsym` `st_other` made hidden) | P-M2 `row set: row 1 names '_Z2viv' ... not an exported definition` |
| NONPREEMPTIBLE cleared (protected row) | P-M2 `flags` (shared_rows) |
| NONPREEMPTIBLE set (default row) | P-M2 `flags` (shared_rows) |
| a keeper bit flipped | P-M2 `flags` |
| the index one up / one down | P-M2 `key` |
| two rows swapped | P-M2 `order` |
| the option without the note (section renamed) | P-M2 `presence: no .note.mason` |
| the note without the option; with `--odr=off` | P-M2 `presence` |
| `-Bsymbolic` added to the line | P-M2 `flags ... bound inside the library` for `_Z2viv`, `_Z2wdv` |
| a unit dropped, duplicated, reordered (PIE and library) | P-M1 `kept section` (bytes) |
| padding after the last unit, non-zero or zero | P-M1 `kept section` (bytes) |
| a unit's zero padding made 1; a byte of a unit | P-M1 `kept section` (bytes) |
| `SHF_ALLOC` | P-M1 `kept section` (flags) |
| an address; inside a segment (PT_NOTE stretched over it) | P-M1 `kept section: at address` |

A control: the same bytes moved to the end of the file are accepted.
So the reseated mutants are caught by their contents, not by the move.

## The sweep

The new case is `shared.table` (`xtask/src/sweep.rs`; added to
`QUICK_CASES`, so `ci --quick` runs it). It sweeps `.note.mason` and
`.mason.meta` only, of the `shared` case's versioned library built with
test-producer units and linked with:
- `-Bsymbolic-functions`;
- `--odr-table=full`;
- `--keep-mason-meta`;
- `--build-id=none`.

The table it gives:

| row | flags | bit 15 |
|---|---|---|
| `sw_data` | 0x0008 | clear |
| `sw_new` | 0x8101 | set |
| `sw_old` | 0x8001 | set |

`=full`'s note holds the script-local `sw_hidden` and a type.

Measured at load about 11 with 4 threads:

| target | bytes | flips | caught | equivalent | survivors | time |
|---|---|---|---|---|---|---|
| AArch64 | 576 | 1152 | 1152 | 0 | 0 | 3.1 s |
| x86-64 | 576 | 1152 | 1152 | 0 | 0 | 3.6 s |

Caught by rule, the same on both targets: P-M1 720, P-M2 432, S11 30.
Nothing is named equivalent. Time added: about 3-4 s per target, and
each lane sweeps its own target. The case is described in plumb.md
§12.3 ("The lane's cases"), where the `Shared` cases are; the brief
said §9.

## Findings on existing outputs

Every finding on a mortar output was a false finding of the verifier,
and each is fixed (part 1). No mislink was found. Found on the way;
these are not stripping-related and are not changed here:

- An exported IFUNC in `-shared`, stripped or not:
  - GNU ld under `-Bsymbolic`: F4;
  - lld: A20;
  - mold: P-D17/P-D18 view B.

  `shared-stripped`'s `more.c` does not carry the IFUNC for that
  reason.
- mold x86-64 `-no-pie`: a `.tbss`-only `PT_TLS` outside every `PT_LOAD`
  gives S9.
- mold's S11 and Y3 on `-S`: the anomalies the lane already expects.

## What the specs leave unsaid

- O-60/O-50 do not say whether a library's table must exist when no row
  is due. The record says "and there is a row to write", but mortar and
  §13.1 say "iff asked". The spec was taken.
- MT-32's "padded to 8" is empty for every unit that parses, and the
  spec does not say so.
- Whether a linker-defined export (file 0) of a stripped library belongs
  in D-110's export set: the verifier reads it from `.symtab`, so a
  stripped output loses it. Not observed.

## What was not verified

- i386.
- `strip`ped copies made after the link: the lane has none for these
  shapes, so only link-time `-s`/`-S` were run.
- A library table under a version script with `local:` patterns that
  hide a row's name, and under `--exclude-libs`, beyond the scratch runs
  on mortar (both judged clean there).
- References' tables (none of them writes one).
