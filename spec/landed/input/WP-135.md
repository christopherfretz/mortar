# WP-135 — an input's `.note.gnu.build-id` is discarded

A defect on main, found by the verifier (B1) on BusyBox's Clang row of
the real-builds lane: `applets/built-in.o` is an `ld -r --build-id`
output, and mortar copied its `.note.gnu.build-id` into the output as
ordinary note content. With `--build-id` the output held two ids, the
input's first (every tool reads the first); with `--build-id=none` or no
option, the input's stale id.

## The rule

`spec/resolve.md` §10, row "name `.note.gnu.build-id`": `Excluded`,
`Dropped(Excluded)`, in every link whatever the line's `--build-id`.
`spec/image.md` I-69 says the output's note is the only one;
`spec/input.md` §2 ("`ld -r` outputs") points at the row.

- References: a local or section symbol of it, referenced from a kept
  section, is §6.3 (a) (`discarded-section-reference`; from a debug name,
  the tombstone), as any dropped section. A non-local symbol defined in
  it is as one in an `SHF_EXCLUDE` section, which §10 does not yet rule
  (gap below). No `ld -r` output defines a symbol in it (only its
  section symbol, never referenced).
- `--gc-sections`: never live, never a root.
- Map: listed under the discarded input sections (`Dropped(Excluded)`;
  `Consumed` kinds are not listed), as GNU ld's map does.
- `--incremental`: classification is a function of the input's bytes;
  `mortar_incr` records nothing by section name.

Code: `crates/mortar_resolve/src/sections.rs`, `classify`, beside
`.note.GNU-stack` (after the `SHF_EXCLUDE` row). No per-arch code.

## Measurements (AArch64 host; GNU ld 2.44, lld 19.1.7, mold 2.37.1)

Inputs: `ld -r --build-id=sha1|md5|uuid|0x0011223344556677`, `ld.lld -r
--build-id`, two `-r` inputs (`sha1` + bare), `ld -r
--package-metadata=...`, `objcopy --add-gnu-debuglink` on an object;
final link by `gcc` with `-Wl,--build-id=sha1` and `-Wl,--build-id=none`.

| input kind | GNU ld | lld | mold | mortar before | mortar after |
|---|---|---|---|---|---|
| `.note.gnu.build-id`, any style, `--build-id` | 1 id, own | 1, own | 1, own | 2, input's first | 1, own |
| the same, `=none` | none | none | none | the input's | none |
| two `-r` inputs, `--build-id` / `=none` | 1 / 0 | 1 / 0 | 1 / 0 | 3 / 2 | 1 / 0 |
| unreferenced, `--gc-sections` | 1 | 1 | 1 | 2 | 1 |
| reference to a local of it from `.data` | error (discarded section) | error | links | links (copied) | `discarded-section-reference` |
| reference from `.debug_*` | links | links | links | links | links (tombstone) |
| global defined in it, referenced | error | error | error (`undefined`, or a crash) | links (copied) | internal error (gap) |
| `.note.package` (`ld -r --package-metadata`) | copied | copied | copied | copied | copied |
| `.gnu_debuglink` on an object | dropped | copied | copied | copied | copied (split, not changed) |
| `.note.gnu.property`, `.note.GNU-stack` (x86-64 `-fcf-protection` `-r` input) | IBT+SHSTK, `PT_GNU_STACK` | same | same | same | same |

`mold -r --build-id` writes no build-id note.

## Tests

- `crates/mortar_resolve/tests/rules.rs` `s10_classification_table`:
  `.note.gnu.build-id` as `SHT_NOTE`+`SHF_ALLOC` and as non-alloc
  `SHT_PROGBITS` are `Excluded`/`Dropped(Excluded)`; `.note.gnu.build-idx`
  stays a kept `Note`.
- `tests/link/layout/input-build-id.test` (three targets, four linkers;
  the `-r` outputs written as the section GNU ld writes, since mortar
  refuses `-r` and the harness has no reference `ld -r` step): exactly
  one id and not the input's with `--build-id`, from one and from two
  inputs, and under `--gc-sections`; none and no section with `=none`
  and with no option; the map lists the input's note as discarded (bfd,
  mortar). Fails on the base (B1 on every target). mold declares A11.

## Gap (not fixed)

A non-local symbol defined in a dropped section that is not a COMDAT
copy (`SHF_EXCLUDE`, and now an input `.note.gnu.build-id`) is not
demoted: referenced from a kept section mortar stops with `internal
error in mortar: relocation R_AARCH64_ABS64: no live target in the
tables` (from data) or `.rela.dyn: a GOT RELATIVE record without a
value` (from PIE code), and under `-E` `.dynsym: bid_g has no value`.
A refusal, not a mislink. Reproducer:

    printf '\t.section .foo,"ae",%%progbits\n\t.globl g\ng:\n\t.quad 1\n\t.data\n\t.quad g\n' > x.s
    as x.s -o x.o; printf 'int main(void){return 0;}\n' > m.c; gcc -c m.c
    gcc -B <dir with ld -> mortar> m.o x.o -o p    # internal error
