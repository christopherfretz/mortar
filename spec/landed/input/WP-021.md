# WP-021 — `mortar_input`: the store, finding, sniffing, the walk, `load`

`crates/mortar_input`, written from `spec/input.md`. Stage A built the
phase up to its own result type (`walk::Loaded`). Stage B (after the one
merge of main, WP-020d) adds the public `load` (§1), which fills
`mortar_core::inputs::Inputs`, and emits every §13 diagnostic as a
`mortar_diag::Kind`.

## What landed

- **`store`** (§11, resident policy). `stat` runs before `open`, so a
  FIFO is never opened. `read_many` reads files in parallel and a file
  over 4 MiB in parallel 4 MiB chunks. It checks `input-changed` (a read
  at offset `n`, then a second `fstat`), deduplicates by
  (device, inode), and computes the content hash while reading. The
  1 TiB and address-space limits are refused by name. The byte API is
  `resident`, `bytes`, `whole` and `copy_to`. `StoreStats` counts the
  system calls, and the `after_fstat` hook drives the change tests.
- **`facts`** (§2, §6, §7.1, §7.3, §8.1).
  - The sniff table, `e_type` rows and header errors.
  - GCC slim LTO is refused with its note.
  - Per object: section, global and COMDAT group counts.
  - Archives through `mortar_elf`'s reader, including thin and GNU
    nested-thin members. A member in member mode applies §7.3.
  - Shared objects through `SharedObject::parse` with section headers
    required: soname, needed list, runpath and rpath, `DF_1_PIE`.
- **`search`** (§4.3-§4.5, §8.6): spelling, the sysroot, candidates,
  labels, target names, colon lists.
- **`walk`** (§3, §4, §5, §7, §9, §10, §8.2-§8.6).
  - It is a sequential walk fed by parallel waves. The walk is pure over
    caches of stats, reads, facts and canonical paths. A missing fact is
    requested and the walk continues speculatively. `Caches::fill`
    answers all requests of a wave in parallel. Only the final pass,
    which needs nothing, is kept. So ids, rows, the link table and the
    diagnostics are a function of the plan, the working directory and
    the bytes (§12).
  - Rows: `files`, `archives`, `LinkTable` (§10.4: groups, sonames,
    closure, opened, probes, script entries, directives, `-R` rpaths).
  - `Problem` carries §13's kind id, severity, exact text and key
    `(unit, k << 40 | offset)` (§12.2).
  - The §8.6 closure is implemented behind `Options { closure: true }`.
    No driver calls it yet.
- **`load`** (§1, §10, stage B). `load(plan, &LoadEnv{cwd, pool}, &store,
  &collector) -> Option<Inputs>`: the walk with the §8.6 closure on, then
  `Inputs` built from its rows. Keys are interned in parallel with
  `mortar_core::intern::number` (`SymbolId` by `(name, version)`,
  `ComdatId` by effective signature, `facts::effective_signature`).
  Shared-object keys follow `spec/resolve.md` §9.2: the default version is
  plain `name`, a hidden version `name@V`, an undefined Needed version
  `name@V`. Paths the tables borrow are kept once in the store's
  append-only arena (`Store::keep`). `link: LinkInputs` carries the link
  table. `None` when any diagnostic is an error. `Inputs::check` rules
  1-10 pass on every test; no conflict was found.
  `dependency_paths(&link)` gives `--dependency-file`'s list (§10.4).
- **Diagnostics** (§13). `Problem` holds a `mortar_diag::Kind`;
  `Problem::diagnostic()` and `Problem::key()` feed `Collector::emit`.
  `tests/s13_diagnostics.rs` checks both for every problem it makes.
- **`examples/input_bench.rs`**: per thread count, in its own process,
  it reports wall time, step timings (`walk::Timing`), `VmHWM`, load
  average and `StoreStats`.

## Evidence

`MORTAR_REQUIRE_TOOLS=1 cargo xtask ci --quick`: `[ci] ok`. In
`crates/mortar_input/tests/`, 123 test functions are named `sN_...` for
§N, plus `hostile.rs` and `differential.rs`.

**Differential against GNU ld 2.44 `--trace`** (`differential.rs`).

Method:
- Each `--trace` line is aligned greedily, in order, with the walk's
  `link.opened`. A line equal to the next opened file is *equal*. A line
  naming a file already printed is a group *rescan*: the walk opens each
  mention once (§10.1). Anything else, on either side, is *different*.
- Spellings are compared byte for byte (§4.5).
- Archives are compared as files: GNU ld prints an archive once, not its
  members.
- The `skipping incompatible` warnings are compared as multisets. Their
  order is checked against the skipped probes (§4.6): the warnings of
  one search share a key (§12.2), so the report orders them by text.
- Every `DT_NEEDED` entry in GNU ld's output must be the soname of one
  of the walk's shared objects (§8.2, §8.3).

| lines | source | trace lines tried | equal | rescans | different | skip warnings equal | `DT_NEEDED` equal |
|---|---|---|---|---|---|---|---|
| 75 | fresh `-###` captures (below) | 1608 | 1333 | 275 | 0 | 12 | 94 |
| 30 | the reviewer's argv (`MORTAR_INPUT_REVIEW_ARGV`) | 650 | 547 | 103 | 0 | 6 | 38 |

Fresh captures:
- Drivers: gcc, g++, gfortran (not on i686: no i686 gfortran), clang
  and clang++.
- Targets: native AArch64, x86-64 cross, i686 cross.
- Modes: dynamic PIE, `-no-pie`, `-static`, `-static-pie`, `-shared`.
- Also, per target, `-nostdlib m.o /dev/null -lc` (no `SEARCH_DIR`;
  `/dev/null` as an empty input).
- On the two cross targets, a multiarch line with
  `-L/usr/lib/aarch64-linux-gnu` first, so the AArch64 libraries are
  skipped.

Reviewer argv: the 30 lines are replayed with the work directory
recreated (`m.o`, `mm.o`, `c.o`, `f.o`, `mpic.o`, `imm.o`, `xmm.o`,
`lib/libz9.a`). `rsp.argv` is not replayed because its response file
is gone.

**Performance** (`cargo run --release -p mortar_input --example
input_bench -- <workload>`). Median of 5 runs; machine load average
27-30 on 24 cores. Inputs are on the workspace bind mount.

| workload | input | threads | median (min) ms | read ms | peak RSS |
|---|---|---|---|---|---|
| `cxx-medium-g` (19 files, 7 archives, 1775 rows) | 200.8 MiB | 1 | 704 (638) | 676 | 204.6 MiB |
| | | 2 | 352 (285) | 336 | 204.7 MiB |
| | | 4 | 219 (197) | 208 | 204.5 MiB |
| | | 8 | 220 (204) | 205 | 204.5 MiB |
| `synthetic-objects` (1013 files, 2605 rows) | 82.0 MiB | 1 | 1444 (1322) | 1425 | 85.9 MiB |
| | | 2 | 769 (745) | 752 | 86.4 MiB |
| | | 4 | 400 (380) | 385 | 87.4 MiB |
| | | 8 | 244 (234) | 223 | 86.3 MiB |

- **Peak RSS** is the input size plus about 4 MiB, as §11.7 predicts.
- **Where the time goes.** Reading is 96-99% of the time.
  - `cxx-medium-g`: sniffing and parsing take 4-5 ms, the walk passes
    2-4 ms, stats 1-2 ms, member hashes 3-20 ms. Past 4 threads it is
    bound by bandwidth: 200.8 MiB in 205 ms is about 1 GB/s from the
    bind mount.
  - `synthetic-objects` scales to 8 threads, because per-file `open`
    latency dominates there (1.4 ms per file at 1 thread).
- **System calls per file read**, all in the order §11.2 gives:
  - one `stat`, before `open`, so that a FIFO or socket is never opened;
  - one `open`;
  - two `fstat`s: one for identity and size against the `stat`, one at
    close for §11.5;
  - one `pread` per 4 MiB chunk, and one `pread` at offset `n` that must
    return 0 (§11.5);
  - one `close`.
  - The walk adds one `stat` per search candidate. `cxx-medium-g` makes
    102 stats for 19 files, mostly `-l` candidates in the driver's `-L`
    directories.
  - `canonicalize` runs for scripts only (§5.3), under 1 ms.

**`load` (stage B)**: the same bench also times the whole `load` (walk,
closure, interning, `Inputs`). Load average 27-32 on 24 cores; reads
from the bind mount were noisy in this run (walk medians at 1-2 threads
varied 2-3× between processes), so only the stable rows compare:

| workload | threads | walk median ms | `load` median ms | keys | peak RSS |
|---|---|---|---|---|---|
| `synthetic-objects` | 4 | 384 | 415 | 204 892 symbols | 134.9 MiB |
| | 8 | 208 | 250 | | 133.5 MiB |
| `cxx-medium-g` | 8 | (noisy) | 443 (min 312) | 44 075 symbols, 22 597 COMDATs | 220.3 MiB |

Interning and building `Inputs` costs about 30-40 ms for 205 k keys at
4-8 threads. RSS grows by the tables: +15 MiB for `cxx-medium-g`, +49 MiB
for `synthetic-objects`.

Proposed changes, with expected gains (not made: beyond the spec):

1. The staged store of §11.1 (b). It would not read debug bodies: 73%
   of `cxx-medium-g`'s bytes [E22]. Expected: read time about 0.3× (205
   to about 60 ms at 8 threads), and peak RSS 147 MB lower.
2. Fold the member hashes into the facts pass, which already touches
   the member bytes. This saves one pass over the archives: 20 ms at 1
   thread (3%), under 2% at 8.
3. Merge the stat wave into the read wave for `Path` inputs, saving one
   barrier: about 1-2%.
4. Drop the `pread` at offset `n` in favour of the second `fstat`
   alone. This needs a spec change to §11.5. It saves one call per file:
   a few percent on many-small-file workloads.

## Decisions taken here (ambiguities in the spec)

- `ProbeOutcome::Found` holds an index into `link.opened`, not a
  `FileId`: a probe can find a script or an archive.
- **The skip rule.** It compares a script's `OUTPUT_FORMAT` against the
  name that is in effect (the third name with `-EL`/`-EB`), not "any of
  its three names" (§4.4).
- **The late script checks** (§3.2):
  - an `OUTPUT_FORMAT` or `OUTPUT_ARCH` naming another known target is
    `incompatible-file`;
  - an unknown name is refused `file-format`;
  - a `TARGET` mismatch is refused `file-format`;
  - the incompatible message uses BFD names.
- **`INCLUDE`.**
  - The entries of an INCLUDEd file resolve relative to that file's own
    directory.
  - `INCLUDE` searches the `SEARCH_DIR`s that precede it.
  - Depth over 10 is refused as `INCLUDE nested more than 10 deep`, a
    name not in §14's list.
- `ENTRY` conflicts are only recorded, in `link.directives`.
- **The closure.**
  - `-R` directories come after the `-rpath` directories in step 2.
  - A soname-less closure file gets its file name as its soname (as
    `-l`, §8.3).
  - A refused `$LIB`/`$PLATFORM` entry is reported once per needing
    file.
  - `--no-allow-shlib-undefined` cannot arise: `mortar_cli` refuses it,
    so the closure for shared outputs is only that of
    `--copy-dt-needed-entries`.
- §8.4's refusal is reported once, at the first shared object.
- **A directory as input.** The message is `cannot open dir: Is a
  directory; file not recognized: file format not recognized`. This
  satisfies the wording policy (GNU ld's whole phrase). The §13 row
  reads `…; file format not recognized`; the two disagree, and the
  policy won.
- **Open failures.** A `-l` or script-entry candidate that is a
  directory or cannot be examined is reported once per file (§9.3), as
  read errors are. The first mention in load order reports it.
- A script in the working directory named relatively probes the working
  directory once, not twice (the script directory is empty).
- A malformed archive reader error is reported, and the members read
  before it are still processed (§10.1). A malformed symbol index
  is now the §7.1 warning (`malformed-input`, severity warning), the
  archive loading as if it had none.

Stage B:

- `LoadEnv` holds a `Pool`, not a thread count: the pool carries the
  scheduling seed the §12 tests vary.
- A probe failure with no OS errno is `Errno(0)` in `ProbeOutcome`.
- `ArchiveKind::Bsd` is never produced: `mortar_elf` reports a regular
  archive, and it becomes `Gnu`.
- The slim-LTO refusal stays in input (§2.2) as the one place;
  `spec/input.md` §2.2 now says so. That and §6's effective signature
  apply `spec/resolve.md` §18's row for `spec/input.md`.
- `version_slots` makes an unknown or ambiguous `.gnu.version` index
  `malformed-input` here rather than leaving it to resolution.
- An `INCLUDE` that cannot be opened uses the `cannot-open-file` kind's
  text (`cannot open linker script file X: …` becomes the kind's
  wording), and `INCLUDE` now records a script entry.
- `Opened` rows of kind "other" and "nested archive" map to
  `OpenedKind::Ignored`.
- `load` always runs the closure; `--allow-shlib-undefined` is honoured
  when choosing closure roots.
