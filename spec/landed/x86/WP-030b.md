# WP-030b: `mortar_x86`, the i386 architecture (stage A)

Branch `wp/030b-x86`, from 4afb6df. Step 0 (the REL interface) is
0987420 and b834262. Stage A, the crate and its tests, was gated at
this record's commit, after merging main 543fd4e (WP-032c). Stage B (the driver, the image side of R-13, end-to-end links)
waits for WP-032c on main. The crate implements `spec/x86.md` for M1:
static and static-pie executables. It is `forbid(unsafe_code)` and has
no third-party dependencies. Every byte that `apply` writes comes from
an x86.md rule.

## Step 0: REL addends in the interface

- `RelocAt.addend: Option<i64>`: `Some(r_addend)` on RELA, `None` on
  REL. `RelocAt::rela_addend()` gives the RELA value to the RELA arches.
- `SectionOut::input(off, dst)`: the input bytes of the clip's section
  (from `with_resident`, the whole section, or `with_margins`, the
  bytes around the clip), for an implicit addend that a clip does not
  hold.
- Mechanical edits in `mortar_a64`, `mortar_x64`, `mortar_scan`
  (`driver.rs`), `mortar_image` (`reloc.rs`) and their tests. RELA
  outputs are unchanged (the gate's test and linktest steps pass).
- arch.md: R-1 (App. B), R-2 (§3.3), R-3 (§3.1), R-13 (§3.3, §3.4,
  §3.6).

## Findings (proposed text where a spec is silent)

Corrections committed to x86.md: §6.3, "named by number (`R_386_<n>`)"
became "(`0x<n>`, diag.md §4.2)".

Proposed changes of meaning (not made):

- **X86-1 (`input-flags`):** diag.md has no such kind. mortar refuses
  with `Refused{Feature, "an i386 input with e_flags other than 0"}`.
  Proposed: "refused by name (class `feature`, the `e_flags` value
  shown)", or add `input-flags` to diag.md §4.
- **X86-12 vs §3.1 (`SIZE32`):** §3.1 says to check after the 32-bit
  reduction, but X86-12's test refuses `Z + A = −1`. mortar checks
  `u(32)` on the integer, as X86-38 does for TP offsets. Proposed for
  §3.1: "except `SIZE32` (X86-12) and the TP offset (X86-38), which are
  checked before the reduction".
- **X86-13 step 1 at scan:** `ScanCx`/`PlaceFacts` carry no
  `SHF_EXECINSTR`, so a `GOT32` in `.data` is refused only at fill
  (`FieldError::Instruction`; an unknown kind gives `GOT_PLACE`).
  Proposed for arch.md §3.4: `PlaceFacts.exec: Option<bool>`.
- **X86-35/X86-37 (A conditions):** T1, L1 and L2 state no condition on
  `A`. mortar requires the lead's A = 0 (and the partner's A as the
  form's: −4 for `PLT32`/`PC32`, 0 for `GOT32`/`GOT32X`), else it
  refuses by name. Proposed: "the lead's `A` is 0" on each form.
- **X86-36 (the note):** the spec asks for `relocation-incompatible`
  with a note. The arch interface has no note on `Incompatible`, so
  mortar refuses as `Refused{Feature}` with x64's names (WP-029b's same
  finding).
- **D2/L2 with rm' = 100:** `call *x(%esp)` puts a SIB where the
  partner's field must start. It is not matched (refused by name).
  Proposed for §9's table: "`ModRM` `10 010 rm'`, rm' ≠ 100".
- **X86-50 (PC16, PC8):** the spec names `PC32` and `GOTOFF` against an
  IFUNC in static-pie. mortar refuses `PC16` and `PC8` the same way,
  with their own names. Proposed: add them to the rule.
- **Relaxed `GOT32X`:** a G1–G5 site still demands its slot. This is
  harmless (an unused slot); a kind-1 decision at scan could drop it.
  No rule change proposed.
- **The brief vs X86-14:** the brief lists `TLS_LE_32` as in scope.
  x86.md refuses it (§6.2, `Later`), and it stays refused.
- **The brief's "PIC `%ebx` form refused per Q9" vs X86-48:** X86-48
  defines the `ff a3` IPLT entry for static-pie. It is implemented.
  Q9's refusal is GOTOFF/PC32 against an IFUNC, as W6/W7 show.
- **`TLS_TO_IE` cannot be reached in M1:** there is no non-local TLS
  kind in a static link. The class table gives `Internal` at scan;
  fill refuses it by name (`relax.rs` `x86_32_gd_to_ie_is_refused`).
- **X86-34 / §15.1 (GNU ld, D3):** GNU ld 2.44 refuses D3 with a base
  other than `%ebx` ("TLS transition from R_386_TLS_GD to
  R_386_TLS_LE_32 … failed"). Proposed: a §15.1 row like L1's.
- **§9 / §15.1 (GNU ld, `PC32` partner in static-pie):** GNU ld
  refuses D1/L1 with a `PC32` partner in static-pie ("relocation
  against `___tls_get_addr` in read-only section"). Proposed: a §15.1
  row. mortar relaxes both, and both run correctly in lld's layout.
- **image.md I-111:** the i386 values (R-3's first half) are image.md's
  and were not edited here.
