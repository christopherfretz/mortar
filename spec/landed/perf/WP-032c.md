## Item (b): the ruling as implemented (spec/image.md I-14, I-16, I-19, I-45)

- Deferred: a live relocated section that is not `SHF_ALLOC`, `Regular`
  or `Debug`, whose dead-target rule is the tombstone, whose relocation
  section is a well-formed `SHT_RELA`, and whose file mentions no key a
  reference to which makes an event (`View::event_keys`: undefined with
  an "undefined" verdict, comdat-mismatch, gnu-warning keys, through
  `redirect`). REL is never deferred (i386 implicit addends stay where
  they are; fill is not precluded from reading them later).
- Demands: `Arch::nonalloc_demand_types` (default empty). x86-64:
  `GOTOFF64` (X-53). AArch64: `GOTREL64`/`GOTREL32` when M2 is enabled
  (they raise the GOT base from non-alloc places), empty at M1. The scan
  visits deferred records of those types only, for demands.
  `tests/deferred.rs` proves the lists complete over types 0..2048 × every
  target kind × TLS × output kind.
- Fill: each record of a deferred section is checked in the clip that
  holds its `r_offset` (the last clip takes `r_offset ≥ b`): key,
  `classify`, `arch.scan` through a checking sink, and the clip's windows
  for overlap. A faulted record is not applied; its section is flagged.
- Reporting: `Walker::deferred_report` walks a flagged section exactly as
  the scan did and keys its diagnostics `(100, file, sec << 32 | rec)`:
  the scan's text, after every scan diagnostic. When the link fails after
  the scan and before fill completes (a phase 80–99 error, a failed job)
  every deferred section is reported; also a deferred section fill never
  reaches. A front failure after the scan reports through a drop guard in
  `front.rs`. Flagged with an empty report is an internal error.
- Dead targets: fill's tombstone branch is `tombstone::field` →
  `mortar_arch::dead` (WP-027e changes its values only).
  `i14_dead_targets_are_the_tombstone_at_fill` checks a COMDAT-dropped
  copy's reference at threads 1/4 and both stores; `--gc-sections` is
  still refused by name, and the test accepts that refusal until it is not.

Changed test expectations: none. Diagnostic order changes only in this
way: a deferred section's fault now sorts after every scan diagnostic
(it was among them by file). With an undefined symbol in u.o and a
fault in d.o, the old order put d.o's fault first; the new order puts the
undefined first (`i14_faults_are_reported_when_the_scan_fails`).

## Interface changes

Made (additive, defaults keep every other implementor unchanged):
`mortar_arch::Arch::nonalloc_demand_types`; `mortar_arch::seq::disjoint_in_order`
(moved from the scan driver); `mortar_core::records::RecIndex::{with_deferred,
is_deferred, deferred}`; `mortar_x64` `nonalloc_demand_types`;
`mortar_image::fill::{Tables::scan_facts, Tables::record_sym, Checked,
write_checked}`, `link::KeyFacts::{facts_at, deferred_report}`,
`plan::Plan::deferred_order`; `mortar_scan::{DEFERRED_PHASE,
Walker::facts_at, Walker::deferred_report, View::event_keys}`; driver
`image.rs` `WalkFacts` delegations and the `front.rs` `Deferred` guard.

Proposed: `SymValue` to carry `sym_type` and `st_other` (or
`Tables::record_sym` to return the `SymFacts` it already has), so that
the deferred check reuses fill's one symbol read instead of `View::facts`
(est. 15–25 ms at 1 thread).

## What remains (ranked by estimated saving, protoc 1 thread)

1. The deferred check's second symbol read: `reloc.rs:742` `check` →
   `LinkTables::scan_facts` → `mortar_scan/src/view.rs:187` (4.4 % of the
   link, ~25 ms): needs the proposal above. 15–25 ms.
2. `reloc::relocate` per-record overhead (`reloc.rs:467`, 8.7 % self):
   decode, pick and `RelocAt` per record; decode resident RELA tables
   in batch. 10–20 ms.
3. `split_target` piece lookups (`link.rs:608` → `refs.rs:181`, 2.8 %),
   cache-miss bound: a per-section last-piece memo. ≤ 10 ms.
4. `LinkTables::sym_value` (`link.rs:506`, 2.6 %) and `RecordKeys::key`
   (`link.rs:661`, 1.7 %): a per-file value table built once, mold's
   shape. 10–15 ms; memory 8 B per live symbol.
5. Scaling past 8 threads (phase 100 is slower at 12): job grain and the
   per-region spawn (WP-032e).
6. `walk_types` (`mortar_scan/src/driver.rs:583`) opens a deferred
   section's contents to scan its demand types; matters on x86-64 and
   M2 only.

## Spec findings

- The ruling said the non-alloc demand list is empty on AArch64; it is
  not at M2 (`GOTREL64`/`GOTREL32` raise the GOT base), so the list is
  `[307, 308]` when M2 is enabled and empty at M1 (the driver's level).
- I-14's old cost premise holds on this input (87 % of records
  non-alloc), and moving them did not make them free: ~25–30 ns per record
  at fill against 52 at the scan.
- An `Undefined` from debug sections only (I-110) stays the scan's by the
  deferral rule (its file is not deferred), with the same text and key.
