# WP-090: AArch64 traditional general-dynamic TLS in static and static-pie links

GCC's traditional-dialect GD sequence (`-fPIC -mtls-dialect=trad`:
`adrp x0, :tlsgd:v` 513, `add x0, x0, :tlsgd_lo12:v` 514, `bl
__tls_get_addr` `CALL26`, `nop`) was refused by name in a static
executable and a static PIE ("unsupported relocation type:
R_AARCH64_TLSGD_ADR_PAGE21": rows 513 and 514 were M2, and both outputs
take the M1 tables, `crates/mortar/src/dynamic.rs`). Found by WP-052
(`spec/landed/dyn/WP-052.md` §5, §8). This package adds R4's static
column (a64.md §8.4).

## 1. What the references write (measured)

GCC 14.2, GNU ld 2.44, lld 19.1.7 and 22, mold 2.37.1, glibc 2.41,
AArch64 host. Objects: `gcc -O1 -fPIC -mtls-dialect=trad`; a global
(`first_g`, the program's first TLS variable), a `static` one (`loc_s`,
which GCC names by its section anchor `.LANCHOR0`), a hidden one (`hid`:
the anchor, then `add x0, x0, #4` after the call) and a later global
(`later_g`); 8 KiB of `.tdata` padding for an offset beyond 12 bits; a
16 MiB `.tbss` object linked after `-lc` for an offset beyond 24 bits
(libc's own `TLSLE_ADD_TPREL_HI12` reaches 16 MiB only, so the padding
must follow libc's TLS); 4 GiB of `.tbss` for one beyond 32 bits. Each
program prints the values it reads and writes. The four words are those
at `o` .. `o+12`.

| case | T | GNU ld `-static` | GNU ld `-static-pie` | lld 19 / 22 | mold (both) | mortar (both) |
|---|---|---|---|---|---|---|
| global, first | 0x1c (0x2020 with the padding) | `d2a00000 f2800380 d53bd041 8b000020` (`f2840400` for 0x2020) | the same | `unknown relocation (513)` | `adrp; add; bl __tls_get_addr; nop` with a GOT pair `1, DTPREL(S)` (read from the image: `0x1, 0xc`) | GNU ld's words |
| local (anchor) | 0x10 | `d2a00000 f2800200 d53bd041 8b000020` | the same | refused | GD kept | the same |
| hidden (anchor + 4) | 0x10 | `d2a00000 f2800200 …` | the same | refused | GD kept | the same |
| later global | 0x18 | `d2a00000 f2800300 …` | the same | refused | GD kept | the same |
| beyond 24 bits | 0x1002090 | `d2a02000 f2841200 d53bd041 8b000020` | the same | refused | GD kept | the same |
| beyond 32 bits | 0x100000068 | `d2a00000 f2800d00 …` = `T[31:0]`, no diagnostic: **wrong** | the same | refused | GD kept, right | `relocation-out-of-range` on 513 and 514 |
| `--no-relax`, `-z now`, `-z norelro` | | unchanged words | unchanged | refused | GD kept | (options not TLS-related) |

Every program that linked ran and printed the expected values (the
4 GiB one ran with GNU ld only by luck: the truncated address lands
inside `huge`). The LE form is the same in every reference that writes
one: `movz x0, #T[31:16], lsl #16; movk x0, #T[15:0]` (a64.md R4), never
an `add tp` pair. No reference writes a wider form beyond 32 bits.

Malformed sequences (`-static` and `-static-pie`, hand-written `.S`):

| case | GNU ld | lld | mold | mortar |
|---|---|---|---|---|
| `mov` instead of the `nop` | relaxed anyway, the `mov` overwritten (`gd 4791744 same 0`): dyn.md W15 | refused | GD kept, runs | `unsupported feature: unrecognized general-dynamic TLS sequence` on the 513 and the 514 |
| `R_AARCH64_NONE` on the `nop` | relaxed, runs | refused | GD kept, runs | `unsupported feature: overlapping relocations` |

The two corpus cases of WP-052 (the review corpus's C and C++ programs,
gcc and g++ `-fPIC -mtls-dialect=trad`, 46 TLSGD records): GNU ld and
mortar link and run all four (`-static`, `-static-pie`) with the same
output; mold runs them keeping GD; lld refuses.

Local-dynamic, traditional (scope item 5): no compiler in the container
emits 517-522. GCC 14 maps `-ftls-model=local-dynamic
-mtls-dialect=trad` to the GD sequence above (and to TLSDESC without
`-mtls-dialect=trad`; g++ and gfortran share the back end); `-mcmodel=tiny`
writes the same small sequence. Clang 19 and 22 reject `-mtls-dialect`
on AArch64 and write TLSDESC (LD through `_TLS_MODULE_BASE_`). The
refusal of 517-522 stays (rows `later`).

## 2. The rule (a64.md §8.4, "The static column")

In an output of the static tables (a static executable; a static PIE,
`spec/dyn.md` D-2), 513 and 514 are accepted only inside R4's pattern:

- pattern holds: R4's LE words, `T = TPREL(S)` (0 for a thread-local
  `weak0`), checked `u(32)` on each rewritten member; beyond it,
  `relocation-out-of-range`. No wider form (none of the references has
  one).
- pattern fails: each 513 and 514 is refused at scan, `refused`, feature
  `unrecognized general-dynamic TLS sequence` (x64.md X-26's name); the
  `CALL26` is then an ordinary call. Never applied half: every member
  evaluates the pattern from the lead.
- a record overlapping the window: arch.md §3.4's overlap check.

The rule is kind 1 (input-only: the section's bytes and records, the
target kind, the call's name) and adds nothing to the dependency index
(arch.md §9). Dynamic executables are unchanged (R4's IE form, and the
module/offset pair without the pattern, D-48).

## 3. Code

- `crates/mortar_a64/src/table.rs`: rows 513 and 514 `M1` (were `M2`).
- `crates/mortar_a64/src/apply.rs`: `scan` takes `m2` (as x86-64's
  does); under the static tables a `TlsGd` member whose `gd_lead` fails
  is refused with `UNRECOGNIZED_GD` (exported from `mortar_a64`).
  `apply` is unchanged: R4's LE path already served every exec output.
- `crates/mortar_a64/src/lib.rs`: `A64::scan` passes
  `self.enables(Status::M2)`.

No byte of a link that linked before changes: every such link has no
513/514 (they were refused), and nothing else reads the rows' status.

## 4. Tests

- `crates/mortar_a64/tests/relax.rs` `s8_4_r4_static_tables`: `A64::M1`
  in `Static` and `Pie`: the LE words (local and `weak0`), no demand, no
  reference to `__tls_get_addr`; `T` beyond 32 bits out of range on both
  members; every pattern failure (another callee, no `nop`, past the
  end, a lone 514, a 513 without its 514) refused by name, no `TLS_GD`;
  the dynamic tables keep the pair for the same inputs.
- `crates/mortar_a64/tests/a64.rs`: the status counts (63 M1, 39 M2) and
  the census (all 34 M1).
- `crates/mortar_scan/tests/rules.rs` `i19_…`: the static tables link the
  matched sequence and refuse the unmatched one (two `refused` and the
  `undefined-symbol` of the now ordinary call).
- `tests/link/tls/gd-trad-static.test`: §1's first five rows, `-static`
  and `-static-pie`: bfd, mold and mortar link and run; the four words of
  each sequence against GNU ld's (bfd and mortar); mold's kept call; lld
  refuses.
- `tests/link/tls/gd-trad-static-refused.test`: the `nop` missing, the
  overlapping record, and `T` beyond 32 bits, refused by name in both
  outputs; bfd `xfail` (W15), mold links and runs.
- `tests/link/tls/gd-trad-corpus.test`: WP-052's two corpus cases by
  name, both outputs.

The verifier (L3) judges every link of the three tests: mortar's
outputs, `-static` and `-static-pie`, have no finding. GNU ld's
static-pie outputs carry A30 (plumb.md §10.2, glibc's absolute
`_nl_current_*_used` GOT slot; not TLS), declared `#@ anomaly(bfd): A30`
in `gd-trad-static.test` and `gd-trad-corpus.test`; its W15 output (the
`mov` overwritten) has R1 findings, the test's `xfail(bfd)`. The
verifier thus checks R4's static rewriting (plumb.md W12): no interface
request.

static-identical: no link that linked before changed (0 differ on the
AArch64 host's baseline); the three tests add 12 links (4 corpus, 6
refused, 2 static), on aarch64, to both hosts' baselines. They are the
corpus's first static-pie links outside `tests/link/dyn`: a static-pie's
map records the command line (plumb.md `arg`), where gcc's linker-plugin
option names a new `/tmp/ccXXXXXX.res` on every run, so the successful
static-pie links pass `-fno-use-linker-plugin` (no input is LTO) to keep
their map digest reproducible. The harness does not normalize that word
(spec/harness.md "static-identical").

`mortar_a64` has no byte-differential of R4 against the references
(`differential.rs` compares single relocations on the references' images
with `--no-relax`; its `r4_object` checks R4's pattern and windows over
the inputs, the trad object included). The link tests compare R4's words
with GNU ld's instead.
