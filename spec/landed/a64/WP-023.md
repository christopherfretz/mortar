# WP-023 — `mortar_arch` and `mortar_a64`

`mortar_arch` is the trait and vocabulary of `spec/arch.md`. `mortar_a64`
is its AArch64 instance (`spec/a64.md`). Stage A is the pure functions
and the writers; stage B is `scan` in full, the relaxations of §8,
IRELATIVE, static TLS, the need functions and the diagnostics.

## Deviations from `spec/arch.md`

All are now reflected in arch.md §3, §3.4, §3.5 and §3.7 on this branch.

- **§3.7 `erratum_sites`** takes `&Code` (bytes, address, proof runs)
  and returns `Result<(), Unproved>`. The spec's signature has no way to
  give the proof, or to report the condition-5 refusal.
- **§3.7** has no writer for the ADR fix or for the `b patch` at `F`. They
  are the free functions `mortar_a64::erratum_adr` and `erratum_branch`.
- **§3.5** `ScanError::Internal` was added, for a class outcome the table
  calls impossible.
- **§3.5** `field_window` gives a marker (`Field::None`) the window the
  howto names, so that a TLSDESC_CALL overlapping another field is
  caught.
- **§3.6** `Records` is implemented for `&[Reloc]` and `Vec<Reloc>`.
- **§3.4, §3.6 (stage B)** `RelocAt` has `proof: &[ProofRun]`, the
  instruction proof of the input section (R4's `o+12`, rule 1), and
  `RelocAt::is_insn`.
- **§3.4, §3.6** `SymNames` (`name(SymKey)`) is a supertrait of both
  `ScanTables` and `FillTables`: R4's pattern names `__tls_get_addr` in
  scan and in fill.
- **§3** three trait methods: `unit_window(output, at, names)` (the unit
  and window §3.4's overlap check needs; default the field window),
  `consumed(output, at, names)` (§3.4, §6 step 1; default false) and
  `patch_reach(e)` (the reach of `b patch` and `b F + 4`, §6 step 1).
- **§3.4** `DemandOut::undefined(SymKey, record)` replaces the
  `undefined-symbol` error; `ScanError::Undefined` is gone. arch.md §3.4
  is amended on this branch (one diagnostic per key, keyed by the first
  reference).
- **§7** `mortar_arch::diag` replaces `error::text`: `scan`, `fill`,
  `chunk` give `(Key, Diagnostic)` with `mortar_diag`'s kinds; an
  `i128` range bound beyond `i64` saturates in `Kind`'s `i64` fields.

## Decisions and readings of `spec/a64.md`

- **§3.1:** values are computed in wrapping `i64` arithmetic, not
  mathematical integers. Every check is at most 48 bits wide (s(33) for
  ADRP), and the inputs are 64-bit addresses and addends, so a wrapped
  value never passes a check that the mathematical value would fail.
  The exception is `Unchecked` 64-bit data, where the two are equal mod
  2^64.
- **§3.2:** the `mov/k` masks admit `opc = 01`, which is unallocated.
  `requires` does not reject it, because AAELF64 lets a MOVW_*_NC
  relocation sit on any MOVZ/MOVN/MOVK.
- **§5 `tls_local`** is `local`, `abs` or `weak0` (§7 as amended). Scan
  passes `local` to the class table for a TLS class against `weak0`, so
  `TE` and `TD` demand nothing and the TLS cells give TLS-local demands.
- **§6.1 status gating:** `classify` refuses a row whose status is above
  `A64.max`. `A64::M1` is the shipped value, and tests use `M2`.
- **§8 rule gating:** R3 and R5 have status M2 on M1 types, so `apply`
  takes them only when `A64.max` is M2 (§8.3: "Before M2, IE is applied
  unrelaxed"; R5 by the same reading). R1 always; R2 and R4 are reachable
  only through M2 types or dynamic outputs. The verifier must read the
  same gate.
- **§8.4 "the records at `[o, o+16)` are exactly the sequence's"**
  (amended): the pattern reads only records `i..i+2`; any other record
  whose window meets `[o, o+16)` overlaps the matched unit (whose
  windows tile `[o, o+16)`) and §3.4 refuses it. The neighbour check of
  the first handback (which left GD unrelaxed) is gone. A marker's
  window is its word (`table.rs` gives `Field::None` 4 bytes after), so
  even `R_AARCH64_NONE` at `o+12` is refused. Over the inputs (below)
  no record meets an R4 window.
- **§8.5 condition 2** is `TargetKind::Local` exactly (`Abs`, `Ifunc`,
  `Weak0`, dynamic kinds are excluded by being other kinds).

### (i) Differential against GNU ld 2.44, lld 22 and mold 2.37.1

The corpus:

- C compiled by GCC 14 and clang 22 at `-O2 -g`, `-O0`, `-fPIC`,
  `-mcmodel=large`, `-mcmodel=tiny` (with and without `-fPIC`) and
  `-fpic`;
- C++ (iostream, exceptions, `thread_local`) compiled by g++ and clang++;
- Fortran compiled by gfortran;

### (iii) R3 and R4 on the input objects

Every corpus object (both compilers or assemblers), a `-mtls-dialect=trad`
GCC build of the C source, and every member of `libc.a`, `libm.a`,
`libstdc++.a`, `libgfortran.a`, `libgcc.a` and `libgcc_eh.a` (3424
members; a superset of what the links pull in). For each IE pair, scan
raises the inhibitors over the object, apply rewrites each record on its
own (M2), and the result is decoded: the `adrp`'s word must become `movz
x<Rd>, #T[31:16], lsl #16`, the `ldr`'s `movk x<Rt>, #T[15:0]`, the
pair's `adrp` (same symbol, `Rd = Rn`) must write the `ldr`'s `Rn`, and
`Rt = Rn`, so `x<Rt>` = `TPREL(S)`, recomputed from §12.2's formula, not
mortar's. A symbol with `TLSIE_NORELAX` must keep both words IE.

| relaxed and correct | kept IE | of them `Rt ≠ Rn` | unpaired | failures |
|---|---|---|---|---|
| 1508 | 4 | 2 | 0 | 0 |

The kept ones are the `asm-ie-regs` unit's (`tv2`): no compiler output
has `Rt ≠ Rn`. The `S` values are synthetic (spread over a 512 KiB
template), since an object has no addresses. Not covered: the use of
`x<Rt>` after the pair (unchanged words), and R5, whose relaxed form
only mold writes (as `relaxed` 23 in 311).

R4 over the same objects: 4 patterns (the `trad` build), 0 records
meeting a window.

### (ii) 843419 against GNU ld 2.44 and lld 22

The input is 640 generated sequences, one per page. The sequences vary:

- the start offset: FF8, FFC, or the non-site offsets FF4 and 000;
- the form: 3 or 4 words;
- the second word: 12 load/store groups and 2 words outside them;
- the third word: 5 kinds;
- the final word: 9 kinds, 6 of them sites;
- data: 162 sequences have one or all words written as `.word`, which
  gives them `$d`.

Each linker linked the input with and without the fix, and the fixed
sites were read off the difference. mortar ran over the unfixed image,
with the proof from the image's mapping symbols.

| reference | fixed by it | mortar sites | missed by mortar | mortar only |
|---|---|---|---|---|
| GNU ld | 177 (134 patches, 43 ADR) | 214 | 0 | 37 |
| lld | 147 (147 patches) | 214 | 0 | 67 |

No mortar site has a word in a `$d` range, and neither reference fixed
one.

### Performance

`cargo run --release -p mortar_a64 --example apply_bench`, on one thread:

- stage A: 2^20 relocations with a static-C++ mix, **59.6 M
  relocations/s**; 2^22, **57.2 M/s** (load 29.4 on 24 CPUs);
- stage B: 2^20, **52 to 55 M/s** (load 26 on 24 CPUs). The difference is
  R4's test on every `CALL26` in an exec output; it reads the `nop` after
  the call first, which every ordinary call fails.
- With the `CALL26` test removed the same run gave about 57 M/s, so a
  per-section bit "has a 513 record", set at scan, would recover nearly
  all of it: no default build has one (0 in 3424 library members), so
  `apply` would skip `gd_lead` for every `CALL26`. It needs a field the
  trait does not have (in `RelocAt` or the section context), so it is
  left as a follow-up; the rest of the gap to 59.6 is within the load
  noise of these runs.

`apply` does not allocate and has no loops. Its branches are the
dispatch on class and form, and the error paths.

## Spec errors found, and the amendments made on this branch

Each is now a change to `spec/a64.md` or `spec/arch.md`, with its
evidence.

1. **a64 §7, thread-local `weak0` (an M1 blocker).** It was "TLS classes:
   `E`", but static glibc's `uselocale.o` and `setlocale.o` reference the
   undefined weak `STT_TLS` symbols `_nl_current_LC_<cat>` (24 IE pairs
   each), so every static C and C++ link was refused.
   - Experiment: every form against an undefined weak TLS symbol, in
     `-static` and non-PIE dynamic links, by GNU ld 2.44, lld 22 and
     mold 2.37.1. The references agree on no single value:
     - lld: `TPREL = A` everywhere. It relaxes IE → LE even with
       `--no-relax`. In a dynamic link it writes slot 0 plus
       `TLS_TPREL64`.
     - GNU ld: the IE slot holds `0 − tls.start + TCB_ALIGNED`. LE gets
       0, with the addend dropped. GD is kept as `1, 0 − tls.start`.
       TLSDESC goes to IE, and ld crashes (SIGSEGV) on one input.
     - mold: the formula with `S = 0` everywhere, and it refuses
       `HI12`/`LO12` as out of range.
   - glibc: every such access is behind `cbz` on the GOT-loaded weak
     `_nl_current_LC_<cat>_used`, so the value is never used and the
     link only has to succeed.
   - Amended: §7 (the value rule `TPREL(S + A) = DTPREL(S + A) = A`, TLS-local, every form, the `TLSIE_NORELAX` interplay, the experiment table), §5 `TD`/`TE`, §8 common terms, §10.1's `weak0` column, §12.2, §12.5, §14 (three rows).
   - Code: the `WEAK_TLS` refusal is removed; `tls_off` and `tls_local` are added.
2. **a64 §14, mold's TLSDESC in a static link** is LE (`nop; nop; movz;
   movk`), not IE. The row is amended.
3. **a64 §14, mold's ADRP against `weak0`** addresses page 0. A row is
   added.
4. **a64 §6.1, 570/571** are now "M1 (implemented, untested: no producer
   known)". The code and the rule stay.
5. **arch §3.7, the erratum signatures** are now as implemented:
   `erratum_sites(e, &Code, &mut Vec<ErratumSite>) -> Result<(),
   Unproved>`, and `patch_reach(e)`. The text now says what each means.
6. **arch §6 step 3**: a patch created in round `k` has no address at
   `A_k`. Its reach is judged from round `k + 1`. Within the step, a need
   reuses a thunk of its key that the step has already put in the
   policy's island. This is what the reference driver does.
7. **a64 §11.2**: the patch window is
   `[F − 2^27 + 4, F + 2^27 − 4]`, derived from the two `s(28)` branches.
8. **a64 §8.4**: the records at `[o, o+16)` are exactly the sequence's,
   and any other record overlapping the window is refused (overlap), not
   relaxed. This was checked against the inputs, where 0 records meet a
