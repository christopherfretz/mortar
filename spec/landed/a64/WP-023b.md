# WP-023b — amendments to `mortar_arch` and `mortar_a64`

This package applies the requests that the later specs make of
`spec/arch.md` and `spec/a64.md`. Those requests are `spec/image.md` §17
(R-1, R-2, R-3, R-5), `spec/layout.md` §20.5 and `spec/synth.md` §14.3
and §14.4. It also takes WP-024's hand-back and WP-023's follow-ups.

Each request is applied to the specs and to the code, and each is marked
applied in its own spec with one line. The trait changes landed first,
in commit `b1546c2`.

## Changed public interface (before → after)

`mortar_arch`:

| item | before | after |
|---|---|---|
| `DemandOut` | `fn undefined(&mut self, key: SymKey, record: u32)` | `fn reference(&mut self, record: u32, class: EventClass, key: SymKey)` |
| `DemandSink` | `pub fn undefined(&mut self, key: SymKey, record: u32)` | `pub fn reference(&mut self, record: u32, class: EventClass, key: SymKey)` |
| `EventClass` | — | `pub enum EventClass { Undefined, ComdatMismatch, DiscardedSection, GnuWarning }` (Ord) |
| `ScanCx` | — | `+ pub name: &'a [u8]`, the name of the place section |
| `SymFacts` | — | `+ pub dead: bool, pub comdat_only: bool, pub gnu_warning: bool` |
| `RelocAt` | — | `+ pub leads: bool` |
| `SectionOut` | `pub bytes: &'a mut [u8]` (whole section) | `bytes` is private; `+ start` (private); `pub fn new(bytes, start, addr, alloc, name)`, `pub fn whole(bytes, addr, alloc, name)`, `pub fn clip(&self) -> (u64, u64)`, `pub fn write(&mut self, off: u64, data: &[u8])` |
| `Facts` | — | `+ pub max_reach: Window, pub code_fill: &'static [u8], pub code_nop: &'static [u8], pub seq_leads: &'static [u32]` |
| `max_window` | — | `pub const fn max_window(a: Window, b: Window) -> Window` |
| `PropMerge` | `And, Or` | `And, Or, OrAll, EqualOrAbsent` |
| `Arch::sequence_extent` | — | `fn sequence_extent(&self, records: &dyn Records, i: u32) -> u32` (default 1) |
| `Arch::patch` | — | `fn patch(&self, e: Erratum) -> Option<&'static ThunkShape>` (required) |
| `Arch::tombstone` | required | the same signature, with a default body: `tombstone(name, self.facts().class)` |
| free `tombstone` | `pub fn tombstone(section_name: &[u8]) -> u64` | `pub fn tombstone(section_name: &[u8], class: Class) -> u64`, in the new `mortar_arch::dead` |
| `dead` | — | `pub enum DeadRef { Tombstone, Zero, Discarded }`, `pub fn dead_reference(name: &[u8], alloc: bool) -> DeadRef`, `pub fn is_debug_name(name: &[u8]) -> bool` |
| `diag` | — | `pub fn unproved(e: Erratum) -> Diagnostic`, `pub fn unproved_key(chunk: ChunkId) -> Key` |

`mortar_a64`:

- New: `MAX_TYPE` (0x800), `MAX_REACH: Window` (computed), `FEATURE_PAUTH`, `erratum::PATCH`.
- New in `relax`: `R4_CALL_AFTER`, `MEMBER_WINDOWS`, `SEQ_LEADS` and `fn sequence_extent(records: &dyn Records, i: u32) -> u32`.
- The `A64::tombstone` override is removed; the trait's default is used.

`mortar_layout` (`fixed.rs`):

- `erratum_patch_shape` is removed; `patch_shape` calls `arch.patch(e)`.
- `unproved_refusal()` becomes `unproved_refusal(e, at)`.

## Per amendment

**image R-1 (events).**
- Scan reports `reference(record, class, key)` for each reference that survives:
  - `GnuWarning`, when the target section is a `.gnu.warning.*`;
  - `DiscardedSection`, when the target is dead and the referring section is `Discarded` by resolve §6.3's table (in that case scan raises no demand);
  - `ComdatMismatch` or `Undefined`, for an undefined target.
- A record that a sequence consumes reports nothing.
- **Deviation.** The request asks for `group: u64`; the signature carries `SymKey` instead. `SymKey` has no public raw accessor, and the driver forms the group from the record and the key. arch.md §3.4 says this.
- Evidence:
  - a64 `s3_4_reference_events`;
  - `s13_2_non_alloc_and_tombstones`, the dead-target events;
  - relax `s8_4_r4_gd_to_le`: a consumed `CALL26` makes no event, even with `gnu_warning`.

**image R-2 (clipped output, `max_reach`).**
- `SectionOut` is a clip. Every write goes through `write`, which discards the part outside the clip. `apply` never reads the output.
- `max_reach` is derived mechanically, with no hand-written value. It is computed in `const` over `table::howto(0..=MAX_TYPE)` and `relax::MEMBER_WINDOWS`, and comes out at (0, 4).
- `unit_window` for R4's `CALL26` uses the same constant.
- Evidence (`tests/clip.rs`, new):
  - **`s3_6_clip_every_type`:**
    - covers 102 accepted types × 28 input words × 4 targets × 3 output kinds, which is 5964 applied cases;
    - each case is checked at every clip `[a, b)` of a 24-byte section, 325 pairs. The bytes inside each clip equal the unclipped bytes, and so does the error;
    - writes are detected with fills of 0x00 and 0xFF, which is valid because `apply` never reads the output;
    - no record writes outside `max_reach` around its field, nor outside its `unit_window`.
  - **`s3_6_clip_sequences_and_erratum`:** the same checks over:
    - R1, R1 tiny, R2, R2 tiny and R3;
    - R4 to LE and to IE;
    - R5;
    - TLSDESC kept in a shared output;
    - the erratum fixes written through `SectionOut::write` after the relocations: the ADR over W1, and `b patch` at F.
  - **`s3_1_max_reach_derived`:** the maximum is taken again over `classify` for 0..=0xFFFF.
  - **arch `s3_6_section_out_clip`:** `write` checked exhaustively over writes × clips.

**image R-3 (`sequence_extent`).**
- The default returns 1.
- AArch64 returns 3 at a 513 followed by a 514 and a `CALL26`, and 2 at a 311 followed by a 312. It reads the types only.
- Evidence: `s3_5_sequence_extent`. It also checks that each GD member's unit lies inside its lead's extent.

**image R-5 (tombstones).**
- `tombstone(name, class)`:
  - `.debug_ranges` and `.debug_loc` give 1;
  - `.debug_aranges` and `.debug_frame` give all ones;
  - any other name gives all ones in ELFCLASS64 and 0 in ELFCLASS32.
- The referring section decides by `dead_reference`: a non-alloc debug name gets the tombstone, `.gcc_except_table` gets 0, and anything else is `Discarded`.
- **Decision.** The arch only gives the values. The image phase owns the rewrite of the length field in `.debug_aranges` (I-112). arch.md §3.11 and a64.md §13.2 both say so.
- Evidence: arch `s3_11_tombstone`, `s3_4_dead_reference_by_referring_section`; a64 `s13_2_non_alloc_and_tombstones`.

**layout §20.5.**
- `code_fill` is `[0; 4]` (UDF) and `code_nop` is NOP, in `Facts`.
- arch §6 has the M2 bullet: the state is (patch set, sizes), with the sizes only growing (L-21, L-121).
- The x86 `got_plt_reserved` doc covers static outputs.
- a64.md §11.1 item 2 has the L-118 margin: "at most 16 bytes" holds for alignments ≤ 16.
- Evidence: a64 `s13_3_facts_dyn_types_properties`.

**WP-024: `Arch::patch`.**
- `A64::patch(E843419)` is `&PATCH`, 8 bytes aligned to 4.
- `fixed.rs` `patch_shape` uses it.
- Evidence: `s13_3`, and the mortar_layout tests stay green.

**WP-024: the unproved refusal.**
- `diag::unproved(e)` is class `feature`, with the note naming `--no-fix-cortex-a53-843419`.
- `fixed.rs:43` uses it. It adds a note with the input section and the offset of W1, which comes from `key_at` of `Unproved.q`.
- **Not done in full.** `LayoutDiag` carries no `FileRef` and no `Key`. So the refusal does not carry a64.md's place, and it does not carry the key `diag::unproved_key(chunk)` = (90, 0, chunk). Layout must add both.

**WP-024: an erratum site with F in a synthetic chunk.**
- Specified as proved unreachable, in arch.md §3.7 and a64.md §11.1 "Sites and synthetic chunks": no site has a word in a synthetic chunk.
- `fixed.rs:400` keeps an internal error with a clearer text.

**WP-023 follow-up: the `leads` bit.**
- `RelocAt.leads` is `false` only when no record of the relocation section has a type in `Facts.seq_leads`, which is 513 on AArch64. `gd_lead` returns `None` at once when the bit is `false`, so a `CALL26` skips the R4 pattern test.
- The driver computes the bit; scan passes `true`.
- Evidence: in the clip tests, `leads = false` gives the same bytes for every case without a 513.

**WP-023 follow-up: R5's relaxed form from the input objects.**
- `r5_object` runs inside `s8_3_r3_from_the_inputs`, over the corpus objects and the members of libc.a, libm.a, libstdc++.a, libgfortran.a, libgcc.a and libgcc_eh.a.
- Each record is decoded:
  - a relaxed 312 is `add xR, xR`, paired with its 311 `adrp xR` at o − 4, and the two compute `S`;
  - a kept record computes `G`;
  - a record is relaxed exactly when its target is local, has no `GOT_NORELAX` and is in range.
- Result: 8121 relaxed; kept for `GOT_NORELAX` 17, not local 159, out of range 1384; 0 bad.

**WP-023 follow-up: `movz`/`movk` pairing in the differential.**
- `compare` pairs each relaxed R3 record of a reference with the other half of its pair: same symbol, same register.
- The only records that do not pair are the 4 per linker of `asm-ie-regs`. There GNU ld and lld write `movz x2`/`movk x3`, the wrong code that a64.md §15 records. These are counted as `r3_rt_ne_rn`; any other unpaired record is a mismatch.

**synth R-A1 (property merge rules).**
- `PropMerge` gains `OrAll` and `EqualOrAbsent`.
- AArch64: `FEATURE_1_AND` is `And`, `FEATURE_PAUTH` (0xc0000001) is `EqualOrAbsent`, and every other type is `None`. S-95 drops a `None` type with the warning `unknown-property`.
- arch.md §3.13 and a64.md §13.3 have the new text, and Q13 is answered.
- `Max` was not added: R-A1's proposed text has no `Max` rule, and the generic types are S-95's.

**synth R-A2.** Spec text only: the `got_plt_reserved` doc comment.

**synth R-A64-1.** a64.md §13.1: personality `0x9b` (sdata4, `PREL32`) and `0x9c` (sdata8, `PREL64`). Both occur.

**synth R-A64-2.** Q9 is answered: `.plt`, `.rela.plt` and `.got.plt` (synth S-68).

## Bench (`examples/apply_bench`, one thread, best of 20)

See the table at the end of this file. The R4 pattern test is skipped
when `leads` is `false`. With `MORTAR_BENCH_LEADS=1`, `leads` is forced
to `true`, which is the case of a section that holds a 513.

The first version of the clipped writes was slower, at 48.8 M/s against
52.7 M/s. The cause was that `apply::put` was not inlined, so each write
called `memcpy`. With `#[inline]` on `put`, `put_word`,
`SectionOut::write` and `SectionOut::clip`, the rate is back above
WP-023's.
