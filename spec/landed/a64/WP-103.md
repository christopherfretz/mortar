# WP-103: every erratum 843419 site gets its fix, and every lane tells the verifier the option

WP-100's real builds found RB-2: abseil's `absl_log_structured_test`
(gcc row) linked by mortar with `--fix-cortex-a53-843419` kept an
erratum 843419 site unfixed, GCC's `adrp x0, :got:__libc_single_threaded;
ldr x0, [x0, :got_lo12:...]; ldrb w0, [x0]` at page offset 0xFFC. On a
Cortex-A53 that load can read the wrong address. No lane had seen it,
because no lane told the verifier the option: every call passed
`fix_843419: None`, and the verifier then infers the option from the
fixes it finds, so an output whose only sites are unfixed has them
counted as not judged (`spec/plumb.md` §5.10 item 4).

## 1. The cause (checked on the bytes)

The erratum scan (`crates/mortar/src/sites.rs`, since 393c759) computes
each round's words with fill's `apply`, over tables of the round's
addresses. A target the round has no address for (`Def::Common`,
`Def::Internal`: a symbol the link defines; `Def::Shared`: a shared
symbol) was given a stand-in address and the record was marked
"forced". `apply` reads the symbol's value for every record, the GOT
page of 311 included, which does not use it. Every forced word that was
an ADRP was then rewritten "out of the ADR's reach" with

```
let far = (w & !0x60FF_FFE0) | (0x8_0000 << 5);
```

which sets bit 24, not immhi's top bit (23): `0xd0000080` became
`0x91000000`, an ADD. The predicate (a64.md §11.1 condition 1) no longer
saw an ADRP, so the site was dropped in every round and in the final
scan, and fill's ADRP was left as it was. Instrumented on the RB-2
reproduction: the record at `0x12ffc` (type 311) was forced, its word
`d0000080`; the sites of the round were only `(0x13ff8, ...)`, the
direct one.

Two more defects of the same scan, found while fixing it:

- Its `FillCx.output` was `OutputKind::Static` for every link, where fill
  uses the link's kind (`front::output_kind`). The §8 relaxations depend
  on it (R2 in a PIE, R3 and R5 in dynamic outputs), so the scan's words
  could differ from fill's.
- A section symbol of a merge section with an addend (GAS's `.L` labels
  in `.rodata.str1.1` are `section + offset`) was valued as the piece at
  `st_value` plus `A`; fill takes the piece at `st_value + A`
  (`spec/synth.md` S-17). The ADR is computed from the scan's `W1`, so
  mortar wrote an ADR to the wrong page: `reloc/erratum-843419-direct-merged.test`
  on the unfixed linker writes `adr x0, 0x415000` where fill's ADRP is
  0x413000, the program prints `wrong: 0x415980 0x415980, want 0x413980`,
  and the verifier finds R1. This one is a wrong address, not a missed
  fix.

A third, practically harmless: the stand-in address also fed R5's range
check (`page_delta`); R5 is an M2 rule, so only dynamic outputs read it.

All three are local to the erratum scan: `sites.rs` feeds only the
erratum's words (`Sites::code`) and the final fixes; the branch targets
(`Sites::targets`) use the round's values and fail on an unknown one.

## 2. Shapes affected and not

Affected (the site dropped, the ADRP left), every output kind:

| `W1` | target | unfixed linker | fixed |
|---|---|---|---|
| 311 GOT page | a shared library's symbol (RB-2) | ADRP | ADR to the slot's page (as GNU ld) |
| 541 TLS IE page | a shared library's TLS symbol | ADRP | ADR |
| 562 TLSDESC page (R2 to IE in an executable) | a shared library's TLS symbol | ADRP | ADR |
| 275 direct page | a common symbol | ADRP | patch |
| 275 direct page | a linker-defined symbol (`__bss_start`) | ADRP | patch |
| 275 direct page | a merge section's section symbol plus addend | **ADR to the wrong page** | ADR to fill's page |

Not affected (fixed before and after): a direct page of a defined symbol;
an absolute symbol (patch: out of reach); a GOT page of a local, a weak
undefined, an IFUNC; IE and TLSDESC of the program's own TLS (relaxed to
LE in an executable, so no site; mortar's static and static-pie outputs
keep IE, R3 being an M2 rule, and their sites get the ADR).

Not covered: a TLSGD page (513) with a load as `W2` (no compiler emits one:
the GD sequence is ADRP, ADD, BL); a `shared` output (mortar refuses
`-shared`, M4).

## 3. The fix

- **A dependent word.** For a record whose target has no address at the
  round, the scan applies the record twice, with two stand-ins
  `ALT = 0x1010` apart, and marks as dependent the words that differ.
  A word that does not use the address (the GOT page: `V` is the slot,
  which the round knows) is an ordinary word.
- **A dependent ADRP stays an ADRP**: `far_adrp(w) = (w & !0x60FF_FFE0) |
  (0x4_0000 << 5)`, the page `Page(Q) − 2^32`, out of every ADR's reach,
  so the round gives the site a patch (a64.md §11.2). A unit test checks
  that it is an ADRP of the same register at `−2^32` for four words.
- **The final scan is exact.** `LinkSites::erratum_fixes` takes the final
  `Placement`: a common's address (`AllocKey::Common`), a linker-defined
  symbol's (`Placement::defined_of`), a shared symbol's copy
  (`AllocKey::Copy`). A site whose `W1` or `F` still depends on an
  unknown address is an internal error, never a guess.
- **The link's output kind** in the scan's `FillCx` (`SiteInputs.output`,
  from `front::output_kind`).
- **Merge-section section symbols**: the piece at `st_value + A`
  (`RoundTables::split_value`).
- **A guard in fill.** Each fix carries the word it was computed from
  (`mortar_image::fill::Fixup`: the ADR's `W1`, the `b patch`'s `F`);
  fill compares it with the word it writes there and refuses the link
  with an internal error naming both words when they differ.
- Two sites with one `W1` (the 3- and the 4-word form at one `Q`) give
  one ADR: the fixes are deduplicated (the guard found this on
  `odr/mt32-keep-meta.test`, where the old code wrote the same ADR twice;
  the output is byte-identical to the unfixed linker's).

**Termination.** Whether a word is dependent is a function of its
record's target (a common, a linker-defined, a shared symbol), not of
the round's addresses; a dependent `W1` gives its site a redirect in the
round it is found, and patches are only added (§11.2 "Who decides"). So
the redirects grow monotonically, bounded by the number of sites, and
the fixed point ends as before. A common or linker-defined target thus
always takes a patch where GNU ld may write an ADR: correct, and a few
bytes larger.

`erratum-843419-off.test` is the negative: a bare `ld` line, and GCC's
`-mno-fix-cortex-a53-843419`, which drops the option Debian's driver
passes. **`--no-fix-cortex-a53-843419` cannot be tested**: GNU ld 2.44,
lld 19 and mold refuse it as unknown, and so does mortar (no row in
`mortar_cli`'s table). Note that mortar's refusal "erratum 843419 scan
without mapping symbols" (a64.md §11.1, `mortar_arch::diag`) names that
option as the way out; it is one mortar does not accept (a request,
not fixed here).

Every reference passes every test (bfd's A30 in a static PIE and
lld's and mold's A20 in got-ifunc's `-z now` PIE declared). mold's A4 is
a run-wide default on AArch64: it is on every mold output with a site and
the option, and the matrix gives it one in every run, so the default is
never stale.

**The hosted lanes.** The hosted x86-64 lane runs the full gate, every
architecture, so the AArch64 tests run there under qemu with Ubuntu's
cross GCC; the option is spelled on every line for a driver that does
not pass it. The AArch64 lane runs them natively. HOSTED.

## 7. Spec changes

- a64.md §11.1, "Words a round cannot know": the words use the link's
  output kind; a word that depends on an unknown address stays in the
  predicate, an ADRP `W1` taken as out of ADR reach; the merge-section
  piece at `st_value + A`.
- a64.md §11.2, "Who decides": such a site takes the redirect in that
  round, why the fixed point still ends; fill writes a fix over its own
  words only, and refuses (internal error) otherwise.
- harness.md L3, "The erratum option" and "The note".

## 8. Not verified

- RB-2's own abseil link was not rerun (`xtask realbuild` is not this
  package's); its shape is the land test's and libstdc++'s.
- The x86-64 host's cross toolchain, other than through the hosted run.
- A GOT page against a shared symbol with a copy (a `-no-pie` program
  taking the variable's address): the matrix's dynamic executable has
  the copy, and its sites get the ADR (to the GOT page, the slot being
  kept for the PIC code). The final scan's copy address
  (`AllocKey::Copy`) is exercised there only.
- The fill guard has no test of its own that makes it fire: no input
  makes the scan and fill disagree now.

## 9. Erratum 835769

Not the same hole. mortar refuses `--fix-cortex-a53-835769` by name
(a64.md §11.5, row `fix-cortex-a53-835769` Refused), so no mortar output
claims the fix; GCC passes it only with `-mfix-cortex-a53-835769` (not
Debian's default: `gcc -###` shows only 843419). The verifier has no
835769 rule, so a reference linker's 835769 output is not judged at all;
that is a coverage gap of the references, not a mortar mislink.
