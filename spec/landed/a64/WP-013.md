# WP-013 — the AArch64 specification

`spec/a64.md`: the AArch64 instance of `spec/arch.md`. It is a design
only. `mortar_a64` (WP-023) implements it, and `mortar_plumb`
re-derives it.

## What it does

- Counts what the producers mortar must link actually emit (§2). The
  counted producers are GCC, gfortran, two Clangs, hod, glibc's static
  libraries and GCC's runtime libraries.
- Gives one row for every static relocation type of AAELF64 (§6.1):
  its formula, field, check, alignment, demand class and status
  (M1, M2, later or refused). It also gives the dynamic types (§6.2)
  and RELR (§6.3).
- Defines the demand of each class per output kind and target kind
  (§5), and the treatment of undefined weak references (§7).
- Defines relaxations R1-R7 (§8). For each one it gives the
  precondition, the exact words written and the kind under
  arch.md §5.2.
- Covers range-extension thunks (§9), and the GOT, `.got.plt`, PLT,
  IPLT, copy and TLSDESC shapes (§10). The PLT shape has plain, BTI,
  PAC and BTI+PAC variants.
- Covers erratum 843419 (§11), the TLS layout (§12), eh_frame,
  tombstones and header facts (§13), and a table of where GNU ld, lld
  and mold differ (§14).

## Decisions the spec records

- **The table comes from the ABI, the statuses from the census.**
  - All 34 types the census found are M1 or M2. 32 are M1. The other
    two are the traditional-dialect GD pair, which GCC emits only with
    `-mtls-dialect=trad -fPIC`.
  - Every other type is refused by name until a milestone takes it.
- **RELA only.** No producer writes `SHT_REL` for AArch64, so it is
  refused by name.
- **The address of a non-preemptible IFUNC is its IPLT entry,
  everywhere**, including in data. One rule removes the
  pointer-equality question. lld does the same in static links.
- **Undefined weak branches go to the next instruction (X = 4).** lld
  and mold do this. GNU ld writes a `nop` for `b`/`bl` and a
  self-branch for conditional branches. Either form is correct;
  branch-to-next has one rule for every branch form.
- **The GOT relaxation is ADRP+LDR → ADRP+ADD (R5).** It is guarded by
  the symbol-wide flag `GOT_NORELAX`, raised at scan for any
  unpaired use. It is kind 2, so the GOT slot stays allocated.
  - lld's NOP+ADR form needs the distance and is left for later (R6).
  - GNU ld does not relax.
- **TLS:**
  - TLSDESC → LE and TLSDESC → IE in executables.
  - Descriptors stay in shared objects (lld, mold).
  - TLSDESC is non-lazy: no `DT_TLSDESC_PLT`.
  - The traditional GD pair is relaxed through a neighbour-record
    sequence (R4). lld refuses it.
- **Thunks are 12 bytes** (`adrp x16; add x16; br x16`), keyed by
  `(SymKey, addend)` or by a PLT entry.
  - A thunk into a BTI-enforced output must land on a valid landing
    pad. If it cannot, the link is refused by name rather than given a
    `bti` pad.
- **Erratum 843419:** ADRP is rewritten to ADR when the target is in
  range, otherwise an 8-byte patch is used. GNU ld behaves the same
  way. lld always uses a veneer; mold does nothing.
- **Tombstones:** 1 in `.debug_ranges` and `.debug_loc`, 0 elsewhere.
  This matches lld and mold. GNU ld writes 0 in `.debug_loc`, where 0
  is ambiguous with an end-of-list entry.
- **Header facts:**
  - The non-PIE base is 0x400000 (GNU ld).
  - The maximum page size is 64 KiB.
  - `EI_OSABI` is always 0.
  - `.got[0]` is `_DYNAMIC` in dynamic outputs.
  - A static `.got.plt` has no reserved words.
  - `__rela_iplt_start`/`__rela_iplt_end` are defined in static
    outputs only.
- **The TLS template is aligned to its own alignment.** This is
  requested of the model, M-3. Under it, SYSVABI64's TP offset reduces
  to `x − tls.start + align_up(16, align)`.

## Evidence

All work was done in a scratch directory of the workspace's `.build/`,
removed at the end.

**Documents** (public), fetched from the ARM-software `abi-aa`
repository, `main` branch:

- `aaelf64/aaelf64.rst`
- `sysvabi64/sysvabi64.rst`
- `pauthabielf64/pauthabielf64.rst`

A small parser turned the reStructuredText grid tables of AAELF64 into
one line per type: number, name, formula and the check text. These 154
lines are the source of §6.1. Each row was then rechecked by hand
against the document.

**Corpus.** Six sources:

- `a.c`, `d.c`: C with every symbol kind and every TLS model, IFUNC,
  and switch tables.
- `b.cc`: C++ with exceptions, `thread_local`, templates and virtual
  calls.
- `c.f90`: Fortran with a module and a common block.
- `e.c`, `f.cc`: the C and C++ sources without TLS, for code models
  that refuse it.

**Compile matrix.** One job per line, at most 4 at a time, each in its
own working directory so that gfortran's `.mod` files do not collide:

```sh
for cc in gcc clang-19 clang-22; do
  for pic in -fno-pic -fPIE -fPIC; do
    for ex in "-O0" "-O2" "-O2 -g -ffunction-sections -fdata-sections" \
              "-O2 -mcmodel=tiny" "-O2 -mcmodel=large" "-O2 -fno-plt" \
              "-O2 -mbranch-protection=standard" "-O2 -mtls-dialect=trad" \
              "-O2 -mtls-dialect=desc" "-O2 -ftls-model=global-dynamic" \
              "-O2 -ftls-model=local-dynamic" "-O2 -ftls-model=initial-exec" \
              "-O2 -ftls-model=local-exec"; do
      $cc $pic $ex -c src.c -o obj.o     # g++ / clang++ for .cc
done; done; done
gfortran {-fno-pic,-fPIE,-fPIC} {-O0,-O2,"-O2 -g",-mcmodel=large,-mcmodel=tiny,-fno-plt} -c c.f90
# hod, through LLVM IR:
clang-22 -S -emit-llvm -O0 [-g] {-fPIC|-fno-pic} -o x.ll src.c
hod --strict -filetype=obj -relocation-model={pic,static} -code-model={small,large,tiny} \
    [-function-sections -data-sections] -o x.o x.ll
# then, for every object:
readelf -rW x.o | awk '$3 ~ /^R_AARCH64/ {print producer, $3}'
```

- There were 390 jobs in the first matrix. 351 succeeded. The 39
  failures were the producers' own refusals:
  - large code model with PIC;
  - large with TLS (Clang, hod);
  - tiny in hod;
  - Clang has no `-mtls-dialect` on AArch64.
- A second matrix of 76 jobs over `e.c`, `f.cc` and `c.f90` covered the
  code models that refuse TLS.

**System libraries:**

```sh
readelf -rW LIB | awk -v l=LIB '$3 ~ /^R_AARCH64/ {print l, $3}' | sort | uniq -c
```

LIB was each of the following:

- From `/usr/lib/aarch64-linux-gnu/`: `libc.a`, `libc_nonshared.a`,
  `libm.a`, and the start files `crt1.o`, `Scrt1.o`, `rcrt1.o`,
  `Mcrt1.o`, `gcrt1.o`, `grcrt1.o`, `crti.o`, `crtn.o`.
- From `/usr/lib/gcc/aarch64-linux-gnu/14/`: `libstdc++.a`, `libgcc.a`,
  `libgcc_eh.a`, `libgfortran.a`, and `crtbegin{,S,T}.o`,
  `crtend{,S}.o`, `crtfastmath.o`.

**Tools:**

- GCC and gfortran 14.2.0
- Clang 19.1.7 and Clang 22
- GNU ld 2.44
- LLD 19.1.7
- mold 2.37.1
- hod: the workspace's release build

**Experiments.** Small assembler or C inputs, linked by GNU ld, lld and
mold, and read with `readelf` and `objdump -d`. Nothing was executed,
see Q14.

| experiment | what it settled |
|---|---|
| PLT | PLT0 and entry words, plain and BTI (`-z force-bti`), PIE and non-PIE against a shared object. `.got.plt[0]` is 0 in GNU ld and lld and `_DYNAMIC` in mold. JUMP_SLOT words initially point to PLT0. |
| thunk | `bl`/`b` to a section placed 129 MiB away (`.far`, via `-Ttext`/`--section-start`). GNU ld's 16-byte thunk with `udf` padding; mold's `$thunk`; sharing between call sites; the BTI case. |
| weak | Undefined weak references from every branch and address form, in static, PIE and shared outputs, with and without a dynamic linker. Branch-to-next versus `nop`. |
| tls | Every TLS form in static, PIE and shared outputs. The TLSDESC → LE and → IE words. The traditional GD pair (GNU ld relaxes it, lld refuses it). The variant I offset `x − start + align_up(16, align)`. |
| ifunc | A static and a static-PIE IFUNC. GNU ld: `.rela.plt` with IRELATIVE, defines `__rela_iplt_*`, OSABI GNU. lld: `.iplt` and `.rela.dyn`, makes the symbol FUNC at its IPLT entry, `__rela_iplt_*` undefined weak in a static PIE. mold: `.plt.got`. |
| gotr | GOT relaxation in PIE, shared and static outputs. GNU ld does none. lld writes NOP+ADR. mold writes ADRP+ADD, and NOP+ADR when in range. |
| e843 | ADRP at offsets `0xff8` and `0xffc` of a page followed by the erratum's load/store patterns. GNU ld rewrites to ADR; lld uses a veneer (`__CortexA53843419_*`: the instruction, then `b` back); mold does nothing. |
| enc | Instruction encodings, assembled and checked against the words in §10: `stp`, `adrp x16`, `ldr x17`, `add x16`, `br x16`, `br x17`, `nop`, `bti c`, `autia1716`, `movz`, `movk`, `mrs tpidr_el0`, `brk`. |
| tomb | A relocation against a discarded COMDAT/`--gc-sections` function from each DWARF section. 1 in `.debug_ranges` from all three tools. In `.debug_loc`, 1 from lld and mold and 0 from GNU ld. 0 elsewhere. |
| tdp | TLSDESC in a shared object. GNU ld is lazy (`DT_TLSDESC_PLT`/`DT_TLSDESC_GOT`); lld and mold are non-lazy in `.rela.dyn`. |

- One TLS experiment, the third variant, is not trusted. An edit left
  the symbol defined where it should have been undefined. Its results
  are not used.
- Page sizes and bases were read from every linked output:
  - segments aligned to 0x10000;
  - non-PIE base 0x400000 in GNU ld, 0x200000 in lld and mold;
  - GNU ld uses one R+X LOAD; lld and mold separate them.
