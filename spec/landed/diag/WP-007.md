# WP-007 — `mortar_diag`: the diagnostic model, refusals, rendering

`spec/diag.md` and `crates/mortar_diag` (no dependencies, no `unsafe`), and
the facade's one diagnostic produced through it.

## What landed

- The model: `Severity`, `Kind` (12 seed kinds with stable ids), `Place`
  (file, archive member, section and offset, symbol, argument, script
  position), `Relation`, `Context`, `Diagnostic` (built by value; `Send`,
  `Sync`, owns its data).
- Refusals: `Diagnostic::refused(class, name)`, 14 classes, one wording
  (`unsupported <noun>: <name>`), always an error.
- The text renderer: lld's and mold's shape (`<prog>: error: <message>`,
  `>>> ` context lines), the demangling hook, control characters made
  visible, color on a boolean.
- The collector: `emit(&self, key, diagnostic)` from any thread, report
  order by key then text then fields, `--error-limit` semantics (default
  20, `0` unlimited, at most `2N + 64` errors held), `--fatal-warnings`,
  `--no-warnings`, `has_errors()` as one atomic load, `Report`.
- `crates/mortar`: `link` refuses with `Refused { class: Feature, name:
  "linking" }`; `Outcome::Failed` carries the `Report`; the executable
  renders it with the basename of `argv[0]` (`mortar::program_name`).

## Evidence

- `source scripts/env.sh && MORTAR_REQUIRE_TOOLS=1 cargo xtask ci --quick`:
  fmt, clippy (pedantic, `-D warnings`) and tests clean. `mortar_diag`: 57
  tests and 2 doc tests; `mortar`: 3 unit tests and 3 tests of the
  executable.
- The survey of `spec/diag.md` §8.1 was taken on this machine with GNU ld
  2.44, lld 19.1.7 and mold 2.37.1 (AArch64), inputs built with `gcc -c`,
  `clang --target=...` and `yaml2obj`; every cell is a line a linker
  printed.
- The spec's tables of kinds, refusal classes and relations are read by
  `tests/spec_tables.rs` and compared with the code.

## Interface changes outside the crate

- `mortar::Outcome::Failed` holds a `mortar_diag::Report` (was
  `Vec<String>`): text needs the program name, which `link` does not have.
- `mortar::program_name` is new.
- `--version` is not a diagnostic and is answered as before.
- `crates/mortar/tests/cli.rs` is new (the executable's stderr, stdout,
  status, and the absence of an output file), with `mortar_testutil` as a
  dev-dependency of `mortar`; `Cargo.lock` records both dependencies.

## Decisions taken here (the supervisor's are in the spec with their reasons)

- Two classes beyond the twelve asked for: `symbol-binding`
  (`STB_GNU_UNIQUE`) and `compression-type` (`ELFCOMPRESS_ZSTD`): the
  object reader of WP-004 meets both.
- `-w` wins over `--fatal-warnings` (GNU ld 2.44 and lld 19 both link
  silently with status 0).
- The limit cuts the *report*; it does not stop a phase (§6.4, §8.2).
- Ties in the key are ordered by the plain text, then by the fields.
- Archive members are `libx.a(y.o)` everywhere (lld: `y.o ... in archive
  libx.a`).
- A demangled head symbol adds `>>> mangled name: ...`.
- Control characters in any outside text are printed as `\u{..}`.

## Open questions

1. `library-not-found` is lld's `unable to find library -l<x>`; GNU ld's
   `cannot find -l<x>` is not matched by mortar's output (§8.2 has the
   reasoning and where to change it).
2. Phase ordinals and what `unit` and `seq` are per phase belong to
   `spec/model.md` (WP-002); this spec fixes only how keys compare.
3. `unknown-option` (not an option of GNU ld's) against `refused` with
   class `option` (known, not implemented): `spec/cli.md` (WP-008) has to
   keep the option table that tells them apart.
4. How many `referenced by` lines an undefined symbol lists, and the
   "referenced N more times" note, are `spec/resolve.md`'s (WP-022).
5. Warnings are not bounded in memory (only errors are). No linker limits
   them; say so if a bound is wanted.
6. Paths that are not UTF-8 are shown with U+FFFD; the model stores
   `String`. Storing bytes would change `FileRef` only.
7. `docs/BACKLOG.md` describes WP-007 as "GNU ld-shaped text"; the decision
   implemented is lld's and mold's shape.

## Follow-ups

- `crates/mortar/src/main.rs`: `std::env::args()` panics on an argument
  that is not UTF-8 (as before this WP); the command line of WP-008 takes
  `OsString`s.
- `crates/mortar/src/main.rs`: color and demangling are off until WP-008
  resolves `--color-diagnostics` and a demangler exists.
- `spec/diag.md` §9: source positions, the enclosing function, a byte
  offset in a file, a machine format, a "would this be cut?" query,
  demangling.
