# WP-112: a link test for every accepted option

Record of WP-112. Scope: every row of `docs/status/options.md` that
mortar accepts (`supported`, `partial`, `noop`) is spelled by a link test
under `tests/link` that shows its effect against the same link without
it and against GNU ld, lld and mold; a `noop` row's test shows the output
is the same bytes with and without it and quotes the row's reason. Tools:
GNU ld 2.44, lld 22.1.8 (`ld.lld-22`), mold 2.37.1, GCC 14.2.0, Clang
22.1.8. No linker crate changed. Main merged at 974db19 (WP-102: the
verifier reads the option line); every test was rerun on the merged
tree, and V1-V5 below are still found there.

## 1. The check

- `xtask/src/linktest/spelled.rs`: the accepted rows of the table, the
  link steps of every test (`format::parse`), and the rows no step
  spells. Counting rule (`spec/harness.md` "Every accepted option is
  spelled"): only what a test file writes; a long option with one dash
  or two, alone, `=value` or a separate value; a one-letter option alone
  or glued; `-z kw`, `-zkw`, with `=value`; in a driver link the words of
  `-Wl,` and `-Xlinker` and the driver options GCC hands on as they are.
  What a driver adds on its own does not count (WP-100 counted it, hence
  its 60 of 114).
- `cargo xtask spelled` prints the rows and `spelled: N of M accepted
  rows spelled by no link test`; the test
  `every_accepted_option_is_spelled_by_a_link_test` wants none and runs
  in `cargo test` (0.07 s), so in the quick gate.
- Count: **81 of 121** at the start (main c5409aa), **0 of 121** at the
  end.

## 2. Harness additions

- `check cmp A B` (`identical`, or where the files first differ): the
  `noop` rows' byte comparison.
- A link's `exit: info` (it succeeds and writes no output, no map, no
  verifier: `--version`, `--help`) and `print:` / `no-print:` (standard
  output: `-v`, `-M`).
- A mortar link that writes its own `--mortar-map FILE` keeps it, and L3
  reads that file (`engine::map_option_named`), as a reference's `-Map`
  already was.
- static-identical replaces the times mortar measures in a link's
  standard error by `<time>` before digesting it (`--time-phases`'
  lines after `: wall `, `--odr-stats`' `; time`, the incremental
  report's ` time=`, `delta time`): `engine::normalise_stderr`, unit
  test `a_standard_error_loses_only_measured_times`. Without it the
  rows of `input/bookkeeping` lines 27 and 45 and the two `--odr-stats`
  links moved on every run. The digested map stays
  `.linktest-plumb-<line>.map`, so a link naming its own
  `--mortar-map` keeps `-` there and no row of main moved.
- The ODR switches test is `diag/odr-switches`, not under `odr/`: the
  producers lane (WP-099) re-links the `odr/` corpus with hod's objects
  and stops on standard errors that differ, which `--odr-stats`' time
  does.
- `input/bookkeeping` sends the report of its second incremental link
  (state found) to a file: its `delta inputs` line says `clean` or
  `hashed-same` by the input's stamp, which differed between this host
  and the hosted AArch64 runner (run 43970052517). The standard-error
  form of the option is tested on a link with a fresh state.
- Byte-identical baselines: AArch64, main's file plus 429 rows of this
  package's tests, 0 of main's rows moved; x86-64, main's file plus 402
  rows from hosted run 43970052517's printout (its `input/bookkeeping`
  rows from the next run), 0 moved.
- `spec/harness.md`: all of the above, the check's section, and sixteen
  rows of "Where the references differ".

## 4. Findings

- **F1 (mortar).** `-v` and `-V` on a line with inputs link but print
  nothing (`crates/mortar/src/lib.rs`: `print_version` is printed only
  when `plan.inputs` is empty); spec/cli.md §5.1 says "`-v` prints the
  same line and parsing goes on". GNU ld prints `GNU ld (GNU Binutils for
  Debian) 2.44` and links; lld and mold print theirs and link. Proposed
  ruling: print the line (standard output) before the link, as the spec
  says. `input/print-version` is `xfail(mortar)`.
- **V1 (verifier).** `crates/mortar_plumb/src/line.rs` knows `-dy` and
  `-call_shared` with one dash only: `--dy`, `--call_shared` (and likely
  `--dn`, `--non_shared`) leave `-Bstatic` in force and every linker's
  correct output is P-D2. The tests use one dash. Proposed: the reader
  takes the table's spellings (WP-102's copy of the table).
- **V2 (verifier).** P-D6 reports lld's DF_SYMBOLIC (DT_FLAGS 0x2) under
  `-Bsymbolic`, which the line asks for. lld's link of that line is left
  out of `dyn/shlib/bsymbolic`. Proposed: DF_SYMBOLIC is allowed when the
  line has `-Bsymbolic`.
- **V3 (verifier).** S2 for mortar's i386 output holds every PT_LOAD's
  `p_align` at 0x1000 and the base at 0x08048000 whatever
  `-z max-page-size` says (`structure.rs`, "S2 (mortar, i386)"); mortar's
  output follows layout.md L-74 and L-68 (and GNU ld's bytes: base
  0x08040000 at 64 KiB) and runs. `layout/max-page-size` is
  `xfail(mortar,i386)`. Proposed: S2 reads the line's max page size.
- **V4 (verifier).** R6 reads an SHF_COMPRESSED debug section's bytes as
  they are in the file: GNU ld's and lld's correct
  `--compress-debug-sections=zlib` outputs are reported (`'.debug_line_str'
  reaches other bytes`). Their links are left out. Proposed: R6 skips (or
  decompresses) compressed sections, as the record checks already do.
- **V5 (verifier) and a mold mislink.** mold 2.37 after `--push-state
  -Bstatic --pop-state -lgreet` writes PT_INTERP, `.dynsym`, a PLT and a
  JUMP_SLOT for `greet` but no `.dynamic` and no DT_NEEDED; the program
  crashes (SIGSEGV), and the verifier passes it. Proposed: a rule that an
  output with PT_INTERP or dynamic records has PT_DYNAMIC.
  `dyn/shlib/push-state` is `skip(mold)`.
- Not a finding, recorded: GNU ld's LTO link (plugin) has a map naming
  `/tmp/cc*.ltrans0.ltrans.o`, on no command line; L3 reports I1.
  `input/plugin` does not make that link. mold's AArch64 static PIE
  leaves the word at `_GLOBAL_OFFSET_TABLE_` 0 (P-D14), no anomaly id:
  `skip(mold,aarch64)` in `dyn/dynamic/no-dynamic-linker`.

No mortar mislink was found.
