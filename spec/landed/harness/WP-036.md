## Item 1 — static twins

Every PIE or dynamic workload has a static non-PIE twin of the same
inputs (`<name>-static`), plus `cxx-medium-gc-static` (protoc with
`-ffunction-sections -fdata-sections` and `--gc-sections`),
`synthetic-library-static` (a 20 000-member archive of which main uses
one member in 50) and `fortran-static` (gfortran and C, the program of
`tests/link/lang/fortran-c.test`). The originals stay; mortar refuses
them by name and the run goes on. mortar links 12 of the 23 workloads,
all verified clean. `rust-self-static` is refused (`-Bdynamic`, below).

## Item 2 — one command, one table

`cargo xtask bench` prints, per workload and linker (mortar, mold
`--no-fork`, lld, GNU ld) at one thread and at the default threads, the
median wall time with the fastest-to-slowest range, the median CPU time
(user + system), and the median peak RSS; the linkers are interleaved
run by run. After the table, it prints one line per mortar link: mortar
against the fastest and the smallest of the others. Each mortar output
is verified (WP-035) and, where the manifest has a `run` line, is run
once alongside GNU ld's output of the same link. Exit status and standard
output must match, or the run fails (exit 1). In every run of this
package, the 11 workloads that were run behaved the same as GNU ld's.
`synthetic-objects*` is not run (exponential calls). "Default threads" and
the run count are in `spec/harness.md`.

## Item 3 — baseline and noise

Three whole runs of one commit (09:42, 10:00, 10:28; 5 runs per link;
load average 8 to 13), each judged against each of the others (`--judge`,
six pairs):

- mortar's median wall moved between runs by 7% to 223% per link (the
  median link 53%); memory by at most 2.6% (6.4 MiB,
  `synthetic-objects-static`, default threads), the median link 0.6%;
- on the links the gate calls steady, the largest slowdown was 28.2%;
- with the margins of 5% time and 2% memory, two pairs had false
  `REGRESSED` rows (two time, one memory).

The margins are now 35% time and 4% memory; with them no pair has a
`REGRESSED` row, and neither do the three runs judged against the
recorded baseline.

The baseline took five recording attempts:

- three were `noisy` (calibrations 51.2/27.2, 39.8/92.8 and 118/102 ms),
  so `--update-baseline` now refuses a noisy run;
- the one recorded (11:07 to 11:24, at commit b0c81eb) ran at a load
  average of 23 to 20, with a calibration of 109/112 ms against 33 to
  36 ms in the quieter runs;
- by the supervisor's ruling (speed is guarded, not pursued, for now), it
  stands, marked in its `reason` as recorded under load;
- `spec/harness.md` "Noise" and `docs/status/perf.md` say what the gate
  can still call `REGRESSED` against it: lost links, memory, and gross
  slowdowns only.

## Item 4 — `xtask plumb --inputs-from` resolves `-l`

`response_inputs` (`xtask/src/plumb.rs`):

- `-L`, `--library-path` and `--sysroot` (`=` and `$SYSROOT` prefixes),
  then each `-l`, `-l:`, `--library` through them;
- `.so` before `.a`, only `.a` after `-static`, `-Bstatic` and their
  synonyms, with `--push-state`/`--pop-state`;
- the values of separate-value options are skipped.

Test: `s8_libraries_are_resolved`. hello-c-static's mortar output now
gives 0 findings with `--inputs-from`.

## Item 5 — `docs/status/perf.md`

It is generated with `bench.md` from the baseline. It gives the date,
commit, host, load and calibration, then per mortar link the wall time
and RSS ratios to the fastest and smallest other linker. It also lists
the three links furthest behind on each, the workloads mortar does not
link, and the run verdicts.

## Found

- mortar refuses rustc's trailing `-Bdynamic` in a `-static` link
  (`crates/mortar_cli/src/rows.rs:157`, `Refused`). To reproduce:
  `cargo xtask bench --workload rust-self-static --linker mortar`. In
  the response file the last option is `-Bdynamic`, after every `-l`.
- `synthetic-library-static`: mortar's RSS is 2.85 to 3.09 times GNU
  ld's (54 MiB). lld and mold use about 140 MiB, so this is not
  mortar's alone. Its wall time is 1.75 to 2.31 times the fastest
  linker's.
- In this container, `/dev/stdout` had become a regular file (43 733
  bytes, protoc's descriptor set) by the time it was noticed. The cause
  was not found: protoc writing to `/dev/stdout` through a pipe leaves the
  link intact. It was restored to `-> /proc/self/fd/1`. The protoc `run`
  lines now write to `/dev/fd/1`. The baseline's `run.*` keys for the
  three protoc workloads say 0 bytes of output from that time.
  A run afterwards (`--workload cxx-medium*-static --linker mortar
  --linker bfd --runs 1`) gave `same: exit status 0, 43733 bytes of
  standard output` for all three.

## Cost

- `cargo xtask ci --quick` runs no bench, only xtask's unit tests (50 in
  `bench`, no workload built), so its cost did not grow.
- A whole `cargo xtask bench` takes 6.6 to 8.4 minutes on the loaded host
  (23 workloads, 4 linkers, 2 thread settings, 5 runs), and 12 to 17
  minutes at load 20.
- `--prepare` of the 11 new workloads took about 25 minutes.
