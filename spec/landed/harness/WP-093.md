# WP-093: the dynamic and static-pie link tests join the byte-identical corpus

Record of WP-093. Scope: `spec/harness.md` "static-identical" for all of
`tests/link/dyn` (124 tests: PIE, non-PIE dynamic, static-pie, the driver
census cases, the ODR table), both hosts' baselines, the one
normalisation the dynamic cases need, and a mutation check of the lane.
Baselines recorded on main `61e806c` (no later main to merge).

## 1. What is not reproducible

The digest mode over the whole corpus, `tests/link/dyn` included, was run
seven times on the AArch64 development container: the default `TMPDIR`
and `-j` (8); `TMPDIR` in two other directories with `-j 2` and `-j 8`/`-j
10`; and once from a copy of the checkout at another path
(`git archive`), with its own target directory and its own build of
mortar.

| what moved | links | column | cause | kind |
|---|---|---|---|---|
| every successful gcc/g++/gfortran-driven link that is not `-static` | 404 of 505 `dyn/` rows | `map` only | gcc passes `-plugin-opt=-fresolution=<TMPDIR>/ccXXXXXX.res` (its LTO plugin's resolution file, a new `make_temp_file` name per link); the map's `arg` records hold every word | (a): an input, not mortar's |

Nothing else moved: no `output`, no `stderr`, no `end`, at any job count,
`TMPDIR` or checkout path. Reproduced by hand: two `gcc -B<dir with ld ->
mortar> a.o` links give identical outputs and maps that differ in that
`arg` line alone (and the `-o` and `--mortar-map` names). No determinism
defect of mortar (item 1(b)) was found.

The rule (`spec/harness.md` "static-identical",
`xtask/src/linktest/engine.rs` `normalise_map`): before the path
substitutions, a map line that is exactly `arg
-plugin-opt=-fresolution=<path>`, `<path>` without blanks and ending in
`/cc` + six ASCII letters or digits + `.res`, has `<path>` replaced by
`<gcc-resolution>.res`. Not the output, not the standard error, not
another form of the word. With it, 0 of 806 rows differ across the runs
above. This also closes WP-059's F4 and the static-identical item of
WP-085's row: a later test need not pass `-fno-use-linker-plugin`.

`xtask/src/identical.rs`: `DYNAMIC_CASES` is gone; the corpus is every
directory of `tests/link`, and `tests/identical`. Its unit test is now
`the_corpus_is_every_link_test`.

| before (main `61e806c`) | 301 | 81 | 110 | 101 | 90 |
| after | 806 | 205 | 363 | 352 | 91 |
| of which `dyn/` | 505 | 124 | 253 | 251 | 1 |

Exclusions: none. Every one of the 124 tests has at least one mortar row.
Treated as in the static corpus: link steps scoped to reference linkers
only (`link(bfd,lld,mold)` and the like: 51 steps in `dyn/`) are not
mortar links and have no row; refusals (88 rows: 42 AArch64, 45 x86-64,
1 i386, `spie/i386-refused`) are rows with `exit status 1`, `-` output
and map, and their diagnostics' digest; no `dyn/` test has
`skip(mortar)`.

## 3. Shared objects built as inputs, two machines

The `shlib` fixtures are built by the host's gcc and GNU ld; their bytes
are absorbed by "one baseline per host". The hosted AArch64 lane (run
`43831140695`, `arm / gate`) checked the baseline recorded here: `806
links ... 0 differ from tests/identical/baseline.on-aarch64.tsv`. So the
development container and the hosted AArch64 machine build the same input
bytes under the tool guard's pins; nothing to report. Between hosts, as
expected, every `dyn/` link row differs (211 AArch64, 206 x86-64) and 82
of 88 refusal rows are the same (the i386 one among them).

## 5. Mutation check

A scratch copy of the checkout (outside the worktree) with
`DF_1_NODELETE` (0x8) or'ed into `DT_FLAGS_1` in
`mortar_synth::dynamic` for one output kind, built, copied as
`<dir>/mortar` and run with `cargo xtask static-identical --mortar`:

| mutation | links that differ | tests | under `dyn/` | outside `dyn/` (the old corpus) | columns |
|---|---|---|---|---|---|
| `DynKind::Pie` only | 263 | 145 | 262 | 1 (`reloc/x64-gotpcrelx-slot` line 38) | `output` |
| `DynKind::StaticPie` only | 38 | 22 | 34 | 4 (`reloc/x64-gotpcrelx-slot` 41, `tls/gd-trad-corpus` 44 and 58, `tls/gd-trad-static` 82) | `output` |

Both failed (`static-identical: FAILED`, exit 1) naming each link. The
scratch copy was removed; nothing of it is on the branch.

Found on the way: a `--mortar` binary not named `mortar` changes every
`stderr` digest of a link with a diagnostic (the program name heads each
diagnostic): a first run with `mortar-mut-pie` showed 156 stderr-only
differences. Written into `spec/harness.md`; not normalised (the name is
part of what a user sees).
