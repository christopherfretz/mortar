# WP-100: real open-source builds linked by mortar, and what they ask for

Record of WP-100 (layer L9, stage 1). Scope: the lane `cargo xtask
realbuild` (`spec/harness.md` "realbuild"), twelve pinned projects built
by their own build systems with mortar as the linker and with a control
linker, every link line counted, the projects' own tests compared, a
baseline, and from it the ranking that plans M4. AArch64 native only.
Toolchain: GCC, G++ and gfortran 14.2.0 (Debian), Clang 22.1.8, GNU ld
2.44 (the gcc rows' control), lld 22.1.8 (the clang rows' control),
CMake 3.31.6, Rust 1.95.0 (the workspace's). mortar is main's at
b413a47 (merged into the branch) for every row of the baseline: no
linker crate changed in this package; the `commit` column of `runs.tsv`
is the branch's head of each run, which differ in `xtask` and
`tests/realbuild` only.

## 1. The lane

- `xtask/src/realbuild.rs` (the command, the build of each mode, the
  `verify` subcommand), `xtask/src/realbuild/outcome.rs` (records, line
  ids, kinds, refusals, outcomes, the baseline and its comparison),
  `xtask/src/realbuild/report.rs` (`tests.tsv`, `runs.tsv`, the ranking,
  `docs/status/realbuild.md`).
- `tests/realbuild/manifest` (the projects, in the bench manifest's
  format; `xtask/src/bench/manifest.rs` now exposes its section parser),
  `tests/realbuild/projects/<name>.sh` (each project's own build and
  tests), `tests/realbuild/lib.sh`, `run.sh`, and `ld`, the wrapper.
- Fetching is the bench's: `xtask/src/bench/prepare.rs` gained
  `fetch_archive` (download, SHA-256, unpack once, now `tar -xf` for
  gzip, xz and bzip2), which the bench's `fetch_and_unpack` now calls; no
  second fetcher.
- The capture: the wrapper is `ld` (and `ld.bfd`, `ld.lld`, `ld.gold`,
  `<triple>-ld`) first on `COMPILER_PATH` and `PATH`, the census's way;
  GCC's collect2, Clang's driver, rustc's `-C linker=$CC` and Kbuild's
  direct `ld -r` all reach it. It records argv, cwd and copies of response
  files; in mode `mortar` the control first links the line to a scratch
  output (the oracle: does the line link at all), then mortar links it
  with a map, `realbuild verify` judges the output with the line (stage
  3), and on any mortar failure the control links the line for the build
  (recorded as the fallback). The build sees mortar's output whenever
  mortar linked.
- Off-gate: `cargo xtask ci` runs only the lane's thirteen unit tests; the
  hosted lanes never run the lane (network, hours). Its evidence is
  `tests/realbuild/baseline.tsv`, `tests.tsv`, `runs.tsv` and the report.
- The shared host: every build and test step under `nice -n 10` with
  `MAKEFLAGS=-j<n>` (the lane's `-j`, default 3, at most 6), ctest at the
  same count, and each build waits for a 1-minute load under 10. The
  baseline's runs used `-j 3` and, once the supervisor allowed it on a
  quieter host, `-j 4`.

## 2. The projects

Twelve projects, eleven with both rows; versions, URLs, digests, licences
and the one-line reasons are in `docs/status/realbuild.md` "Projects".

| need of the brief | projects |
|---|---|
| C | zlib, Lua (hand-written Makefile, `-Wl,-E`) |
| old autotools with libtool (at least two) | expat, PCRE2, GMP (GMP also hand-written assembly, `m4`) |
| CMake C++, many static archives, a test suite | abseil (about 140 archives), googletest |
| template-heavy C++ with exceptions and TLS in tests | fmt, abseil, googletest |
| Fortran (LAPACK's tests or a slice) | LAPACK 3.12.0, the double-precision slice |
| mixed C/C++/Fortran | ARPACK-NG (ISO_C_BINDING; C and C++ examples against Fortran) |
| `ld -r` / a linker script / a version script on purpose | BusyBox (Kbuild's `ld -r` per directory), zlib (`--version-script`) |
| shared libraries AND static tests | zlib (libz.so and libz.a, tests against both), googletest (`gtest_dll`), Lua's test modules |
| a Rust test binary through `-C linker=` | semver 1.0.23 (no dependencies; rustc driven directly) |

Choices, none a patch:

- **abseil, gcc row only.** Its build is the largest of the list (a
  4 GB tree, 18 minutes per mode at three jobs on this host); a clang row
  would double that for link lines of the same shape as googletest's
  and fmt's clang rows.
- **LAPACK, a slice**: `BUILD_DOUBLE` and `BUILD_COMPLEX16`, the single
  and complex variants off (they build as much code again for link lines
  of the same shape). Double real alone does not build: CBLAS's double
  tests (`xdcblat1`) call `cblas_dzasum` and `cblas_dznrm2`, which only
  the double complex set compiles.
- **BusyBox**: `defconfig` with `CONFIG_TC` off (`networking/tc.c` does
  not compile against Debian 13's kernel headers).
- **expat, PCRE2, GMP** configured `--disable-shared` (the operator's
  static-leaning configuration); zlib, Lua and googletest build their
  shared objects anyway, which is what the `-shared` counts measure.
- **semver** is compiled with `rustc` by hand, as cargo would, because
  cargo wants the network to resolve the crate's optional `serde`.
- No project was replaced.

## 5. Defects

Two defects, both reported by the verifier as findings (no crash, no
wrong diagnostic, no lost test). RB-2 is a mislink; RB-1 a verifier
false positive. The stop condition (a test passing with the
control and failing with mortar while the verifier accepted mortar's
output) never fired: no test result differs between the linkers in any
row (section 3).

- **RB-2: an erratum 843419 site whose ADRP is a GOT page of a shared
  library's symbol is left unfixed** (a mortar mislink; owner: layout /
  `mortar/src/sites.rs`, a package to cut). abseil's
  `absl_log_structured_test` (gcc row, the verifier's C1): GCC's `adrp
  x0, :got:__libc_single_threaded; ldr x0, [x0, :got_lo12:...]; ldrb w0,
  [x0]` with the ADRP at page offset 0xFFC. `spec/a64.md` §11.1 makes it
  a site and §11.2 a fix (`W1` 311: `V` is `G(GDAT(S))`); GCC on Debian
  passes `--fix-cortex-a53-843419` to every link; GNU ld writes the ADR.
  mortar leaves the ADRP. The output runs here (this host is not a
  Cortex-A53) and every abseil test passes, which is why the stop
  condition did not fire; on an affected core the load may read the
  wrong address. The same shape against the executable's own data (a
  direct `adrp`/`:lo12:`) in the same section is fixed, so it is the GOT
  slot of a dynamic symbol only. Not diagnosed further (not this
  package's to fix: not a 20-line change I can show is right).
  **The verifier missed it too, unless the output had another fix**:
  `mortar_plumb` judges sites only when its caller says the option was
  given or the output has a fix elsewhere (erratum.rs, `fix =
  map.fix_843419.or(..)`), and every caller in xtask passed `None`
  (`plumb::verify_link_line`'s `fix_843419` argument: linktest's
  engine.rs, census.rs, mason.rs, and this lane's first runs), so an
  output whose only sites are unfixed is counted `erratum_not_judged`,
  not a finding. abseil's test had a fixed site elsewhere. The lane now
  reads the option from the line (`realbuild.rs` `fix_843419`, test
  `the_erratum_option_is_read_from_the_line`), and every gcc row was
  re-run with it (section 3). linktest, census and mason still pass
  `None`: their mortar outputs with only unfixed sites are not judged
  either (a harness change for the supervisor: passing the line's option
  there can raise new findings in the corpus). **With the option read,
  the gcc rows have 16 such sites on 16 lines**: GMP 1 (`tests/libtests.a`
  `trace.o`), googletest 2, fmt 2 (its bundled GoogleTest), abseil 11
  (`absl_log_structured_test` and ten tests through the GoogleTest it
  builds). Every one is C1 at an ADRP whose page is a GOT slot of a
  symbol only a shared library defines: 13 of the 16 checked by
  compiling the object again with the row's compiler and flags and
  reading the relocation at the reported offset (`__libc_single_threaded`,
  libstdc++'s `shared_ptr` count, 6 times; `stdout`, `stderr` and
  `std::cerr`, 7), the other 3 (GMP's `trace.o`, which uses `stdout` and
  `stderr`; `gtest_premature_exit_test.cc.o`; gmock's
  `_Sp_counted_base::_M_release_last_use_cold`) not compiled again. No
  site of another shape was found. Every test still passes (this host is
  not a Cortex-A53). Minimised:
  `tests/link/dyn/reloc/erratum-843419-got-shared.test` (`xfail(mortar):
  RB-2`; GNU ld, lld and mold pass, mortar XFAIL with C1). This is the
  silent-mislink class the stop condition is about, caught here only by
  luck of the second site: it is reported first in the hand-back.

- **RB-1: the verifier's R1 on a debug word against a shared library's
  symbol** (owner: `mortar_plumb`, not this package's). Clang 22 emits,
  for a class with a key function in libstdc++ (`std::bad_alloc`,
  `std::exception`, `std::system_error`), a `_vtable$` variable whose
  `.debug_addr` entry is an `R_AARCH64_ABS64` against the vtable
  (`_ZTVSt9bad_alloc`, ...), which only `libstdc++.so` defines. Nothing
  relocates a non-alloc section at run time, so the field cannot hold the
  library's address: GNU ld, lld and mortar write 0, mold the symbol's
  `st_value` in the library (an address of nothing in the executable).
  GNU ld refuses the same word in a non-debug section ("unresolvable
  R_AARCH64_ABS64 relocation"); lld writes 0 there too. The verifier
  (`spec/plumb.md` §5.8) computes S from its loader's view of the
  library (`loader::lib_base` plus `st_value`, `0x7f00...`) and reports
  R1 on every linker's output. Neither `spec/plumb.md` §5.8 nor
  `spec/image.md` says what such a field holds; the fix is a sentence
  there (the field holds 0 + A, as GNU ld and lld write it; mold's
  value a recorded anomaly) and the verifier following it. Rows: GMP clang `tests/cxx/t-ops2z`, googletest
  clang (4 lines), fmt clang (20 of 21 lines, 37 findings, all of this
  form); the gcc rows never have it (GCC emits no `_vtable$`).
  Minimised: `tests/realbuild/defects/RB-1.test`, one `.quad environ` in a
  `.debug_` section of a PIE. It is not under `tests/link` because every
  reference fails L3 there too, so the harness's self-check refutes it
  (ORACLE) and a test may not mark every reference (`spec/harness.md`
  "Markers"); `cargo xtask linktest --arch aarch64
  tests/realbuild/defects/RB-1.test` shows it today (bfd, lld and mold
  FAIL with L3 R1 at 0x0, ORACLE), and the file moves to
  `tests/link/dyn/reloc/` when the verifier is fixed. Its outputs run
  correctly with every linker, and mortar's field equals GNU ld's and
  lld's.

## 6. Options mortar accepts that no link test spells

The rows of `docs/status/options.md` that are `supported`, `partial` or
`noop` (112 rows) against every word of every file under `tests/link`
(a `-Wl,` word split at its commas; GNU ld's one-dash and two-dash
spellings of a long option taken as one; a `-z` keyword as `-z kw`,
`-zkw` or `-Wl,-z,kw`; and a test with a `link gcc|g++|clang|gfortran`
step counted as spelling what those drivers pass on this host on their
own: `--as-needed`, `--no-as-needed`, `--build-id`, `--eh-frame-hdr`,
`--hash-style`, `--start-group`/`--end-group`, `--push-state`/
`--pop-state`, `--fix-cortex-a53-843419`, `-Bstatic`, `-EL`, `-L`, `-X`,
`-dynamic-linker`, `-l`, `-m`, `-plugin`, `-plugin-opt`, `-pie`,
`-static`, `--no-dynamic-linker`, `-z relro`, `-z text`). **61 of the
112 rows are spelled by no file under `tests/link`.** The second column
says whether a real-build line of this survey uses it; *elsewhere* names
whether anything else in the repository (crate tests, the harness, the
other lanes) spells it at all, *table only* meaning only the options
table itself does.
