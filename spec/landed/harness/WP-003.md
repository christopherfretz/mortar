# WP-003 — jobserver client and process runner

`spec/harness.md` created, with "ci", "Jobserver" and "Limits".

## What landed

- `mortar_testutil::jobs`: the GNU make fifo-style jobserver client
  (`Client`, `Token`, `global()`, `fifo_from_makeflags`), the implicit
  token, release on drop, `release_all`, the non-blocking pool count
  (`refill`, `idle`), and `PrivatePool` / `LocalDir` for tests. No
  dependency.
- `mortar_testutil::run_with` (and so `run`, `write_script`) holds one
  token for the child's lifetime; the time limit starts once the token is
  held. No public signature changed.
- `xtask` is a library and a binary. `xtask::process` is the one place it
  starts a process: `run` (a token, a wall-clock limit, an address-space
  and a CPU limit set in the child, capped output, its own process group),
  `run_measured` (the same under GNU `time`: peak RSS and CPU time), and
  `run_step` (a cargo step). `End::Killed(Limit::Time | Limit::Memory)` is
  a distinct outcome.
- `xtask::jobs` and `xtask::jobs::children`: the SIGINT/SIGTERM thread
  (`signal-hook`) and the live-children table: kill the children, wait for
  them to be reaped, return the tokens, end by the signal.
- `xtask::ci`: the gate's steps run through `run_step`; `--step <name>`;
  one rerun for the two "artifact not listed yet" errors of rustc on the
  bind mount.

## Evidence

`source scripts/env.sh && MORTAR_REQUIRE_TOOLS=1 cargo xtask ci --quick`:
`[ci] ok`. In it: `mortar_testutil` 17 unit tests and 5 in
`tests/jobserver.rs`; `xtask` 23 unit tests and 5 in `tests/jobserver.rs`
(one more in each `tests/jobserver.rs` is `#[ignore]`: the body the others
run as a child process). The tests are listed by section in the spec.

Observed on this machine under `ulimit -v`, which is what the memory marks
of "How a child ended" come from: the dynamic loader (`failed to map
segment from shared object`, exit status 127), GNU ld (`memory
exhausted`), `dd` (`memory exhausted by input buffer`), a libstdc++
program (`terminate called after throwing an instance of
'std::bad_alloc'`, SIGABRT), Python (`MemoryError`). mold and lld ended by
SIGSEGV or SIGABRT with no message: those are reported as the signal.

## Deviations from hod

- **One runner.** hod has three (`irdiff/process.rs`, the two in
  `bench/measure.rs`); here `run` and `run_measured` are one function with
  an optional GNU `time` in front of the program. Every child, measured or
  not, is in the live-children table, has its output captured and capped,
  and is waited for by a thread blocked in `wait` (hod's unmeasured runner
  polls; the blocked wait is what its bench uses to keep the poll interval
  out of the time).
- **`killed: memory`.** hod reports a child that ran into its
  address-space limit by its exit status or signal. The work package asks
  for a distinct outcome, and the kernel leaves no record of a refused
  allocation, so it is recognized by what the child wrote, as kiln's
  runner does (`out_of_memory`), with a longer list of marks (the linkers
  and the loader). A child that dies without a message stays a signal.
- **The CPU limit** is the wall-clock limit (+1 s) times the processors
  plus one. hod's is the wall-clock limit plus one second, which a
  linker running on every processor would exceed long before its
  wall-clock limit.
- **A kill is repeated** every second until the child is reaped (a process
  that joined the group between the kill and the reap), where hod kills
  once.
- **No `cargo xtask jobserver` command.** The pool is counted and refilled
  by `scripts/jobserver.sh`, which has the shared-pool guard; the library
  functions (`jobs::refill`, `jobs::idle`) remain for the tests' own
  pools.
- **`ci`** keeps WP-001's steps and `[ci]` lines (`cargo test --workspace`
  without hod's `--quiet --no-fail-fast`), has `--step` but none of hod's
  other parts (irdiff, shim, the LLVM checks, `--part`), and finds cargo by
  the `CARGO` variable at run time, so that its test can put a stand-in
  there.
- **`signal-hook` is a dependency of `xtask` only**, as in hod;
  `mortar_testutil` stays without dependencies and a test binary handles
  no signal.
- **Tests.** hod's integration tests of the xtask client drive `irdiff`
  with fake tools; here the test binary runs itself as a client whose
  threads call `process::run`, which tests the same bound, fallbacks and
  signal path. hod's `llvm_tools_are_found_only_by_supported_major` is not
  ported: `find_tool` has no spec section yet.
- **Names**: `MORTAR_*` variables, `/run/mortar`, `mortar-jobs-*` temporary
  directories.
