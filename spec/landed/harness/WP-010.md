# WP-010 — link-test format, runner and seed corpus

`spec/harness.md` gains "Link tests"; "ci" gains the `linktest` step.

## What landed

- `cargo xtask linktest` (`xtask/src/linktest.rs` and `linktest/`): the
  test format and its parser (`format`), the line patterns (`pattern`),
  the architectures, linkers and their tools (`target`), one test on one
  architecture (`engine`), the outcomes and the self-check (`outcome`),
  and the summary, results file and exit status (`report`). Units (test ×
  architecture) run on worker threads; every child goes through
  `xtask::process::run` with a jobserver token and limits; the order of
  the results does not depend on the threads.
- Driver links go through generated wrapper scripts (`-B` for the GCC
  drivers, `--ld-path` for Clang) that record the linker's own exit
  status.
- The references (bfd, lld, mold) run first; mortar is judged only on a
  test they establish; a refuted test is `ORACLE`.
- `cargo xtask ci` runs `linktest` after the cargo steps: the host's
  architecture with `--quick`, all three in the full gate.
- 32 seed cases under `tests/link/` (start, lang, resolve, diag, layout,
  tls, ifunc, reloc, input), each `xfail(mortar): no linking yet (M1)`,
  each with its spec section and the gABI/psABI point it checks.

## Evidence

- `MORTAR_REQUIRE_TOOLS=1 cargo xtask ci --quick`: `[ci] ok`.
- Full `cargo xtask linktest` (aarch64 native, x86_64 and i386 under
  qemu): 32 tests, 372 results; every reference record `PASS` except the
  three `XFAIL` of mold on `resolve/common` (a mold bug, below); every
  mortar record `XFAIL`; about 28 s wall on the reference machine (the quick gate: 48 s in all, the link-test step 10 s).
- The end-to-end test (`xtask/tests/linktest.rs`) reaches every outcome
  with fake linkers.

## Deviations from the brief and the inherited notes

- **Exit status under ORACLE.** A reference's `FAIL`/`XPASS` in a unit
  that is `ORACLE` counts as the ORACLE (status 3), not as a linker
  failure (1): the test is wrong. `KILLED` stays 1.
- **`Report.errors`**: run-level errors (`error:` lines, status 3).
- **Extra options**: `--mortar`, `--results`, `--keep`, `-j`, `-v`.
- **`LC_ALL=C`** for every child, so diagnostics match as text.
- **`--quick`** runs the host's architecture, not "the touched areas":
  the whole corpus on one architecture takes about 20 s.
- **Expected-failure links**: the harness removes the output file before
  the link, and "no output afterwards" binds every linker, not only
  mortar (all three references meet it).
- **Reference markers**: `resolve/common` is `xfail(mold)`; the brief's
  "every reference row PASS" holds everywhere else.
- **32 cases**, not 30.

## Reference disagreements found

See the table in `spec/harness.md` "Where the references differ". Two
are bugs of a reference: mold 2.37.1 sizes merged common symbols by the
first tentative definition (16 of 64 bytes: the program writes past
`_end`); GNU ld 2.44 on x86-64 breaks IFUNC address equality for `-fpie`
objects in a `-no-pie` static link.
