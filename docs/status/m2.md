# M2 (dynamic executables)

Where M2 stands. The rules are `spec/dyn.md`. The cut into packages is
`spec/landed/dyn/WP-040.md`, and step 0's record is
`spec/landed/dyn/WP-041.md`. Dynamic output is still refused by name:
`crates/mortar/src/dynamic.rs` (`DYNAMIC_OUTPUT = false`) refuses
`-pie`, `-dynamic-linker` and `-Bdynamic` with the text the command line
gave before step 0e. Static links are byte-identical to the baseline
(`cargo xtask static-identical`).

### The "now" flag, not a variant

The brief asked for `PltVariant::Now`. Under `-z now` D-49 keeps the PLT
shapes, and AArch64's `Bti`/`Pac` shapes combine with it. A variant
would therefore need a `Now` twin of every shape. "Now" is a flag
instead: `OutputCx.bind_now`, on the context that `plt_variant` already
takes. `PltShape` and the existing implementations are unchanged
(R-A6 (b)). WP-047 and WP-048 read the flag where their briefs say
`PltVariant::Now`.

### Deviations from the brief

- **`lazy_target` takes the variant, not a PLT index.** D-49's target
  is either PLT0 or the entry plus a constant, so the index adds nothing:
  `LazyTarget::Entry { plus }` is relative to the entry.
- **`weak_use` also takes `offset`.** x86-64's branch-opcode test reads
  bytes before the field, inside the same input section.
- **The 0k shapes are the nearest that exist.** There is no
  `LiveRelocs`, `SectionMap` or `PerKey` type. `weak_classes` reads the
  scan's own inputs, takes the new trait `SectionMap: Sync`, and returns
  `WeakKeys { weak_dyn: IdSet<SymbolId>, refused }`.
- **The input walk keeps one of its refusals.** "Dynamic executable
  without -dynamic-linker" (input §8.4) stays in `mortar_input`, because
  D-31 keeps it at M2. The guard owns the command-line gates only.
- **`RefFlags` duplicates three columns (for RES).** In
  `mortar_core::resolution`, the bits `FROM_SHARED`, `DEFINED_SHARED`
  and `EXPORTED` say what the 0j columns `ref_dynamic`,
  `defined_dynamic` and `exported` say. RES fills the columns and must
  keep the bits equal to them, or retire the bits. Nothing reads the bits
  for a dynamic output yet.

## The static-identical baseline

`tests/identical/baseline.on-<host>.tsv` (one per host architecture,
AArch64 and x86-64, since WP-015: a host builds its own architecture's
inputs with its native C library, the others with the cross packages)
holds one row per static link of `tests/link` and `tests/identical`. A row is the SHA-256 of the output,
of the normalised `--mortar-map`, and of the normalised stderr. A change
to it is a reviewed commit.

| commit | links | why it changed |
|---|---|---|
| d9a75fc | 150 | Recorded after Q7. Against d86a0cd, exactly 42 AArch64 outputs differ, in output bytes only: the IPLT word is now `S + A` |
| ab28002 | 167 | After merging main 3f4cfe2 (WP-030c). On i386, 33 rows went from exit 1 to 0, 2 diagnostic rows changed in stderr only, and 17 rows are new. Nothing changed on x86-64. One AArch64 row moved (next paragraph) |

The AArch64 row that moved is `reloc/data-pointers.test` line 10
(output and map). The cause is 31175df on main (`got_base_defined`): a
linker-defined `_GLOBAL_OFFSET_TABLE_` now demands `GOT_BASE` on every
architecture. GCC's `-fpie` code names that symbol on AArch64
(`ADR_PREL_PG_HI21`), so `.got` gains its 8-byte header word (0x430
becomes 0x438) and every later place moves by 0x10. The change is
wanted: layout.md L-101 says such a reference gets the header word, as
GNU ld gives it. Before 31175df mortar raised `GOT_BASE` only for the
GotRel/GotBaseRef classes.
