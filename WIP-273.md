## Design decisions taken (see the record's WP-273 section)
- `replan` (mortar_layout `replan.rs`) runs in front.rs right after the
  replay hook returns the materialized layout, before `validate`.
- Phase A has no delta in front.rs (the hook returns a `Layout` only), so
  the call passes every exec extent as dirty (= front 2's refill set, every
  chunk). The dirty-only path is unit-tested; the lane compare needs `df`
  at the call (crates/mortar/src/update/mod.rs: not mine) -> RULING.
- A replan refusal in front.rs can only fail the front (diag) -> front_two
  names it `(image)` FINDING; the real reason is in the diag text. Naming it
  needs a change in update/mod.rs -> RULING.
- materialize: gone-key patches (key in a changed file) -> `Fill` holes
  (replan::hole_gone); island sizes from the delta (stored), "an island
  moved" refused by name (R-1); `moves_code` kept only for non-island
  sized rows.

- The re-plan runs only in the update's front 2 (`env.state5`):
  IN-61's replay (`replay_link`, format 4) and floor.rs write the rows
  they are given (else tests/incremental.rs's mutations are repaired).
- `tables_resized` (.symtab/.strtab sized to the re-planned symtab plan)
  only when the re-plan changed the rows (`replanned`): else it would
  overwrite a replayed SYMTAB_LOCALS.
- L-113 fast path: the EXACT form (RX PT_LOAD p_memsz <= 2^27-4,
  WP-276 ruling 5), unit-tested at the bound. Branch sites restricted to
  the dirty ranges (`branches_in`, WP-276 ruling 3).
- Rulings to raise (record §WP-273): (a) phase A has no delta in
  front.rs -> dirty = full extents, compare vacuous; (b) refusal named
  `(image)`+finding; (c) changed-file patches -> Fill holes (zeros);
  (d) x64 scenarios `not x64` (option refused there); (e) redirects kept
  where an ADR would now fit; (f) Fill hole zeros not trap (R-6);
  (g) fixes + final_got moved before validate.
